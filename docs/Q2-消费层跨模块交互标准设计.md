## 二、跨模块事件体系设计

### 2.1 事件定义表

| 事件类型 | 触发条件 | 触发方 | 携带数据 | 主要消费模块 |
|----------|----------|--------|----------|--------------|
| `EMPLOYEE_TRANSFERRED` | 员工调岗（assignOrg 成功） | 人员管理（employee） | `employeeId, oldOrgId, newOrgId, oldPosition, newPosition, effectiveDate` | 三违 / 隐患 / 培训 / 目标职责 / 月度考核 / 保险 / 预警整改 |
| `EMPLOYEE_RESIGNED` | 员工离职（org_status→离职） | 人员管理 / 人员导入 | `employeeId, resignDate, lastWorkingDay` | 所有持有 `employee_id` 外键的模块 |
| `EMPLOYEE_STATUS_CHANGED` | 状态变更（停薪留职/返岗等） | 人员管理 | `employeeId, oldStatus, newStatus, effectiveDate` | 三违 / 培训 / 月度考核 / 风险画像 / 驾驶舱系 |
| `EMPLOYEE_INFO_UPDATED` | 基础信息变更（姓名/身份证/联系方式） | 人员管理 | `employeeId, changedFields[], newValues[]` | 所有引用员工姓名的模块 |

### 2.2 事件规范要求

**触发时机**：由后端在 `assignOrg` / 状态变更 / 信息更新事务提交后，通过消息总线（建议 RabbitMQ / Redis Stream，前端经 WebSocket 或轮询拉取）发布；前端 `useEmployeeEvent`（§3.2）订阅。

**数据格式**（TypeScript）：
```ts
// 统一事件信封
interface EmployeeEventEnvelope<T = unknown> {
  type: 'EMPLOYEE_TRANSFERRED' | 'EMPLOYEE_RESIGNED'
      | 'EMPLOYEE_STATUS_CHANGED' | 'EMPLOYEE_INFO_UPDATED';
  employeeId: number;          // 唯一规范键（对应 Q1 P0-2：统一 employee_id）
  occurredAt: string;          // ISO8601
  payload: T;
  schemaVersion: 1;            // 版本管理
}

interface TransferredPayload {
  oldOrgId: number; newOrgId: number;
  oldPosition?: string; newPosition?: string;
  effectiveDate: string;
}
interface ResignedPayload { resignDate: string; lastWorkingDay: string; }
interface StatusChangedPayload { oldStatus: string; newStatus: string; effectiveDate: string; }
interface InfoUpdatedPayload { changedFields: string[]; newValues: Record<string, unknown>; }
```

**幂等性保证**：消费方以 `(type, employeeId, occurredAt)` 作为幂等键去重；快照类字段（姓名/部门）以「事件携带的新值」覆盖本地缓存，不依赖事件顺序。

**事件消费契约**（各模块声明依赖，示例）：
```ts
// 三违管理（violations）消费契约
// 依赖 EMPLOYEE_TRANSFERRED：当违章记录中的 violatorId 命中时，
//   将本地姓名快照 violatorName 刷新为最新部门/姓名（不覆盖历史违章，仅当前有效记录）
// 依赖 EMPLOYEE_RESIGNED：标记该员工为「已离职」，前端展示「已离职」标签（对应 Q1 P1-2）
// 依赖 EMPLOYEE_INFO_UPDATED：若 changedFields 含 name，刷新 violatorName 展示
```

### 2.3 事件版本管理策略（向后兼容）
- 所有事件带 `schemaVersion`；v1 为本文档定义。
- 新增字段采用**可选（optional）**追加，不删除/重命名既有字段。
- 消费方对未知 `type` 忽略；对未知 `payload` 字段容忍。
- 重大变更发 v2 并保留 v1 双写过渡期（≥1 个发布周期）。

## 三、公共 Composable 设计

> 所有 Hook 以 `employee_id`（数字）为唯一输入键（对应 Q1 P0-2）。底层统一调用 `employee.ts`（新增的 `getEmployeesByIds`）与事件总线，杜绝散落 `getEmployeeById` 直调。

### 3.1 `useEmployeeData(employeeId: number)`

```ts
interface UseEmployeeDataReturn {
  employee: Ref<EmployeeInfo | null>;
  loading: Ref<boolean>;
  error: Ref<Error | null>;
  refresh: () => Promise<void>;
}

declare function useEmployeeData(employeeId: number): UseEmployeeDataReturn;
```

- **功能**：统一员工数据获取（姓名/部门/岗位/状态/联系方式）。
- **缓存策略**：模块级 `Map<employeeId, EmployeeInfo>` + 全局失效事件；命中缓存立即返回，未命中经 `getEmployeesByIds([id])` 拉取。
- **替代目标**：hazards 中坏掉的 `getEmployeeName(id)`（`hazards/index.vue:1402-1405`，返回 `员工${id}`）——改用本 Hook 后隐患详情正确显示真实姓名（Q1 P0-1）。
- **兼容性**：返回结构对齐 `EmployeeInfo`（§5.1），不破坏现有 `EmployeeItem` 消费点。

### 3.2 `useEmployeeEvent()`

```ts
type EmployeeEventType =
  | 'EMPLOYEE_TRANSFERRED' | 'EMPLOYEE_RESIGNED'
  | 'EMPLOYEE_STATUS_CHANGED' | 'EMPLOYEE_INFO_UPDATED';

interface UseEmployeeEventReturn {
  subscribe: (types: EmployeeEventType[], handler: (e: EmployeeEventEnvelope) => void) => () => void;
  // 返回值为取消订阅函数
}

declare function useEmployeeEvent(): UseEmployeeEventReturn;
```

- **功能**：订阅员工变更事件，注册/注销回调。
- **联动策略**：收到 `EMPLOYEE_TRANSFERRED` 时，自动 `useEmployeeData(id).refresh()` 刷新关联缓存；收到 `EMPLOYEE_RESIGNED`/`EMPLOYEE_INFO_UPDATED` 时，刷新并触发本地「已离职」标记（对应 Q1 P1-2）。
- **替代目标**：模块手动轮询或不做联动（Q1 发现仅 assessment-monthly 有手动 sync，其余无联动）。

### 3.3 `useEmployeeLink(employeeId: number)`

```ts
interface UseEmployeeLinkReturn {
  openProfile: () => void;          // 路由跳转
  EmployeeName: Component;           // 姓名展示组件（可点击）
}

declare function useEmployeeLink(employeeId: number): UseEmployeeLinkReturn;
```

- **功能**：统一「点击员工姓名跳转档案」交互。
- **规范**：所有模块员工姓名展示统一使用 `EmployeeName` 组件（渲染 `<a>` + 姓名，hover 显示完整信息卡片）。`openProfile` 跳转至**统一规范路由**（见 §8 风险 R5：当前仅 `risk-profile` 有入口，需补足主档案 `/hse/employee/:id` 详情页）。
- **替代目标**：violations（`:427/:440` 原始 id 无链接）、warning-center（`targetName` 不可点 `:683`）、workflow（`assignee` 不可点 `:273/:289`）、accidents/emergency/objectives 纯文本姓名 —— 全部改用本 Hook（Q1 P1-1）。

### 3.4 `useEmployeeSearch()`

```ts
interface EmployeeSearchOptions {
```

- **功能**：统一员工搜索，封装 `EmployeeSelector` 逻辑。
- **替代目标**：
  - assessment-monthly 手填 id 文本框（`targets.vue:130-134`）→ 改用本 Hook，杜绝错填/孤儿记录。

  - accidents/emergency/objectives 自由文本/独立源 → 迁移到本 Hook（Q1 P0-3）。

## 四、EmployeeSelector 增强方案

### 4.1 当前问题诊断（基于 Q1 审计）

| 问题 | Q1 证据 | 影响 |
|------|---------|------|
| 误用不存在的 props | `training/requirements:98-100`、`training/plans:161-162` 用 `v-model:employee-id`/`v-model:employee-name`/`mode="position"` | `positionId`/`trainerId` 恒为 0，关联未落库 |
| 用纯文本 Input 代替 | `hazards` 的 `checker`/`fixer`（`:263/:268`）、`emergency` 的 `responsiblePerson`/`leader_name`、`accidents` 的 `handler`、`objectives/committee` 的 `name`、`insurance/personnel` 的 `name` | 数据与主数据脱钩、陈旧 |
| 不调用选择器 | `accidents`/`emergency`/`objectives`/`assessment-monthly`/`warning-center`/`workflow` 均未 import `EmployeeSelector` | 重复台账、手填 id |
| v-model 字段名不一致 | `finderId`/`responsibleId`/`violatorId`/`employeeId`/`trainerId`/`responsiblePersonId` | 跨模块提交字段名不一致（Q1 P0-2） |
| 只读回显缺失 | hazards 详情 `getEmployeeName` 返回 `员工${id}`（`:1402-1405`） | 姓名失效 |

### 4.2 增强设计

**统一 props 接口**：
```ts
interface EmployeeSelectorProps {
  value?: number | number[];          // 统一用 employee_id
  onChange?: (val: number | number[], items: EmployeeInfo | EmployeeInfo[]) => void;
  mode?: 'single' | 'multiple';       // 替代旧 mode="position"
  maxCount?: number;                  // multiple 上限
  filterDept?: number;                // 部门过滤
  filterStatus?: string;              // 状态过滤（org_status）
  disabled?: boolean;
  showDetail?: boolean;               // hover 完整信息卡片
  placeholder?: string;
}
```

**搜索体验增强**：支持按员工编号/姓名/部门/岗位模糊搜索，防抖默认 300ms（经 `getEmployeeSelectorList` 现有能力，无需新增后端）。

**选中项展示增强**：头像 + 姓名 + 部门 + 岗位；`showDetail` 时 hover 显示完整信息卡片（Phone/状态/工号）。

**批量选择增强**：支持 `filterDept` 按部门批量导入；预留 `pasteEmployeeCodes(string[])` 接口（Excel 粘贴员工编号批量选择，对应 Q1 月度考核手填痛点）。

**错误状态处理**：加载失败 / 搜索无结果 / 网络超时的统一 UI（复用 Vben 的 `Empty`/`Spin`/`message`）。

### 4.3 向后兼容方案
- 现有 `value`/`mode`/`placeholder`/`disabled`/`isDriver`/`orgUnitId`/`positionId`/`maxCount`/`showDetail` 用法**全部保留**。
- 新功能（`filterDept`/`filterStatus`/`pasteEmployeeCodes`/统一错误态）通过 opt-in props 启用，不影响旧调用。
- `v-model:employee-id`/`v-model:employee-name` 旧写法标记 `@deprecated`，保留一个兼容适配层映射到 `value`/`onChange`，过渡期后移除。

### 4.4 迁移指南（旧用法 → 新用法）
| 旧用法（Q1 问题点） | 新用法 |
|---------------------|--------|
| `v-model:employee-id` + `v-model:employee-name`（training/requirements/plans） | `v-model:value`（number）+ `onChange` 取 `items[].name` |
| `mode="position"`（training/requirements） | `filterDept` 部门过滤 + `mode="single"` |
| 纯文本 `Input` 录人（accidents/emergency/objectives/insurance-personnel） | `<EmployeeSelector v-model:value="xxxId" />` |
| 手填 id 文本域（assessment-monthly） | `<EmployeeSelector mode="multiple" v-model:value="ids" />` |

## 五、API 规范标准

### 5.1 员工查询接口规范（对齐真实 `employee.ts`）
- **请求参数**（`EmployeeListParams` 扩展）：
```ts
interface EmployeeQueryParams {
  employeeIds?: number[];     // 新增：批量查询键（对应 §5.2）
  keyword?: string;
  deptId?: number;            // 统一用 deptId（替代原 deptName 模糊）
  status?: string;            // org_status
  personType?: string;
  personCategory?: string;
  gender?: string;
  page?: number; pageSize?: number;
}
```
- **响应格式**（统一）：
```ts
interface EmployeeQueryResult {
  total: number;
  list: EmployeeInfo[];
  page: number;
  pageSize: number;
}
```
- **`EmployeeInfo` 类型定义（统一规范，解决 Q1 P0-2/P0-6）**：
```ts
interface EmployeeInfo {
  employeeId: number;         // 唯一规范键（映射 EmployeeItem.id）
  employeeCode: string;       // 映射 employee_code
  name: string;
  deptName: string;           // 映射 dept_name
  positionName: string;       // 映射 position_name
  orgStatus: string;          // 映射 org_status，取值：在职/待岗/离职/退休/返聘（统一枚举，替代 active/inactive）
  phone?: string;
  idCard?: string;
}
```
> 注：前端内部统一 camelCase `employeeId`/`employeeCode`/`deptName`/`positionName`/`orgStatus`；与后端 snake_case（`employee_id` 等）经请求层 adapter 转换，业务模块**不直接接触 snake_case**（对应 Q1 P0-2）。

### 5.2 批量查询优化（解决 Q1 N+1 隐患 / P2-4 死代码）
- **新增端点**：`getEmployeesByIds(ids: number[]): Promise<EmployeeInfo[]>`（路径建议 `GET /hse/employee/employees/batch?ids=1,2,3`）。
- **用途**：列表页展示关联员工姓名时一次性批量获取，替代逐行 `getEmployeeDetail`（死代码）或后端 join。
- **缓存策略**：前端内存缓存 5 分钟（以 `ids` 集合为 key，相同集合不重复请求）；`EMPLOYEE_INFO_UPDATED`/`EMPLOYEE_TRANSFERRED` 事件触发失效（§3.2）。
- **替代目标**：hazards 坏掉的姓名解析（P0-1）、各模块各自实现（P2-2）、死代码 `getEmployeeDetail`（P2-4）。

### 5.3 员工统计接口规范
- 统一响应格式（与 §5.1 一致）：`{ total, list, page, pageSize }` 或聚合 `{ total, byX: [{key,count}] }`。
- `getEmployeeStats`（employee.ts:261）返回 `EmployeeStats`（total/byPersonType/byPersonCategory/byOrgStatus）作为规范统计契约；其他模块自有统计端点（driver-risk-center/executive-cockpit 的聚合名单）建议收敛到统一 `EmployeeInfo` 结构后再聚合，避免 `employeeName`/`name` 混用（Q1 字段分裂）。

## 六、模块间数据依赖声明规范

### 6.1 声明格式
每个模块在模块根目录放置 `employee-deps.json`：
```json
{
  "module": "violations",
  "dependsOn": {
    "employeeFields": ["employeeId", "employeeName", "deptName", "positionName"],
    "events": ["EMPLOYEE_TRANSFERRED", "EMPLOYEE_RESIGNED", "EMPLOYEE_INFO_UPDATED"],
    "queries": ["getEmployeesByIds", "getEmployeeStats"],
    "components": ["EmployeeSelector", "EmployeeLink"]
  },
  "provides": {
    "employeeStats": ["violationCount", "violationScore"],
    "events": ["VIOLATION_RECORDED"]
  }
}
```

### 6.2 用途
- **自动化影响分析**：当 `employee.ts` 模型变更（如字段重命名）时，扫描所有 `dependsOn.employeeFields` 自动识别受影响模块（对应 Q1 P0-2 命名统一需求）。
- **文档生成**：自动生成模块依赖关系图（补充 Q1 §四）。
- **回归测试**：员工 API 变更时，依 `dependsOn.queries` 自动确定需回归的模块范围。

### 6.3 可解析性
- JSON Schema 校验；字段固定为 `module`/`dependsOn`/`provides` 三层，键名枚举化，可被程序解析（无自由文本动态键）。

## 八、风险与注意事项

| 编号 | 风险 | 说明 | 缓解 |
|------|------|------|------|
| R1 | 标识符统一阻力 | 历史数据 `employee_id` 缺失，脱钩模块（accidents/emergency/objectives/insurance）需回填脚本 | Phase 1 任务 4 配数据迁移脚本；先写后读校验 |
| R2 | 快照 vs 实时 | 姓名反规范化快照（Q1 P2-2）在调岗后是否刷新需业务决策 | 采用「事件驱动刷新当前有效记录，历史记录保留」策略（§2.2 幂等） |
| R3 | cockpit 死代码迁移 | `cockpit.ts` 端点分叉，修复需确认后端真实路由（Q1 P0-4） | 先与后端对齐 `/overview/*` vs `/hse/dashboard/*` 再改前端 |
| R4 | EmployeeSelector 误用修复 | training/requirements/plans 改 `v-model:value` 后需回归关联落库（Q1 P2-1） | 修复后跑单元测试验证 `positionId`/`trainerId` 非 0 |
| R5 | 主档案路由缺失 | 当前「点击→档案」仅 `risk-profile` 有入口，主档案 `/hse/employee/:id` 详情页 UI 无入口（Q1 基础事实） | `useEmployeeLink` 先跳 `risk-profile`；后续补主档案详情页作为规范目标 |
| R6 | 事件总线依赖后端 | EMPLOYEE_* 事件需后端发布（Q1 未涉及后端） | 本设计为前端标准；后端事件发布列为 Sprint-Q 后端协作项，前端先实现订阅与缓存失效骨架 |
| R7 | 状态枚举收敛 | `employee-profile` 的 active/inactive 与 employee.ts 在职/离职（Q1 P0-6） | 统一为 `orgStatus` 枚举，前端 adapter 兼容旧值 |
