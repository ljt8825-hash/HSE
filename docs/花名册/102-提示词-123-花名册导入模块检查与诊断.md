## 3. 检查维度

### 3.1 前端代码质量
- 是否使用 `useDataTable` / `useSearchForm` 规范（或说明偏离原因）
- 分页是否正确绑定 `current` / `total` / `pageSize`
- 错误处理是否完善（catch 块是否覆盖所有 async 操作）
- 是否有未使用的 import 或 dead code
- `as any` 断言是否过多（可能隐藏类型问题）
- 权限控制是否与后端一致（`canImport` / `canResolve` / `canExecute` / `canClearAll`）

### 3.2 后端代码质量
- 所有写端点是否正确使用 `requireRole`
- 文件上传是否校验类型和大小
- 敏感字段（身份证/手机号）是否正确加密/脱敏
- 事务处理是否完善（入库是否使用 `BEGIN/COMMIT/ROLLBACK`）
- 错误信息是否对用户友好（避免暴露原始 PostgreSQL 错误）
- 是否有 SQL 注入风险（参数化查询）

### 3.3 数据流一致性
- 前后端字段名映射是否一致（snake_case / camelCase）
- 批次状态流转是否完整（uploaded → parsing → pending_review → completed / partial_completed / failed）
- 待审核状态流转是否完整（pending → approved / rejected → imported）
- 级联清空是否安全（`clear-all-cascade` 是否有二次确认）

### 3.4 边界与异常
- 空文件上传 → 友好提示
- 非 Excel 格式 → 友好提示
- 超大文件 → 性能可控
- 重复批次名 → 处理正确
- 无待审核数据时入库 → 处理正确
- 已入库批次重复入库 → 防重入

### 3.5 回归检查
- 部门匹配五级容错策略是否仍生效（78 修复）
- 岗位匹配三级容错策略是否仍生效（79 修复）
- 司机片区条件匹配是否仍生效（80 修复）
- 表头别名映射是否仍生效（花名册轨道修复）
