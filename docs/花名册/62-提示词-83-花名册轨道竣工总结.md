## 二、修复历程（78 → 82）

### 提示词-78：未知部门匹配修复（P0）
- **问题**：5,160 条 `unknown_dept` 无法自动匹配组织单元。
- **方案**：显式规则优先（L1）+ L5 乡镇前缀兜底算法（插入 `matchOrgUnit()`）。
- **结果**：64 条 `unknown_dept → org_unit` 显式规则，5,160 条全部 L1 命中，自动匹配率从 **0.6% → 100%**。
- **关键坑**：手列规则遗漏「柴胡店镇七班」(35 条)，经 L5 兜底暴露后补显式规则，最终 64/64 全 L1 命中。

### 提示词-79：未知岗位匹配修复 + 端到端（P1）
- **问题**：公司职能岗 21 条 `unknown_position` 无法匹配。
- **方案**：7 条 `unknown_position → position` 显式规则（condition_dept=NULL）+ L3 岗位名模糊兜底（插入 `matchPosition()`）。
- **结果**：21 条全部命中。端到端用合成 7 行 + 1,311 行乡镇文件验证，发现**司机 + 片区 35 条残留**转入提示词-80。

### 提示词-80：司机 / 片区条件匹配修复（P1）
- **问题**：35 条司机、片区岗位因 condition_dept 条件不匹配遗留。
- **方案**：新增 1 条 `司机 | condition_dept IS NULL | 1398 垃圾收运车驾驶员` 兜底规则（id 37，match_priority=50），**零代码改动、零现有规则/数据改动**。
- **结果**：35 条残留归零，unknown_position 全链路 0。

### 提示词-81：正式全量入库 + 数据完整性（P0 里程碑）
- **问题**：`clear-all` 软删除不释放 `uk_employee_code` → 重导撞重复键（failed=1,311）。
- **方案**：回退 `employee.is_deleted=false` 让导入**原地 UPDATE**（updated=1,311），保留主键与业务外键链路。
- **结果**：正式入库 employee/assignment 各 **1,361 条**，failed=0。
- **关键发现**：
  - 50 名文件外真实员工（持 47+ 条业务记录）**不可删** → 保留并恢复任职（实际 49 人）。
  - 18 个空 position_id、1,328 个空 person_type 为**源数据缺口**，记录为偏差非缺陷（提示词-82 修复）。

### 提示词-82：数据质量补全 + 下游验证（P1）
- **任务1 空岗位补全（D2）**：18/18 补全，`empty_pos_remain=0`。（发现 `employee_assignment` 实际**无 `raw_dept/raw_position` 列**，改从 `employee_import_pending` 恢复原始岗位完成映射。）
- **任务2 person_type 推断（D3）**：1,328 条 NULL 全部消除，分布 `生产1264 / 管理69 / 辅助20 / 技术4`（+ 4 个 `验证_` 测试员工 person_type 为非法值 `in_service`，已标注不修改）。
- **任务3 文件外员工清单**：实测 **49 人**（提示词估 50，差 1 口径误差）= 4 名测试员工（持 50 业务记录）+ 45 名真实在册（保洁员，持 48 记录），均按 FK 保护保留。
- **任务4 下游模块验证（只读）**：`v_employee_current` = 1,361 行完整无残缺；`EmployeeName`/`EmployeeSelector` 组件经真实后端取数；7 大模块全部覆盖。
