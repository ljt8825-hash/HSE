# 提示词-130 — 超龄人员模块检查与诊断

> 轨道：人员管理 > 超龄人员
> 执行时间：2026-08-01
> 执行人：Senior Developer（高级开发工程师 / 吴八哥）

## 1. 背景

"超龄人员"模块（`/personnel/over-age`）是人员管理菜单的最后一项（第 7 项），用于自动识别和管理超龄员工（男性 > 60 岁、女性 > 50 岁）。该模块是 Sprint11-2 新增，尚未经过系统诊断。

**目标**：对超龄人员模块进行 5 维度全面诊断，发现潜在问题，为后续修复提供依据。

## 2. 模块概览

### 2.1 架构（双子系统）

```
超龄人员模块 = 两个子系统:

┌─ 子系统 A: 自动识别（人员管理菜单）
│  路径: /personnel/over-age
│  前端: views/hse/employee/over-age/index.vue (691 行)
│  API:  employee.ts → GET /hse/employee/over-age/auto-*
│  后端: hse-employee.js (6632-6837 行)
│  数据源: employee.birth_date（实时 SQL 计算，无需手动维护）
│  规则: employee-age-rule.json（男 60 / 女 50）
│
└─ 子系统 B: 保险管控（保险菜单，隐藏）
   路径: /insurance/over-age
   前端: views/insurance/over-age/index.vue
   API:  insurance.ts → 完整 CRUD + 附件 + 版本
   后端: insurance.js (938-1299 行)
   操作表: over_age_personnel (23 字段)
   附表: insurance_attachments + insurance_versions
```

### 2.2 文件清单

| 层次 | 文件 | 说明 |
|------|------|------|
| 前端页面 | `views/hse/employee/over-age/index.vue` | 唯一页面：统计卡片 + 搜索筛选 + 数据表格 + CRUD 弹窗 + 详情抽屉 + 导出 CSV |

### 2.3 核心功能

- **统计卡片**：总数、男、女、70 岁以上
- **自动识别规则提示**：展示当前阈值（男 60 / 女 50）
- **搜索筛选**：关键词 + 性别
- **数据表格**：分页展示，含姓名/性别/年龄/超龄年限/部门/岗位/电话
- **CRUD 弹窗**：新增/编辑超龄人员记录
- **详情抽屉**：基本信息 + 附件列表 + 历史版本
- **导出 CSV**：全部数据导出

## 3. 诊断维度

### 3.1 维度一：前端代码质量

请检查以下方面：

1. **组件规范合规性**
   - 是否使用 `useDataTable` 托管列表页状态（vs 手写 loading/dataList/total/pagination）
   - 是否使用 `useSearchForm` 托管搜索表单
   - 是否使用 `useCrudModal` 托管弹窗（vs 手写 visible/loading/editingRecord/form）
   - 是否使用 `Page` 组件（`@vben/common-ui`）
   - 是否使用 Ant Design Vue 组件（非 Element Plus）

2. **类型安全**
   - TypeScript 类型定义是否完整（`OverAgeAutoItem` / `OverAgeAutoStats` / `OverAgeAutoDetail`）
   - 是否存在 `as any` 类型断言
   - `reactive` 表单可选字段是否用 `undefined` 初始化（非 `null`）

3. **代码质量**
   - 是否存在未使用的 import
   - 是否存在死代码
   - 命名是否规范

4. **API 调用**
   - 是否通过 `#/api/hse/employee` 统一调用
   - 导出 CSV 是否正确处理 blob 响应
   - 错误处理是否完善

### 3.2 维度二：后端代码质量

请检查以下方面：

1. **路由注册**
   - 3 套后端路由（hse-employee.js / insurance.js / over-age-personnel.js）是否冲突
   - 路由前缀是否与前端 API 一致

2. **权限控制**
   - `requireRole` 调用是否正确（rest 参数 vs 数组）
   - 角色权限是否与前端一致

3. **年龄计算规则**
   - 阈值是否从 `employee-age-rule.json` 集中读取
   - SQL 年龄计算逻辑是否正确（`EXTRACT(YEAR FROM age(birth_date))::INT`）
   - 规则配置是否与硬编码阈值一致

4. **错误处理**
   - 异常分支是否使用统一的 `success`/`error` 响应
   - 数据库连接检查是否完整
   - 参数校验是否充分（:id 是否做数值校验）

5. **加密字段**
   - `id_card` 加密/解密中间件是否正确使用
   - 加密字段在列表和详情中的处理是否一致

### 3.3 维度三：数据流一致性

请检查以下方面：

1. **字段命名一致性**
   - 前端发送的字段名（camelCase）与后端 SQL 列名（snake_case）是否一致
   - 后端返回的字段名与前端 `OverAgeAutoItem` 类型是否一致

2. **双系统数据一致性**
   - 自动识别（employee 表实时计算）与保险管控（over_age_personnel 表）的数据是否一致
   - 两者之间的同步机制是什么

3. **分页一致性**
   - 前端 `pagination` 字段名是否与后端返回一致
   - 后端是否正确处理 `page`/`pageSize` 参数

4. **统计卡片数据**
   - 总数/男/女/70岁以上 四个统计值的计算口径是否一致
   - 是否与表格数据匹配

### 3.4 维度四：边界与异常

请检查以下方面：

1. **空状态处理**
   - 无超龄人员时的展示
   - 统计卡片为 0 时的展示
   - 附件/版本为空时的展示

2. **年龄边界**
   - 恰好等于阈值（男 60 岁、女 50 岁）时的判定（> 还是 >=）
   - 无出生日期员工的处理
   - 年龄为 NULL 时的处理

3. **数据安全**
   - 身份证号是否在列表和导出中加密/脱敏
   - 导出 CSV 是否包含敏感字段

4. **规则配置变更**
   - 阈值变更后自动识别列表是否实时反映
   - 规则配置热加载能力

### 3.5 维度五：回归检查

请检查以下方面：

1. **菜单与路由**
   - 菜单是否正常显示
   - 路由是否正确注册
   - 是否存在路由冲突（人员管理 vs 保险模块）

2. **跨模块影响**
   - 是否引用了其他模块的 API 或组件
   - 是否修改了其他模块的数据
   - `over_age_personnel` 表是否被其他模块读写

3. **构建兼容性**
   - `pnpm build` 是否通过
   - `vue-tsc` 是否有新增错误
