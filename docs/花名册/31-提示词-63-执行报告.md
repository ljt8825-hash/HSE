## 4. 残留同类缺陷（非本次范围，请确认是否扩展）

⚠️ **修正提示词-62 报告中的一处误记**：提示词-62 执行报告所述"同类残留 `GET /departments/:id/employees`（L6029/L6055）"实为误判。经本次核实：
- L6029 / L6055 实际属于 **`GET /employees/profile/list`**（handler 起始 L5980），**并非**部门员工端点。
- 该端点的 `ea` JOIN（L6030）为 `LEFT JOIN employee_assignment ea ON ea.employee_id = ev.employee_id AND ea.is_current = true` —— **仅 `is_current`，同时缺失 `is_deleted` 与 `is_primary`**，是比部门端点更完整的同类缺陷（缺 is_deleted 还可能引入软删除记录）。
- 该端点按 `ea.employee_id = ev.employee_id` 关联、**不限 org_unit**，因此只要员工有 ≥2 条当前任职（跨 org_unit 的主职+兼岗），列表即会产生重复行 —— 在当前数据中极可能存在可见重复。

本次严格按提示词-63 红线**只修复了 `GET /departments/:id/employees`**，未改动 `/employees/profile/list`。如需一并修复，建议方案：
- L6030 改为 `... AND ea.is_current = true AND ea.is_deleted = false AND ea.is_primary = true`（与 GET /employees 一致）；
- 同时确认该 handler 的 `conditions` 数组（L5996 起）是否也需补 `ea.is_deleted`/`ea.is_primary`（当前 conditions 仅含 `e.is_deleted = false`，JOIN 内未过滤 ea 软删除）。
