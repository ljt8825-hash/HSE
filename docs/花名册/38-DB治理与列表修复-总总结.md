## 二、FK 约束补全工程

## 三、员工列表行重复修复（62 / 63 / 64）

### 3.1 根因
`GET /employees` 等列表端点用 `LEFT JOIN employee_assignment ea ON ea.employee_id = ev.employee_id AND ea.is_current = true`，**缺 `is_deleted = false` 与 `is_primary = true`** → 一个员工若有多条任职记录（含已软删）会被 JOIN 出多行，导致列表行重复（提示词-60 标记的遗留症状）。

### 3.2 三个端点的统一修复
| 端点 | 改动 | 验证结果 |
|------|------|----------|
| `GET /employees`（62） | 2 行：`L565 COUNT` + `AND ea.is_primary=true`；`L587 数据查询` + `AND ea.is_deleted=false AND ea.is_primary=true` | total=1298、100 行、**无重复**；DB 复现重复人数 1297→**0** |
| `GET /departments/:id/employees`（63） | 1 行：`conditions` 数组加 `'ea.is_primary = true'`（L1251 拼 whereClause，**同时**覆盖 COUNT+数据查询） | total=168、100 行、**无重复** |
| `GET /employees/profile/list`（64） | 2 行：L6030 COUNT + L6056 数据查询，均 `+ AND ea.is_deleted=false AND ea.is_primary=true` | total=1298、两页均 **无重复** |

**4 个含 `ea` JOIN 的端点现已统一为完整三条件范式**（is_current + is_deleted + is_primary）。

### 3.3 关键偏差说明（已记入报告）
- 提示词-62 §3.2 预期「修复后 total 略小于修复前」不成立：COUNT(L565) 原本已含 `is_deleted=false`，加 `is_primary` 后 total 仍是 1298；**行重复根因只在数据查询**（L587 原缺两条件）。前端「共 N 条」由 COUNT 提供本就准确，列表内重复行才是真实症状。
- 提示词-63 §3.2 的「total 可能略小」仅在该库存在「同 org_unit 内多任职」时显现；当前库无此类数据，故 total 无变化属**预防性正确化**，无回归。
- **修正提示词-62 一处误记**：62 报告曾把 L6029/L6055 记为「部门端点残留」，实测它们属于 `GET /employees/profile/list`（L5980），本次已在提示词-64 一并修复。

## 四、关键环境经验（高复用）

1. **Windows 原生 PG 二进制路径坑**：`pg_dump`/`psql`（`/d/PostgreSQL/17/bin/`）不识别 `/f/...` Unix 路径（报 "could not open output file"）；须用 Windows 风格 `F:/hse-dashboard/...`。bash 内建 `ls`/`psql -c` 可用 `/f/`，但 `-f` 读文件 / `-f` dump 输出 / `pg_dump -f` 必须用 `F:/`。
2. **「防改」触发器是数据清理的隐形护栏**：`hse_deduction_adjustment` / `hse_assessment_audit_log` 等有 `BEFORE DELETE OR UPDATE` 触发器硬性禁止改删。清理其测试/孤儿数据须：**临时 `DISABLE TRIGGER` → 删 → 立即 `ENABLE TRIGGER`**。
3. **后端 `node app.js` 非 nodemon，不热加载**：路由/SQL 改动须**重启进程**才生效。重启前先 `netstat -ano | findstr :5666` 取 PID，`taskkill /F /PID` 仅杀监听 :5666 的那个，勿波及 Vite dev（向 :5666 发起代理连接的进程会被误杀）。
4. **后台任务 `failed` ≠ 服务宕机**：后台包装进程被回收（主动 kill 子进程/会话回收）时 `node app.js` 作为孤儿进程继续跑。判断服务存活须看 `netstat :5666` + `curl /api/health`，而非后台任务状态。
5. **门控类提示词要真执行门控**：提示词「列已存在」「COUNT 会变小」等前提必须 `psql information_schema` 实测。本次提示词-66 门控偏差即因未落实的迁移脚本所致；提示词-59 的「列缺失」探针其实是对的。
6. **后端验证免鉴权手法**：端点受全局 `authMiddleware` 保护 → 用服务端 `JWT_SECRET` 本地自签 `type:'access'` 的 admin token（`jwt.sign({id:1,username:'admin',role:'admin',realName:'管理员',type:'access'}, SECRET, {expiresIn:'30m'})`），`curl -H "Authorization: Bearer $TOKEN"` 调受保护 API 做端到端校验。
