## 4. 修改项清单

### 4.1 R1：删除 index.vue 死代码（P2-1）

**文件**：`安全看板vben/apps/web-antd/src/views/emergency/index.vue`

**问题**：该文件 1452 行，含 `Tabs` + 独立 `planTable`/`drillTable` 两个 `useDataTable` 实例 + 预案附件/版本详情 Tab。文件仅被 `router/routes/modules/hse-emergency.ts` 引用，而 `hse-emergency.ts` 未注册进 `dynamicRouteFiles`（`index.ts` 的 glob 列表只含 `hse-09-emergency.ts`）。该文件完全不可达，为死代码。

**决策**：删除该文件。理由：
- 5 个子页（plans/drills/materials/teams/events）已独立运行且功能完整
- 该范例文件字段类型与真实表漂移（需兼容字段），维护成本高
- 删除后零影响（无路由可达、无 import 引用）

**注意**：删除后 `hse-emergency.ts`（引用该文件的 route 文件）也需一并检查，如该文件也未注册且仅引用 index.vue，则一并删除。

### 4.2 R2：移除不存在的列（P3-6）

**文件**：`安全看板vben/apps/web-antd/src/views/emergency/events/index.vue`、`src/views/emergency/teams/index.vue`

**问题**：
- events 页 `dataIndex: 'response_duration'`（真实 `emergency_events` 表无此列 → 恒空）
- teams 页 `dataIndex: 'member_count'`（真实 `emergency_teams` 表有 `member_ids` 数组、无 `member_count` 列）

**修复**：

**events/index.vue**：
1. 从表格列定义中移除 `{ title: '响应时长', dataIndex: 'response_duration', ... }`
2. 从表单 `eventForm` 中移除 `response_duration` 字段
3. 从模板中移除 `response_duration` 的 `<FormItem>` 和 `bodyCell` 模板

**teams/index.vue**：
1. 将表格列 `{ title: '队员人数', dataIndex: 'member_count', ... }` 改为 `{ title: '队员人数', dataIndex: 'member_ids', ... }`
2. 在 `bodyCell` 模板中按数组长度展示：`{{ Array.isArray(record.member_ids) ? record.member_ids.length : '-' }}`

### 4.3 R3：BIGINT id 序列化修复（P3-7）

**文件**：`server/routes/emergency.js`

**问题**：pg 默认将 BIGINT/BIGSERIAL 返回为字符串，如 materials `"id":"9001"`、teams `"leaderId":"3866"`。前端 `:row-key="(record) => record.id"` 与数值比较需注意类型。

**修复**：在 `formatMaterialRow`、`formatTeamRow`、`formatEventRow` 中将 `id` 转为 `Number`：

```javascript
function formatMaterialRow(row) {
  return {
    id: Number(row.id),  // 新增
    // ... 其余字段不变
  };
}
```

同理 `formatTeamRow`、`formatEventRow`。`formatPlanRow`、`formatDrillRow` 若已有转换则无需重复。

### 4.4 R4：补齐 emergency.ts API 模块（P3-8）

**文件**：`安全看板vben/apps/web-antd/src/api/hse/emergency.ts`

**问题**：仅定义 plans/drills 的 API 函数和类型，无 materials/teams/events。且 plans/drills 子页直接 `import request from '#/api/request'` 调用、不经此 API 模块 → emergency.ts 部分函数为死代码。

## 7. 诊断要求

按标准五维度对保险管理模块进行全面诊断：

### 维度一：前端代码质量
- 是否使用 `Page`（`@vben/common-ui`）组件
- 是否使用 Ant Design Vue（非 Element Plus）
- 是否使用 `useDataTable` / `useSearchForm` / `useCrudModal` 托管
- 是否使用 `EmployeeName` / `EmployeeSelector` 组件
- `vue-tsc` 类型检查结果

### 维度二：后端代码质量
- `node --check` 语法检查
- 路由注册顺序（`/:id` 遮蔽检查）
- 是否使用 `requireRole` 鉴权
- DDL 幂等性（`CREATE TABLE IF NOT EXISTS`）
- 软删除过滤（`is_deleted = false`）

### 维度三：数据流一致性
- 前后端字段名是否对齐（camelCase vs snake_case）
- API 类型定义是否与后端返回一致
- 枚举值是否统一（DB / API / 前端）
- 是否有硬编码规则（应归于 `config/hseRules`）

### 维度四：边界与异常
- 空状态处理
- 敏感信息脱敏（身份证、手机号）
- 文件上传限制
- 日期边界处理

### 维度五：回归检查
- 菜单/路由一致性
- 前端构建含本模块 chunk
- 备份文件状态
- 跨模块依赖
