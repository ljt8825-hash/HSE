## Task 1：修复部门员工子列表 SQL 关联 bug（P1）

### 1.1 根因

提示词-107 验证报告（§5，#3 端点附带发现）指出：

`GET /departments/:id/employees` 端点的 SQL 中 `WHERE ou.id = deptId` 将 `hse_org_unit.id` 与 `department.id` 直接比较，两个表 ID 空间不同 → 员工子列表恒为空。

### 1.2 定位

在 `server/routes/hse-employee.js` 中搜索 `/departments/:id/employees` 端点（约 1280-1340 行），找到 SQL 中的 `WHERE` 条件。

### 1.3 修复方案

**方案 A（推荐）**：通过 `department.name = hse_org_unit.org_name` 映射关联。

将 `WHERE ou.id = deptId` 改为：

```sql
WHERE ou.org_name = (SELECT name FROM department WHERE id = $1 AND is_deleted = false)
```

或者先查 department name，再按 org_name 匹配：

```js
// 1. 先查 department.name
const deptResult = await pool.query(
  `SELECT name FROM department WHERE id = $1 AND is_deleted = false`,
  [parseInt(id)]
);
if (deptResult.rows.length === 0) return res.json(error(-2, '部门不存在'));

const deptName = deptResult.rows[0].name;

// 2. 按 org_name 匹配员工
const result = await pool.query(
  `SELECT ... FROM employee e
   JOIN employee_assignment ea ON ea.employee_id = e.id AND ea.is_current = true AND ea.is_primary = true AND ea.is_deleted = false
   JOIN hse_org_unit ou ON ou.id = ea.org_unit_id AND ou.is_deleted = false
   WHERE ou.org_name = $1 AND e.is_deleted = false
   ...`,
  [deptName]
);
```

### 1.4 验证

1. 访问组织管理页面 → 点击某个部门（如"宁津项目公司"）
2. 确认该部门下的员工列表正常显示
3. 对比部门名称与员工所属组织名称是否一致

## Task 2：员工列表模块检查

### 2.1 定位实际文件

员工列表模块可能位于以下路径之一：
- `apps/web-antd/src/views/hse/employee/list.vue`

### 2.2 检查点

1. **列表页字段显示**：员工编号、姓名、性别、年龄、所属组织、岗位、状态等列是否正常显示
2. **字段映射**：是否存在 camelKeys 键名不匹配（与 101/102/107 同类问题）
3. **搜索/筛选**：搜索姓名、筛选组织、筛选状态是否正常
4. **分页**：分页功能是否正常
5. **与花名册交互**：员工列表数据是否与花名册导入一致（同一 `employee` 表）
6. **详情/操作**：如有详情或操作按钮，功能是否正常

### 2.3 检查方法

1. 打开员工列表页面 → 确认列表有数据
2. 浏览器 Network 面板 → 查看 API 返回的字段名（snake_case 还是 camelCase）
3. 对比前端 `dataIndex` → 确认键名匹配
4. 检查后端对应端点（搜索 `/employees` 相关路由在 `hse-employee.js` 中）
5. 确认 `is_public_welfare` 修复（提示词-106）在员工列表中生效

### 2.4 若员工列表页与员工档案页复用同一数据源
