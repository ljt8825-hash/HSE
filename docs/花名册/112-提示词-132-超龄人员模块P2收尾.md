## 3. 修改项清单（5 项）

### 3.1 修改项 R1：修复 vehicle export 路由遮蔽（P2）

**文件**：`server/routes/insurance.js`

**问题**：`GET /vehicle/export`（约 1128 行）注册在 `GET /vehicle/:id`（约 328 行）之后，Express 将 `export` 字面量匹配为 `:id` 参数，导致导出端点永久不可达。

**修复**：将 `GET /vehicle/export` 路由块整体前移至 `GET /vehicle/:id` 之前（与 131-F1 对 overage export 的处理一致）。

具体操作：
1. 找到 `// GET /vehicle/export — 导出车辆保险台账` 注释块（约 1127-1153 行），整体剪切
2. 粘贴到 `router.get('/vehicle/:id', ...)` 所在行（约 328 行）**之前**，与 `// GET /vehicle — 分页查询` 块之后

```javascript
// 修改前顺序（错误）：
//   router.get('/vehicle/:id', ...)      ← 328 行
//   ...中间其他路由...
//   router.get('/vehicle/export', ...)    ← 1128 行（被遮蔽）

// 修改后顺序（正确）：
//   router.get('/vehicle/export', ...)    ← 前移至此处
//   router.get('/vehicle/:id', ...)       ← 328 行
```

> **注意**：仅移动代码块位置，不修改导出逻辑本身。保险模块其他路由（personnel/vehicle CRUD）保持不变。

### 3.2 修改项 R2：子系统B 导出 CSV 身份证号脱敏（P2）

**文件**：`server/routes/insurance.js`

**问题**：`GET /insurance/overage/export` 的 CSV 输出中身份证号列为明文 18 位完整号，与子系统A（auto-export）的脱敏输出不一致，且存在 PII 泄露风险。

**修复**：在 `GET /overage/export` 的 handler 中，对 `r.id_card` 做脱敏处理后再写入 CSV。

找到 `formatOverage` 函数（约 942 行），观察其返回对象包含 `id_card: row.id_card || ''`。在 CSV 行生成处（约 1090-1093 行），将身份证号列的映射改为脱敏：

```javascript
// 修改前（约 1093 行）：
(r.id_card || '').replace(/"/g, '""'),

// 修改后：
r.id_card
  ? (r.id_card.slice(0, 4) + '**********' + r.id_card.slice(-4)).replace(/"/g, '""')
  : '',
```

完整修改上下文（在 `rows.map()` 回调中）：
```javascript
const rows = data.map(r => [
  r.id || '',
  (r.name || '').replace(/"/g, '""'),
  // 身份证号脱敏：保留前4后4
  r.id_card
    ? (r.id_card.slice(0, 4) + '**********' + r.id_card.slice(-4)).replace(/"/g, '""')
    : '',
  r.gender || '',
  // ...其余字段不变
]);
```

> **注意**：`decryptMiddleware` 已在 131-F1 中挂载，如果 id_card 是明文则 `decryptMiddleware` 为 no-op 原样返回，脱敏逻辑对明文/密文均安全。

### 3.4 修改项 F7：前端阈值去硬编码（P2）

**文件**：`安全看板vben/apps/web-antd/src/views/hse/employee/over-age/index.vue`

**问题**：前端 `index.vue:326-327` 硬编码 `MALE_THRESHOLD=60 / FEMALE_THRESHOLD=50`，与后端规则文件为独立副本。规则变更后前端展示的阈值与后端实际计算不一致。

**修复**：

1. 删除硬编码常量（约 326-327 行）：
```typescript
// 删除以下两行
const MALE_THRESHOLD = 60;
const FEMALE_THRESHOLD = 50;
```

2. 修改 `statsData` 初始化，thresholds 从后端获取（不再硬编码兜底）：
```typescript
const statsData = ref<OverAgeAutoStats>({
  total: 0,
  byGender: {},
  byAgeGroup: {},
  topDepartments: [],
  thresholds: { '男': 60, '女': 50 },  // 仅作为初始默认值，实际由后端下发覆盖
});
```

3. 修改 `ruleDescription`，使用 `statsData.value.thresholds` 动态展示：
```typescript
const ruleDescription = computed(() => {
  const t = statsData.value.thresholds || {};
  const male = t['男'] ?? 60;
  const female = t['女'] ?? 50;
  return `系统根据员工出生日期自动计算年龄：男性超过${male}岁、女性超过${female}岁自动识别为超龄人员。数据来源于员工档案，无需手动录入。规则来源：config/hseRules/employee-age-rule.json。`;
});
```

4. 修改 `getGenderThreshold` 和 `getGenderThresholdText`，使用 stats 中的阈值：
```typescript
function getGenderThreshold(gender?: string): number {
  const t = statsData.value.thresholds || {};
  if (gender === '女') return t['女'] ?? 50;
  if (gender === '男') return t['男'] ?? 60;
  return t['男'] ?? 60;
}

function getGenderThresholdText(gender?: string): string {
  const t = statsData.value.thresholds || {};
  if (gender === '女') return `女性 ${t['女'] ?? 50}岁`;
  if (gender === '男') return `男性 ${t['男'] ?? 60}岁`;
  return `默认 ${t['男'] ?? 60}岁`;
}
```

5. 确保 `fetchStats()` 在 `onMounted` 中最先调用，以便 `ruleDescription` 和阈值函数在首次渲染时拿到真实数据：
```typescript
onMounted(async () => {
  await fetchStats();  // 先获取阈值
  fetchData();         // 再加载列表
});
```

### 3.5 修改项 F10：兜底值 female:55→50 修正（P3）

**文件**：`server/config/hseRules/index.js`

**问题**：`getOverAgeThresholds()` 兜底值 `female: 55`（第 84 行）与 JSON 规则文件 `employee-age-rule.json` 的 `female: 50` 不一致。JSON 缺失或解析失败时静默回退到 55，导致女性阈值漂移 5 岁。

**修复**：

```javascript
// 修改前（第 84 行）：
return rule.overAgeThresholds || { male: 60, female: 55, default: 60 };

// 修改后：
return rule.overAgeThresholds || { male: 60, female: 50, default: 60 };
```

> **注意**：此修改仅影响 JSON 解析失败时的兜底行为，正常运行时不触发（JSON 正常解析则使用 JSON 中的 `female: 50`）。
