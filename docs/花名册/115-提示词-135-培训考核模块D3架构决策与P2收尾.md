## 2. D3/D6 联合分析

### 2.1 问题本质

`training.js` 和 `training-assessment.js` **同时写入同一张 `training_records` 表和同一张 `training_plans` 表**，但使用完全不同的字段约定：

| 维度 | training.js | training-assessment.js |
|------|-------------|----------------------|
| **前端消费** | 有（10 个页面 + API 函数） | **无**（全仓 grep 零命中） |
| **training_records 写入字段** | `personnel_id, name, id_card, dept, position, grid_level, frequency, training_type, training_date, duration_minutes, content, result, score, trainer, remark, employee_id, trainer_id` | `record_no, training_plan_id, training_title, training_type, training_date, start_time, end_time, hours_planned, hours_actual, location, trainer_id, trainer_name, employee_id, employee_name, employee_no, dept_id, dept_name, position, has_checkin, assessment_result, assessment_score, certificate_no, status, remark` |
| **training_plans 写入字段** | `title, plan_type, training_type, target_audience, trainer_name, trainer_id, planned_attendees, actual_attendees, start_date, end_date, location, duration_hours, content, exam_required, pass_score, status, remark` | `plan_no, plan_name, plan_type, training_type, target_dept_id, target_dept, target_position, target_employee_ids, plan_start_date, plan_end_date, plan_hours, trainer_id, trainer, location, description, objective, syllabus, assessment_method, status` |
| **实际可达性** | 全部可达 ✓ | `POST /records` 因 `location` 列不存在直接报错 ✗ |
| **规则端点** | 无 | 12 个 `/rules/*` 端点（只读，返回 `training-assessment-rule.json`） |

### 2.2 决策建议

**方案 A（推荐）**：保留 `training-assessment.js` 的 12 个 `/rules/*` 只读端点，删除其余 26 个 CRUD 端点（`/plans`、`/records`、`/assessments`、`/certificates`、`/comprehensive`、`/stats/overview`）。

理由：
- 26 个 CRUD 端点与 `training.js` 功能重复、字段冲突、无前端消费者
- 12 个 `/rules/*` 端点只读、无副作用，若未来前端需要按规则文件驱动枚举，可直接复用
- 删除后 `training_records` 双表语义问题（D6）自动解决——只剩 `training.js` 唯一写入入口

**方案 B**：保留全部 38 端点，但需修复字段映射（D6）和 `location` 列缺失，并补齐前端消费。工作量大，且与 `training.js` 功能高度重复。

**本次提示词按方案 A 执行。**

### 5.3 修改项 R4：前端枚举动态化（P2）

**文件**：`安全看板vben/apps/web-antd/src/api/hse/training.ts`、`src/views/training/index.vue`、`src/views/training/ledger/index.vue`、`src/views/training/plans/index.vue`

**问题**：前端硬编码业务枚举（如 `type:'safety'`、`result:'合格'/'不合格'`、`status:'draft'/'ongoing'`），与 `training-assessment-rule.json` 中定义的标准值不一致（规则文件定义 `trainingTypes: new_employee/regular/special/...`、`assessmentGrades: pass/fail`、`planStatusFlow: draft/approved/in_progress/completed/cancelled`）。

**修复**：

1. 在 `training.ts` 中新增规则 API 函数：
```typescript
// ========== 规则配置（从 training-assessment-rule.json 动态拉取） ==========
export interface TrainingTypeRule {
  code: string;
  name: string;
  requiredHours?: number;
  cycleType?: string;
}

export interface PlanStatusRule {
  code: string;
  name: string;
  color?: string;
}

export interface AssessmentGradeRule {
  code: string;
  name: string;
  minScore: number;
  maxScore: number;
}

export async function getTrainingTypes() {
  return requestClient.get<TrainingTypeRule[]>('/training-assessment/rules/training-types');
}

export async function getPlanStatusFlow() {
  return requestClient.get<PlanStatusRule[]>('/training-assessment/rules/plan-status-flow');
}

export async function getAssessmentGrades() {
  return requestClient.get<AssessmentGradeRule[]>('/training-assessment/rules/assessment-grades');
}
```

2. 在 `index.vue` 中：
   - 将 `<SelectOption>` 的硬编码培训类型（`safety/skills/emergency/induction/regular`）改为从 `getTrainingTypes()` 动态拉取并渲染
   - 将 `getTypeColor/getTypeText` 函数改为基于规则数据动态映射
   - 将状态枚举（`draft/planned/ongoing/completed/cancelled`）改为从 `getPlanStatusFlow()` 动态拉取

3. 在 `ledger/index.vue` 中：
   - 将培训结果枚举（`合格/不合格`）改为从 `getAssessmentGrades()` 动态拉取

4. 在 `plans/index.vue` 中：
   - 将状态枚举（`draft/approved/in_progress/completed/cancelled`）改为从 `getPlanStatusFlow()` 动态拉取

> **注意**：规则文件 `training-assessment-rule.json` 声明"只读影子数据，不参与业务计算"，此处仅用于前端 UI 枚举渲染，不修改规则文件。若规则文件中的 code 值与数据库历史数据不一致，前端需做兼容映射（同时展示规则定义值和数据库实际值）。
