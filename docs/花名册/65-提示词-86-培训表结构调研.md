# 提示词-86 培训表结构调研

> 调研日期：2026-07-31
> 范围：`employee_induction_training`、`employee_training_status`、`position_safety_profile`、以及**实际被前端读取的 `training_records`**
> 方法：`information_schema` + `pg_constraint` + 后端 `server/routes/training.js` 路由核对

---

## 一、关键发现（提示词假设 ≠ 实际）

提示词指定 `employee_induction_training`、`employee_training_status` 为"0 行导致模块不可用"的两张表。实测结论：

| 表 | 行数(active) | 是否被前端/后端读取 |
|----|:---:|----|
| `training_records` | **109**（补录前 104） | ✅ 是 —— 培训模块实际数据表 |
| `v_training_records` | 109 | ✅ 视图（基于 training_records） |
| `training_plans` | 1 | ✅ 培训计划 |
| `employee_induction_training` | 0（补录后 5） | ❌ 否 —— 遗留/死表，后端 training.js **无任何引用** |
| `employee_training_status` | 0（补录后 5） | ❌ 否 —— 遗留/死表，后端 training.js **无任何引用** |
| `position_safety_profile` | 0 | ❌ 否 —— P2，依赖上游模型，本次不在范围 |

**结论**：培训模块的实际数据存储在 `training_records`（已 104 行，功能正常）。`employee_induction_training` / `employee_training_status` 是早期遗留表，前端 `views/training/new-employee`、`stats` 等页面均经 `GET /api/training/...` 读取 `training_records`，**不读取这两张表**。

### 新员工培训视图的真实缺口
- 前端 `views/training/new-employee/index.vue` → `LedgerApi.getNewEmployeeList` → `GET /api/training/new-employees`
- 后端 `training.js:564` `createTrainingSubRoute('new-employees', '新员工', 'records')`，过滤条件 `training_records.training_type = '新员工'`
- 补录前 `training_records` 无 `training_type='新员工'` 记录 → **该视图空表（total=0）**，这才是"培训模块页面不展示数据"的真正原因。
- 本任务已补 5 条 `training_type='新员工'` 记录，使该视图可正常展示。
