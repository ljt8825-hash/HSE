## 2. 修复清单与逐项详情

### 修复 1：应急事件列表接口（前端 1 行）✅

- **文件**：`安全看板vben/apps/web-antd/src/views/emergency/events/index.vue`
- **根因**：列表请求写 `request.get(API_BASE)`，其中 `API_BASE='/emergency/events'`，但后端路由为 `GET /emergency/events/list`（见 `server/routes/emergency.js:1875`）。前端调 `/emergency/events` → 404。
- **改动**：仅改列表取数调用（保留 `API_BASE` 供 stats/crud 使用，避免破坏 `/stats`、`/:id` 路径）：
  ```js
  // 修改前
  const r: any = await request.get(API_BASE, { params: { ...search.form, page, pageSize } });
  return { list: r?.data?.list || [], total: r?.data?.total || 0 };
  // 修改后
  const r: any = await request.get('/emergency/events/list', { params: { ...search.form, page, pageSize } });
  return { list: r?.list || [], total: r?.total || 0 };
  ```
  > 同时按修复 2 模式将 `r?.data?.list` 改为 `r?.list`（响应解包，见下）。

### 修复 2：应急模块响应解包统一（5 视图）✅

- **根因**：`src/api/request.ts` 配置 `responseReturn:'data'` + `defaultResponseInterceptor({codeField:'code',dataField:'data',successCode:0})`，客户端返回**解包后的内层数据** `{list,total,...}`，但应急模块 5 个视图仍按信封结构 `r.code===0 → r.data.list` 取数，导致列表恒空。
- **涉及文件**（均在 `src/views/emergency/` 下）：
  - `events/index.vue`（useDataTable fetchFn + fetchStats）
  - `teams/index.vue`（fetchFn + fetchStats）
  - `materials/index.vue`（fetchFn + fetchStats）
  - `drills/index.vue`（fetchData + fetchPlans + fetchStats）
  - `plans/index.vue`（fetchData + fetchStats）
- **改动模式**：
  ```js
  // 列表（useDataTable 型：events/teams/materials）
  return { list: r?.list || [], total: r?.total || 0 };
  // 列表（手动型：drills/plans）
  dataList.value = r.list || []; total.value = r.total || 0;
  // 下拉选项（drills 的 planOptions）
  planOptions.value = r.list || [];
  // 统计（5 视图统一）
  const r = await request.get(`${API_BASE}/stats`); stats.value = r || {};
  ```
  > 实际根因更深一层：events/teams/materials 不仅解包错误，**列表路径也缺 `/list` 后缀**（同修复 1 类问题）——后端 `teams`/`materials` 列表路由分别为 `/emergency/teams/list`、`/emergency/materials/list`（见 `emergency.js:1532`、`:1284`），前端原调 `/emergency/teams`、`/emergency/materials` 返回 `code:-100`。故对 teams/materials 同样仅改列表取数路径为 `/emergency/teams/list`、`/emergency/materials/list`（保留 `API_BASE` 供 stats/crud）。drills/plans 列表路径本已正确（`/emergency/drills`、`/emergency/plans`），仅解包需修。

### 修复 3：/violations 路由白名单（前端 1 处）✅

- **文件**：`安全看板vben/apps/web-antd/src/router/routes/index.ts`
- **根因**：`hse-violations.ts`（定义 `path:'/violations'`）未加入 `dynamicRouteFiles` 白名单，仅 `hse-01~hse-11` 等被导入，致 `/violations` 404。
- **改动**：白名单数组追加 `'./modules/hse-violations.ts'`。
- **冲突核查**：`/violations` 与既有 `/site/violation`（现场管理→三违管理，890 条数据）路径不同、互不影响，无冲突，两者并存。

### 修复 4：档案列表（无需修复）✅ 跳过

- **判定**：提示词-73 误判。档案功能由花名册列表「历史」按钮 → `EmployeeHistoryDrawer`（员工档案/培训记录）正常提供，无独立列表页需求。本项跳过，符合提示词红线。

### 修复 5：考核列表端点修正（前端 1 行 + 后端补充路由）✅（含对提示词的偏离决策）

- **前端文件**：`安全看板vben/apps/web-antd/src/api/hse/goals.ts`
  ```js
  // 修改前
  export function getAssessmentList(params) {
    return requestClient.get('/objectives/responsibility', { params }); // 错指目标责任
  }
  // 修改后（端点指向既有后端考核分析系统）
  export function getAssessmentList(params) {
    return requestClient.get('/hse/assessment', { params });
  }
  ```
- **后端文件**：`server/routes/hse-assessment.js`（挂载前缀 `/api/hse/assessment`），在 `module.exports` 前补充 `GET /` 列表路由，查询 `assessment_records` 表并映射为前端 `AssessmentItem` 形状（year/quarter 由 `assessment_date` 推导，department←dept_name，person←employee_name，level←grade 等），返回 `{code:0, data:{list,total,page,pageSize}}`。

**⚠️ 对提示词原文的偏离决策（已验证必要）**：
1. **前端端点**：提示词写 `/objectives/assessment`，但后端考核分析系统挂载于 `/api/hse/assessment`，且无任何 `/api/objectives/assessment` 路由（核查 `server/routes/objectives.js` 仅有 `/objectives`、`/responsibilities`、`/committees`、`/org-personnel`、`/stats`，无 `/assessment`）。若机械按提示词改前端为 `/objectives/assessment` 而后端加在 `hse-assessment.js`，路径永不相交 → 仍 404。故前端改指 **`/hse/assessment`** 以匹配被允许修改的唯一后端文件 `hse-assessment.js`，符合「仅改 1 个后端文件」红线且使列表真实可达。
2. **后端数据表**：提示词假设 `hse_assessment` 表；实勘 `assessment_records` 才是考核记录表（`training-assessment.js` 已在用）。`assessment_records` 当前 **0 行**，故考核列表加载后显示「暂无数据」属正确行为，非空表异常。

## 5. 残留 / 已知问题（非本次引入，建议后续独立跟进）

1. **统计卡片字段命名不一致（5 视图）**：各视图模板读 `stats.year_total`/`stats.handling`（应急事件）、`stats.member_count`/`stats.full_time`（队伍）、`stats.yearTotal`/`stats.completionRate`（演练）等，但后端 stats 接口返回 `total,byType,byStatus,byLevel`、`total,memberCount,byType` 等，字段名不匹配。本次已将 `if(r.code===0) stats.value=r.data.stats` 改为 `stats.value=r`（去除恒假守卫，使名称一致的字段如物资 `total/expiring/expired`、预案 `total/published/pendingReview` 可渲染），但名称不一致的统计卡片仍为空。此为独立的前后端契约问题，超出本次 5 项异常范围。
