## 2. 任务 A：回填脚本增强 v1.2

**文件**：`server/scripts/backfillEmployeeId.cjs`（整体重写为配置驱动引擎）

### 2.1 覆盖范围扩展（2 表 → 5 表 / 6 个目标外键列）

```js
const BACKFILL_TARGETS = [
  { table:'training_records',     targetCol:'employee_id',          idCardCol:'id_card',           nameCol:'name' },
  { table:'violation_records',    targetCol:'violator_id',          idCardCol:'violator_id_card',  nameCol:'violator_name' },
  { table:'hazards',              targetCol:'checker_id',           idCardCol:null,                nameCol:'checker' },
  { table:'hazards',              targetCol:'fixer_id',             idCardCol:null,                nameCol:'fixer' },
  { table:'accidents',            targetCol:'handler_id',           idCardCol:null,                nameCol:'handler' },
  { table:'emergency_plans',      targetCol:'responsible_person_id',idCardCol:null,               nameCol:'responsible_person' },
];
```

### 2.2 身份证号匹配（三违增强）
`violator_id_card` 列已存在时，先 `hashSensitive()` 比对 `employee.id_card_hash`；无匹配再降级姓名唯一匹配。training 保留原 `id_card` 哈希路径。

### 2.3 批量查询优化
- 姓名映射：`SELECT id, name FROM employee WHERE name = ANY($1)` 一次取全，构建唯一 `nameToId`（重名删除）。
- 身份证映射：`id_card_hash = ANY($1)` 一次取全，构建 `hashToId`（重复 hash 标记为歧义跳过）。
- 替代原逐条 `SELECT`（原 2600+ 次往返 → 每表 2 次批量查询）。

### 2.4 事务包裹 + 结果持久化
- 全量回填包裹在单个 `BEGIN / COMMIT`，异常 `ROLLBACK`。
- `backfill_log` 表 `CREATE TABLE IF NOT EXISTS`（幂等 DDL），每次执行写入一行（table/column/空值数/匹配数/更新数/跳对数/dry_run 标志）。

### 2.5 安全机制（保留 v1.0）
- 生产环境 `NODE_ENV=production` 且无 `--dry-run` → 打印拦截横幅并 `process.exit(1)`。
- `--dry-run`：仅统计、不 UPDATE、不 INSERT 日志行（仍确保 `backfill_log` 表存在）。
