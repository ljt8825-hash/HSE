## 0. 背景

提示词-62 修复了 `GET /employees` 的行重复问题（`employee_assignment` JOIN 缺 `is_primary` 过滤）。执行报告中明确标记了同类残留：

> `GET /departments/:id/employees` 同样使用了不完整的 `LEFT JOIN employee_assignment ea ON ... AND ea.is_current = true`（缺 `is_primary`），存在完全相同的行重复风险。

---

## 1. 根因分析

### 1.1 当前代码（`server/routes/hse-employee.js`，L1236-1241）

```js
const conditions = [
  'e.is_deleted = false',
  'ea.is_current = true',
  'ea.is_deleted = false',
  'ou.is_deleted = false',
];
```

**缺失**：`ea.is_primary = true`。

### 1.2 对比

| 端点 | ea.is_current | ea.is_deleted | ea.is_primary | 状态 |
|------|:---:|:---:|:---:|------|
| `GET /employees` (L587) | ✅ | ✅ (62 修复) | ✅ (62 修复) | 已修复 |
| `GET /departments/:id/employees` (L1238) | ✅ | ✅ | ❌ | 待修复 |

`is_current = true` 仅过滤了"当前任职"，但一个员工可能同时有多条当前任职（主职 + 兼岗），不加 `is_primary = true` 会导致 COUNT 和数据查询同时膨胀。

---

## 2. 修复方案

**文件**：`server/routes/hse-employee.js`，`GET /departments/:id/employees`

**改动**：L1236-1241 的 conditions 数组新增一行。

```diff
  const conditions = [
    'e.is_deleted = false',
    'ea.is_current = true',
    'ea.is_deleted = false',
+   'ea.is_primary = true',
    'ou.is_deleted = false',
  ];
```

**仅 1 行**，该 conditions 数组同时被 COUNT 查询（L1252-1258）和数据查询（L1262-1275）的 WHERE 子句引用，一处修改即可覆盖两处。
