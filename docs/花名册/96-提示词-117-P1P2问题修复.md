## P1-5: 路由重复定义，权限不一致

### 根因分析

`departments.vue` 被两个路由文件同时指向，但权限配置不同：

| 路由文件 | 路由路径 | 菜单 | 权限 |
|----------|----------|------|------|
| `hse-07-personnel.ts:33` | `/personnel/departments` | "人员管理" | 仅 `admin` |
| `hse-employee.ts:36` | `/hse/employee/departments` | "人员主数据"（hideInMenu） | `admin` + `safety_manager` |

问题：
- `safety_manager` 角色在"人员管理"菜单中看不到"组织管理"，但可以通过直接 URL 访问 `/hse/employee/departments`
- 两个路由指向同一组件但权限不同，维护时容易遗漏同步

### 修复方案

**方案 A（推荐）：统一旧路由权限，使两个入口权限一致**

修改 `hse-07-personnel.ts` 中"组织管理"路由的 authority：

```typescript
{
  meta: {
    title: '组织管理',
    icon: 'lucide:building',
    authority: ['admin', 'safety_manager'],  // 从 ['admin'] 改为 ['admin', 'safety_manager']
  },
  name: 'PersonnelDepartments',
  path: '/personnel/departments',
  component: () => import('#/views/hse/employee/departments.vue'),
},
```

同时检查"岗位管理"路由是否需要相同处理。

### 影响范围
- `hse-07-personnel.ts` 第 30 行：authority 数组

## P1-6: 编辑表单缺少 manager_id / safety_manager_id 输入控件

### 根因分析

`handleEdit` 函数（`departments.vue:518-531`）读取了 `record.manager_id` 和 `record.safety_manager_id` 并写入了 `formData`：

```typescript
Object.assign(formData, {
  // ...
  manager_id: record.manager_id,
  safety_manager_id: record.safety_manager_id,
  // ...
});
```

但表单模板（`departments.vue:209-274`）中**完全没有这两个字段的输入控件**。用户无法查看或修改部门负责人和安全负责人。

### 修复方案

在编辑表单中增加两个人员选择器（位于"编制人数"和"排序"之间）：

```html
<a-form-item label="部门负责人">
  <a-select
    v-model:value="formData.manager_id"
    placeholder="请选择部门负责人"
    allow-clear
    show-search
    :filter-option="filterEmployeeOption"
    style="width: 100%"
  >
    <Select.Option
      v-for="emp in employeeOptions"
      :key="emp.id"
      :value="emp.id"
    >
      {{ emp.name }} ({{ emp.employee_code || emp.id }})
    </Select.Option>
  </a-select>
</a-form-item>
<a-form-item label="安全负责人">
  <a-select
    v-model:value="formData.safety_manager_id"
    placeholder="请选择安全负责人"
    allow-clear
    show-search
    :filter-option="filterEmployeeOption"
    style="width: 100%"
  >
    <Select.Option
      v-for="emp in employeeOptions"
      :key="emp.id"
      :value="emp.id"
    >
      {{ emp.name }} ({{ emp.employee_code || emp.id }})
    </Select.Option>
  </a-select>
</a-form-item>
```

需要新增：
1. `employeeOptions` ref：在弹窗打开时从已有的员工 API 加载员工下拉列表
2. `filterEmployeeOption` 函数：支持按姓名搜索

**简化方案**：如果加载全部员工列表太重，可以使用 `a-input` 直接输入员工 ID（后期可替换为员工选择器组件）。

### 影响范围
- `departments.vue` 模板：新增两个 a-form-item
- `departments.vue` script：新增 employeeOptions 加载逻辑

## P2-10: 同一张表不同接口返回格式不一致

### 根因分析

| 接口 | 返回格式 | 原因 |
|------|----------|------|
| `GET /departments/tree` | snake_case | 注释标注"前端 tree field-names 用 snake_case" |
| `GET /departments` | camelCase | `camelKeys(result.rows)` |

同一数据源（`department` 表），两个接口返回不同格式。前端 `DeptNode` 类型定义使用 snake_case（`dept_code`、`short_name`、`parent_id`），与 tree 接口一致，但 `getDeptList()` 返回 camelCase 会导致类型不匹配。

### 修复方案

**检查 `getDeptList()` 的调用方**。如果前端无实际调用方（全仓搜索确认），则标记为 dead code 并添加 `@deprecated` 注释。

如果存在调用方，统一为 snake_case 返回（与 tree 接口一致），修改 `hse-employee.js:1277`：

```javascript
res.json(success(result.rows, '查询成功'));  // 移除 camelKeys 包装
```

> 注意：此修改涉及后端路由，但属于格式统一修复，不影响 API 签名。

### 影响范围
- 确认 `getDeptList()` 调用方（前端 `getDeptList` API 函数）
- 后端 `hse-employee.js:1277`

## P2-13: 树搜索不支持大小写不敏感

### 根因分析

`filterTree` 函数（`departments.vue:408-430`）：

```typescript
const matched =
  node.name.includes(keyword) ||
  node.dept_code?.toLowerCase().includes(keyword.toLowerCase());
```

`dept_code` 做了大小写不敏感处理，但 `name` 是精确 `includes`，大小写敏感。中文场景影响不大，但若部门名称含英文则有问题。

### 修复方案

统一为大小写不敏感：

```typescript
const matched =
  node.name.toLowerCase().includes(keyword.toLowerCase()) ||
  node.dept_code?.toLowerCase().includes(keyword.toLowerCase());
```

### 影响范围
- `departments.vue` 第 420 行

## P2-14: 缺少软删除恢复功能

### 根因分析

后端删除是软删除（`UPDATE department SET is_deleted = true`），但前端：
- 树加载时默认不传 `includeInactive` 参数，后端过滤 `status='active'`，停用节点被隐藏
- 即使 `includeInactive=true` 加载了停用节点，也没有"恢复"按钮

### 修复方案

在编辑弹窗中，如果当前部门状态为 `inactive`（停用），将"状态"单选框改为可操作，允许用户将状态改回 `active` 实现"恢复"。

当前代码已支持编辑 status 字段（`handleEdit` 中读取了 `record.status`），所以只需确保：
1. `includeInactive=true` 时能加载已停用节点（当前已支持）
2. 编辑弹窗中的状态单选框对停用节点可操作（当前已支持）

**无需额外修改代码**。本问题记录为"已实现但用户不易发现"——可在后续 UX 优化中增加提示。

## P2-17: DeptFormData 类型缺少 status 字段

### 根因分析

`employee.ts:130-142`：

```typescript
export interface DeptFormData {
  dept_code: string;
  name: string;
  short_name?: string;
  parent_id?: number | null;
  level?: number;
  township?: string;
  manager_id?: number;
  safety_manager_id?: number;
  headcount?: number;
  sort_order?: number;
  description?: string;
  // 缺少: status?: string;
}
```

前端 `departments.vue:339` 为此做了类型补丁：

```typescript
const formData = reactive<EmployeeApi.DeptFormData & { status?: string }>({...});
```

### 修复方案

在 `DeptFormData` 接口中补充 `status` 字段：

```typescript
export interface DeptFormData {
  dept_code: string;
  name: string;
  short_name?: string;
  parent_id?: number | null;
  level?: number;
  township?: string;
  manager_id?: number;
  safety_manager_id?: number;
  headcount?: number;
  sort_order?: number;
  status?: string;       // 新增
  description?: string;
}
```

然后移除 `departments.vue:339` 的交叉类型补丁：

```typescript
const formData = reactive<EmployeeApi.DeptFormData>({...});
```

### 影响范围
- `employee.ts` 第 130-142 行：补充 `status` 字段
- `departments.vue` 第 339 行：移除 `& { status?: string }`

## P2-18: 部门树字段名在组件间不一致

### 根因分析

| 组件 | field-names |
|------|------------|
| `departments.vue:327-331` | `{ children: 'children', title: 'name', key: 'id' }` |
| `OrgTransferModal.vue:27` | `{ label: 'title', value: 'value', children: 'children' }` |

`OrgTransferModal` 的 `field-names` 使用 `{ label: 'title', value: 'value' }`，但它的 `convertDeptTree` 函数（`OrgTransferModal.vue:134-147`）将数据转换为了 `{ value, title, children }` 格式。所以实际是：数据先被转换为 `{ value, title, children }`，然后 `field-names` 再映射回 `{ label: 'title', value: 'value' }`。

这多了一层不必要的转换。但功能正常，**暂不修改**，仅记录为技术债务。
