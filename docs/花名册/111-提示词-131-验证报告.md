## 2. ⚠️ F1 方案变更说明（重要）

### 2.1 按提示词字面执行时遇到的硬阻塞

提示词 §4.1 要求给 `insurance.js` `/overage` 的 POST/PUT 加 `encryptMiddleware('id_card')`。按字面实现后，运行时探针立即暴露阻塞：

```
POST /api/insurance/overage      → code=-1  "对于可变字符类型来说，值太长了(32)"
POST /api/over-age-personnel     → code=-1  "对于可变字符类型来说，值太长了(32)"
```

根因经三方核实：

| 核查项 | 实测结果 |
|--------|----------|
| `over_age_personnel.id_card` 列定义 | `character varying(32)` |
| `encrypt('110101199003071234')` 输出 | `ENC:6hplJIggl19RYi/mJbwvDwXLP0A/...`，**长度 68** |
| 存量数据形态（1300 行） | `max(length(id_card))=18`，`LIKE 'ENC:%'` 命中 **0 行**，即**全部为明文** |

**三个关键推论：**

1. 密文 68 字符 > 列宽 32 → **加密写入在物理层面不可能成功**。
2. `over-age-personnel.js` 虽然早已挂载 `encryptMiddleware`，但只要请求体带 `id_card`，POST/PUT 就**恒定 500 失败** —— 这是诊断阶段（提示词-130）未暴露的**隐藏 P0 写入 bug**，因为诊断为只读静态分析。
3. 存量 1300 行明文说明历史数据由导入脚本/迁移直写数据库，绕过了路由中间件。所谓"加密"一直只是纸面配置。

同时，提示词 §3 红线明确 **"禁止修改数据库表结构"**。

### 2.2 方案影响面评估

| 维度 | 密文统一（扩列 + 迁移） | 明文统一 + 展示脱敏 |
|------|------------------------|---------------------|
| 表结构变更 | 必须 `ALTER COLUMN id_card TYPE varchar(128)` —— **触碰红线** | 无 |
| 存量迁移 | 1300 行明文 → 密文，需全库 `pg_dump` 备份 | 无 |
| 写入点改造 | 5 处（`demo-data.js` / `hse-employee.js` / `import.js` / `insurance.js` / `over-age-personnel.js`） | 0 处 |
| 身份证模糊搜索 | **彻底失效**（`insurance.js:993` 与 `over-age-personnel.js:39` 的 `id_card ILIKE` 无法匹配密文） | 保持可用 |
| PII 防护 | 存储层加密 | 展示层脱敏（F2）+ 导出脱敏（F4） |

### 2.3 最终采用方案（已确认）

**明文统一 + 展示脱敏**：

- **移除**两条路由的 `encryptMiddleware`（写入侧统一为明文）；
- **保留** `decryptMiddleware`（读取侧对明文为 no-op，`isEncrypted()` 判定不命中即原样返回），为未来扩列后的密文/明文混合态提供平滑兼容；
- PII 防护职责下移至 F2（前端表格/详情脱敏）与 F4（导出 CSV 脱敏）。

**F1 的根本目标"跨路由读写不互相破坏"完全达成**，并**顺带修复了 `over-age-personnel.js` POST/PUT 本就存在的写入失败 bug**。

代码中已就地留下说明性注释，避免后人误判为"漏加密"：

```javascript
// server/routes/insurance.js
// F1（提示词-131）：over_age_personnel.id_card 为 varchar(32)，而密文长度 68，物理上无法存储；
// 且存量 1300 行全部为明文（历史由导入脚本绕过中间件写入）。在"禁止修改表结构"红线下，
// 统一策略为：写入不加密（两条路由一致），读取仍挂 decryptMiddleware（对明文为 no-op，
// 兼容未来扩列后的密文混合态）。PII 防护由前端展示脱敏 + 导出脱敏承担。
const { decryptMiddleware, decryptResult } = require('../middleware/encryption');
```

## 3. 各修复项实现明细

### 3.1 F1 — 加解密策略统一（P0）

**文件**：`server/routes/insurance.js`、`server/routes/over-age-personnel.js`

| 路由 | 修改前 | 修改后 |
|------|--------|--------|
| `GET /overage` | 无中间件 | `decryptMiddleware('id_card')` |
| `GET /overage/export` | 无中间件，且**被 `/overage/:id` 遮蔽不可达** | `decryptMiddleware('id_card')` + **前移至 `:id` 之前** + 手工 `decryptResult()` |
| `GET /overage/:id` | 无中间件 | `decryptMiddleware('id_card')` |
| `POST /overage` | 无中间件 | 保持不加密（与对侧统一） |
| `PUT /overage/:id` | 无中间件 | 保持不加密（与对侧统一） |
| `POST /`（over-age-personnel） | `encryptMiddleware` → **恒定写入失败** | 移除加密 → 可正常写入 |
| `PUT /:id`（over-age-personnel） | `encryptMiddleware` → **恒定写入失败** | 移除加密 → 可正常写入 |

**附带修复 —— Express 路由遮蔽**：`GET /overage/export` 原注册在 `GET /overage/:id` **之后**，`:id` 会捕获字面量 `export`，导致导出端点永久不可达。已将 export 块整体前移。

**附带修复 —— `res.send` 绕过解密拦截器**：`decryptMiddleware` 仅包装 `res.json`，而 CSV 导出使用 `res.send`。已在 handler 内显式调用：

```javascript
data = decryptResult(r.rows, ['id_card']).map(formatOverage);
```

### 3.3 F3 — `over_age_id` 主键贯通（P1）

**后端**（`server/routes/hse-employee.js`）：`auto-list` 与 `auto/:id` 均补充 LEFT JOIN 子查询：

```sql
LEFT JOIN (
  SELECT MAX(id) AS id, personnel_id
  FROM over_age_personnel
  WHERE is_deleted = false
  GROUP BY personnel_id
) oap ON oap.personnel_id = e.id
```

SELECT 列表新增 `oap.id AS over_age_id`。使用 `MAX(id)` 保证一对多时取最新建档记录，避免 JOIN 放大行数。

**前端**：`OverAgeAutoItem` 接口新增 `over_age_id?: number | null`；附件/版本查询主键切换：

```typescript
const bizId = record.over_age_id || record.id;   // index.vue:624 / :663 / :679
```

### 3.4 F4 — 导出口径对齐（P1）

**后端新增** `GET /api/hse/employee/over-age/auto-export`（注册于 `auto/:id` 之前，规避路由遮蔽）：

- 复用 auto-list 的查询与筛选逻辑（`keyword` / `gender`），保证**导出内容 == 页面展示**；
- 调用 `decryptResult(rows, ENCRYPT_FIELDS)` 后**再做脱敏**，输出 `Content-Type: text/csv; charset=utf-8`。

**前端** `handleExport()` 改调 `exportOverAgeAutoList()`，并按既有约定（`request` 客户端 blob 响应直返 Blob）先校验 `blob.type`，非 CSV 时解析 JSON 错误提示。

### 3.5 F5 — 编辑弹窗真实持久化（P1）

- **移除**「新增人员」按钮（子系统A 数据源为 `employee` 表实时计算，不应在此新增）；
- **重构**编辑弹窗为「保险管控」表单（管控类型 / 实际保险 / 工伤险 / 雇主险 / 合规 / 优化状态 / 备注）；
