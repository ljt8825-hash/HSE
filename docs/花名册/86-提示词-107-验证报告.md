## 2. Task 2：组织管理模块检查（O1–O4）

### 2.1 模块数据源澄清（关键）

提示词假设"组织管理页"直接展示 `hse_org_unit` 表。经核查，二者职责不同：

- **可见的组织管理页**（`departments.vue`）数据来自 **`department` 表**（组织树）。
- **`hse_org_unit` 表**是花名册导入时 `matchOrgUnit` 的后端匹配基准（导入匹配逻辑位于 `hse-employee-import-v2.js`，独立模块）。
- 二者通过 `department.name = hse_org_unit.org_name` 关联（代码 `hse-employee.js` 第 1197–1201 行）。

因此数据完整性分两部分核验（见 §2.4）。

### 2.2 列表字段显示 / camelKeys 映射（O1、O2）

**实测（重启后端后 `GET /departments/tree`）：**

```json
first item keys: id, dept_code, name, short_name, parent_id, level, path,
                 township, manager_id, safety_manager_id, headcount,
                 sort_order, status, description, children, employee_count, actual_headcount
```

前端 `departments.vue` 树配置：
- `field-names = { children:'children', title:'name', key:'id' }` → `id` / `name` / `children` 一致 ✅
- 标题插槽 `#title="{ name, dept_code, status }"` → 依赖 `dept_code`、`status`
- `filterTree()` 读取 `node.name`、`node.dept_code`、`node.children`

**修复前问题**：后端对树节点执行 `camelKeys`，返回 `deptCode`（非 `dept_code`），导致
- 树节点标题的 `(部门编码)` 始终显示空括号；
- 按"部门编码"搜索永远无匹配。

**已修复（后端，最小改动）**：`hse-employee.js` `/departments/tree` 不再对树节点套 `camelKeys`，直接返回 snake_case，与前端 `field-names` / 标题插槽 / 搜索逻辑完全一致。
→ **O2 已修复**（其余字段 `id/name/children/status` 在 camelCase 与 snake_case 下键名不变，本就正常）。

### 2.3 搜索 / 筛选（O3）

## 3. Task 3：岗位管理模块检查（P1–P4）

### 3.1 列表字段显示 / camelKeys 映射（P1、P2）—— **本次最严重问题**

**修复前实测（`GET /positions`）：**

```json
first item keys: id, positionCode, name, deptId, jobCategory, isSpecialPost,
                 isSafetyCritical, safetyDuties, sortOrder, status, deptName
```

前端 `positions.vue` 的列与插槽：

| 前端引用（dataIndex / bodyCell / computed） | 后端修复前返回 | 结果 |
|---|---|---|
| `dataIndex:'position_code'` | `positionCode` | ❌ 列空 |
| `record.dept_name` | `deptName` | ❌ 显示 `-` |
| `record.job_category` | `jobCategory` | ❌ 显示 `-` |
| `record.is_special_post` | `isSpecialPost` | ❌ 恒显示"否" |
| `record.is_safety_critical` | `isSafetyCritical` | ❌ 恒显示"否" |
| `record.safety_duties` | `safetyDuties` | ❌ 显示 `-` |
| `record.name` / `record.status` | `name` / `status` | ✅ 正常（键名不变） |

**结论**：与提示词-101/102 同源的 **camelKeys 键名不匹配** bug——后端 `camelKeys` 把 snake_case 转成 camelCase，而前端 `dataIndex`/`bodyCell` 全为 snake_case，导致 6/8 列表列渲染为空或错值。

**连带影响（搜索/筛选 P3）**：`filteredList` 计算属性读取 `item.job_category`、`item.is_special_post`（均为 undefined）→ 按"岗位类别""特种作业"筛选 **完全失效**（恒不过滤）。

**已修复（后端，最小改动）**：`hse-employee.js` `GET /positions` 移除 `.map(camelKeys)`，直接返回 SQL 原始 snake_case。

**修复后实测：**

```json
first item keys: id, position_code, name, dept_id, job_category, is_special_post,
                 is_safety_critical, safety_duties, sort_order, status, dept_name
```

✅ 与前端 `dataIndex`/`bodyCell`/`filteredList` 完全对齐 → **P1、P2、P3 一并修复**。
