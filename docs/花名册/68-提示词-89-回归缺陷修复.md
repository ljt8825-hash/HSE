## 二、缺陷详情

### 缺陷1：驾驶员风险中心列表 500（P0）

**现象**：`GET /api/hse/driver-risk-center/drivers` → HTTP 500

**根因**：PostgreSQL 报错「在查询列表中必须出现 SELECT DISTINCT, ORDER BY 表达式」——典型 PG 严格模式下 `SELECT DISTINCT ... ORDER BY` 列不在 SELECT 列表中的错误。

**定位方法**：
1. 搜索 `server/routes/hse-driver-risk-center.js` 中 `drivers` 相关路由处理函数
2. 定位含 `SELECT DISTINCT` 的 SQL 查询
3. 对比 `ORDER BY` 列与 `SELECT` 列，找出不一致处
4. 修复：将 ORDER BY 列加入 SELECT 列表，或调整 DISTINCT 逻辑

**影响范围**：仅「驾驶员风险中心 → 驾驶员列表」子页；同模块 `/overview` 已确认 200。

### 缺陷2：matchPosition 哨兵不一致（P1）

**现象**：提示词-88 导入回归验证中，`matchPosition` 在 `rawDept` 含「片区」时将 `cond` 置为 `*片区`，但 DB 中 `employee_position_mapping_rule.condition_dept` 实际值为 `片区`（无星号）。

**根因**：提示词-80 中引入的哨兵值（`*`前缀）与数据库实际存储值不一致，导致条件分支 `cond === '*片区'` 永远不命中，回退到 `condition_dept IS NULL` 的兜底规则。

**当前影响**：`司机` 在 `*片区` 和 `NULL` 两种条件下均映射 `position_id=1398`（垃圾收运车驾驶员），结果一致，故无功能影响。

**风险**：若未来新增仅在 `片区` 条件下生效的岗位映射规则（如"片区安全员"），该哨兵不一致会导致新规则不生效。

**定位方法**：
1. 搜索 `server/routes/hse-employee-import-v2.js` 或匹配逻辑所在文件中的 `matchPosition` 函数
2. 搜索 `*片区` 哨兵值
3. 对比 `employee_position_mapping_rule` 表中 `condition_dept` 的实际值
4. 统一哨兵写法：去掉 `*` 前缀，或改为与 DB 实际值一致的标识

### 缺陷3：training_records 统计信息过期（P3）

**现象**：`pg_stat_user_tables` 中 `training_records` 的 `last_autoanalyze` 为空，导致 `pg_stat` 误报行数（仅5行，实际112行）。

**修复**：执行 `ANALYZE training_records` 刷新规划器统计。

**注意**：此为非阻塞维护项，不影响功能（API 以显式 `COUNT(*)` 为准），但建议在本次修复中顺手处理。
