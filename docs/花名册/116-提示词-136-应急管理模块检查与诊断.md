## 2. 诊断维度（五维度）

### 维度一：前端代码质量
- 检查每个页面是否使用 `Page` 组件（`@vben/common-ui`）
- 检查是否使用 `useDataTable` / `useSearchForm` / `useCrudModal` 托管（符合项目规范）
- 检查是否使用 Ant Design Vue（非 Element Plus）
- 检查 TypeScript 类型定义完整性
- 检查是否有硬编码的业务规则、阈值、枚举
- 检查 `vue-tsc --noEmit --skipLibCheck` 本模块相关文件有无 TS 错误
- 检查 `index.vue`（多 Tab 多 CRUD 范例）是否与 5 个子页面关系正确

### 维度二：后端代码质量
- 检查 `node --check server/routes/emergency.js` 语法
- 检查路由注册顺序：是否存在 `/:id` 遮蔽字面量路由（如 `/export` 被 `/:id` 捕获）
- 检查权限控制：是否每个端点都有 `requireRole` 声明（参考培训模块 133-D1 同类问题）
- 检查双模式（PostgreSQL + 内存降级）一致性
- 检查 DDL 初始化是否幂等
- 检查备份文件 `emergency.js.bak-pre-v68` 与当前文件的差异（是否有重要逻辑遗漏）

### 维度三：数据流一致性
- 检查前端 API 类型定义与后端返回的字段名是否一致（snake_case vs camelCase）
- 检查 `index.vue`（多 Tab 多 CRUD）中各 Tab 的数据源是否独立
- 检查 5 个子模块的数据是否有交叉依赖或冲突
- 检查导出功能是否与页面展示数据一致
- 检查 `EmployeeName` 组件使用是否符合规范（有 employeeId 时必须用组件，禁止纯文本）

### 维度四：边界与异常
- 检查空状态处理（无数据时的 UI 展示）
- 检查日期边界（预案有效期、演练日期、物资过期日期）
- 检查文件上传边界（预案文件、演练记录附件）
- 检查敏感信息处理
- 检查统计数据的口径一致性

### 维度五：回归检查
- 检查菜单与路由配置（`hse-09-emergency.ts`）是否与 `app.js` 注册一致
- 检查 `index.vue`（多 Tab 页面）与 5 个独立子页面的路由/组件关系
- 检查应急模块是否依赖其他模块的 API（如员工查询、组织查询）
- 检查前端构建：`vite build --mode production` 是否包含本模块所有 chunk
- 检查备份文件 `emergency.js.bak-pre-v68` 是否仍被引用

## 3. 重点检查项

### 3.1 多 Tab 多 CRUD 架构（index.vue）
`views/emergency/index.vue` 是项目文档中明确指定的"多 Tab 多 CRUD 范例"（参考 `docs/code-standards-guide.md`），需重点关注：
- 各 Tab 是否使用独立的 `useDataTable` / `useSearchForm` 实例（planTable vs drillTable）
- 各 Tab 的 CRUD 弹窗是否独立
- 分页键名是否统一用 `current`（不是 `page`）
- 统计卡片是否跨 Tab 聚合

### 3.2 独立子页面与 index.vue 的关系
菜单中 5 个子模块（`/emergency/plans`、`/emergency/drills` 等）各自指向独立的 `index.vue`，但 `views/emergency/index.vue` 也存在。需确认：
- 各子页面是否功能完整（独立 CRUD、搜索、导出）
- `index.vue` 是否仍被路由引用，或已废弃
- 是否存在数据重复加载或路由冲突

### 3.3 备份文件
`emergency.js.bak-pre-v68` 是旧版本备份，需检查：
- 当前 `emergency.js` 是否丢失了备份文件中的重要逻辑
- 备份文件是否仍被任何代码引用
