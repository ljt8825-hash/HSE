## 1. 验证任务 A：浏览器回归验证

在浏览器中逐项验证以下功能点（花名册导入页面 `/personnel/import`）：

### 1.1 工具栏布局

- [ ] "上传花名册"按钮（主按钮，蓝色）正常显示
- [ ] "下载导入模板"按钮（次级按钮，位于"上传花名册"右侧）正常显示，点击后下载 `.xlsx` 文件
- [ ] 右上角"更多操作"下拉菜单正常展开，内含"清空人员信息"（红色/危险样式）
- [ ] 点击"清空人员信息"→ 弹出确认弹窗 → 确认后执行清空

### 1.2 状态标签颜色

- [ ] 批次列表中"待审核"状态标签显示为**橙色 (orange)**
- [ ] "已入库"状态标签显示为**绿色 (success)**
- [ ] "部分入库"状态标签显示为**橙黄色 (warning)**
- [ ] "入库失败"状态标签显示为**红色 (error)**

### 1.3 上传与导入流程

- [ ] 点击"下载导入模板"→ 下载的 Excel 文件包含 13 个标准字段（含"直接上级"列）
- [ ] 上传一个含"直接上级"列的 Excel → 解析成功，批次列表中出现新批次
- [ ] 打开批次详情 → 异常数据列表正常显示（非"暂无数据"）

### 1.4 入库拦截（三态弹窗）

- [ ] **状态 1**：批次中存在未审核（status=pending）数据 → 点击"确认入库" → 弹出警告："存在未审核的异常数据"
- [ ] **状态 2**：全部已审核但无 approved 记录 → 点击"确认入库" → 弹出警告："无可入库数据"
- [ ] **状态 3**：有 approved 记录 → 点击"确认入库" → 弹出确认框，显示具体入库数量（如"即将把 21 条已通过..."）

### 1.5 入库容错（SAVEPOINT 验证）

- [ ] 在 staging 环境构造一个包含 1 条非法数据 + N 条正常数据的批次
- [ ] 执行入库 → 非法行被跳过，正常行入库成功
- [ ] 批次状态 = `partial_completed`
- [ ] 入库结果弹窗中 errors 展示失败行信息（中文提示）
