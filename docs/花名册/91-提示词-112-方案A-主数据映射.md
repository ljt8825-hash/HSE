# 提示词-112: 方案A — 建立 department ↔ hse_org_unit 主数据映射

> 生成时间：2026-08-01
> 专家：Senior Developer（高级开发工程师）吴八哥
> 前置依赖：提示词-108（部门员工子列表SQL修复）、提示词-110（人员管理模块竣工总结）、90-花名册组织管理无数据交互-根因诊断.md
> 性质：架构改造 — 新增数据库迁移 + 修改后端查询/写入逻辑（约5处）
> 改动范围：`server/sql/`（新增1个迁移文件）、`server/routes/hse-employee.js`（约5处修改）
> 不改范围：前端、路由、菜单、其他业务模块、已有表结构

---

## 一、背景

根因诊断报告（90-花名册组织管理无数据交互-根因诊断.md）已确认：

1. `department`（77行，班组级）与 `hse_org_unit`（20行，作业中心级）是两套独立组织模型，无外键、触发器或共享列
2. 员工归属仅绑定 `employee_assignment.org_unit_id → hse_org_unit`，与 `department` 无关
3. 唯一桥梁是名字字符串前缀匹配（`department.name ↔ hse_org_unit.org_name`），精确命中 0/77
4. 组织管理 CRUD 只操作 `department`，从不触碰 `hse_org_unit` 或 `employee_assignment`

用户选择方案A：在 `department` 表增加 `org_unit_id` 外键列，建立 ID 级主数据映射，替代脆弱的字符串前缀匹配。

---

## 二、设计目标

| 目标 | 说明 |
|------|------|
| 增加 `department.org_unit_id` 外键列 | 建立 ID 级关联，替代字符串匹配 |
| 迁移时填充初始映射 | 对已有的 24 个可匹配部门，自动设置 `org_unit_id` |
| 查询端点改用 ID 映射 | `/departments/tree` 和 `/:id/employees` 优先使用 `org_unit_id` 关联，未映射部门降级到前缀匹配 |
| 写入端点自动维护映射 | 新建/改名时自动检测匹配的 `hse_org_unit` 并更新 `org_unit_id` |
| 零破坏 | 不修改前端、路由、菜单、其他业务模块；SQL 变更仅新增列 |

## 三、执行步骤

### Task 1: 数据库迁移（P0）

#### 1.1 创建迁移文件

在 `server/sql/` 下创建 `hse_department_org_unit_mapping_v110_migration.sql`：

```sql
-- ============================================================
-- 迁移名称: department ↔ hse_org_unit 主数据映射
-- 版本: v110
-- 日期: 2026-08-01
-- 说明: 在 department 表增加 org_unit_id 外键列，建立 ID 级关联
-- 依赖: hse_employee_master_v59_migration.sql (department 表)
--        hse_org_center_v68_migration.sql (hse_org_unit 表)
-- ============================================================

BEGIN;

-- Step 1: 添加 org_unit_id 列（允许 NULL，因为班组级部门无对应 org_unit）
ALTER TABLE department ADD COLUMN IF NOT EXISTS org_unit_id BIGINT;

-- Step 2: 创建外键约束
ALTER TABLE department 
  ADD CONSTRAINT fk_department_org_unit 
  FOREIGN KEY (org_unit_id) REFERENCES hse_org_unit(id)
  ON DELETE SET NULL ON UPDATE CASCADE;

-- Step 3: 创建索引
CREATE INDEX IF NOT EXISTS idx_department_org_unit_id 
  ON department(org_unit_id) WHERE is_deleted = false;

-- Step 4: 填充初始映射 — 精确匹配
UPDATE department d
SET org_unit_id = ou.id
FROM hse_org_unit ou
WHERE ou.org_name = d.name 
  AND ou.is_deleted = false 
  AND d.is_deleted = false
  AND d.org_unit_id IS NULL;

-- Step 5: 填充初始映射 — 前缀匹配（兜底未命中的）
UPDATE department d
SET org_unit_id = ou.id
FROM hse_org_unit ou
WHERE ou.org_name LIKE d.name || '%' 
  AND ou.is_deleted = false 
  AND d.is_deleted = false
  AND d.org_unit_id IS NULL;

-- Step 6: 验证映射结果
DO $$
DECLARE
  total_depts INT;
  mapped_depts INT;
  unmapped_depts INT;
BEGIN
  SELECT COUNT(*) INTO total_depts FROM department WHERE is_deleted = false;
  SELECT COUNT(*) INTO mapped_depts FROM department WHERE is_deleted = false AND org_unit_id IS NOT NULL;
  SELECT COUNT(*) INTO unmapped_depts FROM department WHERE is_deleted = false AND org_unit_id IS NULL;
  
  RAISE NOTICE '部门总数: %, 已映射: %, 未映射: %', total_depts, mapped_depts, unmapped_depts;
  
  -- 预期: 77 个部门中 24 个可映射（有对应 hse_org_unit 的作业中心级部门），53 个班组级部门不可映射
  IF mapped_depts < 20 THEN
    RAISE WARNING '映射数(%)低于预期(≥20)，请检查映射质量', mapped_depts;
  END IF;
END $$;

COMMIT;

-- ============================================================
-- 回滚脚本（如需回滚，执行以下 SQL）:
-- BEGIN;
-- ALTER TABLE department DROP CONSTRAINT IF EXISTS fk_department_org_unit;
-- DROP INDEX IF EXISTS idx_department_org_unit_id;
-- ALTER TABLE department DROP COLUMN IF EXISTS org_unit_id;
-- COMMIT;
-- ============================================================
```

if (deptRow.rows.length === 0) return res.json(error(-2, '部门不存在'));

  orgUnitIds = exactIds.length > 0 ? exactIds : ouRows.rows.map((r) => r.id);

## 四、注意事项

1. **外键约束使用 `ON DELETE SET NULL`**：删除 `hse_org_unit` 时，`department.org_unit_id` 自动置 NULL，不会阻断删除。这比 `ON DELETE CASCADE` 更安全。
2. **`org_unit_id` 允许 NULL**：53 个班组级部门在 `hse_org_unit` 中无对应节点，`org_unit_id` 为 NULL 是正常状态。
3. **降级兜底保留**：查询端点中，`org_unit_id` 为 NULL 时仍走字符串前缀匹配兜底，确保未来新增的 `hse_org_unit` 也能被未映射部门匹配到。
4. **不改前端**：`org_unit_id` 不出现在前端请求/响应中，由后端自动维护。
5. **不改 `allowedFields`**：`org_unit_id` 不在 PUT 的 `allowedFields` 中，前端无法直接设置，仅由后端在改名时自动计算。
6. **迁移文件独立**：不在已有 migration 文件中追加，保持每个迁移文件独立可追溯。
7. **约束遵守**：仅修改 `server/routes/hse-employee.js` 和新增 `server/sql/` 迁移文件，不修改前端、路由、菜单、其他业务模块。
