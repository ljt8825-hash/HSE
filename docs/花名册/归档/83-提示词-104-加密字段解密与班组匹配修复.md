# 提示词-104：员工档案详情页加密字段解密 + 作业单元班组匹配修复

## 背景

提示词-103（交互功能验证）执行前，用户发现员工档案详情页存在两个问题：

1. **身份证号/联系电话显示加密字符串**（`ENC:wFqhysUYbIC+...`），而非脱敏后的明文
2. **作业单元（unit_name）显示为 "-"**，但导入时 Excel 有"班组"列，应匹配到作业单元

本提示词合并修复这两个问题，同时覆盖提示词-103 的交互验证。

## 问题 1：详情页加密字段未解密（P0）

### 根因

`decryptMiddleware`（`server/middleware/encryption.js` 第 91-106 行）对 `data.data` 进行解密时，只处理**顶层字段**：

```js
// 当前逻辑：只查找 data.data.id_card 和 data.data.phone
data.data = decryptFields(data.data, fields);
```

但详情 API `/employees/profile/:id` 返回的结构是**嵌套对象**：

```json
{
  "data": {
    "basic": { "id_card": "ENC:...", "phone": "ENC:...", ... },
    "currentOrg": { ... }
  }
}
```

`id_card` 和 `phone` 位于 `data.data.basic` 内，`decryptFields` 在 `data.data` 顶层找不到这两个字段，解密被跳过 → 前端 `maskIdCard`/`maskPhone` 收到原始密文，正则 `/(\d{6})\d{8}(\d{4})/` 不匹配（密文没有 18 位数字），直接透传密文字符串。

> 列表 API `/employees/profile/list` 不受影响：列表项是扁平结构，`id_card`/`phone` 在顶层，`decryptMiddleware` 可正确解密。

### 修复方案

**方案 B（推荐，最小改动）**：在详情端点 handler 中，封装响应前手动解密 `emp` 对象。

修改 `server/routes/hse-employee.js` 第 6106-6150 行（`GET /employees/profile/:id`）：

在第 6122 行（`const emp = empResult.rows[0];`）之后，新增一行解密：

```js
const emp = empResult.rows[0];

// 手动解密敏感字段（decryptMiddleware 无法处理嵌套结构 { basic: { id_card, phone } }）
const { decryptFields } = require('../middleware/encryption');
const decryptedEmp = decryptFields(emp, ['id_card', 'phone']);
```

然后将第 6143-6146 行的 `emp` 替换为 `decryptedEmp`：

```js
res.json(success({
  basic: decryptedEmp,
  currentOrg: currentResult.rows.length > 0 ? currentResult.rows[0] : null,
}, '查询成功'));
```

> **注意**：`require` 语句应放在文件顶部（与其他 require 一起），而非在 handler 内部。在 handler 内部仅调用 `decryptFields`。

### 额外保障：增强 `maskIdCard`/`maskPhone` 的容错

前端 `安全看板vben/apps/web-antd/src/views/hse/employee-profile/index.vue` 第 69-77 行：

```js
function maskIdCard(idCard?: string) {
  if (!idCard) return '-';
  return idCard.replace(/(\d{6})\d{8}(\d{4})/, '$1********$2');
}

function maskPhone(phone?: string) {
  if (!phone) return '-';
  return phone.replace(/(\d{3})\d{4}(\d{4})/, '$1****$2');
}
```

增加 `ENC:` 前缀检测作为兜底保护：

```js
function maskIdCard(idCard?: string) {
  if (!idCard) return '-';
  if (idCard.startsWith('ENC:')) return '***加密数据***';
  return idCard.replace(/(\d{6})\d{8}(\d{4})/, '$1********$2');
}

function maskPhone(phone?: string) {
  if (!phone) return '-';
  if (phone.startsWith('ENC:')) return '***加密数据***';
  return phone.replace(/(\d{3})\d{4}(\d{4})/, '$1****$2');
}
```

## 问题 2：作业单元与班组匹配（P1）

### 根因

当前 `matchOperationUnit`（`server/routes/hse-employee-import-v2.js` 第 265-340 行）的班组匹配逻辑：

```js
// 步骤 2：根据班组动态推断保洁组（如"一班"→"第1保洁组"）
if (rawTeam && orgUnitId) {
  const teamNum = rawTeam.match(/(\d+)/);
  if (teamNum) { ... }
}
```

**问题**：仅当 `rawTeam`（班组）包含数字时才创建作业单元。如果班组值为纯中文（如"保洁组"、"收运组"）或不含数字，则跳过匹配，返回 `null` → 作业单元为空。

### 修复方案

增强 `matchOperationUnit` 的班组匹配，支持非数字班组名称：

在 `server/routes/hse-employee-import-v2.js` 的 `matchOperationUnit` 函数中，修改步骤 2 的逻辑：

**当前**（第 277-306 行）：
```js
// 2. 根据班组动态推断保洁组（如"一班"→"第1保洁组"）
if (rawTeam && orgUnitId) {
  const teamNum = rawTeam.match(/(\d+)/);
  if (teamNum) {
    // ... 创建 "第N保洁组"
  }
}
```

**改为**：
```js
// 2. 根据班组动态推断作业单元
//    支持：数字班组（"一班"→"第1保洁组"）、纯中文班组（"保洁组"→"保洁组"）
if (rawTeam && orgUnitId) {
  const orgResult = await client.query(
    `SELECT org_name FROM hse_org_unit WHERE id = $1 AND is_deleted = false`, [orgUnitId]
  );
  if (orgResult.rows.length > 0) {
    const townName = orgResult.rows[0].org_name.replace('作业中心', '');
    const teamNum = rawTeam.match(/(\d+)/);
    let unitName;
    if (teamNum) {
      // 数字班组：一班→第1保洁组
      unitName = `${townName}第${teamNum[1]}保洁组`;
    } else {
      // 纯中文班组：保洁组→保洁组（保留原始班组名，加乡镇前缀）
      unitName = `${townName}${rawTeam}`;
    }
    // 查询是否已存在（getOrCreate模式）
    const exist = await client.query(
      `SELECT id, unit_name FROM hse_operation_unit
       WHERE org_unit_id = $1 AND unit_name = $2 AND is_deleted = false`,
      [orgUnitId, unitName]
    );
    if (exist.rows.length > 0) {
      return { target_id: exist.rows[0].id, target_name: exist.rows[0].unit_name };
    }
    // 动态创建
    const unitCode = `UNIT-${orgUnitId}-${rawTeam.replace(/[^a-zA-Z0-9\u4e00-\u9fa5]/g, '').substring(0, 10)}`;
    const insert = await client.query(
      `INSERT INTO hse_operation_unit (org_unit_id, unit_name, unit_type, unit_code, status)
       VALUES ($1, $2, 'cleaning_team', $3, 'active') RETURNING id, unit_name`,
      [orgUnitId, unitName, unitCode]
    );
    return { target_id: insert.rows[0].id, target_name: insert.rows[0].unit_name };
  }
}
```

3. 员工档案详情页中"作业单元"字段显示正确的班组名称

## 注意事项

1. **端口**：后端运行在 5800，前端代理指向 5800
2. **`decryptFields` require**：应放在 `hse-employee.js` 文件顶部，与其他 require 一起
3. **班组匹配**：新逻辑会在导入时动态创建作业单元（getOrCreate 模式），不会产生重复
4. **已有数据**：修复后仅对新导入的班组生效，已导入的员工若无班组数据，作业单元仍为空。如需回填已有数据，需单独执行数据修复脚本（不在本提示词范围）
5. **前端改动**：`maskIdCard`/`maskPhone` 的 ENC: 兜底是防御性改动，修复成功后不应触发
