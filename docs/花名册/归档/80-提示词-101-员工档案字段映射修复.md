# 提示词-101：员工档案字段映射修复

## 背景

模块"人员管理"中的"员工档案"页面，列表显示大量字段为空（员工编号、所属组织、作业单元、岗位、入职日期、是否驾驶员），经代码审查确认根因是**前后端字段名约定不一致**：后端通过 `camelKeys()` 将 snake_case 转为 camelCase 返回，但前端 `dataIndex` 全部使用 snake_case，导致键名不匹配，仅 `name`/`gender`/`age`/`status` 等单字字段能正常显示。

同时存在 5 个字段被硬编码为 `NULL`、`is_driver` 判定逻辑与详情 API 不一致等附带问题。

## Task 1：修复列表 API 字段名映射（P0 - 关键）

### 问题

`hse-employee.js` 中 `/employees/profile/list` 端点（第 6068-6093 行）的 SQL 查询返回 snake_case 字段名，但调用 `camelKeys()` 转换为 camelCase，导致前端 `dataIndex`（全部为 snake_case）无法匹配。

### 修复方案

**方案 A（推荐）：SQL 中直接 alias 为前端期望的 snake_case 字段名，移除对 `camelKeys` 的依赖**

将 `result.rows.map(camelKeys)` 改为 `result.rows`（不再转换），同时在 SQL 中将所有字段 alias 为前端期望的 snake_case 名称。

### 具体改动

#### 1.1 替换 5 个硬编码 NULL 为视图实际列

将第 6073-6079 行：
```sql
NULL AS org_code,
NULL AS operation_unit_id,
NULL AS unit_name,
NULL AS unit_type,
ea.position_id,
ev.position_name,
NULL AS position_code,
```

改为：
```sql
ev.org_code,
ev.operation_unit_id,
ev.unit_name,
ev.unit_type,
ea.position_id,
ev.position_name,
ev.position_code,
```

#### 1.2 修复 `is_driver` 判定逻辑

将第 6083 行：
```sql
(ev.position_name ILIKE '%驾驶员%' OR ev.position_name ILIKE '%司机%') AS is_driver
```

改为（与详情 API 一致，从 remark 解析）：
```sql
(ev.remark IS NOT NULL AND ev.remark LIKE '%is_driver=true%') AS is_driver
```

#### 1.3 移除 `camelKeys` 转换

将第 6093 行：
```js
res.json(success({ list: result.rows.map(camelKeys), total, page: pageNum, pageSize: limitNum }, '查询成功'));
```

改为：
```js
res.json(success({ list: result.rows, total, page: pageNum, pageSize: limitNum }, '查询成功'));
```

#### 1.4 更新注释

将第 6021-6025 行的注释更新为准确描述：
```js
// 列表 SQL 返回字段别名与前端 dataIndex 保持一致（snake_case），
// 不再依赖 camelKeys 转换。v_employee_current 视图已提供 org_code/
// operation_unit_id/unit_name/unit_type/position_code 等全部所需字段。
// is_driver 从 employee_assignment.remark 解析（与详情 API 一致）。
```

### 验证要点

1. 修改后启动后端，访问 `/hse/employee/employees/profile/list?page=1&pageSize=20`
2. 确认返回的 `list` 数组中每条记录包含以下字段且值非空：
   - `employee_code`（员工编号）
   - `org_name`（所属组织）
   - `unit_name`（作业单元）
   - `position_name`（岗位）
   - `hire_date`（入职日期）
   - `is_driver`（是否驾驶员，布尔值）
   - `org_code`、`operation_unit_id`、`unit_type`、`position_code`（之前为 NULL）
3. 前端页面刷新后，确认所有列正常显示数据
4. 确认 `is_driver` 筛选功能正常（筛选"是"应与导入时标记的驾驶员一致）

## 风险提示

1. **其他端点不受影响**：仅修改 `/employees/profile/list` 端点，详情 API（`/employees/profile/:id`）已正确使用独立的 SQL 查询，不依赖 `camelKeys` 转换
2. **前端无需改动**：前端 `dataIndex` 使用 snake_case，修复后后端直接返回 snake_case，天然匹配
3. **is_driver 筛选条件**：第 6045-6047 行的 `is_driver` 筛选条件也使用了模糊匹配，需同步修改为从 remark 解析（但这是 SQL WHERE 条件，需改为 JOIN `employee_assignment` 或使用子查询）

### 关于 is_driver 筛选条件的补充说明

当前第 6045-6047 行：
```js
if (is_driver === 'true') {
  conditions.push(`(ev.position_name ILIKE '%驾驶员%' OR ev.position_name ILIKE '%司机%')`);
}
```

由于 `v_employee_current` 视图已包含 `remark` 字段（来自 `employee_assignment`），建议改为：
```js
if (is_driver === 'true') {
  conditions.push(`(ev.remark IS NOT NULL AND ev.remark LIKE '%is_driver=true%')`);
}
```
