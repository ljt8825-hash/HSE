## 1. 问题根因（实测，非假设）

点击员工档案菜单 → `/api/hse/employee/employees/profile/list` 返回的员工列表多项字段为空（员工编号、部门、单位、岗位编码、入职日期、是否驾驶员等全空）。

经核对源码与数据库真实 schema，根因有 **两层**：

### 1.1 字段被写成 NULL
`server/routes/hse-employee.js`（`/employees/profile/list` 约 6068–6093 行）中 5 个列被硬编码为 `NULL`：
`org_code / operation_unit_id / unit_name / unit_type / position_code`。
而 `v_employee_current` 视图 **实际已包含这 5 个列**（视图重建后共 40 列，含 `org_code/operation_unit_id/unit_name/unit_type/position_code/remark/start_date`）。代码注释陈旧，误以为视图不提供这些列。

### 1.2 camelKeys 导致键名不匹配（主因）
后端对该接口结果调用了 `camelKeys()`，把数据库 snake_case 键转换为 camelCase（如 `employee_code` → `employeeCode`、`org_name` → `orgName`）。
但前端 `employee-profile/index.vue` 的 `dataIndex` 全部使用 **snake_case**（`employee_code`、`org_name`、`hire_date`、`is_driver`…），且 API 类型定义 `employee-profile.ts` 也声明为 snake_case。
→ 后端返回的 camelCase 键与前端 dataIndex 对不上，**整个列表渲染为空字段**。

### 1.3 标题报错 `字段 ev.hire_date 不存在`（已先行修复）
`v_employee_current` 重建后 **不再有 `hire_date` / `is_driver` 列**（入职日期列为 `start_date`），而查询引用了 `ev.hire_date`、`ev.is_driver`。在本次任务前已修复（见 §3 修改点），本次为同源问题收口。

## 2. 与提示词方案的**偏差**（重要，必须记录）

**提示词 Task 1.2 要求**：`is_driver` 由 `ev.remark LIKE '%is_driver=true%'` 推导。
**实际执行**：**未采用 remark 方案，保留 position_name 启发式。** 原因（实测数据）：

| 检测方式 | 结果 | 说明 |
|---|---|---|
| `v_employee_current.remark` 非空行 | **0 / 1366** | remark 在本库对全部在职员工为 NULL |
| `employee_assignment.remark` 非空行 | **0** | 任职备注同样全 NULL |
| `position_name LIKE '%驾驶员%' OR '%司机%'` | **43** | 真实驾驶员数量 |

若按提示词改 `remark` 方案，会把 **43 名驾驶员全部误判为 0**，属于回归而非修复。而 position_name 启发式与现有"驾驶员/司机"筛选逻辑、`/employees/profile/:id/driver-info`（解析 `remark.includes('is_driver=true')`，但源数据无此标记）一致，且能正确识别 43 人。故保留 position_name 启发式。

> 提示词基于"remark 存储 is_driver 标记"的假设，但本库 remark 全空，该假设不成立。已在代码注释中明确标注。

## 5. 环境事件：端口 5666 被 Windows 保留（必须知悉）

后端重启时发现 **无法绑定 5666**：`EACCES: permission denied 0.0.0.0:5666`。

排查：`netsh interface ipv4 show excludedportrange` 显示 **5666 落在系统保留区间 `5595–5694`（标记为"管理的端口排除"）**。该区间由 Hyper-V/HNS 等组件动态保留，本会话中途出现（此前 5666 可正常绑定，故为中途新增保留）。

- 尝试 `net stop hns` 释放 → **拒绝访问（错误 5，当前 shell 无管理员权限）**，无法释放。
- 因 `app.js` 端口为 `process.env.PORT || 5666`，故将后端迁至 **5800**（不在任何保留区间），并同步更新 `server/.env` 与 `vite.config.ts` 代理目标。

**当前服务状态**：后端 PID 3180 监听 `0.0.0.0:5800`，`/api/health` 200，数据库 connected；前端 dev 代理与静态托管均指向 5800，相对 `/api` 基址无需改动即可工作。

**如需恢复 5666**：需以管理员身份执行 `net stop hns && net start hns`（或重启主机）清除保留区间，再将 `.env` 与 `vite.config.ts` 改回 5666。
