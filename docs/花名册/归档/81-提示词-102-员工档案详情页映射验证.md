# 提示词-102：员工档案详情页字段映射验证与修复

## 背景

提示词-101 修复了员工档案**列表页**的后端字段名映射问题（移除 `camelKeys()`，直接返回 snake_case）。但员工档案**详情页**（Drawer 弹窗）的 API 端点 `/employees/profile/:id` 仍使用 `camelKeys()` 转换，可能同样存在 camelCase vs snake_case 键名不匹配问题。

验证报告（80-提示词-101-验证报告.md）中已标注此项为残留风险，需在本提示词中闭环。

## Task 3：修复详情 API 字段映射

根据 Task 2 的对比结果：

### 场景 A：详情 API 返回 camelCase，前端读取 snake_case（与列表页同类问题）

修复方案：将 `/employees/profile/:id` 端点的 `camelKeys()` 移除，改为直接返回 snake_case：

将第 6136 行：
```js
res.json(success(camelKeys({
  basic: emp,
  currentOrg: currentResult.rows.length > 0 ? currentResult.rows[0] : null,
}), '查询成功'));
```

改为：
```js
res.json(success({
  basic: emp,
  currentOrg: currentResult.rows.length > 0 ? currentResult.rows[0] : null,
}, '查询成功'));
```

### 场景 B：详情 API 返回 camelCase，前端读取 camelCase（匹配）

无需修改后端，仅需确认所有字段能正常显示。

### 场景 C：详情 API 返回 snake_case，前端读取 camelCase（反向不匹配）

需在后端 SQL 中 alias 为 camelCase，或前端改为 snake_case。优先改后端（与列表页策略一致，但方向相反——列表页是后端适配前端 snake_case）。
