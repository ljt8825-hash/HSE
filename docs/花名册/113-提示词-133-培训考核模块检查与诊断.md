## 2. 诊断维度（五维度）

### 维度一：前端代码质量
- 检查每个页面是否使用 `Page` 组件（`@vben/common-ui`）
- 检查是否使用 `useDataTable` / `useSearchForm` / `useCrudModal` 托管（符合项目规范）
- 检查是否使用 Ant Design Vue（非 Element Plus）
- 检查 TypeScript 类型定义完整性（`TrainingApi.TrainingPlan` / `TrainingRecord` 等）
- 检查是否有硬编码的业务规则（阈值、类型枚举、状态流转）
- 检查 `vue-tsc --noEmit --skipLibCheck` 本模块相关文件有无 TS 错误

### 维度二：后端代码质量
- 检查 `node --check` 两个路由文件语法
- 检查路由注册顺序：是否存在 `/:id` 遮蔽字面量路由（如 `/export` 被 `/records/:id` 捕获）
- 检查权限控制：是否每个端点都有 `requireRole` 声明
- 检查双模式（PostgreSQL + 内存降级）一致性：两种模式下的字段名、数据类型、响应结构是否一致
- 检查 `resolveEmployeeId` 通过 `id_card` hash 匹配的逻辑是否正确
- 检查 `ensureTables()` 的 DDL 是否幂等、是否有遗漏字段

### 维度三：数据流一致性
- 检查前端 API 类型定义与后端返回的字段名是否一致（snake_case vs camelCase）
- 检查 `training.js` 与 `training-assessment.js` 是否有重复端点或数据冲突
- 检查培训计划（`training_records`）与培训台账（`training_ledger` 相关）的数据关系
- 检查 `training_plans`（独立表）与 `training_records`（主表）的关联逻辑
- 检查导出功能是否与页面展示数据一致

### 维度四：边界与异常
- 检查空状态处理（无培训计划、无培训记录时的 UI 展示）
- 检查日期边界（培训开始/结束日期、证书到期日期）
- 检查文件上传边界（附件大小、类型限制）
- 检查敏感信息处理（身份证号、学员信息是否脱敏）
- 检查统计数据的口径一致性（total 与列表 count 是否一致）

### 维度五：回归检查
- 检查菜单与路由配置（`hse-08-training.ts`）是否与 `app.js` 注册一致
- 检查培训模块是否依赖其他模块的 API（如员工查询、组织查询）
- 检查规则文件 `training-assessment-rule.json` 是否被正确加载和使用
- 检查前端构建：`vite build --mode production` 是否包含本模块所有 chunk

## 3. 重点检查项

### 3.1 双路由文件架构
培训模块由 `training.js`（主路由）和 `training-assessment.js`（考核路由）两个文件组成，需检查：
- 两个文件是否有路由冲突（相同前缀、相同路径）
- 两个文件是否有重复逻辑（如格式转换函数、附件管理）
- 两个文件的权限声明是否一致

### 3.2 培训计划与台账的关系
- `training_records` 表同时承载"培训计划"和"培训记录"两种语义
- `training_plans` 表是独立的培训计划表
- 需检查两者的数据关系是否正确、是否有冗余

### 3.3 规则文件使用情况
- `training-assessment-rule.json` 定义了 11 类规则
- 前端是否硬编码了与规则文件重复的枚举值
- 后端 `training-assessment.js` 的规则端点是否正确返回规则内容

### 3.4 内存降级模式
- `training.js` 使用内存降级（`memoryStores`），需检查：
  - 初始化数据是否完整
  - 内存模式与 PostgreSQL 模式的响应结构是否一致
  - 内存模式是否缺少某些端点
