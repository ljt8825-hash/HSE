## 一、P0-1：level 枚举前后端不一致，level=6 写入必失败

- **重要实测偏差**：提示词假设数据库存在 `CHECK (level BETWEEN 1 AND 5)`，但实查 `department` 表 **无任何 level 的 CHECK 约束**（仅 PK + FK `fk_department_org_unit`）；历史数据 `level∈{4,5,6}` 共 78 行，0 行越界。故原"level=6 写入必失败"在当前库不成立，但"缺少防御性约束"确为风险点。
- **修复 1 — 迁移**（`server/sql/hse_department_level_6_migration.sql`，写前已全量备份 `hse_bk_pre_v116_level_*.dump`）：
  ```sql
  ALTER TABLE department DROP CONSTRAINT IF EXISTS department_level_check;
  ALTER TABLE department
    ADD CONSTRAINT department_level_check CHECK (level BETWEEN 1 AND 6);
  ```
  执行结果：`CHECK (((level >= 1) AND (level <= 6)))` 已生效，0 行越界、必定成功。
- **修复 2 — 前端 level 语义**：`levelText()` 当前值已是 `1=公司 2=部门中心 3=乡镇作业中心 4=部门 5=乡镇 6=班组`，与 Select 选项(1-6)一致，**无需改动**（提示词亦注明"仅注释，实际值不变"）。
- **修复 3 — 后端 level 校验**（`hse-employee.js` POST/PUT /departments）：
  ```js
  if (level !== undefined && (level < 1 || level > 6))
    return res.json(error(-3, '层级必须在 1-6 之间'));
  ```
- **API 探针验证**（`_117_probe.cjs`，自签 JWT admin）：
  - POST `level=7` → `code:-3, 层级必须在 1-6 之间` ✅
  - POST `level=0` → `code:-3` ✅
  - POST `level=6`（挂 L5 父） → `code:0 新增成功` → 随即 DELETE `code:0` 清理 ✅
  - PUT `level=9`（宁城街道 id=4056） → `code:-3` ✅
  - 结果：pass=4 fail=0。

## 二、P0-2：删除提示与实际行为完全相反

- **根因**：前端 Popconfirm 文案"删除后子部门将一并删除"，但后端硬拒有子部门删除（返回 -5）。
- **修复**（`departments.vue` Popconfirm `title`）：
  ```
  确定删除该部门吗？若存在子部门将无法删除，请先移除所有子部门后再操作。
  ```
- 后端 -5 提示"存在子部门，无法删除"保持不变，文案与行为一致。无需后端改动。

## 三、P0-3：level 递增溢出风险

- **修复 1 — `handleAdd` level 上限保护**：
  ```ts
  level: parent ? Math.min((parent.level || 3) + 1, 6) : 1,
  ```
- **修复 2 — 班组(level=6)隐藏"新增子部门"按钮**：
  ```html
  <a-button v-if="currentDept && canEdit && (currentDept as any).level !== 6" ...>
  ```
  选中班组节点时按钮不可见；选中 level≤5 节点时仍可新增（自动 level+1，封顶 6）。
