## 3. 预检发现（代码审查阶段已识别）

### 3.1 P1 — 岗位删除无友好提示

**现状**：后端 DELETE `/positions/:id` 直接执行 `UPDATE position SET is_deleted = true`，未检查是否有员工关联该岗位。

**根因**：`employee_assignment` 表有 `position_id BIGINT NOT NULL REFERENCES position(id)`（RESTRICT），数据库层会阻止删除，但返回给前端的是 PostgreSQL 原始错误（如 `"update or delete on table "position" violates foreign key constraint..."`），用户无法理解。

**修复方向**：删除前先查询 `SELECT COUNT(*) FROM employee_assignment WHERE position_id = $1 AND is_current = true AND is_deleted = false`，若 > 0 则返回友好错误 `"该岗位下有 N 名在职员工，无法删除。请先为这些员工调整岗位后再操作。"`

**改动文件**：`server/routes/hse-employee.js`（DELETE `/positions/:id` 路由，新增约 8 行）

### 3.2 P2 — jobCategory / specialPost 筛选为纯前端过滤

**现状**：
- `searchForm.jobCategory` 和 `searchForm.specialPost` 变更时触发 `handleSearch()` → `loadList()`
- `loadList()` 仅传 `deptId` 和 `keyword` 给后端，不传 `jobCategory` / `specialPost`
- `filteredList` computed 在前端做二次过滤

**影响**：每次切换筛选条件都重新全量拉取数据，数据量大时浪费带宽和性能。且当前 `positions` 表共 26 条记录尚可接受，但随业务增长会恶化。

**修复方向**：后端 GET `/positions` 增加 `jobCategory` 和 `isSpecialPost` 查询参数支持（可选，默认不筛选）。前端移除 `filteredList` computed，直接使用 `list` 绑定表格。

**改动文件**：
- `server/routes/hse-employee.js`（GET `/positions`，新增约 10 行条件）
- `src/views/hse/employee/positions.vue`（移除 `filteredList`，表格 data-source 改为 `list`）

### 3.3 P2 — 分页为纯前端分页

**现状**：
```html
:pagination="{ pageSize: 20, showSizeChanger: true, showTotal: (t: number) => `共 ${t} 条` }"
```
无 `current` / `total` 绑定，表格使用 Ant Design 内置前端分页（对 `data-source` 全量数据切片）。

**影响**：当前 26 条数据无实际影响，但架构上不符合项目标准（`useDataTable` 要求服务端分页）。

**修复方向**：后端 GET `/positions` 增加 `page` / `pageSize` 参数支持，返回 `{ list, total, page, pageSize }`。前端绑定 `current` 和 `total`。

**改动文件**：
- `server/routes/hse-employee.js`（GET `/positions`，新增分页逻辑约 15 行）
- `src/views/hse/employee/positions.vue`（pagination 绑定 current/total，新增 handleTableChange）

### 3.4 P3 — dept_id 非必填

**现状**：`formRules` 仅校验 `position_code` 和 `name`，`dept_id` 未加 `required: true`。用户可以创建无归属部门的岗位。

**影响**：无部门岗位在花名册导入时可能无法匹配，导致数据孤岛。

**修复方向**：`formRules` 增加 `dept_id: [{ required: true, message: '请选择所属部门' }]`。

**改动文件**：`src/views/hse/employee/positions.vue`（`formRules`，新增 1 条规则）

### 3.5 代码规范偏离（参考，非必须本轮修复）

**现状**：`positions.vue` 手写了 `loading` / `list` / `searchForm` / `handleSearch` / `filteredList`，未使用项目标准 `useDataTable` + `useSearchForm` composable。

**偏离项**：
- `const loading = ref(false)` → 应使用 `useDataTable` 托管
- `const searchForm = reactive({...})` → 应使用 `useSearchForm` 托管
- `function handleSearch()` → 应使用 `useSearchForm` 的 `handleSearch`
- 无 `handleReset` 方法

**说明**：此偏离不影响功能，但增加维护成本。可在本轮一并改造，或标记为后续债务。
