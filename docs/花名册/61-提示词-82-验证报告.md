**补全结果**（全部为当前任职 `is_current=true` 且 `position_id IS NULL` 的行）：
- 7 名：pending 已解析出 `target_pos_id` → 直接使用（项目总经理/人事专员/会计/副经理/片区长/文员等）。
- 11 名：仅有 raw_position 文本 → 按 `position` 表名称映射（口径同提示词-79：经理/主管→部门经理1391/安环副经理1389，专员→管理员1395，安环专员→1390 精确同名）。
- 1 名（TEST001，文件外/测试员工，无岗位数据）：赋文档化默认值 管理员(1395)。

**验证**：`SELECT count(*) FROM ... WHERE position_id IS NULL` = **0**。

## 四、任务2：person_type 推断补全（D3）

**问题**：1,328 名员工 `person_type` 为空（源文件不提供该字段）。

**方法**：复用提示词给出的 4 类分类规则（与后端 `VALID_PERSON_TYPES` 一致），信号源优先级为 `当前 position.name` → `pending.raw_position` → `pending.raw_dept` → 辅助人员。

**结果**：1,328 条 NULL 全部消除，最终分布：

| person_type | 人数 |
|-------------|------|
| 生产人员 | 1,264 |
| 管理人员 | 69 |
| 辅助人员 | 20 |
| 技术人员 | 4 |
| in_service（非法，测试员工） | 4（未改动，已标注） |

**执行注意（已修正）**：person_type SQL 初次在 position 修复前执行，导致 18 名员工用陈旧 pending 数据（而非已解析的 position.name）分类。已将该 18 人重置 NULL 并重新执行，最终分类正确（如 刘会杰 人事专员→技术人员、曹周平 会计→技术人员）。

**已知规范缺口（非本次引入）**：分类关键词未含"主管"，故 乡镇主管/行政综合主管/作业质量管理主管 类岗位落入"辅助人员"。是否将"主管"纳入管理人员需后续代码侧确认。
