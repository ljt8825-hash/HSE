## 三、执行任务

### 任务1：调研考核模块表结构

**目标**：理解考核模块的完整数据模型。

**方法**：
1. 搜索代码中考核相关的表名（`assessment` / `hse_assessment` / `assessment_target` 等）
2. 对每张表执行 `\d+` 查看列定义和约束
3. 列出所有 NOT NULL 列、外键引用、枚举值
4. 确认表之间的关联关系（如 target → record 的 FK 链路）

### 任务2：调研考核模块前端页面

**目标**：理解考核模块的业务流程，确认数据录入方式。

**方法**：
1. 浏览 `views/objectives/assessment/` 和 `views/goals/` 目录
2. 确认页面功能：是否有"新建考核"、"考核打分"、"生成记录"等流程
3. 确认是否需要先有考核目标才能生成考核记录

### 任务3：制定补录策略

根据调研结果，选择以下策略之一：

| 策略 | 适用场景 | 说明 |
|------|----------|------|
| A. 直接插入 assessment_records | 表结构简单，无前置依赖 | 类似应急模块，直接INSERT |
| B. 先建目标，再生成记录 | 有 target → record 的 FK 依赖 | 按业务流程顺序补录 |
| C. 仅生成目标，记录由流程自动产生 | 记录由前端表单提交时自动生成 | 只补录上游数据 |
| D. 跳过，标记为"需业务流程驱动" | 数据依赖复杂，无法通过SQL合理模拟 | 等待业务方实际使用 |
