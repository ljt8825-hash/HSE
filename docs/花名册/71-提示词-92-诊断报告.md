## 三、问题3：直接上级未按花名册映射（**根因在数据库数据，非后端 SQL**）

### 3.1 后端 SQL 核查
`server/routes/hse-employee.js` 的员工列表查询（约 583–591 行）**已正确** LEFT JOIN
`employee_assignment ea_sup`（is_primary/is_current/is_deleted）并关联 `employee sup` 取
`ea_sup.supervisor_id AS supervisor_id` 与 `sup.name AS supervisor_name`。
→ 后端取数逻辑无缺陷，缺失的是 **`employee_assignment.supervisor_id` 未写入**。

### 3.2 supervisor_id 写入率诊断（核心发现）

| 范围 | 总数 | 含 supervisor_id | 写入率 |
|------|:----:|:----------------:|:------:|
| 全部 `employee_assignment`（is_deleted=false） | 3919 | 1 | ~0.03% |
| 当前主关系 `is_current=true AND is_primary=true` | 1361 | **0** | **0%** |

→ **写前写入率 0%**，远低于 90% 验收线。

### 3.3 根因分析
1. 花名册导入源数据**含有"直接上级"列**：`employee_import_pending` 中 3933 行含
   `raw_supervisor`，去重后 63 个姓名，其中 **61 个与 `employee.name` 精确匹配**（可匹配）。
2. 但 `matchSupervisor()`（`server/routes/hse-employee-import-v2.js`）在**导入当时**对全部行返回了
   `null`，导致 `employee_import_pending.supervisor_id` 与 `employee_assignment.supervisor_id`
   **均为 0**。
   - 直接原因推断：导入解析阶段上级领导（如马鑫、刘晓光为区域层领导）尚未作为员工入库，
     或解析批次早于员工主数据写入，使 `matchSupervisor` 的 `name = $1` 精确匹配失败并保留为 null。
   - `matchSupervisor` 本身逻辑正确（按姓名精确匹配 `employee` 且 `is_deleted=false`），无需修改。
3. 当前 1361 条主关系数据由早期导入/种子写入，未走"上级写回"路径，故全为空。

### 3.4 修复动作（数据回填，可逆 DML，备份已就绪）
以 `employee_import_pending.raw_supervisor` 为权威来源，按姓名精确匹配回填
`employee_assignment.supervisor_id`：

```sql
WITH sup_map AS (
  SELECT DISTINCT ON (p.employee_no) p.employee_no, sup.id AS supervisor_id
  FROM employee_import_pending p
  JOIN employee sup ON sup.name = btrim(p.raw_supervisor) AND sup.is_deleted = false
  WHERE p.raw_supervisor IS NOT NULL AND p.raw_supervisor <> ''
  ORDER BY p.employee_no, sup.id
)
UPDATE employee_assignment ea
SET supervisor_id = m.supervisor_id, updated_at = NOW()
FROM employee sub
JOIN sup_map m ON m.employee_no = sub.employee_code
WHERE ea.employee_id = sub.id
  AND ea.is_current = true AND ea.is_primary = true AND ea.is_deleted = false
  AND ea.supervisor_id IS NULL;
```

**回填结果**：

| 指标 | 回填前 | 回填后 |
|------|:------:|:------:|
| 当前主关系总数 | 1361 | 1361 |
| 含 supervisor_id | 0 | **1306** |
| 写入率 | 0% | **96.0%** ✅ |

- 未匹配 55 条（占 4%）：其中 2 个上级姓名（**马鑫、刘晓光**）为区域层领导、不在员工系统内，
  属"系统外上级"的合理空值；其余为姓名重名/历史批次差异，按最小 supervisor_id 确定性选取。
- 该回填为**纯数据操作（DML，非 DDL）**，未触碰任何路由/模块代码，且执行前已完成全库备份，可回滚。

### 3.5 类型补充
`src/api/hse/employee.ts` 的 `EmployeeItem` 已补充：
```ts
supervisor_id?: number;
supervisor_name?: string;
```
表格"直接上级"列（`dataIndex: 'supervisor_name'`）原本已存在，后端已返回该字段，回填后即可正常显示。
