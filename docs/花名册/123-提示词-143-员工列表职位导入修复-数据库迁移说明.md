## 1. 背景

修复导入逻辑（支持「所属部门 + 职位」花名册格式）后，**未来导入**可正确关联职位。但数据库中孙佳敏等员工的历史任职记录仍是旧数据（职位「管理员」），需要修正存量数据。

**修正方案**：重导整份花名册（推荐，已执行）。

## 3. 执行步骤（已执行）

**执行结果**：

- 无错误

### 3.3 导入逻辑说明

重导时对每条记录执行：

1. 若员工已存在（按 `employee_code` 匹配），更新基础信息（姓名/身份证/手机号等）
2. 将旧的组织关系（`employee_assignment`）设为 `is_current = false`
3. 插入新的任职记录：`is_current = true, is_primary = true`，关联解析出的部门（`org_unit_id`）与职位（`position_id`）
4. 职位不存在时自动创建（`position` 表）

> 因此孙佳敏的旧任职「管理员」被标记为非当前，新任职「行政综合主管」为当前记录，历史数据保留可追溯。

## 4. 验证方法

### 4.1 数据库验证

```sql
SELECT e.employee_code, e.name, ou.org_name, p.name AS position_name, ea.is_current, ea.is_primary
FROM employee e
LEFT JOIN employee_assignment ea ON ea.employee_id = e.id AND ea.is_deleted = false
LEFT JOIN hse_org_unit ou ON ou.id = ea.org_unit_id
LEFT JOIN position p ON p.id = ea.position_id
WHERE e.name = '孙佳敏' AND e.is_deleted = false
ORDER BY ea.is_current DESC, ea.is_primary DESC;
```

**预期结果**：

| employee_code | name | org_name | position_name | is_current | is_primary |
|---------------|------|----------|---------------|------------|------------|
| 00271497 | 孙佳敏 | 人力综合部 | **行政综合主管** | **true** | true |
| 00271497 | 孙佳敏 | 人力综合部 | 管理员 | false | true |

### 4.2 全量一致性验证

花名册职位 vs 数据库职位一致性：**1311 / 1311（100%）一致，0 不一致**。

### 4.3 API 验证

```bash
GET /api/hse/employee/employees?keyword=孙佳敏
```

返回 `position_name = "行政综合主管"`，前端「员工列表」显示正确。

## 5. 回滚方案

若重导后发现问题，可回滚：

1. **恢复任职记录**：将重导前备份的 `employee_assignment` 数据恢复（重导前已做全量备份）
2. **恢复员工基础信息**：从备份恢复 `employee` 表
3. 重导过程为事务性操作，单条失败不影响其他记录

> 重导前已执行数据库全量备份，备份文件保留在服务器备份目录，可随时恢复。

## 6. 注意事项

- 重导会为每个员工创建一条新的当前任职记录，旧记录保留（`is_current = false`），不影响历史追溯
- 部门模糊匹配将花名册班组（如「宁城街道一班」）归并到父级作业中心，属组织树层级限制的预期行为
- 若后续组织树补充班组层级，可再优化部门映射精度
