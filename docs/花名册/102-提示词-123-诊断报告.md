## 3. 分维度诊断

### 3.1 前端代码质量

| 检查项 | 结果 | 说明 |
|--------|------|------|
| `useDataTable`/`useSearchForm` 规范 | ⚠️ P3 偏离 | 本页采用手写 `reactive` 分页 + `loadList()`，单页自包含；属可接受偏离，记录原因 |
| 分页绑定 `current/total/pageSize` | ✅ | 列表 `:pagination` 绑定 `pagination.page/pageSize/total`，`handleTableChange` 正确回写并 reload |
| 错误处理覆盖 | ✅ | 所有 async 操作均有 try/catch + `message.error`，无裸 await |
| 未使用 import / dead code | 🔧 P2→已修 | ① `clearAllEmployees`（POST /clear-all 非级联版，UI 从未调用）未使用 import 已移除；② `uploadProps.customRequest: () => {}` 被模板覆盖的死代码已清理 |
| `as any` 断言 | ✅ P3 可接受 | 集中在 AntD tsx `customRender({record}: any)` 与 `handleTableChange(pag:any)`、外部响应 `ref<any>`，属常规用法，未过度 |
| 权限开关 | ✅ | `canImport/canResolve/canExecute = admin,safety_manager`；`canClearAll = admin`，与后端 `requireRole` 完全对应 |

**🔧 已修复 P2-1 — 上传大小前后端不一致**
- 现象：前端 `beforeUpload` 允许 ≤50MB，后端 `upload.js` 的 `UPLOAD_CONFIG.maxSize = 10MB`。10–50MB 文件前端放行后，后端 multer 抛 `LIMIT_FILE_SIZE`，前端仅显示通用"上传失败"，体验断裂。
- 修复：前端 `beforeUpload` 与提示文案统一为 10MB（`10 * 1024 * 1024` / "文件大小不能超过 10MB"），与后端对齐。

**🔧 已修复 P2-2 — 关键字搜索框为"死"功能**
- 现象：工具栏 `<Input.Search v-model="searchForm.keyword">` 输入后，`loadList()` 并未将 `keyword` 传给后端；而后端 `GET /batches` 仅支持 `status` 筛选。该搜索框点击/回车无任何效果。
- 修复：移除该无效输入框及 `searchForm.keyword` 相关赋值（保持最小改动，不新增后端查询能力，避免触碰核心查询逻辑）。

### 3.2 后端代码质量

| 检查项 | 结果 | 说明 |
|--------|------|------|
| 写端点 `requireRole` | ✅ | 全部使用展开写法 `requireRole('admin','safety_manager')` / `requireRole('admin')`，无 118/119 式数组写法缺陷 |
| 文件类型/大小校验 | ✅ | `upload.js`：扩展名 + MIME + **魔术字节**（ZIP/OLE2 签名）三重校验，10MB 上限 |

| 事务完整性 | ✅（入库/删除/清空）⚠️（上传） | 入库采用 `BEGIN` + 逐行 `SAVEPOINT` 隔离（单行失败 `ROLLBACK TO SAVEPOINT`，整体可控）；删除/清空均 `BEGIN/COMMIT`。**上传端点未在事务内**（见 P3） |
| 错误信息友好化 | 🔧 P2→已修 | 见下 |
| SQL 注入 | ✅ | 全参数化 `$1..$n`；唯一动态表名来自系统目录 `pg_constraint`（`clear-all-*` 的 childTables），非用户输入，无注入风险 |

**🔧 已修复 P2-3 — `GET /clear-all-preview` 异常分支泄露原始错误**
- 现象：catch 分支 `res.json(error(-1, \`预检查失败：${err.message || err}\`))` 直接拼接原始 PG 错误，可能向客户端泄露表结构/约束等内部信息。
- 修复：改用 `formatDbError(err)`（与全模块其他端点一致），统一转为中文友好提示。
- 注：此改动需**重启后端**方能生效；当前沙箱禁止进程枚举/重启工具（wmic、PowerShell Get-Process 均被安全策略拦截），故代码已落地并 `node --check` 验证通过，运行态生效待运维重启。
