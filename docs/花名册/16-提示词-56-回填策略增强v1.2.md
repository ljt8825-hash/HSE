## 0. 背景

当前回填策略（`server/scripts/backfillEmployeeId.cjs` v1.0）存在以下局限：

| 局限 | 影响 |
|------|------|
| 仅覆盖 2 张表（training + violations） | hazards/accidents/emergency_plans 的 employeeId 外键列未回填 |
| 三违表仅依赖姓名匹配 | 准确性低，重名完全跳过 |
| 逐条 SQL（每行 1 SELECT + 1 UPDATE） | 1311 条员工需 2600+ 次查询，性能差 |
| 无事务包裹 | 部分失败不回滚 |
| 结果仅打印控制台 | 无法追溯、审计 |

同时，`Employee_Model_Check.sql` 巡检视图的 status 白名单与 `employeeAssignmentService.js` 的 `STATUS_MAP` 不一致（巡检多了 `leave`/`transfer`，缺少 `reinstated`），`employeeHealthCheckScheduler` 仍处于禁用状态。

## 1. 任务 A：回填脚本增强（v1.2）

**文件**：`server/scripts/backfillEmployeeId.cjs`

### 1.1 扩展覆盖范围

当前仅覆盖 2 张表，v1.2 需扩展到 **5 张表**：

| 表 | 目标列 | 匹配策略 | 说明 |
|----|--------|---------|------|
| `training_records` | `employee_id` | id_card_hash → name | 已有，保留 |
| `violation_records` | `violator_id` | name（唯一匹配） | 已有，保留 |
| `hazards` | `checker_id` | name → employee.id | 新增 |
| `hazards` | `fixer_id` | name → employee.id | 新增 |
| `accidents` | `handler_id` | name → employee.id | 新增 |
| `emergency_plans` | `responsible_person_id` | name → employee.id | 新增 |

### 1.2 新增身份证号匹配（三违模块增强）

三违表当前仅有 `violator_name` 无 `violator_id_card`。如果 Sprint D Step 10 已新增 `violator_id_card` 列，则增加身份证号匹配路径：

```js
// 优先：身份证号匹配（如果列存在）
if (hasIdCardColumn) {
  const hashed = hashSensitive(record.violator_id_card);
  const match = await client.query(
    `SELECT id FROM employee WHERE id_card_hash = $1 AND is_deleted = false LIMIT 1`,
    [hashed]
  );
  if (match.rows.length === 1) return match.rows[0].id;
}
// 降级：姓名匹配
```

### 1.3 批量查询优化

将逐条 SELECT 改为批量查询，减少数据库往返：

```js
// 批量收集待匹配的姓名，一次查询
const names = records.map(r => r.name).filter(Boolean);
const employeeMap = await client.query(
  `SELECT id, name FROM employee WHERE name = ANY($1) AND is_deleted = false`,
  [names]
);
// 构建 name → id 映射（仅唯一匹配）
const nameToId = new Map();
const nameCounts = new Map();
for (const row of employeeMap.rows) {
  nameCounts.set(row.name, (nameCounts.get(row.name) || 0) + 1);
  nameToId.set(row.name, row.id);
}
// 仅保留唯一匹配的 name
for (const [name, count] of nameCounts) {
  if (count > 1) nameToId.delete(name);
}
```

### 1.4 事务包裹 + 结果持久化

```js
await client.query('BEGIN');
try {
  // 逐表回填
  for (const table of TABLES) {
    await backfillTable(client, table);
  }
  await client.query('COMMIT');
} catch (err) {
  await client.query('ROLLBACK');
  throw err;
}
```

结果写入 `backfill_log` 表（如不存在则自动创建）：

```sql
CREATE TABLE IF NOT EXISTS backfill_log (
  id SERIAL PRIMARY KEY,
  table_name VARCHAR(100),
  column_name VARCHAR(100),
  total_nulls INTEGER,
  matched_count INTEGER,
  updated_count INTEGER,
  skipped_count INTEGER,
  executed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  dry_run BOOLEAN DEFAULT false
);
```

### 1.5 安全机制（保留 v1.0 约束）

- 生产环境 + 无 `--dry-run` → `process.exit(1)` 硬拦截
- `--dry-run` 仅统计、不写入
- 回填前打印预估影响行数

## 2. 任务 B：巡检视图 status 枚举对齐

**文件**：`docs/Sprint-C-v1.0/02_SQL/Employee_Model_Check.sql`

### 2.1 不一致现状

| 来源 | status 白名单 |
|------|--------------|
| `Employee_Model_Check.sql`（巡检视图） | `active`, `leave`, `transfer`, `pending`, `inactive`, `retired` |
| `employeeAssignmentService.js`（STATUS_MAP） | `active`, `pending`, `inactive`, `retired`, `reinstated` |

### 2.2 修复

将巡检视图 INVALID_STATUS 检查的白名单与 `STATUS_MAP` 对齐，移除 `leave`/`transfer`，增加 `reinstated`：

```sql
-- 修改前
WHERE status NOT IN ('active', 'leave', 'transfer', 'pending', 'inactive', 'retired')

-- 修改后
WHERE status NOT IN ('active', 'pending', 'inactive', 'retired', 'reinstated')
```

同时检查 `Employee_Model_Check.sql` 中所有 status 硬编码处，确保全部对齐。
