## 5. 经验沉淀（可复用）

1. **门控实勘范式（FK 工程核心）**：落地前必用 `information_schema` 核验列存在性/可空性/类型；只读审计孤儿（引用 id 在父表主键**完全不存在**，含软删除态也算存在）；可空列 SET NULL、NOT NULL 活跃孤儿按红线跳过+人工介入；`DO $$` 幂等块建约束（重跑自愈合）。
2. **触发器是清理的隐形护栏**：`hse_deduction_adjustment` / `hse_assessment_audit_log` 有 `BEFORE DELETE OR UPDATE` 防改触发器 → 清理须 `DISABLE TRIGGER` → 删 → 立即 `ENABLE TRIGGER` 复核 ENABLED。
3. **Windows PG 二进制路径坑**：`pg_dump`/`psql`（`/d/PostgreSQL/17/bin/`）不识别 `/f/...` Unix 路径读文件/输出，须用 Windows 风格 `F:/hse-dashboard/...`。
4. **后端非热加载**：`node app.js` 无 nodemon，改后端须 `netstat -ano|findstr :5666` 取 PID → `taskkill /F /PID` 仅杀 :5666 监听进程（勿波及 Vite）。
5. **后台任务 failed ≠ 服务宕机**：孤儿进程继续跑，存活看 `netstat :5666` + `curl /api/health`。
6. **响应解包模式（前端关键坑）**：Vben `request` 客户端 `responseReturn:'data'` + `defaultResponseInterceptor({codeField:'code',dataField:'data',successCode:0})` → 返回**解包后的内层 `{list,total}`**，非信封 `{code,data}`；读 `r.code`/`r.data.*` 一律 undefined。应急 5 视图曾因按信封取数恒空。
7. **路由白名单机制**：`router/routes/index.ts` 的 `dynamicRouteFiles` 数组控制动态路由文件是否注册（Grep 命中 ≠ 活动文件）；`/violations` 404 即因 `hse-violations.ts` 未入白名单。
8. **F: 盘满环境应对**：`rm` 走回收站垫片不释放空间；`pnpm store` 在个人目录不可动；空间查 `node -e "fs.statfsSync('F:/')"`；满时备份落 D: 盘；`pnpm build` 受阻时以「后端 API 实测 + `node --check`」替代。
9. **用户授权突破红线**：D 任务（`emergency_events` 缺列）/69 扩展（`timeline` 漂移）/66 补列等经 `AskUserQuestion` 明确授权后扩范围，均在授权范围内并实测通过。
10. **迁移漂移专项闭环方法**：对 `hse_core_v1_migration.sql` 做「声明列 vs 实际列」全量 diff → 缺列补建（类型校验）、零引用废弃列 DROP、类型漂移仅做 widening 安全 ALTER，最终声明与实际完全对齐。
