## 3. 修改项 diff 摘要

### 3.1 R1：后端 emergency.js 添加 requireRole 鉴权（P0）

- 顶部新增导入：`const { requireRole } = require('../middleware/auth');`
- 在 **20 个**写操作 / 敏感读端点插入 `requireRole('admin', 'safety_manager')` 中间件：
  - 预案：`POST /plans`、`PUT /plans/:id`、`DELETE /plans/:id`、`GET /plans/export`
  - 演练：`POST /drills`、`PUT /drills/:id`、`DELETE /drills/:id`、`GET /drills/export`
  - 物资：`POST /materials`、`PUT /materials/:id`、`DELETE /materials/:id`、`GET /materials/export`
  - 队伍：`POST /teams`、`PUT /teams/:id`、`DELETE /teams/:id`
  - 事件：`POST /events`、`PUT /events/:id`、`DELETE /events/:id`
  - 通用附件：`POST /:bizType/:id/attachments`、`DELETE /:bizType/:id/attachments/:aid`
- **与提示词偏差**：提示词 R1 还列出 `POST/PUT/DELETE /teams/:id/members`（3 个），但**当前 emergency.js 中该端点根本不存在**（grep 仅有 `GET /teams/:id/members` 读端点）。故按实跳过，实际添加 20 个端点（探针 R1 验证 4 项全过）。
- 读端点（列表/详情/统计）保持仅 `authMiddleware`，查看权限开放，符合提示词意图。

**探针验证**：`POST /plans` 无 token→401、viewer→403、admin→200；`POST /drills` viewer→403。均符合预期。

### 3.2 R2：演练 schema 前后端对齐（P0 + P1-3）

**后端 `emergency.js`**：
- `formatDrillRow` 重写：映射真实列 `no/drillDate/township/name/drillLevel/drillType/participants/duration/location/organizer/result/remark/status`（移除不存在的 `planId/planTitle/evaluator/summary/improvements`）。
- `POST /drills` INSERT 重写：`INSERT INTO emergency_drills (no, drill_date, township, name, drill_level, drill_type, participants, duration, location, organizer, result, remark, status)`，默认值 `no=DR{ts}`、`status='已完成'`。
- `PUT /drills/:id` UPDATE 重写：COALESCE 列列表同步为真实列。
- `GET /drills/export` SELECT + `sendDrillCsvExport` 重写：列头 `编号/演练日期/乡镇/名称/演练级别/演练类型/参演人数/时长(分钟)/地点/组织单位/结果/状态/备注`。
- `GET /drills` 列表过滤：keyword 改为 `(name ILIKE OR township ILIKE OR organizer ILIKE)`；**移除不存在的 `plan_id` 过滤**（真实表无该列，否则触发 SQL 错误）。

> 实现注：提示词 R2.2/R2.3 代码片段有 `const { result } = req.body` 后立即 `const result = await pool.query(...)` 的**重复声明 bug**；实现时改用 `insertResult` / `updateResult` 变量规避，行为一致。

**前端 `api/hse/emergency.ts`**（`DrillRecord` 类型）→ 真实字段（R2.6）。
**前端 `drills/index.vue`**：
- 列定义改为 `no/name/township/drillLevel/drillType/drillDate/location/organizer/participants/duration/result/status`（R2.7）。
- **表单字段对齐**（使 CRUD 真正落库，属 R2「整体修复」必要补强）：演练名称 `drill_name`→`name`、评估人→组织单位 `organizer`、演练总结→备注 `remark`，移除无对应列的「改进措施」。

### 3.3 R3：预案导出修复（P1）

`GET /plans/export` SELECT 移除不存在的 `version/validity_period`，改为 `SELECT ... effective_date, expiry_date ...`；`sendPlanCsvExport` 列头改为 `预案名称/类型/级别/责任部门/责任人/联系电话/生效日期/到期日期/状态/备注`。

### 3.4 R4：预案时效修复（P1）

- `calcExpiryStatus` 签名由 `(effectiveDate, validityPeriod)` 改为 `(expiryDate)`，基于 `expiry_date` 计算：`expired / expiring(≤30d) / valid / permanent(无日期)`。
- `formatPlanRow` 调用、`GET /plans` 内存模式、`GET /plans/export` 双模式调用同步更新。
- 前端 `plans/index.vue` 新增「时效状态」列（Badge：正常/临期/已过期/长期有效），使后端修正可见（R4「时效展示微调」）。

### 3.5 R5：5 子页保存逻辑修复（P1）

`plans / drills / materials / teams / events` 五个 `index.vue` 的 `handleSave`（及 `handleDelete`）移除恒假的 `if (r.code === 0)` 判定，改为 try/catch 直接判定成功（`responseReturn:'data'` 模式下请求成功返回业务对象、失败走 catch）。修复后新建/编辑弹窗正常关闭、列表刷新、提示「新增成功/编辑成功」。

### 3.6 红线相关桥接说明（index.vue 范例文件）

`DrillRecord` 类型按 R2.6 改为真实字段后，会令红线「禁止修改」的 `views/emergency/index.vue`（1452 行多 Tab 范例，未注册路由、属死代码）类型检查失败。为**既满足 R2.6 又不触碰禁改文件**，将旧字段 `planId/planTitle/evaluator/summary/improvements` 在 `DrillRecord` 中**保留为可选**。活跃子页使用 `reactive<any>`，根本不引用 `DrillRecord`，无运行时影响。`index.vue` 文件本身未被修改。
