## 2. 分维度明细

### 维度一：前端代码质量
- **框架规范**：10 个页面（`index/ledger/new-employee/driver/plans/requirements/execute/reminders/stats/analysis`）全部使用 `Page` 组件（`@vben/common-ui`）+ Ant Design Vue，无 Element Plus 混入 ✓。
- **组合式托管**：仅 `index.vue` 使用 `useDataTable`/`useSearchForm`；其余 9 个页面自行管理表格/分页（D11）。
- **TS 类型**：`vue-tsc --noEmit --skipLibCheck` 对 `training/**` **无任何错误**（详见 §4.2）。但类型定义本身与运行时响应不匹配（D2，属运行期而非编译期问题，故类型检查不报）。
- **硬编码规则（D8）**：`index.vue:538` `type:'safety'`、`ledger/index.vue:469/472` `result==='合格'/'不合格'`、`plans/index.vue:366` `status:'draft'`、`index.vue:623` `status:'ongoing'`。这些前端枚举与 `training-assessment-rule.json` 的 `trainingTypes`(`new_employee/regular/special/seasonal/re_training/emergency/driver/position`)、`assessmentGrades`(`pass/fail`)、`planStatusFlow`(`in_progress`) **代码值不一致**；规则文件自述"只读影子数据，不参与业务计算"，前端也未调用 `/rules/*` 端点，故规则文件实际未被驱动。

### 维度二：后端代码质量
- **语法**：`node --check training.js` 与 `node --check training-assessment.js` 均通过 ✓。
- **路由注册顺序（D4）**：`training-assessment.js` 中 `GET /records/export`(611) 在 `GET /records/:id`(184) 之后 → 被 `:id` 遮蔽。探针验证：`GET /api/training-assessment/records/export` 返回 `status=200, ct=application/json, message="操作失败"`（即被 `/records/:id` 处理器捕获 `id='export'` → `SELECT * WHERE id='export'` 报错）。**同类问题在 131-F1/132-R1 已修复，本次为第三处遗漏**。对比：`training.js` 的 `/records/export`(288) 已在 `/records/:id`(335) 之前（带防御注释），正确。
- **鉴权（D1）**：两个文件 **0 处 `requireRole`**。全模块仅依赖全局 `authMiddleware`（登录即放行），与超龄模块修复前（F6/R4）同源问题。
- **双模式一致性（D5）**：`GET /records/:id`(339) 与 `DELETE /records/:id`(429) 内存模式用 `memoryPlans.find(...)`（应为 `memoryRecords`）；`GET /records`(237) 内存模式取 `memoryPlans`、PG 模式取 `training_records`。降级模式下单条查询/删除失效，且计划视图数据形状随模式切换。
- **`resolveEmployeeId`**（training.js:29）：优先用传入 `employee_id`，否则 `hashSensitive(idCard)` 查 `employee.id_card_hash`，逻辑正确 ✓。
- **`ensureTables`**（training.js:50）：全部 `CREATE TABLE IF NOT EXISTS` + `ALTER TABLE ADD COLUMN IF NOT EXISTS`，幂等 ✓。
- **软删除（D7）**：`training-assessment.js GET /records/:id`(184) `SELECT * FROM training_records WHERE id=$1` 未加 `is_deleted=false`；探针 `GET /records/999999999` 返回 `{code:0,data:null}`（无 404），已删记录也可被该端点原样返回。

### 维度三：数据流一致性
- **前后端字段名（D2）**：探针实测 `GET /training/records` 返回字段 `id,name,personnelId,employeeId,supervisorId,supervisorName,trainerId,trainingPlanId,idCard,department,position,gridLevel...`；而 `index.vue` 列绑定 `dataIndex:'title'/'type'/'status'`（636/637/638）→ 这些列取值为 `undefined`，**培训标题/类型/状态三列空白**。根因：`index.vue` 用 `TrainingApi.TrainingPlan`（计划型字段）对接 `/training/records`（记录型响应）。
- **双表语义（D6）**：`training_records` 被设计成"同时承载计划与记录"，但 `training.js` 写入计划视角字段（`title` 型入参 → 实际落 `name`）、`training-assessment.js` 写入另一套记录字段（`record_no/training_title/hours_actual/...`）。两文件对同一表字段约定不统一。
- **重复/孤立端点（D3）**：`training.js` 与 `training-assessment.js` 各有 `/records`、`/plans`（不同前缀 `/api/training` vs `/api/training-assessment`，无字面冲突），但 `training-assessment.js` 全文件 38 端点**无任何前端 API 函数或页面引用**（全仓 grep `training-assessment` 仅命中 `warning-center.ts` 无关匹配）。即 `/assessments`、`/certificates`、`/comprehensive`、`/rules/*`、`/stats/overview` 均为孤立后端。
- **导出一致性**：`training.js /records/export` 字段与页面一致 ✓；`training-assessment.js /records/export` 因 D4 不可达 ✗。

### 维度四：边界与异常
- **空状态**：各列表页均有 `v-if` 空态占位（未逐页深入，但组件结构含空态）。
- **日期边界**：`calcExpiryStatus(trainingDate, validityPeriod)`（training.js:156）基于 `training_date + 12月(默认)` 计算到期；证书有效期用规则 `certificateTypes.validityYears`。后端用 `training_date` 字段，前端 `execute` 表单 `trainingDate` 有值，边界基本覆盖。
- **文件上传（✓ 通过）**：`uploadDocument` 中间件（`server/middleware/upload.js`）限制 `fileSize: 10MB` + 魔术字节签名校验（`FILE_SIGNATURES`），防伪造类型 ✓。
- **敏感信息（D9）**：`training_records.id_card` 明文存储，`formatRecordRow` 原样返回 `idCard`（探针确认响应含 `idCard` 字段）。前端 `new-employee`/`driver` 页面以 `<Input maxlength=18>` 收集身份证号用于 `resolveEmployeeId` 关联，但**列表/详情未做脱敏展示**（与超龄模块 R2 已脱敏形成反差）。属 PII 暴露面。
- **统计口径**：`GET /training/stats` 返回 `totalPlans/ongoing/completed/totalAttendees/passRate/byType`；`byType` 在内存模式为 `{}`、PG 模式有值 → 与 D5 同源双模式不一致。前端 `index.vue` 用 `statsData.ongoing/completed` 渲染统计卡（623-624），PG 模式下正常。

### 维度五：回归检查
- **菜单/路由一致性（✓ 通过）**：`hse-08-training.ts` 5 子项注册于 `index.ts:15`，`app.js:333-334` 挂载 `/api/training` 与 `/api/training-assessment`，redirect `/training`→`/training/plans` ✓。
- **隐藏页面（D10）**：`new-employee/driver/execute/reminders/analysis` 5 个页面未进菜单（疑为 Tab/抽屉内嵌入口）。
- **命名歧义（D10）**：菜单「证书管理」→ `index.vue`（培训主页）、「考核管理」→ `requirements/index.vue`（培训要求）；与后端端点语义不完全对应。
- **跨模块依赖**：`training.js` 经 `employee_assignment`/`employee` 取直接上级（`supervisor_id/name`），`resolveEmployeeId` 查 `employee` 表 —— 依赖员工模块 ✓。
- **规则文件加载**：`/rules/*` 端点能正确返回 `training-assessment-rule.json` 内容（探针 `rules/all` `code=0`），但前端未消费（D3/D8）。
- **前端构建（§4.2）**：生产构建含培训模块 chunk（见 §4.3）。
