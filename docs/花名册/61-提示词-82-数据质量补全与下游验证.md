## 三、执行任务

### 任务1：补全空岗位（D2）

**目标**：为18名 position_id 为空的员工补全岗位。

**执行步骤**：

1. 查询所有 position_id 为空的员工及其 raw_position：

```sql
SELECT e.id, e.name, e.employee_code, a.raw_dept
FROM employee e
JOIN employee_assignment a ON a.employee_id = e.id AND a.is_current = true AND a.is_deleted = false
WHERE e.is_deleted = false AND a.position_id IS NULL;
```

2. 根据 raw_dept 和常见岗位模式推断目标岗位（如"乡镇保洁员"→ position 表中对应ID）

3. 通过 `employee_assignment` UPDATE 补填 position_id，而非新建映射规则

4. 验证：补填后 V6 项（position_id 全部非空）通过

### 任务2：推断并补全 person_type（D3）

**目标**：根据现有信息推断 person_type，减少 NULL 值。

**执行步骤**：

1. 复用 `inferPersonType()` 函数逻辑（根据 raw_dept + raw_position 推断）：
   - 包含"管理/经理/区长/班长" → 管理人员
   - 包含"安全/专员/会计/人事" → 技术人员
   - 包含"保洁/司机/驾驶员/中转站/挂桶" → 生产人员
   - 其他 → 辅助人员

2. 从 `employee_import_pending` 或 `employee_assignment` 中提取 raw_dept/raw_position 信息

3. 批量 UPDATE employee 表的 person_type 字段

4. 验证：补填后 person_type NULL 值大幅减少，分布合理

### 任务3：处理50名文件外员工

**目标**：确认50名不在源文件中的员工归属。

**执行步骤**：

1. 查询这50名员工的完整信息（工号、姓名、部门、岗位、业务记录数）

2. 判断归属：
   - 若属于其他单位的花名册 → 保留，标注来源
   - 若属于本批漏导 → 建议并入源文件
   - 若已离职但持有业务记录 → 保留，标记状态

3. 生成清单文件供业务确认

### 任务4：下游模块可用性验证

**目标**：确认其他模块可正常使用花名册员工数据。

**验证方法**：

1. 检查各模块的员工选择器/下拉框是否正确加载 1,361 名员工
2. 检查各模块的员工姓名显示是否正常（EmployeeName 组件）
3. 检查 employee_assignment 的组织/岗位/上级关系在各模块中是否正确展示
4. 检查 v_employee_current 视图数据完整性

**验证范围**：
