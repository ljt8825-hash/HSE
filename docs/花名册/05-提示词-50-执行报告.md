## 2. 任务 A（P0）：入库事务 SAVEPOINT 改造

**文件**：`server/routes/hse-employee-import-v2.js`，`POST /batch/:batchId/import`

**改动要点**（L953-1064）：
- `for (const p of ...)` → `for (let i = 0; i < ...; i++)`，取 `const p = pendingResult.rows[i]; const spName = \`sp_${i}\`;`
- 每行处理前 `await client.query(\`SAVEPOINT ${spName}\`);`
- 成功路径末尾 `await client.query(\`RELEASE SAVEPOINT ${spName}\`);`
- 失败 catch 开头 `ROLLBACK TO SAVEPOINT ${spName}`（包一层 try/catch 兜底外层的 ROLLBACK），失败行错误信息改为 `第${p.row_num}行: ...`
- 批次状态逻辑保持不变：有失败→`partial_completed`，全成功→`completed`

**效果**：某行因 PG 约束错误 abort 事务后，仅回滚到该行保存点，后续行仍正常入库，彻底消除 "current transaction is aborted" 串炸问题。

## 3. 任务 B（P1）：前端入库前拦截

**文件**：`views/hse/employee-import-v2/index.vue`，`openImportConfirm()`（L358）

**改动**：点击"确认入库"时按顺序拦截：
1. 存在 `status==='pending'` 的未审核异常数据 → `Modal.warning`（"存在未审核的异常数据"，含条数），return
2. 无 `status==='approved'` 记录 → `Modal.warning`（"无可入库数据"），return
3. 正常 → `Modal.confirm`，提示语带具体可入库数量 `即将把 N 条...`

依赖 `pendingList`（打开详情抽屉时已 `loadPendingList()` 加载），调用时若为空则走第 2 条拦截。
