### 4.1 修改项 T1：添加 requireRole 鉴权（P1）

**文件**：`server/routes/training.js`、`server/routes/training-assessment.js`

**问题**：两个文件全部端点均无 `requireRole`，仅依赖全局 `authMiddleware`（登录校验）。与超龄模块修复前（F6/R4）同源问题。

**修复**：

1. 在两个文件顶部添加导入：

```javascript
const { requireRole } = require('../middleware/auth');
```

2. `training.js` 需要添加 `requireRole` 的端点（参考 `over-age-personnel.js` 的 `requireRole('admin', 'safety_manager')`）：

   - `DELETE /records/:id`(L425) → 添加 `requireRole('admin', 'safety_manager')`
   - `POST /ledger`(L494) → 添加 `requireRole('admin', 'safety_manager')`
   - `PUT /ledger/:id`(L515) → 添加 `requireRole('admin', 'safety_manager')`

   - `POST /new-employees`、`PUT /new-employees/:id`、`DELETE /new-employees/:id` → 添加 `requireRole('admin', 'safety_manager')`
   - `POST /driver`、`PUT /driver/:id`、`DELETE /driver/:id` → 添加 `requireRole('admin', 'safety_manager')`
   - `POST /plans`、`PUT /plans/:id`、`DELETE /plans/:id` → 添加 `requireRole('admin', 'safety_manager')`

   - `POST /requirements`、`PUT /requirements/:id`、`DELETE /requirements/:id` → 添加 `requireRole('admin', 'safety_manager')`

### 4.2 修改项 T2：主培训页面前后端字段对齐（P1）

**文件**：`安全看板vben/apps/web-antd/src/views/training/index.vue`、`安全看板vben/apps/web-antd/src/api/hse/training.ts`

**问题**：前端 `index.vue` 使用 `useDataTable<TrainingApi.TrainingPlan>` 调用 `GET /training/records`，但后端 `formatRecordRow` 返回的是记录型字段（`name/trainingType/trainingDate/result/score` 等），不包含 `title/type/status` 等计划型字段。

**根因**：
- API 函数 `getTrainingPlanList` 调 `/training/records`（返回记录型数据）
- 类型 `TrainingApi.TrainingPlan` 定义的是计划型字段（`title/type/status`）

**修复**：

1. 在 `training.ts` 中，修改 `TrainingApi.TrainingPlan` 接口，使其匹配 `/training/records` 实际返回的字段。将原有的 `TrainingPlan` 接口重命名为 `TrainingPlanForm`（用于表单），新增 `TrainingPlanItem` 接口（用于列表展示）：

```typescript

export interface TrainingPlanItem {
  id: number;
  name: string;              // 对应旧 title

  result: string;             // 对应旧 status（培训结果）
  trainer: string;
  supervisorId?: number | null;
  supervisorName?: string | null;
  employeeId?: number | null;
  trainingPlanId?: number | null;
  idCard?: string;
  department: string;
  position: string;
  gridLevel?: string;
  frequency?: string;
  trainingDate: string;
  durationMinutes: number;
  content: string;
  score: number | null;
  remark?: string;
  expiryStatus?: string;
  createdAt?: string;
  updatedAt?: string;
}
```

2. 修改 `getTrainingPlanList` 返回类型为 `TrainingPlanItem`：
```typescript
export async function getTrainingPlanList(params: TrainingApi.TrainingListParams) {
  return requestClient.get<{ list: TrainingApi.TrainingPlanItem[]; total: number }>(
    '/training/records',
    { params },
  );
}
```

3. 在 `index.vue` 中：
   - 将 `useDataTable<TrainingApi.TrainingPlan>` 改为 `useDataTable<TrainingApi.TrainingPlanItem>`
   - 修改表格列绑定：
```typescript
const originalColumns = ref([
```

4. 修改模板中 `#bodyCell` 槽位的对应字段名（`record.type` → `record.trainingType`、`record.status` → `record.result`）以及相关辅助函数（`getTypeColor/getTypeText/getStatusColor/getStatusText`）。

### 4.3 修改项 T3：修复 training-assessment.js 路由遮蔽（P2）

**文件**：`server/routes/training-assessment.js`

**问题**：`GET /records/export`(L611) 注册在 `GET /records/:id`(L184) 之后，Express 路由按注册顺序匹配，`export` 被 `:id` 捕获 → 导出端点不可达。

**修复**：

1. 将 `GET /records/export` 路由注册代码块（L611–L621）整体前移至 `GET /records/:id`(L184) 之前。

2. 在与 `GET /records` 路由（L161）之后、`GET /records/:id` 之前的位置插入：
```javascript
// 导出CSV（必须在 /records/:id 之前注册，避免 :id 捕获字面量 export）
router.get('/records/export', requireRole('admin', 'safety_manager'), async (req, res) => {
  try {
    const result = await pool.query('SELECT * FROM training_records WHERE is_deleted=FALSE ORDER BY training_date DESC LIMIT 5000');
    const headers = ['培训编号','培训标题','类型','培训日期','员工姓名','员工编号','部门','岗位','实际学时','考核结果','状态'];
    const rows = result.rows.map(r => [r.record_no, r.training_title, r.training_type, r.training_date, r.employee_name, r.employee_no, r.dept_name, r.position, r.hours_actual, r.assessment_result, r.status]);
    const csv = [headers, ...rows].map(row => row.map(c => `"${c||''}"`).join(',')).join('\n');
    res.setHeader('Content-Type', 'text/csv; charset=utf-8');
    res.setHeader('Content-Disposition', 'attachment; filename=training_records.csv');
    res.send('\uFEFF' + csv);
  } catch(e) { res.json(error(e.message)); }
});
```

> 注意：参考 `training.js` 中 `GET /records/export`(L288) 已在 `GET /records/:id`(L335) 之前（带防御注释 `// NOTE: export route must be registered before /:id`），两处处理方式一致。

### 4.4 修改项 T4：修复 training.js 内存降级模式（P2）

**文件**：`server/routes/training.js`

**问题**：`GET /records/:id`(L339) 与 `DELETE /records/:id`(L429) 内存降级模式使用 `memoryPlans`（计划型数据），但 PostgreSQL 模式查询 `training_records`（记录型数据）→ 双模式不一致。

**修复**：

1. `GET /records/:id`(L339)：将 `memoryPlans.find(...)` 改为 `memoryRecords.find(...)`：
```javascript
// 修改前
const record = memoryPlans.find(r => r.id === parseInt(req.params.id) && !r.is_deleted);
// 修改后
const record = memoryRecords.find(r => r.id === parseInt(req.params.id) && !r.is_deleted);
```

2. `DELETE /records/:id`(L429)：将 `memoryPlans.find(...)` 改为 `memoryRecords.find(...)`，并将 `memoryPlans[idx].is_deleted = true` 改为 `memoryRecords[idx].is_deleted = true`：
```javascript
// 修改前
const record = memoryPlans.find(r => r.id === parseInt(req.params.id) && !r.is_deleted);
// ...
memoryPlans[idx].is_deleted = true;
// 修改后
const record = memoryRecords.find(r => r.id === parseInt(req.params.id) && !r.is_deleted);
// ...
memoryRecords[idx].is_deleted = true;
```

### 4.5 修改项 T5：training-assessment.js 软删过滤（P2）

**文件**：`server/routes/training-assessment.js`

**问题**：`GET /records/:id`(L184) 的 SQL 查询未过滤 `is_deleted`，返回已软删记录且不报 404。

**修复**：

将 L186 的 SQL 查询改为：
```javascript
// 修改前
const r = await pool.query('SELECT * FROM training_records WHERE id=$1', [req.params.id]);
// 修改后
const r = await pool.query('SELECT * FROM training_records WHERE id=$1 AND is_deleted = FALSE', [req.params.id]);
```

同时添加不存在判断：
```javascript
router.get('/records/:id', async (req, res) => {
  try {
    const r = await pool.query('SELECT * FROM training_records WHERE id=$1 AND is_deleted = FALSE', [req.params.id]);
    if (r.rows.length === 0) return res.json(error(-2, '记录不存在'));
    res.json(success(r.rows[0]));
  } catch(e) { res.json(error(e.message)); }
});
```

### 4.6 修改项 T6：身份证号脱敏展示（P2）

**文件**：`server/routes/training.js`、`安全看板vben/apps/web-antd/src/views/training/new-employee/index.vue`、`安全看板vben/apps/web-antd/src/views/training/driver/index.vue`

**问题**：`training_records.id_card` 明文存储，`formatRecordRow` 原样返回 18 位明文身份证号。与超龄模块 T2（131-F2）同类 PII 暴露。

**修复**：

1. **后端脱敏**：在 `training.js` 的 `formatRecordRow` 函数中，将 `idCard` 字段改为脱敏输出：
```javascript
// 修改前
idCard: row.id_card || '',
// 修改后（保留前4后4，中间替换）
idCard: maskIdCard(row.id_card),
```

在 `formatRecordRow` 之前添加脱敏工具函数：
```javascript
/**
 * 身份证号脱敏：保留前4后4，中间替换为 **********
 */
function maskIdCard(idCard) {
  if (!idCard || typeof idCard !== 'string') return '';
  if (idCard.length <= 8) return idCard;
  return idCard.slice(0, 4) + '**********' + idCard.slice(-4);
}
```

> 注意：`id_card`（snake_case）原始字段仍保留明文（`id_card: row.id_card`），仅 `idCard`（camelCase）展示字段脱敏。这样导出 CSV 等需要原始值的场景可以从 `id_card` 字段获取。

2. **前端脱敏**：`new-employee/index.vue` 和 `driver/index.vue` 收集身份证号的 `<Input>` 组件，在列表展示的 `idCard` 列使用 `customRender` 或 `bodyCell` 槽位做脱敏渲染：

```typescript
// 在 new-employee/index.vue 和 driver/index.vue 的 <script setup> 中添加
function maskIdCard(idCard: string | undefined | null): string {
  if (!idCard) return '-';
  if (idCard.length <= 8) return idCard;
  return idCard.slice(0, 4) + '**********' + idCard.slice(-4);
}
```
