## 一、修复目标与根因（实测核对）

用户反馈两个 P0 显示问题，实测根因如下：

| # | 问题 | 根因（实测） | 修复方式 |
|---|------|------------|---------|

## 二、关键决策：position 1405 不恢复

提示词-96 任务1 步骤2 建议"若 1405 近期被软删则恢复"。实测：

- `position` id=1405 `name='经理'`, `is_deleted=true`, `updated_at=2026-07-31 22:13`（晚于刘金涛导入时间）。
- `matchPosition()` 的 L3 模糊兜底 SQL 已含 `is_deleted=false` 过滤，本就**不应**命中 1405。
- 若恢复 1405（active），其 name='经理' 会使 `'安环管理部经理' LIKE '%经理%'` 对**所有**"X经理"来源都模糊命中 1405 —— 即重新引入本次要修复的 bug。

**结论**：1405 的软删恰恰是正确行为（阻止了泛型"经理"被错误模糊匹配）。本次通过新增显式规则(id=39)让 L2 命中，绕过 L3，从根上修复，**不恢复 1405**。该决策已记录，避免后续误改。
