## 0. 背景

提示词-69 为 `hse_event_timeline` 补全了 4 个迁移声明列（`from_status/to_status/comment/occurred_at`），同时保留了 5 个漂移旧列（`status_from/status_to/description/timestamp/created_at`）。提示词-70 全量 diff 确认这 5 列「声明无、实际有」，属于废弃列，且额外发现 4 处类型漂移。

本任务目标：**安全清理废弃列 + 修复类型漂移**，完成 DB schema 与迁移声明的最终对齐。

## 1. 任务清单

### 任务 A：废弃列代码引用扫描（只读，门控）

对 `hse_event_timeline` 5 个废弃列在 `server/` 下做全量引用扫描：

| 废弃列 | 正确列（69 已补） |
|--------|-------------------|
| `status_from` | `from_status` |
| `status_to` | `to_status` |
| `description` | `comment` |
| `timestamp` | `occurred_at` |
| `created_at` | —（无对应迁移列，但代码可能引用） |

**门控规则**：
- 若任一废弃列被 `server/routes/`、`server/services/` 引用 → **红线跳过该列**，记录引用位置，不 DROP
- 仅零引用的列才进入任务 B 执行 DROP

### 任务 B：废弃列 DROP（幂等）

对通过门控的列，写出 `server/sql/hse_fk71_drop_timeline_stale_cols.sql`：

```sql
BEGIN;
-- 仅 DROP 零引用列（门控后确认清单）
ALTER TABLE hse_event_timeline DROP COLUMN IF EXISTS status_from;
ALTER TABLE hse_event_timeline DROP COLUMN IF EXISTS status_to;
ALTER TABLE hse_event_timeline DROP COLUMN IF EXISTS description;
ALTER TABLE hse_event_timeline DROP COLUMN IF EXISTS timestamp;
ALTER TABLE hse_event_timeline DROP COLUMN IF EXISTS created_at;
COMMIT;
```

> 若某列门控跳过（代码有引用），从脚本中移除该行，执行报告中标记「跳过 + 引用位置」。

### 任务 C：类型漂移评估与修复

对提示词-70 记录的 4 处类型漂移逐表评估是否可安全 ALTER：

| 表 | 列 | 声明类型 | 实际类型 | 评估要点 |
|------|------|------|------|------|
| `hse_risk_factors` | `risk_value` | NUMERIC(6,2) | integer | 是否有小数数据？integer→numeric 安全 |
| `hse_control_measures` | `effectiveness_score` | NUMERIC(4,2) | integer | 是否有小数数据？ |
| `hse_reviews` | `score` | NUMERIC(4,2) | integer | 是否有小数数据？ |
| `hse_rectifications` | `deadline` | TIMESTAMPTZ | date | date→timestamptz 安全（隐式转换） |

**执行策略**：
- `integer → NUMERIC`：**安全**（ widening 转换，不丢精度），直接 ALTER
- `date → TIMESTAMPTZ`：**安全**（隐式转换，date '2026-01-01' → timestamptz '2026-01-01 00:00:00+00'），直接 ALTER
- 若任何列有反向漂移（声明类型窄于实际类型，如 NUMERIC→integer 但存在小数数据）→ **跳过 + 人工介入**

写出 `server/sql/hse_fk71_fix_type_drifts.sql`：

```sql
BEGIN;
-- integer → numeric（安全，widening）
ALTER TABLE hse_risk_factors       ALTER COLUMN risk_value          TYPE NUMERIC(6,2);
ALTER TABLE hse_control_measures   ALTER COLUMN effectiveness_score TYPE NUMERIC(4,2);
ALTER TABLE hse_reviews            ALTER COLUMN score               TYPE NUMERIC(4,2);
-- date → timestamptz（安全，隐式转换）
ALTER TABLE hse_rectifications     ALTER COLUMN deadline            TYPE TIMESTAMPTZ;
COMMIT;
```

## 5. 风险提示

- **废弃列 DROP 不可逆**：DROP COLUMN 后无法回滚（备份恢复除外），必须门控 A 严格零引用
- **created_at 特殊处理**：`hse_event_timeline.created_at` 无对应迁移声明列，但若代码有引用则为合法列，从废弃清单中移除
- **类型 ALTER 可能锁表**：`ALTER COLUMN TYPE` 需全表扫描重写，若表数据量大可能耗时（当前 hse_event_timeline 数据量预期小，风险低）
- **F: 盘满**：与提示词-68/69/70 同，备份落 D: 盘，`pnpm build` 仍无法执行
