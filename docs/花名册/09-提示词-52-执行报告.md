# 提示词-52 执行报告：花名册模块模板下载坏链修复

> 关联提示词：`docs/花名册/07-提示词-52-模板下载坏链修复.md`
> 关联前置发现：`docs/花名册/08-提示词-51-回归验证报告.md`（提示词-51 回归时发现并记录的未修 Bug）
> 执行方式：Craft（直接落地修复 + 验证）

## 1. 任务背景

提示词-51 浏览器回归验证时发现一个真实 Bug：花名册导入页的「下载模板」按钮点击后下载到的是 **SPA 回退 HTML 文件（被改名成 .xlsx）** 或 **404**，无法拿到真正的 Excel 模板。

- 前端代码：`views/hse/employee-import-v2/index.vue` 的 `handleDownloadTemplate()` 写死 `link.href = '/templates/员工花名册导入模板.xlsx'`（中文名）。
- 物理文件：`安全看板vben/apps/web-antd/public/templates/员工花名册导入模板.xlsx`（6851B，13 字段，内容正确）。

## 2. 根因（已实勘确认，非猜测）

1. **Dev 环境（Vite :5173）**：Vite 对 `public/` 下的**中文名**静态资源不会按二进制返回，而是回退到 SPA 的 `index.html`（实测 ASCII 名 `/favicon.ico`、`/logo.png`、`/templates/_probe_test.xlsx` 均正常返回二进制，唯中文名返回 `<!doctype html>`）。浏览器下载到的「.xlsx」实为 HTML，Excel 打开即报错。
2. **Prod 环境（Express :5666）**：`server/app.js` 仅挂载了 `/uploads` 静态目录，**未挂载 `/templates`**，中文名路径直接 404。

## 3. 修复方案与改动清单（共 3 处文件改动，0 行业务逻辑/后端逻辑变更）

### 3.1 模板文件重命名（内容不变）
- `安全看板vben/apps/web-antd/public/templates/员工花名册导入模板.xlsx` → `employee_roster_template.xlsx`（6851B，字节级未改，仅改名）。

### 3.2 前端 href 改为 ASCII（`views/hse/employee-import-v2/index.vue`）
```diff
  function handleDownloadTemplate() {
    const link = document.createElement('a');
-   link.href = '/templates/员工花名册导入模板.xlsx';
+   link.href = '/templates/employee_roster_template.xlsx';
    link.download = '员工花名册导入模板.xlsx';   // 下载文件名仍保留中文，体验不变
    ...
  }
```

### 3.3 Express 补 `/templates` 静态挂载（`server/app.js`，静态文件服务段）
```diff
  // 7. 静态文件服务
  app.use('/uploads', express.static(path.join(__dirname, uploadDir)));
+ app.use('/templates', express.static(path.join(__dirname, '..', '安全看板vben', 'apps', 'web-antd', 'public', 'templates')));
```

- `node --check server/app.js` 语法通过；路径解析 `..\安全看板vben\apps\web-antd\public\templates` 实测存在，files=['employee_roster_template.xlsx']。

## 4. 验证结果

### 4.1 验证基线（重要，避免误读「模板又变回 HTML」）

本机存在 **dev 代理 `127.0.0.1:7890`**，会**透明拦截 `127.0.0.1:5666` 的非 `/api` 请求**并将其路由到 Vite dev（`:5173`）返回 SPA 的 `index.html`。因此：

- ❌ **不能以「直连 `:5666/templates/...` 返回 HTML」判定修复回归** —— 那只是代理把非 `/api` 路径转给了 Vite 首页，与 Express 静态挂载无关。
- ✅ **用户真实下载链路 = 浏览器(加载自 Vite :5173) → `:5173/templates/...` → Vite 从 `public/` 直接返回文件**。这是唯一应以「真实 xlsx」为通过标准的验证路径。
- ✅ Express `/templates` 静态挂载仍正确（生产/直连场景），仅在本开发代理环境下被代理遮蔽，无法从 `:5666` 直连测到。
