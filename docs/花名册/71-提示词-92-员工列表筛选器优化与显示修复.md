## 一、背景

用户反馈员工列表页面存在4个问题：

| # | 问题 | 根因 |
|---|------|------|
| 1 | 筛选器部门/岗位选项"写死" | 当前从组织管理模块（`getDeptTree`/`getPositionList`）获取所有定义的部门/岗位，而非从花名册实际数据中提取有员工的部门/岗位 |
| 2 | 员工状态列多余 | 表格中 `org_status` 列占用空间，实际业务不需要 |
| 3 | 直接上级未按花名册映射 | 前端 `EmployeeItem` 类型缺失 `supervisor_id`/`supervisor_name` 字段定义；需排查后端 supervisor 匹配逻辑是否存在遗漏 |
| 4 | 出生日期列多余 | 表格中 `birth_date` 列占用空间，实际业务不需要 |

## 二、缺陷详情

### 问题1：筛选器部门/岗位选项"写死"

**现状**（`src/views/hse/employee/index.vue` 第 342-366 行）：

```ts
async function loadFilterOptions() {
  const [deptTree, positions] = await Promise.all([
    getDeptTree({ includeInactive: false }),   // 从组织管理模块获取部门树
    getPositionList(),                          // 从岗位管理模块获取所有岗位
  ]);
  // 收集所有部门名称
  const depts = new Set<string>();
  function collectDeptNames(nodes) { ... }
  collectDeptNames(deptTree);
  deptOptions.value = Array.from(depts).sort();
  positionOptions.value = positions.map((p) => p.name).sort();
}
```

**问题**：`getDeptTree()` 来自组织管理模块（`hse_org_unit` 表），`getPositionList()` 来自岗位管理模块（`position` 表）。这些是**组织架构定义**，不是**花名册实际数据**。如果组织架构中定义了100个部门但只有10个部门有员工，筛选器会显示100个选项（含大量空部门），用户体验差。

**期望**：筛选器选项应从花名册（员工实际数据）中提取——即只显示有员工的部门/岗位。

**修复方案**（推荐方案A）：

**方案A（推荐）**：新增后端 API，从员工实际数据中提取去重后的部门/岗位列表。

**后端新增**（`server/routes/hse-employee.js`）：

```js
// 新增路由：GET /hse/employee/employees/filter-options
// 返回花名册中实际存在的部门列表和岗位列表（去重+排序）
router.get('/employees/filter-options', async (req, res) => {
  try {
    const r = await pool.query(`
      SELECT 
        (SELECT json_agg(DISTINCT dept_name ORDER BY dept_name) 
         FROM (SELECT ev.org_name AS dept_name FROM v_employee_current ev WHERE ev.org_name IS NOT NULL) t) AS departments,
        (SELECT json_agg(DISTINCT position_name ORDER BY position_name) 
         FROM (SELECT ev.position_name FROM v_employee_current ev WHERE ev.position_name IS NOT NULL) t) AS positions
    `);
    res.json({ code: 0, data: {
      departments: r.rows[0].departments || [],
      positions: r.rows[0].positions || [],
    }});
  } catch (err) {
    next(err);
  }
});
```

**前端新增**（`src/api/hse/employee.ts`）：

```ts
export interface FilterOptions {
  departments: string[];
  positions: string[];
}

export async function getFilterOptions() {
  return requestClient.get<FilterOptions>(`${BASE}/employees/filter-options`);
}
```

**前端修改**（`src/views/hse/employee/index.vue`）：

```ts
// 替换 loadFilterOptions 函数
import { getFilterOptions } from '#/api/hse/employee';

async function loadFilterOptions() {
  try {
    const options = await getFilterOptions();
    deptOptions.value = options.departments;
    positionOptions.value = options.positions;
  } catch { /* 错误已由拦截器处理 */ }
}
```

**优点**：选项始终与花名册实际数据同步；无需维护两份数据源。

### 问题3：直接上级未按花名册映射

**根因分析**：

**根因A（前端类型缺失）**：`EmployeeItem` 接口（`src/api/hse/employee.ts` 第 22-46 行）缺少 `supervisor_id` 和 `supervisor_name` 字段：

```ts
// 当前定义（缺失项）
export interface EmployeeItem {
  id: number;
  employee_code?: string;
  // ... 其他字段
  dept_name?: string;
  created_at?: string;
  updated_at?: string;
  // ❌ 缺少 supervisor_id、supervisor_name
}
```

需补充：
```ts
  /** 直接上级员工ID */
  supervisor_id?: number;
  /** 直接上级姓名 */
  supervisor_name?: string;
```

**根因B（需排查）**：后端 SQL 查询逻辑已验证正确（`server/routes/hse-employee.js` 第 583-591 行）：

```sql
LEFT JOIN employee_assignment ea_sup 
  ON ev.employee_id = ea_sup.employee_id 
  AND ea_sup.is_primary = true 
  AND ea_sup.is_current = true 
  AND ea_sup.is_deleted = false
LEFT JOIN employee sup 
  ON ea_sup.supervisor_id = sup.id 
  AND sup.is_deleted = false
```

但需要排查：
1. `employee_assignment` 表中 `supervisor_id` 是否已正确写入（花名册导入时 `matchSupervisor` 函数按姓名精确匹配，可能存在匹配失败的情况）
2. 执行诊断 SQL：
   ```sql
   -- 检查 supervisor_id 写入率
   SELECT 
     COUNT(*) AS total_assignments,
     COUNT(supervisor_id) AS with_supervisor,
     COUNT(*) - COUNT(supervisor_id) AS missing_supervisor
   FROM employee_assignment 
   WHERE is_current = true AND is_primary = true AND is_deleted = false;
   
   -- 检查 supervisor_id 指向的员工是否存在
   SELECT ea.id, ea.employee_id, ea.supervisor_id, e.name AS emp_name
   FROM employee_assignment ea
   JOIN employee e ON e.id = ea.employee_id
   WHERE ea.is_current = true AND ea.is_primary = true AND ea.is_deleted = false
     AND ea.supervisor_id IS NOT NULL
     AND NOT EXISTS (SELECT 1 FROM employee sup WHERE sup.id = ea.supervisor_id AND sup.is_deleted = false);
   ```

**修复任务**：
1. 补充 `EmployeeItem` 类型中的 `supervisor_id`/`supervisor_name` 字段
2. 执行诊断 SQL，确认 `supervisor_id` 写入率
3. 如缺失率高，排查花名册导入时 `matchSupervisor` 匹配失败原因，考虑增加模糊匹配或别名匹配
