## 0. 重要纠正（实勘优先）

提示词假设的活动文件为 `src/views/insurance/over-age/index.vue`。经实勘，**该文件是遗留/未挂载文件**，并非活动文件：

- 路由白名单（`src/router/routes/index.ts` → `dynamicRouteFiles`）仅包含 `hse-07-personnel.ts`、`hse-10-insurance.ts` 等，**不包含** `hse-insurance.ts`。
- `views/insurance/over-age/index.vue` 由 `hse-insurance.ts`（未进白名单）挂载 → 生产 UI 不加载，属死代码。
- **活动 over-age 视图**为 `views/hse/employee/over-age/index.vue`（`hse-07-personnel.ts` 白名单内，`/personnel/over-age`）。
- 该活动视图读取 `GET /over-age/auto-list`（`server/routes/hse-employee.js:6347`，注释明确 **"基于 employee 表"**，由员工出生日期自动计算）→ 与保险 `over_age_personnel` 表是**两条截然不同的数据通路**。

> 结论：本审计对象"保险·超龄人员"在活动 UI 中实际**没有独立展示页**，其 `over_age_personnel` 表数据仅在导出（`exportOverAgePersonnel` → `/insurance/overage/export`）与遗留死代码视图中可达。

## 2. 数据库探查结果

### 2.1 表结构（节选关键列）

`over_age_personnel`（25 列）：`id`(bigint)、**`personnel_id`(bigint)**、`name`(varchar)、**`id_card`(varchar)**、`gender`、`birth_date`、`age`、`dept`、`position`、…、`is_deleted`、`is_demo`。

**无 `employee_id` 列。** 仅有 `personnel_id`（独立注册表主键）+ `id_card`（自然人身份证号）。

### 2.2 映射率统计（未删除数据）

| 指标 | 值 | 说明 |
|------|-----|------|
| 总记录数 | **1300** | `is_deleted=false` |
| 有 `id_card` | **1300 (100%)** | id_card 全部填充 |
| `id_card` 匹配 `employee.id_card` | **0 (0%)** | employee 表有 1245 人有 id_card，但 0 个 over_age id_card 出现在 employee 中 → 不同人群/格式 |
| `name` 匹配 `employee.name`（JOIN 行数） | **1345** | 因同名碰撞 > 总记录数 |
| └ 0 匹配 | 3 行 | 0.2% |
| └ 唯一匹配（1 对 1） | **1252 行** | 96.3% |
| └ 歧义匹配（≥2 员工同名） | **45 行** | 3.5% |

### 2.3 `personnel_id` 值域佐证

样本 `personnel_id`：347342、352153、402715、431487、360023… —— 与本项目 employee 真实 ID 段（~5000+，如韩秀青=5162）**量级悬殊**，证实其为**独立注册序列**，而非 `employee.id`。

> 对照：事故(accident)/培训(training)/预警(warning) 等模块的 `personnel_id` 在后端被 `JOIN employee e ON e.id = a.personnel_id` 直接当作 `employee.id` 使用；但 `over_age_personnel.personnel_id` 值域与之完全不同 → 语义不一致，属独立域。

## 3. 代码审查结果

### 3.1 前端

- **活动视图** `views/hse/employee/over-age/index.vue`：
  - 表单 `name`(L124)、`id_card`(L144) 为纯文本 `Input`；详情 `currentDetail.name`(L180)。
  - 数据源 `getOverAgeAutoList/getOverAgeAutoStats`（`#/api/hse/employee`，employee 派生）。
  - **无 `EmployeeName` / `EmployeeSelector`**。
- **遗留视图** `views/insurance/over-age/index.vue`：
  - `name` 纯文本 `Input`；API 用 `getOverAgeList`（`/insurance/overage`）。
  - **该函数全局无任何活动视图引用**（仅 `exportOverAgePersonnel` 用于导出），故即便统一也无法触达用户。
  - 无 `EmployeeName` / `EmployeeSelector`。
- `src/api/hse/insurance.ts`：overage 接口参数/返回均为 `Record<string, any>`，**无 `employeeId` / `personnelId` 类型声明**。

### 3.2 后端

- `server/routes/insurance.js` → `formatOverage`(L942)：仅返回 `personnel_id: row.personnel_id`，**无任何 employee 关联查询/派生字段**。
- `/overage` 全链路（GET/POST/PUT/DELETE）均以 `personnel_id` 为人员标识，无 `employee_id` 解析。
- `grep server/routes` 全量检索：over_age_personnel 相关路由**不存在** `personnel↔employee` 映射逻辑（对照 accident/training/warning 等模块的 `personnel_id = employee.id` JOIN，此处无对应实现）。
- 另有 `server/routes/over-age-personnel.js` 也操作同表，同样无 employee 映射。

## 4. 判定结论

### 保险超龄模块判定结论

**结论：保险超龄人员 = 独立域，不统一（Independent Domain, NOT unified）。**

**依据**：
1. **数据库**：`over_age_personnel` 无 `employee_id` 列；`personnel_id` 为独立注册序列（值域 347xxx，量级远大于 employee.id ~5000+）；`id_card` 与 employee 表 0% 匹配（不同人群/格式）；`name` 匹配 96.3% 唯一但 3.5% 同名歧义、0.2% 无匹配 —— 均非稳定外键。
2. **前端**：活动 over-age 视图读取 employee 派生 auto-list（另一条通路）；遗留保险 over-age 视图未挂载且无 EmployeeSelector 入口；API 无 employeeId 类型。
3. **后端**：`formatOverage` 仅返回 `personnel_id`，无 personnel↔employee 映射逻辑。

**修复方案（方案 B —— 独立域）**：
- 标注保险超龄为「**已评估-不适用**」，保持现状，不强行套用 EmployeeName。
- EmployeeName 统一覆盖最终为 **7/8 模块**，保险列标记"已评估-不适用"。

> 附带观察（**范围外**）：活动 `超龄人员管理` 页（`/personnel/over-age`）数据源自 employee 表（auto-list），**本质上已是员工派生**。若未来希望该页姓名也带 EmployeeName 联动（点击跳转员工档案等），可另立独立任务对其套用 —— 但那属于"员工模块"增强，**不属于"保险模块统一"范畴**，不在本审计修复范围内。
