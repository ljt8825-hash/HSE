## 三、逐表决策明细

### 1. `personnel_assessment_summary` → 流程驱动（跳过手工补录）
- **实测行数**：0（active）
- **后端引用**：`overview.js:198`（`SELECT COUNT ... grade='A'`）、`training-assessment.js:431-557`（列表查询 + 按 `employee_id/period_year/period_type` upsert 自动写入）。
- **FK 依赖**：无（自身无外键；也未被任何其他表引用为父表）。
- **是否聚合表**：**是** —— 含 `total_training_hours`、`avg_assessment_score`、`training_score`、`assessment_score_value`、`violation_score`、`hazard_score`、`risk_score`、`total_score`、`*_count` 系列、`data_sources(jsonb)`、`calculation_details(jsonb)`。
- **结论**：**流程驱动**。该表由培训-考核业务流在运行时聚合生成，手工插入会与 `training-assessment.js` 的 upsert 逻辑冲突，**不应种子补录**。

### 2. `hse_responsibility_assessment` → 跳过
- **实测行数**：0（active）
- **后端引用**：`objectives.js:415-492`（列表/按 grade 统计/详情/INSERT/UPDATE/软删 完整 CRUD）；`import.js:546` 作为导入目标表。
- **FK 依赖**：子表引用 `employee(employee_id)`、`hse_org_unit(org_unit_id)`，均 `ON DELETE SET NULL`。
- **是否聚合表**：否，是业务实体表（责任制考核记录）。
- **结论**：**跳过**。属"目标/责任制考核"独立业务模块的真实业务数据，需由独立录入任务产生，非数据补录轨道的种子补录范畴。

### 3. `responsibilities` → 跳过
- **实测行数**：0（active）
- **后端引用**：`server/routes` 中**无任何 `FROM/INSERT/UPDATE responsibilities` 引用**（提示词-87 引用的 `objectives.js:49` 实为 JS 对象键名，非该表）。
- **FK 依赖**：无。
- **是否聚合表**：否，结构为 `year/quarter/department/person/score/level/status` 的责任制台账。
- **结论**：**跳过**。遗留/未启用表，无后端模块驱动，既非前端读取也非业务流写入，非种子补录范畴。

### 4. `position_safety_profile` → 流程驱动（跳过手工补录）
- **实测行数**：0（active）
- **后端引用**：`hse-employee.js:3017-3396`（岗位安全画像模块完整 CRUD：列表/统计/详情/UPSERT/编辑/软删）。
- **FK 依赖**：子表引用 `position(position_id)`，`ON DELETE CASCADE`。
- **是否聚合表**：否，是岗位风险画像实体；但字段 `risk_level/risk_score/risk_factors/ai_risk_analysis/ai_suggestion/ai_analysis_*` 表明数据须由"岗位风险模型 + AI 风险分析"生成。
- **结论**：**流程驱动**。模块已上线但数据依赖尚未跑通的"岗位风险模型/AI 分析"，当前 0 行系上游未生成；手工补录会写入失真数据，**跳过**。

### 5. `assessment_rule_detail` → 已具备 / 跳过
- **实测行数**：**3**（⚠️ 提示词-87 §三标 0 行，实勘为 3，清单滞后）
- **后端引用**：`hse-dynamic-capability.js:296/344-369`（按 `rule_id` 查明细 + 明细 CRUD）。
- **FK 依赖**：子表引用 `assessment_rule(rule_id)`，`ON DELETE CASCADE`。
- **是否聚合表**：否，是规则明细实体。
- **结论**：**已具备 / 跳过**。`hse-dynamic-capability.js:8/178` 明确注释：`assessment_rule` "仅作为未来规则中心预留，不参与当前业务计算"，`config/hseRules` 才是唯一业务计算来源。其 3 行影子数据自洽且无业务副作用，无需补录。
