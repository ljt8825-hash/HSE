## 4. 修改项清单（5 项）

### 4.1 修改项 R1：枚举统一（P1）

**文件**：`安全看板vben/apps/web-antd/src/views/emergency/plans/index.vue`、`src/views/emergency/drills/index.vue`、`src/views/emergency/materials/index.vue`、`src/views/emergency/teams/index.vue`、`src/views/emergency/events/index.vue`、`src/api/hse/emergency.ts`

**问题**：诊断报告 P1-5 指出 emergency 模块枚举存在三重失配：

| 字段 | API 类型(emergency.ts) | 种子/真实 DB | 前端页面 |
|------|------------------------|--------------|----------|
| plans.status | active/inactive/drilling/archived | active/published/pending/review | 草稿/审批中/已发布/已废止 |
| plans.type | fire/traffic/chemical/... | (空表) | 综合预案/专项预案/现场处置方案 |
| drills.result | excellent/good/pass/fail | (中文实测) | — |
| drills.status | (DrillRecord 无此字段) | 已完成(中文) | — |

**修复**：

#### 4.1.1 统一以 DB 真实值为准

以 DB 实际存储的 code 值作为唯一词汇来源，前端枚举、API 类型、搜索/筛选全部对齐：

**预案状态（plans.status）**：
- DB 真实值：`active`、`published`、`pending`、`review`
- 前端展示映射：`{ active: '生效中', published: '已发布', pending: '待审核', review: '复审中' }`
- 搜索下拉选项与表单选项统一使用上述映射

**预案类型（plans.type）**：
- 由于 DB 中 `emergency_plans` 表当前为 0 行，无 ground truth
- 以 `hse-09-emergency.ts` 路由定义和常见应急管理实践为准
- 统一值：`comprehensive`（综合预案）、`special`（专项预案）、`site`（现场处置方案）
- 前端展示映射：`{ comprehensive: '综合预案', special: '专项预案', site: '现场处置方案' }`

**演练结果（drills.result）**：
- DB 当前 48 条，result 字段为中文值
- 保持中文值不变，前端展示和搜索直接使用中文

**演练状态（drills.status）**：
- DB 当前 48 条，status 全为 `已完成`
- 统一值：`计划中`、`进行中`、`已完成`、`已取消`
- 前端展示和搜索使用中文

#### 4.1.2 具体修改

**emergency.ts**：
- 修改 `PlanStatus` 类型：`'active' | 'published' | 'pending' | 'review'`
- 修改 `PlanType` 类型：`'comprehensive' | 'special' | 'site'`
- 修改 `DrillResult` 类型：`'优秀' | '良好' | '合格' | '不合格'`
- 修改 `DrillStatus` 类型：`'计划中' | '进行中' | '已完成' | '已取消'`

**各子页面**：
- 搜索表单的 `<SelectOption>` 枚举值与上述统一值对齐
- 表格列的 `getXxxColor/getXxxText` 映射函数与统一值对齐
- 新增/编辑表单的 Select 选项与统一值对齐

### 4.2 修改项 R2：plans/drills 规范统一（P2）

**文件**：`安全看板vben/apps/web-antd/src/views/emergency/plans/index.vue`、`src/views/emergency/drills/index.vue`

**问题**：plans 和 drills 子页手搓 `ref`/`reactive` + 手写 `fetchData`/`handleTableChange`/`handleSearch`/`handleReset`，未使用 composable 托管。与 materials/teams/events 子页使用 `useDataTable`/`useSearchForm`/`useCrudModal` 的规范不一致。

**修复**：

将 plans/index.vue 和 drills/index.vue 的数据管理改造为 composable 托管：

#### 4.2.1 plans/index.vue

```typescript
// 改造前（手搓模式）
const loading = ref(false);
const dataList = ref<EmergencyPlan[]>([]);
const total = ref(0);
const pagination = reactive({ current: 1, pageSize: 10 });
const searchForm = reactive({ keyword: '', status: undefined, type: undefined });

const fetchData = async () => { /* 手写 fetch */ };
const handleSearch = () => { pagination.current = 1; fetchData(); };
const handleReset = () => { /* 手写 reset */ };
const handleTableChange = (pag: any) => { /* 手写 change */ };

// 改造后（composable 托管）
const { loading, dataList, total, pagination, fetchData, handleTableChange, handleReset: tableHandleReset } = useDataTable<EmergencyPlan>({
  fetchFn: async ({ page, pageSize }) => {
    const params = { page, pageSize, keyword: searchForm.keyword, status: searchForm.status, type: searchForm.type };
    const res = await getEmergencyPlanList(params);
    return { list: res.list || [], total: res.total || 0 };
  },
  defaultPageSize: 10,
});

const { form: searchForm, reset: resetSearch } = useSearchForm<{ keyword: string; status: string | undefined; type: string | undefined }>({
  defaults: { keyword: '', status: undefined, type: undefined },
  onSearch: () => tableHandleReset(),
});

// CRUD 弹窗托管
const { visible: modalVisible, loading: modalLoading, editingRecord, openCreate, openEdit, handleSave } = useCrudModal<EmergencyPlan>({
  createFn: (data) => createEmergencyPlan(data),
  updateFn: (id, data) => updateEmergencyPlan(id, data),
  onSuccess: () => fetchData(),
});
```

### 4.3 修改项 R3：导出补全（P2）

**修复**：

#### 4.3.1 后端补 teams/events 导出端点

在 `emergency.js` 中新增两个导出端点：

**GET /teams/export**（注册在 `GET /teams/:id` 之前）：
```javascript
router.get('/teams/export', requireRole('admin', 'safety_manager'), async (req, res) => {
  try {
    const result = await pool.query('SELECT * FROM emergency_teams WHERE is_deleted = false ORDER BY created_at DESC');
    const headers = ['队伍名称','队伍类型','负责人','联系电话','成员人数','备注','状态'];
    const rows = result.rows.map(r => [r.name, r.team_type || '', r.leader_name || '', r.contact_phone || '', 
      Array.isArray(r.member_ids) ? r.member_ids.length : 0, r.remark || '', r.status || '']);
    const csv = [headers, ...rows].map(row => row.map(c => `"${c||''}"`).join(',')).join('\n');
    res.setHeader('Content-Type', 'text/csv; charset=utf-8');
    res.setHeader('Content-Disposition', 'attachment; filename=emergency_teams.csv');
    res.send('\uFEFF' + csv);
  } catch(e) { res.json(error(-1, e.message)); }
});
```

**GET /events/export**（注册在 `GET /events/:id` 之前）：
```javascript
router.get('/events/export', requireRole('admin', 'safety_manager'), async (req, res) => {
  try {
    const result = await pool.query('SELECT * FROM emergency_events WHERE is_deleted = false ORDER BY created_at DESC');
    const headers = ['事件名称','事件类型','事件级别','发生地点','发生时间','结束时间','影响范围','处置状态','备注'];
    const rows = result.rows.map(r => [r.name, r.event_type || '', r.event_level || '', r.location || '', 
      r.occurred_at, r.ended_at, r.impact_scope || '', r.status || '', r.remark || '']);
    const csv = [headers, ...rows].map(row => row.map(c => `"${c||''}"`).join(',')).join('\n');
    res.setHeader('Content-Type', 'text/csv; charset=utf-8');
    res.setHeader('Content-Disposition', 'attachment; filename=emergency_events.csv');
    res.send('\uFEFF' + csv);
  } catch(e) { res.json(error(-1, e.message)); }
});
```

#### 4.3.2 前端 handleExport 接入真实端点

**plans/index.vue**：
```typescript
const handleExport = async () => {
  try {
    const res = await request.get('/emergency/plans/export', { responseType: 'blob' });
    const url = window.URL.createObjectURL(new Blob([res as any]));
    const link = document.createElement('a');
```

### 4.5 修改项 R5：materials 责任人接入 EmployeeSelector（P2）

**文件**：`安全看板vben/apps/web-antd/src/views/emergency/materials/index.vue`

**问题**：materials 的 `responsible_person` 为纯文本 `<Input>`，未使用 `EmployeeSelector`/`EmployeeName` 组件。与 plans（`responsiblePersonId` + EmployeeName）、teams（`leaderId` + EmployeeName + EmployeeSelector）接入花名册的做法不一致。

**修复**：

1. 在新增/编辑表单中，将 `responsible_person` 的纯文本 `<Input>` 替换为 `<EmployeeSelector>` 组件：
```vue
<FormItem label="责任人">
  <EmployeeSelector
    v-model:value="materialForm.responsiblePersonId"
    placeholder="请选择责任人"
  />
</FormItem>
```

2. 在表格列中，将 `responsible_person` 的纯文本展示替换为 `<EmployeeName>` 组件：
```vue
<template #bodyCell="{ column, record }">
  <template v-if="column.key === 'responsiblePerson'">
    <EmployeeName v-if="record.responsiblePersonId" :employee-id="record.responsiblePersonId" />
    <span v-else>{{ record.responsiblePerson || '-' }}</span>
  </template>
</template>
```

3. 在 `materialForm` 中新增 `responsiblePersonId` 字段（`undefined` 初始化），在 `columns` 中新增 `responsiblePerson` 列。

4. 确认后端 `POST /materials` 和 `PUT /materials/:id` 支持 `responsible_person_id` 参数（需检查 `emergency.js` 中 materials 的 INSERT/UPDATE 是否包含此列；若真实表无此列则不修改后端，仅前端展示用 EmployeeName 纯展示组件）。

> **注意**：如果 `emergency_materials` 表没有 `responsible_person_id` 列，则 R5 的 EmployeeSelector 改为仅 UI 优化——保留 `responsible_person` 文本输入，但在表格展示列使用 `<EmployeeName>` 组件（通过与 `employee` 表按姓名模糊匹配 employeeId）。不要修改数据库表结构。
