# 提示词-75：应急模块统计卡片字段对齐

> 编号：提示词-75 ｜ 日期：2026-07-31 ｜ 性质：既有缺陷修复（P2），前端 + 可能后端
> 前置：提示词-74（5 项异常修复完成，残留统计卡片字段不一致）
> 改动范围：前端 5 视图的统计卡片取值 + 可能后端 stats 接口字段调整（不修改 DB/FK/menu/组件库）

## 0. 背景

提示词-74 修复了应急模块 5 个视图的列表取数问题，但统计卡片仍显示为空。根因是**前后端 stats 接口字段名不一致**：

| 视图 | 前端模板读取 | 后端 stats 返回 | 匹配状态 |
|------|-------------|----------------|:--:|
| 应急事件 | `stats.year_total` / `stats.handling` | `total, byType, byStatus, byLevel` | ❌ 不匹配 |
| 演练 | `stats.yearTotal` / `stats.completionRate` | `total, memberCount, byType` | ❌ 不匹配 |
| 队伍 | `stats.member_count` / `stats.full_time` | `total, memberCount, byType` | ❌ 不匹配 |
| 物资 | `stats.total` / `stats.expiring` / `stats.expired` | `total, expiring, expired` | ✅ 部分匹配 |
| 预案 | `stats.total` / `stats.published` / `stats.pendingReview` | `total, published, pendingReview` | ✅ 部分匹配 |

提示词-74 已将 `if(r.code===0) stats.value=r.data.stats` 改为 `stats.value=r`（去除恒假守卫），使字段名一致的物资/预案卡片可渲染，但字段名不一致的应急事件/演练/队伍卡片仍为空。

## 1. 任务清单

### 任务 A：实勘后端 stats 接口（只读）

对 5 个视图的 stats 端点逐一 curl 确认返回结构：

| 视图 | 端点 | 需确认 |
|------|------|--------|
| 应急事件 | `GET /api/emergency/events/stats` | 完整返回字段名 |
| 演练 | `GET /api/emergency/drills/stats` | 完整返回字段名 |
| 队伍 | `GET /api/emergency/teams/stats` | 完整返回字段名 |
| 物资 | `GET /api/emergency/materials/stats` | 确认 `total/expiring/expired` |
| 预案 | `GET /api/emergency/plans/stats` | 确认 `total/published/pendingReview` |

### 任务 B：实勘前端模板统计卡片取值（只读）

对 5 个视图的 `<template>` 中统计卡片部分，逐文件确认实际读取的字段名：

| 视图 | 文件 |
|------|------|
| 应急事件 | `src/views/emergency/events/index.vue` |
| 演练 | `src/views/emergency/drills/index.vue` |
| 队伍 | `src/views/emergency/teams/index.vue` |
| 物资 | `src/views/emergency/materials/index.vue` |
| 预案 | `src/views/emergency/plans/index.vue` |

### 任务 C：决策对齐策略

根据 A+B 实勘结果，对每个视图的二选一决策：

**策略 1（优先）：前端适配后端** — 修改前端模板字段名，对齐后端返回结构
- 优点：不碰后端，风险最低
- 适用：后端返回字段语义清晰，前端可映射

**策略 2：后端扩展字段** — 在后端 stats 接口中补充前端需要的字段别名
- 优点：前端不改模板
- 适用：后端返回字段不足以表达前端卡片语义，或前端改动涉及复杂计算

**决策原则**：优先策略 1，仅当后端字段语义无法映射到前端卡片时采用策略 2。

### 任务 D：执行修改

根据 C 的决策逐文件修改，每文件改后浏览器验证统计卡片正常渲染。

### 任务 E：全量回归

修改完成后，浏览器验证 5 个视图的统计卡片 + 列表均正常。

## 6. 风险提示

- **字段语义映射**：后端 `byType`/`byStatus` 等聚合字段可能与前端卡片语义不完全对应（如 `stats.handling` 可能对应 `byStatus['处理中']`），需仔细判断映射可行性
- **统计卡片为 0 不等于异常**：若 DB 无数据，统计卡片显示 0 是正确行为，非 bug
- **后端 stats 可能返回嵌套结构**：若 `byType` 等为 JSON 对象，前端需按对象属性访问
