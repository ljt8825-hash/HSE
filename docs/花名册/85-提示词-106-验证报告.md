## 一、Task 1：is_public_welfare 硬编码修复（P1）

### 1.1 根因（比提示词更深一层）
提示词指出 `INSERT INTO employee` 将 `is_public_welfare` 硬编码为 `false`。但实测数据链路后发现**真正阻断数据写入的是断层**，而非仅那一行：

导入采用两段式：`Excel → parseExcelRow → employee_import_pending（待审核）→ 入库 SELECT → employee`。

- `employee_import_pending` 表**原本没有 `is_public_welfare` 列**；
- 唯一流向 `employee` 的 `auto_matched` 落库 INSERT（原行 725-741）**未写入该字段**；
- 入库查询 `SELECT ... FROM employee_import_pending`（原行 983）**未 SELECT 该字段**。

因此即便只按提示词 4 步改，入库时的 `p.is_public_welfare` 永远为 `undefined`，`|| false` 仍得 `false` —— **修复会形同虚设**。必须打通 pending 链路才能让 Excel 的「是否公益岗」真正落库。

### 1.2 改动清单（7 处，文件 `server/routes/hse-employee-import-v2.js`）

| # | 位置 | 改动 |
|---|------|------|
| 1 | `ROSTER_HEADER_MAP`（行 34-48） | 增加 `'是否公益岗': 'is_public_welfare'` |
| 2 | `HEADER_ALIASES`（行 50-69） | 增加 `'公益岗'`、`'公益岗位'` → `'是否公益岗'` |
| 3 | `parseExcelRow`（行 119 之后） | 增加布尔解析：`result.is_public_welfare = ['是','true','1','yes','y'].includes(v)` |
| 4 | DB DDL | `ALTER TABLE employee_import_pending ADD COLUMN is_public_welfare BOOLEAN NOT NULL DEFAULT FALSE;` |
| 5 | `auto_matched` 落库 INSERT（列清单/占位符/值） | 补 `is_public_welfare` 列与 `$27` 占位符，值取 `row.is_public_welfare === true` |
| 6 | 入库 SELECT `FROM employee_import_pending` | 增加 `is_public_welfare` 到选中列 |
| 7 | `INSERT INTO employee` 值数组 | `false` → `p.is_public_welfare \|\| false` |

> 说明：步骤 1-3、7 对应提示词原方案；步骤 4-6 为补全 pending 链路所必须的补充（提示词未提及，但缺则修复无效）。改动严格限定在导入模块，未触碰菜单/路由/其他业务模块。

### 1.3 验证（端到端真实导入）
构造含「是否公益岗」列的测试 Excel，走通 `auto_matched` 路径（部门=宁津项目公司精确匹配，岗位=管理员模糊匹配），重启后端后通过 API 上传→入库，再查库：

| 测试公益岗是 | 是 | `true` | ✅ |
| 测试公益岗否 | 否 | `false` | ✅ |

**结论：PASS。** 测试数据已软删清理，未污染业务表。

## 二、Task 2：超龄人员模块检查

### 2.1 数据源澄清（关键发现）
`apps/web-antd/src/views/hse/employee/over-age/index.vue` **并未调用 `over-age-personnel.js`**，而是调用 `getOverAgeAutoList / getOverAgeAutoStats`（来自 `#/api/hse/employee`），其真实后端为 **`server/routes/hse-employee.js` 的 `/over-age/auto-list`、`/auto-stats`、`/auto/:id`**——基于 `employee` 表按 `birth_date` 派生 `person_category='超龄人员'`（规则见 `config/hseRules/employee-age-rule.json`）。

`over-age-personnel.js` 是一套**独立的手动 CRUD 路由**（针对 `over_age_personnel` 表），并非本列表视图的数据源。

### 2.2 字段映射 / camelKeys 核对
- 列表接口（`/over-age/auto-list`）经 `buildListResponse(res, rows, ...)` 返回，该函数默认 `camelCase=false`（`server/utils/commonResponse.js`），**直接输出 snake_case**；
- 前端 `over-age/index.vue` 的 `dataIndex` 正是 snake_case：`dept_name`、`position_name`、`id_card`、`birth_date`、`over_age_years`、`employee_code`、`person_type`、`is_public_welfare`、`phone`…与后端返回列完全一致；
- 详情接口（`/over-age/auto/:id`）经 `buildDetailResponse` 同样默认 snake_case，前端详情页读取 `currentDetail.is_public_welfare`、`employee_code`、`dept_name` 等匹配。

**不存在员工档案 101/102 类 camelKeys 键名不匹配问题。**

### 2.3 与花名册的数据交互
- 超龄列表/详情的数据源即 `employee` 表；
- 花名册导入现可正确写入 `employee.is_public_welfare`；
- 超龄详情页「是否公益岗」字段（`over-age/index.vue` 行 197）读取 `currentDetail.is_public_welfare`，来源为 `hse-employee.js` 详情查询 `e.is_public_welfare`（行 6546）——**与 Task 1 修复形成完整闭环**。

### 2.4 结论
超龄人员模块检查通过，**无字段映射问题，无需修改代码**。`over-age-personnel.js` 不在本视图链路中，按约束不改动。
