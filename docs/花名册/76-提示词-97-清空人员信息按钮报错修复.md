## 一、问题描述

用户进入「人员管理 → 花名册导入」页面，点击右上角「更多操作 → 清空人员信息」按钮后：

| 现象 | 说明 |
|------|------|
| 报错 | 控制台出现 3 个 401 Unauthorized 错误 + "Access token or refresh token is invalid or expired" 警告 |
| 员工列表未变动 | 清空操作未生效，员工数据仍在列表中 |
| 页面跳转登录 | 401 拦截器触发 `doReAuthenticate()` → `authStore.logout()` → 重定向到 `/auth/login` |

**截图证据**（已上传）：
- 3 个 401 错误分别对应：员工列表 API (`/api/hse/employee/employees?page=1&pageSize=20`)、统计 API (`/api/hse/employee/employees/stats`)、筛选选项 API (`/api/hse/employee/employees/filter-options`)
- 每个 401 下方伴随 `Access token or refresh token is invalid or expired` 警告
- 页面最终跳转至登录页 (`/auth/login?redirect=%2Femployee_1`)

## 二、根因分析

### 2.1 调用链路

```
用户点击「清空人员信息」
  → openClearAllConfirm() → Modal.confirm 弹窗
  → 用户确认 → handleClearAll()
  → clearAllEmployees() → POST /api/hse/employee/clear-all
  → 后端 requireRole('admin') 中间件
  → 物理 DELETE employee_assignment → employee → employee_import_pending → employee_import_batch
  → 成功 → loadList() 刷新列表
  → 失败 → catch 块 message.error()
```

### 2.2 401 拦截器吞异常机制

`request.ts` 中 `authenticateResponseInterceptor` 处理 401 的逻辑：

```javascript
// L88-97: token 过期 → doReAuthenticate() → setAccessToken(null) → authStore.logout()
// → 页面跳转登录页，handleClearAll 的 try/catch 不会执行
```

**关键问题**：当 token 过期时，`clearAllEmployees()` 返回 401，`authenticateResponseInterceptor` 直接触发重定向到登录页，`handleClearAll` 中的 `catch` 块不会执行，用户看不到具体的错误提示，且员工列表未被清空。

### 2.3 可能的二级根因

| 可能性 | 说明 | 概率 |
|--------|------|:--:|
| **Token 过期** | 用户会话超时，所有 API 返回 401，包括 clear-all | 🔴 高 |
| **FK 约束拦截** | 业务表（如 training、violation、assessment）存在外键引用 employee，DELETE 被 NO ACTION 约束回滚 | 🟡 中 |
| **requireRole('admin') 拦截** | 当前用户角色非 admin，返回 403 而非 401 | 🟢 低 |

### 任务2：修复 — 前端错误处理增强

**文件**：`安全看板vben/apps/web-antd/src/views/hse/employee-import-v2/index.vue`

**问题**：当 clear-all API 返回 401 时，`authenticateResponseInterceptor` 拦截并重定向到登录页，用户看不到有意义的错误提示。

**修改**：在 `handleClearAll` 中增加更明确的错误处理，并在 401 场景下给出友好提示：

```typescript
async function handleClearAll() {
  try {
    const res: any = await clearAllEmployees();
    message.success(
      `清空完成：员工 ${res.employeeCount || 0} 人、任职 ${res.assignmentCount || 0} 条、批次 ${res.batchCount || 0} 个`
    );
    loadList();
    if (detailDrawerVisible.value) {
      detailDrawerVisible.value = false;
    }
  } catch (e: any) {
    // 增强错误信息
    const errMsg = e?.message || e?.toString() || '未知错误';
    if (errMsg.includes('401') || errMsg.includes('token') || errMsg.includes('认证')) {
      message.error('会话已过期，请重新登录后再试');
    } else if (errMsg.includes('403') || errMsg.includes('权限')) {
      message.error('权限不足，仅管理员可执行清空操作');
    } else if (errMsg.includes('foreign key') || errMsg.includes('外键') || errMsg.includes('constraint')) {
      message.error('清空失败：存在业务数据引用员工记录，请先清理相关业务数据');
    } else {
      message.error('清空失败：' + errMsg);
    }
  }
}
```

### 任务3：修复 — 后端增强错误信息

**文件**：`server/routes/hse-employee-import-v2.js` → `POST /clear-all`

**问题**：当前 FK 约束错误通过 `formatDbError(err)` 返回，前端可能无法识别具体原因。

**修改**：在 catch 块中增加 FK 约束错误的友好提示：

```javascript
} catch (err) {
  await client.query('ROLLBACK');
  const msg = String(err.message || err);
  if (msg.includes('foreign key') || msg.includes('violates foreign key constraint')) {
    // 提取被引用的表名
    const detailMatch = msg.match(/on table "(\w+)"/i);
    const detail = detailMatch ? `（被表 ${detailMatch[1]} 引用）` : '';
    throw new Error(`清空失败：员工数据被其他业务表引用${detail}，请先清理相关业务数据`);
  }
  throw err;
```
