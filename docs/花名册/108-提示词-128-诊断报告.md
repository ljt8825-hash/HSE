## 4. 分维度明细

### 3.1 前端展示与交互
- ✅ 任务列表/详情/明细三态表格、状态 Tag、进度条、轮询刷新闭环正常。
- ⚠️ **P2③ 模板下载错误被吞**：`downloadTemplate`（`api/hse/batch-import.ts:275`）使用 `responseType:'blob'`，后端返回 JSON 错误时仍进入 `.then` 并 `message.success('模板下载成功')`，用户实际得到一个内容为 `{"code":-1,...}` 的损坏 `.xlsx` —— **错误响应与成功响应无法区分**。
- ⚠️ **P2④ `safety_record` 必败**：前端 `importTypeOptions`（index.vue:72）与类型 `ImportType`（batch-import.ts:12）均开放"安全记录"，但后端 `_processItem` 对该类型返回 `NOT_SUPPORTED` 且未实现；预检查会通过、确认后**全部明细失败**。UI 提供了必败选项。
- ⚠️ **P2⑤ 业务范畴字段缺失**：`BatchImportDrawer.handleCreateTask`（line 121-127）仅收集 `files/importType/importVersion:'v1.0'/businessScope:{}`，**不收集 `categoryId/enterpriseId/departmentId`**。`document` 导入经 `documentService.uploadFile` 需要 `categoryId`，缺省为 `null` → 资料落入未分类或失败。抽屉无对应 UI。
- 🟡 **P3⑦ version 硬编码**：创建任务（`BatchImportDrawer:126`）与模板下载（`BatchImportDrawer:209`）均写死 `v1.0`，后端 `version` 参数未校验格式，多版本模板能力形同虚设。
- 🟡 **P3⑧ 死代码**：`uploadProps.customRequest:()=>{}`（BatchImportDrawer:101）与模板内联 `:custom-request="() => {}"`（line 328）为无意义死代码（与 123 模块同模式）。
- 🟡 **P3⑩ 轮询卸载边界**：`index.vue`/`BatchImportDrawer` 的 `progressTimer` 依赖 `closeDetailDrawer`/`emit('cancel')` 清理；若抽屉异常关闭路径未走到，定时器可能泄漏（低危）。

### 3.2 后端接口与逻辑
- ✅ 11 个端点职责清晰，角色校验（`requireRole` 展开写法）正确。
- ✅ 任务创建使用 **DB 事务 + 失败回滚 + 临时目录清理**（`batchImportService.createTask` line 275-358），稳健。
- ✅ 预检查/确认/重试 状态机闭环完整，重试次数上限（`MAX_RETRY_COUNT=3`）保护到位。
- ⚠️ **P1② 路径遍历**：`getTemplate`（`batchImportService.js:1257-1260`）将 `importType`/`version` 直接拼入 `path.join(templateDir, 'hse-import-template-${importType}-${version}.xlsx')`，**自身未对 `importType` 做 `IMPORT_TYPE` 白名单校验、`version` 未做格式校验，且未用 `path.basename` 归一**。`res.sendFile` 可借 `../` 序列读取模板目录外 `.xlsx` 文件。虽受 `.xlsx` 后缀约束，仍属明确安全隐患。
- ⚠️ **P2⑥ `getTemplate` 缺 IMPORT_TYPE 校验**：与 P1②同源；即便不计遍历，非法 `importType` 应返回"不支持的模板类型"而非盲目拼路径。
- ✅ `retryItem` 的 `SELECT bi.*, bt.* as task_info`（line 1126）**经 PostgreSQL EXPLAIN 实测语法合法**（退出码 0），`row.task_id/import_type` 等均可用，**重试功能本身正常**——此前怀疑的"SQL 非法"不成立，已从诊断移除。

### 3.3 数据流与持久化
- ✅ 主表 `hse_batch_import_tasks` + 明细 `hse_batch_import_items` 字段映射（`camelTask`/`camelItem`）与前端 `BatchTask`/`BatchItem` 类型一一对应，无字段漂移。
- ✅ 文件落盘采用 `fs.renameSync` + `ensureDir`，存储目录 `uploads/batch-import/<taskNo>` 与任务绑定。
- ✅ 预检查哈希去重（`computeFileHash` + `existingHashes`）逻辑正确，跨任务查重。
- ✅ 操作日志（`_writeOperationLog` → `sys_operation_log`）与完成通知（`createNotification`）均有 try/catch 兜底，单点失败不影响主流程。

### 3.4 边界与异常
- ✅ 所有 `:id` 参数均做 `parseInt` + `isNaN` 校验，返回"无效的 ID"。
- ✅ 文件大小前后端一致（前端 `beforeUpload` 100MB ↔ 后端 `maxSize:100MB`），**优于 import-v2 模块的 50/10 不一致**。
- ✅ 文件类型白名单（`ALLOWED_EXTENSIONS`）+ 内容签名校验（`validateFileSignature`，仅 document）防伪造。
- 🟡 **P3⑨ 外键未校验**：`createTask` 的 `enterpriseId/departmentId` 未验证被引用行是否存在，传无效 ID 静默落库。
- 🟡 **P3⑪ 无事务/断点续传**：`processTask` 逐条 `UPDATE` 无整体事务，进度每 5 条刷新一次；若进程在导入中途被杀，任务可能停留中间态且无断点续传（架构级 P3，非本次修复范围）。

### 3.5 回归与兼容性
- ✅ 探针显示本模块 11 端点中 6 个核心端点全部 `code=0`，**无跨模块回退**。
- ✅ 路由 `hse-batch-import.ts` 与 `app.js` 注册一致，菜单"批量导入"正常挂载（独立于已合并的组织管理模块）。
- ✅ 前端 `vue-tsc` 本模块 0 错误，构建产物确认包含 `batch-import` + `BatchImportDrawer` chunk（242 个 JS chunks 总计）。
