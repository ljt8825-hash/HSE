## 1. 背景

当前系统存在两套独立组织模型：
- `hse_org_unit`（20 节点）：公司 → 职能部门 → 作业中心 → 乡镇（作业中心架构）
- `department`（77 节点）：公司 → 部门 → 乡镇 → 班组（组织管理架构）

两套模型通过 `org_unit_id` 外键关联，但班组级部门（如"长官镇一班"）无 `org_unit_id` 映射，导致点击后员工列表为空。

**目标**：将两套模型合并为一棵统一组织树，以 `hse_org_unit` 为骨架、`department` 班组为叶子节点，一次性解决同名冗余、空列表、编制人数三大问题。

## 4. 实现方案

### 4.1 核心逻辑（三步）

**第 1 步：查询 hse_org_unit 全量节点**

```sql
SELECT id, parent_id, org_name, org_type, org_code, org_path, level,
       sort_order, headcount, status, description, manager_id
FROM hse_org_unit
WHERE is_deleted = false
ORDER BY level, sort_order, id
```

**第 2 步：查询 department 班组级节点（挂载到乡镇下）**

```sql
SELECT id, dept_code, name, short_name, parent_id, level, path, township,
       manager_id, safety_manager_id, headcount, sort_order, status, description,
       org_unit_id
FROM department
WHERE is_deleted = false AND status = 'active'
  AND name ~ '(\u4e00|\u4e8c|\u4e09|\u56db|\u4e94|\u516d|\u4e03|\u516b|\u4e5d|\u5341)\u73ed$|^\u8f66\u961f$|^\u7247\u533a$|.*\u7247\u533a$'
ORDER BY sort_order ASC, id ASC
```

> 正则说明：匹配"X班"结尾、"车队"、"片区"结尾的班组名。

**第 3 步：构建合并树**

```
1. 以 hse_org_unit 节点构建主干树（parent_id 关联）
2. 对每个 hse_org_unit 节点：
   a. 计算员工数：SELECT COUNT(*) FROM employee_assignment
      WHERE org_unit_id = node.id AND is_current = true AND is_primary = true AND is_deleted = false
   b. 查找对应的 department 行（通过 org_name 前缀匹配 department.name）
      - 若找到 → 使用 department.id 作为节点 id（兼容前端 /departments/:id/employees）
      - 若未找到 → 使用 "ou_" + hse_org_unit.id 作为合成 id
3. 对每个乡镇节点（org_type = 'town_center'）：
   a. 从 department 班组列表中筛选属于该乡镇的子节点
      - 匹配规则：department.name 以乡镇名开头（如 "长官镇" 匹配 "长官镇一班"、"长官镇片区"）
   b. 将这些班组节点挂载为乡镇节点的 children
   c. 计算班组员工数：从父乡镇员工数中按比例分配（精确班组人数需阶段 2 数据增强）
4. 汇总上层节点员工数（公司 = 直属职能部门之和；作业中心 = 下属乡镇 + 车队之和）
```

### 4.2 节点响应格式

每个节点返回以下字段（snake_case，与现有前端 `departments.vue` 兼容）：

```javascript
{
  id: number | string,        // department.id（优先）或 "ou_XXX"（合成）
  name: string,               // 显示名称（如 "长官镇"）
  dept_code: string | null,   // 编码（hse_org_unit.org_code 或 department.dept_code）
  org_type: string,           // 新增！company / department / center / town_center / team
  level: number,              // 层级（1=公司 2=职能部门/作业中心 3=乡镇 4=班组）
  status: string,             // active / inactive
  headcount: number | null,   // 编制人数
  employee_count: number,     // 实际人数（新增！从 employee_assignment 统计）
  actual_headcount: number,   // 同 employee_count（兼容旧字段名）
  manager_id: number | null,  // 负责人 ID
  supervisor_name: string | null, // 新增！负责人姓名（从花名册"直接上级"字段）
  children: [],               // 子节点
  sort_order: number,         // 排序
  description: string | null, // 描述
  path: string | null,        // 层级路径
  org_unit_id: number | null, // hse_org_unit 原始 ID（用于 /departments/:id/employees 映射）
}
```

### 4.3 员工数计算策略

| 节点类型 | 计算方式 | 说明 |
|----------|----------|------|
| 公司 | 直属职能部门人数之和 | 不含下属乡镇 |
| 职能部门 | `employee_assignment WHERE org_unit_id = ?` | 精确计数 |
| 作业中心 | 下属乡镇+车队人数之和 | 汇总 |
| 乡镇 | 下属所有班组人数之和 | 汇总 |
| 班组 | 父乡镇人数 / 班组数（近似） | 阶段 2 精确化 |

> **注意**：班组级精确人数需要花名册导入时存储"所属部门"字段到 `employee_assignment` 中。当前导入流程仅存储 `org_unit_id`（乡镇级），不存储班组级。这是阶段 2 的数据增强项。阶段 1 中班组人数使用父乡镇人数均分，并标记 `employee_count_approximate: true`。

### 4.4 负责人姓名（supervisor_name）

新增 `supervisor_name` 字段，从 `employee_assignment` 中查询 `supervisor_id` 对应的员工姓名。

对于 hse_org_unit 节点：
```sql
SELECT sup.name AS supervisor_name
FROM employee_assignment ea
JOIN employee sup ON sup.id = ea.supervisor_id AND sup.is_deleted = false
WHERE ea.org_unit_id = $1 AND ea.is_current = true AND ea.is_primary = true
LIMIT 1
```

取第一个匹配的 supervisor_name（通常一个组织只有一个负责人）。

## 5. 兼容性约束

### 5.1 前端 `departments.vue` 依赖

当前前端对树节点的使用：

| 使用点 | 字段 | 要求 |
|--------|------|------|
| `treeFieldNames` | `{children, title: 'name', key: 'id'}` | `name` 必须存在，`id` 必须唯一 |
| `#title` 插槽 | `name, dept_code, status, level` | 所有字段必须存在 |
| `handleSelect` | `currentDept.value = info.node` | 节点对象完整 |
| `loadDeptEmployees` | `currentDept.value.id` | `id` 必须能传给 `/departments/:id/employees` |
| `levelText(level)` | `level` 1-6 | 层级映射正确 |
| `levelColor(level)` | `level` | 颜色映射正确 |
| 详情面板 | `headcount, employee_count, actual_headcount, manager_id` | 字段存在 |

**关键约束**：`id` 字段用于 `GET /departments/:id/employees`。对于 hse_org_unit 节点，如果 `id` 是 department 表的 ID，则当前员工查询逻辑仍能工作（通过 org_unit_id 映射）。如果 `id` 是合成 ID（"ou_XXX"），阶段 2 需要改造 `/departments/:id/employees` 以支持直接按 org_unit_id 查询。

**阶段 1 策略**：优先使用 department.id。对于没有对应 department 行的 hse_org_unit 节点（如车队、市政绿化），使用 `"ou_" + hse_org_unit.id` 作为合成 ID。

### 5.2 其他调用方

`GET /departments/tree` 还被以下页面调用，必须保持兼容：

| 调用方 | 用途 | 兼容性 |
|--------|------|--------|
