## 1. 关键实勘修正（执行铁律）

提示词假设 `ev.org_path`（视图列）可直接透传，但**实勘发现三层偏差**：

| # | 提示词假设 | 实况 | 处置 |
|---|---|---|---|
| 1 | `v_employee_current` 含 `org_path` | **无该列**（视图仅 10 列：employee_id/employee_code/name/assignment_status/is_current/hire_date/org_name/org_type/position_name/is_driver） | 不可用 `ev.org_path` |
| 2 | 改 `NULL AS org_path` → `ev.org_path` | 会报 `字段 ev.org_path 不存在` | 弃用 |
| 3 | （首次回退尝试）`hse_operation_unit opu` 有 `org_path` | **无该列**（opu 仅 unit_name/unit_code/unit_type 等） | 弃用 `opu.org_path` |
| 4 | 最终定位 | `org_path` 在 **`hse_org_unit`** 表（详情端点 L958 `LEFT JOIN hse_org_unit ou` 已用） | 补 JOIN `hse_org_unit ou ON ou.id = ea.org_unit_id`，SELECT `ou.org_path` |

**根因**：列表端点 L588 原本 JOIN 的是 `hse_operation_unit opu ON ea.operation_unit_id`（操作单元，无 org_path），而组织路径在 `hse_org_unit`（经 `ea.org_unit_id` 关联）。`opu` 仍被 deptName 过滤（L544 `opu.unit_name`）引用，不可删除，故**新增** `ou` JOIN。

> 这正是"执行铁律"价值：提示词的 `ev.org_path` 与首次回退的 `opu.org_path` 均会运行时报错，实勘 `information_schema` 后才定位到正确表。

## 2. 后端改动（`server/routes/hse-employee.js`）

**GET /employees 数据查询**（L573-595）：

```sql
-- 改动 1：SELECT（L578）
- ea.org_unit_id, ev.org_name AS dept_name, NULL AS org_path,
+ ea.org_unit_id, ev.org_name AS dept_name, ou.org_path AS org_path,

-- 改动 2：新增 JOIN（L589 后插入，仅数据查询，不在 COUNT 查询，避免行膨胀）
+ LEFT JOIN hse_org_unit ou ON ou.id = ea.org_unit_id AND ou.is_deleted = false
```

- `employee_code`/`birth_date`/`is_driver`/`assignment_status AS org_status` 均已存在于原 SELECT，无需改动。
- `buildListResponse` 默认 `camelCase=false` → 响应键为 snake_case（`org_path`/`employee_code`/`org_status` 等），与前端 `dataIndex` 一致。
- COUNT 查询不加 `ou` JOIN（沿用提示词-57 supervisor JOIN 的"仅数据查询"范式，避免多任职记录导致行膨胀）。

## 3. 前端改动

### 3.1 `src/api/hse/employee.ts` — 类型扩展

`EmployeeItem` 增字段（其余 employee_code/birth_date/org_path/org_status/team_name 已存在）：


### 3.2 `src/views/hse/employee/index.vue` — 列重排

columns 由 11 列替换为 14 列（员工编号/姓名/性别/出生日期/身份证号/联系电话/所属部门/班组/职位/入职日期/是否驾驶员/员工状态/直接上级/操作），删除"序号""年龄"两列。

### 3.3 bodyCell 槽位

- **删除**：`column.key === 'index'`、`column.key === 'age'`（slot 解构去掉 `index`）
- **新增 5 槽位**：
  - `employee_code` → `{{ record.employee_code || '-' }}`
  - `birth_date` → `{{ formatDate(record.birth_date) }}`
  - `team_name` → `{{ extractTeamName(record.org_path) }}`（前端从 org_path 提取末级）
  - `is_driver` → `<Tag :color="record.is_driver ? 'blue' : 'default'">是/否</Tag>`
  - `org_status` → `<Tag :color="getStatusColor(...)">{{ getStatusText(...) }}</Tag>`

### 3.4 辅助函数（formatDate 旁）

```ts
function getStatusColor(status?: string) { /* 在职green/离职red/待岗orange/退休default/返聘blue */ }
function getStatusText(status?: string) { return status || '未知'; }
function extractTeamName(orgPath?: string): string {
  if (!orgPath) return '-';
  const parts = String(orgPath).split('/').filter(Boolean);
  return parts[parts.length - 1] || '-';
}
```

> 班组采用 **bodyCell 内即时计算** `extractTeamName(record.org_path)`，无需在 fetchFn 中 mutate dataList，降低 TS/响应结构风险。
