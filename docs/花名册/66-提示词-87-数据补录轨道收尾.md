### 任务2：死表处置决策

**选项**：
- A. 保留现状（种子数据自洽，无害，未来若启用可直接使用）

**建议**：选 A+B 组合——保留数据但标记废弃，在 `project_memory.md` 中记录。

## 五、跨模块数据一致性校验

### 任务3：执行全线一致性检查

**目标**：确保补录数据在跨模块引用中无断裂。

**检查项**：
1. 所有种子数据中引用的 `employee_id` 在 `employee` 表中存在且 active（FK孤儿检查）
2. 所有种子数据中引用的 `org_unit_id` 在 `hse_org_unit` 表中存在
3. 所有种子数据中引用的 `position_id` 在 `position` 表中存在
4. 种子数据之间无冲突（如主键重复、唯一约束冲突）
5. 种子数据与既有真实数据无冲突

**方法**：
```sql
-- 示例：全局FK孤儿检查
SELECT 'emergency_events' AS tbl, personnel_id FROM emergency_events WHERE is_deleted=false AND personnel_id NOT IN (SELECT id FROM employee WHERE is_deleted=false)
UNION ALL
SELECT 'emergency_plans', responsible_person_id FROM emergency_plans WHERE is_deleted=false AND responsible_person_id NOT IN (SELECT id FROM employee WHERE is_deleted=false)
UNION ALL
-- ... 覆盖所有补录表
```
