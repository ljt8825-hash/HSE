# 提示词-114: 组织树同名冗余与编制人数显示优化

## 背景

在"人员管理 → 组织管理"页面的目视化检查中，发现两个影响用户体验的问题：

1. **组织树节点同名冗余**：左侧树形目录中，上下级节点存在同名问题（如"宁城街道"下属第一个子节点依然是"宁城街道"；"津城街道"、"柴胡店镇"等也全部是类似情况）。这给用户带来极大困扰，不符合常规组织架构层级逻辑。

2. **编制人数显示违和**：部门详情卡片中，"编制人数"显示为 0，而"实际人数"显示为 49 人。在编制基数未录入时直接展示 0 与 49 的巨大反差容易让人误解。

## 问题一：组织树同名节点冗余

### 根因分析

`department` 表（77 行）支持 6 级层级（实际数据库 CHECK 约束为 1-5，但前端显示 6 级）。同一地理位置（如"宁城街道"）在不同层级中存在多条记录：

```
宁城街道 (level=3, 乡镇作业中心, parent_id=XX)
  └── 宁城街道 (level=5, 乡镇, parent_id=上述ID)
        ├── 宁城街道一班 (level=6, 班组)
        └── 宁城街道二班 (level=6, 班组)
```

树组件仅展示 `name` + `dept_code`，level=3 和 level=5 的节点都叫"宁城街道"，用户无法区分。

### 修复方案

**方案：在树节点标题中追加层级标签**，让同名不同层的节点可区分。

树标题模板当前代码（`departments.vue:62-67`）：

```html
<template #title="{ name, dept_code, status }">
  <span :class="{ 'node-inactive': status === 'inactive' }">
    {{ name }}
    <span class="node-code">({{ dept_code }})</span>
  </span>
</template>
```

修改为：在名称后追加层级标签（如 `宁城街道 [乡镇] (DEPT_XXX)`），使同级同名节点可区分。

具体要求：
- 使用 `levelText()` 函数（已存在于 `departments.vue:365-375`）获取层级文本
- 格式：`{{ name }} [{{ levelText(level) }}] ({{ dept_code }})`
- 层级标签使用 `a-tag` 组件，颜色使用 `levelColor()` 函数（已存在）
- 仅当同父节点下存在同名节点时才显示层级标签（可选优化，也可始终显示）
- 保持 `node-inactive` 样式对停用节点的生效

### 影响范围
- 仅修改 `departments.vue` 第 62-67 行的 `#title` 插槽模板
- 不改动 `treeFieldNames`、数据加载逻辑、后端 API

## 问题二：编制人数为 0 时的显示优化

### 根因分析

`department` 表的 `headcount` 字段默认值为 0，在业务落地初期未录入编制基数时，界面上直接展示"编制人数: 0"与"实际人数: 49 人"的强烈反差。

当前代码（`departments.vue:137-139`）：

```html
<a-descriptions-item label="编制人数">
  {{ currentDept.headcount ?? 0 }}
</a-descriptions-item>
```

### 修复方案

当 `headcount` 为 0、null 或 undefined 时，显示 `-`（暂无数据），而非 `0`。

修改为：

```html
<a-descriptions-item label="编制人数">
  {{ currentDept.headcount ? currentDept.headcount : '-' }}
</a-descriptions-item>
```

> 注意：`headcount` 为 0 时视为"未设置"，因为实际场景中不存在编制人数为 0 的部门。

### 影响范围
- 仅修改 `departments.vue` 第 138 行
