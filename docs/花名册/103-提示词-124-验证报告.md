## 2. 实现要点

### 2.1 三步合并逻辑（与提示词 4.1–4.3 一致）
1. **骨架**：`SELECT ... FROM hse_org_unit WHERE is_deleted=false`，按 `parent_id` 串联主干（company → 职能/作业中心 → 乡镇）。
2. **叶子**：`SELECT ... FROM department` 用正则命中班组（`X班$` / `^车队$` / `片区$`），全部 51 个班组节点 `level=6`、`org_unit_id` 均为 NULL。
3. **挂载与计数**：
   - 班组按**乡镇名前缀**（乡镇 `org_name` 剥离"作业中心"后缀）挂到对应 `hse_org_unit` 乡镇节点（如 `长官镇一班` → `长官镇`）。
   - 员工数：`org_unit_id` 精确计数（职能/乡镇）；班组 = 父乡镇人数 / 班组数（**近似**，标记 `employee_count_approximate: true`）；作业中心 = 下属乡镇之和；公司 = 直属职能部门之和（不含乡镇）。
   - 负责人姓名 `supervisor_name`：`employee_assignment.supervisor_id` 关联 `employee.name` 批量查询。

### 2.2 前端兼容性决策（红线：不改前端）
前端 `departments.vue` 用 6 级 `levelText/levelColor`（1公司/2部门中心/3乡镇作业中心/4部门/5乡镇/6班组）。提示词 4.2 的 `level` 注释为 4 级简化（班组=4），但前端 4→"部门" 会显示错误。为守住"前端不可改 + 层级映射正确"双重约束，**班组节点 `level` 使用 `department.level`(=6)**，前端正确渲染为"班组"。其余节点沿用 `hse_org_unit.level`（公司1/职能·中心2/乡镇3）。

### 2.3 节点 id 策略
- `hse_org_unit` 节点：合成 id `"ou_<id>"`，并保留 `org_unit_id` 真实值供阶段2 映射。
- `department` 班组节点：使用真实 `department.id`（兼容现有 `/departments/:id/employees` 按 name 前缀匹配）。
