## 八、附：本里程碑轨道关键工程经验（可复用）

1. **camelKeys 错位第一反应**：任何列表/详情整列空、统计卡为 0 → 先查该端点是否多套了 `camelKeys(...)`，尤其 `stats` 类把整对象包进去导致内层数组键翻转。
2. **跨 ID 空间关联**：`department.id`(4056+) 与 `hse_org_unit.id`(1–20) 不可直接比；须经 `name` 映射，采用「精确优先 + 前缀兜底」规避粒度差异（班组级 vs 作业中心级）。
3. **值集分裂根因**：前端下拉值与 DB 枚举错位时，先 `SELECT DISTINCT` 确认库内真实值——本例库内本无分裂值，迁移为 no-op，避免了无谓写操作。
4. **构建死锁兜底**：rolldown-vite v8.1.4 emit 阶段偶发卡死，规范命令 `pnpm run build:antd`（minify:esbuild）在提示词-108 实测 exit0；若再卡死，用 `--minify false` 不压缩兜底必过。
5. **API 实时探查**：用 node 内置 `crypto` 手搓 HS256 JWT（免 jsonwebtoken 依赖）探后端，后端无热重载须重启再探。
