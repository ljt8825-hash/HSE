## 1. 背景

提示词-136 诊断报告已产出，识别出应急管理模块的 23 个问题（2 P0 + 5 P1 + 7 P2 + 9 P3）。本提示词聚焦 **P0（2 项）+ P1（5 项）** 中高优先级的修复，共 5 项。P1-3（演练 DTO）随 P0-1 一并修复（同根因），P1-5（枚举）与 P2 项留待后续提示词。

### 4.4 修改项 R4：预案时效修复（P1）

**文件**：`server/routes/emergency.js`

**问题**：`calcExpiryStatus(effectiveDate, validityPeriod)` 依赖 `validity_period`（表无此列，恒 undefined）→ 函数 L99 `if (!effectiveDate || !validityPeriod...) return 'permanent'` → 所有预案 `expiryStatus` 恒 `'permanent'`。真实 `expiry_date` 列被忽略。

**修复**：

1. 修改 `calcExpiryStatus` 函数签名和逻辑，改为基于 `expiry_date` 计算：

```javascript
// 修改前
function calcExpiryStatus(effectiveDate, validityPeriod) {
  if (!effectiveDate || !validityPeriod) return 'permanent';
  const now = new Date();
  const expiryDate = new Date(effectiveDate);
  expiryDate.setMonth(expiryDate.getMonth() + validityPeriod);
  // ...
}

// 修改后
function calcExpiryStatus(expiryDate) {
  if (!expiryDate) return 'permanent';
  const now = new Date();
  const expiry = new Date(expiryDate);
  const diffDays = Math.ceil((expiry - now) / (1000 * 60 * 60 * 24));
  if (diffDays < 0) return 'expired';
  if (diffDays <= 30) return 'expiring';
  return 'valid';
}
```

2. 修改 `formatPlanRow` 中的调用：

```javascript
// 修改前
expiryStatus: calcExpiryStatus(row.effective_date, row.validity_period),
// 修改后
expiryStatus: calcExpiryStatus(row.expiry_date),
```

3. 确认 `formatPlanRow` 返回 `expiryDate` 字段（`expiryDate: row.expiry_date`），供前端时效列展示。

### 4.5 修改项 R5：5 子页保存逻辑修复（P1）

**文件**：`安全看板vben/apps/web-antd/src/views/emergency/plans/index.vue`、`drills/index.vue`、`materials/index.vue`、`teams/index.vue`、`events/index.vue`

**问题**：5 子页 `handleSave` 均用 `if (r.code === 0)` 判定成功。但 `request` 客户端（`api/request.ts`，`responseReturn: 'data'`）已解包到 `data` 字段，返回的是业务对象（无 `code`）。故 `r.code` 恒 `undefined` → 恒走 `message.error('操作失败')`，弹窗不关闭、列表不刷新。数据实际已成功落库。

**修复**：

将 5 个子页面的 `handleSave` 函数从：

```typescript
// 修改前
const handleSave = async () => {
  try {
    const values = await formRef.value?.validateFields();
    if (!values) return;
    let r;
    if (editingRecord.value) {
      r = await updateXxx(editingRecord.value.id, { ...values });
    } else {
      r = await createXxx({ ...values });
    }
    if (r.code === 0) {  // ← 恒 false
      message.success(editingRecord.value ? '编辑成功' : '新增成功');
      modalVisible.value = false;
      fetchData();
    } else {
      message.error(r.message || '操作失败');
    }
  } catch (error) {
    message.error('操作失败');
  }
};
```

改为：

```typescript
// 修改后
const handleSave = async () => {
  try {
    const values = await formRef.value?.validateFields();
    if (!values) return;
    if (editingRecord.value) {
      await updateXxx(editingRecord.value.id, { ...values });
    } else {
      await createXxx({ ...values });
    }
    message.success(editingRecord.value ? '编辑成功' : '新增成功');
    modalVisible.value = false;
    fetchData();
  } catch (error: any) {
    message.error(error?.message || '操作失败');
  }
};
```

> `responseReturn: 'data'` 模式下，请求成功直接返回业务对象，请求失败走 catch 分支。删除操作同理（`handleDelete` 若有类似判定也一并修正）。
