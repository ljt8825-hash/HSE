# 禁止类：模块聚焦与上下文锁定原则

> 级别：**强制性约束（Hard Constraint）**
> 适用范围：所有提示词生成、诊断报告、修复执行、验证报告
> 生效日期：2026-08-02
> 关联模块：全量业务模块

---

## 1. 核心禁令

### 禁令一：未授权不得切换模块

**在用户未明确指令切换模块前，所有提示词、诊断报告、修复执行、验证报告必须严格限定在当前模块范围内。**

- **当前模块**由用户最后一次明确指定的模块决定
- 如用户说"修改模块A"，则后续所有交付物必须围绕模块A展开
- **严禁**以"收尾""下一步""接下来"等名义擅自进入下一模块诊断或生成提示词

### 禁令二：建议与执行分离

- 可以就当前模块的优化方向、后续规划向用户**提出建议**
- 但**必须等待用户明确确认**后，方可生成下一模块的提示词
- 建议应以问句形式呈现，如："保险管理模块人员保险子板块改造完成后，是否需要继续处理车辆保险/其他保险子板块？"或"是否进入下一模块诊断？"

### 禁令三：禁止预生成下一模块内容

- 禁止预生成未授权模块的诊断报告
- 禁止预生成未授权模块的提示词文档
- 禁止在验证报告中夹带下一模块的检查项

## 3. 违规示例（严禁出现）

| 违规类型 | 示例 | 正确做法 |
|----------|------|----------|
| 擅自收尾 | "本次修复完成后，进入系统管理模块诊断" | "本次修复已完成，是否继续处理保险管理其他子板块或进入下一模块？" |
| 夹带诊断 | 在保险验证报告中加入系统管理模块检查项 | 验证报告仅限保险管理模块范围 |
| 预生成提示词 | 直接生成提示词-142包含系统管理诊断 | 仅生成当前模块改造提示词，下一模块等待用户确认 |
| 暗示推进 | "Part B：启动下一模块——系统管理" | 当前模块全部完成后，询问用户下一步意向 |

## 4. 合规流程

```
用户指令修改模块A
    ↓
生成模块A的诊断/提示词/修复
    ↓
执行并生成验证报告（仅限模块A）
    ↓
向用户汇报完成项 + 询问下一步意向
    ↓
用户明确指令（是/否/去模块B/继续模块A子项）
    ↓
按用户指令执行
```
