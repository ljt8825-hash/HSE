## 0. 执行摘要

应急管理模块（5 子模块 / 43 后端端点）存在 **2 个 P0、5 个 P1、7 个 P2、9 个 P3** 级问题。核心结论：

1. **演练模块在 PostgreSQL 模式下整体损坏（P0）**：后端 `emergency_drills` 真实表结构与代码引用列完全不匹配，导致演练的创建、更新、导出、关键字搜索全部抛 SQL 错误。代码是按一份与真实迁移表不符的旧 spec/seed 编写的，内存模式可用、PG 模式崩溃。
2. **后端零角色鉴权（P0 安全）**：43 个端点无任何 `requireRole`，仅全局 `authMiddleware` 校验登录；`viewer` 角色可全量访问所有应急端点，前端 `authority:['admin']` 形同虚设（同培训模块 133-D1）。
3. **5 个子页保存逻辑恒报"操作失败"（P1）**：`request` 客户端 `responseReturn:'data'` 已解包到 data，但保存处理用 `r.code === 0` 判定 → 恒 false → 永远提示失败、不关弹窗、不刷新（数据实际已落库）。
4. **预案导出损坏 + 预案时效状态失效（P1×2）**：导出 SELECT 引用不存在的 `version`/`validity_period` 列；时效计算依赖不存在的 `validity_period` → `expiryStatus` 恒 `'permanent'`，真实 `expiry_date` 被忽略。
5. 通过项：`node --check` 语法 OK、vue-tsc 本模块 0 TS 错误、`vite build` 成功含应急 chunk、路由 `/:id` 遮蔽检查全部正确、备份文件为当前文件的子集（无逻辑丢失）。
