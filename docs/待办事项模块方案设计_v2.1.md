# 待办事项模块 · 方案设计（v2.1 终定版）

> 目标：在 HSE 看板新增独立一级菜单「待办事项」，把各业务模块里"还没做完 / 该跟进"的事项（如目标责任书未签订人员）按「每天 / 每周 / 每月 / 每年」聚合展示，每行可一键导出 Excel 明细、跳转到来源模块处理。
> 状态：**已终定** —— 全部关键决策已确认，待进入 P1 实现。

---

## 0. 已锁定的全部决策（来自商议）

| 项 | 决策 |
|----|------|
| 模块名 | **待办事项** |
| 菜单位置 | **独立一级菜单**（日常高频，入口最显眼） |
| 菜单权限 | **对全员开放**（不限制角色，与现有多数业务菜单一致） |
| 注册表形态 | **DB 表 `hse_todo_sources`**（可运行时启停，无需改代码重启） |
| 首期接入源 | **目标职责 + 保险管理 + 培训管理 + 隐患治理**（4 个持续型）+ **年度责任书到期 + 年度考核未提交**（2 个年度型） |
| 导出格式 | **Excel (.xlsx)**（复用 server 已含的 `xlsx` 依赖） |
| 每年视图内容 | 首期放 **年度责任书到期 / 年度考核未提交**；其余（年度培训/演练/整改）P2 补 |
| 顶栏角标 | **不做**总待办数红点（首期不做，P2 也不做，已决定） |

---

## 1. 与已有「通知中心」的关系（不重复）

现有「通知中心」（`/hse/notifications`，路由当前 `hideInMenu:true`、仅 admin）是**事件驱动消息流**（临期/紧急/系统/任务），有已读未读与 CSV 导出。

「待办事项」是**数据缺口主动聚合**：实时扫描各模块当前状态，把"还缺什么/谁没做"摊开，缺口关闭即消失。两者互补，首期**并行独立**；P3 可选做双向跳转。

---

## 2. 周期语义（锁定）

- **每天 / 每周 / 每月**：持续型缺口在这三个视图里都出现（如责任书未签订人员，直到签完才消失）。本质是同一条待办在"日/周/月"三个滚动视图里都可见。
- **每年**：年度性、跨年才闭环的事项——年度责任书到期、年度考核未提交等。**仅出现在「每年」Tab**，由 `cadence=[yearly]` 控制。
- 一个数据源在 `cadence` 里打一个或多个标签（持续型打 `daily,weekly,monthly`；年度型只打 `yearly`）。

---

## 3. 整体架构：数据源注册 + 聚合器

```
各业务模块 ──暴露──> 缺口查询 gap query → {count, items[]}
                              │
                     hse_todo_sources 注册表（DB 表，可运行时启停）
                              │
                 待办聚合器 GET /hse/todos?cadence=daily|weekly|monthly|yearly
                              │
              前端 待办事项页（每天/每周/每月/每年 Tab）
                              │
              导出明细 GET /hse/todos/export?sourceCode=xxx  → .xlsx
```

### 3.1 注册表 `hse_todo_sources`（DB 表，迁移 seed）

| 字段 | 说明 |
|------|------|
| `source_code` | 唯一标识，如 `target_responsibility_unsigned` |
| `module` / `sub_board` | 来源模块 / 子板块 |
| `title` | 事项名，如"目标责任书未签订人员" |
| `cadence` | 周期标签数组，如 `[daily,weekly,monthly]` 或 `[yearly]` |
| `detail_api` | 取明细的接口路径（聚合器按 code 调） |
| `export_columns` | 导出列（字段→中文表头）JSON |
| `link` | 前往处理路由 |
| `enabled` | 是否启用（运行时可关，无需重新部署） |

> 新增一个模块的待办 = 往 `hse_todo_sources` 插一条 + 后端加一个返回 `{count,items}` 的 gap 查询。**聚合器与前端零改动**。

### 3.2 聚合器 `GET /hse/todos?cadence=`

- 读 `enabled` 且 `cadence` 含该周期的源；逐个调 `detail_api` 取 `count`；
- 返回 `[{sourceCode, module, subBoard, title, count, link, updatedAt}]`；
- **5 分钟 TTL 缓存**，避免同时打多个模块库；
- 明细仅在"导出"或"展开"时按需拉取。

## 4. 首期 6 个数据源（P1 一次到位）

### 4.1 持续型（每天/每周/每月都出现）

| source_code | 模块·子板块 | cadence | 缺口查询 | 导出列（示意） |
|------|------|------|------|------|
| `target_responsibility_unsigned` | 目标职责·目标责任书管理 | daily/weekly/monthly | **已有** `GET /objectives/employees/responsibility-status?signStatus=unsigned` | 工号/姓名/部门/岗位/分管 |
| `insurance_uncovered` | 保险管理 | daily/weekly/monthly | 实现时核实现有接口，补 `{count,items}` 缺口查询 | 工号/姓名/险种/状态 |
| `training_pending` | 培训管理 | daily/weekly/monthly | 实现时核实（应培未培/逾期未复训） | 工号/姓名/培训班次/到期 |
| `hazard_overdue` | 隐患治理 | daily/weekly/monthly | 实现时核实（超期未整改隐患） | 隐患编号/位置/等级/责任部门 |

> 目标职责已具备完整缺口查询与计数（`/responsibility-stats` 返回 `{total,signed,unsigned,signRate}`），作为**范式**优先打通；其余 3 个在实现时先核实是否已有可用列表/统计接口，没有再补最小 gap 查询。

### 4.2 年度型（仅「每年」Tab）

| source_code | 模块·子板块 | cadence | 缺口查询（实现方式，已核验底表存在） | 导出列（示意） |
|------|------|------|------|------|
| `contract_annual_expiry` | 目标职责·目标责任书 | **yearly** | `objectives.js` 加 gap 查询：`hse_target_contracts` 中 `status='signed' AND review_cycle_months=12 AND (expiry_date BETWEEN 年初 AND 年末 OR expiry_date < 今天)` → 今年到期/已逾期清单 | 责任书标题/类型/签订人/部门/到期日/剩余天数 |
| `assessment_annual_unsubmitted` | 考核管理·年度考核 | **yearly** | `hse-assessment.js` 加 gap 查询：当年 `hse_assessment_target` 中 `status IN ('pending','overdue')` 或 `submitted_at IS NULL` → 年度考核未提交清单 | 考核名称/周期/被考核部门/考核对象/状态 |

> 两年数据源可查性已核验：`hse_target_contracts` 含 `status/effective_date/expiry_date/review_cycle_months`，`objectives.js` 已暴露该表；`hse-assessment.js` 已有 `getYearRange(year)` 与按年统计框架，`hse_assessment_target` 含 `submitted_at` 与 `pending/overdue` 状态。两者均在**现有 route 文件内加查询**即可，零新依赖。

## 5. 前端页面（独立一级菜单，全员可见）

- 菜单：新增一级「待办事项」（icon 建议 `lucide:check-square`，`authority` 不限制角色 → 全员可见）。
- 页面：顶部汇总条（当前周期「共 N 项待处理 / 涉及 M 模块」）+ 四个 Tab（每天/每周/每月/每年）+ 待办表格。
- 表格列：**来源模块 ｜ 子板块 ｜ 事项 ｜ 待处理数量 ｜ 更新时间 ｜ 操作（导出明细 / 前往处理）**。
- 待处理数量颜色分档：≥20 红、5–19 橙、<5 绿。
- 每行「导出明细」→ `GET /hse/todos/export?sourceCode=...` 下载 `.xlsx`；「前往处理」→ `router.push(link)`。
- 页面布局示意见 v1 文档附图（结构不变，仅"导出明细"产出 xlsx）。

---

## 6. 导出机制（Excel）

- 新增 `GET /hse/todos/export?sourceCode=xxx`：按 source 的 `export_columns` 跑明细查询，用 server 已含的 `xlsx` 生成 `.xlsx` 返回（带 `Content-Disposition: attachment`）。
- 复用 `notifications.js` 的导出骨架（列映射、中文表头、转义），把 CSV 输出换成 xlsx 工作簿。
- 文件名如 `待办明细_目标责任书未签订人员_20260813.xlsx`。

---

## 7. 分阶段路线

- **P1（本次实现）**：`hse_todo_sources` 表+seed → 聚合器 `GET /hse/todos` → 前端「待办事项」页（4 Tab+汇总+表格+Excel 导出）→ 接入 **6 个源**（4 持续 + 2 年度）。
- **P2（增强）**：来源页"前往处理"双向可用；空状态/已清零的源自动隐藏；管理员可视化维护 `hse_todo_sources`（启停开关）。**不含顶栏角标（已决定不做）。**
- **P3（可选）**：与通知中心 `task` 类型互跳；每日生成待办快照供"每年"回看；补充其余年度型源（年度培训/演练/整改未完成）。

---

## 8. 实现范围确认（P1 将构建的内容）

1. **DB**：`server/sql/` 新增迁移 `hse_todo_sources` 建表 + 6 条 seed（含 `cadence` 标签与 `export_columns`）。
2. **后端**：`server/routes/todos.js` 聚合器 `GET /hse/todos?cadence=` + `GET /hse/todos/export?sourceCode=`；在 `objectives.js` 加 `contract_annual_expiry` gap 查询，在 `hse-assessment.js` 加 `assessment_annual_unsubmitted` gap 查询；持续型 3 个源核实/补 gap 查询。
3. **前端**：一级菜单「待办事项」+ `待办事项` 页（4 Tab+汇总条+表格+数量分色+导出/前往）+ API 封装。
4. **导出**：Excel 产出，文件名带日期与事项名。
