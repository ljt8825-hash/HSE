## Codex 复核结论

阶段 1 的端口传递、dotenv 定位、Vite 环境覆盖、前端类型检查及构建验证基本成立，但报告结论不能直接判定“通过”，原因如下：

1. 官方默认命令 `npm --prefix server run test -- --runInBand` 的报告退出码仍为 `1`。测试断言全绿不等于命令成功，CI 会因此失败。
2. `jest.config.js` 自称单元测试白名单，但包含 `**/routes/*.test.js` 等目录通配符；未来新增未 mock 数据库的路由测试会被默认收集，隔离边界不是结构性安全。
3. 集成测试门控目前是独立前置进程，需要确认所有正式集成测试入口都无法绕过门控，并且门控条件在 Jest 进程中仍然成立。
4. `vite.config.ts` 仍包含带完整 pnpm 虚拟目录版本号的 `vue-i18n` alias，跨机器或依赖版本变化时可能失效。此项不是 P0，但本轮应评估并在不破坏构建的前提下收敛。

完成以上门槛后，按既定开发顺序进入身份认证与公开接口边界的第一批 P0 收口。

## 第一段：阶段 1 最终测试门槛收尾

### 任务 1：定位并关闭 Jest 未释放句柄

1. 运行默认单元测试并记录真实退出码：

```powershell
npm --prefix server run test -- --runInBand
```

2. 如退出非零或出现未退出警告，使用以下方式定位：

```powershell
npm --prefix server run test -- --runInBand --detectOpenHandles
```

3. 优先检查：
   - `server/services/aiService.test.js` 中重试、超时模拟产生的定时器；
   - `queryLogger`、缓存、调度器或日志模块创建的 interval/timeout；
   - HTTP mock 中未结束的请求或 Promise。
4. 修复测试 teardown 或资源生命周期。若根因是生产代码未释放资源，可做最小生命周期修复，但不得改变业务语义。
5. 禁止使用 `--forceExit` 作为解决方案。
6. 最终默认命令必须：
   - 所有套件与用例通过；
   - 退出码为 `0`；
   - 不出现 Jest did not exit、open handles 或数据库连接日志。

### 任务 2：把默认单元测试变成真正的精确白名单

1. 将默认 Jest 收集范围改为精确、可审计的单元测试清单，或采用明确的 `*.unit.test.js` 命名约定并完成现有文件迁移。
2. 不得继续依赖 `**/routes/*.test.js` 这类会自动吸收未来未知测试的通配符作为安全边界。
3. 推荐方案按优先级：
   - 独立 `unitTestFiles` 精确列表并在配置中映射；或
   - 将确认无数据库连接的测试统一命名为 `*.unit.test.js`，默认配置只收集该后缀。
4. 如重命名文件，必须同步所有引用和文档；不得修改测试业务内容。
5. 增加一个配置级回归检查，证明：
   - 当前默认收集集合与批准清单完全一致；
   - 新建一个普通 `routes/example.test.js` 不会自动进入默认单元测试集合。
6. 不得创建会被遗留在仓库中的临时测试文件；配置验证使用系统临时目录或纯脚本模拟。

### 任务 3：加强集成测试门控不可绕过性

1. 保留显式授权、`NODE_ENV=test`、测试库命名及禁止 `safety_dashboard` 的现有规则。
2. 确认 `test:integration` 和 `test:integration:coverage` 都经过同一门控。
3. 门控不仅要在 npm 命令的前置进程执行，还必须在 Jest 集成配置的 `globalSetup` 或 `setupFiles` 中再次校验，避免直接运行 `jest --config jest.integration.config.js` 绕过。
4. 将门控校验提取为可复用函数，CLI 与 Jest 使用同一实现，避免规则漂移。
5. 只执行负向验证，不运行真实集成测试：
   - 无授权变量时直接调用 Jest 集成配置，必须在任何测试和连接之前失败；
   - 数据库名为 `safety_dashboard` 时必须失败；
   - 数据库名不符合测试命名规则时必须失败。
6. 验证过程中不得使用真实 DB_HOST、DB_USER、DB_PASSWORD。

### 任务 4：处理脆弱的 vue-i18n alias

1. 现在 `web-antd` 已显式依赖 `vue-i18n`，优先验证能否删除 `vite.config.ts` 中指向 `.pnpm/vue-i18n@完整版本...` 的硬编码 alias。
2. 删除后执行类型检查和仓库外空目录构建验证。
3. 如果 Vite 8 的已知问题确实要求 alias：
   - 使用 `import.meta.resolve`、`createRequire().resolve()` 或包根目录动态解析；
   - 不得包含完整版本号、TypeScript 版本号或 `.pnpm` 虚拟目录结构。
4. 不得升级 Vite、Vue、vue-i18n 或其他框架依赖。
5. 如果稳定解析方案无法验证，保留现状并在报告中给出证据；此项不单独阻断进入第二段。

## 第二段：阶段 2-A P0 鉴权收口

### 安全目标

消除无需合法登录即可获得管理员身份、执行数据导入或访问敏感诊断信息的路径。本轮只处理公开接口边界和鉴权入口，不实施全系统细粒度 RBAC。

### 任务 5：建立公开接口显式清单

1. 盘点 `server/middleware/auth.js` 的 `publicPaths`、`publicPrefixes`、开发模式放行项及所有 `/api/auth/*` 路由。
2. 删除或替换宽泛的公开前缀：
   - 不允许继续公开整个 `/auth/`；
   - 不允许继续公开整个 `/import/`。
3. 使用明确的 `method + path` 公开规则，至少区分 GET、POST，避免同路径不同方法被误放行。
4. 默认只公开系统正常启动所必需的最小接口，例如登录、刷新令牌及经过脱敏的存活检查。
5. 对注册、退出、当前用户、修改资料、修改密码、调试登录、导入上传、确认、回滚和日志查询逐项确定是否需要认证。
6. HSE 内部管理系统不得默认开放匿名注册；若现有产品确有自助注册要求，只记录为待决策，不得擅自放开。
7. 对每个公开接口写清业务理由，并建立自动化测试锁定清单。

### 任务 6：移除开发模式管理员回退

1. 修改 `server/routes/vben-compat.js` 和相关鉴权逻辑：
   - 缺少 Token、Token 无效或 Token 过期时，不得生成临时管理员 Token；
   - 不得回退 `admin` 用户或返回管理员权限码；
   - 开发环境与生产环境必须遵守相同身份真实性原则。
2. `/api/user/info`、`/api/access/codes`、`/api/auth/codes` 必须基于已经验证的用户身份返回数据。
3. 不得在兼容路由中再次自行解析并放宽 JWT；优先复用全局 `authMiddleware` 注入的 `req.user`。
4. Token 中的角色只能作为身份声明，权限码应与当前后端角色权限映射一致，禁止固定返回 `permissions: ['all']`。
5. 如用户在数据库中已禁用或不存在，应返回明确的 `401/403`，不得回退默认用户。

### 任务 7：关闭匿名导入链路

1. `/api/import/parse`、`confirm`、`rollback`、`logs`、`config`、`upload`、`stats` 等全部要求合法登录。
2. 写入、确认和回滚接口至少要求现有管理员或安全管理角色；优先复用现有 `requireRole` 或 `requirePermission`。
3. 模板下载是否允许匿名必须有明确产品理由；无依据时默认要求登录。
4. 审计日志中的操作人必须来自 `req.user`，不得信任请求体中的 `operator` 作为身份来源。
5. 不改变现有文件解析、字段映射、写库逻辑和响应结构。
6. 本轮仅通过 mock 单元测试验证，不得实际上传、解析、确认或回滚文件。

### 任务 8：收紧诊断和监控端点

1. `/api/health` 可以保留匿名存活检查，但匿名响应必须最小化：
   - 不返回数据库版本、主机、用户、库名、原始错误、内存详情或 AI 配置；
   - 不因数据库查询暴露内部异常。
2. `/api/postgres/status` 必须要求管理员权限，并避免向非管理员返回连接详情。
3. `/metrics` 必须默认受保护：
   - 可复用 JWT 管理员鉴权；或
   - 使用独立监控凭证，并在缺少配置时 fail-closed。
4. 启动脚本依赖的健康检查必须继续可用。
5. 不改变业务 API 的正常认证后响应。

### 任务 9：增加鉴权回归测试

测试必须全部 mock 数据库，不得产生真实连接。至少覆盖：

1. 匿名请求不能访问 `/api/user/info`、权限码接口。
2. 无效或过期 Token 不会获得临时管理员 Token。
3. 合法普通用户不会得到 `all` 或管理员权限。
4. 匿名请求不能调用导入上传、确认、回滚和日志接口。
5. 普通查看者不能调用导入写操作。
6. 允许角色可进入导入写操作的路由层，业务处理器使用 mock 阻断，避免真实文件与数据库行为。
7. `/api/health` 匿名可用但响应不包含敏感字段。
8. `/api/postgres/status` 和 `/metrics` 匿名访问被拒绝。
9. 公开接口清单中未列出的新接口默认返回 `401`。
