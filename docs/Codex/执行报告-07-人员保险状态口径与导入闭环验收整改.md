## 三、最终规则表（唯一口径）

### 3.1 当前有效与四态状态（`calcInsuranceStatus` 纯函数，DB SQL 与内存等价）

| 条件 | 状态 |
|---|---|
| 记录存在 + `is_deleted=false` + `is_current=true` + `start_date/expire_date` 均有效 + `start_date <= 业务日 <= expire_date`，且止期距业务日 **> 30 自然日** | `insured` |
| 同上（当前有效）且止期距业务日 **0–30 自然日（含 0 和 30）** | `expiring` |
| 只有历史保单（被选记录 `expire_date < 业务日` 且非当前有效） | `expired` |
| 未来、停用（`is_current=false`）、日期缺失（起期/止期）、起期晚于止期、根本无记录 | `uninsured` |
| `is_current` 缺失、起期缺失、止期缺失、起期晚于止期 | **一律 `uninsured`**（不默认 true、不宽容） |

日期按 `YYYY-MM-DD` 业务日字符串比较（`toBusinessDayStr`），避免本地时区/UTC 转换偏差。

### 3.2 确定性选单（`policyPivotSql` SQL 与 `pickBestInsuranceRecord` 内存比较器等价）

排序键（升序 rank）：**当前有效(0) > 未来(1) > 历史(2) > 停用/日期不完整(3)**；同 rank 内 `is_current DESC`、`expire_date DESC NULLS LAST`、`start_date DESC NULLS LAST`、`id DESC`。被选记录整行返回（id/保单号/日期/保额/保费/isCurrent/快照同源），禁止跨记录拼接（原 `MAX(CASE)` 多列拼记录已彻底移除）。

### 3.3 hasInsurance / 合规 / syncStatus

- `hasInsurance` = 当前有效参保（`status === 'insured' | 'expiring'`），与 `status` 同源；`recordExists` 单独表示"存在业务记录"（历史/停用/未来也有 ID，可进入编辑流程）。
- 合规 = 适龄人员(男<60, 女<50) 有**当前有效**工伤险 **或** **当前有效**雇主险保额 ≥ 80 万；超龄人员有当前有效工伤险。过期/未来/停用记录不得致合规。
- `syncStatus` 三态：无任何关联记录 `missing`；有记录且全部被选记录快照（person_name/department/position）与花名册一致 `synced`；任一不一致 `unsynced`。

### 任务 2：主列表、筛选、统计、合规、同步同一口径 ✅

- DB 主列表筛选重写：四态均显式含 `activePolicySql(emp/inj)`（`is_current=true AND start_date/expire_date 有效 AND start_date<=CURRENT_DATE AND expire_date>=CURRENT_DATE`）；`insured` 用 `> CURRENT_DATE + 30 days`、`expiring` 用 `<= CURRENT_DATE + 30 days`（第 30 天只属 expiring，无重叠）；`uninsured` 用 `NOT (activePolicySql(emp)) AND NOT (activePolicySql(inj))`（含未来/停用/日期不完整）；`expired` 用 `NOT 当前有效 AND expire_date < CURRENT_DATE`。
- 合规筛选同口径：`activePolicySql(inj) OR (适龄 AND activePolicySql(emp) AND COALESCE(emp.coverage_amount,0) >= 800000)`。
