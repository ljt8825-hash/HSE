## Codex 复核结论

阶段 1 当前状态为：**不通过，需整改后复核**。

上轮有价值的修改可以保留，但以下结论不成立或尚未达到验收标准：

1. `start-hse-v2.ps1` 虽声明后端使用 `5666`，启动后端子进程时没有显式设置 `PORT`。当前 `server/.env` 存在旧端口配置时，后端仍可能启动在 `5800`，脚本却轮询 `5666`，一键启动会失败。
2. `server/app.js` 将 `dotenv.config()` 提前了，但仍使用默认相对当前工作目录的 `.env` 查找方式。从项目根目录执行 `node server/app.js` 时可能读取根目录 `.env`，无法稳定读取 `server/.env`。
3. `vite.config.ts` 在配置模块顶层读取 `process.env.VITE_PROXY_TARGET`。Vite 的 `.env.development`、`.env.production` 通常在配置解析阶段通过 `loadEnv()`读取，当前写法无法保证 `.env.*` 中的覆盖值生效。
4. 默认 `npm --prefix server test` 仍会收集约 30 个依赖数据库的集成/E2E 套件。上轮首次测试已意外写入开发库，说明测试隔离门槛尚未建立。
5. 前端 `typecheck` 仍有 7 个错误，生产构建没有成功完成，因此运行基线不能判定通过。
6. `routes/auth.test.js` 仍有 4 个失败用例，默认单元测试没有全绿。

## 任务一：修正一键启动端口契约

目标：无论 `server/.env` 中是否存在旧 `PORT`，一键启动脚本启动的后端、健康检查和前端代理都必须使用同一端口。

1. 修改 `start-hse-v2.ps1`，建立一个统一后端端口变量：
   - 默认值为 `5666`；
   - 可以通过专用环境变量（建议 `HSE_BACKEND_PORT`）覆盖；
   - 必须校验为合法 TCP 端口。
2. 启动后端子进程时，显式把最终端口作为 `PORT` 传给该子进程，确保覆盖 `.env` 中的旧端口。
3. 启动前端子进程时，显式传入与后端端口一致的 `VITE_PROXY_TARGET`。
4. `$backendHealthUrl`、端口检查、启动日志和最终提示必须全部派生自同一个端口变量。
5. 不得通过修改真实 `server/.env` 实现这一目标。
6. 使用 PowerShell 语法解析或静态检查验证脚本，不得实际运行脚本中的清理和启动流程。

## 任务二：固定 dotenv 查找位置

1. 修改 `server/app.js`，让它显式从 `server/.env` 加载环境变量，路径必须基于 `__dirname`，不得依赖启动时的当前工作目录。
2. `dotenv` 仍须在任何读取配置的业务模块之前完成加载。
3. 从以下两种启动方式进行不连接数据库的静态或模块级验证：

## 任务四：建立默认测试隔离

目标：`npm --prefix server test` 默认只能运行不连接数据库的单元测试，集成测试必须显式选择并通过安全门控。

1. 盘点当前测试，明确分类：
   - 纯单元测试；
   - mock API 测试；
   - 需要 PostgreSQL 的集成测试；
   - 独立诊断或验收脚本。
2. 为 Jest 建立清晰的单元测试配置：
   - 默认 `npm test` 只收集确认不连接数据库的单元测试；
   - 不得使用过于宽泛的忽略规则掩盖测试；
   - 可以使用独立 `jest.unit.config.js` 或精确目录/文件约定。
3. 增加明确的集成测试脚本，例如 `test:integration`，但默认不得执行。
4. 集成测试必须 fail-closed，至少同时满足：
   - 显式授权变量，例如 `ALLOW_INTEGRATION_TESTS=true`；
   - `NODE_ENV=test`；
   - 数据库名符合专用测试库命名规则，例如以 `_test` 或 `test_` 开头；
   - 数据库名不得是 `safety_dashboard`；

6. 修复 `server/routes/auth.test.js` 的 4 个失败用例：

   - 保持业务实现不变；

7. 默认单元测试必须全绿，且执行过程中不得产生 PostgreSQL 连接日志。
