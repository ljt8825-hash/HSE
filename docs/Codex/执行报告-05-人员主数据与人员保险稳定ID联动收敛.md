## 3. 人员保险稳定 ID 数据契约（任务 1）

- 唯一人员来源：`employee`；当前显示信息来源：`v_employee_current`（主键在视图中为 `employee_id`）。
- 数据库关联字段：`personnel_insurance.employee_id -> employee.id`（迁移后）。
- API 对外字段：`employeeId`；保险记录 ID：`id`、`employer.id`、`injury.id`（不得与 `employeeId` 混用）。
- 快照字段：`person_name`、`department`、`position` —— 保留用于历史展示/审计/同步状态比较，**不参与主查询 JOIN、分组、更新/删除定位、自动匹配**。
- 花名册为左表；无保险事实 → `uninsured`，不插入虚假记录。
- 已离职/未匹配历史记录不丢失，不混入主列表；通过未匹配查询暴露（本轮 pending-list 排除逻辑已切 employee_id；未匹配记录清单在迁移核验 SQL 提供）。
- 姓名不作自动匹配唯一依据：同名保持两人、改名经 `employee_id` 关联同一人（测试锁定）。

**字段映射表**：

| 旧字段 | 目标字段 | 写入方 | 读取方 | 是否快照 | 迁移策略 | 兼容期策略 | 删除条件 |

|------|------------|------------|

**当前保单确定性选择规则**（任务 3 第 3 条，测试锁定 SQL）：
`ROW_NUMBER() OVER (PARTITION BY employee_id ORDER BY is_current DESC, expire_date DESC NULLS LAST, start_date DESC NULLS LAST, id DESC)` + `WHERE rn = 1`（险种已按 `insurance_type` 过滤）。字段全部取自该条被选记录，**杜绝多个 MAX(CASE) 跨记录拼接**。

**未匹配/历史记录**：`employee_id IS NULL` 或引用不存在的保险记录不混入主列表（主列表左表为花名册）；数量与明细由迁移核验 SQL 提供（保险记录 ID、快照姓名、险种、保单号、原因）。
