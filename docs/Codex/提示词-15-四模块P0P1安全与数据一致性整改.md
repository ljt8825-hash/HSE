## 背景

执行报告-14扫描发现4个P0和多个P1问题。本轮为**代码整改轮次**，需要实际修改代码并验证。

**P0问题（必须全部修复）**：
1. **违章权限黑洞**：`violations.js`写接口使用`requirePermission('hse:site-mgmt:violations')`，但该权限码未在`auth.js`的`HSE_MANAGER_PERMISSIONS`中注册，导致admin/safety_manager写三违全部403（仅system_admin可写）
2. **事故模块无角色校验**：`accidents.js`全部router（GET/POST/PUT/DELETE/attachments/import/export）无`requireRole`，任何登录用户可写
3. **事故模块err.message泄漏**：10处catch直接返回`err.message`泄漏SQL/连接信息
4. **accidents.vehicle_id无DDL来源**：代码INSERT/UPDATE引用`vehicle_id`列，但`init-tables.js`和`ensureTables`均未定义该列，真实库未手工加列则写操作运行期报错

**P1问题（本轮一并修复）**：
5. **车辆删除不联动事故**：`DELETE /api/insurance/vehicle/:id`只软删vehicles+insurance_history，未处理accidents.vehicle_id引用
6. **事故创建/更新无车辆存在校验**：传入vehicle_id时不校验vehicles表中存在且未删除
7. **risk-center统计查旧表**：`hse-driver-risk-center.js:101`查`vehicle_inspection_records`（旧表），应统一查`hse_driver_inspection_records`（新表）
8. **vehicles.status枚举口径分裂**：schema枚举`['在用','停用','报废']`不含"维修中"，但BI/demo/import依赖"维修中"

**本轮明确不做**（边界声明，禁止越界）：
- ❌ 不开发维修工单模块
- ❌ 不给三违(violation_records)加vehicle_id（三违为人员维度）
- ❌ 不补三检CRUD（工作量大，独立轮次）
- ❌ 不给事故加"交通事故必须关联车辆"强制校验（待业务确认）
- ❌ 不拆分vehicles历史保单表（13轮已明确）
- ❌ 不修改前端运行时代码（.ts/.vue文件）
- ❌ 不连接/修改真实数据库，不执行SQL迁移脚本（仅创建SQL迁移文件）

## 整改任务清单

### 任务1：违章权限修复（P0-1）

**文件**：`server/routes/violations.js`

**问题**：6处写接口使用`requirePermission('hse:site-mgmt:violations')`，该权限码未注册。

**修复方式**（对齐车辆模块13轮模式）：
- 将所有写接口（POST /、PUT /:id、DELETE /batch、DELETE /:id、PUT /:id/rectify、PUT /:id/review）的`requirePermission('hse:site-mgmt:violations')`替换为`requireRole('admin', 'safety_manager')`
- 读接口（GET /、GET /:id、GET /stats、GET /filter-options、GET /export/csv、GET /statistics/*）保持现有`requirePermission`读权限不变（读权限码`hse:site:violations:view`等已注册）
- 将所有catch块的`res.json(error(-1, err.message))`改为console.error服务端日志 + 安全错误文案（"操作失败，请稍后重试"等），参照车辆模块模式
- 不修改`auth.js`的权限映射表（因为改用requireRole后不再依赖该权限码）

**验证点**：
- admin/safety_manager角色可正常创建/更新/删除/整改/复查三违
- viewer角色不能写三违
- SQL错误不向前端泄漏内部信息

### 任务3：accidents.vehicle_id DDL补齐（P0-3）

**文件**：
- `server/init-tables.js`（CREATE TABLE accidents段）
- `server/routes/accidents.js`（ensureTables函数）
- 新建 `server/sql/accidents_add_vehicle_id.sql`（迁移脚本）

**修复内容**：

1. **init-tables.js**：在CREATE TABLE accidents的字段列表中添加`vehicle_id BIGINT`列（放在personnel_id之后或involved_person之前），确保全新初始化的库包含该列。

2. **accidents.js ensureTables函数**：添加幂等ALTER TABLE：
   ```sql
   ALTER TABLE accidents ADD COLUMN IF NOT EXISTS vehicle_id BIGINT;
   ```
   确保已有库在服务启动时自动补列（幂等，IF NOT EXISTS避免重复加列报错）。

3. **创建迁移脚本** `server/sql/accidents_add_vehicle_id.sql`：
   - 幂等DDL：`ALTER TABLE accidents ADD COLUMN IF NOT EXISTS vehicle_id BIGINT;`
   - 注释说明：该列用于关联vehicles表主键，支持交通事故关联车辆
   - 可选：创建索引 `CREATE INDEX IF NOT EXISTS idx_accidents_vehicle_id ON accidents(vehicle_id) WHERE is_deleted = false AND vehicle_id IS NOT NULL;`
   - 回退语句：`-- ALTER TABLE accidents DROP COLUMN IF EXISTS vehicle_id;`

4. **formatRow补vehicleId输出**：在formatRow函数中添加`vehicleId: row.vehicle_id || null`字段，确保前端能获取车辆ID用于回显。

### 任务4：事故vehicle_id数据一致性加固（P1-1 + P1-2）

**文件**：
- `server/routes/accidents.js`（POST/PUT）
- `server/routes/insurance.js`（DELETE /vehicle/:id）

**修复内容**：

1. **车辆存在校验**（accidents.js POST和PUT）：
   - 当请求体中包含vehicle_id且值非空/非null时，在事务内校验：
     ```sql
     SELECT id FROM vehicles WHERE id = $1 AND is_deleted = false
     ```
   - 若车辆不存在或已删除，返回`res.json(error(-2, '关联车辆不存在或已删除'))`
   - vehicle_id为空/null时不校验（非交通事故可不关联车辆）

2. **UPDATE COALESCE修复**（P2顺带）：
   - PUT /:id中vehicle_id的COALESCE改为显式检查：`b.vehicle_id !== undefined ? b.vehicle_id : null`（注意：需要支持传null置空，不要用COALESCE忽略null）
   - 参照车辆模块PUT修复模式，避免"传null无法置空"的问题

3. **车辆删除联动**（insurance.js DELETE /vehicle/:id）：
   - 在现有事务中（软删vehicles + 软删insurance_history之后）增加检查：
     ```sql
     SELECT COUNT(*)::int AS cnt FROM accidents WHERE vehicle_id = $1 AND is_deleted = false
     ```
   - 如果存在未删除的关联事故，**阻止删除**，返回`res.json(error(-3, '该车辆存在关联事故记录，无法删除。请先处理相关事故后再试。'))`
   - 不做级联软删（事故是重要安全记录，不应因车辆删除而消失），不做置空（保留vehicle_id指向已删除车辆是合理的，因为车辆已软删，ID不回收）
   - 仅做**阻止删除**，这是最安全的策略（参照外键RESTRICT语义）
