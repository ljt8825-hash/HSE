## 三、最终 active/冲突决策表（唯一纯函数）

唯一判定函数（任务 1）：

```js
// server/services/personnelInsurancePolicyService.js
isPolicyActiveOnBusinessDay({ isCurrent, startDate, expireDate }, businessDay)
```

- 条件（与 09 轮真值表完全一致）：`is_current=true` + 起止日期都存在 + `start<=expire` + `start<=businessDay<=expire`
- 默认业务日：`getBusinessDayStr()`（Asia/Shanghai，可注入固定时刻）；**禁止** `toISOString().slice(0,10)`
- 所有写入口先合并"最终完整事实"，再调用本函数；仅结果为 true 时才查 active 冲突

| 事实 | is_current | 起/止 | 业务日关系 | active 判定 | 是否查冲突 | 允许行为 |
|-----|-----------|-------|-----------|------------|-----------|---------|
| 当前有效 | true | 齐全且 start<=expire | start<=day<=expire | ✓ active | 查（排除自身） | 无冲突可写 |
| 当天生效 | true | start=day, expire>=day | 区间含 day | ✓ active | 查 | 无冲突可写 |
| 当天到期 | true | start<=day, expire=day | 区间含 day | ✓ active | 查 | 无冲突可写 |
| 未来 | true | 齐全合法 | start>day | ✗ 非 active | **不查** | 允许（不被已有 active 误拦） |
| 历史 | true | 齐全合法 | expire<day | ✗ 非 active | **不查** | 允许 |
| 停用 | false | 任意 | 任意 | ✗ 非 active | **不查** | 允许 |
| 缺起期/缺止期 | true | 不齐全 | — | ✗ 非 active | **不查** | 允许（日期合法性由各入口自己的校验处理，与冲突语义分离） |
| 起期晚于止期 | true | 非法顺序 | — | ✗ 非 active | **不查** | 由入口自己的 date_order_invalid 拒绝 |
