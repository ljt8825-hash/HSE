## 三、最终规则表

### 3.1 Asia/Shanghai 业务日

- `server/services/businessDay.js`：`getBusinessDayStr(now)` 用 `Intl.DateTimeFormat('en-CA', { timeZone: 'Asia/Shanghai' })` 生成 `YYYY-MM-DD`，可注入时刻（测试固定北京时间零点边界）。
- DB 侧统一 `BUSINESS_DAY_SQL = "CURRENT_TIMESTAMP AT TIME ZONE 'Asia/Shanghai'::date"` 替换 personnel 相关全部裸 `CURRENT_DATE`（主列表/COUNT/stats/选单/查重/expiring-soon）；不依赖连接会话时区。

### 3.2 确定性选单排名（SQL 与内存完全等价）

| rank | 语义 | SQL CASE / 内存 rank 条件 |
|---|---|---|
| 0 | 当前有效 | `is_current=true` 且 `start_date <= 业务日 <= expire_date` |
| 1 | 当前标记的未来 | `is_current=true` 且 `start_date > 业务日` |
| 2 | 当前标记的历史 | `is_current=true` 且 `expire_date < 业务日` |
| 3 | 停用/日期不完整/非法 | `is_current=false` 的未来/过期、缺起/止期、起期晚于止期 |

同 rank 排序：`is_current DESC`、`expire_date DESC NULLS LAST`、`start_date DESC NULLS LAST`、`id DESC`（SQL `END ASC` 后的键序与内存 `compareInsuranceRecords` 逐项一致）。`is_current=false` 的未来/过期记录 SQL 与内存均 rank 3（修复点 4）。

### 3.3 人员级互斥四态（优先级 expiring > insured > expired > uninsured）

| 人员级状态 | 条件 |
|---|---|
| `expiring` | 任一受支持险种存在当前有效且 0–30 天到期的被选保单 |
| `insured` | 不属于 expiring，且至少一个险种当前有效 |
| `expired` | 无任何当前有效，且至少一个险种的被选记录是历史过期 |
| `uninsured` | 以上均不满足（无记录，或只有未来、停用、日期不完整/非法） |

- 共享构造：SQL `personLevelSql(emp, inj)`（expiring/covered/hasExpired 三表达式）与 JS `calcPersonStatus(empStatus, injStatus)` 完全一致；DB list/COUNT、stats 复用同一表达式，内存筛选/格式化复用同一纯函数。
- **stats 恒等式**：`covered = insured + expiring`、`expired = expired`、`pending = uninsured`，`total = covered + expired + pending`；`expiring30d ⊆ covered`；`byType` 按各险种当前有效人数。

### 3.4 险种字典（唯一生产字典 `server/services/insuranceTypeDict.js`）

| 输入 | 规范化结果 | 行为 |
|---|---|---|
| `雇主责任险` | 雇主责任险 | 允许 |
| `工伤保险` | 工伤保险 | 允许 |
| `工伤险` / `工伤` | 工伤保险 | 别名归一 |
| `意外伤害险` | —（不支持） | `unsupported_insurance_type` 拒绝写库 |
| `五险` | —（规则条件，非保单类型） | 拒绝写库；规则输出映射为工伤保险（五险人员方案=工伤保障） |
| 其他未知 | —（不支持） | `unsupported_insurance_type` 拒绝写库 |
