## 3. 最终 API 写入契约与前端表单字段映射（任务 1/2）

```ts
interface PersonnelInsuranceWritePayload {
  employeeId: number;          // 必填、正整数
  insuranceType: string;       // 必填
  coverageAmount?: number;
  premium?: number;
  startDate?: string | null;
  expireDate?: string | null;
  isCurrent?: boolean;
  policyNo?: string;
  remark?: string;
}
```

- `createPersonnelSchema`：`z.object({...}).strict()` —— 旧 snake_case / 页面旧字段（personnel_id/person_name/name/idCard/policyNumber/policyStartDate/policyEndDate）被**明确拒绝（400）**，不再静默剔除。
- `updatePersonnelSchema`：独立 strict schema；不含 employeeId → 不修改关联人；显式 employeeId → 换人（服务端校验 + 刷新全部快照）。
- camelCase → snake_case 映射集中在路由层（`insuranceType→insurance_type`、`startDate→start_date` 等），页面不发送数据库列名。
- 前端 `createPersonnel/updatePersonnel` 使用严格类型（不再 `Partial<PersonnelItem>`）。

前端表单：姓名/身份证输入替换为 `EmployeeSelector`（单选 → `personForm.employeeId`）；编辑时锁定所属人员（只读展示姓名）；续保改用 `startDate/expireDate`。

## 4. 调用链与稳定 ID 解析规则（任务 3/4）

| 路径 | 解析规则 |
|------|---------|
| `POST /personnel`（新增） | employeeId（schema 必填）→ `resolveEmployee({employeeId})` 查 v_employee_current → 快照 person_name/department/position 服务端生成 → INSERT 写 employee_id + personnel_id（兼容同值） |
| `PUT /personnel/:id`（更新） | 无 employeeId → 仅更新保单字段（关联键/快照不变）；显式 employeeId → `resolveEmployee` 校验 → `employee_id=$10, personnel_id=$10, person_name=$11, department=$12, position=$13`（姓名用查询结果） |
| `POST /personnel/import`（直接导入） | 每行 employeeCode/employeeId → `resolveEmployee` 唯一解析 → 姓名附加一致性校验（不一致失败）→ INSERT 写 employee_id + 快照；零候选/多候选/缺标识 → 行失败 |
| import.js 通用导入 personnel | Excel "工号/员工编号" → `employee_code`（中间字段）→ 预处理按 employee_code/employee_id 唯一解析 → 注入 employee_id + person_name/department/position → 错误行（`_import_error`）不写入，进入 `rowErrors` |
| 续保 `PUT` | 同更新（startDate/expireDate/premium/remark），不换人 |

## 5. 有效保单、确定性选单、syncStatus、合规与未匹配规则表（任务 6）

| 规则 | 定义 |
|------|------|
| 当前有效 | 未删除 + `is_current=true` + `start_date <= 业务日 <= expire_date` |
| insured / expiring / expired / uninsured | 有效且 >30 天 / 有效且 ≤30 天（含今天与第 30 天边界）/ 有效记录已过期 / 无有效当前保单、未生效或缺必要日期 |
| 确定性选单 | `ROW_NUMBER() OVER (PARTITION BY employee_id, insurance_type ORDER BY is_current DESC, expire_date DESC NULLS LAST, start_date DESC NULLS LAST, id DESC)` 取 rn=1（字段全部来自该条记录） |
| syncStatus | 无任何关联保险 → missing；所有被选记录快照（姓名/部门/岗位）与花名册一致 → synced；任一不一致 → unsynced |
| 合规 | 有工伤险 或（适龄且雇主险保额 ≥80 万）→ compliant；否则 noncompliant |
| 未匹配原因 | `missing_employee_id`（employee_id 空）/ `employee_not_found`（指向不存在或非当前人员） |

所有日期/状态判定集中于 `calcInsuranceStatus`（可单测纯函数，接受固定 today）；SQL 与 JS 边界一致（expire_date 当天仍为 expiring，第 31 天起 insured）。
