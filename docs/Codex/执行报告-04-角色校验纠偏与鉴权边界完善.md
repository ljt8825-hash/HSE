## 6. 认证解析最终流程（任务 3）

```
请求
 ├─ 公开路径（POST login/refresh/logout、GET health）
 │    └─ 可选认证：resolveAuthentication(authHeader, { checkUser: true })
 │         ├─ 有效且用户启用 → req.user 注入（health 返回认证详情）
 │         └─ 无 token / 无效 / 过期 / 拉黑 / 禁用 / 删除 / 存储异常 → 按匿名处理（health 最小字段）
 └─ 受保护路径
      └─ resolveAuthentication(authHeader, { checkUser: true })
           ├─ ok          → req.user（规范字段）→ next()
           ├─ blacklisted → 401 令牌已失效
           ├─ disabled    → 403 账户已被禁用
           ├─ deleted     → 401 用户不存在或未登录
           ├─ error(存储异常) → 503 认证服务暂不可用（fail-closed）
           ├─ no-token    → 401 未提供认证令牌
           └─ invalid     → 401 无效的令牌
```

`req.user` 规范字段：`{ id, username, role, realName, jti }`；`checkUser` 从 `users` 表取最新角色（角色变更立即生效，不信任 Token 旧声明）。

## 7. 登出、撤销与 refresh 最终语义（任务 4）

| 场景 | 行为 |
|------|------|
| 无 Token 登出 | 200 幂等成功 |
| 有效 Token 登出 | `jwt.verify` 验签（access + jti）→ `blacklistToken` INSERT → 200；审计用可信身份 |
| 伪造/过期/类型错误 Token 登出 | 200 幂等成功，不写黑名单、不用其声明写审计 |
| 黑名单写入失败 | 500「登出失败：服务端会话撤销失败」，不伪装成功 |
| refresh 黑名单检查异常 | 503「认证服务暂不可用」（fail-closed，不放行） |
| 黑名单中 refresh Token | 401「刷新令牌已注销」 |

测试证据：`auth-gate` 5 个 logout 用例 + 1 个 refresh 异常用例全过。
