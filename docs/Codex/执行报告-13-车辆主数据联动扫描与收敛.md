## 三、架构决策记录

### 3.1 主入口确定

- **唯一主入口**：`/api/insurance/vehicle`（前端`src/api/hse/insurance.ts`实际调用的接口）
- **遗留接口**：`/api/vehicles`（`routes/vehicles.js`+`controllers/vehicles.js`），保留向后兼容，添加遗留标记注释
- **理由**：前端实际使用`/api/insurance/vehicle`；该接口字段模型更完整（含交强险/商业险分项）；`/api/vehicles`使用旧的简单字段模型和`insurance_history`表，与生产数据模型不一致

### 3.2 稳定主键方案

- `vehicles.id`：BIGSERIAL主键（已存在），作为车辆稳定ID
- `plate`(车牌)：业务唯一键，添加部分唯一索引（`WHERE is_deleted=false`），支持车牌过户后重新启用
- `vin`：辅助索引（非唯一，VIN可能为空或录入错误），添加普通索引支持查询

### 3.3 数据模型边界

- **vehicles表**：保持"车辆主信息 + 当前有效保险状态"混合模型
  - 主信息：plate/vin/engine_no/reg_date/model/owner/vehicle_type/status/remark
  - 当前保险：insurance_type/insurance_start/insurance_end/premium
  - 交强险分项：compulsory_start/compulsory_end/compulsory_premium
  - 商业险分项：commercial_start/commercial_end/vehicle_damage/third_party/passenger/commercial_total
  - 合计字段：vehicle_tax/total_premium/policy_holder/registered_owner
- **insurance_history表**：保留给遗留接口`/api/vehicles`使用，主入口`/api/insurance/vehicle`不依赖它
- **不拆分历史保单表**：系统扫描04明确"不宜在本轮贸然重写"，本轮仅做收敛和加固，历史保单拆分留待后续专门轮次
- **有效止期口径**：`COALESCE(commercial_end, compulsory_end, insurance_end)`（已验证与生产数据一致，commercial_end优先）

### 3.4 时效状态计算（统一后）

```
expiryStatus = calcExpiryStatus(COALESCE(commercial_end, compulsory_end, insurance_end), businessDay)
  - expired: 止期 < 业务日
  - expiring: 业务日 ≤ 止期 ≤ 业务日+30天
  - normal: 止期 > 业务日+30天
  - unknown: 无止期
```

- DB侧：`$1::date`参数化业务日，不使用裸`CURRENT_DATE`
- Node侧：`new Date(businessDay + 'T00:00:00+08:00')`，不使用`new Date()`
- 筛选与徽标100%口径一致（列表insuranceStatus筛选 ≡ expiryStatus徽标）
