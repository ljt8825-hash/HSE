## 二、三违责任传导规则最终冻结

### 2.1 核心规则

```
三违人员（违规者）
        ↓
  直属上级（direct_manager_id）
        ↓
  生成责任扣分（100%传导，chain_level=1）
```

### 2.2 关键参数

| 参数 | 固定值 |
|------|--------|
| `chain_level` | `1`（仅一级传导） |
| `transmission_ratio` | `1.0`（100%传导） |
| `relation_type` | `direct_supervisor` |
| `VIOLATION_DEDUCTION` | `5`（每次三违扣5分） |

### 2.3 禁止事项

- ❌ 禁止多级传导
- ❌ 禁止跨级传导
- ❌ 禁止平级传导

详见：《三违责任传导规则最终冻结版.md》

## 三、三违扣分标准统一冻结

### 3.1 统一标准

| 场景 | 扣分 |
|------|------|
| 个人三违（每次） | 5分 |
| 直属上级传导扣分 | 5分 × 100% = 5分 |

### 3.2 已删除内容

- ❌ 重大三违扣20分
- ❌ 较大三违扣10分
- ❌ 一般三违扣5分
- ❌ 其他三违扣2分
- ❌ 50%传导比例

### 3.3 保留内容

- ✅ `violation_level` 字段保留（仅用于审计追溯，不影响扣分计算）

详见：《三违扣分标准统一修正版.md》

## 四、评分引擎修正冻结

### 4.1 评分流程

```
自动评分 → 人工调整 → 加分 → 否决项 → 最终得分 → 等级计算
```

### 4.2 核心计算

| 计算项 | 公式 |
|--------|------|
| 个人三违扣分 | 三违次数 × 5 |
| 传导扣分 | 个人扣分 × 100% |
| 自动得分 | max(0, 100 - 总扣分) |
| 最终得分 | score_auto + score_manual + score_bonus |
| 等级 | A(≥90) / B(≥80) / C(≥70) / D(≥60) / E(<60) |

### 4.3 冻结逻辑修正

**修正前**（bug）：
1. 设置frozen状态 → 2. 更新排名 → ❌ 触发器阻止

**修正后**：
1. 更新排名 → 2. 设置frozen状态 → ✅ 成功

详见：《评分引擎修正版报告.md》

### 7.2 事务回滚bug

| 项目 | 内容 |
|------|------|
| 问题 | 冻结端点在pending检查失败时使用 `return` 退出，未调用 `ROLLBACK` |
| 影响 | 事务未正确回滚 |
| 修正 | 在return前添加 `await client.query('ROLLBACK')` |
