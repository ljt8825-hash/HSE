## 一、修正概述

### 1.1 修正范围

| 模块 | 修正内容 |
|------|----------|
| 三违指标扣分 | 删除分级规则，统一为固定扣分5分/次 |
| 责任传导计算 | 修正传导比例100%，层级固定为1 |
| 冻结逻辑 | 修正排名更新顺序（先排名后冻结） |
| 评分流程 | 确保自动评分、人工调整、加分、否决项、最终得分、等级计算正确 |

### 1.2 修正原因

1. 旧版本三违扣分使用分级标准（重大/较大/一般/其他），规则不统一
2. 旧版本责任传导比例为50%，与最终冻结规则（100%）不符
3. 冻结逻辑存在bug：先设置frozen状态再更新排名，导致触发器阻止排名更新

## 二、评分引擎核心逻辑

### 2.1 自动评分流程

```
1. 查询考核周期 → 校验状态
2. 查询考核对象 → 遍历每个对象
3. 查询考核指标 → 遍历每个指标
4. 根据指标data_source计算扣分：
   - violation_records: 三违次数 × 5分
   - hazards: 隐患整改率
   - training_records: 培训完成率
   - risk_alerts: 风险预警响应
   - responsibility_forms: 责任书签订
   - veto: 否决项
5. 计算单项得分 = base_score - metricDeduction
6. 汇总总扣分
7. 自动得分 = max(0, 100 - totalDeduction)
8. 计算等级（A/B/C/D/E）
9. 写入评分记录
10. 更新考核对象得分
```

### 2.2 三违指标扣分（修正后）

```javascript
if (metric.data_source === 'violation_records') {
  const violationsResult = await client.query(
    `SELECT count(*) as cnt
     FROM violation_records
     WHERE violator_id = $1
       AND violation_date >= $2
       AND violation_date <= $3
       AND is_deleted = FALSE`,
    [target.employee_id, cycle.start_time, cycle.end_time]
  );
  const violationCount = parseInt(violationsResult.rows[0].cnt);
  rawValue = violationCount;
  rawValueDesc = `三违${violationCount}次`;
  metricDeduction = violationCount * VIOLATION_DEDUCTION;  // 5分/次
}
```

### 2.3 人工调整流程

```
1. 查询扣分明细 → 校验存在
2. 校验对象未冻结
3. 获取旧分值（confirmed_score 或 suggested_score）
4. 计算新版本号 = current_version + 1
5. INSERT 调整记录（hse_deduction_adjustment）
6. UPDATE 扣分明细（current_version, confirmed_score, review_status='adjusted'）
7. 重新计算对象总扣分
8. 更新对象得分和等级
```

### 2.4 加分机制

```sql
-- 对象总分计算（包含加分）
score_total = COALESCE(score_manual, 0) + score_auto + COALESCE(score_bonus, 0)
```

| 字段 | 说明 |
|------|------|
| `score_auto` | 自动评分（100 - 总扣分） |
| `score_manual` | 人工评分（手动覆盖） |
| `score_bonus` | 加分项 |

### 2.5 否决项处理

```javascript
if (metric.metric_type === 'veto') {
  rawValue = 0;
  rawValueDesc = '无否决项';
  dataSources.push({ source_table: 'accidents', note: '待接入' });
}
```

否决项指标当前默认无否决，待后续接入事故数据后实现一票否决逻辑。

### 2.6 最终得分计算

```javascript
const scoreAuto = Math.max(0, Math.round((100 - totalDeduction) * 100) / 100);
const grade = calculateGrade(scoreAuto);
```

### 2.7 等级计算

```javascript
function calculateGrade(score) {
  if (score >= 90) return 'A';
  if (score >= 80) return 'B';
  if (score >= 70) return 'C';
  if (score >= 60) return 'D';
  return 'E';
}
```

| 等级 | 分数范围 |
|------|----------|
| A | ≥ 90 |
| B | 80 ~ 89 |
| C | 70 ~ 79 |
| D | 60 ~ 69 |
| E | < 60 |

## 三、冻结逻辑修正

### 3.1 旧版本bug

```javascript
// 旧版本（有bug）
await client.query(`UPDATE hse_assessment_cycle SET status = 'frozen' ...`);
await client.query(`UPDATE hse_assessment_target SET status = 'frozen' ...`);  // 触发器激活
// 以下排名更新被 trg_prevent_frozen_target 触发器阻止
await client.query(`UPDATE hse_assessment_target SET rank_township = ...`);  // 失败！
await client.query(`UPDATE hse_assessment_target SET rank_all = ...`);  // 失败！
```

### 3.2 修正后逻辑

```javascript
// 修正版本（先排名后冻结）
// 1. 先计算排名（此时对象未冻结，可以更新）
for (const row of townshipsResult.rows) {
  await client.query(`UPDATE hse_assessment_target SET rank_township = ...`);
}
await client.query(`UPDATE hse_assessment_target SET rank_all = ...`);

// 2. 再设置冻结状态（排名完成后才冻结）
await client.query(`UPDATE hse_assessment_cycle SET status = 'frozen' ...`);
await client.query(`UPDATE hse_assessment_target SET status = 'frozen' ...`);
```

### 3.3 冻结保护机制

| 修改扣分 | 允许（仅pending状态） | ❌ 拒绝 |
| 添加扣分 | 允许 | ❌ 拒绝 |
| 调整扣分 | 允许 | ❌ 拒绝 |
| 审核扣分 | 允许 | ❌ 拒绝 |
| 修改对象 | 允许 | ❌ 拒绝 |

## 四、评分版本管理

### 4.1 版本号机制

| 字段 | 说明 |
|------|------|
| `score_version` | 评分版本号，每次自动评分+1 |
| `current_version` | 扣分明细版本号，每次调整+1 |
| `version_no` | 调整记录版本号，与current_version对应 |

### 4.2 调整记录不可篡改

```sql
-- hse_deduction_adjustment 表触发器
CREATE TRIGGER trg_prevent_adjustment_update
    BEFORE UPDATE OR DELETE ON hse_deduction_adjustment
    FOR EACH ROW
    EXECUTE FUNCTION prevent_adjustment_modify();
-- 错误: 扣分调整记录表仅允许INSERT，禁止UPDATE和DELETE
```

调整记录采用INSERT-only模式，每次调整新增一条记录，不修改旧记录，确保完整的版本历史。
