## 一、任务概述

在 WebSocket 连接断开（网络抖动 / 代理超时 / 浏览器休眠恢复）时，跨模块员工数据刷新依赖的 `EmployeeName` 不会自动更新。本任务在 WS 不可用时，优雅降级为 **30s 间隔 HTTP 轮询 `/api/hse/employee/events?since=`**，确保跨模块员工数据最终一致。

设计目标（来自提示词）：
- WS 正常：不轮询（省带宽）
- WS 断开：自动启动 30s 轮询
- WS 重连：自动停止轮询
- 轮询端点不可用：静默失败，不阻塞 UI

## 三、改动清单

### 后端（`server/routes/hse-employee.js` / `server/services/employeeEventService.js`）
**无代码改动** —— 端点与 `getEventsSince(since)` 已存在且正确。仅做确认 + 冒烟验证（见第四节）。

### 前端（`src/components/hse/useHseWebSocket.ts`）

1. **新增轮询状态变量**
   ```ts
   const POLL_INTERVAL_MS = 30_000;            // 30s
   let pollTimer: ReturnType<typeof setInterval> | null = null;
   let pollCursorMs = Date.now() - 60_000;     // 首次轮询拉取最近 60s 事件
   ```

2. **新增轮询函数**
   ```ts
   async function pollEmployeeEvents() {
     try {
       const token = useAccessStore().accessToken;
       const res = await fetch(
         `/api/hse/employee/events?since=${encodeURIComponent(String(pollCursorMs))}`,
         { headers: token ? { Authorization: `Bearer ${token}` } : {} },
       );
       if (!res.ok) return;
       const body = await res.json();
       const events = (body?.data?.events as any[]) || [];
       for (const event of events) {
         publishEmployeeEvent(event as any);
         const ts = typeof event?.publishedAtMs === 'number'
           ? event.publishedAtMs
           : (event?.occurredAt ? Date.parse(event.occurredAt) : 0);
         if (ts > pollCursorMs) pollCursorMs = ts;   // 推进游标
       }
     } catch {
       // 静默失败，不阻塞 UI（B-6）
     }
   }

   function startPolling() {
     if (pollTimer) return;                  // 幂等守卫
     pollEmployeeEvents();                   // 立即拉取一次
     pollTimer = setInterval(pollEmployeeEvents, POLL_INTERVAL_MS);
   }

   function stopPolling() {
     if (pollTimer) { clearInterval(pollTimer); pollTimer = null; }
   }
   ```

3. **在 WS 生命周期中集成**
   - `ws.onopen` → `stopPolling();`（WS 恢复，回归 WS 事件驱动，B-5）
   - `ws.onerror` → `startPolling();`（B-3）
   - `ws.onclose`（含 `code===4001` 认证失败降级分支）→ `startPolling();`
   - `handleFailure()` 降级分支 → `startPolling();`
   - `disconnect()` 与 `onBeforeUnmount` → `stopPolling();`（资源清理，B-7）

> 说明：`useHseWebSocket` 在 `store/notifications.ts` 中**单例**实例化（仅一个轮询定时器，不会重复）；store 在 logout 与 store-dispose 时调用 `disconnect()`，故 `pollTimer` 在应用销毁时被清理。

## 七、结论

WS 轮询兜底已实现并通过后端冒烟 + 前端代码审查 + 服务层单测。WS 不可用时的跨模块员工数据最终一致得到保障，且：

1. **修正了提示词的两处实质缺陷**：端点路径（`/events` 非 `/employees/events`）、`fetch` 必须带 JWT（否则 401 静默失败）。
2. **游标改用数值（epoch ms）**，与后端 `publishedAtMs > sinceMs` 严格过滤精确对齐，避免 ISO 字符串比较边界误差。
3. **WS 主路径零侵入**，仅在断开时补充轮询，重连即停；去重与清理机制完善，无内存泄漏风险。

> 建议：后续任何"前端直接 `fetch('/api/...')`"的调用，均须显式携带 JWT（或改用 `requestClient`），以免踩中全局 `authMiddleware` 的 401 静默失败坑。
