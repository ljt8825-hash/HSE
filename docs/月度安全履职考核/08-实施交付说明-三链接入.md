# 驾驶 / 转运站 / 培训台账 接入自动评分 —— 实施交付说明

- 日期：2026-09-04

- 目标应用：`server` 规则引擎；前端零改动（评分列表动态读类别扣分上限）。

- 关联：`07-接入评分方案-驾驶转运培训.md`、`04-默认扣分配置表.md`。

***

## 0. 最终口径（2026-09-04 拍板）

| 项                          | 默认分值            | 扣分对象     | 传导                |
| -------------------------- | --------------- | -------- | ----------------- |
| HSE教育培训（培训台账 缺少/资料不完整）     | 每人/每份 **1** 分   | 培训人本人    | 不传导上级             |
| 现场管理-驾驶员管理（三检/灯牌/灯具/监控/消防） | 每项每 **1** 次 1 分 | 乡镇作业中心经理 | 传导（supervisor）    |
| 现场管理-转运站管理（台账/标识/用电/消防/物品） | 每项每 **1** 次 1 分 | 乡镇作业中心经理 | 传导（area\_team→经理） |

- 三种均以**页面「扣分规则库」可自定义**，不在代码写死（`rule.deduct_score` 默认 1）。

- 三条链均**直进自动评分**（纳入 `AUTO_DEDUCTION_ADAPTERS` 门面），与网格/三违一致。

## 2. 各适配器口径速览

- **培训**：读 `hse_training_ledger_monthly`（month=YYYY-MM），每 trainer 一条，`rawScore=(missing_count+incomplete_count)×unit`，扣 trainer 本人；trainer 无 id/非考核对象 → skipped。

- **驾驶**：读 `driver_monthly`（month、is\_deleted=FALSE），5 子项计数；每驾驶员的 `personnel_id → supervisor(经理)`，聚合到经理 target；`rawScore=Σ(项次×unit)`；无 personnel/无经理/经理非考核对象 → skipped。

- **转运**：读 `transfer_station_check`（check\_date ∈ 当月、is\_deleted=FALSE），5 子项（标识=sign\_*4 汇总、消防=fire\_*3 汇总，补三列）；`area_team` 在 `v_employee_org_full` 匹配「乡镇作业中心经理」→ 经理 target；无片区/无经理 → skipped。

## 3. 引擎复用（零新增机制）

- 维度列/类别钳制：引擎统一 `applyCap`，驾驶/转运/培训并入各自类别上限（驾驶20/转运10/培训30）。

- 幂等落库 `createDeductionWriter`：月度模式，`deductKey=适配器:cycleId:employeeId`（驾驶/转运=经理，培训=本人）。

- 传导=直接把 intent 的 `targetId` 指向经理 target，天然落经理名下，无需额外传导代码。

## 4. 运行前置（在你有库的环境执行，顺序）

1. `node server/migrate-transfer-5subitems.js`（转运站补列）
2. `node server/migrate-rule-new-sources.js`（三规则就绪）
3. `node server/migrate-category-deduct-target.js`（类别上限补扣分对象列）
4. 重启后端；重跑当月「自动评分」即可看到 驾驶/转运/培训 三条链落库。

## 5. 需要注意 / 待你确认

- **驾驶传导机制（2026-09-04 修订）**：不再用上级 supervisor 关系，改为**按驾驶员所属作业中心(department) 匹配该中心「乡镇作业中心经理」考核对象**（职位判断），严格"只能是乡镇经理"。
  真库验证：13 个作业中心 12 个精确命中——大曹→孙建栋、张大庄→靳洪刚、宁城→张万恒、保店→杨清华、杜集→张卫新、刘营伍→张和祥、长官→张华平、相衙→李振恒、柴胡店→王臣祥、大柳→谢俊章、时集→郭志强、**环卫→刘菲**；**津城街道作业中心无乡镇经理目标 → 该中心驾驶员扣分 skipped**。

- 环卫作业中心存在乡镇作业中心经理（刘菲/韩晓亮），按其同逻辑传导给刘菲等；津城无乡镇作业中心经理考核对象，需补建目标后才会扣分（当前为空则安全跳过）。

- 驾驶`personnel_id`为空或 `supervisor` 非「乡镇作业中心经理」的驾驶员 → 该条 skipped，不计分（不背锅）。若存在较多这类数据，需先补齐人员/上下级映射。

- 转运站 `area_team`（片区名）必须与 `v_employee_org_full.org_name` 能匹配上「乡镇作业中心经理」，匹配不到整月 skipped。**这是转运站传导生效的唯一前提**——请核对片区名与组织名是否一致。

- 分值目前统一用规则 `deduct_score`（默认1）；若后期要「缺少」「资料不完整」分别配分，需拆成两条独立规则（当前合并为一条，token 内先沿用统一分）。

- 本机无真实库，未做端到端跑数自测；已保证语法与逻辑遵循既有 engine/适配器契约。

## 6. 驾驶「只能是乡镇经理」传导 —— 修订记录（追加自 08）

- 时间：2026-09-04

- 变化：driverMonthlyAdapter 传导目标由「直属上级 supervisor」改为「按 department(所属作业中心) 匹配该中心职位=乡镇作业中心经理的考核对象」。

- 依据：真库 v\_employee\_org\_full 中驾驶员 supervisor 多为"垃圾收运/转运车驾驶员(班组长)"，并非经理；而每个乡镇作业中心考核对象内恰有一位乡镇作业中心经理，用它作为传导目标是正确且完整的。

- 新增函数 `findTownManagerForDept(depart, cycleId)`：先 org\_name 精确，再 `LIKE '%'||dept` 兜底。

- 环卫=刘菲(乡镇作业中心经理)可传导；津城无乡镇经理 → skipped，留待补建目标。
