## 3. 实施方案（复用现有"台账导入 + 引擎适配器"两套成熟模式，不新造）

### 3.1.1 样例表格「专项活动台帐」（已核，2026-09-04）

来源：`7月乡镇作业中心经理月度考核结果.xlsx` → sheet「专项活动台帐」。

```
R1: 岗位 | 姓名 | "三违"专项活动 | 轮值安全员 | 交通安全危险因素识别清单 | 扣分
R2: 序号 | 所属乡镇
R3:  1   宁城街道  乡镇主管  张万恒   √  √  √   0
R4:  2   津城街道  乡镇主管   /      √  √  √   0
...
R14: 12   时集镇   乡镇主管  郭志强   √  √  √   0
```

- 每行 = 一个被考核对象（本表为「乡镇主管」=二级网格长/乡镇作业中心经理）。

- 三个活动项打「√」=已开展；否则视为未开展。表格自带「扣分」列（当月实际扣分）。

- 工作表名「专项活动台帐」；同一工作簿还有 考核总结/月度培训台账/三违照片/月度安全生产检查表/三检表/周例会/隐患 各表 —— 只取「专项活动台帐」。

### 3.1 数据表（新建）

`hse_safety_culture_monthly`（月度安全文化建设台账），字段映射自实施例：

- `month` CHAR(7) YYYY-MM

- `level` VARCHAR —— 岗位：乡镇主管=二级网格长(乡镇作业中心经理) / 管理员=三级网格长

- `dept` VARCHAR —— 所属乡镇/作业中心（表 2 列「所属乡镇」）

- `name` VARCHAR —— 被考核对象姓名（表 3 列「姓名」）

- `employee_id` INT NULL —— 匹配到的考核对象员工 id（按 name+dept+level 匹配 v\_employee\_org\_full）

- `act_three_violation` SMALLINT —— "三违"专项活动 是否开展（√=1/0）

- `act_duty_safety` SMALLINT —— 轮值安全员 是否开展（√=1/0）

- `act_traffic_risk` SMALLINT —— 交通安全危险因素识别清单 是否开展（√=1/0）

- `manual_deduct` NUMERIC —— 表格「扣分」列（人工填，>0 优先采用）

- `is_deleted` BOOL 默认 false

- 唯一键 `(month, level, name)`，全量覆盖按 month+level 先清后插，保留 is\_deleted 审计

### 3.3 规则 + 适配器（复用评分引擎）

- **规则**：自动扣分沿用 `SAFE001`(?)/新建 `SAFE_AUTO`，`category='安全文化建设'`、`adapter_key='safety_culture'`、`deduct_type='fixed'`（按次）、**每项 10 分/次**（用户定），`max_deduct=20`（引擎钳制）。

- **扣分逻辑（挑起两源，优先人工）**：

  1. 表格 `manual_deduct`>0 → 直接采用该行扣分（人工填的数值优先）；
  2. 否则按开展列：三个活动项任一「非 √（未开展）」→ 每未开展 1 项 = 10 分/次，`rawScore = 未开展项数 × 10`。

- **扣分对象**：按行 `level` 决定 —— 乡镇主管→二级网格长(乡镇作业中心经理)，管理员→三级网格长；`employee_id` 由导入时按 `name+dept+level` 在 v\_employee\_org\_full 匹配回填，`name+dept` 无法唯一命中或非考核对象 → 该行 skipped。

- `buildDeductKey`：月度模式 `safety-culture:cycleId:employeeId`。引擎 `engine.js` 注册 `safety_culture` + 加入 `AUTO_DEDUCTION_ADAPTERS`。
