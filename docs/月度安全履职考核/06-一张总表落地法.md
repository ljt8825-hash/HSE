# 一张总表落地法（简化方案）

- 日期：2026-09-04

- 目标：把「自定义考核项 / 扣分项 / 分值 / 封顶 / 扣谁」全部收进一个页面一张表，零硬编码。

- 目标应用：`apps/web-naive`（Naive UI），复用 vben 既有组件，不自定义页面、不造轮子。

***

## 一、结论先行：系统已几乎零硬编码

| 要自定义的东西   | 现状                                        | 结论  |
| --------- | ----------------------------------------- | --- |
| 考核项（类别）   | 存 `hse_assessment_category_limit` 表，可增删改  | 不写死 |
| 扣分项（考核内容） | 全量保存 `rule_items` jsonb，可逐行增删改            | 不写死 |
| 每项扣几分     | `rule_items[].deductScore` 可改             | 不写死 |
| 封顶多少分     | `max_deduct` 可改                           | 不写死 |
| 类别字典      | `/categories` 从规则表 `DISTINCT category` 现查 | 不写死 |
| 评分维度列     | 读「类别扣分上限」动态生成                             | 不写死 |

唯一前端硬编码：`scoring.vue` 里的 `DEFAULT_CATEGORIES`（仅决定首次打开默认显示哪些列，非逻辑写死）。

## 二、唯一缺口：缺「扣分对象（扣谁）」

用户扣分逻辑含一层链路：**驾驶员 / 转运站 扣分 → 传导给所属乡镇作业中心经理**；培训 / 三违 → 扣本人。
但现有「类别扣分上限」表**没有"扣谁"这个字段**，所以这张总表不完整。

## 三、最简落地法：在现有表加一列

不新建页面。直接在现有【扣分规则库】→【类别扣分上限】这张 NDataTable 上加一列「扣分对象」，
下表为最终形态（✓=已有，＋=本次新增）：

| 列         | 用途                | 现状     |
| --------- | ----------------- | ------ |
| 类别（考核项）   | 自定义考核项名           | ✓ 可增删改 |
| 扣分上限（分）   | 该类当月封顶            | ✓ 可改   |
| **扣分对象**  | 扣本人 / 传导到乡镇作业中心经理 | ＋ 新增   |
| 规则名称（扣分项） | 该类扣分项 + 每项分值 + 启用 | ✓ 可增删改 |
| 排序 / 操作   | 拖拽排序、删除           | ✓      |

## 四、改动清单（最小集）

1. **后端**：`hse_assessment_category_limit` 表新增 `deduct_target` 字段（值如 `self` 本人 / `manager` 传导到乡镇作业中心经理），
   `GET/POST /limits` 读写该字段。
2. **前端**：`assessment-rule/index.vue` 的 `catColumns` 加「扣分对象」下拉列（NSelect，三级取值，可输入自定义）。

## 五、扣分对象取值（已拍板）

三级取值，NSelect 支持 `tag` + `filterable` 自动补全：

| 取值    | 含义                  | 用于                    |
| ----- | ------------------- | --------------------- |
| `本人`  | 扣在考核对象本人（二级/三级网格长）  | 安全文化建设、HSE教育培训、三违管理   |
| `经理`  | 传导到所属乡镇作业中心经理       | 现场管理-驾驶员管理、现场管理-转运站管理 |
| `自定义` | 自由输入其它扣分对象（如某专项管理员） | 备扩展                   |

## 六、分步实施计划

### 第 1 步：后端加字段（先通数据）

- `hse_assessment_category_limit` 表新增 `deduct_target`（文本，取值 `self` / `manager` / 自定义），
  `GET /limits` 读出、`POST /limits` 全量保存。

- 无迁移破坏：已有行默认 `self`（本人）。

### 第 2 步：前端一张总表

- `assessment-rule.ts` 的类型加 `deductTarget`。

- `assessment-rule/index.vue` 的「类别扣分上限」NDataTable 加「扣分对象」列（NSelect 三级）。

### 第 3 步：传导打通（关键）

- 评分时读取每个类别的 `deduct_target`：

  - `self` → 扣本人（现状即本人，无变化）；

  - `manager` / 自定义 → 走 `chain_transmission` 通道，把该类别扣分计入所属乡镇作业中心经理名下。

### 第 4 步：清理默认列硬编码

- 可选：`scoring.vue` 的 `DEFAULT_CATEGORIES` 改为首次直接取全类别，彻底去写死。

### 第 5 步：自测 + 文档

- 后端单测 / 前端 typecheck+build；交付执行总结归档。

## 七、边界遵守

- 只改 `web-naive` 与 assessment 相关后端，不动 `web-antd`、不动登录、不动其它模块路由。
