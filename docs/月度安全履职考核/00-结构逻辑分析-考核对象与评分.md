## 3. 「考核对象」逻辑（targets.vue + 后端）

### 前端（web-naive `views/hse/assessment-monthly/targets.vue`）

- 顶部周期下拉（`getAssessmentCycleList` page\_size=100，默认取首条）。

- 筛选区：乡镇（12 乡镇作业中心+环卫）、岗位（乡镇作业中心经理/管理员/预留公园负责人）、状态（pending/scored/reviewed/frozen）、姓名/工号 keyword（透传 `getAssessmentTargetList`）。

- 操作：导出隐藏；**同步对象**（`syncAssessmentTargets`）→ 自动纳入/移除；**添加对象**（弹窗逗号分隔 employee\_ids，`addAssessmentTargets`）；**单条/批量移除**（`removeAssessmentTarget`）。

- 列：姓名/工号/岗位/乡镇/网格级别/状态/总分/等级/乡镇排名/总排名/操作。

### 后端（server/routes/hse-assessment-monthly.js，路径前缀 `/hse/assessment-monthly`）

- 核心端点：

  - `GET /cycles/:id/targets`：分页列表，支持 township/position/status/keyword/grid\_level/服务端排序。

  - `POST /cycles/:id/targets/sync`：**考核对象同步引擎**。

  - `POST /cycles/:id/targets`：手动添加（employee\_ids）。

  - `DELETE /targets/:id`：移除（软删除）。

  - `GET /cycles/:id/targets/:targetId/deductions`：对象扣分明细。

- **同步白名单 SQL 逻辑**（关键）：
  从视图 `v_employee_org_full` 取 `relation_status='active'` 且满足任一：

  1. 岗位 = `乡镇作业中心经理`；
  2. 岗位 = `管理员` 且 `org_type='town_center'`；
  3. 员工存在于 `grid_areas.personnel_id`（网格长）；
  4. （TODO）市政绿化作业中心公园负责人，花名册录入后追加分支。

  - **反向清理**：已存在但不再命中白名单的对象物理删除（覆盖白名单从宽→窄）。

  - 乡镇名为 `hse_org_unit(org_type='town_center')` 的 org\_name（沿 org\_path 最长匹配），否则回退 `v.org_name`。

  - 同步后回写 cycle.target\_count 并写审计日志（SYNC/TARGET）。

## 4. 「自动评分」逻辑（scoring.vue + 后端评分引擎）

### 前端（web-naive `views/hse/assessment-monthly/scoring.vue`）

- 顶部：周期下拉 + \[增加列]/\[删除列]（按「类别扣分上限」动态增减维度列，localStorage 持久化）+ \[导出] \[刷新进度] \[执行评分]。

- 评分结果列表：默认筛 `grid_level='二级网格长,三级网格长'`，`sort_by=score_total desc`。

- 动态维度列表头 `类别（最大扣分 分）`，单元格取 `row.categoryDeductions[category]` 的有效扣分合计。

- 操作列「查看」→ 抽屉展示该对象扣分明细（细化到规则名称/类别）。

- 导出 xlsx：序号/姓名/岗位/乡镇/网格级别/扣分类型/扣分规则名称。

- 执行评分后轮询 `getScoringProgress`（3s）判停。

### 后端（评分引擎）

- 关键端点：`POST /scoring/execute`（执行）、`GET /scoring/progress/:cycleId`、`POST /scoring/recalculate`、`GET /cycles/:cycleId/export-scoring`。

- 引擎：`server/services/assessmentScoringEngine.js`；事件源：`assessmentEventService`（消费 三违/事故/培训/网格/隐患 事件）+ 定时 `assessmentScheduler`。

- 规则引擎四层：考核模板 → 考核指标 → 考核检查项 → 扣分规则库；扣分方式 fixed/cumulative/detail/tiered。

- **类别扣分上限**在有效分聚合层强制（`categoryCap`），非原始分生成处；分级映射 A/B/C/D；

- 生效分算法（后端 `sumDeductionsByCategory`）：pending 用 suggested\_score；approved/adjusted 用 confirmed\_score；过滤 rejected 与 is\_deleted。

- 事件幂等：`hse_assessment_event_log.event_type+event_key` 唯一，防重复扣分。

## 5. 现状盘点与差异（需用户确认）

> 重要：目标页面在 web-naive **并非空页**。

- `views/hse/assessment-monthly/` 下 `index.vue / targets.vue / scoring.vue / cycles.vue / deduction-review.vue / freeze.vue / excel.vue` 已由「阶段06B-3」迁移建好，前端大多已完成取数与交互链路。

- `server/routes/hse-assessment-monthly.js`（2986 行）后端接口已齐备，含评分引擎接入。

### 因此「做出来」需要先明确差额目标，常见方向：

1. **验收/补差**：对照 web-antd 基线核对 web-naive 两页的功能等价性（列、筛选、排序、导入导出、操作闭环），修复已迁移页的缺口。
2. **新增能力**：如考核对象——更友好的按姓名/部门选择器（目前为 raw employee\_ids 逗号输入）；自动评分——维度列默认集、导出列、批量落库等。
3. **仅适配**：若上一轮工作实际在 `web-antd` 完成（阶段 06B 合同来源是 web-antd），需确认是否把该能力在本轮平移到 `web-naive`。

### 与既有记忆的差异（按用户要求如实指出）

- 项目记忆里「驾驶员管理」等前端改动与应用目标是 `web-antd`；但本任务与 AGENTS.md/00 计划明确目标应用是 `web-naive`（Naive UI）。**两者并存**，需确认本轮以 `web-naive` 为准（需求点 6 已声明 naive，据此本轮应落在 web-naive）。

- 约束文档要求：未获任务书授权不得改动 `web-antd`、`server`、SQL、后端接口；「考核对象/自动评分」当前若仅需前端构建，则符合「不动后端」边界。
