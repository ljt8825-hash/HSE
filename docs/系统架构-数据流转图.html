🧭 HSE 安全环保管理系统 · 数据流转架构图

一个保洁公司的安全管理系统：手机上报 → 飞书登记 → 后台搬运 → 正式账本 → 电脑查看
📱 手机端🗂 飞书多维表格🏗 后端搬运 🗄 公司数据库💻 电脑端看板🤖 AI 辅助
① 手机端 H5 现场巡查填报
使用人：保洁员 / 网格长 / 乡镇作业中心经理 / 公司管理（分级角色）
  • 拍现场照片 → 判断是不是「三违」
  • 是三违：从 20 条三违行为库中选一条
  • 选违章人员 + 填措施 / 罚款 → 提交
手机提交，把记录写进飞书表格
② 飞书多维表格 临时登记本
放在飞书云上（不在本电脑），手机端把第一手记录先记在这
  • 主台账：《H5员工日常不安全行为台账》
  • 记录：违章人姓名 / 违章行为 / 现场照片 / 整改后照片 / 检查人 / 措施与罚款
  • 身份表：《网格长信息台账》决定手机端谁能登录
后台定时 / 手动拉取（单向，只搬不反向）
③ 后端搬运工 server 大脑
电脑网页「背后」干活的程序，负责把飞书数据翻译并搬进正式库
  • 对照「字段翻译表」，把飞书栏目 → 数据库正式栏目
  • 写进《网格巡查记录》+ 一张对账映射表
搬入正式账本
④ 公司数据库 PostgreSQL 正式大账本
所有电脑端看到 / 统计 / 考核的数据，都来源于这里
  • 数据写进来才供查询、统计、考核
  • 巡查人归属、网格归属两个关键字段不许被覆盖
被前端「点单」→ 查询出账
⑤ 电脑端安全看板 管理橱窗
使用人：安全管理员 / 经理，在电脑上查看、统计、考核
  • 安全总览、三违管理、网格长巡查台账
  • 人员 / 培训 / 考核 / 风险 / 报表等 14 组菜单
五步链路 → 电脑端产出的主要功能（界面视角）
①手机填报
保洁员/网格长现场拍照上报三违，数据从这出发，是整条链路的源头
②飞书登记
第一手记录暂存飞书多维表格，带照片、措施、检查人，随时可手工维护
③后台搬运
字段翻译 + 自动同步，规范、防重复、防误删地把数据搬进正式库
④⑤看板统计
电脑端安全看板读取正式库：三违统计、网格台账、月度考核、报表
⚙️ 搬运时的四条铁律（系统专门锁死，保障数据不乱）
  • 方向唯一：飞书 → 数据库，只许搬进来；数据库改回飞书是禁止的。
  • 防重复：用「飞书记录编号 + 文件编号」当唯一指纹，同一笔不会搬两遍。
  • 防误删：飞书删掉的记录，正式库不跟着删，只做统计标记。
  • 关键字段不许动：巡查人归属、网格归属由正式库说了算，搬运时绝不覆盖。
🤖 附：AI 智能分析（本系统独有的亮点）

• 电脑端「安全总览 → AI 智能分析」可调用后端 AI（可用本地离线模型）做统计分析和生成管理建议。

• 定了人机边界：AI 只当参谋出建议；定责任、扣分罚款、改考核结果这类决定，必须由人工审核拍板。

• AI 不可用时，页面自动降级为只显示统计数据，不会整页报错。

📖 一次完整的故事（从现场到报表）
  1. 乡镇作业中心经理小张在现场发现保洁员老李作业不规范（三违）
  2. 2用手机 H5 拍下照片，勾选「三违」、选「作业不规范」、选违章人老李、填措施，点提交
  3. 3这条记录连同照片先存进飞书《H5员工日常不安全行为台账》
  4. 4后端搬运工从飞书把它抄回公司数据库的《网格巡查记录》
  5. 5安全管理员在电脑端「现场管理 → 三违管理 / 网格台账」看到正式记录，做统计、扣分、整改
  6. 6需整改的通过微信推送提醒责任乡镇 / 接收人去处理，处理完补传整改后照片，形成闭环
术语对照：前端=网页界面 · 后端/接口=网页背后的程序和「点单入口」· 数据库=正式账本 · 三重=三层分工（接单→转单→干活）
