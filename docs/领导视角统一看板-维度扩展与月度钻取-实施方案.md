# 领导视角统一看板 · 维度扩展与月度钻取 · 实施方案

> 版本：v1.1 ｜ 日期：2026-09-27 ｜ 归属对话：当前会话
> 前置：已有「领导视角统一看板」（`/overview/leader-dashboard`，M1/M2 已交付），本方案为对它的**增强改造**。
> 状态：**v1.1 已含 5 项前置确认结果（第四节已闭合），待用户授权 P1 身份链写后进入实施**。

---

## 一、背景与目标

现有看板链路为「作业中心 → 乡镇 → 角色分组 → 人员明细」，维度 8 项（事故/三违/巡查/考核/培训/应急/保险/超龄），仅按「年度」筛选。

本次要做三件事：

1. **扩维度**：环卫线由 8 项调整为 **10 项**（去保险/超龄，增驾驶员/风险/隐患/转运站）。
2. **加月度**：乡镇/公园从「年度汇总」升级为「**历年累计 + 逐月趋势表**」；经理（/公园管理员）支持「个人 + 辖区」双口径，并可下钻到**某月明细**。
3. **纳入园林**：新增「市政园林作业中心 → 4 公园（3 有管理员，1 暂不需要）」这一条线，公园用**独立 8 项维度**。

**公园线维度（8 项）**：事故、风险、隐患、巡查、三违、培训、应急演练、考核。（无驾驶员、转运站两环卫专属项；「网格长巡查」在公园侧改为「公园安全巡查」，主体是公园管理员）

## 五、技术方案设计

### 5.1 组织树变更（migration，需授权）

- 新组织类型：`org_type` 增枚举 `park`（公园）。
- 变更节点（具体化）：
  - `UPDATE hse_org_unit SET org_name='市政园林作业中心' WHERE id=20`（org_code=CENTER-LH 保留）。
  - 建 4 个 `park` 节点，挂 parent=20 之下：康宁湖公园 / 中心公园 / 福宁河公园 / 新河公园（湿地）——`org_type='park'`、`level=3`、`status='active'`。
- 公园管理员关联（身份链写，独立授权）：
  - `employee` 新建 6 人（孙小霞/郑玉红/杨立卫→新河公园；王晓燕/丁新霞→康宁湖公园；孙海清→中心公园），`roster_department='市政园林作业中心'`、`roster_position='管理员'`。
  - `employee_assignment` 关联 `org_unit_id=公园id` + `position_id=POS-ADMIN(1395)`；手机号按用户提供录入（郑玉红疑点待复核）。
  - 福宁河公园：不建人、不建岗。
- 前端作业中心卡片文案由「下辖 N 个乡镇作业中心」改为按 center 类型区分（园林→「下辖 N 个公园」）。

### 5.2 维度集与归因层扩展

- 维度集按 center 类型驱动：环卫 10 项 / 园林 8 项（前端 `MODULES` 改为按 center 动态生成）。
- 归因层新增 4 类：
  - 驾驶员（复合）→ 驾驶人员数=`roster_position='司机'` 在职人数；驾驶证记分=`license_demerit_records`(employee_id)；车辆检查=`vehicle_inspection_records`(employee_id)；驾驶员检查=`hse_driver_inspection_records`(employee_id)；违章=`driver_violation`+`driver_three_violation`(employee_id)——均经 `v_employee_org_full` 反推（复用现 a/c 通道）。
  - 隐患 → `finder_id`/`responsible_id` 经 `v_employee_org_full` 反推（复用 c 通道）。
  - 风险 → `responsible_person_id` 反推，缺失时 `area/responsible_dept` 文本对齐（复用 b 通道）。
  - 转运站 → `area_team` 长前缀匹配（复用 b 通道）。
- 保险/超龄：**彻底移除**（乡镇卡片与作业中心级均下线，见四.5）。

### 5.3 后端接口设计（草案，Phase 2 冻结）

修改 2 个、新增 3~4 个（均只读，权限沿用 `admin/safety_manager`）：

| 端点 | 类型 | 说明 |
|---|---|---|
| `GET /centers/:id/towns` | 改 | summary 换新维度集（按 center 类型 10/8）；累计算法「历年累计」 |
| `GET /centers/:id/towns/:id/trend` | 新 | 该乡镇/公园逐月趋势矩阵（维度 × 月） |
| `GET /towns/:id/managers` | 新 | 该乡镇经理（公园=管理员）列表，每人带 employeeId |
| `GET /managers/:employeeId/overview?townId=` | 新 | 经理双口径：辖区累计 + 个人累计 |
| `GET /managers/:employeeId/month-detail?townId=&month=` | 新 | 某月各维度明细（辖区 + 个人） |

> 具体字段结构、累计算法（是否含当前年未满月）、趋势月份范围（数据最早月 ~ 当前月）在 Phase 2 冻结。

### 5.4 前端改造

- `api/hse/leader-dashboard.ts`：类型扩展 + 新端点封装。
- `views/hse/leader-dashboard/index.vue`：
  - `MODULES` 由静态 8 项改为按 center 类型动态（环卫10 / 园林8）。
  - 乡镇页：顶部「历年累计」概览卡（10/8 格）+「逐月趋势表」+「经理入口」卡片。
  - 经理页（新视图层）：**双卡并排**（辖区累计 + 个人累计），下方两套逐月趋势；月选择器 → 选中月展示「各维度明细」。
  - 公园线：复用同视图，维度 8 项、人员为管理员。
- 路由：沿用 `/overview/leader-dashboard`（authority `admin/safety_manager`），不新增菜单。

## 八、验收标准

- 环卫线：点乡镇 → 10 项历年累计正确 + 逐月趋势表对齐；点经理 → 双卡（辖区/个人）正确；选月 → 当月各维度明细正确。

- 全链路只读无副作用；`vue-tsc`/jest 零新增错误；生产放行后 5876 实时复验与开发一致。
