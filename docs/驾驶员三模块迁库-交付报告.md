# 驾驶员三模块 内存→数据库 持久化 · 交付报告

**日期**：2026-09-04
**范围**：`site-mgmt.js` 下三个曾为「纯内存存储、重启即丢」的模块
**目标**：数据落 PostgreSQL，重启后端不丢失；前端 API 契约**零改动**

---

## 一、背景

诊断结论（见《交通安全档案-数据未存储-根因诊断.md》）：
- `/driver-assessments`（交通安全档案）、`/driver-violations`（驾驶员违章）、`/driver-monthly`（驾驶员月度考核）此前全部读写进程内数组 `memoryStores.*`，**数据库无对应表**。
- 后端进程重启（如 2026-09-04 08:38）即清空内存 → 用户录入的数据蒸发。
- 本次获授权后三模块一并迁 DB。

## 二、交付内容

| # | 文件 | 动作 | 说明 |
|---|---|---|---|
| 1 | `server/scripts/_migrate_driver_modules_to_db.js` | 新增 | 幂等迁移脚本：建 3 张表 + 从运行中 5800 内存接口拉取存量导入 |
| 2 | `server/routes/site-mgmt.js` | 修改 | `formatDriverMonthlyRow` 补 personnelId 与 5 个新列映射；15 个端点（3 模块 × GET列表/GET详情/POST/PUT/DELETE）改为 **DB 优先、内存降级** 双模式 |
| 3 | 前端 `web-naive` | 无改动 | API 契约、字段名、响应结构完全不变 |

### 建表（三张，snake_case 落库、camelCase 出参）

- **`driver_assessment`**：交通安全档案（archive_no/name/id_card/license_type/department/vehicle_no/assessment_date/assessment_result/assessment_level/assessment_type/control_measures/status/expiry_date/phone/remark…）
- **`driver_violation`**：驾驶员违章（name/plate_no/violation_time/violation_location/violation_type/violation_desc/demerit_points/fine_amount/handle_status/handle_method/handle_result…）
- **`driver_monthly`**：驾驶员月度考核（month/name/department/**personnel_id**/安全驾驶等旧评分子段保留 + **three_check_management/lamp_dirty/lamp_failure/safety_monitor/fire_management** 2026-09 新增 5 列）

> 旧内存字段一律保留为列（如 safety_score/assessment_level），避免历史数据丢失；新前端已不展示评分列，仅存档。

### 端点改造范式（沿用同文件 grid 模块先例）

1. `initMemoryData()` 仍执行（不破坏其它内存模块）；
2. 三模块 GET/POST/PUT/DELETE 一律走 `pool.query`，命中返回 DB 数据；
3. 列表端点保留原分页/筛选语义：assessments 支持 keyword/department/archiveYear；violations 支持 keyword/handleStatus/violationType；monthly 支持 keyword/department/month/assessmentLevel；
4. 写操作保留 `auditLog` 审计；
5. 删除为软删（`is_deleted=true`），与前端一致；
6. DB 查询异常时 catch 内回退内存数组（双模式容错，与 grid 模块一致）。

## 六、⚠️ 用户必做：重启后端 5800

- 当前 5800 仍运行**旧代码（内存模式）**，改动不生效。
- **请手动重启 5800 后端进程**：停掉旧进程 → 重新 `node app.js`。
- 重启后三模块自动走 DB，历史数据（44 档案 + 3 月度考核）在页面可见、可编辑、可持久。
- ⚠️ 重启**之前**请勿再在页面上新增/修改这三模块数据——那会写入旧内存、重启即丢，且不会出现在 DB（DB 是迁移时点的快照）。

## 七、遗留风险与建议

1. `site-mgmt.js` 仍有内存模块未迁：违章违规（非驾驶员类）、消防器材等（此前统计「内存模式」字样遍布 21 个路由文件，为系统性历史欠账）。如需根治，建议后续按同样范式分批迁移。
2. 迁移脚本为一次性工具，已留档于 `server/scripts/_migrate_driver_modules_to_db.js`，可复查。
