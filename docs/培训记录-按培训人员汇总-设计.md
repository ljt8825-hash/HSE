# 培训记录页面改造设计（按培训人员汇总）

> 状态：待评审
> 关联模块：二级菜单「培训记录」（`/training/records` → `views/training/ledger/index.vue`，导入 `module=ledger`）

## 一、需求（已与用户确认）

将二级菜单「培训记录」页面改造为**按培训人员（培训人）汇总**的形态，表头从左到右为：

| 姓名     | 部门     | 培训日期   | 应培训人数  | 实际培训人数 | 缺少人数   | 操作     |
| ------ | ------ | ------ | ------ | ------ | ------ | ------ |
| <br /> | <br /> | <br /> | <br /> | <br /> | <br /> | <br /> |

确认要点：

1. **姓名**取三级菜单「员工档案」表（`v_employee_org_full`）中的姓名；**部门**为其所属部门。
2. 培训人员 = 员工档案中的 乡镇作业中心经理 / 管理员，以及安环管理部、环卫作业中心、生产管理部等各部门管理人员（按岗位/部门筛选）。
3. **只统计培训人员情况**，不把一线员工被培训情况作为主行口径；页面以「培训人员」为一行。
4. 应培训人数 / 实际培训人数 / 缺少人数均**系统自动统计**；培训日期按**月度周期**汇总。

## 二、现状与数据缺口（实查）

* `training_records` 共 82 条，`personnel_id=0`、`employee_id=0`（全都未关联员工主数据）；`trainer` 为自由文本讲师名；`name/dept/position` 均为自由文本。

* 员工档案 `v_employee_org_full`：1311 名在职。乡镇作业中心经理 13 人、管理员 49 人；部门（安环管理部/生产管理部/人力综合部等）人员若干。

* `department` 表 `headcount=0`、`manager_id=null`、`safety_manager_id=null`（编制数/负责人均未落库）→ **不能依赖 headcount，应培训人数按「所辖单位在职员工数」动态统计**。

* `hse_assessment_cycle` 有 `cycle_name / assessment_year / assessment_month / status`，可复用作月份筛选。

* 已用组织路径前缀法验证口径可行（如乡镇作业中心经理所辖作业中心在职员工 49\~167 人）。

## 三、目标口径（计算规则）

一条汇总行 = 一名培训人员 × 一个考核月度（默认当前进行中周期，可选其他月）。

**培训人员清单**（来源：员工档案 `v_employee_org_full`，需 `is_current=true` 且未删除）：

* `position_name IN ('乡镇作业中心经理','管理员','环卫作业中心片区长','网格长')`

* **或** `org_type = 'department'`（安环管理部、生产管理部、人力综合部等职能部门管理/办公人员）

**应培训人数** = 该培训人员所辖组织单位内的在职在册员工数：

```
应培训人数 =
  COUNT(in-service employees WHERE s.org_path = tp.org_path
        OR s.org_path LIKE tp.org_path || '/%')
```

> tp.org\_path 即培训人员自身组织路径；前缀匹配即覆盖其管理范围内的下属部门/班组。

**实际培训人数** = 该培训人员当月实际组织培训覆盖的人数：

```
实际培训人数 =
  COUNT(training_records WHERE trainer_employee_id = 培训人员.id
        AND training_date ∈ 所选月份)
```

> 依赖迁移新增的 `trainer_employee_id` 落键。

**缺少人数** = `应培训人数 - 实际培训人数`（可能为负数或 0，统一按数值显示；不硬性截断）。

**培训日期**列 = 所选考核月度的周期标识（如 `2026-08`）。

## 四、数据库迁移（`docs`/`server/sql` 提供可执行 SQL）

1. `training_records` 新增培训人员外键：

   ```sql
   ALTER TABLE training_records ADD COLUMN IF NOT EXISTS trainer_employee_id BIGINT;
   -- 回填：trainer 字段与员工档案唯一姓名匹配，命中写 trainer_employee_id（复用现有 resolveTrainingPersonId 思路）
   ```
2. 建轻量配置视图 `v_training_personnel`（不落库，动态来自员工档案）：

   ```sql
   CREATE OR REPLACE VIEW v_training_personnel AS
   SELECT employee_id AS id, name, position_name, org_unit_id, org_name AS dept_name,
          org_type, org_path
   FROM v_employee_org_full
   WHERE is_deleted = false AND is_current = true
     AND (position_name IN ('乡镇作业中心经理','管理员','环卫作业中心片区长','网格长')
          OR org_type = 'department');
   ```
3. `training_records` 建索引：`idx_training_records_trainer_emp ON training_records(trainer_employee_id)`。

> 说明：应培训人数为动态统计，不落汇总表；如需人工调整编制可在后续加 `headcount_override` 字段，本期不做。

## 五、后端接口（`server/routes/training.js` 内新增，不改路由文件）

* `GET /api/training/personnel-summary?month=YYYY-MM` → 每培训人员一行：`{ employeeId, name, department, month, expectedCount, actualCount, missingCount }`。

  * 内部：查 `v_training_personnel`；应培训人数用上述组织路径 COUNT；实际培训人数用 `trainer_employee_id` 按月经 COUNT；缺少数 = 应-实际。

* `GET /api/training/personnel/{employeeId}/records?month=YYYY-MM` → 该培训人员当月实际培训明细（底层 training\_records，分页），供「操作→查看详情」。

* 保留并复用现有 `training_records` 增删改/导入/附件接口，作为明细维护入口（汇总导入后自动刷新）。

## 六、前端改造（`views/training/ledger/index.vue`）

* 主表 `columns` 替换为：姓名(员工档案)、部门、培训日期(月度)、应培训人数、实际培训人数、缺少人数、操作。

* 顶部新增**考核月度**筛选（复用 `getAssessmentCycles`/周期数据，默认当前进行中周期）。

* 「操作」列 = 「查看详情」→ 抽屉展示该培训人员本月实际培训明细（可编辑/删除/附件，保留原有新增记录能力，**不削减现有功能**）。

* 「导入」按钮保留（`module=ledger`），导入明细后 `@refresh` 刷新汇总。导入映射增加 `培训人员 ID`（`trainer_employee_id`）与姓名员工档案校验。
