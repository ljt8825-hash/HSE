### 1.2 坐标来源说明

- 数据源：用户提供的 `康宁湖.osm`（OpenStreetMap 导出）。
  - relation `9600468`（`natural=water` / `water=pond` / `multipolygon`）
  - 外环 `way 531453474`（湖泊主体轮廓）
  - 内岛 `way 690888532`（湖心小岛）—— `KangningLakePolygon` 接口仅支持单环，暂忽略内岛镂空，不影响整体轮廓。
- 坐标系修正（**关键风险点**）：OSM 原始坐标为 **WGS-84**，而高德地图 JS API v2.0 使用 **GCJ-02 国测局加密坐标系**。若直接套用 WGS-84 会导致湖泊整体偏移。生成脚本对全部顶点执行标准 WGS-84→GCJ-02 偏移算法（含 `outOfChina` 判定、经纬度偏导转换），保证与既有 GCJ-02 内联坐标（转运站 / 设施 / 公园 / 乡镇边界）严格一致。
- 文件头注释已更新，标注「根据康宁湖 OSM 数据提取坐标、已做 WGS-84→GCJ-02 转换」。

### 1.3 校验

- 顶点数 66 ≥ 4（满足提示词「≥4 顶点」要求）。
- 首尾顶点闭合：`[116.790544, 37.625374]` … `[116.79088, 37.625255]` … 末点回到 `[116.790544, 37.625374]`。
- 仅修改 `kangning-lake.ts`，未触碰任何受保护文件。

| 道路等级 | 颜色 | 粗细 | 数量 |
|----------|------|------|------|
| 国道 | `#FFD700` | 5 | **135** |

> 数量与源 `123.geojson` 同名校验完全吻合（motorway/trunk→国道、primary/secondary→省道、tertiary→县道、unclassified/service/track→乡道/穿村道路；已剔除 `residential`/`construction`/`footway`/`*_link` 等密集或无关类别）。

### 2.3 生成规则（避免 2 点直路被丢弃）

- 对每条 `MultiLineString` 取**最长 segment** → 转 GCJ-02 → 超过 20 顶点抽稀（decimate）→ 仅有 2 顶点时**插入中点**补足至 ≥3 顶点 → 入表。
- 每条道路 `path` 均 ≥3 顶点（满足提示词要求）。
- 保留导出 `ROAD_LEGEND` / `NINGJIN_CENTER` / `TOWNSHIP_CENTERS` / `TOWNSHIP_NAMES` / `getFallbackCoords` **完全不变**（红线合规）。
