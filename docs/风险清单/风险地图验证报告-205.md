### 1.2 关键结论：报告-204 的统计数字**正确**，无需修正

提示词-205 审查认为报告-204 误报为 660、实际应为 666。经严格核验，**报告-204 的 660 是准确的道路条数**，'666' 是把非道路的 `cls:` 也计入造成的计数假象。

**核验方法与证据**（基于 `risk-map-data.ts` 当前 2073 行）：

1. **道路实体计数（权威）**：全文件 `id: 'R...'` 路网条目 = **660**（道路是唯一带 `id` 的实体，图例不含 `id`）。
2. **区块内 `cls:` 计数**：`ROAD_NETWORK_DATA` 块（L21–L2004）内 `cls:` 分布 = 乡道 223 / 县道 174 / 国道 135 / 省道 109 / 穿村道路 19 = **660**，与 `id` 计数完全一致。
3. **'666' 的来源**：对全文件 `cls:` 做 grep 得到 666，是因为额外计入了 **2 类非道路 `cls:`**：
   - L11：`RoadData` 接口的 TypeScript 联合类型声明 `cls: '国道' | '省道' | '县道' | '乡道' | '穿村道路';`（1 处，非道路）
   - L2006–L2010：`ROAD_LEGEND` 图例数组（5 处，每条带 `cls:` 用于图例配色，非道路）
   - 合计 = 660 道路 + 1 接口声明 + 5 图例 = **666**。

> 因此：**报告-204 §2.2 的 660 与代码实际道路条数一致**，属于正确值；'666' 是把接口类型与图例误当道路统计的结果。本报告§1.1 对比表"经核验实际代码"列即采用权威的 660。

### 1.3 处置

- 未修改 `risk-map-data.ts` 的道路数据（遵守提示词-205 §4.2"不要修改道路数据本身"）。

## 七、附：提示词-205 审查问题 #3（道路名称）说明（非强制任务，留作参考）

提示词-205 审查表问题 #3 指出"道路名称全部为'县道-996204566'格式，缺少真实道路名称"。补充说明：

- **命名规则已按源数据最优处理**：生成脚本对 `123.geojson` 中**有真实名称的道路保留其 OSM 名称**（如 `京岚线`、`滨德高速` 等已以真实名呈现）；对 **OSM 未命名的道路**回退为"等级-OSM ID"（如 `县道-996204566`）作为稳定唯一标识。
- 源 `123.geojson` 共 1488 要素，**仅约 165 个带 `name`**，且多为高速/国道骨干路，绝大多数县道/乡道/穿村道路在 OSM 中本就无名。
- **可行性**：在无外部路名对照表的前提下，给 660 条道路"补全真实中文路名"需凭空编造，反而降低数据可信度。提示词-205 未提供路名来源、亦未将其列为正式任务（任务仅一/二/三），故本次**未做批量改名**。
- **如需补全**：请提供"OSM way ID → 真实路名"对照表（或带 `name` 的更新版 GeoJSON），可据此仅替换 `name` 字段（接口结构不变，属红线条目"道路名称"允许范围）。
