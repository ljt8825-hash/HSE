## 二、任务一：修复 InfoWindow 关闭按钮（❌号问题）

### 2.1 修改要求

在 `openHover` 和 `openPopup` 两个函数中，创建 InfoWindow 时设置 `closeButton: false`，隐藏右上角的 X 关闭按钮。

**openHover 修改**：
```js
// 修改前
hoverInfoWindow = new AMapGlobal.InfoWindow({ offset: new AMapGlobal.Pixel(0, -10) });
// 修改后
hoverInfoWindow = new AMapGlobal.InfoWindow({
  offset: new AMapGlobal.Pixel(0, -10),
  closeButton: false,
  showShadow: false,
});
```

**openPopup 修改**：
```js
// 修改前
clickInfoWindow = new AMapGlobal.InfoWindow({});
// 修改后
clickInfoWindow = new AMapGlobal.InfoWindow({
  closeButton: false,
  showShadow: false,
});
```

> 注意：`showShadow: false` 可选，用于去除气泡阴影，使悬浮提示更轻量。

## 三、任务二：修复公园/康宁湖鼠标事件不触发

### 3.1 根因

公园 Polygon zIndex=5，低于县道(6)、省道(8)、国道(10)、转运路线(12)，高德地图中高 zIndex 覆盖物优先接收鼠标事件，导致道路线条遮挡了公园区域。

### 3.2 修改要求

1. **提高公园/康宁湖 Polygon 的 zIndex**：将公园多边形的 `zIndex` 从 5 提升到 **20**（高于所有道路和转运路线），确保公园区域优先接收鼠标事件
2. 乡镇边界 Polygon 也检查 zIndex：当前乡镇边界是虚线（strokeWeight=1，strokeOpacity=0.35），填充 fillOpacity=0.04，zIndex 应该设为 **15**（高于道路但低于公园，因为公园交互更重要），确保乡镇边界 hover 也不被道路遮挡
3. **保留道路 Polyline 的 zIndex 不变**（国道10/省道8/县道6/乡道4/穿村4），道路是线条要素，zIndex 调整不影响面要素的事件接收（当面要素 zIndex 高于线要素时）

### 3.3 额外优化

- 给公园 Polygon 添加 `bubble: true` 属性，确保事件不被阻断
- 康宁湖 Polygon 同样设置 zIndex=20 和 bubble:true

## 四、任务三：基于道路名称的风险点智能坐标匹配

### 4.1 背景

当前 61 条风险点坐标全部为哈希兜底（策略5）占位，定位不准确。但经分析数据库 `location` 字段，发现以下典型值：
- `"镇驻地、沿线、村内道路（G104、S339、廊万线、宁东路等）"`
- `"G104、S339、廊万线等国道快速路"`
- `"绿化带、公园、道路两侧树木"`
- `"道路、绿化带等"`
- `"镇驻地、沿线、村内道路"`

**关键发现**：location 中包含明确的道路名称（G104国道、S339省道、廊万线、宁东路），可以利用已有的 `ROAD_NETWORK_DATA` 道路数据，将风险点吸附到对应道路上，大幅提升坐标准确性。

### 4.2 实现方案：前端智能吸附（地图加载时）

在 `loadAndRenderRisks` 函数中，对坐标为"哈希兜底"的风险点（或所有风险点），基于 `risk.location` 文本分析，尝试匹配到真实道路位置。

**匹配策略（按优先级）**：

1. **道路名称关键词匹配**：
   - 解析 `risk.location` 文本，提取道路关键词（正则匹配 `G\d+`、`S\d+`、以及道路名如"廊万线""宁东路""京岚线""滨德高速""大柳路""宁东路""宁德路"等）
   - 在 `ROAD_NETWORK_DATA` 中查找 `name` 字段包含该关键词的道路
   - 匹配到多条道路时，取距离宁津中心最近的一条
   - 匹配到道路后，取道路 path 的**中点坐标**作为风险点坐标

2. **场所类型匹配**：
   - 若 location 含"转运站"/"中转站" → 匹配到最近的转运站坐标（已有 `transferStations` 数组）
   - 若 location 含"公园"/"草坪"/"绿化带"且不含"道路" → 匹配到最近的公园/康宁湖中心
   - 若 location 含"办公室"/"仓库" → 匹配到自有设施坐标

3. **区域模糊匹配**：
   - 若 location 含乡镇名（如"大曹镇"/"柴胡店镇"等） → 匹配到对应乡镇中心坐标（已有 `TOWNSHIP_CENTERS`）
   - 通用"镇驻地/村内道路" → 匹配到宁津中心附近的乡道中点

4. **兜底**：以上均不匹配时，保留原有坐标（可能是哈希兜底，不做修改）

### 4.3 道路关键词提取规则

```javascript
function extractRoadKeywords(location) {
  const keywords = [];
  // 国道 G+数字，如 G104、G339
  const gMatch = location.match(/G(\d{3})/g);
  if (gMatch) keywords.push(...gMatch);
  // 省道 S+数字，如 S239、S339
  const sMatch = location.match(/S(\d{3})/g);
  if (sMatch) keywords.push(...sMatch);
  // 具体道路名（从 ROAD_NETWORK_DATA 中收集所有真实 name，做匹配）
  // 排除掉"县道-XXXXXX"格式的ID型名称
  return keywords;
}
```

### 4.4 实现位置

在 `map.vue` 中新增函数 `snapRiskToRoad(risk)`，在风险点加载后、创建 Marker 前调用：

```javascript
// 在 loadAndRenderRisks 中，风险点数据加载后：
allRisks.value = data.list?.map((risk: any) => {
  const snapped = snapRiskToRoad(risk);
  return { ...risk, lng: snapped.lng, lat: snapped.lat, _snapped: snapped.method };
}) || [];
```

其中 `snapRiskToRoad` 返回 `{ lng, lat, method }`，method 记录匹配方式（'road'/'station'/'park'/'facility'/'township'/'original'），用于调试。

### 4.5 匹配坐标缓存

为避免每次加载地图都重新计算，在模块级维护一个 `roadCenterCache: Map<string, [number, number]>`，缓存道路名→中点坐标的映射，首次计算后复用。

### 4.6 重要约束

- **仅前端吸附，不修改后端数据库**：坐标吸附仅在地图渲染时生效，不调用后端更新接口，原始数据不变
- 已有精确坐标的风险点（非哈希兜底的）不做吸附，直接使用原始坐标
- 吸附坐标用于地图展示（Marker位置、聚合、点击定位），风险列表和详情页仍显示原始 location 文本
- 如果一条风险点匹配到多条道路，取第一条（G道优先于S道优先于县道）

## 七、技术规范

### 7.1 zIndex 层级设计（修复后）

| 图层 | zIndex | 说明 |
|------|--------|------|
| 乡镇边界 Polygon | 15 | 提高后确保不被道路遮挡 |
| 公园/康宁湖 Polygon | 20 | 最高面要素，确保hover/click优先 |
| 国道 Polyline | 10 | 不变 |
| 省道 Polyline | 8 | 不变 |
| 转运路线 Polyline | 12 | 不变（线条不构成面覆盖） |
| 县道 Polyline | 6 | 不变 |
| 风险点/站点/设施 Marker | 100+ | 不变（点要素最高） |

### 7.2 道路名收集

在 `snapRiskToRoad` 模块初始化时，从 `ROAD_NETWORK_DATA` 中收集所有**非ID格式**的真实道路名：
```javascript
const realRoadNames = ROAD_NETWORK_DATA
  .filter(r => !r.name.match(/^(国道|省道|县道|乡道|穿村道路)-\d+$/))
  .map(r => r.name);
```
用这些名称做 location 文本的关键词匹配。
