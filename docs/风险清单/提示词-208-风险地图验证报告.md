## 一、任务一：InfoWindow 关闭按钮（❌号）修复

**根因**（已确认）：`openHover()` / `openPopup()` 创建 `AMap.InfoWindow` 时未设置 `closeButton: false`，高德默认显示右上角 ❌ 关闭按钮。

**修改位置**：`map.vue` 第 872-878 行（`openHover`）、第 891-897 行（`openPopup`）。

**最终代码**：
```js

  offset: new AMapGlobal.Pixel(0, -10),
  closeButton: false,   // 隐藏右上角 ❌

// openPopup（约 L893）
clickInfoWindow = new AMapGlobal.InfoWindow({
  closeButton: false,   // 隐藏右上角 ❌
  showShadow: false,    // 去除气泡阴影
```

## 五、★ 执行中额外修复的两个回归 Bug（关键）

> 这两个 Bug 不在提示词-208 字面清单内，但会导致任务三的"智能坐标匹配"**事实上失效**，属于必须修复的正确性缺陷，且改动严格限定在 `map.vue` 内，符合红线。

### Bug A：锚点误判为 `(0,0)`（L1077-1082）
**原代码**：
```js
const cur = [Number(risk.lng), Number(risk.lat)];
const anchor = isNaN(cur[0]) ? NINGJIN_CENTER : cur;  // ❌ Number(null)===0，非 NaN
```
**问题**：所有风险点 `lng/lat` 为 `null`，`Number(null) === 0`（不是 `NaN`），于是 `anchor` 变成 `(0,0)` 而非"宁津中心"。这导致道路/转运站/公园/乡镇的"最近"判定全部退化成"距原点(0,0)最近"，所有匹配**塌缩到最靠南的单一要素**（原实现下 station→大曹镇、park→康宁湖、township→大曹镇），**完全违背 prompt §4.2"取距离宁津中心最近"的设计意图**。

**修复后**：
```js
const cur = [Number(risk.lng), Number(risk.lat)];
const anchor = (risk.lng == null || risk.lat == null || isNaN(cur[0]) || isNaN(cur[1]))
  ? NINGJIN_CENTER : cur;
```
修复后 56 条全部以"宁津中心"为锚点，命中分布变为 station→时集镇转运站、park→新河公园、township→宁城街道（均为距中心最近），结果地理语义正确。

### Bug B：兜底坐标 `Number(null)=0` 导致 16 个 Marker 误放 (0,0)（L1172）
**原代码**：
```js
return { lng: Number(risk.lng), lat: Number(risk.lat), method: 'original' };  // ❌ null→0
```
**问题**：兜底分支把 `null` 经 `Number()` 变成 `0`，使 `allRisks` 里 16 条 original 风险点的 `lng/lat` 由 `null` 变为 `0`。原渲染逻辑 `if (lng == null || lat == null) return` 本应跳过它们，现在 `0 != null` 不跳过，**16 个 Marker 会被堆到几内亚湾 (0,0)**。

**修复后**：
```js
return { lng: risk.lng, lat: risk.lat, method: 'original' };  // ✅ 保留原始 null
```
修复后 16 条 original 风险点保持 `null`，渲染时按原逻辑跳过（与接入吸附前行为一致）。
