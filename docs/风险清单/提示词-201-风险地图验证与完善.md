## 五、任务二：康宁湖边界数据完善

### 5.1 背景

当前 `map.vue` 中康宁湖使用 4 个边界点的简化矩形。但实际存在完整边界数据文件 `康宁湖-裁剪后.geojson`（包含 200+ 个边界顶点坐标），以及原始 OSM 数据 `康宁湖.osm`。

### 5.2 要求

1. 读取 `康宁湖-裁剪后.geojson` 文件（路径在附件中），分析其数据结构
2. 将康宁湖完整边界数据转为 TypeScript 常量，写入新建文件 `src/components/hse/kangning-lake.ts`
3. 导出常量 `KANGNING_LAKE_POLYGONS`，类型为 `{ name: string; path: [number, number][]; color: string }[]`
4. 修改 `map.vue` 的 `renderParks` 函数，康宁湖区域使用完整边界数据替代当前简化矩形
5. 保持公园颜色不变（康宁湖西区 #2f54eb、东区 #2f54eb）

### 5.3 数据格式

GeoJSON 中康宁湖数据包含 4 个要素（2个水域 + 2个公园区域），每个要素的 `geometry.coordinates` 可能为 `Polygon` 或 `MultiPolygon` 格式。需要提取所有坐标环，合并为东/西两个区域。

## 六、任务三：风险点坐标回填脚本

### 6.1 背景

当前风险清单中部分风险点缺少 GPS 坐标（`lng`/`lat` 为 null），地图上无法渲染这些点。需要编写一个回填脚本，根据风险点的 `location`/`sheet` 字段智能匹配坐标。

### 6.2 回填策略

按以下优先级逐级匹配：

| 优先级 | 策略 | 说明 |
|--------|------|------|
| 1 | 转运站精确匹配 | `location` 包含转运站名称 → 使用该转运站坐标 |
| 2 | 自有设施匹配 | `location` 包含"办公室"/"仓库" → 使用对应坐标 |
| 3 | 公园范围匹配 | `location` 包含公园名称 → 使用公园中心坐标 |
| 4 | 乡镇模糊匹配 | `location`/`sheet` 包含乡镇名 → 使用乡镇中心坐标（`TOWNSHIP_CENTERS`）+ 微小偏移 |
| 5 | 哈希分配 | 以上均不匹配 → 按 `id` 确定性哈希分配到一个乡镇中心 |

### 6.3 脚本要求

1. 新建 `scripts/backfill-risk-coords.js`（Node.js 脚本）
2. 读取数据库 `risk_sources` 表，查询 `lng IS NULL OR lat IS NULL` 的记录
3. 按上述策略匹配坐标，输出 SQL UPDATE 语句（不直接执行）
4. 生成回填报告：匹配成功/失败数量、各策略匹配数、未匹配记录列表
5. 脚本需支持 `--dry-run` 参数（默认启用），仅当 `--execute` 时才执行 UPDATE

### 6.4 数据库连接

- 参考项目现有 `knexfile.js` 或 `server/db.js` 中的数据库配置
- 表名：`risk_sources`
- 字段：`id`, `name`, `type`, `level`, `location`, `lng`, `lat`, `area`, `sheet`

## 七、任务四：地图性能优化

### 7.1 当前问题

风险点数量较多时（78条），每个风险点都创建独立的 `AMap.Marker` 和 `InfoWindow`，可能导致首屏渲染缓慢。

### 7.2 优化要求

1. 风险点图层使用**点聚合**（`AMap.MarkerClusterer`）：需要在地图 SDK 加载时增加 `AMap.MarkerClusterer` 插件
2. 聚合样式：按风险等级分色（一级红/二级橙/三级黄/四级绿），聚合数字显示在圆形内
3. 缩放级别 ≥ 15 时展开显示单个风险点，< 15 时显示聚合点
4. 如果 `AMap.MarkerClusterer` 在当前 SDK 版本不可用，则使用条件判断确保兼容
