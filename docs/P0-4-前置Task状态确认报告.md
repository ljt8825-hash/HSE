### 5.2 重复程度
两份文档**结构约 95% 相同**，逐节对照：

| 章节 | Pre-Readiness (T-1h) | Pre-Closure (T-0) | 是否重复 |

| 概述/检查时间 | §一 检查概述（含检查时间/人员） | 无独立概述节 | 部分差异 |
| Task 1 映射表 | §2.1（9 行）+ §2.2 预检查 | §1.1（9 行）+ §1.2 检查 | **逐字相同** |
| Task 2 六方签字 | §3.2 | §2.2 | **逐字相同** |
| Task 3 备份 | §4.1–4.3 | §3.1–3.3 | **逐字相同** |
| Task 4 窗口/人员 | §5.1–5.4 | §4.1–4.4 | **逐字相同** |
| 执行包冻结 | §六（10 文件 + SQL 冻结 + 工具） | §五（同） | **逐字相同** |
| 综合结论 | §七（T-1h 前置 8 项） | §六（T-0 前置 8 项） | 仅 T-1h/T-0 措辞差异 |
| 签字 | §八（3 角色，进 T-1h） | §七（3 角色，进 T-0） | 角色相同，gating 措辞差异 |

**实质问题**：两份文档检查的是**完全相同的 4 项 Task 与同一组签字**，这意味着同一组 6 方审批签字 + 3 角色 gate 签字要被收集两次，但 T-0 文档**未体现任何区别于 T-1h 的现场实时复核项**（如 DBA 确认 DB 可达、应用已停、活跃连接=0、Step 0 锁检查）。当前 T-0 gate 只是 T-1h 的复制粘贴。

### 5.3 合并/废弃建议（明确）
> **建议：合并为单一份「生产执行前手续闭环检查」文档，不保留两份完全重复的文件。**

- **推荐方案**：以 `Pre-Production-Readiness-Check.md` 为基线（已含 P0-3 禁止代签注记 + 检查概述），将 `Pre-Execution-Closure-Report.md` **降级/重构为「T-0 入场最终复核」薄文档**——仅保留真正区别于 T-1h 的现场实时项（DBA 实时确认库状态、应用已停止、活跃连接=0、Step 0 锁检查通过），**不再重复收集 4 项 Task 签字**（T-1h 已收）。
- **不推荐**：维持两份逐字重复文档 —— 会造成双签负担，并引发「签了 T-1h 是否等同 T-0」的歧义。
