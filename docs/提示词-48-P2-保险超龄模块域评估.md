## 0. 背景

审计报告（§2.7）标明保险·超龄人员模块当前状态：

| 维度 | 状态 |
|------|------|
| 数据库 | 🟡 `personnel_id` 列存在（独立 personnel 注册表），非 `employee_id` |
| 后端 formatRow | 🟡 返回 `personnel_id`/`name`，非 employee 视图 |
| 前端 API 类型 | 🔴 `insurance.ts` 无 `employeeId`/`personnelId` |
| 前端表单 | 🔴 `name` 纯文本 Input |
| 前端详情/列表 | 🔴 `name` 文本 |

**核心问题**：超龄人员数据"来源于员工档案"（代码注释），但系统中以**独立 personnel 注册表**管理（`personnel_id` 而非 `employee_id`），与"花名册为基石"的 employee 链路不同源。需先确认 `personnel_id` 与 `employee.id` 的映射关系，再决定是否纳入 EmployeeName 统一模式。

**目标**：通过代码审查 + 数据库探查，确认 insurance 模块与 employee 链路的关系，输出明确结论和修复方案（如有）。

### 1.2 后端代码审查

```bash
# 4. 确认后端 personnel 相关路由
grep -n "personnel_id\|employee_id\|personnel\|over.age" server/routes/insurance.js

# 5. 确认是否有 personnel↔employee 映射逻辑
grep -rn "personnel.*employee\|employee.*personnel" server/routes/
```

### 1.3 数据库探查

```sql
-- 6. 确认 personnel 表结构
SELECT column_name, data_type
FROM information_schema.columns
WHERE table_name IN ('over_age_personnel', 'insurance_personnel')
ORDER BY table_name, ordinal_position;

-- 7. 确认 personnel_id 与 employee.id 的关系
-- 检查 personnel 表中是否有 employee_id 或 id_card 等可关联字段
SELECT column_name, data_type
FROM information_schema.columns
WHERE table_name = 'over_age_personnel'
  AND column_name IN ('employee_id', 'id_card', 'employee_code', 'name');

-- 8. 样本数据
SELECT personnel_id, name, employee_id, id_card
FROM over_age_personnel
LIMIT 10;

-- 9. 尝试通过 name 匹配 employee 表
SELECT COUNT(*) AS match_count
FROM over_age_personnel op
JOIN employee e ON e.name = op.name AND e.is_deleted = false;
```

## 2. 判定标准

| 证据 | 指向"可与 employee 链路统一" | 指向"独立 personnel 域，不统一" |
|------|---------------------------|-------------------------------|
| personnel 表有 `employee_id` 列 | ✅ 可直接映射 | — |
| personnel 表有 `id_card` 列 | ✅ 可通过 id_card 映射 | — |
| name 可匹配 employee 表 | ✅ 可通过 name 匹配（但同名风险） | — |
| 无任何 employee 关联字段 | — | ✅ 独立域 |
| 数据来源为独立注册流程 | — | ✅ 独立域 |
| 页面有"从花名册选择"按钮 | ✅ 可切换 EmployeeSelector | — |

### 3.2 若"可统一"的修复方案（方案 A）

| 层次 | 改动 |
|------|------|
| 数据库 | 确认是否有 `employee_id` 列可映射，或需新增映射视图 |
| 后端 | `formatRow` 增 `employeeId`（通过 personnel→employee 映射查询） |
| 前端 API 类型 | `insurance.ts` 补 `employeeId?: number` |
| 前端表单 | `name` Input → `EmployeeSelector`（`@change` 同步 name） |
| 前端详情/列表 | `name` 文本 → `EmployeeName` + 文本兜底 |

### 3.3 若"独立域"的结论（方案 B）

输出明确结论：保险超龄模块不适用 EmployeeName 统一模式，EmployeeName 覆盖最终为 **7/8 模块**，保险列为"已评估-不适用"。不强行统一。
