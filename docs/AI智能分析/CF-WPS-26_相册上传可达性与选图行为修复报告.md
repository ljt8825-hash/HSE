# CF-WPS-26 「从相册上传」可达性与选图行为修复

- **诉求**（原话）：「点击"从相册上传"，默认显示照片/相册中图片。」
- **结论**：已修复并上线。Pages 部署 `7bc79267`（生产别名 `grid-mobile-cloudflare.pages.dev`）；**未动 Worker**。

## 一、平台边界（先说清楚什么改得了、什么改不了）

选图器落在哪个视图由**宿主 App**（微信 XWeb / 各浏览器 / OS）决定，网页侧唯一可控的是
`<input type="file" accept="image/*">`（无 `capture`）——线上**原本就是**这一配置，已是 Web 标准最优：

| 宿主 | 点「从相册上传」后的行为 |
|---|---|
| 安卓微信 | `accept="image/*"` → 面板通常只有「从手机相册选择」→ 直达相册 |
| iOS 微信 / iOS Safari | 固定弹「照片图库 / 拍照」面板（系统行为，网页改不了） |
| 安卓 Chrome | 弹「相机 / 文件」选择器（系统行为） |

唯一能强制跳过面板直达相册的手段 = 微信 JS-SDK `wx.chooseImage({sourceType:['album']})`，
但它要求已认证公众号 + 将 H5 域名配置为 JS 安全域名 —— `pages.dev` 无法配置，接入不了（如实说明）。

## 二、代码侧的两个真实缺口（本次修复）

1. **R1 相册通道会"消失"**：现场照片出片后，「拍现场照片 / 从相册上传」按钮组被整体收起，
   且点照片区**只会再开相机** ⇒ 拍完后想换用相册照片，无任何入口。
   修法：点照片区**重新展开按钮组**（拍照/相册二选一，用户自定来源）；提示文案同步改为
   「点击上方照片可重拍，或改从相册上传」。
2. **R2 `display:none` 的 file input 有调起兼容风险**：老版 X5/部分安卓 WebView 会拒绝调起
   `display:none` 的 file input（表现为点了没反应）。修法：4 个 file input 换 `.file-ghost`
   （1px + opacity:0 + pointer-events:none，视觉不变、保持渲染；程序化 `.click()` 与
   Playwright `setInputFiles` 均不受影响）。

「选图器只显示图片」由 `accept="image/*"` 保证（相册 input 均无 `capture`，有 `capture` 会直接开相机）。

## 三、验证（`worker/test/cfwps26-browser-e2e.mjs`，24 断言，本地 + 生产双绿）

- **静态层 15 条**：相册 input 属性最优（`accept=image/*`、无 `capture`）；4 input 全部 `.file-ghost`
  且不再 `.hidden`；照片区点击处理改为重展按钮组、不再强制开相机；整改照片步两按钮常驻（无同类缺口）。
- **浏览器层 9 条（决定性）**：
  - B2 ★ 点「从相册上传」→ **真实触发系统 filechooser**，并经 chooser 设图成功（相册通道端到端）；
  - B4 ★ 出片后点照片区 → 按钮组重新展开（R1 核心断言）；
  - B1/B3/B5 交互闭环：初始可见 → 出片收起 + 下一步出现 → 重拍后再收起、相机按钮仍可用。
- 结果：**本地 24 PASS / 0 FAIL；生产 24 PASS / 0 FAIL**。
- 回归：cfwps23 33/33（其中 1 条断言从旧契约「点照片=直接触发相机」更新为新契约
  「点照片=重展按钮组」，属行为变更的配套）、cfwps25 60/60。
- 纪律：脚本走到 view-photo 即止，**不点「下一步」** ⇒ 不产生任何巡查记录。

## 五、遗留（如实标注）

- 「点一下直接落在相册网格里」在 iOS 微信 / 系统浏览器上**做不到**（OS 面板不可编程）；
  安卓微信上面板通常只有「从手机相册选择」一项，等于一步直达。
- 若未来业务要求彻底去掉面板：需把 H5 迁到可配置 JS 安全域名的备案域名下接入微信 JS-SDK，
  属独立变更。
