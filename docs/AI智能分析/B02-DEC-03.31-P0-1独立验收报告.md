### D.4 控制器是否会把拒绝误判为成功（关键项）

**源码层**：`controllers/employeeImportV2Controller.js:16-28`

```js
function respond(req, res, r) {
  if (r == null) return res.status(500).json(error(-1, '服务无返回'));
  if (r.__t === 'json') {
    if (r.error) {                                   // ← 先判 error
      if (r.httpStatus) res.status(r.httpStatus);
      return res.json(error(r.error.code, r.error.message));
    }
    return res.json(success(r.payload, r.message));   // ← 仅在无 error 时走成功
  }
  return res.json(success(r.payload ?? null, r.message));
}
```

`r.error` 分支**先于** `success` 分支，且 `err()` 描述符形状为 `{ __t:'json', error:{code,message} }` ⇒ 必进 error 分支。

**行为层（本轮独立探针）**：以 `require.cache` 注入 stub 掉 `config/db`（`pool.query` / `pool.connect` 一经调用即抛 `FATAL_*`）、
`routes/audit`、`utils/encryption`、`middleware/upload`，走**真实 controller + 真实 service** 调用：

```

EXIT=0
```

**判定 PASS**：拒绝不会被误判为成功——`success=false`、`code=-1`、`data` 为空、`message` 含「已暂停」。
探针未触达任何数据库（stub 的 connect/query 若被调用会抛错并致 EXIT=9，实测 EXIT=0）。

> ⚠️ 但请注意 HTTP 状态码为 **200**。这是本域既有约定（`employeeImportV2Controller.js:10` 注释明示「本域所有 service 错误均不带 httpStatus，故全部 200」），
