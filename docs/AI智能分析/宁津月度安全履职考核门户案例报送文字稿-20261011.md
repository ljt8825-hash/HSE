## 二、业务场景

**业务范围**：月度安全履职考核覆盖 **6 条业务线**——**培训（HSE 教育培训）、各种专项活动、驾驶员、转运站、三违、网格巡查**，最终统一汇入月度考核评分、审核、冻结、报表。

**痛点**：6 条线台账散落在「目标职责 / 现场管理 / HSE 教育培训」多个一级菜单、十几个二级菜单；月度考核时管理员需逐菜单翻台账取数、Excel 手工汇总、人工判断扣分对象归属；现场检查数据此前靠微信群流转，考核依据滞后、口径不统一、无法追溯。

### （一）以前怎么干

1. **现场检查（H5 上线前）**：各网格长将检查的图片发到微信群，**每天约 70 张照片**；管理人员每日在群内逐张查看、检查，检查出的问题再返回人员整改。
   - 痛点：照片**无定位、无行为分类、无整改前后对照**；问题归属靠人工认领；整改结果无法核验；台账事后补录，数据不进考核系统，月度评分无据可依。
2. **月度考核（系统上线前）**：培训 / 专项活动 / 驾驶员 / 转运站 / 三违 / 网格巡查**各进各的菜单**翻台账 → Excel 手工汇总 → 人工判断扣分对象归属与分值，每周期以小时计，口径因人而异、结果反馈慢。

### （二）现在怎么干

**A. 手机端 H5（现场即采即闭环，替代微信群）**

网格长打开 H5 现场工作台：**GPS 自动定位 → 选择普通巡查 / 三违检查 → 现场拍照取证 → 从三违行为标准库（多维表格同步）直接点选违章行为 → 确认涉及人员（自动带出性别 / 年龄 / 岗位）→ 现场能整改的立即拍整改后照片闭环，不能当场整改的转「稍后整改」生成整改任务 → 责任人整改后补传整改后照片、管理人员在线复查**。

- 每条记录自带**定位、行为分类、整改前后对照照片**，现场一次录入即结构化落入多维表格主台账（「H5 员工日常不安全行为台账」17 列），再经系统台账通道汇入巡查台账、供月度考核取数；链路单向不可逆，系统侧反向写入外部台账恒禁用（链路现状详见第四章 4）；
- 管理人员从「每天逐张看 70 张照片」变为「后台按条件筛选 + 抽查审核 + 处理待办」；「我的整改 / 整改任务」实时可查，问题发现、派发、整改、复查**全程留痕可追溯**；
- 三级角色分流：公司管理 / 乡镇作业中心经理 / 管理员（手机号登录，身份来自人员台账）。

**B. PC 门户（月度安全履职考核 · 门户，一个入口管全月）**

选考核周期 → 按岗位 Tab（乡镇作业中心经理 / 管理员）查看**类别扣分上限卡片**（上限 / 规则数 / 扣分对象）→ 一键进入 **9 个台账镜像**（与各模块原页面数据同源双向联动，杜绝双口径）→ **自动评分 → 扣分审核 → 结果冻结 → Excel 导入导出**全流程入口集中；**扣分规则库**（active 13 条，单一事实源）自动取数传导扣分，人工只做审核与冻结。

**C. 6 条线月度考核「以前 / 现在」**

| 业务线 | 以前怎么干 | 现在怎么干 |
|--------|------------|------------|
| **培训** | 纸质签到、Excel 逐人手工汇总；「应培训 / 实际参训 / 缺少人员 / 资料不完整 / 考核分数」五类口径人工核对，资料归档分散 | 培训计划 / 培训记录 / 证书管理全线上；培训记录按人月度汇总五项口径一目了然；**AI 识图（OCR）**扫签到表、培训资料自动生成月度台账；月度考核直接同源取数 |
| **各种专项活动** | 《专项活动台帐》Excel 逐项人工统计「开展 / 未开展」，扣分人工数格子 | 导入专项活动台帐后**自动识别当月活动列**（安全生产月、三违专项活动等按表头动态识别），「未开展项 × 单位分值」自动扣分进评分引擎，无台账自动满分 |
| **驾驶员** | 三检表（发车前检查）完成情况手工汇总；违章线下登记、月终人工评等级 | 驾驶员考核 / 违章 / 月度考核三页联动；「同步花名册人员」一键生成考核对象；三检表按人逐月归集；等级自动汇总、扣分悬浮明细逐笔下钻 |
| **转运站** | 转运站检查记录 Excel 汇总、月度续报手工复制 | 转运站管理台账支持导入预检 / 确认、**续月**、批量、导出；检查数据自动进月度考核取数 |
| **三违** | 微信群照片 + 人工认领归属；整改无法核验 | 三违候选（AI 识别候选、人工确认）→ 记录 → 分析 → 台账 → 管理考核全链条；**未按时整改自动扣分**（责任网格长优先、违章人直接上级兜底，1 分 / 起），明细分毫不差可下钻 |
| **网格巡查** | 纸质记录、事后补录，台账不进考核系统 | 巡查管理 / 巡查台账 / 待归属 / 已归属四页闭环；未巡查自动扣分（gridUncheckedDeductionService）；台账当月数千条可筛选、可编辑、可导入导出 |

**适用环节**：现场数据采集闭环 + 月度考核全流程（取数、评分、审核、冻结、报表）。

### 4. 手机端 H5（`grid-mobile-cloudflare`，Cloudflare 公网部署）

- 页面：登录（手机号 + 姓名拼音密码，身份来自人员身份台账，三级角色：公司管理 / 乡镇作业中心经理 / 管理员）→ 工作台（我的检查 / 待整改 / 待复查 / 待办）→ 开始巡查（GPS 定位）→ 拍照取证（canvas 压缩）→ 分类 → 三违行为选择（行为标准库）→ 人员选择（两级：管理 / 人员，自动补性别年龄岗位）→ 处置 / 转交 / 确认 → 整改（补传整改后照片）→ 完成 → 记录列表 / 详情。
- 提交字段白名单对齐主台账 17 列（序号 / 片区班组 / 网格等级 / 日期 / 违章人员姓名 / 性别 / 年龄 / 项目采取措施 / 违章行为 / 整改后照片 / 司龄 / 检查人姓名 / 违章照片 / 车辆类型 / 描述 / 备注 / 惩罚数额），未三违时违章行为 =「无三违行为」。
- 数据链路（2026-10-11 按代码与生产库核对修正）：
  1. H5 现场提交 → **飞书多维表格**主台账「H5 员工日常不安全行为台账」（base「9月台账」，17 列；照片入附件列；幂等去重靠备注 `req:` 回溯；整改后照片事后补挂）；
  2. 系统巡查台账（PostgreSQL）入账通道两条：**WPS 多维表格台账 → 单向 Pull Engine**（`wpsGridPullEngine.js`，WPS-PG-SYNC-02 冻结：幂等键 `(wps_record_id, wps_file_id)`、单事务双写、WPS 删除 ⇏ PG 删除、反向写硬锁 `POST /push` 恒 410；生产实测 2026-08 的 1724 条经此入库、同步最后更新 2026-09-11）＋**台账 Excel 导入**（2026-09 的 1504 条经导入/录入入库）；
  3. 注：H5 所写飞书主台账与 PostgreSQL 之间目前**无自动同步代码**（服务端无飞书依赖、H5 Worker 不连 PG），H5 数据汇入系统台账走「台账导出 → 导入」等通道；架构方向单向不可逆，系统侧不回写外部台账。PPT 表述避免宣称「自动同步入库」。
