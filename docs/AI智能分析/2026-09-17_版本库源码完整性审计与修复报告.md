## 一、为什么值得单独立项

`5876` 生产后端是**从工作区直接运行**的，Pages 也直接从 `_pages_deploy/` 发布。这两条发布线都不经过 git ⇒ **文件没入库不等于没上线**。反向的风险才是致命的：**线上正在依赖的东西，版本库里没有**。一旦 clone / 回滚 / 换人接手，故障在 `require`/`import` 阶段就发生，且故障点不在改动处，排查成本极高。

## 二、查出的两处缺件

### 2.1 `server/services/ai/signinCodeMap.js` —— 从未被 `git add`（成因：漏 add）

- **证据**：`server/services/ai/visionService.js:19` 有 `const { resolveTeamCode } = require('./signinCodeMap');`
- **严重性**：`visionService.js` 已随 `e6193fa` 入库、且被 5876 生产后端加载 ⇒ 线上依赖一个版本库里不存在的模块。
- **为什么规则救不了**：文件名不以 `_` 开头，`.gitignore` 从未命中它（`git check-ignore` 为空）——纯粹是漏了 `add`。
- **修复**：`3f16738`。入库前实跑验证：`node --check` 通过；`require()` 可解析并导出 4 项；三条样例符合业务口径（`DC-1` → 大曹镇乡镇作业中心/管理员（role）、`DC-01` → 大曹镇一班（class）、`CHD-2` → 柴胡店镇乡镇作业中心/转运站操作工（role））；内容无凭据/无手机号。

### 2.2 `grid-mobile-cloudflare/**/functions/_workerProxy.js` —— 被 `.gitignore` 误伤（成因：规则过宽）

- **证据**：`functions/api/[[route]].js:3` 与 `functions/wps/[[route]].js:4` 都有 `import { proxyToWorker } from '../_workerProxy.js';`
- **规则**：`.gitignore` 里全局 `_*.js`（本意是忽略 `_check_*.js` 这类一次性调试脚本）把它一起吃掉了。
- **严重性**：**已跟踪的 Pages Functions 导入了一个不在版本库里的模块**。后果是 clone / 回滚 / 换人接手后**部署不出可用的 Functions** ⇒ `/api/*` 落静态兜底 ⇒ **登录 POST 405**——与当天那次真实生产中断（发布命令带目录参数）**同症状、不同成因**。也就是说：同一个故障面在一周内被两条独立的路径命中，说明它是个真问题面而不是偶发。
- **修复**：`d1b6244`。
  - 入库两份（`pages/functions/` 与 `_pages_deploy/functions/`，实测逐字节一致）；内容为同源反代到 Worker（`DEFAULT_WORKER_ORIGIN` 兜底、CORS 白名单头透传、剥 `host`/`cookie`），无凭据。
  - `.gitignore`：两条例外规则放进**既有的**「例外：受版本控制的正式运行脚本」段落（沿用仓库原有约定，不新造机制）；回归实测 `server/_check_api.js` 仍被 `_*.js` 忽略。

## 三、把手法固化成自检工具

`tools/check-repo-source-integrity.mjs`（只读，静态分析 + `fs` 存在性判定，不执行业务代码、不连库、不发网络请求；有问题 exit 1）

**不变量**：被跟踪文件里的相对说明符，必须解析到「**也在 git 索引里**」的文件。

两项检查：
- **A 相对说明符解析**：CJS `require('.')` + ESM `import ... from '.'` / 动态 `import()` / 裸 `import '...'` 全覆盖。实测扫描 1456 个 JS、2054 处 `require` + 51 处相对 import。
- **B 交叉引用**：以 `git ls-files` 为全集，报出「被跟踪代码引用但不在索引里」的文件，并注明成因（被 gitignore 忽略 / 仅未 add）。

### 3.1 开发这个检测器时踩到的四个坑（都已写进脚本注释，避免重犯）

| # | 坑 | 表现 | 处置 |
|---|---|---|---|
| ① | **注释里的路径被当成真依赖** | 大量文件头部注释含 `require('./routes/xxx')` 或自身相对路径 ⇒ 满屏假缺件 | 扫描前剥块注释与行注释（保留了换行数以报准行号）。**与当天 E2E 里「HTML 注释含 meta refresh」是同一类误报** |
| ② | **只比对「是否被 gitignore」** | 给 `_workerProxy.js` 加了例外规则后，它从「被忽略」变成「未跟踪」，检查 B 反而报 **0**——问题依旧（文件仍不在库里） | 改为以 **git 索引**为全集；报表同时给出成因，便于对症下药 |
| ③ | **`fs.existsSync` 对目录也为真** | `require('../routes/insurance')` 先命中**目录**，被当成「已解析」却「不在索引里」⇒ 误报未入库 | 候选路径只认**文件**。修正前 62 条里 **58 条**是这类目录假阳性 |
| ④ | **预期内的例外** | `bin/*.mjs` 包装器动态 import 同包 `dist/` 构建产物（dist 由构建步骤生成，本就不入库）；`server/backups`、`_archive` 是从别处拷来的历史副本 | 前者**显式 allowlist 并写明理由**（不静默放过）；后者分组单列，不计入问题数 |
