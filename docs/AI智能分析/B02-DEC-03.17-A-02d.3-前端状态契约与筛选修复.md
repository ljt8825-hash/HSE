## 三、P1–P5 逐项修复证据

### P1：web-naive 委员会页筛选静默失效

**根因（A-02d.2 已证）**：`:497` 用 `Object.keys(STATUS_LABEL).map(v => ({ value: STATUS_LABEL[v] }))` 把**中文标签**当 option value，`:128` 再用只有 5 个中文键的 `STATUS_VALUE` 反查编码 ⇒ A-02d 新增的 `secondment`/`unpaid_leave`/`former` 三项反查得 `undefined` ⇒ 筛选条件被静默丢弃、返回全量。

**修复**（`views/objectives/committee/index.vue`）：

| 变更 | 行号（改后） |
|---|---|
| 删除本地 `STATUS_LABEL` / `STATUS_VALUE` | 原 `:65-81` 整体移除 |
| 引入模块：`COMMITTEE_STATUS_FILTER_OPTIONS` / `orgStatusLabel` / `toOrgStatusParam` | `:46-50` |
| 请求参数改为编码直传 + 未知值显式提示 | `:121-125` |
| 下拉选项改为 `:options="COMMITTEE_STATUS_FILTER_OPTIONS"` | `:499` |
| 列表/抽屉状态标签改用 `orgStatusLabel` | `:514`、`:588` |

修复后的参数传递代码：

```ts
const statusParam = toOrgStatusParam(personnelSearch.status);
if (personnelSearch.status && !statusParam) {
  message.warning(`未知的状态筛选值「${personnelSearch.status}」，已忽略该筛选条件`);
}
...
status: statusParam as EmployeeApi.OrgStatus | undefined,
```

**「不允许未知状态静默退化」的落实**：`toOrgStatusParam` 命中白名单原样返回；未命中返回 `undefined`，且调用点在返回 `undefined` 且原值非空时**必须**弹 `message.warning` —— 不再是无声丢弃。同时筛选项本身已是编码，UI 路径上不存在未命中值（测试第 5 项即锁此性质）。

**旧实现残留核查**：全仓检索 `Object.keys(STATUS_LABEL)` / `STATUS_VALUE` → 仅命中新模块的注释文字，代码零命中。

### P2：两个委员会页「返聘」编码错误

**关于 `inactive` 不设独立筛选项的设计决定**：`inactive` 与 `left` 在界面上都显示「离职」，若并列成两个下拉项，使用者无法区分二者查询口径（`left` 走用工关系、`inactive` 走任职状态原值），会制造新的静默困惑。因此 `inactive` 只参与**展示**映射，不提供筛选入口，并在两个模块内以注释固定该决定（单测 `不提供 inactive 独立筛选项` 亦锁定它）。

**关于 `former` 的只读语义**：本轮只改「怎么查、怎么显示」，`former` 仍不可写入（`WRITABLE_STATUS_CODES` 不含它，`normalizeStatus('former')→null`，后端零改动）。
