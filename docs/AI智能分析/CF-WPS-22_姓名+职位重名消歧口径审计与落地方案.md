## 一、⚠️ 首先必须纠正的一点：两个「职位」是两套词表

用户的措辞用的是**台账「分级」**的词，而重名发生在**花名册「职位」**上。两套枚举完全不同：

| 口径 | 列名 | 取值（实测） |
|---|---|---|
| 台账（68 人） | **分级** | 管理员 **51** / 乡镇作业中心经理 **11** / 公司管理 **6** |
| 花名册（1291 人） | **职位** | 乡镇保洁员 1156 / 人工班长 45 / 司机 43 / 中转站管理员 16 / **人工片区长 13** / 垃圾收运辅助工 3 / 安环专员 2 / 其余 11 种各 1 人 |

**逐人对齐（68 人实证）**：

| 台账 分级 | 花名册 职位 | 人数 |
|---|---|---|
| 管理员 | **人工班长** | 45（含郭秀梅） |
| 乡镇作业中心经理 | **人工片区长** | 11 |
| 公司管理 | 项目总经理 / 安环管理部经理 / 生产管理部经理 / 生产作业中心副经理（人工） | 4 |
| 公司管理 | 人工片区长（环卫作业中心 刘菲 / 韩晓亮） | 2 |

### ❗ 若按字面把「管理员\|乡镇作业中心经理」拿去花名册「职位」过滤

实测结果：**68 人里 62 人 0 命中 ⇒ 直接被打成 fail-closed（拿不到网格、无法巡查）**。
→ **该字面实现方式绝不可用**。脚本证据：`worker/test/cfwps22-job-disambig-audit.mjs`。

## 二、口径的正确落地方式

用户口径的**实质**是：「只有够到网格长层级的职位才纳入同名候选，非网格长（如保洁员）无权占坑」。
按实测数据，落成 **花名册职位 → 是否网格长** 的显式映射（禁用正则模糊匹配）：

| 判定 | 花名册职位 | 人数 |
|---|---|---|
| ✅ 网格长（纳入候选） | 人工班长、人工片区长、项目总经理、安环管理部经理、生产管理部经理、生产作业中心副经理（人工）、人力综合部经理、行政综合主管、作业质量管理主管 | 69 |
| ❌ 非网格长（排除） | 乡镇保洁员、司机、中转站管理员、垃圾收运辅助工、安环专员、人事专员、标准化专员、维保管理专员、库管专员、文员、会计 | 1222 |

> **为什么必须用显式白名单而不是 `/管理员/` 这类正则**：花名册里存在「**中转站管理员**」——正则会把它当网格长放行，但它是中转站岗位（68 人台账中无人持有该职位）。**未知 / 新增职位一律 fail-closed，不得默认放行。**

---

## 三、该规则能解决与不能解决什么（对 24 组重名的实测）

花名册 1291 人 = **重名 24 组 / 50 人**。按新规则拆解：

| 情形 | 组数 | 新规则效果 |
|---|---|---|
| 同名且「职位」互不相同 | 2 组 | ✅ 职位即可收敛（郭秀梅 = 乡镇保洁员 vs **人工班长**；刘建军 = 乡镇保洁员 vs **司机**） |
| 同名、职位相同、**部门不同** | 20 组 | ✅ 仍需靠 `name+dept`（职位键无区分力） |
| 同名、**职位与部门都相同** | 2 组 | ❌ 仍不可收敛：**张桂芹×2（皆刘营伍乡一班·皆乡镇保洁员）**、**孙风英×2（皆大曹镇四班·皆乡镇保洁员）** —— 二者均**不在台账 68 人内**，当前零线上影响 |

**结论**：「姓名+职位」是**新增的一道键**（当前 `phone → employee_code → name → name+dept → name+superior` 之外的补充），
其真正价值是**排除非网格长同名者**；对「同部门同名同职位」的极端重名依旧无解，仍需手机号或员工编码补列。

## 五、实现（已落地在代码，未部署）

`worker/index.js`：

| 改动 | 内容 |
|---|---|
| `mapRosterAreaRecord()` | 增读花名册「职位」→ `job` |
| `PATROL_GRID_BY` | 新增 `NAME_JOB: 'name+job'` |
| `GRID_LEADER_JOBS_DEFAULT` | 网格长白名单：花名册词表 6 项（人工班长/人工片区长/项目总经理/安环管理部经理/生产管理部经理/生产作业中心副经理（人工））+ 台账词表 2 项（管理员/乡镇作业中心经理），**精确等值匹配** |
| `gridLeaderJobs(env)` / `isGridLeaderJob()` | 白名单可由 Worker 变量 `PATROL_GRID_LEADER_JOBS` 覆盖（逗号分隔精确值；`/re/` 按正则）；职位缺失 = 非网格长 |
| `narrowDuplicateName(hits, me, env)` | **新增第一道键**：同名多行 → 先滤出网格长；恰 1 人即 `by='name+job'`；否则用网格长子集继续走部门 → 上级；**0 名网格长时保留原全集降级**（职位未维护/新职位不误杀） |

**键优先级（终版）**：`phone` → `employee_code` → 姓名唯一 → **`name+job`（网格长）** → `name+dept` → `name+superior` → fail-closed。

**关键判定语义**：① 姓名唯一的人**不做**职位过滤（保证 62/68 零回归）；② 职位键**优先于**部门键（非网格长无权占坑）；③ 绝不盲选，收敛不到唯一即 fail-closed 并回传 `roster_matches`。
