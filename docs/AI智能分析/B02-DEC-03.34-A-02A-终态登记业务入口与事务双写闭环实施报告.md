- **单事务执行顺序（已逐行核实）**
  1. 入参校验（员工ID / terminal_type / event_date 必填且格式合法）— **全部在 `pool.connect()` 之前**，非法入参零数据库交互；
  2. `const client = await pool.connect();` → `await client.query('BEGIN')`；
  3. `SELECT ... FROM employee WHERE id=$1 FOR UPDATE` → 校验 存在 / 未软删 / 关系非空 / 非终态 / 必须为「正式员工」（`isTerminalRelation` 判定，**只读 `employment_relation`，绝不读段形态反推**）；
  4. `SELECT ... FROM employee_assignment WHERE employee_id=$1 AND is_current=true AND is_deleted=false FOR UPDATE` → 必须恰好 1 条（0 条拒绝、>1 条拒绝，禁止自动补造）；
  5. 时间轴校验：登记日期不得早于当前段 `start_date`（防倒挂）；
  6. `UPDATE employee SET employment_relation=$2, leave_date=$3, updated_at=NOW() ...`（**rowCount===0 显式抛错**，防「关系未更新仍继续关段」）；
  7. `UPDATE employee_assignment SET status=$2, is_current=false, end_date=$3 ...`（**rowCount===0 显式抛错**，防「段未关」）；
  8. `INSERT INTO employee_history (...)`；
  9. `INSERT INTO sys_operation_log (...)` — **与业务写同事务提交**（非内存事件，满足审计可追溯要求）；
  10. `COMMIT`；
  11. `EMPLOYEE_RESIGNED` / `EMPLOYEE_STATUS_CHANGED` 事件在 COMMIT **之后**发布，失败仅 `console.warn`，不回滚已完成事务；
  12. `catch → ROLLBACK; throw`；`finally → client.release()`。

## 4. 后端事务流程（摘要）

```
入参校验(连接前) → connect → BEGIN
  → FOR UPDATE 锁员工 → 关系闸门(非空/非终态/必须正式员工)
  → FOR UPDATE 锁当前段(恰好1条) → 时间轴校验
  → UPDATE employee(关系+离职日期, rowCount=0抛错)
  → UPDATE employee_assignment(关段, rowCount=0抛错)
  → INSERT employee_history → INSERT sys_operation_log   [同事务]
  → COMMIT
  → 发事件(失败仅告警)
catch → ROLLBACK; throw
finally → client.release()
```

**不可发生的畸形（已用测试证明）**：关系已改/段未关、段已关/关系未改、业务成功/历史失败、事务失败却成功、并发重复登记。

## 5. 前端调用链

```
index.vue「更多」→ buildTerminateAction 判定展示 → openTerminate(row) 打开 TerminalModal
  → 选择 终态类型 + 业务事件日期 + 备注
  → handleSubmit → validateTerminateForm(本地) → terminateEmployee(buildTerminatePayload(...))
  → POST /api/hse/employee/org/terminate
  → 成功: message.success + emit('success') → index.vue onTerminateSuccess → onRefresh()(重新拉取真实数据)
  → 失败: extractTerminateError(原样展示后端 message)，保留已填内容
```

**不使用模拟数据**：成功反馈依赖后端 `code=0`；失败文案直接来自后端 `message`；前端不本地改写任何 `employment_relation`/`org_status`。

## 6. 接口契约

请求 `POST /api/hse/employee/org/terminate`：

```jsonc
{
  "employee_id": 9001,
  "terminal_type": "辞职" | "死亡" | "退休",   // 不接受「离职」等笼统词
  "event_date": "2026-11-10",                  // YYYY-MM-DD，业务事件日期，必填且显式
  "remark": "审批文号..."                        // 可选
}
```

响应（成功）：`{ code:0, success:true, data:{ employee_id, employment_relation, leave_date, assignment_id, assignment_status_code:'inactive', is_current:false, end_date, event_date } }`。
拒绝：`{ code:-4|-3|-2, message }`（HTTP 200，沿用本域约定；详见 §8 GAP-1）。

## 7. 业务规则处理

| 规则（任务书 §5） | 处理 |
|---|---|
| 已终态不可重复登记 / 不可经普通状态操作恢复 | 关系闸门 `isTerminalRelation` 拒绝，`BIZ_CONFLICT=-4` |
| 待岗/借调/停薪留职为中间态，不当终态 | `terminal_type` 仅接受 辞职/死亡/退休 |
| NULL/空/未知关系 = 待核实 | 关系为空即拒绝，不推断、不补值 |
| 软删员工不可操作 | `is_deleted` 校验拒绝 |
| 无有效任职段不自动补造 | 段数≠1 拒绝 |
| 不重新开放返聘 | 未新增任何返聘入口；`TerminalModal` 不引用 rehire |
| 不修改历史数据批量修复 | 仅单条事务写入，无批量脚本 |
| 业务事件日期必须显式 | `event_date` 入参必填，前端 `NDatePicker` 初始 `null` |
