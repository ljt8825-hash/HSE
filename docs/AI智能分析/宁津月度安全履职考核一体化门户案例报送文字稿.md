## 二、业务场景

**痛点**：月度考核涉及培训、专项活动、驾驶员、转运站、三违、网格巡查 **6 大类台账**，散落在多个一级菜单，管理员需在 5 个以上页面反复切换取数核对；现场检查数据此前靠微信群流转，考核依据滞后、口径不统一、追溯困难。

**以前怎么干**（系统上线前）：

- **各网格长将检查照片发到微信群，每天约 70 张**；管理人员每日在群内逐张查看、核对检查情况，发现的问题通过群消息返回人员整改；
- 痛点：照片**无定位、无行为分类、无整改前后对照**；问题归属靠人工认领；整改结果无法核验；台账事后补录，数据不进考核系统，无法支撑月度自动评分；
- 月度考核取数需逐页翻台账（三违/驾驶员/转运站/网格巡查/培训/专项活动各自进入）→ Excel 手工汇总 → 人工判断扣分对象归属，每周期以小时计，口径因人而异。

**现在怎么干**（系统闭环）：

1. **H5 手机端（现场即采即闭环）**：网格长打开 H5 现场工作台：**GPS 自动定位 → 普通巡查/三违检查 → 现场拍照 → 三违行为标准库（WPS 同步）选择行为 → 确认人员 → 现在整改/稍后整改 → 拍整改后照片**，形成整改闭环；检查记录带**定位、行为分类、整改前后照片**，数据单向自动进 PostgreSQL（WPS→PG→HSE），**替代微信群流转**，免人工二次录入；记录实时可查（我的整改/整改任务），管理人员仅需抽查审核。
2. **PC 门户（月度安全履职考核 · 门户）**：选考核周期 → 按岗位 Tab（乡镇作业中心经理/管理员）查看类别扣分上限卡片（上限/规则数/扣分对象）→ 一键进入 9 个台账镜像（**数据同源双向联动，杜绝双口径**）→ 自动评分 / 扣分审核 / 结果冻结 / Excel 导入导出全流程入口集中。
3. **自动评分引擎**：扣分规则库 active=13 条（含专项活动未开展 SAFE001）自动取数传导扣分，人工仅做审核与冻结。

**适用环节**：月度考核全流程（取数、评分、审核、冻结、报表）+ 现场数据采集闭环。

## 四、扣分规则库与自动评分引擎核心代码逻辑

### 1. 扣分规则库（`server/routes/hse-assessment-rule.js` + 三表结构）

**数据模型（三层）**：`hse_assessment_rule`（规则主表：`category / trigger_type / deduct_type / status / integration_status / rule_code / rule_name / source_table`）→ `hse_rule_detail`（子项：`detail_name / deduct_score / unit / detail_code`）→ `hse_rule_condition`（触发条件）。类别扣分上限独立表 `hse_assessment_category_limit`（**category + target_role 双键**，`max_deduct` 上限、`deduct_target` 扣分对象）。

**接口能力**：

- 列表：分页 + 六维筛选（类别 / 触发方式 / 扣分方式 / 状态 / 接入状态 / 关键词 ILIKE），实时返回子项数 `detail_count` 与最近执行周期编码 `last_run_cycle_code`；
- 统计：总数 / 启用数 / 各扣分方式 / 类别分布；
- 详情：主表 + 子项 + 条件三表联查；
- 新建 / 更新：**更新时整体替换子项与条件（事务）**，保证规则定义原子一致；
- 软删（`is_deleted=TRUE`）、启停（`status`）；
- **Excel/CSV/文本批量导入**：自动识别表头（正则匹配「子项名称/考核内容/子项」「扣分/分值」「单位」「编码」），逐行解析为子项，`toNum` 清洗 `￥/分/元` 字符。

### 2. 自动评分引擎（`server/services/assessmentScoringEngine.js`）

**分数口径（以扣分明细为准）**：

```text
score_auto  = max(0, 100 − Σ(有效 auto + chain_transmission 扣分明细建议分))
score_total = COALESCE(score_manual, 0) + score_auto + COALESCE(score_bonus, 0)
等级：A≥90 / B≥80 / C≥70 / D≥60 / E<60
```

**四类扣分来源**：`auto`（自动）/ `import`（导入）/ `manual`（人工）/ `chain_transmission`（责任传导）。

**规则层命中优先级**（只取最高一条生效，不叠加）：

1. `object_type='employee'` 精确绑定（员工 ID，最高优先）；
2. `grid_level` 网格等级（position 含「网格长」自动推断）；
3. `township` / `department` 组织维度；
4. `all` 全体兜底；同层内按 `priority DESC` 取大；生效期 `valid_from/valid_to` 校验；命中后 `effectiveScore = round(suggested × scale_factor)` 换算并记录 `source_detail.ruleHit`（规则 ID/名称/系数/原建议分）**全程可追溯**。

**幂等与一致性**：

- `findAutoDeduction` 按「来源表 + 来源 ID + 指标」查重，重复执行不重复扣分；
- 明细落库 `hse_assessment_deduction`（`deduction_source='auto'`、`review_status='pending'`、`current_version=1`，待人工审核）；
- 聚合评分 `hse_assessment_score`（`AUTO_TOTAL_SNAPSHOT`），审计日志 `hse_assessment_audit_log`（审计失败不阻断主流程）；
- 责任传导：`TRANSMISSION_RATIO=1.0`、`CHAIN_LEVEL=1`（仅一级传导，直属上级 100% 传导）。

**执行入口**：`POST /scoring/execute`（权限 `hse:training:create`）、`GET /scoring/progress/:cycleId`、`POST /scoring/recalculate`，支持手动重算与每日校验任务对齐两套口径。

**对考核结果的价值**：三违 / 培训 / 专项活动 / 驾驶员 / 转运站 / 网格巡查台账 → 各域生成自动扣分明细 → 引擎统一重算分数与等级 → 门户按岗位展示 → 扣分审核（`pending` 状态人工确认）→ 结果冻结。
