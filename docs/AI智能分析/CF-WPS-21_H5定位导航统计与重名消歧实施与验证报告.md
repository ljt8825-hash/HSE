### 2.1 离线逆地理编码（诉求 2）

| 文件 | 说明 |
|---|---|
| `worker/geo-ningjin-data.js` | 生成物（64KB）。宁津县 12 个乡镇/街道边界，Douglas–Peucker 简化 `tol=0.00012°`（≈13m），顶点 4068→3444；**保留全部环**（多环=外环+孔洞，判定用偶奇规则自然镂空） |
| `worker/geo-regeo.js` | `wgs84ToGcj02` / `gcj02ToWgs84` / `townOfGcj`（偶奇规则）/ `nearestTownGcj` / `regeoNingjin` / `validLatLng` / `GEO_TOWNS` |
| `worker/tools/gen-geo-ningjin.mjs` | 边界生成脚本（边界数据更新后重跑），**保留** |
| `worker/tools/verify-geo.mjs` | 简化后边界 vs 原始边界全县网格比对：**16948 一致 / 2 不一致**（皆大曹镇–保店镇交界 ~4m 级） |

**坐标系结论**：源数据 `安全看板vben/apps/web-naive/public/geojson/ningjin-boundary.geojson` 已是 GCJ-02（用 `TOWNSHIP_CENTERS` 做点-面包含测试 **11/12 命中**；未命中的津城街道中心点落在宁城街道内＝源数据自身缺陷，非坐标系问题）。浏览器 `navigator.geolocation` 返回 WGS-84，**必须先转 GCJ-02**，否则偏移 300~600m，在乡镇交界处会判错。

**接口** `GET /api/mobile/geo/regeo?lat=&lng=`（需 Session）：

| 场景 | 返回 |
|---|---|
| 县内 | `address = 宁津县+乡镇/街道`，`inCounty=true` |
| 县外 ≤30km | `宁津县境外（距X约Nkm）` |
| 更远 | `县境外` |
| 非法 / 哨兵 (0,0) | 400 `GEO_INVALID_COORD` |
| 未认证 | 401 |

**高德增强为可选**：仅当配置 `AMAP_WEB_KEY` 时才外呼补全到村级（`source:'amap'`）；未配置**绝不发起外部请求**（单测断言 `amapCalls=0`）。注意该 key **必须是「Web 服务」类型**——现有 JS API key 调 REST 端点返 `USERKEY_PLAT_NOMATCH`(10009)。

### 2.2 重名消歧（诉求 7）

`resolvePatrolGrids()` 键优先级：

```
① phone          发现花名册「手机号」列后自动生效（也可由 11 位 Session sub 自动取用）
```

## 四、重名消歧：真实数据审计（飞书源，只读）

### 4.1 数据源口径（重要）

- 线上花名册 = **飞书多维表格** base `WX9TbTqJKa7sywsgrU4cVoKdnXb` 的「花名册」表 `tbl2ZHdXX5d8R12a`，**1291 人**。
- 16 列：员工编码 / 姓名 / 所属部门 / 职位 / 性别 / 年龄 / 身份证号码 / 出生日期 / 入职日期 / **直接上级** / 用工关系状态 / 入司日期 / 离职日期 / 完整度百分比 / 负责区域（在职）/ 负责区域（离职）。
  ⇒ **有「直接上级」列，无「手机号」列**（故「手机号」键当前不生效，属为将来补列预留）。
- WPS Sheet11「员工信息维护」仅是该表的历史导入来源，**不作为线上依据**。

### 4.2 全量枚举手法

`GET /api/mobile/roster?q=` 为**包含匹配**且 `limit` 上限 200；员工编码为 8 位（形如 `00347342`，全部以 `00` 开头）→ 用**编码前缀 BFS** 逐位展开即可无损拉全 1291 行，并以接口回传的 `rosterSize` 校验覆盖率。

- 陷阱 1：`q="0"` 命中全部（所有编码都含 0）⇒ `total=1291, truncated=true`，**不能当作全量已取回**。
- 陷阱 2：不带 `q`/`area` 时接口 `scopedToSelf=true`，只回本人部门（张万恒＝4 条）；带 `q` 才是全公司检索。
