==================================================
二、阶段目标
==================================================

本阶段目标：

完成"手机端网格长巡查管理"的 Cloudflare H5 文字业务闭环：

手机 H5
→ 登录
→ 工作台
→ 开始巡查
→ 自动识别当前登录人员 employee_code
→ 选择/确认网格
→ 填写巡查问题
→ 选择问题类型
→ 填写巡查说明
→ 提交巡查记录
→ WPS 缓冲表
→ 为后续既有 WPS→PG 同步链准备数据

本阶段只解决"移动端巡查记录业务链"。

不解决 WPS Attachment 页面预览问题。

==================================================
三、照片状态冻结
==================================================

CF-WPS-12B 已正式将照片链路定义为：

PHOTO_STATUS=PENDING_EXTERNAL

禁止：

1. 再寻找未公开 Attachment API
2. 猜测 /v7/coop/dbsheet/.../attachments/upload 参数
3. 猜测 proto body
4. 猜测私有 object API
5. 接入第三方对象存储
6. 引入新的云服务器
7. 使用 Cloudflare Tunnel
8. 为解决照片问题修改 WPS 生产表结构

本阶段允许：

- 保留手机原生拍照入口 UI
- 保留照片字段模型
- 保留 Worker / API 的照片接口抽象
- 将照片上传结果明确标记为 PENDING_EXTERNAL
- 在正式提交前明确告诉用户照片链路尚未开放

但不能把"上传成功"伪装成"WPS 页面可预览"。

==================================================
四、业务范围严格限制
==================================================

只做：

"网格长巡查管理"

如果巡查过程中发现三违：

允许移动端记录：

- 是否三违
- 三违行为描述
- 涉及人员
- 必要的基础现场信息

但：

禁止重新设计三违责任链。

禁止重新实现：

- 三违责任认定
- 直接经理计算
- 扣分
- 审核
- 驳回
- 整改
- PC 端三违台账
- 现有 HSE 三违业务

三违后续业务继续交给现有 HSE / PC 系统。

本阶段不得修改现有三违业务逻辑。

==================================================
五、身份体系必须严格沿用 CF-WPS-11
==================================================

移动端业务身份：

employee_code

不是：

- WPS user_id
- 手机号
- 姓名
- 身份证号

登录方式：

手机号 + 密码

沿用 CF-WPS-11：

phone
→ WPS Sheet 14「H5移动端身份」
→ employee_code
→ 当前 Session
→ 巡查记录 employee_code

禁止重新设计登录。

禁止 SMS。

禁止微信 OAuth。

禁止 WPS OAuth 作为员工业务身份。

禁止把手机号作为业务主键。

禁止把姓名作为业务主键。

身份证号不得返回 H5。

==================================================
七、生产写入安全门
==================================================

本阶段开始涉及真实 H5 业务提交，因此：

生产 WPS 写入必须采用明确的 fail-closed 机制。

至少检查：

ALLOW_WPS_WRITE

生产目标必须显式 allowlist。

禁止前端传入并覆盖：

- inspector_employee_id
- grid_id
- attribution_status
- employee_code（不得信任前端）

其中：

employee_code 必须从 Worker Session 中取得。

前端提交的 employee_code 一律忽略。

Worker 从：

Session.sub

取得 employee_code。

==================================================
十二、提交链路
==================================================

目标：

POST H5 Worker API
→ Worker 验证 Session
→ 从 Session 获取 employee_code
→ 校验业务字段
→ WPS 正式缓冲表 create record
→ 返回 record_id / client_request_id
→ H5 显示提交成功

提交失败：

必须显示明确失败状态。

不能显示"提交成功"后后台实际失败。

==================================================
十三、幂等
==================================================

沿用 CF-WPS-10 已建立的 client_request_id 思路。

每次 H5 提交：

客户端生成唯一 client_request_id。

Worker：

- 接收
- 校验
- 传递
- 在允许的情况下执行幂等保护

不要声称已经解决高并发生产幂等问题，除非真实测试证明。

如果当前生产 Sheet 的 O(n) 扫描方式无法满足严格并发幂等：

明确记录：

IDEMPOTENCY_STATUS=LIMITED

不要虚构"100%并发幂等"。
