### 2.1 V1 有两个导入入口，必须分别甄别

| 入口 | 路由 | 服务函数 | 是否写任职段 | 是否存在复活路径 |

| JSON 批量 | `POST /api/hse/employee/employees/import`（`routes/hse-employee/import.js:20`） | `employeeImportService.js:376 importEmployees` | **否** | **否** |

`importEmployees` 通读 `:376-441`：仅 `INSERT INTO employee`，按 `employee_code` / `id_card_hash` / `phone_hash` 三条做**重复即拒绝**校验，**没有任何 `employee_assignment` 写入**。
⇒ 该入口既不能建立任职段，也不能复活终态人员（终态人员会先被重复校验挡下）。**本节点不对其加闸门**，理由与证据见 §3.3。

调用链：`routes/hse-employee-import-v2/main.js` → `controllers/employeeImportV2Controller.js` → `services/employeeImportV2Service.js:1363 batchImport` → `:898 performBatchImport`。

```

:938  for (每条 approved 的 pending) {

:946-965 员工匹配：employee_code → id_card_hash → phone_hash+name   ← 三处 SELECT 只取 id
:966-1008  新员工 INSERT / 已有员工 UPDATE（COALESCE 补缺失字段）
:1011-1019 花名册三列同步 UPDATE
:1023-1028 UPDATE employee_assignment SET is_primary=false, is_current=false, end_date=CURRENT_DATE
           WHERE employee_id=$1 AND is_current=true AND is_primary=true AND is_deleted=false  ← 无条件关段
:1030-1041 上级兜底匹配
:1049-1056 INSERT INTO employee_assignment (..., true, true, 'active', COALESCE($10, CURRENT_DATE))
:1059-1062 UPDATE employee_import_pending SET status='imported'
:1064   RELEASE SAVEPOINT sp_i
:1065 } catch → :1085 ROLLBACK TO SAVEPOINT sp_i → failedCount++ → errors.push(`第${row_num}行: ...`)
:1076   批次状态：failedCount>0 ? 'partial_completed' : 'completed'
:1083   COMMIT
```

**复活机制**：与 V1 同构。三条匹配 SQL 均 `SELECT id`（**不含关系字段**），关段 + 建段无条件 ⇒ 终态人员被复活为 `active + current + primary`。
`uk_emp_assign_primary`（B1 已证实的 partial unique index，谓词 `WHERE is_primary AND is_current AND NOT is_deleted`）对终态人员**不生效**——终态人员无 `is_current=true` 段，谓词前提不成立。

### 3.2 V2 的另一处相关缺口（未修，属 GAP）

上传/审核阶段 `matchEmployee`（`:473-494`）同样只 `SELECT id, name`，且 `:812` 命中已有员工后直接判为 **approved**（`:850` 注释「通过全部校验和匹配，保存为 approved（可直接入库）」）。
⇒ 终态人员的行**在审核页看不出异常**，直到入库才失败。本节点未改此处：改动它会改变**审核态语义**（自动审核规则），超出「最小修复」范围。记入 §9 GAP-2。

## 5. 修改文件与必要性

### 5.1 `server/services/employeeStatusDict.js`（新增共享判定出口，+19 行）

`:262 function isTerminalRelation(value)`（`:369` 导出）。

必要性：若三个入口各写一套白名单，则「终态集合」会出现 3 份副本，任一处漏改即产生绕过路径。该函数为**纯函数、零依赖**（DICT 文件本身 `require` 数为 0，无循环依赖风险），语义边界写在注释中：`null`/空串/中间态/未知值一律 `false`，仅 `TERMINAL_RELATION_VALUES` 精确命中（去首尾空白）为 `true`。

> B1 的 `checkRelationAllowsAssignment`（`ASG:390-400`）语义与本函数一致但各自实现。本轮**未改 B1 代码**（已验收、避免动已验证路径），两处共用同一个 `TERMINAL_RELATION_VALUES` 常量，不构成规则分叉。收敛为单一函数记入 §9（GAP-4，可选）。
