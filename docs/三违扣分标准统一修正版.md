## 一、修正背景

### 1.1 旧版本问题

旧版本三违扣分采用分级标准：

| 旧分级 | 扣分 |
|--------|------|
| 重大三违 | 20分/次 |
| 较大三违 | 10分/次 |
| 一般三违 | 5分/次 |
| 其他三违 | 2分/次 |

**问题**：
1. 多套规则并存（评分引擎、数据库、接口、测试数据各有一套）
2. 分级标准主观性强，执行不一致
3. 责任传导比例不统一（旧版本50%传导）

### 1.2 修正目标

- 删除重大/较大/一般/其他分级规则
- 统一为固定扣分标准
- 统一传导比例
- 确保评分引擎、数据库、接口、测试数据一致

## 二、统一扣分标准

### 2.1 个人三违扣分

| 项目 | 标准 |
|------|------|
| 扣分方式 | 固定扣分，不分等级 |
| 每次扣分 | **5分** |
| 代码常量 | `VIOLATION_DEDUCTION = 5` |
| 计算公式 | `个人扣分 = 三违次数 × 5` |

### 2.2 直属上级传导扣分

| 项目 | 标准 |
|------|------|
| 传导方式 | 直属上级一级传导 |
| 传导比例 | **100%** |
| 代码常量 | `TRANSMISSION_RATIO = 1.0` |
| 计算公式 | `传导扣分 = 个人扣分 × 100%` |

### 2.3 完整扣分示例

| 场景 | 三违次数 | 个人扣分 | 传导扣分（直属上级） |
|------|----------|----------|---------------------|
| 1次三违 | 1 | 5分 | 5分 |
| 2次三违 | 2 | 10分 | 10分 |
| 3次三违 | 3 | 15分 | 15分 |

### 3.1 评分引擎（hse-assessment-monthly.js）

```javascript
// 三违扣分统一标准（Sprint10-D-2-2-A 冻结）
const VIOLATION_DEDUCTION = 5;           // 每次三违固定扣5分（个人）
const TRANSMISSION_RATIO = 1.0;          // 直属上级传导比例100%
const CHAIN_LEVEL = 1;                   // 仅一级传导，禁止多级
```

**评分引擎三违指标计算逻辑**：

```javascript
if (metric.data_source === 'violation_records') {
  const violationsResult = await client.query(
    `SELECT count(*) as cnt
     FROM violation_records
     WHERE violator_id = $1
       AND violation_date >= $2
       AND violation_date <= $3
       AND is_deleted = FALSE`,
    [target.employee_id, cycle.start_time, cycle.end_time]
  );
  const violationCount = parseInt(violationsResult.rows[0].cnt);
  rawValue = violationCount;
  rawValueDesc = `三违${violationCount}次`;
  metricDeduction = violationCount * VIOLATION_DEDUCTION;  // 统一扣分
}
```

## 六、冻结声明

本标准自2026-07-24起冻结：

1. **三违扣分统一为5分/次**，不再区分等级
2. **传导比例统一为100%**，不再使用50%
3. **传导层级统一为1级**，禁止多级传导
4. 旧版本分级扣分代码已全部删除
5. `violation_level` 字段仅用于审计追溯，不参与扣分计算

作为后续前端开发、接口联调、正式测试的唯一依据。
