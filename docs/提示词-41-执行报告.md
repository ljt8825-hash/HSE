## 0. 执行摘要

将事故模块 `reporter`（报告人）从纯文本 `<Input>` 切换为 `<EmployeeSelector>`，与既有 `handlerId` 同模式，打通「花名册为基石」的最后一块人员字段。后端新增 `accidents.reporter_id` 列（INTEGER，FK→employee.id，可空），`formatRow/INSERT/UPDATE` 全链路支持；前端表单、详情展示同步切换为 `EmployeeName + 文本兜底`。

**与原提示词的关键偏差（已纠正，均经实勘验证）：**

| # | 提示词假设 | 实际 schema | 处理 |
|---|-----------|------------|------|
| 1 | `accidents.reporter` 为 VARCHAR 文本列，需「保留兼容」 | 表**不存在** `reporter` 列（历史 reporter 实际复用 `handler` 文本兜底） | 不新增/不自建 reporter 文本列；报告人姓名改由前端 `EmployeeName(reporterId)` 运行时解析 |
| 2 | 后端 `INSERT` 已含 `reporter` 列 | `INSERT` 列清单**无** `reporter` 列 | 仅新增 `reporter_id` 列；报告人姓名无需落文本列 |
| 3 | 校验层 `reporterId` 会透传到 handler | `validateBody` 用 zod 解析并 `req.body = parsed`，zod 默认**剥离**未知字段 → `reporterId/handlerId/reporter` 全被丢弃，导致 ID 永不入库（原 handlerId 亦因此长期静默失效） | 在 `createAccidentSchema` 显式声明 `reporter`/`handlerId`/`reporterId`（可选），使其通过校验；`updateAccidentSchema = createAccidentSchema.partial()` 自动继承 |
| 4 | 端点路径 `POST /api/hse/accidents` | 实际挂载前缀为 `/api/accidents` | 冒烟测试使用真实路径 `/api/accidents` |

> 偏差 3 是本次最重要的修复：否则即便前端发出 `reporterId`，后端也会因校验层剥离而写为 NULL，B-2 冒烟必失败。此修复同时让此前「已实现但未真正生效」的 `handlerId` 关联也真正持久化（回归验证见下）。

## 1. 任务 A：数据库迁移（✅）

新建 `server/sql/hse_accidents_reporter_id.sql`（完全幂等）：

```sql
ALTER TABLE accidents ADD COLUMN IF NOT EXISTS reporter_id INTEGER;
-- DO $$ 块内 IF NOT EXISTS 加 FK：
ALTER TABLE accidents ADD CONSTRAINT fk_accidents_reporter_employee
  FOREIGN KEY (reporter_id) REFERENCES employee(id) ON DELETE SET NULL;
CREATE INDEX IF NOT EXISTS idx_accidents_reporter_id ON accidents(reporter_id);
```
