## 2. 十、Feishu→employee 实际匹配率（本轮新增实测）

方法：飞书只读 list records → 提取 11 位手机号/18 位身份证（仅内存）→ HMAC-SHA256 → 与 PG 哈希集合等值比对。**明文一律不输出、不落盘。**

| 飞书表 | 记录 | 有效标识 | 命中在册 employee | 匹配率 | 说明 |
|---|---:|---:|---:|---:|---|
| H5移动端身份表 `tbl58t9kjyDlacSw` | 73 | 手机号 73（0 重复） | **62** | **84.9%** | 含软删全集命中 63（+1 软删员工） |
| H5花名册表 `tbl2ZHdXX5d8R12a` | 1369 | 身份证 1369（0 重复） | **1291** | **94.3%** | 命中 0 软删行 |
| H5隐患排查台账表（排查人ID） | 2 | 手机号 2 | 2（distinct 1 人） | — | 两条同一人 |

匹配缺口分析（§十要求逐项）：

| 风险项 | 实测 |
|---|---|
| 空手机号/无 phone_hash | employee 在册 2105 人无 phone_hash（61.6% 空值率）⇒ 手机号匹配覆盖率上限 = 38.4% 的员工侧 |
| 重复 phone_hash | 现役 0 冲突 |
| 员工已删除 | 身份表 1 人命中软删行（63 vs 62） |
| 员工已离职 | `employment_relationship_status` **0/3417**（列全空）⇒ 离职状态不可判 |
| 手机号变更 | 无法从现有数据检测（无变更留痕） |
| 花名册 78 人未命中 | 待核（可能是新员工未同步入 PG，或非在册人员） |

**结论**：技术匹配可行且匹配率高；但「匹配成功」≠「业务归属正确」（§十二），且员工侧手机号覆盖率仅 38.4%，手机号不能作为普适内部键。
