### DEC-A0205-01｜隐患「期限」的业务语义与来源

| 要素 | 内容 |
|---|---|
| **问题** | 「隐患应在几天内整改」这一事实从哪里来？系统当前没有任何期限事实，所有"超期"都是按默认 30 天推导的。 |
| **已知事实** | ① `hazards.deadline` **0/110**、`deadline_date` **0/110**、`deadline_days` **110/110 全 = 30**（列默认值）；② 导入白名单 8 列中**无任何期限列**；③ `hazard-rule.json` 的 `expiryRules.defaultDeadlineDays = 30`；④ 隐患页超期 50 条全部由该默认值推导；⑤ 驾驶舱超期 0 条（用 `deadline_date`，全空）；⑥ 考核 HZD-002 读 `hse_rectifications.deadline`（表 0 行）⇒ 永久 0 分。 |
| **缺失证据** | ① 原始 8 份月度台账中是否有"整改期限"列（仅 6 月原件留存，其余 7 份缺失）；② 业务上是否曾有过口头/文件规定的整改时限（分级时限？按隐患等级？）；③ 历史隐患的实际整改周期分布（`fix_date - hazard_date` 可算，但只能反映"实际"不能反映"应然"）。 |
| **影响范围** | 隐患页「超期 50」全部数字；驾驶舱超期；考核 HZD-002；预警规则；所有按"是否超期"做的排行与通报。 |

| **依赖前置** | 先补齐 7 个月份原件（否则方案 B/D 无法落地） |
| **不定会怎样** | 任何"超期"数字都不能对外；HZD-002 永久为 0；隐患页与驾驶舱的超期口径永远矛盾（0 vs 50）。 |
