> 审计对象：`hazards` 及其关联的隐患域表（B 模型 4 表、C 模型 2 表）
> 审计方式：**只读**。源代码静态检索 + 运行时路由挂载核对 + 数据库行数与内容核对。
> 目的：把「数据从哪里来」锁死到 **字段级**，区分 IMPORT / H5 / WEB / SYSTEM / EXTERNAL / HISTORY / UNKNOWN。

### 2.3 写库白名单（关键）

```js
// importShared.js:483
dbColumns: ['no','hazard_date','description','measure','checker','fixer','fix_date','remark']
```

**只有 8 列可写。** 显式排除：

| 被排除字段 | 排除理由（代码注释原文） |
|---|---|
| `status` | 「隐患生命周期状态严禁由 Excel 决定」——批量 INSERT / 逐条 INSERT / UPDATE 三条 SQL 都只按此白名单取列 |
| 其余 37 列 | **未出现在白名单中** ⇒ 结构性不可写（不是"没想到"，是"不在列清单里"） |

> 后果：**只要走这条导入链，`deadline` / `deadline_date` / `review_*` / `responsible_id` / `fixer_id` / `checker_id` / `location` / `grid_id` / `hazard_type` / `township` / 全部分类维 —— 永远写不进去。**
> 这不是数据质量问题，是**导入器能力边界**决定的。110 行的空字段分布与此白名单**逐列吻合**。
