# A02-05-02｜跨模块共性问题与架构缺口清单

> **任务定位**：把隐患域、考核域的发现，与 D0-D11 其余 10 个域的实测结果对照，
> 判断哪些问题是**系统性的**、哪些只存在于个别模块、哪些**证据不足不能外推**。
>
> 本轮只读。`CODE CHANGE = 0 / DDL = 0 / DML = 0 / CONFIG CHANGE = 0 / PRODUCTION CHANGE = 0`
>
> **分级纪律（任务书 §四）**：
> - `A 类｜已证实的跨模块问题` —— 在两个及以上业务域有独立证据
> - `B 类｜目前只在单一模块发现` —— 只有一域证据，**不得外推**
> - `C 类｜有待其他模块核实` —— 迹象存在但证据不足，登记为待核
>
> 全文不使用「考核模块需要重构」这类笼统结论；每项问题标注**性质**，性质分六类：
> `数据事实` / `数据模型` / `计算逻辑` / `页面展示` / `跨模块架构` / `业务决策`

## 1. 结论摘要

10 类候选中，**7 类为 A 类（跨模块已证实）**，**3 类为 B 类（单模块）**，
另有 **5 项 C 类待核**。

```text
A 类（跨模块已证实，≥2 域独立证据）
  ├─ ① 同一业务多套数据模型 ............ 10 域
  ├─ ③ 历史数据 / 默认值 / 真实事实混杂 ... 6 域
  ├─ ④ 页面数据源 ≠ 业务事实源 .......... 3 域
  ├─ ⑤ 指标/排名/汇总缺可靠来源 ......... 4 域
  ├─ ⑥ 无写入路径却保留历史数据 ......... 7 域
  ├─ ⑧ 统计口径多页不一致 .............. 4 域
  └─ ⑨ 跨模块关联字段为空/关系不可追溯 ... 7 域  ← 最严重、最普遍

B 类（单模块，不得外推）
  ├─ ② 导入白名单丢字段 ............... 2 域（隐患、巡查）已证 + 1 域待核（保险）
  ├─ ⑦ API 存在但页面零调用 ........... 2 域（隐患、考核）；反例：分析域 5/5 全在用
  └─ ⑩ 旧模型/硬编码并存 .............. 3 域（隐患、考核、分析页）

C 类（待核，5 项）
```

> **最重要的判断**：本系统的问题**不是"某个模块坏了"，而是"同一类结构缺陷在不同域反复出现"**。
> 其中最普遍的是 **⑨ 关联字段为空**——它在 7 个域都能量化，且直接导致 ⑤ 与 ⑧。
