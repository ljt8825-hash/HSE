# A02-03-02｜隐患整改数量统计口径审计

> 审计对象：`public.hazards` 110 行的「整改完成」事实，以及所有可能的统计口径
> 审计方式：**只读**。字段交叉矩阵 + 原始台账三方比对 + 后端 SQL 逐条核对
> 目的：回答「已整改多少、未整改多少、多少无法判定」，并说明每个数字的口径。
> CODE CHANGE = 0 / DDL = 0 / DML = 0 / CONFIG CHANGE = 0 / PRODUCTION CHANGE = 0。

---

## 1. 一句话结论

> **「已整改」在当前系统里有 4 个不同答案：60 / 69 / 97 / 66（6 月）。**
> **「未整改」有 3 个：50 / 41 / 13。**
> **没有任一字段能独立承载"已整改"，最接近事实的是 `status='closed'`=60，但它漏掉了 6 月原始台账明确写着「是」的 22 条。**
> **状态待核实 = 50 条（其中 22 条有原件证明为"已整改"、9 条状态自相矛盾、19 条确实无任何状态记录）。**

## 2. 字段级原始事实（先看数据长什么样）

| `status` | 行数 | 有 `fix_date` | 有 `fixer` | 有 `rectification` | 有 `review_result` |
|---|---:|---:|---:|---:|---:|
| `closed` | **60** | 60 | 60 | 2 | **0** |
| `discovered` | **50** | **9** | 37 | 0 | **0** |
| `processing` | 0 | — | — | — | — |
| `pending_review` | 0 | — | — | — | — |

**两条必须分开写的事实：**

## 3. 「已整改」的四个口径（逐个给 SQL 与结果）

### 口径 A｜`status = 'closed'`（系统唯一的状态口径）

```sql
SELECT count(*) FROM hazards WHERE is_deleted = false AND status = 'closed';
-- 结果：60
```

- 这是 `/api/hazards/stats` 的 `closed` 字段、前端「已关闭」卡片、总览页 `fixed`（`overview.js:33` 经 `sqlStatusClosed()`）**共同的取数**。
- 语义来源：Excel「是否整改完成 = 是」（A02-02 已证 60/60 一一对应、0 冲突）。
- **局限**：只反映"当时填了是"，不反映复查/验收（`review_result` 全 0）。

### 口径 B｜`fix_date IS NOT NULL`（有整改完成时间）

```sql
SELECT count(*) FROM hazards WHERE is_deleted = false AND fix_date IS NOT NULL;
-- 结果：69
```

- 比口径 A 多 9 条：即 4 月清明专项"有整改时间但没打勾"的 9 条。
- **语义**：有整改完成的事实，但状态未同步。
- 若业务认为"有整改时间即已整改"，则已整改 = **69**。

### 口径 C｜`fixer IS NOT NULL`（有整改责任人）

```sql
SELECT count(*) FROM hazards WHERE is_deleted = false AND fixer IS NOT NULL;
-- 结果：97
```

- **不可作为"已整改"口径**。`fixer` 只是"指派了谁整改"，13 条无整改人的行也全在 `discovered` 里。
- 但它说明：**110 条中有 97 条已明确整改责任人**，人员缺席不是主要缺口（缺口 13 条）。

### 口径 D｜原始台账「是否整改完成 = 是」（仅 6 月可验证）

```sql
-- 无法用 SQL 得到，必须读原始 Excel
-- 6月原始台账 66 行，「是否整改完成」列 66 个非空值，全部为「是」
```

- 6 月原始台账：**66/66 = 100% 标记「是」**
- 汇总表：44「是」+ 22 空
- DB：44 `closed` + 22 `discovered`

> **这是本轮最重要的口径冲突：同一批 66 条隐患，原始台账说全部已整改，系统说 22 条未整改。**

### 3.1 四个口径对照表

| 口径 | SQL / 来源 | 已整改 | 未整改 | 适用性 |
|---|---|---:|---:|---|
| **A** `status='closed'` | `hazards.status` | **60** | 50 | 系统当前唯一在用的口径；可解释、可追溯 |
| **B** `fix_date IS NOT NULL` | `hazards.fix_date` | **69** | 41 | 若改判 4 月 9 条，则 +9 |
| **C** `fixer IS NOT NULL` | `hazards.fixer` | 97 | 13 | ❌ 语义错误，只是"有责任人" |
| **D** 原始台账「是」 | 原始 Excel | **66（6月）/ 未知（其余）** | 0（6月） | 仅 6 月可验证；其余 7 个月原件缺失 |

## 8. `closed` 在本轮的正确读法（延续 A02-02，不重开结论）

| 命题 | 判定 | 依据 |
|---|---|---|
| `status='closed'` 是事实 | ✅ 是 | 值真实存在，60 行 |
| `closed` = Excel「是否整改完成=是」 | ✅ 是 | 110 行逐行比对，60「是」→60 `closed`，0 冲突 |
| `closed` = 已复查 | ❌ 否 | `review_result`/`review_date`/`reviewer_id` 全 0/60 |
| `closed` = 已验收 | ❌ 否 | `verify_date`/`verify_user` 全 0/110 |
| `closed` 经 `close()` 写入 | ❌ 否 | 60 行 `updated_at` 与 `created_at` 精确相等，`close()` 会写 `updated_at` |
| `discovered` = 未整改 | ❌ **否** | 50 条中含 22 条原件为「是」、9 条有完成时间 |
| `discovered` = 状态未回填 | ✅ 更接近 | 加工方摘要原文称「未回填状态」「待回填」 |

> **本轮不改变 A02-02 的 C1 结论（`review(pass)` 是唯一正式关闭），只是补充：**
> **`closed` 连"已整改"都不是全部（漏 22 条），更不是"已复查"。**
