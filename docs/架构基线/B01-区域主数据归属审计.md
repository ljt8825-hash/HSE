## 3. 十六、区域与组织是否混用（判定=是，三重证据）

1. **结构层**：hse_org_unit 把 12 个乡镇作业中心（town_center）作为组织节点——「谁负责管理」与「在哪里发生」合在一行。
2. **数据层**：hse_assessment_target.township 直接填组织名（作业中心/部门）；violations.township 混入 26 行组织名。
3. **语义层**：网格体系（grid_areas.grid_level 总/一/二/三级网格长）是**人的层级**，其 `area` 列又承担区域——一个组织（作业中心）→ 多个网格长 → 一个网格长管一个乡镇，组织/人员/区域三层纠缠在同一张表。

多对多关系实测佐证：hse_operation_unit（89 个作业单元）通过 org_unit_id 挂组织，location 自由文本指地点——「一个组织 → 多个作业单元 → 多个地点」的链路当前只能靠文本对齐。

## 4. 十七、H5/Feishu 区域字段（只读核验）

| 字段（飞书主台账 tbl5QiCv5Qbal044，33 字段） | 语义 |
|---|---|
| 网格等级 | 人的层级（二级/三级网格长） |

| 隐患表（tblnyMjxtxjpP08q）「隐患位置」 | 自由文本（样本含「大柳镇」） |

**回答**：Feishu 中的区域值 = **自由文本 + 组织名借用**，不是独立区域主数据；主台账甚至没有乡镇字段，区域语义完全靠「网格等级+片区|班组」和组织单位间接表达。

## 5. 十八、WPS 区域字段（只读核验）

`grid_inspection_records`（WPS Pull 目标，2069 行）：

```text
grid_id     1741/2069 填充，1741 全部命中 grid_areas（0 悬空）
grid_areas  63 行 = 网格长人员表（name=人名，grid_level=网格层级，area=乡镇文本）
township 列不存在
personnel_name 2069/2069（人名文本）
```

**回答**：WPS 线的区域语义 = `grid_id → grid_areas.area（自由文本乡镇）`；与 Feishu 的「片区|班组」**不是同一套语义**（一个挂网格长，一个挂片区文本），两者也无乡镇规范名交集校验。三系统（PG 业务表 / WPS 网格 / 飞书 H5）当前**没有统一的区域词典**。
