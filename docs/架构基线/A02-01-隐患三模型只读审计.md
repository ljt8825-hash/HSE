## 1. 一句话结论

| 模型 | 角色判定 | 判定依据（硬证据） |
|---|---|---|
| **A `hazards`** | **唯一事实来源（As-Is 生产口径）** | 110 行真实数据；`POST /api/hazards` 是唯一对外写入端点；`source_check` 见 §2.1 |
| **B `hazard_record`+3表** | **候选模型 / 未启用**（结构完整、页面已建、数据为测试夹具） | 9 行全部 `created_by=1`、`created_at=2026-07-20`、状态 `open`；`review_record` 仅 1 行 `hazard_id=99999`（不存在） |

`fixer`/`fixer_id`、`checker`/`checker_id`、`responsible_dept`/`responsible_dept_id`、`measure`/`rectification`。
→ 说明 A 表本身经历过至少一次模型演进，**新字段是叠加而非替换**。

**外键（仅 2 条，均为人员）**：`checker_id → employee SET NULL`、`fixer_id → employee SET NULL`。
`finder_id` / `responsible_id` / `corrector_id` / `reviewer_id` / `grid_id` **无外键约束**。

### 2.2 B 模型（4 表 / 42+16+18+15 列 / 合计 11 行）

| 表 | 列数 | 行数 | 说明 |
|---|---:|---:|---|
| `hazard_record` | 42 | **9** | 主表。`hazard_code` 形如 `HD-1784516666796-UK6WS`（时间戳随机码） |
| `rectification_task` | 16 | **0** | 整改任务 |
| `rectification_action` | 18 | **1** | 整改措施（`task_id=99999`，任务不存在） |
| `review_record` | 15 | **1** | 复查（`hazard_id=99999`、`task_id` 空） |

**9 行 `hazard_record` 的全部实况**：`status` 均为 `open`，`created_by=1`，`created_at=2026-07-20`。
而 `hazardRectificationService` 使用的状态词表是 `confirmed / processing / pending_review / closed`
（见 `services/hazardRectificationService.js:76,189,237,453`），**与库中 `open` 不匹配**。
→ 这 9 行**不是该服务写入的**，是更早一次造数/测试遗留。

**B 模型外键数量 = 0**。`hazard_record` **没有任何指向 `hazards` 的引用**（无 `hazard_id` 列指向 A，只有自造的 `hazard_code`）。
因此 B **不是 A 的子模型，而是一套平行模型**。

**B 模型自带闭环状态机**：`hazard_record.status`（open→confirmed→processing→pending_review→closed）
+ `review_status` + `is_closed`，与 A 的 `status` 完全独立。

### 2.3 C 模型（2 表 / 20+18 列 / 合计 0 行）

| 表 | 列数 | 行数 | 外键 |
|---|---:|---:|---|
| `hse_rectifications` | 20 | **0** | `department_id → hse_org_unit SET NULL`、`responsible_person_id → employee SET NULL` |
| `hse_reviews` | 18 | **0** | **`hazard_id → hazards RESTRICT`**、`reviewer_id → employee SET NULL` |

`hse_rectifications` 带有 `inspection_plan_id` / `task_id` / `event_id` / `plan_type` 四列 →
说明它最初是为「**计划式检查 → 整改任务 → 事件**」这一条与 A 完全不同的链路设计的。

`hse_reviews` 同时保留 `rectification_id` 与 `hazard_id` 两个关联列 →
`routes/hse-chain.js:177-188` 的注释明确记载：
> `canonical 正式键（N-02-A）：hse_reviews.hazard_id`；`legacy / Model C 兼容键：hse_reviews.rectification_id`。

→ **C 模型自身也存在「canonical 键 vs legacy 键」双轨**，且 canonical（`hazard_id`）指向的是 **A 表**。
