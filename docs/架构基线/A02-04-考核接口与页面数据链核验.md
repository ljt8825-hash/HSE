### 3.3 ★ 路由遮蔽缺陷：`/results/ranking` 永远不可达

`server/routes/hse-assessment-monthly/main.js` 注册顺序：

```js
:74  router.get('/results', ...)              // 结果列表
:75  router.get('/results/:targetId', ...)    // 单对象结果   ← 通配在前
:76  router.get('/results/ranking', ...)      // 排名          ← 被上一条吃掉
```

Express 按注册顺序匹配。请求 `GET /api/hse/assessment-monthly/results/ranking` 会**先命中 `:75`**，此时 `req.params.targetId = 'ranking'`，控制器把它当考核对象 id 去查 —— 得到「对象不存在」而非排名数据。

**双重问题：**
1. 服务端：`/results/ranking` **永久不可达**（死路由）；
2. 客户端：`api/hse/assessment-monthly.ts` 里**根本没有 `/results/ranking` 的函数**（只有 `/results`、`/results/:targetId`、`/export/results/:cycleId`），说明前端从未接过这个能力。

⇒ 这是一个「后端写了、前端没接、且写了也调不通」的三重废弃端点。

## 4. 权限模型：考核复用培训域权限码

`hse-assessment-monthly/main.js` 中所有写端点使用：

```js
requirePermission('hse:training:create')   // 新增周期/对象/扣分/评分/传导
requirePermission('hse:training:update')   // 修改周期/扣分/标准
requirePermission('hse:training:delete')   // 删除周期/对象/扣分
requirePermission('hse:training:audit')    // 审核/调整/冻结/解锁
requirePermission('hse:training:export')   // 导出
```

| 端点类别 | 数量 | 权限域 |
|---|---:|---|
| 写（create/update/delete） | 17 | **`hse:training:*`** |
| 审核类 | 6 | **`hse:training:audit`** |
| 导出 | 3 | **`hse:training:export`** |
| 读 | 12 | 仅 `authMiddleware` |

**问题：考核域的写权限完全寄生于培训域权限码。** 授予某人「培训新增」权限，即同时授予「创建考核周期、改扣分、跑评分、冻结周期」的能力。**权限边界与业务边界不一致。**
