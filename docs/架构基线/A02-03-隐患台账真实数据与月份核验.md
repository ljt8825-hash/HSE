> 审计对象：`public.hazards` 110 行 + 其原始导入文件本体
> 审计方式：**只读**。数据库精确查询 + **原始 Excel 逐行逐列比对**（本轮首次取得原件）

## 1. 一句话结论

> **110 条不是「6 月台账」，是 2–7 月共 6 个月的合并台账；其中 6 月 66 条（60%）。**
> **它们是 8 份月度原始台账 → 1 份二次加工汇总表 → 1 次导入的结果。**

## 3. 110 条的真实日期分布（六个口径必须分开）

任务书要求区分五种日期。实测如下：

| 口径 | 字段 | 实测值 | 说明 |
|---|---|---|---|
| **隐患发生/发现日期** | `hazard_date` | min **2026-02-17** / max **2026-07-10** | 来自 Excel「检查时间」 |
| **原始台账归属月份** | Excel「月份」列 | 2026-02 ~ 2026-07 | **该列未入库**，只在 Excel 中 |
| **数据导入时间** | `file_records.created_at` | **2026-08-24 23:36:10**（id=315） | 上传时点 |

## 6. 三类数据质量问题（本轮新发现）

### 6.1 隐患描述被改写 1 条 → 会破坏 `conflictKey` 判重

| 项 | 值 |
|---|---|
| 原始台账 | `柴胡店转运站卸料口平台警示标识老化` |
| 汇总表/DB | `柴胡店转运站卸料口平台**围栏**警示标识老化` |
| 影响 | 导入 `conflictKey = 'description'`（`importShared.js:463`）⇒ 同一隐患若用原始措辞重导，会被判为新行（INSERT）而非 UPDATE |

### 6.2 备注：36 条全部丢失，其中 2 条是关键业务说明

| Excel 备注值 | 条数 | DB 结果 |
|---|---:|---|
| `[含现场照片]` | 34 | `NULL`（全部丢失） |
| `不使用，收纳库房` | 1（id=154 相衙转运站高压水枪损坏） | `NULL` |
| `暂时无法整改` | 1（id=212 大曹转运站水井阀内漏） | `NULL` |
| 空 | 74 | `NULL` 或 `''`（2 行为空串） |

> **`暂时无法整改` 被丢弃的后果是实质性的**：它把"已识别但客观无法整改"与"未整改"抹平为同一状态（`discovered`）。系统此后无法区分这两类业务事实。

### 6.3 `NULL` 与空串混淆

| id | `no` | `hazard_date` | Excel 备注 | DB `remark` |
|---:|---:|---|---|---|
| 233 | 10 | 2026-07-10 | `None` | `''`（长度 0） |
| 234 | 11 | 2026-07-10 | `None` | `''`（长度 0） |

> 110 行中 `remark` 非 NULL 的只有这 2 行，且都是空串。其余 108 行为 `NULL`。
> **同一语义（无备注）在表内有两种物理表示**，任何 `WHERE remark IS NOT NULL` 都会错误命中 2 行。

### 6.4 重复隐患 1 组（跨月）

| id | `no` | `hazard_date` | `status` | `remark` |
|---:|---:|---|---|---|
| 152 | 3 | 2026-04-28 | `closed` | NULL |
| 209 | 6 | 2026-06-16 | `discovered` | NULL |

同描述 `时集转运站高压水枪损坏`，4 月与 6 月各一次。
汇总表摘要 WARN-2 已自行标注：「『时集转运站高压水枪损坏』在 4 月与 6 月重复出现，**需人工确认是否同一隐患重复填报**」。
> **本轮不裁决是否重复**（任务书禁止推断业务事实），只记录：110 行仅 109 个唯一描述，`conflictKey='description'` 下这 2 条永远是同一键。

## 8. 月份维度的可用性判定

| 用法 | 是否可行 | 依据 |
|---|---|---|
| 按业务月份统计隐患数 | ✅ **可行** | `hazard_date` 与原始「月份」110/110 一致 |
| 按源文件统计 | ❌ **不可行** | 「来源文件」列未入库，且 4 月有两个同月文件无法区分 |
| 按导入批次统计 | ⚠️ 有限 | `created_at` 只有 2 个不同值，全部同批 |
| 按"发现日 ≠ 台账月"区分 | ❌ 不可行 | 无独立"台账月"字段 |
| 追溯某行来自哪个月表 | ⚠️ 部分可行 | 仅 6 月可用原件反查；其余月份只能靠汇总表（已丢失） |

## 10. 本章判定

```text
HAZARDS ROWS                = 110
业务月份范围                 = 2026-02 ~ 2026-07（6 个月）
JUNE BUSINESS RECORDS       = 66（占 60.0%）/ 已用原始台账证实
月份归属错位                 = 0 / 110

数据链层级 =
  8 份月度原始台账（1月0/2月4/3月9/4月4/4月清明14/5月2/6月66/7月11）
    ↓ 二次加工（新增 月份/来源文件/备注 3 列，剔除 17 行模板占位）
  1 份汇总表 2026年安全生产隐患排查登记表.xlsx（8 个副本，5 个有 file_records）
    ↓ /api/import/parse → confirm（白名单 8 列）
  hazards 110 行

原始事实保留率 =
  落库 = 序号 / 隐患描述 / 整改措施 / 检查时间 / 检查人员 / 整改人员 / 整改时间（7 列，109~110/110 一致）
  丢弃 = 月份 / 来源文件（2 列，DB 无对应字段）
  间接 = 是否整改完成（→ status，60「是」→closed / 50 空→discovered）
  丢失 = 备注（36 非空 → 0 条有效值）

原件可验证边界 =
  6 月 66 条 = 可三方比对（原始台账 / 汇总表 / DB）
  其余 44 条 = 仅汇总表单层，无法回溯

月份口径可用性 =
  按 hazard_date 统计月度数 = 可用
  按源文件统计         = 不可用（列未入库）
  按导入批次统计       = 仅 1 个批次

CODE CHANGE = 0   DDL = 0   DML = 0   CONFIG CHANGE = 0   PRODUCTION CHANGE = 0
```
