## 1. 本轮最重要的三条业务理解（写在最前面）

### 1.1 本系统不是以「流程引擎」为核心设计的

```text
外部已有业务台账 / Excel / 系统数据
        ↓  数据导入（27 个模块 / 396 个文件实证）
   HSE 平台数据沉淀
        ↓  与 人员 / 组织 / 车辆 / 区域 等主数据关联
      H5 移动端
        ↓  现场数据产生 / 补充 / 更新（仅 2 个写接口）
   HSE 平台统一分析
        ↓
   考核 / 统计 / 预警 / AI
```

**「数据从哪里来」比「流程是谁发起」更重要。** 因此本文的归位依据是**数据对象与写入通道**，不是流程图。

### 1.2 隐患是「一种业务事实」，不是一条流程

`hazards`(110) 的存在方式证明了这一点：它由 **Excel 导入（10 个文件）+ Web 新建 + 风险联动生成** 三条通道写入，
并且 `hazard_source` 110/110 全部为 `daily_check` —— 即**它记录的是"某天某次检查发现了这个隐患"这一事实**，
而不是某个流程实例的状态。复查字段（`review_result/reviewer_id/review_date`）内嵌在同一行里，
且**110 行全部为 NULL**，说明系统从未真正跑过「复查流程」。

### 1.3 本系统存在「三代数据结构」并行

| 代 | 形态 | 规模 | 状态 |
|---|---|---|---|
| 第 1 代 | `t_0X_中文表名` 原始 Excel 落地层 | **48 张**（41 非空） | **代码已不在仓库**，仍有 3 张被生产统计接口读取 |
| 第 2 代 | 规范化业务表（`hazards`/`violation_records`/…） | 268 张系统表（165 非空） | **现行主体** |
| 第 3 代 | 规划模型（Risk02 14 表 / 隐患 B·C 模型 / `hse_cost_*`） | 大量 0 行表 | 结构已建、**未启用** |

> **归位工作必须同时处理这三代**，否则「迁移」会搬错对象、「统计」会读错表、「考核」会永远为 0。

## 11. 对后续 A02/A03 的 10 条硬约束（由本轮事实推导）

1. **任何统计/看板不得直读 `t_0X_*`**（现 `overview.js` 违反 2 处）。
2. **任何"总览"只允许从 D4/D3/D5 的事实表取数**，不允许从派生表（`hse_assessment_score`）反推事实。
3. **人员/组织/车辆/区域四个主数据必须先收敛再谈业务域重构**（U-01、U-03、U-04 未决前，D9/D10 无法收口）。
4. **隐患域在 A/B/C 选型前禁止任何新表/新字段**（三套已并存，再加第四套成本最高）。
5. **考核指标必须"码—表—字段"三元可追溯**，孤儿码（5 个）与 11 个零实现指标须先清理。
6. **导入是主入口，不是辅助功能**（396 文件 / 23 模块）；导入落库语义必须先修正（3 个内存模块 + 3 个不存在表）。
7. **H5 只产生 2 类事实**（巡查、三违），任何"移动端全业务"设计都与现状不符。
8. **EXTERNAL 只有 WPS 一条链**，且单向只读；飞书不在本仓库，跨系统口径必须显式声明。
9. **展示层（D11）不得新增任何写接口**。
10. **菜单重构不得早于数据域收敛**（菜单只是入口，域才是边界）。
