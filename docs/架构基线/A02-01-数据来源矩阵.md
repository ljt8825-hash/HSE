# A02-01-05｜数据来源矩阵

> 核心原则：**「数据从哪里来」比「流程是谁发起」更重要。**
> 判定要求：每一条 ✓ 必须有**代码/接口/表**证据；**不允许按「应该如此」填写**；无法确认的标 `UNKNOWN`。
> 本轮只读：CODE CHANGE = 0 / DDL = 0 / DML = 0。

---

## 1. 六类来源定义与判定标准

| 标记 | 含义 | 判定证据要求 |
|---|---|---|
| **IMPORT** | 外部台账 / Excel / 批处理导入 | 存在导入端点 或 `NATIVE_IMPORT_MODULES` 配置项 或 `file_records.module_type` 实证 |
| **H5** | 移动端现场产生/补充 | `/mobile/*` 页面调用 `POST/PUT` 且落到该表 |
| **WEB** | PC Web 端创建/维护 | 存在 `INSERT/UPDATE` 于 `services|controllers|routes` |
| **SYSTEM** | 系统计算/派生/后台任务 | 由事实表计算生成，无外部录入 |
| **EXTERNAL** | 外部系统接口 | 定时拉取/推送（当前仅 WPS 多维表） |
| **HISTORY** | 历史遗留数据（代码已不在仓库） | 有数据、有日志痕迹、**无现存写入代码** |
| **UNKNOWN** | 当前代码无法确认 | 显式列出，不猜测 |
