## 3. 月度考核页逐页比对

### 3.1 首页四张卡（`assessment-monthly/index.vue`）

| 卡片 | 显示 | DB 实际 | 一致性 |
|---|---|---|---|
| 考核周期总数 | 周期列表长度 | 15（含 1 软删，接口通常过滤为 14） | ✅ |
| 进行中周期 | `status='in_progress'` 计数 | **9** | ✅ |
| 已冻结周期 | `status='frozen'` 计数 | **0** | ✅ 数字一致 |
| 考核指标数 | `GET /metrics` 长度 | **29** | ✅ |

> 「已冻结周期 = 0」数字是对的，但**语义上是系统级缺陷的显示器**：考核体系从未产出过任何一期正式（冻结）结果。页面上所有分数都是中间态。

### 3.2 考核对象表（`targets.vue`）

列定义（`:116-119`）：

| 列 | 字段 | DB 非空率 | 页面表现 |
|---|---|---:|---|
| 总分 | `scoreTotal` ← `score_total` | 925/925（100%） | ✅ 正常显示 |
| 等级 | `grade` | 925/925（100%） | ✅ 正常显示 |
| **乡镇排名** | `rankTownship` ← `rank_township` | **0/925（0%）** | ❌ **永远空白** |
| **总排名** | `rankAll` ← `rank_all` | **0/925（0%）** | ❌ **永远空白** |

> 表格里 4 列有 2 列结构性空白。用户看到的是「总分 + 等级」但**没有任何位次信息**，而 `grade` 本身不提供位次（A 级 747 人）。
> 根因见 A02-04-02 §8：冻结门禁不可达 ⇒ `rank_*` 从未写入。

### 3.3 冻结页（`freeze.vue`）

页面提供了 `POST /freeze/cycle/:id` 按钮。点击后，后端第 34-46 行检查「未审核扣分数」，实测 14 个周期最少 3 条、最多 101 条未审核 ⇒ **必然返回 409「还有 N 个对象未完成审核，不可冻结」**。

**⇒ 冻结按钮在现有数据下 100% 失败。** 这不是 bug，是数据未审核完；但页面未提示「需要先审完 N 条」，用户会反复点击。

## 4. 分析页五端点逐项核验

`views/analysis/assessment/index.vue:55-59` 一次性并发调用 5 个端点。

### 4.1 `GET /overview`（集团考核总览）—— 混用 7 张事实表

服务实现 `hseAssessmentAnalysisService.js:77-290`，单次请求内并发 7 条独立 SQL：

| # | 事实表 | 行数 | 用途 | 风险 |
|---:|---|---:|---|---|
| 1 | `violation_records` | 2645 | 三违数/严重/一般/轻微/已关闭/待处理 | ✅ 有数据 |
| 2 | `training_records` | **19** | 培训总数/合格/不合格/均分 | ⚠️ 事实极稀 |
| 3 | **`rectification_task`** | **0** | **隐患整改 total/completed/overdue/pending/in_progress** | ❌ **恒 0** |
| 4 | `license_demerit_records` | **3** | 驾照扣分 | ⚠️ 事实极稀 |
| 5 | `employee` + `employee_assignment` + `position` | 28864（assignment） | 驾驶员人口分母 | ✅ |
| 6 | **`hse_employee_risk_snapshot`** | **0** | 风险等级分布 + 均分 | ❌ **恒 0** |
| 7 | `hse_assessment_target` | 925 | 乡镇排名 | ✅ |

**关键缺陷：`rectification_task` 是隐患 B 模型的空表。**
A02-03 已确证：`rectification_task` = 0 行，`hazard_record` = 9 行（纯造数夹具），真实隐患在 `hazards`（110 行）。
⇒ **分析页的 5 个隐患整改指标全部恒 0**，且它**从未读过 `hazards` 表**。

### 4.2 `GET /department-ranking`（部门排名）—— 数据源为空

`hseAssessmentAnalysisService.js:348` 核心取数：

```sql
COALESCE(AVG(hrs.total_score), 0) as avg_risk_score
FROM hse_employee_risk_snapshot hrs ...
```

| 检查 | 结果 |
|---|---|
| `hse_employee_risk_snapshot` 行数 | **0** |
| ⇒ `avg_risk_score` | **恒 0.00** |
| ⇒ 排名排序依据 | 全 0，排序无意义 |
| ⇒ 页面表现 | 部门列表要么为空，要么全部 0 分并列 |

**并且度量对象错了**：部门排名量的是「**风险分**」（`hse_employee_risk_snapshot.total_score`），不是「**考核分**」（`score_total`）。

### 4.3 `GET /township-ranking`（乡镇排名）—— 唯一正常

`hseAssessmentAnalysisService.js:542-696`，注释明确写着「得分 = `hse_assessment_target.score_total`（自动评分总分），按 `score_total` 降序排名」。

| 检查 | 结果 |
|---|---|
| 数据源 | `hse_assessment_target.score_total`，925 行全部非空 |
| 与月度考核页总分 | **同一字段** ✅ |
| 结论 | **这是全系统唯一一处考核分数口径一致的跨页指标** |

> 但注意：它在分析页叫「乡镇排名」，与月度考核页的「总排名」不是一回事 —— 前者是乡镇维度聚合，后者是个人位次（恒空）。

### 4.4 `GET /goals`（目标达成）—— 隐患整改率恒 0%

`hseAssessmentAnalysisService.js:809-813`：

```js
case '隐患整改率':
  actualValue = hazardTotal > 0 ? Math.round((hazardCompleted / hazardTotal) * 100) : 0;
```

`hazardTotal` / `hazardCompleted` 来自 §4.1 第 3 项的 `rectification_task` 查询 ⇒ **均为 0** ⇒ `actualValue = 0`。

| 项 | 值 |
|---|---|
| 页面目标值 | **98%**（`hseAssessmentAnalysisService.js:42` 静态定义） |
| 页面实际值 | **0%** |
| 状态 | `in_progress` |
| **隐患域真实值（按 `status='closed'`）** | **60 / 110 = 54.5%** |
| **隐患域真实值（按 `fix_date` 非空）** | **69 / 110 = 62.7%** |
| **误差** | **55~63 个百分点** |

> 同一系统，「隐患整改率」在分析页是 **0%**，在隐患域数据里是 **55%~63%**。
> 这不是精度问题，是**数据源选错表**（选了空表 B 而非事实表 A）。

### 4.5 `GET /deduction`（考核扣分明细）—— 第三套算法

`hseAssessmentAnalysisService.js:855-1000+`，**不复用 `hse_assessment_deduction`**，而是硬编码单价自算：

```sql
-- 事故
SUM(CASE a.level WHEN '轻微' THEN 3 WHEN '一般' THEN 10 WHEN '较大' THEN 20
     WHEN '重大' THEN 50 WHEN '特别重大' THEN 100 ELSE 5 END)
-- 三违
SUM(CASE vr.violation_level WHEN '严重' THEN 5 WHEN '一般' THEN 2 WHEN '轻微' THEN 1 ELSE 1 END)
-- 隐患逾期（读 hse_rectifications，0 行）
COUNT(DISTINCT CASE WHEN rh.is_overdue = true THEN rh.id END) * 5
```

### 4.6 三套扣分算法单价对照

| 事实类型 | ① 真实 `hse_assessment_deduction` | ② 综合接口 `assessmentService` | ③ **分析接口（页面在用）** |
|---|---|---|---|
| 事故 | `NEG-004` **100 分/条**（否决） | `majorAccidentCount * 15` | 轻微 **3** / 一般 **10** / 较大 **20** / 重大 **50** / 特别重大 **100** |
| 三违 | `SAF-001` 多来源（Excel 对齐/台账/月度分） | `totalWeightedIndex * 3` | 严重 **5** / 一般 **2** / 轻微 **1** |
| 隐患逾期 | **0 分**（无实现） | `rectOverdue * 5` | `is_overdue * 5`（读 0 行表） |
| 公司人员查处 | **5 分/次**（规则库）× 类别封顶 | 无 | 无 |
| 写入数据库 | ✅ 写 | ❌ 只读展示 | ❌ 只读展示 |

**⇒ 「考核扣分」在全系统有 3 套互不相同的算法，其中只有 ① 写入数据库并进入总分，而用户能看到的页面用的是 ③。**
