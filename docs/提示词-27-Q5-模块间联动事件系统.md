#### 3. 创建校验脚本（Q2 §6.3）

在 `scripts/` 目录下创建 `validate-employee-deps.ts`（或 `.mjs`），功能：

1. **扫描**：遍历 `src/views/*/employee-deps.json`，收集所有声明
2. **JSON Schema 校验**：
   - 顶层字段仅允许 `module`/`dependsOn`/`provides`
   - `dependsOn` 内部仅允许 `employeeFields`/`events`/`queries`/`components`
   - `provides` 内部仅允许 `employeeStats`/`events`
3. **完整性校验**：
   - 所有 8 个核心模块均有 `employee-deps.json`
   - `dependsOn.employeeFields` 至少包含 `["employeeId", "employeeName"]`
4. **一致性校验**：
   - `dependsOn.events` 中的事件类型必须在 Q2 §2.1 定义的 4 种枚举内
   - `dependsOn.components` 中的组件名必须在 `["EmployeeSelector", "EmployeeName"]` 内
   - `module` 字段值必须与文件所在目录名一致
5. **输出**：校验通过输出 `✅ 8/8 modules valid` + 依赖关系矩阵；校验失败输出具体错误文件和原因

**脚本要求**：
- 可直接通过 `node scripts/validate-employee-deps.mjs` 运行
- 无需安装额外 npm 依赖（使用 Node.js 内置 `fs`/`path`）
- 退出码：通过 → 0，失败 → 1

#### 4. 事件驱动缓存刷新集成（Q2 §2.2）

在 `useEmployeeData` 中集成事件驱动缓存刷新，Q3 当前实现仅有内存缓存，未订阅事件总线。

**4.1 增强 useEmployeeData.ts**

在 `useEmployeeData` 内部增加：
```ts
import { useEmployeeEvent } from './useEmployeeEvent';

// 在 useEmployeeData 函数内：
const { subscribe } = useEmployeeEvent();

// 模块级缓存（Q3 已有，保持）
const cache = new Map<number, EmployeeInfo>();

// 新增：订阅事件，当命中缓存中的 employeeId 时自动刷新
subscribe(
  ['EMPLOYEE_TRANSFERRED', 'EMPLOYEE_RESIGNED', 'EMPLOYEE_STATUS_CHANGED', 'EMPLOYEE_INFO_UPDATED'],
  (event) => {
    if (cache.has(event.employeeId)) {
      cache.delete(event.employeeId); // 失效缓存，下次访问重新拉取
      // 如果当前正在展示该员工，触发 refresh
      if (currentEmployeeId.value === event.employeeId) {
        refresh();
      }
    }
  }
);
```

**要求**：
- 事件驱动失效仅在 cache 中已存在该 employeeId 时触发（避免无效刷新）
- 如果当前组件正在展示该员工（`currentEmployeeId` 匹配），调用 `refresh()` 触发响应式更新
- 事件处理使用 try/catch 包裹，防止单个事件处理异常影响其他订阅者

**4.2 在 violations 模块中落地事件驱动刷新（示例）**

在 `src/views/violations/index.vue` 中增加事件订阅示例：
```vue
<script setup>
import { useEmployeeEvent, useEmployeeData } from '#/composables/hse';

const { subscribe } = useEmployeeEvent();

// 订阅员工变更事件，刷新违章列表
onMounted(() => {
  const unsubscribe = subscribe(
    ['EMPLOYEE_TRANSFERRED', 'EMPLOYEE_RESIGNED'],
    (event) => {
      // 离职/调岗 → 刷新列表（违章记录中的 violatorName 快照可能过期）
      fetchViolationList();
    }
  );
  // 组件卸载时取消订阅
  onUnmounted(unsubscribe);
});
</script>
```

> 注意：此示例仅用于验证事件总线通路和订阅/取消订阅生命周期。实际刷新策略（全量刷新 vs 单条刷新）由业务方后续决定，本次不做强制要求。
