## 三、发现并修复的问题

### 问题：driver 三模块「下载模板」表头为通用占位，与导入 fieldMapping 不匹配
- **现象**：`GET /api/import/template/driver-assessment` 返回模板表头为 `字段1/字段2/字段3/字段4/字段5`（占位降级），而导入解析依赖 `NATIVE_IMPORT_MODULES['driver-*'].fieldMapping` 的中文源表头（档案编号/姓名/驾驶证号/…）。
- **后果**：用户按下载模板填表后上传，因表头无一处命中 fieldMapping，**所有字段无法映射 → 导入得到空记录**。属运行态暴露的真实缺陷。
- **根因**：`server/routes/import.js` 内 `moduleTemplates` 对象**未包含** `driver-assessment` / `driver-violation` / `driver-monthly` 三个键，触发了 `||` 后的通用降级模板。
- **修复**：在 `moduleTemplates` 中补齐这三项的表头行（取各自 fieldMapping 的首个别名作为列名，与既有模块写法一致）：
  ```js
  'driver-assessment': [{ 档案编号:'', 姓名:'', 驾驶证件号:'', 准驾车型:'', 所属部门:'', 车辆编号:'', 评估日期:'', 评估结果:'', 评估等级:'', 有效期至:'', 联系电话:'', 备注:'' }],
  'driver-violation':  [{ 姓名:'', 车牌号:'', 违章时间:'', 违章地点:'', 违章类别:'', 违章事实描述:'', 扣分:'', 罚款金额:'', 处理状态:'', 处理方式:'', 处理结果:'', 备注:'' }],
  'driver-monthly':    [{ 考核月份:'', 姓名:'', 所属部门:'', 安全驾驶得分:'', 遵章守纪得分:'', 培训学习得分:'', 得分:'', 考核等级:'', 主要问题:'', 评定人:'', 备注:'' }],
  ```
- **验证**：`node --check server/routes/import.js` 通过；导入链路实测用**正确中文表头**文件走通 `upload→preview→confirm→list`（见下）。
- **生效条件**：后端为内存常驻，改动 `import.js` 需**重启 5800** 后下载模板才会带正确表头（遵循项目“改后端须用户重启 5800”约定，本次未自行 kill 进程）。
