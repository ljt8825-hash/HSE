**核心判断**

- 三违评估"在列表中"目前缺的**不是字段**（模型、`ASSESSMENT_TYPES`、筛选 UI 都已就绪），而是：

## 三、升级方案（对标 vben.pro `dashboard/analytics`）

### 3.1 数据层：让"三违评估"真正进列表（P0）

复用现有 `calcDriverRisk` 引擎（它本来就读违章记录、算扣分/次数/最严重行为），新增一条**三违评估判定通道**：

1. 按姓名聚合 `driver-violations`（DB 已迁，非内存）→ 得「三违次数 / 扣分合计 / 最严重类型」。
2. **三违评估风险等级独立口径（用户 2026-09-04 给定，见截图）**：按「累计扣分」区间定级，与驾驶证评估的窗口扣分/次数口径不同：

   | 风险等级 | 累计扣分区间 |
   |---|---|
   | 较低 | ≤ 15 分 |
   | 一般 | 16 ~ 30 分 |
   | 较大 | 31 ~ 50 分 |
   | 重大 | > 50 分 |

   该口径在三违评估模块内独立维护；管控措施文本仍复用 `riskRules` 的 `riskContent` / `riskMeasures`，保持 UI 配色与文案一致。
3. 放开 `findArchiveByName` 限制（或新增 `findSwViolationArchiveByName`），使判定结果同时写入 `assessmentType='三违评估'` 的档案。
4. 新增「**生成三违评估**」按钮（类比现有同步/判定弹窗），对花名册驾驶员批量落三违评估记录。
5. `onRiskLevelChange` 去掉 `assessmentType` 限制，三违评估也自动带出评估结果 + 管控措施。

### 3.2 展示层：卡片 + 图表 + 分区（P1–P2）
