# 评分引擎实现报告

## 一、概述

月度安全履职考核评分引擎是整个考核系统的核心计算模块，负责根据考核指标和数据源自动计算每个考核对象的得分。

## 二、评分模型

### 2.1 总分计算规则

```
总分 = 自动评分 + 人工调整分 + 加分
```

其中：
- **自动评分** = 100 - 各项指标扣分总和
- **人工调整分** = 手动评分记录（需审核通过）
- **加分** = 额外加分项（预留）

### 2.2 指标类型

| 类型 | 说明 | 计算方式 |
|------|------|----------|
| positive（正向指标） | 得分越高越好 | 原始分 - 扣分项 |
| negative（负向指标） | 扣分制 | 直接按规则扣分 |
| veto（否决项） | 一票否决 | 触发则直接不合格 |

## 三、数据源接入

### 3.1 三违行为管控 (violation_records)

**指标：** 三违行为管控（40分，负向）

**扣分规则：**
| 三违等级 | 单次扣分 |
|----------|----------|
| 重大 | 10分 |
| 较大 | 5分 |
| 一般 | 2分 |
| 其他 | 1分 |

**SQL 逻辑：**
```sql
SELECT count(*) as cnt, COALESCE(SUM(
  CASE 
    WHEN violation_level = '重大' THEN 10
    WHEN violation_level = '较大' THEN 5
    WHEN violation_level = '一般' THEN 2
    ELSE 1
  END
), 0) as total_deduction
FROM violation_records
WHERE violator_id = :employee_id
  AND violation_date >= :start_time
  AND violation_date <= :end_time
  AND is_deleted = FALSE
```

### 3.2 隐患整改完成率 (hazards)

**指标：** 隐患整改完成率（20分，正向）

**计算规则：**
- 整改率 = 已完成隐患数 / 总隐患数
- 扣分 = (1 - 整改率) × 基础分
- 无隐患：默认100%，不扣分

**实际表结构适配：**
- 原设计：`responsible_person_id` + `found_date` + `rectification_status`
- 实际表：`fixer`（姓名关联） + `hazard_date` + `status`（已完成/未完成）

### 3.3 培训计划完成率 (training_records)

**指标：** 培训计划完成率（10分，正向，仅管理员）

**计算规则：**
- 完成率 = 合格培训数 / 总培训数
- 扣分 = (1 - 完成率) × 基础分
- 无培训计划：默认100%

**实际表结构适配：**
- 原设计：`completion_status = '已完成'`
- 实际表：`result = '合格'`

### 3.4 其他数据源（预留）

| 数据源 | 状态 | 默认值 |
|--------|------|--------|
| risk_alerts（风险预警） | 待接入 | 100% |
| responsibility_forms（责任书） | 待接入 | 100% |
| manual（改进与创新） | 手动 | 基础分 |
| accidents（事故否决） | 待接入 | 无否决 |

## 四、评分执行流程

```
开始
  ↓
查询周期信息
  ↓
查询激活的考核指标（9项）
  ↓
查询该周期的所有考核对象
  ↓
计算新版本号（MAX(score_version) + 1）
  ↓
遍历每个考核对象：
  ├─ 初始化总分扣减 = 0
  ├─ 遍历每个指标：
  │   ├─ 判断是否适用该职位
  │   ├─ 根据数据源计算扣分
  │   ├─ 累加总分扣减
  │   └─ 保存指标评分记录
  ├─ 计算自动评分 = MAX(0, 100 - 总扣减)
  ├─ 计算等级
  ├─ 删除旧的自动评分记录
  ├─ 跳过已有手动评分的指标
  ├─ 插入新的评分记录
  └─ 更新对象表（score_auto, score_total, grade, score_version, status）
  ↓
更新周期状态为 pending_review
  ↓
记录审计日志
  ↓
结束
```

## 五、评分等级标准

| 等级 | 分数范围 | 说明 |
|------|----------|------|
| A（优秀） | ≥ 90分 | 安全履职优秀 |
| B（良好） | 80-89分 | 安全履职良好 |
| C（合格） | 70-79分 | 安全履职合格 |
| D（不合格） | < 70分 | 安全履职不合格 |

**实现函数：** `calculateGrade(score)`

## 六、版本管理

### 6.1 版本号规则
- 每次执行自动评分，版本号 +1
- 版本号基于当前周期内最大版本号计算

### 6.2 手动评分保护
- 自动评分时，跳过已有手动评分的指标（is_manual = TRUE）
- 手动评分记录不受自动评分覆盖
- 确保人工干预结果保留

## 七、容错机制

### 7.1 数据源异常处理
每个数据源查询均包裹 try-catch：
- 异常时使用默认值（不扣分）
- 记录异常说明到 data_sources 字段
- 不中断整体评分流程

### 7.2 JSONB 字段处理
- 使用 `JSON.stringify()` 序列化数组
- 使用 `::jsonb` 类型转换
- 确保 PostgreSQL JSONB 类型正确写入

## 八、性能优化

### 8.1 索引支持
- score 表：target_id, cycle_id, metric_id, review_status 索引
- target 表：cycle_id, status, position, township 索引
- violation_records：violator_id, violation_date 索引

### 8.2 事务控制
- 所有对象评分在一个事务中
- 确保数据一致性
- 失败时整体回滚

## 九、接口说明

### 9.1 执行自动评分
- **接口：** `POST /api/hse/assessment-monthly/scoring/execute`
- **参数：** `{ cycle_id }`
- **返回：** `{ cycle_id, scored_count, score_version, status }`

### 9.2 查询评分进度
- **接口：** `GET /api/hse/assessment-monthly/scoring/progress/:cycleId`
- **返回：** `{ total, scored, progress_percent, status }`

### 9.3 重新评分
- 支持对已评分周期再次执行评分
- 自动评分记录会被删除后重新生成
- 手动评分记录保留不变
