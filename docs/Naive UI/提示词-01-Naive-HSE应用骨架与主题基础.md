# WorkBuddy 任务书：阶段 01 - Naive HSE 应用骨架与主题基础

## 任务定位

你正在执行 HSE 系统 Naive UI 改版的第 01 阶段。总体计划见同目录的 `00-Naive-UI-HSE总体实施计划.md`。

本阶段仅建立可运行的 Naive HSE 应用骨架、主题和基础路由承载能力。不要迁移任何 HSE 业务页面，不要修改后端、数据库、`apps/web-antd` 或现有业务接口。

## 已确认的设计约束

- 保留现有 HSE 一级/二级菜单结构、路由语义、权限、接口和功能。
- 使用现有 Vben Naive 基线，不引入第二套 UI 框架，不混用 Ant Design Vue 组件。
- 技术版本保持项目锁定版本：Naive UI `2.44.1`、VXE Table `4.19.25`。
- 绿色为主色；蓝色信息、橙色预警、红色风险/危险操作、灰色普通/草稿。
- 全局左侧菜单固定宽度，不增加拖动调宽功能。
- 不实现业务页面、表格、导入、双列布局或接口改造；这些属于后续阶段。

## 具体工作

1. 审核 `apps/web-naive` 现有官方基线，并使其可作为 HSE 新前端的独立启动入口。
2. 创建 HSE 专用的基础目录与最小可运行页面承载结构，目录命名须清晰且可扩展，例如 `views/hse`、`router/routes/modules`、`components/hse`、`layouts`。不要复制或迁移业务视图代码。
3. 建立 HSE Naive 主题覆盖：使用 Vben/Naive 官方 `NConfigProvider` 与设计令牌机制；不得通过大面积硬编码 CSS 颜色实现主题。
4. 在主题中定义可复用的主色、信息、预警、危险和中性色，并确保亮色与暗色模式均可用。
5. 建立最小 HSE 路由骨架：只创建一个可访问的“安全总览”占位页面和一个明确的 HSE 一级菜单入口，用于验证应用外壳、菜单和路由链路。不得提前创建其余业务菜单页面的空壳。
6. 确保 `web-naive` 可以在不依赖 `web-antd` 运行时组件的条件下通过类型检查与生产构建。
7. 保持改动最小、可读、符合本仓库既有 Vben 代码风格。不要修改锁文件、升级依赖、删除任何文件或重写现有 `web-naive` 官方代码，除非为本阶段 HSE 入口所必需。
