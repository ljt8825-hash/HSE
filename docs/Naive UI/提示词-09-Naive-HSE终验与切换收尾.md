## 三、Part 2 —— 运行时验证缺口闭环（只读优先）

> 缺口来源（08-3 §2.5）：后端 `/api/hazards` 实测 `total:0`，列表无行，导致详情抽屉（附件 / 关联风险 / 版本 3 tabs）与整改流转（整改 / 提交复查 / 复查确认 / 关闭 4 操作）**仅代码与 typecheck 就绪，未做 runtime 端到端验证**。

1. **只读优先**：若后端已存在只读的演示数据 / 现有隐患数据，直接 CDP 打开详情抽屉，逐项验证：
   - 附件：上传（multipart）/ 列表 / 下载 / 删除；
   - 关联风险：`getRelatedRisk` 卡片渲染 + 跳转 `/risk/list?highlightRiskId=...`；
   - 版本：`getHazardVersions` 版本表；
   - 整改流转：`rectify → submitReview → review(pass|fail) → close` 四操作往返，确认状态流转正确、错误如实提示。
2. **若后端仍 `total:0`**：**STOP**，在总结中如实声明「运行时验证缺口未能闭环」，并列明「需注入演示数据」的授权请求（不擅自写数据）；同时给出「生产数据初始化后补测」的清单。
