## 二、审核中发现的 2 项确认缺口（附条件）

### 条件① —— N1 `/system*` 跳登录判定的自洽性缺口

执行总结 §二 与 `decision-list.md` N1 将 `/system`、`/system/users`、`/system/audit` 三项跳登录归因为「测试 admin token 缺少 `accessCodes` 权限码之假象（基线同源）」。

但 `regression-matrix.md` 第 69–71 行显示：**`/system/roles` 可达（`shotweb-system-roles.png` 已截屏），`/system/users` 与 `/system/audit` 却跳登录**。而 `hse-system.ts` 中三个子路由的 `meta.authority` **完全一致**，均为 `['admin']`，且均无 `accessCodes` 字段、无组件级 redirect 逻辑。

> 一个统一的「缺权限」原因，无法解释「同一父路由、同一 `authority:['admin']`、同一时刻」下 roles 可达而 users/audit 跳登录的差异。

因此 N1 的归因**逻辑不自洽**，需在切换前闭环：

- 用携带正确 `accessCodes`（或具备完整 admin 权限码）的 token 复测 `/system`、`/system/users`、`/system/audit` 三路由，确认其正常渲染（非跳登录、非 404、无组件失败）。
- 若复测仍跳登录，则需进一步排查是「路由注册顺序 / keepAlive 缓存差异」还是「audit/users 视图内部守卫」所致——届时 N1 从「等价（假象）」降级为「待修复」。

> 不影响本节「0 组件失败、0 404、0 console error」三项硬门禁的成立，但属于**切换前必须闭环的最后确认项**。

### 条件② —— 偏离①考核分析「数据等价性业务复核」未真正完成

`提示词-07` §四明确要求 Part B 完成「偏离①考核分析数据等价性业务复核」（即 `assessment-analysis` 双 API 整合后，概览/部门排名/乡镇排名/目标/扣分五块数字与 web-antd 一致性）。

由于本环境 **Chrome DevTools(9222) 无法绑定**，Part B 实际只完成三层「浏览器无关」证据：启动可达 curl、后端同源 401、静态契约比对。执行总结已如实披露此局限，但必须指出：

- **契约级等价 ≠ 数据等价**。`parity.json` 的 24/24「等价」建立在「共享后端 + 共享 service 契约」的**结构性推断**上，并未对考核分析中心五块数据的**具体数值**做逐字段比对。
- 偏离①在 06E-2 审核时已被标记为「转业务复核」，07 任务书亦点名要闭环此复核；受 CDP 限制，本批**未闭环**。

处置建议（切换前二选一）：

- (a) 启用 Chrome 远程调试后补做考核分析中心 runtime 级数据比对；或
- (b) 用户明确接受「共享后端 + 共享契约」的结构等价作为该项放行依据（需在对话中显式确认）。
