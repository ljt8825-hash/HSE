## 四、如实记录的既有行为差异（非本阶段引入，未自行修改）

### 4.1 safety_manager 可访问 admin-only 页面（Vben frontend 过滤未生效）

- **事实**：safety_manager 正常登录（userRoles=['safety_manager']）后，`/personnel/departments` 与 `/standards/relation`（meta.authority=['admin']）在浏览器完整渲染。
- **代码预期**：`generateRoutesByFrontend` 的 `filterTree` 应删除不满足 `hasAuthority` 的节点（父 `/personnel` authority=['admin'] 不含 safety_manager）。
- **实测结果**：未被过滤。**根因待查**（可能涉及 Vben 运行时 accessMode/路由生成时机），但这是**既有 Vben 框架 + 既有 web-naive 配置**的行为，**不是本阶段引入或放宽**。
- **本阶段处理**：未修改 Vben 权限机制、未修改路由 authority、未放宽。如实记录，需用户/架构决定是否单独授权修复 Vben 权限过滤或调整路由配置。

### 4.2 后端未对 safety_manager 拦截 admin-only 端点

- **事实**：`GET /hse/standard/relation/stats`、`POST /hse/standard/relation` 对 safety_manager 均 200/code=0。
- **本阶段处理**：未修改后端 requireRole。如实记录，需单独授权后端权限收紧。

### 4.3 登录后 homePath `/hse/todos` 404

- **事实**：`/user/info` 返回 `homePath: '/hse/todos'`（后端写死），但 web-naive 未注册该路由 → 登录后落地页 404（截图 `06_sm_login` 后跳转）。
- **本阶段处理**：未改后端 homePath。如实记录（`/hse/todos` 可能为未来待办页预留）。
