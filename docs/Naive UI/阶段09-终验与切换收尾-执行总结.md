### 2.4 新发现缺陷记录（仅记录，不修复 —— 转授权）

- **缺陷**：`server/routes/hazards.js` 第 1020 / 1047 / 1107 行 `LEFT JOIN v_employee_current e ON h.responsible_id = e.id`，而视图 `v_employee_current` 的主键列为 **`employee_id`（无 `id` 列）** → PG 报「字段 e.id 不存在」→ 三端点 catch → `code:-1`。
- **影响**：web-naive（与 web-antd 基线同源）的「隐患提醒」抽屉三 tab（重大/超期/责任人超期）**在任何数据状态下均报错**；08-3 CDP 时提醒抽屉能打开但数据获取失败（当时 toast 的「字段 e.id 不存在」即此后端错误，与前端无关）。
- **建议修复（需后端授权）**：`hazards.js` 三处 `e.id` → `e.employee_id`（1 行 × 3 处，纯后端，与前端无关）。
- **证据**：`_verify/09/runtime-gap-probe.txt` + 上方探针表。

### 2.5 授权请求（不擅自执行）

1. **演示数据注入授权**：请求允许注入 2–3 条只读演示隐患（含不同 status、关联风险、附件、版本记录），以闭环「详情抽屉 3 tabs + 整改流转 4 操作往返」的 CDP runtime 验证。注入方式、表、字段由授权后另行确认（不写 SQL）。
2. **后端缺陷修复授权**：`hazards.js` 三处 `e.id` → `e.employee_id` 修复（1 行×3，需重启后端）。
