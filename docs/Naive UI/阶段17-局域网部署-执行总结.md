## 三、lan-server.js 关键设计

`lan-server.js`（`G:\hse-dashboard\` 根目录，单文件，ESM）是本次部署的唯一新增代码。

### 3.1 基础能力

| 项 | 说明 |
|---|---|
| 监听 | `0.0.0.0:5280`（全网卡，局域网可达，区别于阶段14遗留的 `127.0.0.1:5280`） |
| 静态目录 | `path.resolve(__dirname, '安全看板vben', 'apps', 'web-naive', 'dist')` |
| API 代理 | `/api` 及其子路径 → `http://127.0.0.1:5800` |
| SPA 回退 | 哈希路由：未知无扩展名路径 → `index.html`；带扩展名缺失 → `404` |
| 目录穿越防护 | `path.resolve + startsWith(DIST_DIR + sep)`；越界返回 `403` |

### 3.2 **关键修复：代理侧剥离 `origin/referer` 头部**

在 CDP 验证中发现：**代理返回 500 给 `POST /api/auth/login`**，但 `GET /api/health` 正常；通过 curl 隔离定位到根因——当请求携带 `Origin: http://192.168.10.107:5280` 头部时，后端返回 500（curl 不带该头 → 200；带该头 → 500；直接到 `:5800` 不带该头 → 200）。

> 这是后端对非白名单 Origin 的处理返回 500（不是标准的 CORS 拒绝）。后端代码属红线禁区（禁止修改 `server/`、SQL、`package.json`），故在代理侧修复：

```js
// 关键修复：浏览器访问 /api 属同源（均在 192.168.10.107:5280），
// 不会触发 CORS 预检；剥离 origin/referer/sec-fetch-* 后，
// 后端按"无 Origin"处理（已验证返回 200），
// 浏览器端因同源不校验 CORS，登录/接口调用恢复正常。
delete options.headers['origin'];
delete options.headers['referer'];
delete options.headers['sec-fetch-site'];
delete options.headers['sec-fetch-mode'];
delete options.headers['sec-fetch-dest'];
```

修复后的验证（curl 模拟浏览器）：

| 测试 | 状态 |
|---|---|
| `GET /api/health` via `192.168.10.107:5280` | **200** `{"code":0,"status":"ok"}` |
| `POST /api/auth/login`（无 Origin）via `127.0.0.1:5280` | **200** `登录成功` |
| `POST /api/auth/login`（带 `Origin: http://192.168.10.107:5280`）via `127.0.0.1:5280` | **200** `登录成功`（修复前为 500） |
| `POST /api/auth/login` via `192.168.10.107:5280` | **200** `登录成功` |
| 目录穿越 `/../lan-server.js` | **403** |
| 目录穿越 `/%2e%2e/lan-server.js` | **403** |
| 缺失资源 `/js/does-not-exist.js` | **404**（不回退为 index.html） |

## 四、防火墙入站规则

### 4.1 状态

`New-NetFirewallRule` **需要管理员权限**，当前 WorkBuddy 的 PowerShell 会话为非提升会话，执行返回：

```
CREATE_FAILED: 拒绝访问。
```

故防火墙规则未在本次会话内创建；本批"防火墙规则"以**状态卡 + 精确命令**形式交付，**需用户以管理员身份**在 PowerShell 中执行一次。

### 4.2 执行命令（管理员 PowerShell）

```powershell
New-NetFirewallRule -DisplayName "HSE LAN Server" `
  -Direction Inbound -Protocol TCP -LocalPort 5280 `
  -Action Allow -RemoteAddress 192.168.10.0/24

# （可选）若同事需直连后端调试 API：
New-NetFirewallRule -DisplayName "HSE Backend" `
  -Direction Inbound -Protocol TCP -LocalPort 5800 `
  -Action Allow -RemoteAddress 192.168.10.0/24
```

### 4.3 规则属性（创建后）

| 字段 | 值 |
|---|---|
| DisplayName | HSE LAN Server |
| Direction | Inbound |
| Protocol | TCP |
| LocalPort | 5280 |
| Action | Allow |
| RemoteAddress | 192.168.10.0/24（仅办公室局域网，不开放公网） |

### 4.4 影响范围

- **本机回环（127.0.0.1 / localhost）**：不受防火墙限制，无需规则，**当前已可访问** ✅
- **局域网同事**：规则创建后即可通过 `http://192.168.10.107:5280` 访问
- **公网**：规则限制为 `192.168.10.0/24`，不开放公网（符合红线 2）
