## 二、关键发现

### P1（必须修复 · 转 06E-4 首项）路由重名 + 「高级分析」侧栏可见重复

- **事实**：`hse-advanced.ts` **已存在** `HseIot`（`/hse-advanced/iot`）、`HseSupplyChain`（`/hse-advanced/supply-chain`）两子路由，与本次插入 `hse.ts` 的 `/overview/iot`、`/overview/supply-chain` **route name 完全相同**，复用同一视图组件（`rg` 已确认 naive 两文件四行 `HseIot`/`HseSupplyChain`）。
- **分级责任**：重名 **name** 属基线同源 quirk——基线 `hse-01-overview.ts` 与 `hse-advanced.ts` 本就各自定义 `HseIot`/`HseSupplyChain`（我独立 `rg` 确认基线同样四行重名），naive 忠实复现，不阻塞。
- **真正偏离**：基线 `hse-advanced.ts` 的 `HseAdvanced` 父级带 **`hideInMenu: true`**（整组隐藏），而 naive `hse-advanced.ts` **缺 `hideInMenu`**，导致侧栏出现一个**可见的「高级分析」顶层分组**，其下重复展示「IoT物联网 / 供应链安全」——这是基线**不存在**的可见重复项。
- **实证**：`06e3_sider_dump.txt` 侧栏清单含可见「高级分析 / IoT物联网 / 供应链安全」三项；`report.json.insertOrderOk=false` 佐证侧栏顺序未达基线 1:1。
- **职责界定**：`hse-advanced.ts` 属 06E-3 红线外（提示词 §七「唯一改动 hse.ts」），执行者**未触碰并如实移交 P1**，处理正确、非执行者过错。
- **处置（转 06E-4 作为首项）**：给 naive `HseAdvanced` 加 `hideInMenu: true`（对齐基线，消除可见重复，保留 `/hse-advanced/iot|supply-chain` 深链，不减少功能）。重名 name 为基线同源遗留，可一并评估「移除 hse-advanced 重复子路由」但非必须。
