## 试点范围

- 人员主数据 → 员工列表：保留原路由语义、权限、查询条件、分页、查看/编辑/删除、新增和真实 API。
- 应急管理 → 应急预案：保留原有字段、状态、详情/编辑流程和 API；列表使用统一表格。
- 风险管控 → 风险清单：保留风险等级、责任对象、状态、筛选和详情流程；列表使用统一表格。

以 `web-antd` 为只读业务行为参考，以现有 `web-naive` 路由和 API 适配方式为实现边界。不得复制 Ant Design 组件到 Naive 页面。

## 强制实现规范

- 页面结构统一使用 `HsePageLayout`、`HseSearchPanel`、`HseActionBar`、`HseStatusTag`。
- 列表统一使用 `HseDataGrid + VXE Table`；表头居中、长文本 tooltip、语义对齐。
- 仅编号、日期、数量、金额、状态、风险等级等明确可比较字段设置 `sortable: true`；排序事件必须请求服务端并传 `{ sortBy, sortOrder }`，取消排序传 `sortOrder: undefined`，不得只排序当前页。
- 必须给服务端分页传入真实 `total`，避免使用表格当前页长度代替总数。
- 不提供列宽拖动、列顺序拖动或用户自定义列宽。
- 工具栏顺序固定为刷新、下载模板、导入、导出、新增；新增是唯一 primary 动作；没有对应能力的动作隐藏。
- 操作列按查看、编辑、删除排序，删除必须二次确认；颜色只使用 HSE 语义色。
- 导入统一复用 `HseImportDialog`，接入真实模板下载、解析/校验和确认 API；界面文案只能使用“下载模板”和“导入”。
- 新增/编辑使用统一表单抽屉或弹窗；查看优先抽屉。不得改变业务字段、接口和权限。

## 阶段 04 前置加固

先确认 `HseDataGrid` 的 `pager=true` 默认总数不会因数据回灌触发网格配置重建；优先让试点页面全部传入服务端 `total`，如需修改公共组件，保持兼容并补充验证。确认 `run-dev-nosafe.cjs` 仅为验证辅助，不作为正式业务启动入口。

## 验证要求

对三个试点分别验证：

- 路由可达、权限行为未改变、页面无 Ant Design 组件引用；
- 查询、重置、刷新、分页、服务端排序、查看、编辑、新增、删除及导入/导出（页面实际支持的动作）功能可用；
- 桌面和窄屏无横向溢出，表头居中，长文本 tooltip，操作栏顺序和颜色一致；
- 亮色/暗色主题一致；浏览器控制台无本次改动新增错误。

执行并记录：
