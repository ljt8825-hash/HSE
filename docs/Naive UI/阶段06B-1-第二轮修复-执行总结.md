### P0：恢复 HseSearchPanel 的 Naive NGrid 上下文（阻断崩溃）

| 项 | 内容 |
|---|---|
| 根因 | 上一轮将 `HseSearchPanel` 的 `NGrid` 替换为普通 `<div>`，但 7 个调用方（员工/应急预案/风险清单/三违/消防/网格/总览）仍传 `<NGi>`。import 了 `NGi` 的页面（员工/应急预案/风险清单/总览）在无 `NGrid` 提供的 `gridInjectionKey` 上下文时运行时解构崩溃；site 三页因**漏 import `NGi`**（渲染为未解析原生元素）筛选区异常 |
| 修复 1 | `components/hse/HseSearchPanel.vue` 恢复 Naive `NGrid`：`<NGrid :cols="gridCols" :x-gap="16" :y-gap="16" responsive="screen">`；`gridCols = computed(() => \`1 s:2 l:${props.columns}\`)`（合法响应式字符串 cols，**不再向 cols 传对象**）。保留 columns/collapsible/defaultExpanded/默认插槽/more 插槽/查询·重置按钮全部既有接口 |
| 修复 2 | `views/site/{violation,fire-facility,grid}/index.vue` 三页 **补齐 `NGi` import**（缺失依赖，非修改调用方式掩盖问题） |
| 验证 | 7 页逐一打开：筛选字段全部可见（selection=1~5），控制台 **0 个** NGi/GridItem/Cannot destructure/gridInjectionKey 应用错误；375px 窄屏无横向溢出 |
| 说明 | 源码确认：Naive `Grid.mjs` 渲染只保留 `__GRID_ITEM__` 的 NGi；`useBreakpoints`（vooks）返回激活断点数组，seemly 数组分支正确解析 `"1 s:2 l:N"`；对象 cols（`[object Object]` → NaN 列）才是此前"不渲染"的真正根因 |

### P1：修复消防负责人电话自动回填（回调签名）

| 项 | 内容 |
|---|---|
| 根因 | `handleManagerSelect(option)` 单参数被当作 `{phone}` 选项对象；Naive `NSelect` 的 `@update:value` 真实签名是 `(value, option)`，第一个参数是选中值（姓名），`option.phone` 永远取不到 |
| 修复 | `views/site/fire-facility/index.vue`：`handleManagerSelect(_value: string \| number \| null, option: { phone?: string } \| null)`，用第二个参数 `option.phone` 回填 `formModel.phone`；模板绑定不变 |
| 配套 | 补**转运站兜底列表**（与旧版 `web-antd` 一致）：`locationOptions` 初始 `['宁津镇转运站','柴胡店镇转运站','时集镇转运站','保店镇转运站']`，部门树动态加载到含"转运站"的 level2 时覆盖；加载失败/无转运站时保持兜底（旧版行为） |
| 保持 | 位置切换清空负责人/电话、花名册关联提示、导入后匹配校验、CSV 下载、隐藏导出按钮——均未改动 |

- 花名册部门命名（作业中心）与转运站选项（转运站）不一致为既有数据/业务命名问题，需**用户/Codex 决策**是否调整（如位置选项改为「作业中心」或数据侧补充转运站部门），本任务未改动。

## 六、过程发现的环境问题（供后续阶段参考）

1. **`env -u http_proxy -u https_proxy` 在本 harness 下会吞掉 node 子进程 stdout**（node -e / 脚本均无输出、退出码 0）——改用 bash 内联 `http_proxy= https_proxy=` 前置赋值；
2. **`pnpm run build` 输出被 harness 吞**（退出码 0 但无输出、无 dist）——改用 `NODE_OPTIONS= node "G:/…/vite/bin/vite.js" build --mode production`（注意 node 是 Windows 程序，路径须 `G:/` 形式，`/g/` 会被解析为 `G:\g\`）；
3. `NODE_OPTIONS` 中的 `--require=genie-safe-delete.cjs` 钩子在 `dist` 存在时会拦截 `emptyOutDir`——build 前先 `mv dist dist_stale_$(date +%s)` 或清空 `NODE_OPTIONS`。
