### B.2 前端组织管理（authority admin+safety_manager）

- safety_manager 浏览器访问 `/personnel/departments` → **可达**（截图 `05_safety_dept`）
- 写按钮（`aria-label="新增根部门"`）**可见** → `canEdit = hasAccessByRoles(['admin','safety_manager'])` = true
- 与 web-antd 基线 `PersonnelDepartments` authority 一致

### B.3 前端条款关联（authority admin）

实测发现 **Vben 路由过滤未拦截** `/standards/relation`（safety_manager 浏览器可达，菜单可见「制度标准」）。**这不是本阶段放宽权限，而是 injectLogin 方案的固有限制**：

> **原因说明**：当前 injectLogin 仅设置 SecureLS accessToken，**未走完整 login 流程**（未触发 `useUserStore.login()` 填充 `userRoles`）。当 admin 登录后 `userStore.userRoles = ['admin']`，切到 safety_manager 时 `userRoles` 仍残留 admin → `hasAccessByRoles(['admin']) === true` → 路由不被过滤 → 页面可达。
>
> **后端权限现状**（与本阶段无关）：后端 `GET /api/hse/standard/relation/*` 未对 safety_manager 做 requireRole 拦截，HTTP 200 可读；这是后端既有行为，本阶段未修改后端。
>
> **业务决策依赖**：若需严格 safety_manager 不可访问条款关联，需同时授权修改后端 requireRole 与 Vben `meta.menuVisibleWithForbidden`/真实双流程 login 填充 `userRoles`。本阶段未授权这些修改。
