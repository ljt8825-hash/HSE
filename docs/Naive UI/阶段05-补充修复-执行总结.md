## 二、四项待补证项（如实保留，未绕过）

任务书明确"不要把下列事项改写为'已完成'，也不要通过后端、数据库或伪造 JWT 绕过"。逐项原样保留：

### 1. pending → valid 的确认关联 UI 验收缺口（P1）

- **事实**：既有后端契约 `createRelation` 固定创建 `manual / status=valid`（`standardRelationService.js:192`）。上轮 UI 闭环实测中新增关联直接为 `valid`，因此"页面点击确认（pending → valid）"未在 UI 中实际执行。
- **不通过伪造/绕过**：未创建 pending 测试数据（无授权）、未改后端、未改契约。
- **所需**：一条可安全清理的真实 pending 关联测试数据，或用户明确授权在非生产环境创建该类数据；之后用页面"确认"按钮完成一次 PUT、状态与统计刷新并清理。

### 2. `/standards` redirect 与 relation 菜单可见性（P1）

- **事实**：基线 `redirect: '/standards/regulations'` + relation `hideInMenu: true`；web-naive 当前 `redirect: '/standards/relation'` + relation 菜单可见（本阶段只迁移 relation，禁建空白 regulations 占位）。
- **不通过绕过**：未改动路由 redirect 与菜单隐藏语义。
- **所需**：用户确认临时入口策略（relation 作为迁移入口的临时偏离 vs 保留旧 redirect/隐藏语义）。

### 3. 普通新增 department 不进入部门树（P1）

- **事实**：既有 `GET /departments/tree` 仅返回组织单元 + 班组命名规则的 department；普通新增部门刷新后不可见（上轮 API/浏览器实测）。
- **不通过绕过**：未改 `server/routes/hse-employee.js`，未在前端猜测挂载位置。
- **所需**：确认组织树应否展示全部 `department`，再单独授权后端树语义调整或明确前端合并规则。

### 4. safety_manager 真实权限验收（P1）

- **事实**：库中无有效该角色账号；上轮自签 JWT 被后端 `checkUser` 校验拒绝（401）。
- **不通过绕过**：未创建账号、未直接改库、未伪造 JWT。
- **所需**：用户提供非生产测试账号，或明确授权创建并清理测试账号。
