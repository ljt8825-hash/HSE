## 三、修复与必要副作用

### 3.1 字符串 id 比较 bug（12A / 12B 全部 4 启页面统一修复）

后端 `id` 实际类型为字符串（如 `"880"`），但 TypeScript `HazardItem.id: number` / `Regulation.id: number` 等与运行时不一致。`<NSpace v-if="row.id !== rowEditingId">` 中 `row.id` 实际为字符串、`rowEditingId` 初始为 `null`，且赋值时 `rowEditingId.value = row.id` 在 `ref<number>` 下赋字符串（TS noUncheckedIndexedAccess 虽不报，但 `String(row.id)` 比较恒为 true）→ **操作列编辑/保存 按钮永远不切换**。

修复（4 文件统一）：
- `const rowEditingId = ref<number | null>(null)` → `ref<string | null>(null)`
- `rowEditingId.value = row.id` → `rowEditingId.value = String(row.id)`
- 模板 `v-if="row.id !== rowEditingId"` → `v-if="String(row.id) !== rowEditingId"`

### 3.2 vite dev proxy Origin 头移除（必要 dev 修复，apps/web-naive/vite.config.ts）

**根因链路**（CDP 实机捕获）：
1. 阶段 12 保存路径首次验证 → 浏览器 PUT `/api/training/ledger/880` 返回 **500**；
2. 直接 curl 同 payload 到 5800 → 200 `更新成功`；通过 vite proxy 5174 转发同 payload → 200 `更新成功`；
3. CDP `Network.getResponseBody` 捕获浏览器实际响应 → `{"code":-1, "message":"CORS 策略不允许此来源"}`；
4. **根因**：浏览器非 GET 请求带 `Origin: http://127.0.0.1:5174`；后端 `server/.env` 的 `CORS_ORIGINS` 仅白名单 5173/5175/5666（无 5174 = web-naive dev 端口）；vite proxy 的 `changeOrigin: true` 仅改写 Host 头，**不改写 Origin**（http-proxy 已知行为），后端 CORS origin 函数 → `CORS_ORIGINS.indexOf(origin) === -1` → 拒绝；
5. **此为潜伏 dev CORS 缺口**：此前所有阶段 CDP 仅 GET 读 + 弹窗浏览（GET 浏览器不发送 Origin → 通过），从未实际触发浏览器写接口，故 08-1/08-2/08-3 均未暴露。本批首次实测浏览器保存路径暴露该缺口。生产环境两应用同源部署，此配置仅 dev 必需。

**修复**（仅 web-naive `apps/web-naive/vite.config.ts`，非后端、SQL、package.json、锁文件 → 合规红线）：
```ts
'/api': {
  changeOrigin: true,
  target: 'http://127.0.0.1:5800',
  ws: true,
  configure: (proxy) => {
    proxy.on('proxyReq', (proxyReq) => { proxyReq.removeHeader('origin'); });
  },
},
```
- 移除 Origin → 后端 CORS origin 函数 `if (!origin) return callback(null, true)` → 放行（dev 同源代理语义）
- 副作用（正面）：同时修复 web-naive dev 模态写（create/edit/delete）的潜伏 CORS 500
- vite auto-restart 约 40s 后生效
