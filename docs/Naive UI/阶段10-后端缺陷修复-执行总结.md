## 一、Part 1 —— 后端缺陷修复（5 行，已授权）

### 1.1 根因（与审核一致，未动视图）

`v_employee_current` 视图主键列为 `employee_id`（无 `id` 列），且无 `department`/`position` 列（实为 `org_name`/`position_name`）；`hazards.js` 三端点误用 `e.id`、`e.department`、`e.position` → PG 报「字段 e.id 不存在」→ 三端点 `code:-1`。

### 1.2 修复清单（逐行核查 ✓）

| 行 | 现状（错误） | 改为 | 状态 |
|---|---|---|---|
| 1020 | `LEFT JOIN v_employee_current e ON h.responsible_id = e.id` | `... = e.employee_id` | ✅ |
| 1047 | `LEFT JOIN v_employee_current e ON h.responsible_id = e.id` | `... = e.employee_id` | ✅ |
| 1102 | `SELECT e.id AS responsible_id, e.name AS responsible_name, e.department, e.position,` | `SELECT e.employee_id AS responsible_id, e.name AS responsible_name, e.org_name AS department, e.position_name AS position,` | ✅ |
| 1107 | `LEFT JOIN v_employee_current e ON h.responsible_id = e.id` | `... = e.employee_id` | ✅ |
| 1109 | `GROUP BY e.id, e.name, e.department, e.position` | `GROUP BY e.employee_id, e.name, e.org_name, e.position_name` | ✅ |

- **别名兜底（§2.3 契约保全）**：`e.org_name AS department`、`e.position_name AS position` —— 响应字段名与修复前前端期望一致（`responsibleId/responsibleName/department/position/...`），**前端零改动**。
- **`e.name AS responsible_name` 未动**（视图真实存在 `name` 列）。
- 改动前备份：`server/routes/hazards.js.bak-pre-10`（57,411 B）。
- 语法检查：`node --check routes/hazards.js` → OK。
- 残留核查：`rg "e\.id\b|e\.department\b|e\.position\b"` → 0。
- diff 仅 5 行改动（证据 `_verify/10/hazards-fix.diff`）。
