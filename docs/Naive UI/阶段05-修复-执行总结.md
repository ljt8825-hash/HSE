无其他外部引用（grep `HseDepartments|HseStandardRelation|PersonnelDepartments|StandardsRelation` 仅命中以上 4 处 + 注释）。

### 2. 部门表单真实校验（`departments.vue`）

- imports 加 `FormInst` 类型；
- 新增 `const formRef = ref<FormInst | null>(null);`；
- 模板 `<NForm ref="formRef" :model="formData" :rules="formRules" ...>`；
- `handleSubmit` 顶部新增校验：
  ```ts
  try { await formRef.value?.validate(); }
  catch { return; } // 校验失败：不进入加载态、不调用新增/更新 API
  ```
- **校验失败**：弹窗保持打开，由 NForm/NFormItem 显示错误（聚焦/错误信息由 Naive 表单承担）。
- **校验通过**：进入 loading + 写请求；接口失败 catch 不显示成功、弹窗保持。

### 3. HseDataGrid 无分页修复（公共组件）

```ts
if (props.pager) {
  // ... 原有分页配置 ...
} else {
  // 显式禁用 VXE pager：否则 VXE 默认启用分页栏（共 N 条/每页/翻页），
  // 会在调用方声明 :pager="false" 时仍显示分页控件。
  opts.pagerConfig = { enabled: false }; // ← 与项目 formConfig.enabled:false 同款写法
}
```
检查所有调用方（员工/风险/应急 pager=true、部门员工 pager 对象、relation pager=false）均不受影响。

### 4. 视觉收口

**4a. 树节点标签**：renderNodeLabel 改为"二选一"——`d.org_type` 优先显示组织类型；否则显示层级（`L1/L2` 等文本）；不丢失语义（组织类型已隐含层级）。实测根节点 tagCount=1。

**4b. 操作按钮图标**（`departments.vue`）：
- 移除 `NTooltip` 包裹 + template trigger 槽（引入 NTooltip/NPopconfirm trigger 槽必须单根的 Vue3 编译错误，已一并修复）；
- 改用 NButton `title` 属性作为 tooltip（HTML title 提示）；
- 编辑按钮 `IconifyIcon icon="lucide:pencil"`；删除按钮 `IconifyIcon icon="lucide:trash-2"`（从 `@vben/icons` 导入 `IconifyIcon`，与 web-antd 基线完全一致）。

**4c. 条款关联页 NCard 包裹**：移除 `<NCard :bordered="true" class="relation-card">` 外层，HseSplitPane 直接置于 HsePageLayout；补充 `.relation-split { height: calc(100vh - 260px); min-height: 420px; }` 样式；保留边界、间距、亮暗主题一致。

### 5. 视觉收口附带修复：控制台 24 条 app-code error

修复 NTooltip 包裹 NButton 触发 Naive `getFirstSlotVNode` 错误"slot[trigger] should have exactly one child"——**移除 NTooltip/NPopconfirm 包裹，用 NButton title 属性或单根 `<span>` 包裹**。实测控制台从 24 条 app-code 错误 → 0 条。

## 四、三项待决事项（原样状态、证据与所需决定）

任务书 §三 明示"不要修改后端、数据库、路由 redirect、菜单隐藏语义，也不要伪造验证来绕过它们"。逐项原样记录：

### 1. `/standards` redirect 与菜单可见性偏离基线

**事实**：
- 基线 `hse-03-standards.ts`：`redirect: '/standards/regulations'` + `StandardsRelation: hideInMenu: true`；
- web-naive 本阶段：`redirect: '/standards/relation'`（未迁移 `/regulations`）+ relation 不设 `hideInMenu`（任务书要求"不得用隐藏路由替代"）。

**当前取舍**：暂用 `/standards/relation` 作为 redirect（避免指向未迁移页 404），relation 在菜单可见（以便验收父子菜单与动作权限）。

**所需决定**：是 Codex/用户批准该临时偏离（relation 暂时作为迁移入口），等规章制度页迁移完成后回归基线？还是在规章制度迁移完成前保留旧 redirect/隐藏语义？未决定前保持当前实现不动。

### 2. 普通新增 `department` 不被既有 `/departments/tree` 返回

**事实**：浏览器与 API 双重验证（`regression_s5_crud.json` 第 2 项 `部门树可见新增部门=false`）：
- 普通新增 `department`（非班组命名、无 `org_unit_id`）→ 后端 `departments/tree` 接口**不渲染**（web端端既有实现，第 1 步仅渲染 `hse_org_unit` + 第 2 步按正则筛选 `department` 班组节点）。
- UI 仍显示「新增根部门/新增子部门」按钮，创建成功仅刷新树（无效）。

**当前取舍**：未擅自改 `server/routes/hse-employee.js` 的树构建逻辑，也未在前端猜测挂载位置。

**所需决定**：组织管理树是否应展示全部 `department` 实体？若是，需单独授权服务端树语义修正（添加 department 表全量节点或前端合并规则）。

### 3. `safety_manager` 无可用账号

**事实**：`_` 库仅 1 行（admin，`SELECT id, username, role FROM users`）；自签 `role=safety_manager` JWT 被后端 `middleware/auth.js` 校验拒绝（`checkUser` 查库 `id=999` 不存在 → `status: deleted` → 401）。

**当前取舍**：未创建账号、未直接改库、未伪造 JWT。

**所需决定**：用户提供可用的非生产 `safety_manager` 账号，或明确授权创建并清理非生产测试账号，再补做真实双角色浏览器回归。
