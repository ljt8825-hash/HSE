# 阶段 06B-1 Codex 审核

> 审核对象：`阶段06B-1-执行总结.md` 及 `apps/web-naive` 中本批新增的现场管理 API、路由和 3 个页面。
>
> 审核日期：2026-08-17
>
> 结论：**不通过。06B-1 有业务功能回归，完成修复并重审前不得开始 06B-2。**

## 已确认正确

- `hse-site.ts` 保留了 `HseSite`、3 个基线路由 name/path、`authority: ['admin']` 和 order 6；没有修改 `routes/index.ts`、`ignoreAccess` 或 `publicRoutes`。
- 两个 Naive API 适配层使用了既有 URL/HTTP 方法，通用导入模块标识为 `violation`、`fire-facility`、`grid`。
- 三页使用 Naive/Vben/HSE 公共组件，`web-naive/src` 未发现 `ant-design-vue` 引用。
- 网格“三违记录”入口、mock 抽屉和“未入库”标识得到保留，且没有调用未实现的 `/violations/by-grid`。
- 本轮独立执行 `pnpm --filter @vben/web-naive run typecheck`，结果为 **EXIT=0**。

## 阻断项

### P1：三违管理丢失统计分析与多项原有业务字段

旧版在 `views/violations/index.vue` 中存在“统计分析”入口及员工、高风险人员、部门排行、岗位排行 4 个统计接口/页签；新页和 `api/hse/violations.ts` 均未迁移它们。执行总结将其列为“未实现”，但 06B-1 任务要求保留旧版实际业务功能，不能将其降级为后续项。

新建/编辑表单还遗漏发生时间、违章人身份证号、违章人/检查人/处理人/处罚人 ID、处罚类型/金额、整改措施、复训标志等旧版字段。整改弹窗虽然保留了 `handlerId`，但仅允许手填数字 ID，既未复用旧版的人员选择器，也未按旧版要求将该项设为必填；这不等同于恢复处理人员选择。这会导致编辑保存覆盖或无法维护已有业务数据。

### P1：消防设施的站点花名册关联与导入后匹配校验被删除

旧版依据安装位置加载对应转运站花名册、自动带出负责人电话、提示关联结果，并在导入后执行负责人-花名册匹配校验、展示不匹配明细和下载 CSV。新页只提供全局人员搜索，未实现站点关联、电话回填、匹配校验和不匹配记录下载。

执行总结也承认该功能未复刻；这与“保留负责人/站点关联校验”的任务要求冲突。

### P1：网格表单改变原有枚举并丢失统计筛选联动

旧版网格状态为“在岗/离岗/休假/调整”，风险等级为“重大风险/较大风险/一般风险/低风险”，默认状态为“在岗”。新页改为“正常/停用”和“高/中/低”，会写入不同业务值且无法正确标识既有状态。

此外，旧版将当前年/月传入 `getSiteStats(params)`；新页在查询后调用无参数 `getSiteStats()`，导致完成率统计卡与年/月筛选不一致。新页还把仅供旧版表单展示的 `gridPersonnel` 作为 API 类型字段并随保存 payload 发送，而旧版会在保存前删除该临时字段。

### P1：消防和网格显示了无实现的“导出”按钮

`HseActionBar` 未传 `export.hidden` 时默认显示“导出”。消防和网格页面均以空 `actionState` 渲染该组件，且未绑定 `@export`，按钮点击无任何行为。这违反“无对应能力则隐藏动作”的强制规范，也与执行总结“只显示真实支持动作”不符。
