# HSE Naive UI 强制设计约束

本文件是 HSE Naive UI 改版的唯一强制规则源。任何参与该改版的 AI 或开发者必须在开始工作前完整阅读本文件、`00-Naive-UI-HSE总体实施计划.md` 和最近一期 Codex 审核文档。

如任务描述与本文件冲突，以本文件为准；无法判断时必须停止实现，在执行总结中记录冲突并等待 Codex 决策。

## 1. 技术与变更边界

- 目标应用仅为 `安全看板vben/apps/web-naive`。
- 仅使用 Vben、Naive UI、VXE Table 和项目既有依赖；不得引入第二套 UI 框架，不得在 `web-naive/src` 引用 `ant-design-vue`。
- 未获某阶段任务书明确授权，不得修改 `apps/web-antd`、`server`、SQL、数据库、后端接口、锁文件或依赖版本。
- 不得删除既有文件或进行无关重构；保持改动小、可读、可回退。
- 每阶段完成后必须停止，不得自行进入下一阶段。

## 2. 信息架构与业务边界

- 保留当前 HSE 11 个一级菜单、二级菜单、中文名称、顺序、路由语义、权限和业务功能。
- 不以 UI 改版为由合并、删除、重命名菜单或改变业务流程。
- API、数据库字段、导入模板与审批规则保持不变；若某项功能需要服务端支持，必须在任务书中明确授权。

## 3. 视觉与主题

- 使用 HSE 语义色，不在页面或公共组件散落硬编码色值：绿色为主色/成功，蓝色为信息，橙色为预警，红色为风险/危险操作，灰色为普通/草稿。
- 页面内组件与离散 UI（message、notification、dialog、modal、loadingBar）必须使用同一主题令牌，且亮色/暗色模式一致。
- 不复制通用 Dashboard 的营销式版面；HSE 页面应保持紧凑、可扫描、适合高频业务操作。
- 所有新增图标使用项目既有 Lucide 图标体系；图标按钮必须提供 tooltip。

## 4. 页面与操作规范

- 列表页结构固定为：标题/面包屑、筛选区、可选统计概览、操作工具栏、数据表格或业务主体。
- 工具栏动作顺序固定：刷新、下载模板、导入、导出、新增。
- 新增是唯一 primary 按钮；无对应能力则隐藏动作，不保留空位。
- 操作列顺序固定：查看、编辑、删除；按权限显示，删除使用危险语义和二次确认。
- 新增、编辑使用统一表单抽屉或弹窗；查看详情优先抽屉；复杂大弹窗可拖动，普通确认弹窗不可拖动。

## 5. 表格规范

- 所有业务表格后续统一通过 `HseDataGrid + VXE Table` 实现。
- 表头文字和排序图标居中；长文本单行省略并悬停展示完整内容。
- 单元格按语义对齐：长文本左对齐；日期、数值、状态、风险等级和操作列居中。
- 仅编号、日期、数量、金额、状态、风险等级、完成率等可比较字段支持排序。
- 排序必须为服务端三态排序：升序、降序、取消排序并恢复默认业务顺序；不得只排序当前分页数据。
- 不提供表格列宽拖动、表格列顺序拖动或用户自定义列宽。

## 6. 双列、响应式与导入

- 双列布局只用于“目录/树选择对象，右侧处理详情或列表”的页面。
- 双列页面允许拖动中间分隔条：默认左侧 `280px`，可调范围 `220px-420px`，仅保存当前浏览器偏好。
- 小屏幕必须自动转为“目录抽屉 + 主内容”；全局侧栏不得允许用户拖动调宽。
- 导入文案统一为“下载模板”和“导入”，禁止使用“导入数据”等替代文案。
- 导入流程固定：下载模板、上传文件、解析/校验预览、确认导入、导入结果。

## 7. 交付、验证与审核

- 每一阶段的任务书和执行总结必须存放在 `G:\hse-dashboard\docs\Naive UI`。
- 执行总结必须逐项说明完成情况、变更文件、验证命令及真实结果、风险和下一阶段建议。
- 每阶段至少执行目标应用的 typecheck 和 production build；前端组件改动还必须进行对应的浏览器或响应式手工验证。
- 未经 Codex 审核明确通过，不得进入下一阶段。
