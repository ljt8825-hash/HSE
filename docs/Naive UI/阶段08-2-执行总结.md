**path 无重复**（跨文件 0 对）。

### 2.3 处置（与提示词 §3.2 一致：保持不动，仅记录在案）

- 4 对重名**全部保持不动**，未改任何 name/path/authority。
- 理由（与 HseIot/HseSupplyChain 同一判定链）：
  1. **基线同源**：web-antd 的 `hse-01-overview.ts` 与 `hse-advanced.ts` / `hse-center.ts` 存在完全同构的重名（上表右列），web-naive 忠实迁移，改名会偏离「基线 name 1:1」原则；
  2. **无编程式导航引用**：`rg "push\(\{name:...Hse(Iot|SupplyChain|Alerts|Notifications)"` → 0；
  3. **hideInMenu 已缓解可见重复**：4 个隐藏路由均 `hideInMenu:true`，侧栏不重复；
  4. **keep-alive include 无实质歧义（本批实测评估）**：
     - KeepAlive `:include="getCachedTabs"`（`packages/effects/layouts/src/basic/content/content.vue`）按**组件 name** 匹配；`cachedTabs` 来自 `tabbar.ts` 的 `cacheMap`（**Set 去重**，name 只存一次）；
     - 重名两路由指向**同一组件文件**且 `defineOptions({name})` 相同（iot/supply-chain/alerts/notifications 均已核）；
     - `<component :key="getTabKey(route)">` 的 key 由 `fullPath/path/pageKey` 生成（`tabbar.ts:712`，**非 name**）→ 两路由实例在 KeepAlive 内部**各自独立缓存**，无互相覆盖；
     - 结论：name 重名在 keep-alive 场景无实际功能影响。
- **建议（不实施）**：若未来需彻底消除重名，可在 hse-advanced.ts / hse-center.ts 的隐藏路由上改 name（如 `HseIotAdvanced`/`HseAlertsCenter`），但将偏离基线 1:1，且需同步核对 `defineOptions({name})` 与 tabbar 缓存语义 —— **转用户另行授权，本批不改**。
