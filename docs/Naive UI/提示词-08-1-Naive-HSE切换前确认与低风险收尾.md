## 二、Part 1 —— 附条件① N1 复测（验证性，唯一优先）

> 背景：`hse-system.ts` 三个子路由 `meta.authority` 均为 `['admin']`，但阶段 07 回归里 `/system/roles` 可达、`/system/users` 与 `/system/audit` 跳登录，`/system` 父重定向亦跳登录。「性能缺 `accessCodes`」的归因不自洽，须复测定位。

要求：

1. 用**携带正确权限码**的测试 token（具备完整 admin `accessCodes` 或等价权限），复测以下三路由的可达性：
   - `/system`（父，redirect `/system/users`）
   - `/system/users`（用户管理）
   - `/system/audit`（审计日志）
2. 断言每路由：**是否跳登录 / 是否 404 / 是否 `Failed to resolve component` / 是否 console error / 正文是否渲染**。
3. 结论三选一，并给出证据：
   - (a) **均正常渲染** → N1 判定「基线同源·测试 token 权限假象」得到证实，附条件①闭环，记录使用的 token 权限来源（脱敏）。
   - (b) **仍跳登录** → 进一步定位是「路由注册顺序 / `keepAlive` 差异 / users 与 audit 视图内部守卫」所致，把 N1 从「等价」降级为「待修复」，并在执行总结里给出根因与最小修复建议（**仅建议，不实施**，除非用户本批授权）。
   - (c) 若环境确实无法取得正确 token 完成实测 → **如实声明「N1 复测未闭环」**，不得把 07 的推断当作已证，转用户另行授权测试账号。
4. 红线：本任务**不改任何源码**；只读复测 + 记录。

## 五、Part 4 —— 决策项 #7：风险地图风险集 `pageSize:500` 截断

> 现状：`views/risk-control/map.vue:754` `getRiskList({ page: 1, pageSize: 500 })`，若生产风险总数 >500 将截断。

要求：

1. **先确认生产风险总数**：读取后端风险列表总数接口（只读），确认是否 >500。若无法取得生产真实数据，则以当前后端可观测到的最大总数说明，并标注「未经生产确认」。
2. **分支处置**：
   - 若 ≤500 → 现状不截断，无需改动，记录结论即可。
   - 若 >500 → 改为全量加载。优先**前端**方案（如调大 `pageSize` 至后端单页上限、或循环拉取合并）；**凡涉及改后端 `server/` 或分页契约的，本批一律不擅自实施**，仅给出方案并 STOP 说明「需单独后端授权」。
3. 红线：**不改 `web-antd`、后端 `server/`、SQL、`package.json`、锁文件**；若判断「改前端无法闭环、必须动后端」，立即停止并在执行总结里转为待授权项，不得越权。
4. 验收：改动后 `map.vue` 能渲染完整风险集（如有数据可验证）；`typecheck` 通过；无 antd 引入。
