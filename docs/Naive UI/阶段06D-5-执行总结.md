## 四、API 契约核验结论

### 4.1 新建 `api/hse/system.ts`
对照 web-antd 基线 `api/hse/system.ts` 逐一建立，请求方法 / URL / 参数 / 返回结构一致：
- **用户**：`getUserList` / `getUserDetail` / `createUser` / `updateUser` / `deleteUser` / `updateUserStatus` / `resetPassword`（全部 `GET|POST|PUT|DELETE /core/users...`）
- **角色**：`getRoleList` / `getRoleDetail` / `createRole` / `updateRole` / `deleteRole`（全部 `/core/roles...`）
- **菜单**：`getMenuList` / `createMenu` / `updateMenu` / `deleteMenu` / `getRoleMenus` / `assignRoleMenus`（全部 `/core/menus...`）
- 附加视图所需类型 `UserStatus` / `UserFormData` / `RoleFormData`（基线 `UserItem.status` 为内联联合类型，缺 `UserStatus` 别名，视图引用 `SystemApi.UserStatus` 故补齐）。

### 4.2 后端契约（只读核对，`server/app.js`）
- `app.use('/api/core/users', usersRoutes)`、`/api/core/roles`、`/api/core/menus` 均挂载 ✅
- 即现有 `core/system.ts` 端点有效，新建 `hse/system.ts` 复用同一契约，与 web-antd 生产版一致。

### 4.3 视图 API 引用整流
- `views/system/users/index.vue`、`views/system/roles/index.vue` 由 `#/api/core/system` 改为 `#/api/hse/system`；符号（`getUserList`/`createUser`/`updateUser`/`deleteUser`/`updateUserStatus`/`resetPassword` 及 `getRoleList`/`createRole`/`updateRole`/`deleteRole`/`getMenuList`/`getRoleMenus`/`assignRoleMenus` + `SystemApi`）在新建文件中均导出 ✅。
- `views/security/audit/index.vue` 沿用 `#/api/hse/audit`（`getAuditLogs`/`exportAuditLogs`/`getAuditStats`，端点 `/hse/audit/logs`·`/hse/audit/stats`·`/hse/audit/export`），与 `server/routes/audit.js` 一致 ✅。

### 4.4 已知后端怪癖（保持与基线一致，未改）
`getRoleMenus` 路径为 `/core/roles/${id}/core/menus`（双重 `/core`），与 web-antd 基线完全相同；后端日志曾见该路径 404，属历史遗留，本次镜像基线行为、不动服务端。
