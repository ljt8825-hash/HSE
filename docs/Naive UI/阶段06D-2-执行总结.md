## 四、视图迁移结论（基线行为逐项对齐）

### 1. `employee-import-v2/index.vue`（`name: 'PersonnelImport'`）

- **工具栏**：`HseActionBar` 固定顺序（刷新/下载模板/导入）+ 状态筛选 `Select` + `重置` + `更多操作` NDropdown（`canClearAll` 时显「清空人员信息」danger 选项）。

- **入库结果**：`NResult`（`failedCount>0 → warning`，否则 `success`），subTitle 展示 inserted/updated/assignment/失败记录。

## 五、修复的运行时缺陷（验证中发现并修复）

> ⚠️ **重要发现：基线迁移时遗留的真实 bug**

`employee-import-v2/index.vue` 最初使用 `import { useDialog } from 'naive-ui'`，但应用根 `app.vue` **只挂载 `NConfigProvider + NNotificationProvider + NMessageProvider`，未挂载 `NDialogProvider`**。浏览器加载 `/personnel/import` 时 `useDialog()` 在 setup 抛 `[naive/use-dialog]: No outer <n-dialog-provider /> founded`，导致组件渲染失败、页面整片空白。

**修复**：改用应用既有的离散 API 规范——`import { dialog } from '#/adapter/naive'`（该模块通过 `createDiscreteApi(['message','dialog','notification','loadingBar','modal'], { configProviderProps })` 导出全局可用 dialog）。`useMessage()` 保持不变（message provider 存在）。修复后浏览器验证：导入页完整渲染，标题/工具栏/列表/API 全部正常。

> 🔍 **跨文件遗留隐患**（不在本批允许范围，需后续批次处理）：`apps/web-naive/src/views/hse/reports/index.vue:65` 同样使用 `useDialog()`，在启用报表页时大概率也会触发同一 `n-dialog-provider` 报错。建议在下批 06D-3/06D-4 一并按本批规范替换为 `#/adapter/naive` 的 `dialog`。
