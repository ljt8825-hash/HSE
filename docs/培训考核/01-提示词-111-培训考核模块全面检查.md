# 提示词-111：培训考核模块全面检查

## 背景

"人员管理"菜单（提示词-78~110）已全线竣工。现在进入左侧菜单中下一个顶层模块：**培训考核**。

从人员管理模块的经验来看，该模块大概率存在同类问题：
1. **camelKeys 键名错位**：后端 `camelKeys()` 返回 camelCase，前端 `dataIndex` 使用 snake_case → 列表列空/筛选失效
2. **数据依赖**：培训记录关联 `employee` 表，需验证与花名册的数据一致性
3. **字段映射**：加密字段（身份证/电话）的显示处理

## Task 2：培训管理模块检查

### 2.1 检查点

1. **列表页字段显示**：培训名称、培训类型、培训日期、参与人数、状态等列是否正常显示
2. **字段映射**：是否存在 camelKeys 键名不匹配（对比后端返回 → 前端 dataIndex）
3. **搜索/筛选**：搜索、筛选是否正常
4. **分页**：分页功能是否正常
5. **与花名册交互**：培训记录是否关联员工（通过 `employee_id`），数据是否一致
6. **详情/操作**：详情、新增、编辑、删除功能是否正常

### 2.2 检查方法

1. 浏览器打开培训管理页面 → 确认列表有数据
2. Network 面板 → 查看 API 返回的字段名 → 对比前端 dataIndex
3. 检查后端 `training.js` 中所有 `camelKeys()` 调用
4. 测试搜索、筛选、分页功能
5. 确认培训记录中的员工姓名是否通过 EmployeeName 组件显示（而非纯文本）

### 2.3 常见 camelKeys 问题模式（从人员管理模块总结）

```js
// 问题模式：后端套了 camelKeys()
res.json(success({ list: result.rows.map(camelKeys), ... }, '查询成功'));

// 修复：去掉 camelKeys，直接返回 snake_case
res.json(success({ list: result.rows, ... }, '查询成功'));
```

检查 `training.js` 中所有 `camelKeys` 出现位置，逐一核对前端 dataIndex。

## Task 4：数据一致性验证

### 4.1 培训记录 ↔ 员工数据

```sql
-- 培训记录中引用的员工是否在 employee 表中存在
SELECT COUNT(*) AS orphan_refs
FROM training_record tr
LEFT JOIN employee e ON e.id = tr.employee_id AND e.is_deleted = false
WHERE tr.is_deleted = false AND e.id IS NULL;
```

### 4.2 关键指标

| 指标 | 查询 |
|------|------|
| 培训记录总数 | `SELECT COUNT(*) FROM training_record WHERE is_deleted = false` |
| 涉及员工数 | `SELECT COUNT(DISTINCT employee_id) FROM training_record WHERE is_deleted = false` |
| 考核记录总数 | 待确认表名后补充 |
