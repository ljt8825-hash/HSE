## 二、问题清单

### P1-1【必须修复】stats接口返回的平均完成率被内存值覆盖

**位置**: `server/routes/site-mgmt.js` 第639-677行

**问题描述**:
```js
// 第643-656行：正确从DB动态计算了 avgCompletionRate
if (isConnected()) {
  try {
    const rateMap = await gridCompletionService.getCompletionRateMap();
    const grids = await pool.query(...);
    // ...正确计算出 avgCompletionRate
    avgCompletionRate = rates.length > 0 ? ... : 0;
  } catch (e) { /* 保持内存兜底值 */ }
}

// 第675-677行：BUG！响应时又用内存值覆盖了上面算好的值！
avgCompletionRate: gridAreas.length > 0
  ? Math.round(gridAreas.reduce((sum, g) => sum + (g.completionRate || 0), 0) / gridAreas.length)
  : 0,
```

DB模式下，第643-656行正确算出了动态平均完成率赋给`avgCompletionRate`变量，但第675行响应时直接用内存数据的`g.completionRate`（静态旧值）覆盖了它。这导致：**统计卡片永远显示内存缓存的旧完成率，不会随年/月筛选变化**。

**修复方案**:
将第675-677行改为直接使用已计算好的变量：
```js
avgCompletionRate: avgCompletionRate,
```

### P1-2【必须修复】stats接口不支持年/月参数

**位置**: `server/routes/site-mgmt.js` 第580行左右的stats路由

**问题描述**:
当前 `/stats` 接口不接收 `year`/`month` 查询参数。前端阶段2已添加年/月筛选器，用户切换年/月后期望统计卡片的"平均完成率"随之变化，但后端不会响应筛选。

同时第645行和649行调用 `getCompletionRateMap()` 和 `expectedForFreq()` 时未传year/month，永远默认当前月。

**修复方案**:
1. 在stats路由开头从req.query解构year和month：
   ```js
   const { year, month } = req.query;
   ```
2. 将第645行改为：
   ```js
   const rateMap = await gridCompletionService.getCompletionRateMap(year, month);
   ```
3. 将第649行改为：
   ```js
   const expected = gridCompletionService.expectedForFreq(g.patrol_frequency, year, month);
   ```
4. 内存模式的avgCompletionRate也应考虑年月（但内存模式无检查记录，保持0即可）

### P2-2【记录在案，无需修改】完成率统计粒度说明

当前实现按**grid_id**（网格维度）统计实际检查次数，而非按personnel_name（人员维度）。这是合理的：
- 网格管理页面展示的是网格列表，完成率是网格的属性
- 每个网格配置了巡查频率（patrol_frequency），这是网格的工作要求
- grid_id通过片区/班组+网格等级模糊匹配自动关联
- 按网格统计是行业主流做法

注意：若未来需要"人员维度完成率"（某个人负责多个网格的完成情况），可在personnel_name上加GROUP BY做独立报表，但不在本期范围内。

### P2-3【记录在案，无需修改】全年每日频率近似值

年仅选+每日一次时 expected = 30×12 = 360（实际365/366天），这是可接受的近似值（误差<2%），管理看板场景不需要精确到天。
