## 二、问题清单

### P1 - 序号列分页显示错误（必须修复）

**位置**: `columns` 定义中序号列的 `customRender`

**问题描述**:
```ts
// 当前代码（错误）
{ title: '序号', key: 'index', width: 70, customRender: ({ index }: { index: number }) => index + 1 },
```

翻到第2页时，序号仍从1开始显示，而不是从11开始（pageSize=10时）。这是一个功能性bug。

**参考三违管理正确实现**（`views/violations/index.vue`）：
```ts
customRender: ({ index }: { index: number }) => (pagination.current - 1) * pagination.pageSize + index + 1,
```

**修复方案**: 将序号列的customRender改为与三违管理一致的分页累加逻辑。

---

### P2 - 详情抽屉"负责人"字段显示错误（建议修复，顺手处理）

**位置**: 第249行，详情抽屉中负责人显示

**问题描述**:
```html
<!-- 当前代码（错误，显示的是职务） -->
<span class="detail-value">{{ currentRecord.position || '-' }}</span>
```

此处标签写的是"负责人："，但绑定的是 `position`（职务字段），导致负责人显示的是"网格员"等职务名称而非人名。这是**原有代码遗留bug**，不是本次引入的，但既然在重构该文件，建议一并修复。

**数据模型核查**:
- `SiteApi.GridArea` 接口有 `personnelId: number | null` 但没有姓名字段
- 表单中"负责人"输入框绑定 `gridPersonnel`，但保存时被 `delete (saveData as any).gridPersonnel` 删除了，意味着负责人姓名实际未持久化
- 这是一个数据模型缺陷，但本期不要求解决

**临时修复方案**（阶段1范围内）:
由于后端未存负责人姓名，暂时无法正确显示人名。建议：
1. 方案A（推荐）：将详情中"负责人"标签改为"职务"，避免误导；或
2. 方案B：在后端GridArea模型中添加 `personnel_name` 字段并在表单保存时持久化（这涉及后端改动，建议放到阶段2或后续）

**建议采用方案A**，保持阶段1的改动范围可控。
