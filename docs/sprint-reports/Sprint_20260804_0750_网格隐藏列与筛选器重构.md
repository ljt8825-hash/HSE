**② 筛选器框架升级核心片段**
```ts
import { useDataTable, useSearchForm } from '#/composables/hse';

const {
  loading,
  dataList: gridList,
  total,
  pagination,
  fetchData,
  handleTableChange,
  handleReset: tableHandleReset,
} = useDataTable<SiteApi.GridArea>({
  fetchFn: async ({ page, pageSize }) => {
    const res = await getGridAreaList({
      page, pageSize,
      keyword: searchForm.keyword || undefined,
      gridLevel: searchForm.gridLevel,
      township: searchForm.township,
      status: searchForm.status,
    });
    return { list: res.list || [], total: res.total || 0 };
  },
  defaultPageSize: 10,
});

const { form: searchForm, reset: resetSearch } = useSearchForm<{
  keyword: string; gridLevel: string | undefined;
  township: string | undefined; status: string | undefined;
}>({
  defaults: { keyword: '', gridLevel: undefined, township: undefined, status: undefined },
  onSearch: () => tableHandleReset(),
});
```

## 7. 风险评估

- **低风险**：本次为前端单文件改造，未触及后端、数据库、API 契约；`GridArea` 接口与后端响应结构未变，向后兼容。
- **回归风险（低）**：筛选器从手动模式切换为 composable，逻辑等价；已对齐三违管理同款模式。唯一差异点是 `useDataTable.handleReset` 仅重置 `current=1`（不重置 `pageSize`），与原 `handleReset` 行为一致，无副作用。
- **构建风险（低）**：`useSearchForm` 的 `reset()` 内部执行 `Object.assign(form, defaults)`，会将 `gridLevel/township/status` 置为 `undefined`，Select 的 `allow-clear` 可正常反映空值；已确认模板 Select 均带 `allow-clear`。
- **注意事项**：因 `useDataTable` 的 `fetchData` 内部 `catch` 不再手动 `message.error`（交由请求拦截器统一处理），与原 `fetchList` 的 `message.error($t('hse.message.fetchFailed'))` 行为略有差异——失败时提示文案可能变化，属预期的架构统一，已在报告中记录以便评审。
