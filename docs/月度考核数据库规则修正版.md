## 二、hse_responsibility_chain 表规则

### 2.1 表结构

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGSERIAL | 主键 |
| `subordinate_id` | BIGINT | 下级ID（违规者） |
| `subordinate_name` | VARCHAR(50) | 下级姓名 |
| `subordinate_post` | VARCHAR(50) | 下级岗位 |
| `manager_id` | BIGINT | 上级ID（直属管理者） |
| `manager_name` | VARCHAR(50) | 上级姓名 |
| `manager_post` | VARCHAR(50) | 上级岗位 |
| `township` | VARCHAR(50) | 乡镇 |
| `relation_type` | VARCHAR(30) | 关系类型（固定 `direct_supervisor`） |
| `chain_level` | INT | 传导层级（月度考核固定 `1`） |
| `effective_date` | DATE | 生效日期 |
| `is_active` | BOOLEAN | 是否有效 |
| `is_deleted` | BOOLEAN | 软删除标记 |

### 2.2 月度考核限制

| 规则 | 说明 |
|------|------|
| `chain_level` | 月度考核模块固定写入 `1` |
| `relation_type` | 固定写入 `direct_supervisor` |
| `is_active` | 新记录固定 `TRUE` |
| 唯一性 | `subordinate_id + manager_id + is_active=TRUE` 唯一 |

### 2.3 扩展性支持

- 表结构支持 `chain_level > 1`（未来可用于多级传导）
- 表结构支持多种 `relation_type`（如 `indirect_supervisor`、`cross_department`）
- **但月度考核模块代码硬编码 `chain_level = 1`**，确保不会出现多级传导

### 2.4 写入逻辑

```sql
INSERT INTO hse_responsibility_chain
  (subordinate_id, subordinate_name, subordinate_post,
   manager_id, manager_name, manager_post, township,
   relation_type, chain_level, effective_date, is_active, is_deleted)
SELECT $1, $2, $3, $4, $5, $6, $7, 'direct_supervisor', $8, $9, TRUE, FALSE
WHERE NOT EXISTS (
  SELECT 1 FROM hse_responsibility_chain
  WHERE subordinate_id = $1 AND manager_id = $4 AND is_active = TRUE AND is_deleted = FALSE
)
```

- `$8` = `CHAIN_LEVEL` = `1`（代码常量）
- 使用 `WHERE NOT EXISTS` 避免重复写入

## 三、扣分记录表规则

### 3.1 hse_assessment_deduction（扣分明细表）

| 字段 | 类型 | 说明 |
|------|------|------|

| 人工调整 | 不变 | 调整后=新值 |

## 四、调整记录表规则

### 4.1 hse_deduction_adjustment（扣分调整记录表）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGSERIAL | 主键 |
| `deduction_id` | BIGINT | 扣分明细ID |
| `target_id` | BIGINT | 考核对象ID |
| `version_no` | INT | 版本号 |
| `old_score` | NUMERIC(6,2) | 旧分值 |
| `new_score` | NUMERIC(6,2) | 新分值 |
| `operation_type` | VARCHAR(30) | 操作类型 |
| `adjustment_reason` | TEXT | 调整原因 |
| `adjusted_by` | BIGINT | 调整人ID |
| `adjusted_by_name` | VARCHAR(50) | 调整人姓名 |
| `adjusted_at` | TIMESTAMPTZ | 调整时间 |
| `is_current` | BOOLEAN | 是否当前版本 |

### 4.2 INSERT-Only 模式

```sql
-- 触发器：禁止UPDATE和DELETE
CREATE TRIGGER trg_prevent_adjustment_update
    BEFORE UPDATE OR DELETE ON hse_deduction_adjustment
    FOR EACH ROW
    EXECUTE FUNCTION prevent_adjustment_modify();
```

- **仅允许INSERT**，禁止UPDATE和DELETE
- 每次调整新增一条记录，保留完整历史
- 版本号 `version_no` 每次递增（1, 2, 3, ...）

### 4.3 唯一索引

```sql
CREATE UNIQUE INDEX idx_adjustment_version_unique 
ON hse_deduction_adjustment (deduction_id, version_no);
```

- 同一扣分明细的版本号唯一
- 防止重复调整记录

### 4.4 版本记录流程

```
1. 查询扣分明细 → 获取 current_version
2. 新版本号 = current_version + 1
3. INSERT 调整记录（version_no=新版本号, old_score=旧值, new_score=新值）
4. UPDATE 扣分明细（current_version=新版本号, confirmed_score=新值, review_status='adjusted'）
```

## 六、冻结保护规则

### 6.1 冻结触发器

```sql
-- hse_assessment_target 冻结保护
CREATE TRIGGER trg_prevent_frozen_target
    BEFORE UPDATE ON hse_assessment_target
    FOR EACH ROW
    EXECUTE FUNCTION prevent_frozen_target_modify();

-- 函数逻辑
IF OLD.status = 'frozen' THEN
    RAISE EXCEPTION '已冻结的考核对象记录不可修改';
END IF;
```

### 6.2 冻结流程（修正后）

```
1. 检查所有对象 review_status = 'approved'
2. 计算乡镇内排名 → UPDATE rank_township（此时未冻结）
3. 计算全局排名 → UPDATE rank_all（此时未冻结）
4. 设置周期状态 = 'frozen'
5. 设置所有对象状态 = 'frozen'
6. 更新 frozen_count
```

**关键修正**：先排名后冻结，避免触发器阻止排名更新。

### 6.3 冻结后保护

| 操作 | 保护机制 | 错误信息 |
|------|----------|----------|
| 修改扣分 | 代码检查target.status | 已冻结的对象不可修改扣分 |
| 添加扣分 | 代码检查target.status | 已冻结的对象不可添加扣分 |
| 调整扣分 | 代码检查target.status | 已冻结的对象不可调整 |
| 修改对象 | 数据库触发器 | 已冻结的考核对象记录不可修改 |
| 修改调整记录 | 数据库触发器 | 扣分调整记录表仅允许INSERT |

## 十、冻结声明

本数据库规则修正版自2026-07-24起冻结：

1. `hse_responsibility_chain` 表支持扩展，但月度考核限制 `chain_level=1`
2. `hse_deduction_adjustment` 表为INSERT-Only，不可篡改
3. `hse_assessment_audit_log` 表为INSERT-Only，不可篡改
4. 冻结保护通过代码检查和数据库触发器双重保障
5. 冻结流程先排名后冻结，避免触发器冲突

作为后续前端开发、接口联调、正式测试的唯一依据。
