## 8. 行级数据范围语义

| scope | 触发角色 | SQL 行为 |
|-------|----------|----------|
| `all_grid` | 平台级高权限角色 | 无额外限制（`buildScopeSqlCondition` 返回 null） |
| `own_grid`（有网格） | grid_inspector / manager | `grid_id IN (SELECT id FROM grid_areas WHERE personnel_id=$n AND is_deleted=false)` |
| `own_grid`（无网格）/ `none` | 未绑定 / 未识别角色 | `'1 = 0'`（不可见任何记录，fail-closed） |

范围只由「认证用户 + `users.role` + 后端配置」决定，前端不得传 `scope` 作为授权依据。

## 9. GET 行级范围实现（`routes/site-mgmt.js`）

- 在 `const conditions=[]` 之后注入 `resolveGridScope` + `buildScopeSqlCondition`，条件进 `WHERE`。
- **置于 WPS 分支 return 之后**，故仅作用于 PG/memory 分支（WPS 行级 scope 延期，见 §16）。
- 历史 `grid_id IS NULL` 记录因不满足 `grid_id IN (...)`，对 `own_grid` 自然不可见（不靠姓名/编号补偿）。

## 10. PUT 行级范围实现

- `UPDATE ... WHERE id=$n ${scopeClause} RETURNING *`；scope 条件直接进 WHERE。
- 0 行且非 `all_grid` → `403 SCOPE_DENIED`（禁止「先 UPDATE 再判断」越权）。
- 白名单字段：`areaTeam` 等（PUT 用 snake_case 口径，与 POST 的 camelCase 不一致——已知坑，已规避）。

## 11. DELETE 行级范围实现

- `DELETE FROM grid_inspection_records WHERE id IN (${placeholders})${scopeClause}`，scope 进 WHERE，**禁止先删后判**。
- `own_grid` 删他人记录 → 0 行影响（`deleted=0`），由 scope 拦截。
- 验证见测试 D1/D2/D3。

## 12. DELETE ALL 三层保护（保持不变）

`requirePermission('hse:site:grid:purge')` → `requireRole('system_admin','admin')` → `body.confirmText === '清空全部台账'`，PG/WPS 双分支同等生效，本阶段未改动。

## 13. grid_id 后端派生（fail-closed）

POST 分支（`dsCreate==='pg'`）逻辑：
1. 剥离客户端 `body.gridId` / `body.grid_id`（前端不可决定）。
2. `authenticatedEmployeeResolver` 解析身份（失败即拒）。
3. `deriveGridIdForEmployee(employeeId)`：
   - 0 个 live grid → `403 NO_GRID_FOR_EMPLOYEE`
   - 1 个 live grid → 使用派生 `gridId`
   - >1 个 live grid → `409 MULTIPLE_GRIDS_FOR_EMPLOYEE`（禁猜测）
4. 仅 `isConnected()`（连接态）执行；内存降级不设置 `grid_id`（DB 不可用兜底）。
5. `inspector_employee_id` 恒等于 `resolver.employeeId`（后端派生）。

## 14. inspector_employee_id 防覆盖

POST/PUT 均剥离客户端提交的 `inspectorEmployeeId` / `inspector_employee_id`（camel + snake 双向）；身份恒由后端按 `employee_id` 反查，禁姓名兜底。测试 E2/C6/F2 验证不可覆盖。

## 15. 前端 grid_id 忽略

前端提交的任何 `gridId` / `grid_id` 在后端一律剥离；正式 `grid_id` 由后端派生。响应 `formatGridInspectionRow` 输出 `gridId`（camelCase）但**不暴露** `inspector_employee_id`。
