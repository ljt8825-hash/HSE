### 3.2 状态流转

#### 考核周期状态
```
not_started（未开始）
    ↓ 启动
in_progress（进行中）
    ↓ 执行评分
pending_review（待审核）
    ↓ 审核完成
reviewed（已审核）
    ↓ 冻结
frozen（已冻结）
```

#### 扣分状态
```
pending（待审核）
    ├─→ approved（已确认）
    │       ↓ 调整
    │     adjusted（已调整）
    └─→ rejected（已驳回）
    
调整后可再次审核，版本号递增

frozen（已冻结）：周期冻结后自动冻结
```

## 四、核心业务逻辑

### 4.1 评分引擎
- **基础分：** 100分（各项指标基础分之和）
- **数据来源：** 三违记录、隐患整改、培训记录（已适配实际表结构）
- **手动评分保护：** 自动评分不覆盖手动评分记录
- **版本管理：** 每次评分版本号递增

### 4.2 三违责任传导
- **传导规则：** 三违人员 → 直属上级（一级）
- **传导比例：** 50%（扣分值的一半）
- **禁止多级传导：** 仅传导一级
- **自动识别：** 通过 v_employee_org_full 视图的 supervisor_id 动态获取

### 4.3 扣分审核
- **审核权限：** 审核角色可操作
- **审核类型：** 通过 / 驳回 / 调整
- **调整机制：** 生成新版本，旧版本保留
- **审计留痕：** 所有审核操作记录日志

### 4.4 版本管理
- **调整记录表：** hse_deduction_adjustment
- **防篡改：** 触发器禁止 UPDATE 和 DELETE
- **版本号：** 每次调整版本号 +1
- **历史追溯：** 完整记录修改前/修改后/原因/操作人/时间

### 4.5 冻结机制
- **冻结条件：** 所有对象审核通过
- **冻结后限制：** 禁止直接修改扣分、评分
- **解冻：** 预留接口（需特殊权限）
