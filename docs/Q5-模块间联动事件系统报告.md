## 二、校验脚本说明

> 文件：`apps/web-antd/scripts/validate-employee-deps.mjs`
> 运行：`node scripts/validate-employee-deps.mjs`（从 `apps/web-antd` 目录）
> 依赖：仅 Node.js 内置 `fs` / `path` / `url`，无第三方包；退出码 通过 → 0 / 失败 → 1

**逻辑（Q5 §3）：**
1. **扫描**：`findDepsFiles` 递归遍历 `src/views/**/employee-deps.json`（采用递归而非 `src/views/*/` 单层，以覆盖嵌套模块如 `hse/assessment-monthly`）。
2. **JSON Schema 校验**：
   - 顶层键仅允许 `module` / `dependsOn` / `provides`
   - `dependsOn` 内部仅允许 `employeeFields` / `events` / `queries` / `components`
   - `provides` 内部仅允许 `employeeStats` / `events`
   - 任何未声明键名即报错
3. **完整性校验**：
   - 8 个核心模块（硬编码 EXPECTED_MODULES）须全部存在
   - `dependsOn.employeeFields` 至少含 `employeeId` / `employeeName`
4. **一致性校验**：
   - `dependsOn.events` 元素须 ∈ 4 种枚举（`EMPLOYEE_TRANSFERRED` / `EMPLOYEE_RESIGNED` / `EMPLOYEE_STATUS_CHANGED` / `EMPLOYEE_INFO_UPDATED`）
   - `dependsOn.components` 元素须 ∈ `{EmployeeSelector, EmployeeName}`
   - `module` 字段值须与文件所在目录末级名（`basename`）一致
5. **输出**：校验通过打印 `✅ 8/8 modules valid` + Markdown 依赖关系矩阵；失败打印逐条错误与原因。

> 注：首版脚本因 JSDoc 注释中含 `src/views/**/employee-deps.json`（`**/` 内 `*/` 提前闭合块注释）导致语法错误，已将注释改写为 `src/views（含子目录）` 规避，已复测通过。

## 四、事件驱动缓存刷新集成详情

### 4.1 useEmployeeData.ts 增强（Q2 §3.1 / Q5 §4.1）

> 文件：`apps/web-antd/src/composables/hse/useEmployeeData.ts`

在 `useEmployeeData` 内订阅 `useEmployeeEvent` 总线：

```ts
import { ref, onUnmounted } from 'vue';
import { getEmployeeSelectorBatch } from '#/api/hse/employee-selector';
import { mapSelectorToInfo, type EmployeeInfo } from './types';
import { useEmployeeEvent } from './useEmployeeEvent';   // 新增，无循环依赖

const EMPLOYEE_EVENT_TYPES = [ /* 4 种事件 */ ] as const;

export function useEmployeeData(employeeId: number): UseEmployeeDataReturn {
  // ... employee / loading / error / fetchData / refresh 不变 ...

  // Q5：订阅员工变更事件
  const { subscribe } = useEmployeeEvent();
  const unsubscribe = subscribe([...EMPLOYEE_EVENT_TYPES], (event) => {
    try {
      if (cache.has(event.employeeId)) {
        cache.delete(event.employeeId);          // 失效缓存，下次访问重新拉取
        if (employeeId === event.employeeId) {
          void refresh();                          // 当前正展示该员工 → 响应式刷新
        }
      }
    } catch (e) {
      console.error('[useEmployeeData] 事件处理异常:', e);  // 单 handler 异常不阻断其他订阅者
    }
  });
  onUnmounted(unsubscribe);   // 组件卸载取消订阅，避免泄漏
  // ...
}
```

**要点（满足 Q5 §4.1 要求）：**
- 事件驱动失效**仅当缓存已存在该 employeeId** 时触发，避免无效刷新。
- 若当前组件正展示该员工（`employeeId === event.employeeId`），调用 `refresh()` 触发响应式更新。
- 事件处理 `try/catch` 包裹（且 `publishEmployeeEvent` 全局已对 handler 做异常隔离）。
- `onUnmounted(unsubscribe)` 确保订阅随组件卸载清理，无内存泄漏。
- **无循环依赖**：仅 `import useEmployeeEvent`（其内部只 `import type` 自 types），未引入 `EmployeeSelector` 等组件。

### 4.2 violations 模块订阅示例（Q5 §4.2）

> 文件：`apps/web-antd/src/views/violations/index.vue`

// Q5：订阅员工变更事件，离职/调岗时刷新违章列表（violatorName 快照可能过期）
