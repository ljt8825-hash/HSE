#### 2. 设计跨模块事件体系

**事件定义**：定义员工数据变更时触发的事件类型

| 事件类型 | 触发条件 | 携带数据 | 消费模块 |
|----------|----------|----------|----------|
| EMPLOYEE_TRANSFERRED | 员工调岗 | employeeId, oldOrgId, newOrgId, oldPosition, newPosition, effectiveDate | 三违/隐患/培训/目标责任书等 |
| EMPLOYEE_RESIGNED | 员工离职 | employeeId, resignDate, lastWorkingDay | 所有关联模块 |
| EMPLOYEE_STATUS_CHANGED | 状态变更（停薪留职/返岗等） | employeeId, oldStatus, newStatus, effectiveDate | 三违/培训/月度考核等 |
| EMPLOYEE_INFO_UPDATED | 基础信息变更（姓名/身份证/联系方式） | employeeId, changedFields[], newValues[] | 所有引用员工姓名的模块 |

**事件规范要求**：
- 每个事件定义：触发时机、携带字段、数据格式、幂等性保证
- 事件消费契约：消费模块需声明的依赖（如"我依赖 EMPLOYEE_TRANSFERRED 事件来更新违章记录中的部门字段"）
- 事件版本管理策略（向后兼容）

#### 3. 设计公共 Composable 函数

基于 Q1 审计发现的代码重复和模式不一致，设计以下公共 Composable：

**3.1 `useEmployeeData(employeeId: string)`**
- 功能：统一的员工数据获取 Hook
- 输入：员工 ID（统一使用 employee_assignment 的 employee_id）
- 输出：reactive 员工信息对象（姓名/部门/岗位/状态/联系方式）
- 缓存策略：模块级缓存 + 全局失效机制
- 替代目标：各模块中散落的 `getEmployeeById()` 直接调用

**3.2 `useEmployeeEvent()`**
- 功能：员工变更事件订阅 Hook
- 输入：订阅的事件类型列表
- 输出：事件回调注册 / 注销
- 联动策略：当收到 EMPLOYEE_TRANSFERRED 事件时，自动刷新关联数据
- 替代目标：模块手动轮询或不做联动

**3.3 `useEmployeeLink(employeeId: string)`**
- 功能：统一的"点击员工姓名跳转档案"交互
- 输入：员工 ID
- 输出：路由跳转函数 + 员工姓名展示组件
- 规范：所有模块中员工姓名展示统一使用此 Composable
- 替代目标：各模块中硬编码的 router.push 或纯文本展示

**3.4 `useEmployeeSearch()`**
- 功能：统一的员工搜索 Composable（封装 EmployeeSelector 逻辑）
- 输入：搜索配置（单选/多选、部门过滤、状态过滤）
- 输出：选中员工列表、搜索状态、错误处理
- 替代目标：各模块中重复的搜索表单逻辑

**每个 Composable 需产出**：
- 接口签名（TypeScript 类型定义）
- 参数说明
- 返回值说明
- 使用示例（基于真实模块场景）
- 与现有代码的兼容性说明

#### 5. 设计 API 规范标准

**5.1 员工查询接口规范**：
- 统一请求参数格式：`{ employeeIds?: string[], keyword?: string, deptId?: string, status?: string, page?: number, pageSize?: number }`
- 统一响应格式：`{ total: number, list: EmployeeInfo[], page: number, pageSize: number }`
- 统一 EmployeeInfo 类型定义（字段名/类型/必填）

**5.2 批量查询优化**：
- 针对 Q1 发现的 N+1 查询问题，设计批量查询接口 `getEmployeesByIds(ids: string[])`
- 使用场景：列表页中需要展示关联员工姓名时，一次性批量获取
- 缓存策略：前端内存缓存 5 分钟，相同 ID 集合不重复请求

**5.3 员工统计接口规范**：
- 统一各模块中员工统计相关接口（人数/完成率/分布等）
- 统一响应格式

#### 7. 设计模块间数据依赖声明规范

**依赖声明格式**：每个模块在模块根目录放置 `employee-deps.json`：

```json
{
  "module": "violations",
  "dependsOn": {
    "employeeFields": ["employeeId", "employeeName", "deptName", "positionName"],
    "events": ["EMPLOYEE_TRANSFERRED", "EMPLOYEE_RESIGNED"],
    "queries": ["getEmployeesByIds", "getEmployeeStats"],
    "components": ["EmployeeSelector", "EmployeeLink"]
  },
  "provides": {
    "employeeStats": ["violationCount", "violationScore"],
    "events": ["VIOLATION_RECORDED"]
  }
}
```

**依赖声明的用途**：
- 自动化影响分析：当员工模型变更时，自动识别受影响的模块
- 文档生成：自动生成模块依赖关系图
- 回归测试：员工 API 变更时，自动确定需要回归测试的模块范围
