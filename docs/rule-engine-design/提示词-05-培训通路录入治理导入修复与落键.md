## 1. 任务 A：培训导入链路修复（编码 + 人员落键）

1. **编码 bug 诊断与修复**：
   - 对比同日正常的网格/三违导入与培训两个模块（`training`、`培训台账`）的 Excel 读取链路（xlsx/CSV 解析、编码探测、单元格取值），定位培训路径中文变乱码的根因（疑似 GBK/UTF-8 编码处理缺失或读取选项差异）。
   - 修复后用**临时构造的样例文件**（含中文姓名、合格/不合格、培训日期）验证：导入后 name/result/content 中文正常落库。
   - 报告中写明根因、修复点、修复前后对比。
2. **人员落键**（对齐三违导入写法）：两个培训导入模块在写库前，按行解析人员：
   - 有身份证号 → hash 命中 `employee.id_card_hash` 落 personnel_id/employee_id；
   - 否则姓名经 `v_employee_org_full`（is_current=true、is_deleted=false）批量匹配：唯一存活匹配 → 落键并写回标准 name；重名/未匹配 → 保留原文、不落键、不报错；
   - 响应与日志输出 `resolved/ambiguous/unmatched` 统计；
   - conflictKey 在落键后优先用人员 id（避免同名文本冲突），无键行回退原 name 文本键。
3. 样例文件与导入产生的测试数据**验收后清理**（软删或物理删除，报告给清理证据）。

## 2. 任务 B：后端录入接口支持人员落键

2. 新建/编辑接口接收 `employeeId`（或 personnelId）：传入时校验存在于员工主数据，并以员工表为准同步标准 name；未传时按 name+id_card 自动解析（解析结果写库，解析失败保留原文不报错）。

4. 不改动既有字段语义与 OCR 其他逻辑。
