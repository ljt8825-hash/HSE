## 1. 任务 A：调度与周期创建链路只读核查

### 1.1 cron 表达式 / 开关 / 时区实值

| 项 | 实值 | 来源（硬编码 vs .env） |
|---|---|---|
| `CRON_CREATE_CYCLE` | `'30 0 1 * *'` → **每月 1 日 00:30** | `assessmentScheduler.js:24` 常量 |
| `CRON_DAILY_CHECK` | `'0 2 * * *'` → **每日 02:00** | `:25` 常量 |
| `CRON_GRID_CHECK` | `'0 1 * * *'` → **每日 01:00** | `:26` 常量 |
| `CRON_TZ` | `'Asia/Shanghai'` | `:27` 常量 |
| `SCHEDULER_ENABLED` | `true` | `:22` **硬编码常量**（非读 `process.env`） |

⚠️ **发现 A1**：文档称 `SCHEDULER_ENABLED` 受"环境开关控制"，但代码为 `const SCHEDULER_ENABLED = true;`，**不读 `.env`**；cron 表达式与时区亦全部硬编码。要临时停用调度须改代码并重启。

### 1.2 CRON_CREATE_CYCLE 完整逻辑与"上月"语义

核心代码（`initAssessmentScheduler` 内联计算）：
```
const m = now.getMonth();                       // 9/1 → 8（0-based，September）
const prev = new Date(y, m, 1);                 // 9/1
const targetMonth = new Date(prev.getFullYear(), prev.getMonth() - 1, 1); // 8/1（上月）
autoCreateAndSyncCycle(targetMonth.getFullYear(), targetMonth.getMonth() + 1); // → 2026-08
```
即 **CRON_CREATE_CYCLE 创建的是"上月"周期**（与文件头注释"自动创建上月考核周期"一致）。

- **目标对象生成口径**：`autoCreateAndSyncCycle` → `syncAssessmentTargets` 用白名单 `乡镇作业中心经理 / (管理员 AND 乡镇中心) / grid_areas.personnel_id`，与手动建周期 `/cycles/:id/targets/sync` 同一份 SQL，口径一致；写入 `target_count`。
- **幂等性**：按 `cycle_code = HSE-CYCLE-{yyyy}{mm}` + `is_deleted=FALSE` 查重，已存在则 `return {ok:true, skipped:'cycle-exists'}`，**同月重复触发不会建重**。
- **失败重试**：cron 回调内 `try/catch` 仅 `console.error`，**node-cron 无内置补跑**；依赖进程存活。

### 1.3 遍历周期的 WHERE 条件

| 任务 | WHERE 条件 | 对历史周期的影响 |
|---|---|---|
| `runDailyCheck` | `status IN ('in_progress','pending_review','reviewed') AND is_deleted=FALSE` | 历史 `pending_review` 周期**仍被遍历**（库内 Jun/Jul/Aug 均 `pending_review`），每日重算全部对象（幂等、数值不变，但有 ~180 次/日空转与日志噪声）。`frozen` 周期被排除（安全）。 |
| `runGridCheck` | `status IN ('in_progress','pending_review') AND start_time<=NOW() AND end_time>=NOW()` | **仅当前月窗口内的周期**被选；过去月份与未来月份均不匹配 → 无历史周期噪音，但也是"已建周期永不跑网格校验"的根因（见发现 A2）。 |

### 1.4 9 月首跑时间线推演表

| 时间 | 任务 | 实际行为（按当前代码 + 库状态推演） |
|---|---|---|
| 9/1 00:30 | CREATE_CYCLE | `now=9月` → `targetMonth=8月` → 建 `HSE-CYCLE-202608`，但 cycle 24 已存在 → **幂等跳过。9 月周期不被创建。** |
| 9/1 01:00 | GRID_CHECK | 选「窗口含 9/1」的周期：Jun/Jul/Aug 窗口已过、9 月不存在 → **0 周期，安全 no-op**。 |
| 9/1 02:00 | DAILY_CHECK | 选 `pending_review`：Jun/Jul/Aug 命中 → 对约 180 个对象重算（幂等，数字不变）；失败事件重放（无）；超期扫描（无 9 月数据）→ 无新增扣分。 |
| 9 月全月 | 三任务每日 | 因**无 9 月周期**：网格应巡不累计到 9 月窗口、三违窗口（2026-09）无命中、观测无 9 月数据。 |
| 9/30 | （无） | 调度器**无自动冻结**逻辑，周期保持 `pending_review`（见发现 A3）。 |
| 10/1 00:30 | CREATE_CYCLE | `targetMonth=9月` → **首次创建 `HSE-CYCLE-202609`**。但其窗口 9/1~9/30 已过去 → 此后 10 月每日 GRID_CHECK 因 `end_time < NOW()` **永不选它** → 9 月周期建好后也跑不到网格校验。 |

### 1.5 风险清单

- **[高] 发现 A2（同 A1 根因）**：`runGridCheck` 要求 `start<=now<=end`，而 `CRON_CREATE_CYCLE` 在建好的**次月**才创建周期（窗口已过去）。两者语义冲突 → **任何由调度创建的"上月"周期，其网格缺巡扣分永远不会随调度累计**。该缺陷直接导致"9 月完整生命周期"目标在当前代码下无法实现。
- **[高] 发现 A1**：9 月周期截至 8/31 **不存在**，且 9/1 调度不会创建它（只建 8 月并跳过）。若业务期望 9 月周期 9/1 起经历"建周期→累计→冻结"，须**人工在 9/1 前建 2026-09**，或修复 create-cron 的 off-by-one（改建"当月"）。**本轮未改代码**，作为决策项上报（见 §5）。
- **[中] 发现 A3**：无自动月末冻结。周期长期 `pending_review`（库内 Jun/Jul/Aug 实证），`runDailyCheck` 每日对已结束周期重算，幂等无副作用但空转 + 日志噪声。
- **[低] 发现 A4**：`SCHEDULER_ENABLED`/cron/时区硬编码，无 `.env` 开关（见 1.1）。
- **[低] 发现 A5**：进程在 cron 命中的那一分钟宕机则漏跑；重启后 `initAssessmentScheduler` 重新注册（已自动，无碍）。
- **[低] 发现 A6**：create 回调内 `new Date()` 用服务器本地时区，若系统 TZ≠Asia/Shanghai，00:30 边界有月份偏移风险（本机 Asia/Shanghai，无碍）。
