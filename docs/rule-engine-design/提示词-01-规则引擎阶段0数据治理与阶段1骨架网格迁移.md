## 3. 已拍板决策（需求依据，勿自行更改）

1. **本轮范围**：阶段0（地基）+ 阶段1（引擎骨架+网格迁移），零行为变化。
2. **三违分值口径**：以规则库为准——普通三违 1 分/次；"公司查处"的三违 5 分/次。**本轮不实现**（violation_records 无查处来源字段，留阶段2），但代码与报告须登记此口径。
3. **两套分类统一**：考核结果表继续用"指标维度（英文码 HSE-KPI-* / 权重）"算分；规则库"中文大类"专管扣分归类与上限；二者通过规则表 `metric_code` 映射打通。
4. **来源表不存在的规则**：在规则库标注"未接表/待数据"，界面提示"暂不会自动扣分"，不得因"配了规则"而误以为生效。
5. **大类上限**：本轮只对**自动扣分**生效（网格通路已实现钳制，迁移时保留）；人工扣分不强制砍断、仅提示（人工提示本轮不做，登记非目标）。
6. **可观测性**：规则库列表新增两列——"接入状态"（已接入/待数据/未接表/人工）与"最近执行结果"（扫描人数/扣分人数）。

## 5. 阶段1 任务：规则引擎骨架 + 网格通路迁移

### 5.1 新建引擎目录 `server/services/ruleEngine/`

- `ruleLoader.js`：`loadEnabledRules()`、`getRuleByAdapterKey(adapterKey)`——查 `hse_assessment_rule`（`is_deleted=FALSE AND status='enabled'`），返回含 `adapter_key/integration_status/metric_code/category/deduct_type/deduct_score/max_deduct` 的配置对象。
- `adapterRegistry.js`：`registerAdapter(key, adapter)`、`getAdapter(key)`、`listActiveAdapterKeys()`。
- `deductionWriter.js`：把现 `gridUncheckedDeductionService.js` 中的 `findExisting / stableStringify / upsertDeduction / revokeDeduction` **泛化**为通用幂等写入器，参数化：sourceTable、kind、deductKey 生成函数、item（deduction_item）、metricId/metricCode、detail 构建函数。必须完整保留语义：
  - 幂等：按 `target_id+cycle_id+deduction_source='auto'+source_table+source_detail->>'kind'+source_detail->>'deductKey'` 找既有行；
  - 人工锁定（review_status 为 approved/adjusted）不覆盖、不软删，返回 `locked`；
  - 软删行复活（is_deleted=TRUE → 复用并重置 pending）；
  - 分数或明细无变化返回 `noop`；
  - 缺次归零/被钳制为 0 时软删（revoke），锁定行除外。
- `categoryCap.js`：`getCategoryCap(category)` 与 `applyCap(...)`——封装"读取 `hse_assessment_category_limit.max_deduct` + 该对象该类别其他自动扣分合计（复用 `assessmentRuleCategoryService.resolveRuleForDeductionRows`，排除本通路 kind）→ 计算 allowed 与 cappedScore"。**仅自动扣分通路调用**。
- `runLogger.js`：`recordRuleRun({ ruleId, cycleId, scanned, deducted })`——UPDATE 规则 `last_run_at=NOW()/last_run_cycle_id/last_scanned_count/last_deducted_count/last_run_summary='扫描${scanned}人/扣分${deducted}人'`。
- `engine.js`（主编排）：`runCycleAdapters(cycleId, { adapterKeys, dryRun })`：
  1. 周期加载与状态守卫（frozen/not_started → 返回 `{ok:false, reason:'cycle-status-xxx'}`）；
  2. 取年/月（`assessment_year/assessment_month`，回退 `start_time`）；
  3. 依次执行适配器 `adapter.scan({ cycle, year, month, rule, dryRun })`，返回 `{ scanned, intents:[], revocations:[], skipped:[], noLedger }`；
  4. 适配器内部保留"当月无台账 → noLedger"守卫（网格必须）；
  5. 对 intents 调 `categoryCap.applyCap` 钳制 → `deductionWriter` upsert；revocations 调 revoke；
  6. 收集 changedTargets，逐个 `assessmentScoringEngine.recalculateTarget(cycleId, targetId)`（单个失败不阻断）；
  7. 非 dryRun 时 `runLogger.recordRuleRun`；
  8. 返回聚合 `{ ok, cycleId, scanned, affected, details, skipped, dryRun, reason }`。
- `adapters/gridUncheckedAdapter.js`：把 `gridUncheckedDeductionService.syncGridUncheckedDeductions` 的业务逻辑（grid_areas 聚合、`gridCompletionService` 应巡/实巡、缺次与 rawScore、无台账守卫、三违类别其他扣分、upsert/revoke、recalculate）迁入为适配器，`adapter_key='grid_unchecked'`，绑定规则 R000001（经 ruleLoader 读取，不再用 category+LIKE 模糊匹配）。**source_detail 结构、deductKey、kind、summary 文案必须与现状逐字段一致。**
