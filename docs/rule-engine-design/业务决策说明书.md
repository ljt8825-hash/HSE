## D1 未标注查处来源的违规计分（NULL_SCORE）

**背景（数据事实）**
- 三违自身行为适配器（`violation_record`）对 `check_source`（查处来源）为空的违规记录，默认按 `NULL_SCORE = 1` 计分，即「未标注来源 = 1 分/次」。代码注释明确："若业务要求未标注不计分，改常量为 0 即可"。
- 录入端「查处来源」已上线**必填**校验，新录入不会落 NULL。
- 历史 `violation_records` 2506 行中 `violator_id` 全空（未关联责任人），不参与自动扣分；但**未来仍可能因漏选来源而落 NULL**。

**选项**
- **A（默认现状）**：维持 `NULL_SCORE = 1`，未标注来源按 1 分/次计。
- **B**：改 `NULL_SCORE = 0`，未标注行 `skipped`（不计分）。

**各选项影响**
- A：未标注的违规一律计 1 分，可能**高估**三违扣分；长期口径不一致、难追溯"到底因何计分"。
- B：未标注行不计分，须依赖录入端必填兜底；若录入仍漏选，则漏计（低估）。

**技术建议**
- 倾向 **B**（与"来源必填"录入约束一致，计分口径更干净）；但需业务确认"漏选来源是否应视为未处理而强制 0 分"。
- 仅改 `violationAdapter.js` 一个常量，影响面小；建议与 D3④（统一 1 分/条是否区分来源）合并评审。

**拍板后执行动作（由开发执行，走变更审批）**
- 选 B：修改 `server/services/ruleEngine/adapters/violationAdapter.js` 中 `NULL_SCORE` 常量 → `0`，重启后端，按 §3.1 dryRun 验证 + §3.2 重跑目标周期。
- 选 A：无需动作；在录入端加强"来源必填"提示即可。

**不决策的默认后果**
- 维持 A：所有未标注来源的违规**持续按 1 分/次计**，三违扣分偏高且口径不可追溯，直到有人主动改码为止。

## D2 培训扣分口径（含 D2b 82 行乱码处置）

**背景（数据事实）**
- 规则库存在两条"培训"相关路径：
  - **规则库口径 TRAIN002「培训记录缺失」**：1 分/人/周期累计，类别上限 30（属 `pending_data`/`no_table`，当前未接自动通路）。
  - **旧评分路「培训不合格」`HSE-KPI-TRN-002`**：3 分/次（`assessmentScoringEngine.js` 的 `FILL_SOURCES.training`），受 `LEGACY_TRAINING_FILL` 开关控制，默认启用=现状。
- 数据事实：`training_records` 198 行仅 3 行有 `personnel_id`、82 行存活记录为 **2026-08-29 乱码批量数据**、2026-08 零不合格 → 旧路两关联键全空（死路），当前不产生新扣分。
- 旧路有刹车开关 `LEGACY_TRAINING_FILL`（默认 `!=='false'`=启用）。

**选项**
- **A（规则库口径）**：走 TRAIN002「培训记录缺失」1 分/人/周期累计（上限 30），需先建培训数据采集/接入。
- **B（旧路口径）**：走「培训不合格」3 分/次 `HSE-KPI-TRN-002`，依赖 `training_records` 落键。

**各选项影响**
- A：口径与规则库一致、可累计、上限可控；但需先解决"培训数据从哪来"（当前基本无干净数据）。
- B：沿用旧表，但数据质量差（仅 3 行有人员键、82 行乱码），落键后可能**静默激活并错扣**。

**技术建议**
- 当前两路都不该产生扣分（旧路死路、规则库未接）。建议：**先治理数据（D2b）+ 先关旧路 `LEGACY_TRAINING_FILL=false`**，待培训采集按规则库口径立项后再建适配器。

**拍板后执行动作（由开发执行，走变更审批）**
- 关旧路：设环境变量 `LEGACY_TRAINING_FILL=false` 并重启后端（Runbook §5.5.2）。
- 建规则库适配器：基于 TRAIN002 新建 `adapters/trainingMissingAdapter.js` + 指标号 + 加入 `AUTO_DEDUCTION_ADAPTERS` + 重启（另立提示词轮次）。

**不决策的默认后果**
- 维持现状：培训类规则持续 `pending_data`/`未接表`，不参与自动扣分，培训考核口径空缺；且旧路在 `training_records` 落键后可能**无口径无测试覆盖地静默激活**，存在错扣风险。

### D2b 82 行乱码处置

**背景**：`training_records` / `violation_records` 等历史表中 82 行存活记录为 2026-08-29 乱码批量数据（GBK 编码乱码），干扰三违窗口命中与归类，潜在错扣/漏扣。

**选项**
- **① 软删重导**：对 82 行执行软删（`is_deleted=TRUE`），重新用干净 Excel 导入。
- **② 逐条修复**：按源表逐条修正编码/字段。
- **③ 保留观察**：不动，仅观察，靠录入端新数据稀释。

**各选项影响**
- ① 干净彻底，但需有干净源数据；② 精准但人工成本高；③ 零风险动作但脏数据长期干扰。

**技术建议**：倾向 **①**（软删重导），软删可经管理接口恢复（`revived`），风险最低。

**拍板后执行动作（由开发执行，走变更审批，本轮不执行）**
- ① 的 SQL 形如（需先备份）：`UPDATE training_records SET is_deleted=TRUE WHERE <乱码判定条件>;`（乱码判定条件由业务与开发共同确认，先 SELECT 预览再 UPDATE）。

**不决策的默认后果**
- 脏数据持续留存，可能干扰三违窗口命中与归类，带来潜在错扣/漏扣，且无法追溯。

## D3 VIOLATION002「检查未反馈 / 三违未整改」激活

**背景（数据事实）**
- 适配器 `violationUnrectifiedAdapter.js` 已 `registerAdapter`（引擎 `engine.js:39`），但 `METRIC_CODE=null` 且**不在** `AUTO_DEDUCTION_ADAPTERS`（`engine.js:30` 仅 `grid_unchecked`+`violation_record`）→ 当前零影响。
- 就绪 SQL 已备：`server/sql/sprint_activate_violation002_READY_NOT_RUN.sql`（**全注释态，本轮不执行**）。
- 事实：128 条历史"需整改未整改"记录**违规人未关联**（violator_id 空），激活初期**零命中**，随录入落键逐步生效。

**子决策**
1. **是否激活**：纳入自动考核 vs 维持人工。
2. **与 VIOLATION003 双扣分**：同一违规记录"自身行为 + 未整改"是否允许双扣分（技术上 kind 隔离 `violation_event` vs `violation_unrectified`，互不误判"已存在"，互不干扰）。
3. **指标号**：新增 `HSE-KPI-SAF-007` 还是复用 `HSE-KPI-SAF-001`。
4. **统一 1 分/条是否区分查处来源**：同 D1④。

**各选项影响**
- 激活：整改闭环获得自动考核牵引；但需先确保录入端"整改状态 + 责任人"落键，否则零命中、无收益。
- 不激活：未整改三违无自动计分，整改闭环缺乏考核牵引（现状）。

**技术建议**
- 建议**激活**（子决策 2 允许双扣分、3 用新增 `HSE-KPI-SAF-007` 便于区分、4 与 D1 合并评审），但**前提**是录入端"需整改/已整改 + 责任人"字段已落键（见 D2b / 录入治理）。

**拍板后执行动作（由开发执行，走变更审批）**
1. 业务确认四子决策口径；
2. 解除并执行就绪 SQL（指标补建 + 适配器候选 SQL）；
3. 将 `'violation_unrectified'` 加入 `AUTO_DEDUCTION_ADAPTERS`（`engine.js:30`）+ 重启；
4. 按 §3.1 dryRun 验证 → §3.2 重跑目标周期（Runbook §4 四步）。

**不决策的默认后果**
- 未整改三违不自动计分，整改闭环缺自动考核牵引；已备建资源闲置，128 条历史记录持续不参与。

## D4 事故一票否决路线

**背景（数据事实）**
- 旧评分路 `accident`（事故一票否决，`HSE-KPI-NEG-001/002/003`，suggestedScore=100）在 `assessmentScoringEngine.js` 中，受 `LEGACY_ACCIDENT_VETO` 控制。
- 事实：`accidents` 46 条存活记录 `personnel_id` 全空、录入端**无员工选择器**、旧路 100 分否决**无测试覆盖** → 当前死路，不产生否决。

**选项**
- **A（维持现状）**：保留旧路默认启用，待 `accidents` 落键后静默激活 100 分否决。
- **B（先关后建，推荐）**：先设 `LEGACY_ACCIDENT_VETO=false` 关旧路，事故录入做人员落键治理，再按规则库口径建适配器。

**各选项影响**
- A：落键后旧路静默激活，**100 分否决无口径无测试覆盖直接生效**，风险最高（一票否决影响最大）。
- B：先停风险最大通路，治理数据后用受控适配器替代，安全可控。

**技术建议**
- **强烈建议 B**：否决项 100 分影响最大，不该无测试上线；先关旧路消除隐患，治理落键后再建规则库适配器（与培训同理）。

**拍板后执行动作（由开发执行，走变更审批）**
- 关旧路：设 `LEGACY_ACCIDENT_VETO=false` 并重启（Runbook §5.5.2）。
- 后续建适配器：基于规则库事故否决口径新建 `adapters/accidentVetoAdapter.js` + 指标号 + 加入 `AUTO_DEDUCTION_ADAPTERS` + 重启（另立提示词轮次）。

**不决策的默认后果**
- 维持 A：`accidents` 一旦落键，旧路 100 分一票否决**无测试无口径直接生效**，可能误否决某人整月考核，风险最高且不预警。

## D5 月末自动冻结

**背景（数据事实）**
- 当前调度器**无自动冻结逻辑**，周期长期保持 `pending_review`（`assessmentScoringEngine.js` 已有 `frozen/not_started` 守卫，引擎/调度 WHERE 已就绪，但 freeze 任务未实现）。
- 详见《方案设计-月末自动冻结.md》：三选项 **自动 / 人工 / 混合（推荐）**。

**选项**
- **自动**：每月末（如 28 日/最后工作日）调度自动 `frozen`。
- **人工**：管理员在月末手动点冻结。
- **混合（推荐）**：调度到点自动置 `pending_freeze` 待确认，管理员一键确认冻结（或超时自动冻结）。

**各选项影响**
- 自动：省心但缺人工兜底，误冻难回退；人工：可控但依赖人；混合：兼顾自动与兜底。

**待业务确认（决策点）**
1. 冻结语义：冻结后**人工补录是否允许**？允许则走"补录即解冻/重算"，不允许则硬冻结。
2. 解冻流程：谁有权解冻、解冻后是否重算。
3. 冻结时点：月末几号、是否跳过节假日。

**技术建议**
- 推荐**混合**（自动预冻结 + 人工确认/超时自动），并明确"冻结后补录"语义后再实现。

**拍板后执行动作（由开发执行，走变更审批，本轮只设计不实现）**
- 依据《方案设计-月末自动冻结.md》的 6 决策点拍板后，新建 freeze 任务（调度 `CRON_FREEZE` + `freezeCycle` 函数 + 前端冻结按钮/确认弹窗），重启生效。

**不决策的默认后果**
- 维持现状：周期长期 `pending_review`、数字持续累计（已属预期），但月末无官方"封账"节点，考核结果无明确截止口径，审计/归档缺依据。

## D6 四类无源表检查立项（车辆/消防/转运站/晨会）

**背景（数据事实）**
- 车辆、消防、转运站、晨会系统内**无数据表**（TRAIN001 晨会已确认无表）。规则库对应规则维持「未接入 + 暂不会自动扣分」提示（`integration_status='no_table'`）。
- 当前自动考核仅覆盖：网格缺巡、三违自身行为两类。

**选项**
- **立项采集**：为四类各建最小采集（表单/Excel 导入），再建适配器接入自动考核。
- **维持现状**：四类继续人工/Excel 考核，不自动化。

**各选项影响**
- 立项：考核完整性提升，但需业务先定义采集字段与频次；维持：考核盲区持续。

**技术建议**
- 逐类评估 ROI 后立项；每类最小采集字段参照违规/网格表：**人员外键（`employee_id`/`personnel_id`）+ 日期 + 结果**。
  - 车辆：检查人 + 日期 + 是否合规（结果）
  - 消防：设施/点位 + 检查人 + 日期 + 是否完好
  - 转运站：站点 + 检查人 + 日期 + 是否达标
  - 晨会：参会人 + 日期 + 是否出席/记录

**拍板后执行动作（由开发执行，走变更审批，本轮不立项）**
- 业务立项后，按"建表/导入链路（复用 `useGenericImport` + `NATIVE_IMPORT_MODULES`）+ 建适配器 + 指标号 + 加入 `AUTO_DEDUCTION_ADAPTERS`"流程，每类一个提示词轮次。

**不决策的默认后果**
- 四类业务数据无自动考核覆盖，仍依赖人工/Excel，考核完整性不足，且规则库持续显示"未接入"提示。
