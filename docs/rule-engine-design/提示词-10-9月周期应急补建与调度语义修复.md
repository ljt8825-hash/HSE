## 2. 任务 B：调度语义长效修复（代码）

### B1. 建周期 cron 改为"保当月、兜底上月"

1. 抽纯函数并导出（便于单测）：`getScheduledTargetMonths(now = new Date())` → 返回 `[{year, month}, ...]`：
   - 第一项=**当月**（如 2026-09-01 任意时刻 → {2026,9}）；
   - 第二项=**上月**（兜底，防漏建；如 {2026,8}）；
   - 跨年正确：2026-01-15 → 当月 {2026,1}、上月 {2025,12}。
2. cron 回调遍历两项分别调 `autoCreateAndSyncCycle`（幂等，已存在自动跳过），日志分别打印结果；更新日志文案为「自动确保考核周期存在（当月+上月兜底）」。

### B2. 网格校验加 3 天收尾宽限

`runGridCheck` 周期 WHERE 改为：
```sql
WHERE is_deleted=FALSE AND status IN ('in_progress','pending_review')
  AND start_time <= NOW()
  AND ( end_time >= NOW()
        OR end_time >= NOW() - INTERVAL '3 days' )
```
语义：窗口含今天的周期（当月累计）+ 刚结束 3 天内的周期（月初补跑上月收尾整月口径，幂等；服务器宕机/晚建场景的安全网）。`start_time<=NOW()` 保留（未来周期不选）。报告中论证：宽限期内对上月周期跑引擎=整月口径最终值，upsert 幂等、人工锁定行不覆盖、与"执行评分"手工触发同路径，无新增风险。

### B3. 调度开关外置

`const SCHEDULER_ENABLED = process.env.SCHEDULER_ENABLED !== 'false';`（默认 true，显式设 'false' 才停用）；cron 表达式与时区保持硬编码常量不动。导出值保持在 module.exports。

### B4. 单测（新建 `server/services/__tests__/assessmentScheduler.unit.test.js`，mock config/db 与 node-cron）

- `getScheduledTargetMonths`：2026-09-01 → 当月 {2026,9}+上月 {2026,8}；2026-01-15 跨年 → {2026,1}+{2025,12}；2026-12-31 → {2026,12}+{2026,11}。
- `runGridCheck` 选周期 SQL：mock pool.query 捕获 SQL，断言含 `INTERVAL '3 days'` 宽限子句与 status 白名单；mock syncGridUncheckedDeductions 返回值，断言 cycles/scanned/affected 聚合；memory-mode 跳过分支。
- cron 回调建周期逻辑：mock autoCreateAndSyncCycle，模拟 9/1 触发 → 当月与上月各被调用一次、已存在时 skipped 不报错。
- 测试不得连真实库、不得真实注册 cron（mock node-cron 的 schedule）。
