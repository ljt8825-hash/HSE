## 2. 任务 B：旧评分路刹车开关（默认=现状）

- 位置：`assessmentScoringEngine.js` 的 `fillMissingDeductionsForTarget` 两条旧路（`FILL_SOURCES.training` / `FILL_SOURCES.accident`）。
- 开关：
  ```js
  const LEGACY_FILL_ENABLED = {
    training: process.env.LEGACY_TRAINING_FILL !== 'false',
    accident: process.env.LEGACY_ACCIDENT_VETO !== 'false',
  };
  ```
  默认 `true` = 与今天完全一致（两路关联键全空，死路，零新扣分）。关闭时跳过该路并 `console.warn` 一次。
- 用途：事故/培训录入落键治理前，业务可先关旧路，等引擎适配器按规则库口径重建（避免落键后静默激活、无测试无口径风险）。业务拍板后设 env 重启即生效，**无需改码**。
- 单测 `assessmentScoringEngine.fill.unit.test.js`（4 项）：
  - 默认：training/accident fetch 均执行，各产生 1 次补扣/否决（added=2）；
  - `LEGACY_TRAINING_FILL=false`：training fetch 不被调用、无培训补扣，accident 仍运行；
  - `LEGACY_ACCIDENT_VETO=false`：accident fetch 不被调用、无否决，training 仍运行；
  - 双关：两路均跳过、无 fetch、无补扣。
- 注：测试以通用 `pool.query` mock 让补扣路径成功落库，并以「`INSERT INTO hse_assessment_deduction` 出现次数 + fetch SQL 是否出现」作为断言（模块内 `addAutoDeduction` 以局部绑定调用，`jest.spyOn` 无法拦截，故改用 SQL 模式断言，等价可靠）。
