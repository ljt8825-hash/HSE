## 1. 任务 A：4 项缺陷修复

### A1. 查处来源前端新建必填

文件：`apps/web-naive/src/views/site/violation/index.vue` 的 `onSubmit`：

- **新建模式**（formMode !== 'edit'）：`formModel.checkSource` 为空时 `message.warning('请选择查处来源')` 并拦截提交（company/township/self 三选一，从源头消灭新 NULL）。
- **编辑模式**：原值为空时允许保存，但首次提交弹 `window.confirm` 或 NDialog 提示「该记录未标注查处来源，未标注将按 1 分/次计分，建议补选」，用户确认后继续；已选值编辑不受影响。
- typecheck 零新增错误。

### A2. 三违适配器「换人撤销」缺陷修复

现状缺陷：违规记录 violator_id 由 A 改挂 B 时，记录仍在本月有效集（validIds）内，A 名下既有扣分（source_id=该记录）不会被撤销，B 又新增一条 → 双重扣分。

修法（`server/services/ruleEngine/adapters/violationAdapter.js`）：

1. `buildDetail` 的 source_detail 增加 `employeeId`（intent.employeeId）与 `targetId`（intent.targetId），供撤销判定与排查。
2. scan 中撤销集判定改为：先建 `Map<sourceId, employeeId>`（本月窗口内有效记录 id → 当前 violator_id）；遍历既有活动扣分行时：
   - source_id 不在 Map 中 → revoke（记录被软删/落键丢失，原逻辑）；
   - source_id 在 Map 中但 `Map.get(sid) !== 该行 source_detail.employeeId` → **同样 revoke**（记录已改挂他人）；行明细无 employeeId 字段的历史行跳过本判定（生产环境目前无此类行）。
3. 补单测 `__tests__/violationAdapter.unit.test.js`：A→B 换人场景，A 的旧扣分产出 revocation、B 产出新 intent；软删场景回归；employeeId 已写入 buildDetail。

### A3. 观测值测试污染复位 + 集成脚本防污染
