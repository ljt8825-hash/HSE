## 1. 背景：为什么本轮不做三违扣分适配器

第 01 轮审核时连库实测（2026-08-30，2506 行有效数据）：

1. **人员关联断裂**：`violation_records.violator_id` **全部为 NULL**（inspector_id / handler_id / punisher_id 也全空）；违规人仅以姓名散落在 `violator_name`、甚至 `violation_behavior` 文本中（该列混有姓名与行为描述）。与 cycle 24 考核对象（`hse_assessment_target.employee_id`）交集为 **0**。
2. **现有硬编码三违扣分是死路**：`server/services/assessmentScoringEngine.js` 的 `FILL_SOURCES.violation`（525 行附近）按 `WHERE violator_id = $1` 取数，因 violator_id 全空，**该通路从未产生过扣分**（cycle 24 的 24 条扣分全部来自网格通路）。
3. **无"查处来源/层级"字段**：`violation_level`、`punishment_type` 全空；`risk_level` 全为"中"；`status` 全为"待处理"；`violation_type` 全空。无法区分"公司查处"与普通查处。
4. 可参考的现有列：`area_team`（乡镇，杜集镇/长官镇…）、`grid_level`（三级/二级/一级/总网格长）、`position`（管理员/乡镇作业中心经理/公司管理员…）、`is_supplementary`、`report_status`。

结论：三违适配器（阶段2）必须等两个地基就绪——**违规人能可靠关联到员工**、**每条违规有"查处来源"标识**。本轮只做这两个地基 + 阶段1 收口，**不接扣分**。

## 4. 任务 B：三违数据治理地基

### B1. 迁移 SQL：`server/sql/sprint_violation_governance_phase2a.sql`

- 备份后执行；事务包裹；可重复执行。
- `ALTER TABLE violation_records ADD COLUMN IF NOT EXISTS check_source VARCHAR(20)`：
  - 字典：`company` = 公司查处（阶段3 计 5 分/次）；`township` = 乡镇/管理区及以下查处（1 分/次）；`self` = 自查自纠（1 分/次）；NULL = 未标注（阶段3 按 1 分保守处理或不计，报告中给出建议）。
  - 加 `COMMENT`：说明字典值与阶段3 计分口径（公司查处 5 分/次，其余 1 分/次）。
- 加索引：`CREATE INDEX IF NOT EXISTS idx_violation_check_source ON violation_records (check_source) WHERE is_deleted IS NOT TRUE;`
- **不批量回填历史数据**（无可靠推断依据）；历史行 check_source 保持 NULL。
- 报告中给出字典值的业务依据调研：阅读 `server/routes/violations.js` 与三违录入页现有字段，确认是否已有"检查层级/来源"概念可复用（若有更合适的现有字段，在报告中提出但不擅自改设计）。

### B2. 人员关联可行性分析（只分析，不回填）

新建分析脚本 `server/scripts/_ruleEngine/_violation_link_analysis.js`，连库只读，输出：

1. 员工主数据表确认：以 `hse_assessment_target.employee_id` 反查实际员工主数据表（grep 引擎 `findAssessmentTarget` 的 SQL 确认表名，大概率为 hse_employee_master 或 employees），给出表名与姓名列。
2. 姓名匹配：取 `violation_records.violator_name`（排除空/明显非姓名值），与员工主数据姓名做匹配，输出：
   - 违规记录总数、violator_name 非空数；
   - 唯一匹配到 1 名员工的记录数/占比；
   - 重名（匹配多名）记录数/占比；
   - 匹配不到的记录数/占比，并抽样 20 个匹配不到的名字；
   - `violation_behavior` 中疑似姓名的占比（判断该列污染程度）。
3. 与考核对象交集：用匹配出的 employee_id 与近 3 个周期 `hse_assessment_target` 求交集，输出"若现在建三违适配器，最多能覆盖多少考核对象/多少违规记录"。
4. 结论与建议：匹配率是否达到可回填门槛（建议 ≥90% 唯一匹配才可自动回填，其余靠录入页修正）；给出阶段3 适配器的取数键建议（violator_id 回填后按 violator_id 关联）。
