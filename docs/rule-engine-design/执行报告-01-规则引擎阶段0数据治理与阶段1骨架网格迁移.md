## 4. 偏离项与原因

1. **no_table 计数**：提示词写 8 条，实测 7 条（TRAIN001+CAR×3+FIRE001+TRANSFER×2=7），13 条总数无误。
2. **scanned 人数**：提示词示例写「扫描24人/扣分24人」，实测 `last_scanned_count=62`（网格长总数）、`last_deducted_count=24`（实际扣分人数）。说明：提示词示例为示意，62 与「24 个考核对象」不矛盾——62 是扫描到的网格长人数，其中 24 人有有效扣分。
3. **后端单测失败**：`import-personnel-behavior` 套件 7 条失败为既存问题，与本次改动无关。
4. **前端 typecheck 既有错误**：51 个错误全部为历史文件（meeting-records/site/* 等）积累，本次改动文件未新增错误。

## 6. 待业务确认项（按需求不擅自实现）

1. **TRAIN002 来源表更正为 `training_records` 是否可支撑「培训记录缺失」**
   - 实测 `training_records` 字段：`personnel_id`、`employee_id`、`name`、`training_date`、`result`、`training_type`。
   - 可判断「某员工在某周期无培训记录」，但缺少「应培训人员/培训计划」维度，无法表达「缺了几次」。建议阶段3 建设适配器前，先明确培训计划来源。

2. **非活跃规则 metric_code 建议映射表**
   - `VIOLATION001/002/003` → `HSE-KPI-SAF-001`（三违行为管控）/ `HSE-KPI-SAF-003`（三违未及时处理），需先解决字段后才能细分。
   - `TRAIN001` → `HSE-KPI-TRN-001`（晨会）或新建指标；但表不存在，暂不映射。
   - `TRAIN002` → `HSE-KPI-TRN-002`（培训不合格）相近，但业务含义为「记录缺失」，建议新增 `HSE-KPI-TRN-005`。
   - `CAR001/CAR002/CAR003` → 驾驶员管理类指标，建议新增 `HSE-KPI-DRV-001`。
   - `FIRE001` → 消防管理类，建议新增 `HSE-KPI-FIRE-001`。
   - `TRANSFER001/002` → 转运站管理类，建议新增 `HSE-KPI-TRANSFER-001`。
   - 以上均需在规则表回填 `metric_code`，并建设对应适配器。

3. **"公司查处5分" 落地所需字段建议**
