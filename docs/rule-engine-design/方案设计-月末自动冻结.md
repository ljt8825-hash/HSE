# 方案设计：月度考核周期月末自动冻结（仅设计，未实现）

> 编写：提示词-11 任务 D（2026-08-31）
> 状态：**设计文档，不写码、不改码、不迁移**
> 配套：执行报告-11（`执行报告-11-窗口修复与旧路开关.md`）、`上线运维Runbook.md`

## 1. 现状

- 周期状态机：`not_started → in_progress → pending_review → reviewed → frozen`（含 `archived` 可选）。
- 当前所有运行周期长期挂在 `pending_review`（库内 June/July/Aug/Sept 均为该态），**从未进入 `frozen`**。
- `runDailyCheck`（每日 02:00）对每个 `in_progress/pending_review/reviewed` 周期重算全部对象分数 + 重放失败事件；对 `frozen` 周期**不选中**（WHERE 未含 `frozen`），故冻结后 daily check 天然跳过。
- `runGridCheck`（每日 01:00）仅选 `in_progress/pending_review`，同样不含 `frozen`。
- 自动扣分引擎 `runCycleAdapters` 对 `frozen` 周期直接返回 `reason:'cycle-status-frozen'`（已在 `engine.js:82` 守卫），即冻结周期不会被自动扣分引擎触碰。
- **结论**：引擎层、两个调度 WHERE 均已具备"识别 frozen 即跳过"的能力；缺的是"谁来把周期置为 frozen"的触发器与状态迁移 SQL。daily check 对历史 `pending_review` 周期每日空转（幂等、无副作用，但浪费算力，属可优化项，本轮不处理）。

## 2. 方案选项

| 方案 | 描述 | 优点 | 缺点 |
|---|---|---|---|
| ① 自动 cron 冻结 | 每月末/月初由调度自动将"已到结束日 + 仍 pending_review"的周期置 `frozen` | 零人工、长期自洽 | 失去人工复核窗口；若月末数据未录入完会被提前冻结 |
| ② 纯人工按钮 | 保留"执行审核/归档"按钮触发状态迁移（走现有 `/cycles/:id/...` 接口） | 业务完全掌控时点 | 依赖人工记得点；可能遗漏 |
| ③ 混合（推荐） | 调度自动标记"可冻结候选"（如置 `ready_to_freeze` 或仅打标日志），由人工"确认冻结"按钮最终置 `frozen`；或设定"结束日 + N 天宽限"后自动冻结、期间可人工提前冻结/解冻 | 平衡自动与可控，月末不漏、异常可回退 | 实现稍复杂 |

**推荐 ③**：在月末（如每月最后一天 23:30，或次月 3 日宽限后）由 `runDailyCheck` 内新增一步"自动冻结到期周期"，但保留人工"解冻"能力（见 §3）与"提前冻结"按钮。

## 3. 冻结语义建议

- **冻结后自动扣分**：`runCycleAdapters` 已守卫返回，不再 `upsert/revoke` 任何扣分明细（`frozen` 周期 score_id 聚合不被改写）。✅ 引擎层零改动即可生效。
- **冻结后人工录入**：建议**允许**人工在 frozen 周期补录/修正扣分（经人工接口 `deduction_source='manual'`），但**禁止**自动引擎改写。需明确：人工补录是否触发分数重算——建议触发（人工操作即有意）。
- **链传（chain_transmission）**：frozen 后上级传导是否停止？建议**停止**自动链传扫描（frozen 周期不再参与 `scanOverdueDeductions` 的自动扣分），但人工链传仍可。
- **解冻流程**：提供"解冻"接口将 `frozen → pending_review`（或 `reviewed`），解冻后 daily check / 自动引擎重新接管；解冻须记录审计（`logAudit`）。
- **分数封存**：frozen 视为"当月正式成绩"，前端"考核评分"页应显式标注"已冻结"并禁用编辑（除非解冻）。

## 4. 对引擎 / 调度的改动点清单（待实现时落地）

> 以下为**设计层面**的改动清单，未经本轮实现，供后续专项排期。

1. **状态机迁移 SQL**（新增或复用现有接口）：
   ```sql
   UPDATE hse_assessment_cycle
      SET status='frozen', frozen_at=NOW(), updated_at=NOW()
    WHERE id=$1 AND is_deleted=FALSE AND status IN ('pending_review','reviewed');
   ```
   回滚（解冻）：
   ```sql
   UPDATE hse_assessment_cycle
      SET status='pending_review', frozen_at=NULL, updated_at=NOW()
    WHERE id=$1 AND is_deleted=FALSE AND status='frozen';
   ```

2. **调度新增"自动冻结"步骤**（建议挂 `runDailyCheck` 末尾或独立 cron）：
   - 选取 `status IN ('pending_review','reviewed') AND end_time < NOW() - INTERVAL 'N days'`（N=宽限天数，建议 3）的周期；
   - 调用迁移 SQL 置 `frozen`；
   - 写 `logAudit(operationType='CYCLE_AUTO_FROZEN')`。

3. **WHERE 条件补充**（若需显式）：当前 `runDailyCheck` / `runGridCheck` 已不含 `frozen`，无需改动即可跳过；但若新增"解冻后重跑"，需保证状态回退后重新入选。

4. **前端**：考核评分页增加 `frozen` 角标 + 禁用自动编辑；提供"确认冻结 / 解冻"按钮（调用新接口）。

5. **回滚与验证**：冻结/解冻均幂等；提供 dryRun 式核查（先 SELECT 待冻结周期清单，运维确认后再执行）。
