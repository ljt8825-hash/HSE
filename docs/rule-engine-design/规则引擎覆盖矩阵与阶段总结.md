## 2. 已完成阶段总结

### 引擎架构现状（三层结构）
```
统一门面  runCycleAutoDeductions(cycle)
   └─ 遍历 active 适配器 → adapter.scan() 产出 扣分意图/撤销意图/跳过
        └─ deductionWriter 双模式：monthly（按月度聚合按人）| event（事件级按 source_id 幂等）
             ├─ categoryCap   类别上限钳制（三违管理 15 / HSE教育培训 30）
             ├─ 人工锁定      approved/adjusted 不覆盖
             └─ runLogger    可观测三数（last_scanned/assessed/deducted）+ 展示文案 summary
```
- **两种幂等模式**：monthly（网格未巡查，按人）与 event（三违，按违规记录 source_id）。
- **统一门面**：所有适配器经同一 `runCycleAutoDeductions` 驱动，零行为差异。
- **上限钳制**：categoryCap 按"排除当前行"累加同类别，正确支持一人多次三违累计受上限约束。
- **决策⑤（类别上限）**：自动钳制强制执行 ✅（applyCap）；**人工扣分上限提示 ✅（提示词-08 本轮）**——computeManualCapWarning 纯 advisory（只提示不拦截），归类口径与自动钳制共用 assessmentRuleCategoryService，无第二套口径。
- **人工锁定**：approved/adjusted 状态扣分不被自动覆盖。
- **可观测三数**：scanned / assessed / deducted + 展示文案（事件级 deducted 称"人次"，本轮回修）。

## 5. 调度缺陷与长效修复（提示词-09 发现 / 提示词-10 修复）

### 5.1 高严重度调度缺陷（提示词-09 独立复核确认）
- **现象**：`CRON_CREATE_CYCLE`（每月 1 日 00:30）回调内联算"上月"并 `autoCreateAndSyncCycle(上月)`，且 `runGridCheck` 周期 WHERE 仅选 `start_time<=NOW() AND end_time>=NOW()`（窗口含今天）。结果：9 月周期不会被调度创建；且调度建的"上月"窗口已过去，`runGridCheck` 永远选不到它 → **网格缺巡扣分不会随调度累计**，9 月全月扣分零累计。
- **影响面**：网格缺巡（`grid_unchecked`）月度扣分通道。三违自身行为（`violation_record`）按事件实时命中，不直接受此缺陷影响。
- **决策（提示词-09 上报，二选一）**：① 人工在 9/1 前建 `HSE-CYCLE-202609`；② 修复 off-by-one 使调度建"当月"并同步对齐 `runGridCheck` 窗口。
