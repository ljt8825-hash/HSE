## 2. 审计标准

### 2.1 前端展示标准

人员字段在**列表/详情/表单**中的展示应遵循以下模式（以 `handlerId` 为范例）：

```
列表列 bodyCell / 详情 Descriptions：
  <EmployeeName v-if="record.xxxId" :employee-id="record.xxxId" />
  <span v-else>{{ record.xxxName || '-' }}</span>

表单：
  <EmployeeSelector v-model:value="form.xxxId" @change="onXxxChange" />
```

### 2.2 后端数据标准

```
formatRow：xxxId: row.xxx_id（camelCase）
INSERT：含 xxx_id 列，值 = body.xxxId
UPDATE：setClauses 含 xxx_id = COALESCE($N, xxx_id)
```

### 2.3 不一致分类

| 级别 | 定义 | 示例 |
|------|------|------|
| 🔴 缺失 | 数据库无 ID 列，后端无 formatRow，前端纯文本 | 旧 reporter（提示词-41 修复前） |
| 🟡 部分 | 后端有 ID 返回但前端未用 EmployeeName | 列表/详情仍用纯文本 |
| 🟢 已统一 | 前后端 + 数据库全链路 ID 模式 | handlerId/checkerId/fixerId/responsiblePersonId |

## 3. 审计方法

### 3.1 前端 Grep 审计

对每个模块视图文件执行：

```bash
# 1. 检查是否使用了 EmployeeName
grep -n "EmployeeName" src/views/{module}/index.vue

# 2. 检查是否仍有纯文本人员字段（v-else 兜底除外）
grep -n "record\.\w*Name\|record\.\w*Person\|\.reporter\|\.handler" src/views/{module}/index.vue

# 3. 检查 EmployeeSelector 使用情况
grep -n "EmployeeSelector" src/views/{module}/index.vue
```

### 3.2 后端 Grep 审计

```bash
# 检查 formatRow 是否返回人员 ID 字段
grep -n "Id: row\.\w*_id" server/routes/{module}.js

# 检查 INSERT 是否含人员 ID 列
grep -n "employee_id\|person_id\|user_id" server/routes/{module}.js

# 检查 UPDATE setClauses 是否含人员 ID
grep -n "COALESCE.*_id" server/routes/{module}.js
```

### 3.3 数据库列审计

```sql
-- 检查各业务表是否有人员 ID 外键列
SELECT table_name, column_name, data_type
FROM information_schema.columns
WHERE table_schema = 'public'
  AND column_name LIKE '%employee_id%'
   OR column_name LIKE '%person_id%'
   OR column_name LIKE '%checker_id%'
   OR column_name LIKE '%fixer_id%'
   OR column_name LIKE '%handler_id%'
   OR column_name LIKE '%responsible_person_id%'
ORDER BY table_name, column_name;
```
