# 领导视角统一看板 P2 · 月度趋势与经理双口径规则（冻结）

> 日期：2026-09-27
> 归属：领导视角统一看板（维度扩展与月度钻取）实施计划 P2
> 状态：2026-09-27 用户确认后冻结，前端 P3 须严格沿用
> 涉及端点：`/centers/:centerId/towns/:townId/trend`、`/managers/:employeeId/overview`、`/managers/:employeeId/month-detail`

## 一、逐月趋势口径

1. **月份集合**：逐月趋势的月份 = 该组织各维度「有记录月份」的并集，升序排列（空月份不补零）。
2. **未来日期截断**：累计模式（year 缺省）下趋势表截断到当前月（`YYYY-MM`），未来日期脏数据不入趋势；按年模式截断到该年 12 月。
3. **静态台账不入月度**：风险（risk_sources）为静态台账（无业务日期）→ 不参与月度，`rows.risks` 恒 `null`。
4. **时点台账仅累计**：驾驶人员数（在职驾驶岗位）为时点台账 → 仅进 `summary.drivers.personCount`，不入月度单元格。
5. **summary 与趋势可不同步**：累计模式 summary 为全历史口径（含未来脏数据），趋势表为截断口径 —— 两者并行呈现，前端不得用趋势行合计反推 summary。

## 二、经理双口径

1. **辖区口径** = 该组织（乡镇/公园）全量汇总，完全复用 `fillSummaries` 10 维口径（事故含重大/加权指数、三违含严重、驾驶员复合 5 项、风险/隐患/转运站、巡查、培训人次+人数、应急 count+passed、考核 targetCount+avgScore+gradeGood）。
2. **个人口径** = 本人归因：
   - 事故 / 考核 / 培训 / 车辆检查 / 驾驶员检查：按 `personnel_id / employee_id` 精确匹配；
   - 三违 / 巡查 / 记分 / 司机违章 / 风险 / 转运站：ID 匹配，未命中再按**清洗后姓名**（去括号备注）全局唯一姓名兜底（重名不参与兜底）；
   - 隐患：按 `finder_id / responsible_id` 匹配；
   - 应急演练：表无人员关联字段 → 个人恒 0，如实呈现，不捏造。
3. **驾驶人员数个人口径**：按该员工岗位是否驾驶（`/驾驶|司机/`）判定 1/0。

## 三、归因策略（与 M1 一致，不另立）

1. 记录带人员 ID 且命中当前任职（`v_employee_org_full` relation_status='active'）→ 按任职反推组织（town_center 归乡镇/公园）。
2. 否则按自由文本对乡镇短名做最长前缀匹配（转运站 `area_team` 短名、隐患 `description` 描述、演练 `township||name`）。
3. 均未命中 → 未匹配桶（不计数）。

## 四、岗位识别

- 乡镇线经理 = 岗位含「乡镇作业中心经理」；公园线管理员 = 岗位含「管理员」。`roleLabel` 按组织类型（park / 其他）区分返回。

## 五、数据源与 SQL 对齐

- 逐月趋势/个人聚合与乡镇汇总（fillSummaries）**同源同表**，仅列选择不同（趋势额外取日期别名 `_d`/考核 `_ay`,`_am` 做月份键）。
- 日期月份键 `monthKey` 兼容 Date、`YYYY-MM`、`YYYY-MM-DD` 与 ISO 串；`transfer_station_check.check_date` 为 VARCHAR（'YYYY-MM' 截取）已实测兼容。
