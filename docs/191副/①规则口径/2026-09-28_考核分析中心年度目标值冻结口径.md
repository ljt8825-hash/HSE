## 规则 / 口径内容

**考核分析中心年度目标值口径（2026-09-28 冻结）：硬编码值为唯一口径。**

**背景**：探查发现库中不存在年度目标值来源——
- `objective_contract_version` / `objective_contract_indicator`（`/goals` 原查询的表）**在库中不存在**，原查询靠 `.catch(() => ({rows:[]}))` 静默兜底，即「目标责任书」Tab 自上线起一直显示硬编码兜底数据；
- 真实目标体系为另一套：`hse_target_contracts`（2433 行，**按员工**签订台账）+ `hse_assessment_target`（913 行，**按人按周期**考核得分），均为个人维度，不是年度公司级目标值；
- 唯一形似年度目标的 `safety_goals`（year/type/target_value）存在但 **0 行**。

**冻结内容**：
1. 年度目标值以 `server/services/hseAssessmentAnalysisService.js` 头部冻结常量 `DEFAULT_TARGETS` / `DEFAULT_GOAL_ITEMS` 为唯一口径，单点维护，禁止两处漂移：
   - `/overview.targets`：事故起数 0 起 / 重大事故 0 起 / 事故加权指数 0 分 / 三违 50 次 / 培训完成率 95% / 隐患整改率 98% / 平均风险 80 分 / 驾驶扣分率 10% / 网格长巡查合规率 90%
   - `/goals` 兜底 9 项清单（名称/分类/目标值/单位/说明）与 `DEFAULT_TARGETS` 同源。
2. `goals()` 已移除对不存在表（`objective_contract_*`）的查询；返回 `contractVersion=null`、`allVersions=[]`（与既有生产展示一致，前端 GoalsAssociation 仅消费 `goals` 字段）。
3. 状态分级与阈值保留既有兜底逻辑不变：三违「in_progress」上限 80 为存量阈值（非 50×1.5=75），培训/整改/高风险/驾驶为两档（completed/in_progress），不随目标值联动。
4. `avgRiskScore=80` 无对应目标责任书指标，保留独立项。
5. 遗留（另议，未冻结）：`demeritRate` 分母 `驾驶员数×60` 语义、网格合规率口径（现用 `position` 岗位名 + `hazard_record` 计数，未读 `grid_inspection_records` 台账）。

**实现记录**：`hseAssessmentAnalysisService.js` 改动——文件头新增两常量；`overview()` targets 改 `{ ...DEFAULT_TARGETS }`；`goals()` 删除死查询 + 目标构建改由 `DEFAULT_GOAL_ITEMS` 驱动（行为等价既有兜底，`gap=-90` 保留）。

**验证**（dev 只读，零写库）：`node --check` 通过；专项脚本 `_verify_targets_freeze.cjs` 断言 overview targets 9 项 == 冻结值、goals 9 项名称/目标值/单位一致、`contractVersion=null`、`allVersions=[]`、网格长 `gap=-90` 全部通过；全量冒烟 5 端点 200 + 404 正常。实时数据参照：2026 年三违实际 824 次（目标 50，完成率 0）、事故指数 13（目标 0）、驾驶扣分率 17%（目标 10）。
