## 二、字段级来源（URL → SQL 源 → 表）

后端唯一载体：`server/routes/hse-driver-risk-center.js`（app.js 注册 `/api/hse/driver-risk-center`）。

1. `GET /overview`：
   - driverCount/levelDistribution/highRiskCount ← `employee_assignment`×`position`（驾驶员身份）+ `hse_employee_risk_snapshot`（最新 `MAX(snapshot_date)`）
   - demerit（近5年）← `license_demerit_records`
   - accident ← `accidents`（`accident_type='交通事故'`）
   - inspection（三检）← `hse_driver_inspection_records`
   - training ← `employee_training_status`（限定驾驶员集合）
2. `GET /drivers`：← `hse_employee_risk_snapshot` JOIN `employee_assignment`×`position`
3. `GET /demerit/statistics`：← `license_demerit_records`（近5年）
4. `GET /accident/statistics`：← `accidents`

## 三、与「现场管理→驾驶员管理」的关系（关键差异，需业务知悉）

- 「现场管理→驾驶员管理」= `/site/driver`，含三子页：评估档案 `/site/driver/assessment`、违章 `/site/driver/violation`、月度 `/site/driver/monthly`。
- 「评估档案」后端为 `siteMgmtController/siteMgmtService` 的 **`driver_assessments` 台账**（驾驶证评估/三违评估，CRUD+导入，字段属手工建档），**与风险中心所用风控表（三检/扣分/快照）相互独立、无交叉**。
- 即：风险中心当前**并未**从「现场管理→驾驶员管理→评估档案」台账直取数据；其驾驶员数据来自**风控引擎实时表**（扣分/三检/事故/快照）。
- **结论**：「从事故管理取数」已成立（accidents 同源）；「从驾驶员管理取数」仅在"驾驶员识别取花名册岗位"意义上成立；若要求"驾驶员数据=评估档案台账数据"，则属**数据口径重构**（放弃风控快照、改读 driver_assessments），需业务单独确认后另行排期，非本次只读核对可落地。
