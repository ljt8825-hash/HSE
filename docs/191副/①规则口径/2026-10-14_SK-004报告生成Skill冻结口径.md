## 规则 / 口径内容

**SK-004 报告生成 Skill 冻结口径**（任务书 AI-Phase-01-07 + 实施实证）：

1. **职责边界**：SK-004=「把已经可信的事实和分析结果组织成结构清晰、可追溯、可审核的公司业务报告」；**不是**「AI 自由写报告」，**不得**重算核心业务数据（不能成为第二个 SK-003）——报告需要新统计指标时回 SK-003 确定性计算层；
2. **事实先于文字**：结构化事实 → 确定性结果 → Evidence → 报告结构规划 → AI 文字生成 → 事实一致性检查 → 结构化报告；确定性表格由程序从 facts/analysis 直接组装（columns+rows，≤12 行/表），AI 不重排不重算不改数；
3. **事实一致性双层检查（§四十四）**：生成前 factIndex 事实锁定（从 facts/analysis/evidence/document 提取 ≤80 条「数字+指标+维度+时间」四元组，作为 AI 唯一合法数字来源）+ 生成后 checkReportFactConsistency 四元组比对（继承 SK-003 机制，禁止只查「数字是否存在」）；不一致 → warnings + 自动重试一次（重试指令带不一致明细+点名缺失章节）→ 仍不一致 → `consistency_status=failed` + **标记人工审核**（「相关数字一律以确定性事实/表格为准，修正后方可正式使用」），**禁止静默通过、禁止只返回不标记**；
4. **输出协议**：report.{title, report_type, report_version(=v1 字段保留不建版本库), summary, sections[{key,title,content,tables,evidence_ids}], disclaimer} + facts.used/unresolved + evidence + warnings + suggestions + confidence + metadata（含 consistency_status/fact_count/evidence_count 等 §四十六 全部追踪字段）；内容模型与文件格式解耦（§十一，为未来 Word/PDF/PPT 留口）；
5. **章节机制（§十二）**：inspection_monthly 自动 6 章节 overview/trend/ranking/problems/anomalies/suggestions；用户 sections > template > 自动章节；中文标题反查语义 key；**数据驱动**：无异常事实 → anomalies 安全文案「本期未发现达到当前分析规则的明显异常波动。」禁止硬写异常严重；无问题清单 → problems 如实兜底；章节缺失 → 重试点名补写 → MISSING_SECTION_TEXT；
6. **空数据/数据不足/Evidence 不足安全文案（§二十六~二十八）**：data=[] → success=true + NO_DATA_TEXT「当前没有有效数据，无法判断本月实际检查情况。」+ 说明「不代表未开展检查」；跨度不足 → 「当前数据跨度不足，无法形成可靠同比判断」不生成同比；无 Evidence → 「该结论缺少可追溯数据依据，暂不形成确定性表述」不伪造引用；
7. **HSE 专业边界（§二十）**：核心零 HSE 规则硬编码；输入已含等级结论（如 violation_level=一般）可忠实转述，SK-004 不得自行判定等级；
8. **推测与事实分离（§十九/§二十三）**：报告可含「已确认事实（数据）/分析判断（AI 解释）/建议核查（人工确认）」三层；禁止把推测写成事实、把建议写成已完成、无证据管理判断（如「安全管理松懈」）；
9. **AI 上下文预算 aiContextMaxChars=4200**：事实清单+约束+确定性表格+证据；任何降级档不得把 AI 置于「没有事实素材」状态（SK-003 T17 教训继承）；处理上限：title≤200/goal≤500/sections≤20/evidence≤50/facts≤50000 字符/analysis≤300000/document 摘要 1600 字符/重试≤2；
10. **降级链**：JSON 解析 → trySalvageMarkdownSections 语义抢救 → 重试（点名缺失章节）→ 两次非 JSON → degraded 单节 report_body（AI 原文保留），consistency_status=degraded，markdown 抢救成功也 warnings 留痕；
11. **qwen2.5:7b 输出格式口径（重要教训）**：JSON-only 强约束对该 7B 模型是**负优化**（实证输出全空 JSON 约 330 tokens）；正确口径=Markdown 信封+语义抢救；单次生成 60~350s；
12. **权限**：JWT + SKILL_USER + 8 角色 allowlist（与 SK-005/001/002/003 逐字一致 fail-closed）；先鉴权后处理输入；用户自带素材不扩大数据库访问权限；
13. **组合验证口径（§七/§二十八）**：SK-001→SK-003→SK-004 与 SK-002→SK-004 以现有调用方式验证（T05/T06 通过），不开发 Orchestrator。
