## 冻结范围（原文要点）

1. **Skill 定义**：`skill_id / skill_key / name / version / description / domain / type / owner / status` 九字段必填；`skill_key = <domain>.<capability>.<verb>`。
2. **Skill 生命周期**：`Draft → Testing → Active → Deprecated → Archived`，不得回跳跨越。
3. **标准调用链（冻结）**：`Business/Agent → Skill → Skill Service → Permission → Evidence/Retrieval → Prompt Registry → AI Gateway → Provider Registry → Model → Structured Output → Generation Record → Human Review（需要时）`。
   - 与 SK-005 实际唯一结构性差异：**v1 允许「Skill Service」由 Skill 模块 + 控制器共同承担**（不独立成模块）；≥3 个 Skill 时再评估抽取。
4. **输入协议**：区分 **Skill 公共字段**（request_id / user context / scope / options）与 **Skill 业务字段**（各 Skill 自定义）。铁律：**不得因 SK-005 需要 question/knowledge_scope/top_k/require_citation 就要求所有 Skill 都有这些字段**。
5. **输出协议**：`success / skill / request_id / answer|result / evidence / confidence / warnings / suggestions / metadata`。必备：success、skill、request_id、answer|result、evidence、confidence、metadata；`error` 仅失败时出现。
6. **错误协议**：统一 `AI_ERROR_CODES` + `toErrorResponse`；参数错误必带 `error.details[]`；访问控制错误用独立码 `SKILL_PERMISSION_DENIED`(403)。
7. **Evidence 标准**：`evidence_id`（**容许别名词 citation_id**）/ source_id / source_name / source_type / document_id / document_name / chunk_id / page / section / content / score / evidence_strength；**字段缺失允许 null，禁止伪造**；入 Gateway 的 evidence 与响应 evidence 必须同源。
8. **Prompt 标准**：必须入 Prompt Registry，禁止长期硬编码完整 Prompt；key 与 skill_key 对齐；记 `prompt_key/prompt_version`。
9. **Model Policy**：Skill 禁止写死 Provider/模型；`provider:null` 交 Gateway 活动 Provider 决定。
10. **权限标准**：身份认证（req.user.id，禁推断）/ 角色 allowlist（8 角色 fail-closed）/ 数据范围 / 资源权限 / 知识源权限；**知识源级 ACL = 未来能力（R3），不写成已实现**。权威 8 角色与 `auth.js ROLE_PERMISSIONS_MAP` 逐字一致：`system_admin, admin, safety_manager, hse_manager, township_manager, manager, viewer, grid_inspector`。
11. **AI 记录标准**：目标字段 request_id/skill_id/skill_version/prompt_key/prompt_version/provider/model/duration/status/error/evidence/usage；**缺口 R2**：`ai_generation_records` 无 skill_id/skill_version 列 → 统一 migration 方案（可空列 + `idx_ai_gen_skill` 索引 + 分批回填 + DROP 回滚），**本阶段不执行**。
12. **前端标准**：Vue3 + Vben 5.7.0 + **Naive UI**（禁 Ant Design Vue）；复用现有组件/`@vben/request`；AI 接口须显式设足够超时。
13. **Skill 与 Agent 边界**：Agent 可调用多个 Skill；**Skill 不能反向绑定某一个 Agent**。
14. **Company 与 HSE 边界**：Company Skills 负责通用能力；HSE 专属能力（三违/隐患/风险/HSE 检查分析与规则）留在 HSE 层；方向为 **HSE AI → 调用 Company Skill**。
15. **第一阶段 5 个 Skill（冻结清单）**：SK-001 Excel 数据分析（`company.excel.analysis`/data_analysis）、SK-002 文档解析（`company.document.parse`/document_parse）、SK-003 检查数据分析（`company.inspection.analysis`/inspection_analysis，HSE 专业规则走适配层）、SK-004 报告生成（`company.report.generate`/report_generation）、SK-005 企业知识问答（`company.knowledge.answer`/knowledge_qa）。**仅 SK-005 = Active，其余= Draft（未开发）。**

## 架构风险（冻结登记，本阶段不修复）

- **R1** 默认 Provider=grok 但 GROK_API_KEY 未配置（重大，运维授权处理）
- **R2** `ai_generation_records` 缺 skill_id/skill_version（中，统一 migration）
- **R3** 知识源级 ACL 未建立（中，独立授权后最小 migration）
- **R4** `/api/hse/ai` 历史双 Router 挂载（重大，后续统一入口）
- **R5** 部分历史 AI 代码绕过 Gateway（重大，后续收敛到 aiGateway）

## 适用范围

- 影响：所有公司级 AI Skill（SK-001~SK-005 及后续）、HSE AI 与 Company Skill 的边界、AI 记录/证据/Prompt/权限口径。
- 不影响：HSE 现有业务规则、既有 `/api/hse/ai/*` 路由、生产配置。
