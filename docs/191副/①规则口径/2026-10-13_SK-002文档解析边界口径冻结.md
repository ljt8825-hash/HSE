## 规则 / 口径内容

SK-002（company.document.parse v1.0.0，AI-Phase-01-05）实施中冻结的边界口径：

1. **0 字节文件边界（§二十五）**：
   - 0 字节 `.txt` / `.md` → 属「合法文件但文本为空」→ **安全返回**：`success=true + ai_called=false + confidence=low`（UNPARSEABLE_TEXT 文案），不走错误；
   - 0 字节 `.pdf` / `.docx` → 解析器抛错 → **AI_FILE_INVALID**（真非法文件路径）；
   - skill 内 Buffer 守卫只拦「非 Buffer 的程序性错误」，不拦 0 字节（守卫收窄决策）。
2. **AI 统一错误信封渲染位置**：统一 AI 错误信封唯一出口是控制器 `handleError()`；上传层 multer 错误不经控制器，**必须在路由层包装器内直接 `res.json(toErrorResponse(...))`**；路由层 `next(AiError)` 会落入通用错误处理器（HTTP 500 + `{"code":-1}`），禁止。SK-001/SK-002 上传端点均按此约定（D7 修复固化）。
3. **aiContextMaxChars = 2000**：SK-002 AI 上下文预算冻结为 2000 字符（实测校准：3000 时 T01 129.7s 超前端 120s 预算；配合 limitAiContext 三级降载 tier1/tier2/tier3）。依据本地 qwen2.5:7b 纯 CPU prefill ≈39 tokens/s；生产切换更强 provider 时可重测放宽。
4. **格式支持边界（§七/§八）**：支持 `.pdf/.docx/.txt/.md(.markdown)`；`.doc` 无稳定纯 Node 方案 → `AI_UNSUPPORTED_FILE_TYPE` 不强做；xlsx/csv 归 SK-001 不重叠；OCR 不混入 SK-002，扫描 PDF → `extractable=false` 安全返回，禁止 AI 猜内容。
5. **页码口径**：docx 无可靠页码来源 → `page=null`（不虚构）；PDF 页码来自 pdf-parse v2 `-- N of M --` 标记行真实切页。
6. **权限口径**：SK-002 允许角色 allowlist 与 SK-005/SK-001 逐字一致（8 角色 fail-closed）；actor 仅取 `req.user.id/role`，不推断 employee_id/grid_id。
