# AI 识图「OpenAI 兼容通道」与 DSH 开关口径（CF-WPS-VISION-01 / 02 / 03 / 04）

- 日期：2026-10-19
- 类别：①规则口径
- 归属：`server/services/ai/visionService.js`、`web-naive` 培训记录页「AI 识图」
- 状态：生效，与 `2026-09-17_AI识图视觉参数与开发栈代理注入口径冻结.md` 并存（后者仍是 Ollama 通道的口径）

## 一、为什么加这一层

原来 `visionService` 只会说 Ollama 的 `/api/chat`（图片放 `messages[].images`）。
本机装好 dsh + `dsh-our-free-model` 后，它对外提供的是 **OpenAI 兼容** `/v1/chat/completions`
（图片走 `image_url` dataURL），协议不同，无法直接指过去。本次加一层传输适配，**默认仍是 Ollama**。

## 二、通道选择（每次调用时读 env，改完重启即生效）

| 配置 | 结果 |
|---|---|
| 都不配 | `ollama`（行为与改造前完全一致） |
| `VISION_PROVIDER=openai` + base + model | `openai` 通道 |
| 只配 `VISION_OPENAI_BASE_URL` | 自动视为 `openai` 通道 |
| `VISION_PROVIDER=openai` 但缺 base/model | **明确报错**，不静默回退 Ollama |

| 变量 | 说明 |
|---|---|
| `VISION_PROVIDER` | `ollama` / `openai`（也认 `openai-compatible`、`gateway`、`relay`） |
| `VISION_OPENAI_BASE_URL` | 例 `http://127.0.0.1:18899/v1`；不带版本段会自动补 `/v1` |
| `VISION_OPENAI_MODEL` | 例 `nvidia/nemotron-3.5-super-vl:free` |
| `VISION_OPENAI_API_KEY` | 网关 key；同时以 `Authorization: Bearer` 与 `x-api-key` 发出 |
| `VISION_OPENAI_TIMEOUT_MS` | 默认沿用 `OLLAMA_VL_TIMEOUT_MS` / `AI_TIMEOUT_MS` / 300s |
| `VISION_OPENAI_JSON_MODE` | `auto`（默认，先带 `response_format`，被拒去掉重试）/ `on` / `off` |

## 三、协议映射

| 语义 | Ollama | OpenAI 兼容 |
|---|---|---|
| 端点 | `POST {base}/api/chat` | `POST {base}/chat/completions` |
| 图片 | `messages[0].images = [b64]` | `messages[0].content[1].image_url.url = data:<mime>;base64,...` |
| 强约束 JSON | `format: 'json'` | `response_format: {type:'json_object'}`（可降级） |
| 温度/上下文 | `options.temperature / num_ctx` | `temperature`（无 num_ctx 概念） |
| 取正文 | `message.content` / `response` | `choices[0].message.content`（含 parts 数组） |

响应解析统一走 `extractText → extractJson`，两条通道共用同一套「去围栏 / 平衡括号 / 裸数组包 rows」清洗。

## 四、顺带修掉的既有 bug

`extractJson` 策略 1 直接 `JSON.parse` 成功时原样返回；模型若吐**裸数组** `[{...}]`，
调用方读 `json.rows` 得到 `undefined`，整页结果被静默丢弃。现统一包成 `{rows:[...]}`。

## 六、dsh 侧注意事项

- 网关默认**关闭**。开：dsh → 设置 → 本地 OpenAI 网关（默认 `127.0.0.1:18899`）。
- key 不在 `~/.dsh/openai-gateway/api-key`（那是 **chan-relay** 的 key，格式 `ofm-…` 但用途不同），
  真正的 forward key 在 `~/.dsh/our-free-model/settings.json` 的 `forwardKey`；UI 里也能直接看到。
  服务端**自动读取**该文件，无需手工配置 `DSH_API_KEY`（配了则优先用 env）。
- 免费渠道无 SLA，`availability.json` 会因 IP 判定整批 `unavailable`（当日 EAC 全线曾不可用）。
  **建议：dsh 只作为可选加速通道，Ollama 保持默认兜底。**

## 七、前端「DSH 识别」开关（CF-WPS-VISION-02）

位置：培训记录 → 导入弹窗 → AI 识图卡片右上角。

- **开** = `provider=dsh`，走 DSH 本地网关；**关** = `provider=local`，走本机 Ollama（默认）。
- 选择落 `localStorage['hse.ai.vision.provider']`，刷新后保持。
- 旁边的状态灯：绿=可用 / 红=不可用 / 灰=未知；hover 显示当前模型与失败原因。
- 每次打开导入弹窗自动探测一次（`GET /api/training-ocr/ai-provider`，服务端结果缓存 10s）。

请求链路：

```
表单 provider=local|dsh
  → POST /api/training-ocr/ai-recognize（multipart 字段 provider）
  → trainingOcrService.aiRecognize → normalizeAiProvider()
  → runAiJob({provider}) → recognizeLedgerImage / recognizeSigninSheet({provider})
  → visionService.callVision({provider}) → resolveVisionProvider(provider) 覆盖 env
```

**优先级铁律**：`provider=local` 必须压过 `.env` 里的 `VISION_PROVIDER=openai`——
开关关掉就得回本地，否则用户以为切了实际没切（已有单测锁定）。

响应 `meta` 会如实回报实际通道：`channel: 'ollama-vl' | 'dsh-vl' | 'openai-vl'`，前端据此可核对。

## 七之二、模型下拉框与附加提示词（CF-WPS-VISION-03）

### 模型下拉框（仅开关打开时出现）

数据源是服务端白名单 `DSH_VISION_MODELS`，**只收真正接受 `image_url` 的模型**——
其余模型放进去只会在识别时报 `No endpoints found that support image input`。

2026-10-19 在本机 `127.0.0.1:18899` 逐个实测：

| 模型 | 渠道 | 结果 |
|---|---|---|
| `nvidia/nemotron-3.5-super-vl:free` | kilo | ✅ 2.3s（推荐，默认） |
| `nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free` | kilo | ✅ 4.1s（上游偶发 502 ResourceExhausted） |
| `openrouter/free` | kilo | ✅ 4.3s |
| `kilo-auto/free` | kilo | ✅ 4.5s |
| `nemotron-3.5-super-vl-free` / `deepseek-v4.1-flash-free` / `glm-5.3-flash-free` / `space-bunny-free` / `big-pickle` | EAC | ⚠️ 本机 IP 被判滥用，整批 403 |
| `nvidia/nemotron-3.5-lightning:free` | kilo | ❌ 拒绝图像输入（已排除） |

- EAC 模型从插件 `availability.json` 读可用性，`available=false` 时下拉框置灰并标注「当前不可用」。
- 选择落 `localStorage['hse.ai.vision.model']`；失效/未选时自动落到第一个可用模型。
- 服务端二次校验：`provider=dsh` 且传了 `model` 时，必须在白名单内，否则 `-8 不支持的视觉模型`。
- 扩展白名单：`DSH_VISION_MODELS=my-vl-1,my-vl-2`。

### 附加提示词

- 前端 `NInput type=textarea`（≤300 字），**不持久化**——每次识别需求不同，留旧提示反而误事。
- 服务端截断到 500 字，`appendUserPrompt()` 追加到系统提示词**尾部**，并明确写
  「必须服从上面的 JSON 输出格式与字段口径；冲突时以 JSON 格式为准」。
- **不替换**原提示词：JSON schema、枚举候选、字段口径是下游解析的前提，被替换就必然解析失败。

实测（同一张样图）：提示词写「只识别表格中的第一行，其余行全部忽略」→ 返回 **1 行**（基线是 3 行）。

## 七之三、瞬时错误自动重试（CF-WPS-VISION-04，2026-10-19）

**背景**：用户用 DSH 免费渠道识别 PDF 时报「视图网关识别失败（HTTP 502）：Provider
returned error」。日志断案：文案出自 `assertVisionResponse` openai 分支，`Provider
returned error` 是 dsh 网关透传的上游（kilo 免费渠道）错误体——网关/key 均正常，
**免费渠道瞬时抖动，非代码 bug**。同类故障用户无法自行区分，故加重试 + 友好文案。

**重试口径**（仅 OpenAI 兼容 / DSH 通道，本地 Ollama 不重试——自建服务没有瞬时抖动）：

- 瞬时状态码集合 `TRANSIENT_GATEWAY_STATUS = {408, 429, 502, 503, 504}`；
  网络层错误（`postJsonUrl` reject，如 ECONNRESET）同样触发。
- 每次逻辑发送最多 **2 次尝试**（首帧失败 → `sleep(延迟)` 原样重发）；
  延迟取 `VISION_TRANSIENT_RETRY_DELAY_MS`（默认 2000ms，显式配 0 表示不等）。
- 与 jsonMode=auto 的 `response_format` 被拒兜底链路**互不破坏**：最坏情况
  502 → 重试撞 400 拒绝 → 去掉再发，共 3 次请求（有用例钉住）。
- 仍然失败时文案统一为「视觉网关瞬时错误（HTTP xxx，已自动重试一次仍失败）」，
  dsh 通道额外给可操作建议：换免费模型 / 关 DSH 开关回本机 Ollama。
