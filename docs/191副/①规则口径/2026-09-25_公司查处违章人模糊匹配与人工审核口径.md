# 公司查处违章人·模糊匹配与人工审核（冻结口径 + 交付）

> 日期：2026-09-25 ｜ 归属对话：三违分析「公司查处扣分」+ 人工审核
> 类别：①规则口径 + ②交付报告

## 一、需求

公司网格长（总网格长 + 一级网格长）查处的违章人，姓名常含笔误（如 李兰凤→李兰风、杜瑞兰→杜润兰、范志新→范治新、王春灵去备注）。询问可否按「模糊查询」匹配，再由人工审核处理。用户确认采用「落库持久化」方案，并授权共享库新建「违章人名→员工」映射表实施。

## 二、冻结口径（2026-09-25）

- **匹配策略 = 三级，依次兜底**：
  1. **冻结笔误归并**（NAME_ALIAS，常量）：姚奎岭→姚奎领、李建方→李建芳、李凤丽→李风丽、范志新→范治新（8 月）；李兰凤→李兰风、杜瑞兰→杜润兰（9 月）。袁书霞/王春灵等由「去括号备注/空白」清洗（cleanVName）覆盖。
  2. **花名册姓名精确匹配**：清洗后姓名命中 `employee.name`（`is_deleted=FALSE`），取 `roster_department` 归乡镇。
  3. **人工审核映射表**：前两级未命中 → 落入「待审核」；人工审核后写入映射表。
- **公司查处扣分规则**：每起扣分 = 违章行为含「头盔/安全帽」→ **5 分/起**；其他三违 → **1 分/起**。
  - 统计对象：`personnel_name` ∈ 公司管理网格长 = `['黄殿兴','刘金涛','张康','刘菲','韩晓亮','黄元同']`（总 1 + 一级 5）。
  - 排除「无三违行为 / -- / - / 无」等非真三违行为。
  - 乡镇归因：公司管理记录 `area_team` 恒为「公司管理」，无法按巡查区域归乡镇 → 按违章人姓名→花名册「所属部门」含某经理乡镇名（最长匹配）判定乡镇。
- **注意：公司查处扣分 ≠ 网格缺巡**。缺巡=网格长未完成巡查（GRIDCHECK001，1 分/次）；公司查处=公司管理查处三违（本口径）。

## 三、人工审核（落库持久化）

- **新表**：`hse_violator_name_resolution`
  - `source_name`（清洗后原始违章人名，UNIQUE）→ `employee_id` + `employee_name`（冗余展示）。
  - `employee_id/employee_name` **均可空**：NULL 表示「确无此人/不计入」（抑制，不再进待审核）。
  - `remark`（备注）、`resolved_by`（审核人 account）、`created_at/updated_at`。
- **审核结果**：跨月/跨用户/刷新均保留，计入该公司该项员工所属乡镇的公司查处扣分。
- **接口**（均 `requireRole('admin','safety_manager')`）：
  - `GET /hse/sanwei-analysis/company-deduct/employee-search?keyword=` 花名册姓名模糊搜索（ILIKE，最多 20 条，附所属部门）。
  - `POST /hse/sanwei-analysis/company-deduct/resolution` body `{source_name, employee_id?, remark?}`；employee_id 省略/null=抑制项；`ON CONFLICT (source_name) DO UPDATE` 幂等。
  - `DELETE /hse/sanwei-analysis/company-deduct/resolution?source_name=` 撤销一笔（回到待审核）。
- **list 响应新增**：
  - 每行 `companyDeduct: { score, helmetCount, otherCount }`（当月该乡镇公司查处扣分）。
  - 顶层 `companyUnresolved: [{ month, sourceName, count }]`（待审核清单，前端经理 tab 展示「公司查处·待审核 n」按钮 + 弹窗人工归属）。

## 四、前端（analysis.vue · 经理 tab）
