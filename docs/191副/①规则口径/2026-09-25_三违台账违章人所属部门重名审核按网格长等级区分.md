# 规则 / 口径 归档：三违台账「违章人所属部门」重名审核按网格长等级区分

- **日期**：2026-09-25
- **归属对话**：当前会话
- **类别**：①规则口径

## 规则 / 口径内容

「现场管理 → 三违管理 → 三违台账」新增「违章人所属部门」列。违章人姓名在台账中为自由文本，先从全量花名册（含离职人员）按姓名清洗（去括号备注/空白）后匹配部门。归属规则按**巡查网格长等级**区分：

> **归属 / 持久化口径更新（2026-09-25 会话内追加）**：人工在「重名」行下拉中选择的「违章人所属部门」会通过 `PUT /grid-records/:id`（白名单字段 `violator_dept`）**持久化**到 `grid_inspection_records.violator_dept` 列，刷新/翻页后不丢失。本页不再遵循「派生态只读不落库」原约束（仅限该部门列），其余列保持只读。清空选择则回退为「待选择」(`unselected`)。同时新增「违章人所属部门」筛选项：`未匹配` / `未选择部门` / 具体部门名。

归属 / 持久化规则（当前生效）：

1. **总网格长 / 一级网格长**巡查的三违：其巡查跨乡镇/班组，违章人可能隶属他处 → 同一违章人姓名在花名册命中多个部门（重名）时，姓名列以「重名」Tag 标注，所属部门由**人工在下拉中选择**；选择结果持久化到 `violator_dept` 列（状态=`matched`）；未选择则状态=`unselected`，可在筛选中归入「未选择部门」。
2. **二级 / 三级网格长**巡查的三违：他们只巡查本人所属部门 → 对应的违章人就是该部门的人。即使姓名重名也**不需要人工审核**，直接按「巡查网格长（personnel_name）所属部门」在违章人候选中自动归属；若巡查人部门未能命中候选或违章人姓名整体未命中花名册，则视为「未匹配」(`unmatched`)，可在筛选中归入「未匹配」。

未匹配判定（`unmatched`）：违章人姓名清洗后未命中任何花名册员工，或二级/三级网格长巡查人部门未命中违章人候选。此类行 `violator_dept` 为空、状态=`unmatched`。

## 适用范围

- 页面：`web-naive/src/views/site/violation/ledger.vue`（三违台账）
- 路由：`/site/violation/ledger`
- 数据源：`grid_inspection_records`（巡逻台账派生）+ 花名册员工主数据（`/hse/employee/employees`，`dept_name` 即所属部门）

## 触发背景

用户先行提出需按违章人姓名从花名册自动匹配「所属部门」，重名时标注并人工选择。随后补充细化口径：重名仅总/一级网格长需人工审核；二级/三级网格长巡查的违章人必在其本部门，重名也自动归属、不人工。经实测确认 `grid_level` 取值为 总网格长/一级网格长/二级网格长/三级网格长，`personnel_name`（巡查网格长姓名）完整度 100%。本次会话再追加两点：①人工选择的「所属部门」需**自动保存**到 `violator_dept` 列；②增加「违章人所属部门」筛选项（含未匹配/未选择）。已固化为上述「归属 / 持久化规则」。

## 交付 / 实现（2026-09-25）

- 数据库：已执行生产 `ALTER TABLE grid_inspection_records ADD COLUMN violator_dept VARCHAR(100)`（2026-09-25 用户显式授权，单次留痕）。
- 后端：`siteMgmtService.js` 新增 `ATT_DEPT_UNMATCHED/__unmatched__`、`ATT_DEPT_UNSELECTED/__unselected__` 标记与 `buildAttDeptMap()`/`deriveAttStatus()` 归属解析；`gridRecordList` 支持 `attDept` 筛选（未匹配/未选择/具体部门）并返回 `violatorDept`+`violatorDeptStatus`；`gridRecordFilterOptions` 返回 `attDepartments` 部门选项；`GRID_RECORD_EDITABLE` 白名单加 `violator_dept`，`gridRecordUpdate` 据此持久化。
- 前端：`web-naive/src/views/site/violation/ledger.vue` 新增「违章人所属部门」筛选项，重名下拉选择后经 `updateGridInspectionRecord` 持久化（`onSelectDept`），展示以 `violatorDept`/`violatorDeptStatus` 为准；`api/hse/site.ts` 扩展类型与参数。
- 验证：服务层实测 `attDept=unmatched=76`、`attDept=unselected=3`（一级网格长：李连荣/李振清/刘金华）；保存 `violator_dept` 后重读为 `matched` 且按部门筛选命中；确认后清理验证写入项。
- **缺陷修复（同日追加）：按「未匹配/未选择」筛选后三违照片不显示**——根因 `gridRecordList` 的 `attDept` 分支原先 `SELECT` 窄列集（未含 `image_content/rectified_photo`），`formatGridInspectionRow` 因此返回空图。已改为 `SELECT *`，`unmatched` 分支实测 `imageContent/rectifiedPhoto` 5/5 行非空；`unmatched`/`unselected` 共用同一代码路径，一并修复。后端 5888 重启加载，health 200，未碰 5876。
- 附注（数据现状）：此前 3 条 `unselected`（李连荣/李振清/刘金华）经用户在前端人工选择后，`violator_dept` 已落库（大柳镇/大柳镇/时集镇），故当前「未选择部门」筛选自然为 0——功能按预期收敛，非缺陷。
- **「未匹配/待选择」就地修正入口（2026-09-25 用户选定「选部门+可改违章人姓名」方案）**：此类行在表格中提供两处编辑控件——①「违章人姓名」列改为可编辑输入框，保存 `violator_name`（已在 `GRID_RECORD_EDITABLE` 白名单，同一 PUT 接口即持久化）后自动重载，按新姓名重新从花名册派生所属部门（修正后姓名唯一命中→`matched` 自动归属；仍不命中→维持 `unmatched`）；②「所属部门」列对 `unmatched` 行渲染全部部门下拉（`allDeptOptions`，来自 `filterOptions.attDepartments`），手动选定后落 `violator_dept` 并移出未匹配。二者均写回底层 `grid_inspection_records` 对应列。服务层实测：未匹配行 id=8399 姓名 孙俊萍→改「黄殿兴」后重新派生 `matched`/项目管理层，恢复原名后回退 `unmatched`，无数据污染。前端 `ledger.vue` 新增 `onSaveName`（按 record id 去重防并发）、`allDeptOptions`，typecheck 零报错。
- **两处二次修复（2026-09-25 追加）**：①「违章人姓名」之前改不了——根因 NInput 仅绑 `:value` 未绑输入回调，Naive 将其当受控组件冻结，无法输入；现改为 `:value`+`@update:value` 写入按 record id 缓存的本地输入态 `nameEditMap[row.id]`，blur/enter 时 `onSaveName(row)` 读该输入态校验后保存。②「所属部门选错无法改」——根因部门落库后 `violatorDept` 非空即被 `deptDisplay` 判为 `auto`（纯文本），下拉消失；现后端 `deriveAttStatus` 对已落库 `violator_dept`（非哨兵值）返回新状态 **`manual`**（区别于 `matched` 自动归属），前端对 `manual` 与 `unmatched`/`unselected` 三种状态均保留可改下拉（全部部门），选错可随时更改/清除；`site.ts` 状态联合类型补 `'manual'`。实测：落库 8 行返回 `manual`、自动归属 170 行 `matched`、未匹配 22 行，后端 5888 重启加载、前端热更新，未碰 5876。
- **姓名修改权限收口（2026-09-25 用户确认「按此方案加角色判断」）**：仅 **admin** 可修改「违章人姓名」（`violator_name` 属影响统计口径敏感列）；普通安全员等只能选/改「所属部门」，不能改姓名。双重拦截——前端按 `userStore.userInfo.roles` 的 `isAdmin` 隐藏改名输入框（部门下拉对非 admin 仍保留可用）；后端 `gridRecordUpdate` 在「集散→白名单」前 fail-closed 校验，`violator_name !== undefined && user.role !== 'admin'` → 403「无权限修改违章人姓名」，PG 与内存分支一致。实测：admin 改名 OK，safety_manager/grid_manager/anonymous 均 403，测试后已恢复原名无污染。
- **二/三级拍摄直接按拍摄网格长部门归属（2026-09-25 用户追加口径）**：只要该条「不是公司管理（总/一级）拍摄的」，即按拍摄记录里 `personnel_name`（二级/三级网格长）本人所属部门自动归属，**即使违章人姓名脏化/多人合并/未命中花名册也不再判未匹配**——因为二级/三级网格长只巡查本人部门，违章人即其部门。`deriveAttStatus` 非公司级分支改为：`sup=map[clean(personnel_name)]` 有值即 `matched{sup[0]}`；仅当拍摄网格长部门未知才兜底用违章人唯一命中部门、否则未匹配。公司级分支维持按姓名匹配（命中1→matched、0→unmatched、多→unselected 待人工）。实测 `deriveAttStatus` 全量 200 行：matched 174 / manual 25 / unmatched **仅剩 1**（id=6730 一级网格长张相岗拍摄、违章人「楊印正」生僻字未命中花名册，按规则正确保留未匹配）；此前 22 条未匹配中的二/三级已全部自动归到拍摄网格长部门，前端 `deptDisplay` 局部兜底同步对齐（typecheck 零报错）。
- 遗留：部分台账违章人姓名为脏数据（含标点/多人合并如「孙孟坤，商恩来」「王振梅′''」、省略号「--」），归属为 `unmatched`，属源数据质量问题，非规则缺陷。
