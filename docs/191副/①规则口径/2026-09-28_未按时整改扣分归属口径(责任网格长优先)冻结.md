## 规则 / 口径内容

「三违管理考核」管理员 tab「未按时整改」扣分归属（取代此前"按直接上级归属"单一口径，2026-09-28 升级冻结）：

1. **责任网格长优先**：`grid_inspection_records.grid_id → grid_areas.id → grid_areas.personnel_id → hse_assessment_target.employee_id`。
   - 记录有 `grid_id` 且该网格 `personnel_id` 对应的责任网格长在考核目标名单内 → 扣该网格长 1 分/起。
2. **违章人直接上级兜底**：当记录无 `grid_id`，或责任网格长未命中考核目标时，按被查处人「直接上级」归属（`resolveViolatorAttribs` 解析 supervisor+dept，dept 按候选乡镇匹配后映射到考核目标 employee_id）。
3. **计分口径**：真三违（`violation_behavior <> '无三违行为'`）且 `rectified_photo` 缺失/占位（NULL/''/--/-/无）= 未整改，**每起 1 分**，当月（`to_char(inspection_date,'YYYY-MM')`）归集。
4. **乡镇作业中心经理 tab**：按 `regionBase(area_team)` 乡镇归因，与 sanweiLedgerDerive「未完成整改」口径对齐。
5. **保洁员扣分不再波及全镇管理员**（全员+1 缺陷已修复）。

## 适用范围

- 页面：web-naive「三违管理」→「三违管理考核」管理员/乡镇作业中心经理 tab
- 后端：`server/routes/hse-violation-assessment.js`（`/list` 的 rectifiedDeduct 计算）
- 数据表：`grid_inspection_records`、`grid_areas`、`hse_assessment_target`、`hse_sanwei_score_monthly`（均只读）

## 触发背景

用户反馈"保洁员扣分后全镇管理员都扣分"根因是未按人归属；修复后要求三条口径并存：①保洁员上级、②管理员/乡镇作业中心经理自己巡查致三违填报不完整、③未按时整改。本口径聚焦③；①②沿用既有落库口径（`violation_event` 按直接上级、`violation_unrectified` 按考核引擎落库）。

修复过程中定位两处代码缺陷：返回块引用不存在的变量 `unrectifiedSupMap`；`grid_areas.personnel_id` 为 bigint 导致 `trim(personnel_id)` 触发 `btrim(bigint)` SQL 错误。均已修复。
