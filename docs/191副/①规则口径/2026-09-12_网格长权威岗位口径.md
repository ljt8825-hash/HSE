## 规则 / 口径内容

1. **「网格长权威岗位口径」**：**网格长仅限以下四类岗位**——`总经理`、`部门经理`、`乡镇作业中心经理`、`管理员`。

2. **保洁员/中转站管理员不兼网格长**：员工主数据 `employee` 中岗位为「乡镇保洁员」「中转站管理员」等非管理岗的人员，**不是也不能充当网格长**。凡台账 `violation_records.position/grid_level` 将这类人员标为上述四类网格长岗（如 `三级网格长`/`二级网格长`）的，一律视为**身份错配**，须将 `position` 归位到员工实际 HR 岗位 `roster_position`，`grid_level` 置空。

3. 判定依据：以员工主数据 `roster_position` 为准，非以台账自由文本 `position` 为准。

4. **「人工班长=管理员=三级网格长」（同名异称，业务确认）**：花名册岗位写作「人工班长」的同一批人，在考核体系中就是「管理员」「三级网格长」，属于网格长序列。故判定是否错配**不能只看 roster_position 字符串**（人工班长、保洁员都非网格长岗字样）：
   - **保洁员 / 中转站管理员**台账被标「管理员/乡镇作业中心经理」→ **错配**，归位到 roster_position、grid_level 置空；
   - **人工班长**台账被标「管理员/乡镇作业中心经理」→ **正当身份**，它们是真实考核对象（在 `hse_assessment_target` 以 `position='管理员'` 参与考核），**保留不动**。

## 适用范围

- 现场管理 → 三违管理 → 三违台账（`violation_records`）
- 现场管理 → 三违管理 → 三违管理考核 / 三违分析（`hse_assessment_target`）
- 未来所有三违台账/考核导入与校验，均按此口径识别身份错配

## 触发背景

- 用户对「三违台账」大组「保洁员→管理员/乡镇作业中心经理」（约 500+ 条）曾判为「保洁员兼任网格长职责、未改动」。
- 用户纠正：**「保洁员只是保洁员，网格长只有总经理、部门经理、乡镇作业中心经理、管理员才是」**。
- 据此冻结本口径，并批量归位 501 条错配（见②交付报告《2026-09-12_三违台账4922身份错配修正》）。
