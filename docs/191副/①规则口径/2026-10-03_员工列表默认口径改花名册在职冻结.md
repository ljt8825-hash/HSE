# 规则 / 口径 归档

> 用途：记录经确认不可再改的规则、数据口径、岗位归属、映射表。

- **日期**：2026-10-03
- **归属对话**：当前会话（花名册在职 1303 与员工列表/档案不一致）
- **类别**：①规则口径

## 规则 / 口径内容

1. **员工列表默认口径 = 花名册在职**：默认（未点统计卡、未选状态）仅显示 `employee.employment_relation = '正式员工'` 的员工（实测 1297 人），与统计卡「在职人员」一致。**取代 2026-10-01 冻结的「存在当前主岗任职」口径**（该口径 3447 人含花名册已辞职/死亡/空关系的 2150 人，与花名册矛盾，故升级）。
2. **离职口径**：`employment_relation IN ('辞职','死亡')`（实测 1958 人），列表「离职」筛选与统计卡「离职人员」同源。
3. **状态筛选映射**：列表与档案的「在职/离职」筛选一律走花名册用工关系权威；「待岗/退休/返聘」仍按 `employee_assignment.status`（`pending/retired/reinstated`；前端值修复 `rehire`→`reinstated`）。
4. **员工档案页**：档案总数=全部未删除员工（`is_deleted=false`，实测 3469）；在职=1297、离职=1958，与员工列表页一致；新增「在职/离职」筛选（`getProfileList status=active|left` 映射花名册）。

## 适用范围

- 人员管理 → 员工列表（web-naive `employee/index.vue`）、员工档案中心（`employee-profile/index.vue`）
- 后端 `employeeService.js listEmployees`、`employeeProfileService.js getProfileList`
- 跨模块引用员工"在职/总数"对账时：先按「花名册用工关系（正式员工 / 辞职+死亡）」口径核对

## 触发背景

用户反馈「花名册中在职员工 1303，员工列表中显示数据不对，员工档案中无法查询在职人员数量」。只读核对：员工列表默认 3447 ≠ 花名册在职 1297/1303；档案页无在职统计与筛选。经用户确认修复方案（员工列表默认=仅花名册在职；档案页=统计卡+状态筛选）。
