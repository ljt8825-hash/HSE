# 自动评分「HSE教育培训」列扣分明细拆分：缺少人员 / 资料不完整

> 类别：②交付报告　日期：2026-09-26　归属对话：当前会话

## 需求
「自动评分」页 **HSE教育培训** 维度列的扣分，点击后明细不应合并成一条「培训台账缺训」，而应拆分为两个独立指标项展示：**「缺少人员」（缺训人数）** 与 **「资料不完整」（资料份数）**。两 tab（管理员 / 乡镇作业中心经理）同逻辑。

## 现状（改动前）
培训台账适配器（`server/services/ruleEngine/adapters/trainingLedgerAdapter.js`）把缺训人数（missing）与资料不完整份数（incomplete）合并成一条 `hse_assessment_deduction`，`deduction_item`=规则名「培训台账缺训（缺少/资料不完整）」。前端 `openDimDetail` 按 `ruleName` 分组，导致管理员 tab 的 HSE教育培训 点开只显示一条合并项，无法区分「多少人缺训 / 多少份资料不完整」，与三违列「逐列明细」的口径不一致。

## 实现（2 文件）

### 1. 后端：透出源指标（只读增强）
`server/services/assessmentMonthlyExportService.js` → `getTargetDeductions`（`/cycles/{id}/targets/{id}/deductions`）：
- 每行明细在原 `summary` 基础上新增 `sourceDetail` 字段透出 `d.source_detail` 全量（含训练台账通路的 `missing` 缺少人数 / `incomplete` 资料不完整份数 / `unit` 单份扣分）。
- 纯读取字段透出，不动库、不动扣分逻辑，不影响现有消费方。

### 2. 前端：HSE教育培训 专属拆分明细 + 类型
`apps/web-naive/src/api/hse/assessment-monthly.ts`：`TargetDeduction.sourceDetail` 为可选类型（missing/incomplete/unit），后端未返回时不影响其他维度列。

`apps/web-naive/src/views/hse/assessment-monthly/scoring.vue` → `openDimDetail`：
- 类别为 HSE教育培训 时，遍历同类别明细：凡携带 `sourceDetail.missing/incomplete` 的按 **`缺少人数 × unit` → 明细项「缺少人员」**、**`资料不完整份数 × unit` → 明细项「资料不完整」** 累加（unit 默认 1）。
- 仅存在源指标才生成这两项；若某项计数为 0 则不展示（避免 0 分空项）。
- 同类别下非培训台账通路的明细仍按原 `ruleName` 合并，互不干扰。
- 下钻、合计、空明细提示、居中模态框等交互不变。
