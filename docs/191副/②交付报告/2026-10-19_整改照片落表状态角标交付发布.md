# 整改照片落表状态角标 交付与发布（2026-10-19，CF-WPS-107，版本 .108）

> 类别：②交付报告。承接同日「整改后照片台账漏挂死锁修复」（.107）的遗留建议：手机端「显示照片」≠「已落台账」，用户决策加角标。

## 需求与方案

在整改后照片区加「已落台账 / 待补传」状态角标：绿「✓ 已落台账」/ 橙「待补传 ↻」，**待补传可点击立即重试**（bindLandBadgeRetry → retryPendingSyncOnce → 成功就地重绘翻绿）。

## 关键设计决策：显式落表标记 rectifyLanded

实施中发现 .107 修复仍有盲区：**本机终态（attach 成功：token 有 + pending 无）与死锁存量（token 上传成功但 attach 失败：token 有 + pending 无）在本机状态上完全不可区分**——按 .107 的 `(pending || !token)` 判定，15:35 那单会被错标「已落台账」，且补偿循环仍跳过它。

修正为 **rectifyLanded 显式标记**（唯一权威）：

- **置位点 4 处**（全部 = attach/complete 真成功）：①syncRecordOnce 补偿块 ②补偿循环 ③整改完成即时补挂分支 ④fromServer complete 带照片回写成功。
- 判定 `rectifyLandState(rec) = rec.rectifyLanded ? landed : pending`；**禁止以 token 存在性当已落依据**。
- 补偿循环条件改 `afterPhoto && !rectifyLanded` → 存量死锁数据（含 15:35 单）自动重 attach（写同列同 token，**幂等无害**）→ 成功置标记收敛；正常终态数据有标记 → 不重试，无写放大。
- 一次性成本：老版本正常落表过的记录缺标记 → 首次被扫到会重 attach 一次后置标收敛，可接受。

## 覆盖 UI 路径（renderDetail / renderServerDetail 双路径）

| 路径 | 旧行为 | 新行为 |
|------|--------|--------|
| renderDetail（本机记录详情，**15:35 单盲区**） | 仅文本「已拍摄」，无落表状态 | 照片框角标 landed/pending + 点击重试 |
| renderServerDetail 本机副本 | 已有文本「已同步/待上传」 | 保留文本 + photo-box 加角标 + 重试 |
| renderServerDetail 服务端 token | 无标注 | 外层 relative wrapper 加「✓ 已落台账」（token 来自台账列必然已落；renderServerPhotos 会清空容器故角标放 wrapper） |

CSS：`.photo-land-badge`（absolute 右上、绿 rgba(22,138,60,.92)/橙 rgba(217,119,6,.94)、pending::after " ↻"），.photo-box 补 position:relative。
