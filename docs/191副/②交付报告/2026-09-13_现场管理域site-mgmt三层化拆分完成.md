## 关键技术决策与本单特殊处理
1. **`gridDataSourceMode(res)` 改造**：原 helper 依附 `res` 直接在此响应配置错误。service 内改为 `gridDataSourceModeGuard()` —— 'misconfigured' 时返回 `{__t:'json', error:{code:-2, message:WPS_CONFIG_ERROR}}` 描述符让 controller 发送，否则返回 `'wps'|'pg'`；调用端点以 `isConfigErrorDescriptor()` 短路返回。WPS_CONFIG_ERROR 文案原样保留，禁止静默回退 PG。
2. **WPS/PG 双数据源分支逐字保留**：`wps` 走 gridWps 仓库、`pg` 走 PG，SQL/排序/筛选/内存逻辑原样搬移，不因重构改数据落点。
3. **权限/范围中间件分层**：`requirePermission('hse:site:grid:*')`、`requireRole` 留在 main.js 绑定层；`resolveGridScope/buildScopeSqlCondition/deriveGridIdForEmployee/SCOPE` 属纯计算业务留在 service；service 需 req.user/logger/ip 处经 controller 的 `gridCtx(req)` 传入。
4. **httpStatus 保留**：原实现 grid-records 多处用 `res.status(403/400/401/409/503)`，respond() 扩展 `httpStatus` 字段，逐个字节保留 HTTP 状态码。
5. **内存单例转发**：原文件除 router 外导出 `memoryStores/memoryCounters/initMemoryData`，被 `services/importMemoryService.js` 直接读写。父聚合转发这三者，且 service 与端点共享同一模块缓存单例，内存一致性不破。
6. **grid-areas 原未挂权限**：与原文一致，保持公开（smoke 计入公开 GET 形状而非 401）；grid-records 挂 requirePermission。
