# 领导视角统一看板 下钻弹窗子指标级过滤交付

> 日期：2026-09-28
> 归属：领导视角统一看板（全维度数字下钻）P3.1 增强
> 前置：`/dim-records` 已按维度整体下钻（P3）；本批次为趋势表子指标行（重大事故/严重三违/演练通过/考核优良/驾驶员4子项等）点击时二次过滤

## 一、需求

趋势表每行是一个**子指标**（如「重大事故」「严重三违」「演练通过」「考核优良」），此前点击任一数字只按维度整体返回全部明细（如点「严重三违」返回所有三违记录）。本次让下钻弹窗**按子指标二次过滤**——点「严重三违」只显示严重等级的三违记录，点「考核优良」只显示优秀/良好的考核记录。

## 二、设计

### 后端：`sub` 参数 + DIM_RECORD_SPEC.subs 下发

`GET /dim-records?sub=<子指标键>` 可选；**列/过滤口径仍由后端 `subs` 下发表驱动，前端零重复维护**：

| 维度 | sub 键 | subLabel | 过滤方式（对齐汇总口径） |
|------|--------|----------|--------------------------|
| accidents | major | 重大事故 | 行级谓词 `level ∈ {重大, 特别重大}`（同 summarizeWithMatcher） |
| violations | serious | 严重三违 | 行级谓词 `violation_level === '严重'` |
| assessments | gradeGood | 考核优良 | 行级谓词 `grade ∈ {优秀, 良好}` |
| emergencies | passed | 演练通过 | 行级谓词 `result ∈ {pass, excellent}` |
| drivers | demeritCount / vehicleCheckCount / driverCheckCount / violationCount | 对应中文 | **sources 限定**：violationCount = driverViolations + driverThreeViolations（同汇总口径，违章+三违并集） |
| 其余（count 类） | 无 subs | — | 缺省 sub = 维度整体（不传即全部） |

实现：`subs.sources` 限定来源表（drivers 组合维度），`subs.filter` 为行级谓词；非法 sub → `code 1 不支持的子指标`；响应新增 `sub` / `subLabel` 字段。

### 前端：趋势行携带 sub → 弹窗展示子指标标签

- `LdTrendRow` 增 `sub?: string`；`buildTrendRows` 的 push 原样携带子指标键
- `onTrendCellClick` → `openOrgDim(dim, month, row.sub)`；经理页个人趋势表走 `openPersonalDim(dim, month, row.sub)`（个人口径同样生效）
- 弹窗头部新增 warning 色 NTag 显示 `subLabel`（如「严重三违」），用户可确认当前过滤范围
- 维度格卡片（模块网格）主值=维度整体 count，维持不传 sub（整维下钻）

## 五、数据现状说明（重要，非缺陷）

真实库当前数据下部分子指标恒 0，**过滤谓词与汇总层口径严格一致，弹窗数字=趋势表数字，属正确对齐**：

| 子指标 | 现状 | 原因 |
|--------|------|------|
| 严重三违 | 恒 0 | `violation_records.violation_level` 2026 全年 824 条**全为空串**（字段未维护） |
| 重大事故 | 恒 0 | 事故等级枚举实为 `一级/三级/四级/一般`，与汇总层 `重大/特别重大` 判定不匹配（既有口径问题，非本批次引入） |
| 演练通过 | 恒 0 | `emergency_drills.result` 2026 全年 48 条**全为 null** |
| 考核优良 | 恒 0（长官镇） | 该镇 2026 无考核记录 |
| 驾驶员违章/三违 | **有真实命中** | 2026 违章 6 条 + 三违 7 条，个人口径过滤精确生效 |

「重大事故」等级口径（ACCIDENT_WEIGHT 用 一般/较大/重大/特别重大，表数据用 一级~四级）建议另行评估是否对齐，记入风险待办。
