## 一、诊断链（决定性证据）

- 兜底页版本号显示 .109 → HTML 前半部（head+兜底脚本）完整到达；
- 兜底页**无红框** → 主脚本不是「执行报错」（报错必有红框），而是**整块静默未执行**；
- check.html 主脚本为约 250KB 单块内联 `<script>`（原 L1479-7218，占文件 80%）——HTML5 规范：传输在 script 块中间截断时**整块丢弃且不触发任何错误事件** → 与「fatal 无红框」完全吻合；
- 桌面 curl 全量 445KB MD5 一致 → 服务端资源完整，问题在手机网络路径对大体积单响应的截断（弱网/运营商代理）。

## 二、改动内容（.110）

1. **主脚本外置**：check.html L1480-7217 抽成独立 `check.app.js`（333946B）；原位替换 `<script src="./check.app.js?v=2026-10-19.110" onerror="window.__hseScriptFail=1"></script>`。check.html **445590B → 112132B（-75%）**，大响应截断概率大幅下降；独立 JS 可吃 CDN/HTTP 缓存，老用户二次进入显著提速。
2. **下载失败可自报**：script 标签 onerror 置 `window.__hseScriptFail=1`；兜底 fatal() 新增分支——`__hseFatalErr` 优先（执行错误红框），其次 `__hseScriptFail` 显示「脚本文件下载失败：当前网络中断了页面脚本的传输（页面本体已到达，仅脚本没下来）。请切换网络…」，无信号才显示原网络建议文案。自此三类失败全部可从截图分辨：页面截断（fatal 无信号）/脚本下载失败（netFail 文案）/脚本执行错误（SyntaxError/ReferenceError 红框）。
3. **sw.js 未动**：其 fetch handler 为空操作（纯 BG 补传不拦缓存），check.app.js 走 Cloudflare CDN 默认缓存。
4. 版本：meta hse-build + config/app/check.app 三处 `?v=` + version.json = **2026-10-19.110**（`CF-WPS-106/.109` 类历史注释串不含完整版本前缀，replace_all 不会误伤，保持原样）。
