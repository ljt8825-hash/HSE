# 三违管理考核·「未按时整改」列扣分明细改为自动拉取（交付）

> 日期：2026-09-26  |  类别：②交付报告  |  归属对话：当前会话

## 需求

「未按时整改」列的扣分明细，与「三违信息填报」列一样，**点击数字自动拉取明细**（分项+合计弹窗）。

## 背景

「未按时整改」（列 key=`manual_rectify`）自 2026-09-26 起已由手填列改为**自动计算**：值 = 当月台账 `grid_inspection_records` 中「真三违（`violation_behavior<>'无三违行为'`）且未上传整改照片（`rectified_photo` 缺失/占位）」，每起 1 分、按乡镇（`regionBase(area_team)`）归因。但其**明细弹窗是空的**——`DEDUC_KINDS` 未配置该列，点击数字无法拉取明细（与「三违信息填报」不一致）。

## 实现（纯新增接口+前端接线，不改动既有分数与落库逻辑）

| 环节 | 文件 | 说明 |
|------|------|------|
| 后端明细接口 | `server/routes/hse-violation-assessment.js`（新增 `GET /unrectified-detail?cycleId=&targetId=`） | 按目标所在乡镇拉取当月真三违未整改记录，返回与 `/deductions` 同形的 `{ list: [{date, item, score:1, detail:{summary,unit:1}}] }`；与 `/list` 的 `rectifiedDeduct` **同口径**（同月+真三违+照片缺失/占位+regionBase 乡镇归属），只读不写库 |
| 前端 API | `violation-assessment.ts`（`getUnrectifiedDeductions`） | 新增明细拉取函数 |
| 前端接线 | `index.vue` | `DEDUC_KINDS` 增补 `manual_rectify`（虚拟 key `unrectified_ledger`，非真实扣分 kind）→ 单元格数字可点击；`openAutoDeduct` 对 `manual_rectify` 走独立加载器 `loadUnrectifiedDeduct`；明细行、加载态、合计统一走既有弹窗渲染管线（与「三违信息填报」同一模态框分项+合计样式） |
