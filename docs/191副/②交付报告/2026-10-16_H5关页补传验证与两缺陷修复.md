# H5 关页补传（CF-WPS-105）全链路验证与两缺陷修复（.106）

> 日期：2026-10-16　类别：②交付报告（验证记录）　归属对话：H5 关页补传验证（用户指令「请帮我验证一下关页补传功能」）
> 验证方法：桌面 Chrome + 本地桩后端（`Referer` 区分页面/SW 请求）+ **Node 直跑 sw.js/check.html 原文函数**做无真机端到端验证；**产出 .106 修复两缺陷**（未发布）

## 一、验证方法（可复用口径）

真机 Background Sync 触发链无法在桌面复现，采用组合验证：
1. **桩后端**：Node http 静态服 + 假 API——页面 fetch 同源默认带 `Referer`，SW 发起的 fetch 天然无 `Referer` ⇒ 用该请求头零侵入区分两条路径：页面 submit 恒 503（模拟弱网）、SW submit 恒 200、login/upload 恒 200、`/me` 恒 500（引导 boot 走离线路径，STORE_KEY 可预测）。全程日志落盘。
2. **SW 重放**：从 sw.js 按标记切出 BG 段原文（bgIdbGet/Set、bgFetch、bgDataUrlToFile、bgEnsureAuth、bgSubmit、bgSyncRetry），`new Function` 注入假 IDB（Map 实现）+ 真 HTTP 执行——跑的就是**发给浏览器的同一份代码文本**。
3. **合并回写**：同法从 check.html 切出 bgMergeFromMirror 原文，5 用例直跑。
4. 浏览器侧用种子数据（过期会话+凭据+身份快照+pending 记录）驱动真实页面走镜像/合并/UI。

## 三、验证发现并修复的两个真缺陷（.106）

1. **镜像覆盖 SW 结果（clobber）**：页面每次失败重试的 saveDB 都会重建镜像，把 SW 已写入的 `synced` 覆盖回 `pending`，合并永远拿不到结果（生产影响=冗余重传一次，靠服务端幂等自愈）。修复：bgMirrorQueue 重建前读旧镜像，`synced/failed` 定态结果一直保留到「打开页面合并」消费（[check.html bgMirrorQueue](file:///g:/hse-dashboard/grid-mobile-cloudflare/frontend/check.html)）。
2. **bgSubmit 字段臆造**：SW 侧从响应取 `recordIds[0]`，真实 Worker 返回 `record_id`（与页面 syncRecordOnce 同口径）——SW 补传成功后 serverRecordId 恒为空，详情无法关联台账。修复：`j.record_id || (j.recordIds && j.recordIds[0])`（[sw.js bgSubmit](file:///g:/hse-dashboard/grid-mobile-cloudflare/frontend/sw.js)）。
3. （测试用例 3 顺带发现）**failed 合并误弹成功 toast**：SW 同步「失败原因」回来也弹「✓ 已补传」，误导用户。修复：synced/failed 分开计数，仅真落表弹提示。
