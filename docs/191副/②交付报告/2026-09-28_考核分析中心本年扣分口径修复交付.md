# 考核分析中心「本年扣分」口径修复交付

> 类别：②交付报告 · 日期：2026-09-28 · 归属对话：当前会话

## 一句话结论
`/api/hse/assessment-analysis/overview` 的 `currentYearDemeritPoints` 字段此前误用「近 5 年累计扣分」，已修复为「本年（自然年）扣分」；同时修正本年统计的日期边界（`< yearEnd` → `<= yearEnd`），与同文件 `/goals` 端点口径对齐。仅后端 1 个服务文件 3 处小改，前端无需改动，字段名不变。

## 问题定位
- 文件：`server/services/hseAssessmentAnalysisService.js`（Sprint6.5-A 考核分析中心业务层）
- 现象：考核总览页「本年扣分」展示值偏大——SQL 已计算出 `current_year_points`（本年扣分）却未被使用，返回体 `currentYearDemeritPoints` 直接取 `fiveYearDemeritPoints`（近 5 年累计）。
- 影响面：web-naive（生产）与 web-antd 两版考核总览页均消费该字段，均展示错误值。
- 旁证：`/goals` 端点同样计算了 `current_year_points/count` 但未暴露字段，本次不涉及、不改动。

## 改动内容（3 处，均在 `overview()` 内）
1. SQL 本年统计日期边界：`demerit_date >= $1 AND demerit_date < $2` → `<= $2`（原写法会漏掉 12-31 当天的扣分记录，与 `/goals` 端点 `<= $2` 不一致）。
2. 新增常量：`const currentYearDemeritPoints = parseInt(demeritRow.current_year_points) || 0;`
3. 返回体：`currentYearDemeritPoints: fiveYearDemeritPoints` → `currentYearDemeritPoints`（取本年值）。

## 验证结果（dev 环境，只读）
- `node --check` 语法通过。
- 专项脚本 `server/_verify_current_year_demerit.cjs`（临时验证件，gitignore）：
  - SQL 本年直算：记录=1 扣分=1；API 返回 `currentYearDemeritRecords=1`、`currentYearDemeritPoints=1` → 完全一致
  - `currentYearDemeritPoints(1) <= demeritPoints(近5年累计10)` → 逻辑自洽
  - 修复前该字段会显示 10（5 年累计），修复后显示 1（本年）
- 全量冒烟 `_smoke_hse_assessment_analysis.cjs`：5 端点 200 形状全过 + 不存在路径 404 正常，零写库。
