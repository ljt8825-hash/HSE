## 三、本轮改动（已上线）

1. **登录页自诊断（CF-WPS-111）** —— `frontend/login.html`
   - 新增 `<meta name="hse-build" content="2026-10-21.130">`
   - 页面底部常显：`版本 X · 脚本已加载/未加载 · 首个错误`（红色为异常）
   - 采集 `window.onerror`（含脚本资源加载失败）与 `unhandledrejection`；**只报同源脚本**，第三方统计失败不误导现场用户
   - 脚本全局缺失时提供「清缓存并刷新」按钮（注销 SW → 清 CacheStorage → `/login?r=<ts>`）
   - 登录失败提示带真实状态码：`手机号或密码错误（HTTP 401）` / `（无响应，可能超时或断网）` / `网络异常：<原因>`
   - `pageshow.persisted=true` → 强制重载：手机很少杀进程，从后台切回会恢复 bfcache 里的**旧页面实例**（旧 CSP/旧脚本状态），必须重载
2. **CSP 二次修正** —— `_pages_deploy/_headers`
   - 放行 Cloudflare 边缘自动注入的 Web Analytics：`script-src` 加 `https://static.cloudflareinsights.com`，`connect-src` 加 `https://cloudflareinsights.com`（此前被拦，控制台报错干扰真机诊断）
   - **回滚 `frame-ancestors 'none'` 与 `X-Frame-Options: DENY`**：这两项与故障同批（今日）上线，是唯一能导致「整页白屏/打不开」的头部改动；现场可能从微信/钉钉/门户菜单以嵌入方式打开，禁止嵌入会把嵌入场景直接打成空白页。回滚后恢复上线前行为（保留 CSP 其余项、nosniff、Referrer-Policy）。

## 五、遗留待定性（需一条真机截图）

手机侧仍有三类可能，诊断条可直接区分：

| 诊断条显示 | 含义 | 处置 |
|---|---|---|
| 版本 2026-10-21.130 · 脚本已加载 | 已拿到新版、脚本正常 | 看 err 文案：401=密码错；无响应=手机网络到 Pages 不通；带「网络异常」=请求未发出 |
| 版本号更旧 / 无版本行 | 跑到旧页面（旧 tab、bfcache、桌面快捷方式指向旧地址） | 彻底划掉 H5 进程重开；或点「清缓存并刷新」 |
| 红色「脚本加载失败 / 脚本报错」 | 客户端拦截或语法不兼容 | 截图原文，按语法定向 |
| 整页空白、无任何文字 | 未加载到 HTML（域名/网络/嵌入被禁） | 确认是否为桌面图标（PWA `start_url=/check`）或从微信/钉钉内打开 |

**另需排除的历史风险**：`grid-mobile-cloudflare/docs/微信域名拦截申诉材料.md` 记录微信对**整个 `dpdns.org` 后缀**的拦截（2026-09-23）。若用户是在微信内置浏览器打开 `grid1ns.dpdns.org`，会直接看到微信拦截页，与代码修复无关 —— 需确认打开渠道；微信内可「··· → 在浏览器打开」验证。

## 六、冻结口径

1. 多页多段内联脚本 + 频繁改 HTML 的站点**禁用 CSP 内联哈希白名单**，只能用 `'unsafe-inline'`（存在 hash/nonce 时 `'unsafe-inline'` 被忽略）。
2. **禁止给该 H5 加 `frame-ancestors 'none'` / `X-Frame-Options: DENY`**：现场存在嵌入打开场景，会导致整页白屏。
3. 真机排障必须先看**页面自诊断条（版本 + 脚本状态 + 错误原文）**，不得再用「桌面能开」推定手机正常。
4. bfcache 是手机「修复不生效」的常见放大器：`pageshow.persisted` 必须触发重载。
5. 判断线上是否生效，一律以**响应字节 MD5** 为准，`wrangler` 的「Uploaded 0 files」不代表未变更。

## 七、追加：真机截图定案（CF-WPS-112，2026-10-21 17:5x 截图）

**截图证据**：手机从桌面图标（PWA，`start_url=/check`）进入，停在启动页「网格巡查 / 正在验证登录状态…」，**既无 8 秒兜底「页面没能正常启动」，也无 15 秒 watchdog「网络较慢，启动超时…」**。

**由此反推（两条互斥事实同时成立）**：
1. 无 8 秒兜底 ⇒ `check.app.js` **已执行**到底（末尾 `window.__hseAppReady = true` 使 `fatal()` 直接 return）→ 不是脚本下载失败、不是语法错误、不是 CSP。
2. 无 15 秒 watchdog ⇒ `boot()` **从未被调用**（`armBootWatchdog()` 在 `boot()` 第一行）。

**根因**：`check.html` 用**动态 `document.createElement('script')` 注入** `check.app.js`（async，不阻塞 DOMContentLoaded），而 `boot()` 与全部事件绑定只注册在 `document.addEventListener('DOMContentLoaded', …)` 内。慢网下 337KB 脚本执行时 `DOMContentLoaded` **早已触发**，监听永久错过 → 页面永久停在初始文案。桌面/快网下脚本常在事件前执行，故表现为「时好时坏、只有手机不行」。

**修复（check.app.js）**：
- 事件回调首行加 `if (window.__hseBootDone) return; window.__hseBootDone = true;`（一次性守卫）
- 文件末尾在 `__hseAppReady = true` 之后补 `if (document.readyState !== "loading") document.dispatchEvent(new Event("DOMContentLoaded"));`
  - 已错过则立即补一次；未错过则由原生事件触发；守卫保证只启动一次

**版本与发布**：`hse-build` 与 `check.html` 内 3 处 `?v=` 由 `2026-10-20.122` → `2026-10-21.130`，`version.json` 同步 `.130`；MD5 全量同步校验后部署 **`5941a661`**。

**线上验证**：
- `/check` 117392B MD5 `0EE3B8CB…` = 本地；`/check.app.js` 338670B MD5 `92A746E1…` = 本地且含 `__hseBootDone`
- 浏览器实测 `/check` → **正常启动并跳转 `/login`**（无会话时应有的行为），不再停留在启动页

**冻结口径（新增）**：
6. **异步脚本（动态注入）内禁止只依赖 `DOMContentLoaded` 做启动**——必须 `readyState` 判断或补发事件，否则慢网必卡启动页。
7. 「无 8 秒兜底 + 无 15 秒 watchdog」= 主脚本已执行但启动入口未调用的**确定性指纹**，可直接排除网络/CSP/语法三类原因。
