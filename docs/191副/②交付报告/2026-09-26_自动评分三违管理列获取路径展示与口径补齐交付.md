# 目标职责→自动评分「三违管理」列：获取路径展示 + 口径补齐交付

> 类别：②交付报告　日期：2026-09-26　归属对话：当前会话

## 背景
「自动评分」页（目标职责 → 自动评分，`/objectives/assessment-scoring`）的「三违管理」维度列所需的分数，按 2026-09-26 冻结口径，应从「现场管理 → 三违管理 → 三违管理考核」同周期、同岗位 Tab 的「考核分数」列获取。本次核对发现该对接已存在但有两处不完整，随需求修正并补上获取路径展示。

## 现状核对
`安全看板vben/apps/web-naive/src/views/hse/assessment-monthly/scoring.vue` 已实现：
- `loadViolationScores()` 拉取 `getViolationAssessmentList` + `getViolationAssessmentConfig`，按当前岗位 Tab 把每个考核对象在三违管理考核页当前展示列（网格长巡查考核 / 三违巡查 / 三违信息填报 + 各人工列）求和为 `violationScoreMap`（按 employeeId 一一对应）。
- `dimValue()` 对「三违管理」（兼容「现场管理-三违管理」前缀）列改取上述映射，其余维度列仍走 `categoryDeductions`。
- 该列仅覆盖展示值，不影响本页「总分」（score_total 由后端评分引擎得出）。

## 改动内容（纯前端 `assessment-monthly/scoring.vue`）
1. **口径补齐·公司查处扣分**：`loadViolationScores()` 求和处补充 `s += row.companyDeduct?.score ?? 0`。此前只统计列池展示列（自动列+人工列），漏计 2026-09-25 新增的三违管理考核固定列「公司查处扣分」，会导致本列与三违管理考核「考核分数」不一致。现已与 `views/hse/violation-assessment/index.vue` 的 `totalScore` 完全同口径。
2. **获取路径展示**：
   - `dimHelpText(col)` 对「三违管理」列返回专属文案，注明获取路径：现场管理 → 三违管理 → 三违管理考核（同周期、同岗位 Tab）的「考核分数」列 = 该页当前展示列之和（网格长巡查考核 + 三违巡查 + 三违信息填报 + 各人工列 + 公司查处扣分），并强调仅覆盖本列展示值、不影响本页「总分」；其余维度列保留原有通用文案。
   - `#dimHeader` 模板工具提示 `NTooltip` 增加 `style="max-width: 460px"`，保证长文案多行换行显示（不再单行截断）。
   - 内置字体图标 `lucide:circle-help` 即需求中 `document.querySelector(...#dim-col-title-line > svg)` 指向的表头悬浮问号。
