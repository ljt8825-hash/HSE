# 隐患 UI「变量高度塌陷」系列修复与版本号自显（2026-10-19，CF-WPS-108b~f，版本 .112→.117）

> 类别：②交付报告。承接用户反馈「我登记的/全部隐患及验收按钮修改仍未完成」，经五轮迭代（.112~.117）定位并修复，用户真机确认正常。

## 一、排查历程（工具化取证范式）

1. **.112 误判轮**：用户视频逐帧分析判定「登记新隐患」按钮丢色（GPU 合成层假设）→ 渐变双通道 + 卡片真舒展（12px 间距 + padding 20/18）→ **用户复测无效**。
2. **.113 版本自显轮**：首页底部常显「版本 xxx」（id=build-tag 读 hse-build meta）——终结「手机拿到哪版靠猜」；用户截图证实已拿 .113 但按钮仍丢色。
3. **.114 探针轮**：`translateZ(0)` 修复 + **右上角诊断探针**（每 900ms 显示按钮 computed style）→ 用户截图读数 `op=1 bg=img dis=false y=100 h=0` —— **破案：不是丢色，是高度塌成 0**，白字溢出浮灰底=「半透明残影」假象。
4. **.115 兜底轮**：`min-height:65px;padding:14px 18px` 字面量兜底 7 个主按钮（不依赖 CSS 变量）→ 用户截图 `h=65 mh=65px var=65px` 修复生效，且 **var=65px 证明变量解析正常、是 height 计算环节失效**。
5. **.116 全家轮**：用户再报「我登记的/全部隐患分段加载后变矮」——同源问题（.seg 高度同样 `height:var(--h-btn-sm)` 无兜底）→ 全家族字面量 min-height 兜底。
6. **.117 正式轮**：撤诊断探针，保留全部兜底。

## 二、根因冻结（CF-WPS-108f）

**该用户的安卓 WebView 在列表大重排（innerHTML 渲染卡片）后，对 `height:var(--xxx)` 的计算失效**——初始布局正常、大重排后塌陷；`getComputedStyle().getPropertyValue('--x')` 解析值正常（非变量定义问题），塌陷点在 height 使用环节；叠加代码中 `min-height:0` + 上下 padding:0 无兜底 → 塌至 0。

**防御口径（冻结）**：H5 关键控件（按钮/分段/输入框）高度若用 `height:var()`，**必须同时给字面量 min-height 兜底**；禁止依赖单一变量高度。已覆盖：.seg 分段 52px、.back-link 52px、.input/.pwd-input/.hz-input/.hz-deadline 65px、#btn-hz-geo 65px、7 个 btn-primary.btn-row 主按钮 65px+padding 14px 18px。

## 四、发布波折（冻结）

- **Cloudflare OAuth refresh_token 被服务端吊销**：dash.cloudflare.com 网络抖动（直连超时/本机 7890 代理 403）期间多次 refresh 失败所致（/oauth2/token 400）。恢复 = `npx wrangler login --browser=false` 打印授权 URL → 用户浏览器点 Allow（回调 localhost:8976）→ 凭证重建。
- **后续会话中 dash 再次抖动**：wrangler 报「auth token expired could not be refreshed」且日志见 ConnectTimeout → **凭证未损坏，等待 20 秒重试即通**（与吊销的区别：400=吊销需重授权；timeout=抖动可重试）。
