# H5 巡查页屏幕自适应与大字体兼容 交付报告

> 日期：2026-10-16　类别：②交付报告　归属对话：手机端 H5 巡查界面屏幕适配
> 改动文件：`grid-mobile-cloudflare/frontend/check.html`（唯一改动文件，纯前端 CSS/文案，零后端、零生产数据、零 WPS）

## 一、背景与根因

用户真机截图（安卓手机、系统字体调大）暴露两类问题：

1. **底部导航栏页签文字粘成一串**：「首页派发记录整改任务巡查台账我的」横向溢出互相粘连，导航栏被挤爆。
2. **整页文字偏大**：同一页面在不同手机上字号观感不一。

根因诊断（两项叠加）：

- **屏幕宽度差异**：全站字号是固定 px 令牌（`--fs-*`），不随视口宽度缩放；手机 CSS 视口宽度 320~430px 不等，同一套 px 在窄屏显得大、宽屏显得小。
- **系统大字体缩放**：安卓「设置→字体大小」调大后，Chrome 会把网页文字整体放大约 1.3~1.5 倍，但按钮/卡片/导航栏的宽高与内边距仍是固定 px 不跟着长 → 文字溢出自身槽位（`.tab-item` 原为 `min-width:auto`，内容超宽时各标签横向溢出、互相粘连）。

既有代码已在 check.html 注释中预见「系统字体缩放会把 11px 渲染得更大」（CF-WPS-45 注释），当时用 `white-space:nowrap` 防换行兜底，但未防横向溢出粘连。

## 二、改动清单（每项独立段落）

### 1. 字号令牌 clamp() 流式化（方案 A）

`check.html` `:root` 内 8 个字号令牌由固定 px 改为 `clamp(下限, vw, 上限)`：

| 令牌 | 原值 | 新值 |
|------|------|------|
| `--fs-hero` | 30px | `clamp(24px, 7.7vw, 30px)` |
| `--fs-h1` | 26px | `clamp(21px, 6.7vw, 26px)` |
| `--fs-h2` | 24px | `clamp(19px, 6.2vw, 24px)` |
| `--fs-btn` | 22px | `clamp(18px, 5.65vw, 22px)` |
| `--fs-title` | 20px | `clamp(16px, 5.15vw, 20px)` |
| `--fs-body` | 15px | `clamp(12px, 3.85vw, 15px)` |
| `--fs-sub` | 13px | `clamp(11px, 3.35vw, 13px)` |
| `--fs-cap` | 11px | `clamp(9px, 2.85vw, 11px)` |

设计基准 390px 视口（vw 恰等于原 px），320px 触底不再缩小，≥390px 封顶保持原设计值。全站组件本就只引用令牌，**一处定义改动全局生效，组件零改动**。已确认无任何 JS 读取这些 CSS 变量做像素运算。

### 2. 底部页签防挤爆（方案 B1）

- `.tab-item` 增加 `flex:1 1 0; min-width:0`：5 个页签严格等分导航栏宽度，标签再宽也不会把相邻页签挤走（根治截图粘连事故）。
- 页签标签统一缩为 2 字：`派发记录→派发`、`整改任务→整改`、`巡查台账→台账`（`首页/我的` 本就 2 字）。公司管理角色的整改页签 JS 分支 `任务反馈→反馈`（check.html 原 L2089）。**页内导航栏标题（nav-title「巡查台账/派发记录」等）保持全称不变，只动页签**。
- `.tab-item` **不加** `overflow:hidden`：页签角标 `right:-6px` 溢出可见，加 hidden 会裁掉角标。
- 同步更新 CF-WPS-45 注释块，记录新纪律与真机截图事故背景。

### 3. 固定高度容器弹性化（方案 B2）

三处固定 `height` 改 `min-height`（系统大字体放大文字时容器可撑高不裁切；正常字体下内容小于令牌值，由 min-height 定高，**外观与原固定高完全一致**）：

- `.stat-card`：`height:var(--h-entry)` → `min-height:var(--h-entry)`（78px，首页统计卡大数字放大时会溢出 78px 固定高，此项为必要修复）
- `.entry-card`：同上（78px，首页入口卡）
- `.big-cta`：`height:var(--h-cta)` → `min-height:var(--h-cta)`（190px，主操作大按钮；`.big-cta-row` 的 `min-height:68px` 后置覆盖行为不变）

其余固定高（按钮 64px、宫格 88px、导航栏 64/56px、搜索框 64px 等）经核算在 1.5 倍字体放大下内容仍放得下，**按最小改动原则不动**。

### 4. 构建版本号

`hse-build` meta 与 `config.js`/`app.js` 的 `?v=` 后缀统一 bump 为 **2026-10-16.103**（三处一致；此前 meta .102 / script .102）。`sw.js` 为纯透传无缓存版本号，不需改动。

## 三、验证记录

自测方式：本地临时静态服务（127.0.0.1:5899，已停止并清理）+ 测试壳页（fetch check.html 源码剥除全部 `<script>` 后 srcdoc 注入三个 320/360/390px iframe，手工激活「巡查台账」视图、注入与真机截图同构的记录卡、显示底部导航；壳页已删除）。

| 验证项 | 结果 |
|--------|------|
| 正常模式：字号随宽度递增（320<360<390），导航标题/卡片文字/hero 同步缩放 | PASS |
| 正常模式：页签独立分离、无粘连无溢出，卡片布局无重叠 | PASS |
| 大字体 1.5x 模拟（.tab-item 17px / nav-title 30px / 卡片文字 23px 等）：320/360/390px 页签均独立分离、未撑破导航栏 | PASS（本人核验截图确认） |
| 大字体 1.5x：记录卡文字正常换行撑高、无裁切 | PASS |

局限说明：浏览器无法完全复现安卓系统字体缩放机制，1.5x 为近似模拟；**最终效果需真机复验**（发布后强刷或清缓存重载即可看到，页面自带热更新检测会提示覆盖旧版）。
