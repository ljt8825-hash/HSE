## 交付摘要

- **Provider 统一架构**：`aiService.js` 原地演进为「Provider 注册表 + 统一契约」（HseAiProvider：chat/chatStream/chatStructured/vision/embed/listModels/healthCheck/getMetadata/capabilities），新增 `openaiCompatibleProvider`（DeepSeek/Qwen/vLLM/OpenAI），现有 7 个消费方导出面零破坏；**明确禁止平行第二套 Provider 系统**（演进路径 M1→M2→M3 已定稿）。
- **七大统一组件设计**：Provider Registry、AI Gateway、Prompt Registry（版本化，现有 9 模板迁移注册 + vision_scene_desc/rag_qa 预留）、Evidence Chain（`ai_evidence_items`，input/output 双向证据）、AI Task（`ai_analysis_tasks` 统一任务模型）、Vision 接入规范（本地 Qwen3-VL-4B 起步，双轨制）、RAG 接口规范（chunker/embedder/pgvector/retriever）。
- **双重挂载治理**：Step1 v2 端点独立前缀 `/api/hse/ai/v2` 共存 → Step2 收编；`ai.js` 4 端点处置建议（`/qa` 废弃、risk-predict/anomaly-detect/classify 迁移分析域或标注 rule-based）留用户确认。
- **API 接口基线**：16 个 v2 端点（generate/stream/structured/vision/embed/models/health/tasks*/prompts*/rag*），鉴权沿用 AI_WRITER/行级过滤模式，SSE 格式沿用现有 chatStream 基线。
- **数据模型**：新增 6 张 `ai_*` 表（prompt_registry/analysis_tasks/evidence_items/provider_configs/rag_documents/rag_chunks），**不修改任何现有表**，密钥不入库（api_key_ref 指向 .env 变量名）。
- **双轨制铁律**：Gateway 层字段白名单——AI 只写 `ai_*` 建议轨，人工轨 `compliance_status` 等只由 `/tasks/:id/confirm` 人工写入。
- **前端基线**：Naive UI 2.44.1 冻结；SSE 流式消费（ReadableStream）、Markdown 渲染（md-editor-v3/markdown-it 待授权）、NImage 预览、模型健康页、任务/证据链页分批配套。

## 关键冻结基线（供 AI-03 起沿用）

1. **Provider 契约**：`HseAiProvider` 接口 + `ProviderCapability` 能力声明 + `ChatRequest/ChatResult/HealthStatus/ModelMetadata` 统一模型（设计文档 §4.2-4.4）。
2. **能力路由**：`AI_PROVIDER` 静态路由保持 + `select({capability})` 能力路由 + 降级链默认关闭（启用需用户确认）。
3. **错误码**：`TIMEOUT/AUTH_FAILED/RATE_LIMITED/NOT_SUPPORTED/BAD_RESPONSE/PROVIDER_DOWN/EMPTY_RESPONSE`。
4. **超时/重试**：全局 `AI_TIMEOUT_MS=60000` + 请求级覆盖；重试 `AI_MAX_RETRIES=2` 指数退避；**流式不自动重试**。
5. **双轨制范本**：`standard_evaluation_items`（ai_verdict/ai_evidence/ai_suggestion/ai_confidence + compliance_status/manual_remark/checked_by/checked_at），统一层推广到所有域。
6. **演进铁律**：aiService.js 导出面 11 个方法 + TEMPLATES 零破坏；`aiService.unit.test.js` 保持绿色为回归保障。
7. **边界**：统一层不直接 SQL Workbuddy 在迁表（grid_*/三违），业务取数走各域既有只读查询。
