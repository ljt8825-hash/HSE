## 交付/变更概要

**问题**：手机端 H5「现在无法登录」——登录页能正常显示、输入框和「登 录」按钮都在，但点击后按钮只是短暂 loading 然后恢复，**不发任何请求、也不出任何提示**。

**根因（实测）**：2026-10-21 16:2x 的一次 Pages 部署（`7b6022f0`）在 `_headers` 新增了 CSP，`script-src` 用 **10 个 sha256 内联脚本白名单**。上线后登录页的内联 `<script>`（定义 `doLogin`、绑定按钮点击）**被判为不可执行**，整段没有运行：

- `typeof window.doLogin` → **undefined**（登录函数从未创建）
- `typeof window.mobileApi` → function（外部 app.js 正常执行）
- 内联脚本文本本身完整：`len=1988`、`{` 16 / `}` 16 平衡、首尾字符正常
- 按钮绑定未发生 → 点击静默无响应
- 无可见报错（CSP 拦截属于「静默失效」，页面看起来完全正常）

**同一批部署的第二个坑**：`app.js` / `check.app.js` 被换成了压缩产物（3894B / 182765B），排查初期一度被误判为「app.js 被截断导致 mobileApi 缺失」，后经浏览器运行时符号验证（mobileApi 正常存在）排除。

**定位方法**：

1. 后端实测正常：`POST /api/mobile/auth/login`（错误手机号）→ **401 +「手机号或密码错误」**，说明 Worker/飞书链路均健康。
2. 浏览器运行时取证：页面渲染正常、`doLogin` undefined、点击不发请求 → 锁定「内联脚本未执行」。
3. 逐字节核对 CSP 哈希：以原始字节计算 6 个页面共 10 段内联脚本的 sha256，**10/10 与本机文件一致**——说明不是「哈希写错」，而是该白名单机制在真实浏览器环境下仍失效（且失效时无提示）。
4. 对比部署产物：线上 `app.js` 3894B ≠ 本地 9161B；线上 `check.app.js` 182765B ≠ 本地 337781B。

**修复**：

1. `_headers` 的 `script-src` 改为 `'self' 'unsafe-inline'`，**删除全部 10 个 sha256**。
   > 关键点：CSP 规范中只要存在 hash 或 nonce，`'unsafe-inline'` 就会被忽略——两者不能并存，不能只追加。
2. `_pages_deploy` 与 `frontend` 全量同步：`app.js` 9161B、`check.app.js` 337781B、`check.html` 117392B、`login.html` 5215B、`config.js` 745B、`version.json` 26B。
3. 重新部署 → **Deployment `0537098b`**（`https://0537098b.grid-mobile-cloudflare.pages.dev`）。

**验证（线上 + 浏览器实测）**：

- 线上资产：`login`=200/5215、`app.js`=200/9161、`check.app.js`=200/337781、`check`=200/117392
- 浏览器运行时：`doLogin` = **function**、`mobileApi` = function、`btn` 存在
- 点击登录（故意错误密码）：**发出 `POST /api/mobile/auth/login` → 401**，页面正常显示 **「手机号或密码错误」**
- 结论：登录链路已恢复

## 冻结口径（本次教训）

1. **内联脚本哈希白名单禁用**：多页、多段内联、HTML 频繁变更的站点，不要用 `script-src 'self' sha256-...` 白名单——失效时页面完全正常、点按钮无反应、无可见报错，排查成本极高。需要 CSP 就用 `'unsafe-inline'`（保留同源限制）或服务端 nonce。
2. **CSP 失效指纹**：页面渲染正常 + 内联脚本 `textContent` 完整 + 全局符号缺失（`typeof window.xxx === 'undefined'`）+ 点击静默 → 优先怀疑 CSP，而不是 JS 语法。
3. **线上表现以「运行时符号」为准**：不要只看 HTML 体积/哈希/文本截断判断；用 `typeof window.doLogin`、`document.scripts[i].textContent.length` 取证。
4. **`_pages_deploy` 必须与 `frontend` 全量同步**：本次两个核心 JS 曾被替换为压缩产物（3894B/182765B），既干扰排查也造成线上与本地不一致；同步后统一校验 MD5。
