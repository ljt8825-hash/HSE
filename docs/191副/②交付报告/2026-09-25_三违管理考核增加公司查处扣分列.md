# 三违管理考核：考核分数左侧新增「公司查处扣分」列（交付）

> 类别：②交付报告　日期：2026-09-25　归属对话：当前会话

## 需求
现场管理→三违管理→三违管理考核：在「考核分数」列左侧新增「公司查处扣分」列，与现场管理→三违管理→三违分析的公司查处扣分逻辑、样式一致。用户确认：两个 Tab（乡镇作业中心经理 / 管理员）都显示。

## 变更明细

### 1. 新增共享服务 `server/services/companyViolationDeduct.js`
把「公司查处扣分」口径从三违分析内联逻辑（2026-09-21 冻结）抽离为共享服务，供两页共用，保证数值与乡镇归属完全一致：
- 只统计公司管理网格长（总+一级：黄殿兴/刘金涛/张康/刘菲/韩晓亮/黄元同）查处的真三违记录。
- 每起扣分 = 违章行为含「头盔/安全帽」→5 分，其他三违→1 分（`HELMET_RE` / 排除「无三违行为/--/-/无」）。
- 乡镇归因 = 违章人姓名 → 花名册 `roster_department` 含某乡镇名，最长匹配（冻结笔误归并 NAME_ALIAS → 花名册精确命中 → 人工审核映射表三级兜底）。
- 导出 `buildCompanyDeduct({ months?, candidateTowns })` → `{ map: Map<'${month}|${town}',{score,helmetCount,otherCount,details}>, unresolved }`。

### 2. 三违分析路由 `server/routes/hse-sanwei-analysis.js`
`/list` 中公司查处扣分内联块改为调用共享服务（`buildCompanyDeduct({ candidateTowns })`，month 不过滤，保持原行为），返回结构（`companyDeductMap` / `companyUnresolved`）不变。已清理 INLINE 期本地常量（`COMPANY_GRID_LEADERS`/`HELMET_RE`/`NAME_ALIAS`），仅保留仍在 DELETE resolution 路由使用的 `cleanVName`。

### 3. 三违管理考核后端 `server/routes/hse-violation-assessment.js`
`/list` 增加 companyDeduct 计算（复刻分析页同源口径）：
- 由 cycleId 解析考核月份 `YYYY-MM`。
- 归属乡镇候选集合 = `hse_sanwei_score_monthly` 该月 distinct `town`（与分析页同源，**避免引入分析页不统计的乡镇，如「环卫」**，否则环卫下属违章会多计 5/1 分，破坏一致性）。
- `buildCompanyDeduct({ months:[cycleMonth], candidateTowns })`。
- 每行：`regionBase(township)`（截「作业中心/片区/中心」后缀）→ 查 `month|短镇名` → 输出 `companyDeduct{score,helmetCount,otherCount,details}`；环卫等无打分乡镇计 0。

### 4. 前端
- `src/api/hse/violation-assessment.ts`：`ListRow` 增加 `companyDeduct` 类型。
- `src/views/hse/violation-assessment/index.vue`：
  - `allColumns` 在「考核分数」前新增固定列「公司查处扣分」（`slots.default='companyDeduct'`，带 titleHelp 口径说明）。
  - 新增 `#companyDeduct` 插槽，完全复刻三违分析：分值>0 → 可点击 `NTag warning` + NPopover 弹出逐条明细（日期/违章人/行为/负分值 + 头盔条第5分合计行）；=0 → `NTag success`。列为固定列（不参与「增加列/删除列」列池），且**不纳入「考核分数」求和**（与分析页的 score 不含公司查处扣分一致）。
