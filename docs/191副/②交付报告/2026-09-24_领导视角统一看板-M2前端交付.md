### 6.2 联调发现的缺陷与根因

**缺陷**：角色层个人「巡查」计数与明细层不一致（张华平 角色层 6 vs 明细层 37）；角色层「三违」按 ID 计数仅命中极少数。

**根因（只读 SQL 摸底，2026 年全年）**：

| 模块 | 总记录 | 有员工 ID | 无 ID（仅姓名文本） |
|------|--------|-----------|---------------------|
| 三违 violation_records | 824 | 83（10%） | 741（90%） |
| 事故 accidents | 24 | 3（12.5%） | 21（87.5%） |
| 巡查 grid_inspection_records | 2061 | 337（16%） | 1724（84%） |

H5/WPS 单向同步的记录大多只落「姓名/片区文本」，`*_id` 多为空（H5 口径：巡查人员手机号→姓名入检查人姓名，ID 不落库）。角色层与明细层原实现仅按员工 ID 计数 → 严重低估。

### 6.3 修复内容（`server/services/leaderDashboardService.js`）

1. **新增 `cleanPersonName`**：去 `（ ）( )` 括号备注 + trim，对齐三违按花名册口径（`_aug_generate.py clean_viol`）；笔误归并表按月维护属三违分析模块，看板不复刻
2. **角色层 `rolesByTown`**：三违/巡查计数先按 `violator_id` / `inspector_employee_id`，未命中再按清洗后姓名匹配本镇在岗花名册；**重名员工（nameCnt>1）不参与姓名兜底**，避免错配（长官镇实测重名：曹凤森/刘秀芬/张会祥）
3. **明细层 `employeeDetail`**：三违改为 `violator_id = $n OR 清洗后 violator_name = 本人姓名`；巡查改为 `inspector_employee_id = $n OR 清洗后 personnel_name = 本人姓名`
4. **事故**：`accidents` 表无姓名字段（仅 personnel_id）→ 保持 ID 匹配，乡镇层仍走 `township` 文本归因不受影响

### 6.5 已文档化的限制（非本轮范围）

- **事故人员层**：87.5% 无 ID 事故无姓名列可兜底，仅统计 ID 关联记录；乡镇卡仍按 township 文本正常显示
- **三违姓名兜底收益有限**：90% 无 ID 记录中绝大多数为 `--`/`男`/`女` 等脏值（实测 643 条 `--`、42 条 `女`、32 条 `男`），精确+去括号清洗仅能恢复少量（长官镇 +2）；笔误归并（李兰凤→李兰风 等）按月维护不复刻
- **乡镇卡 vs 角色层合计口径差**（长官镇：三违 74 vs 24、巡查 179 vs 216）：乡镇卡按台账文本（area_team/township 前缀）归因，角色层按花名册人员归因，两者口径不同属既有实践（同三违分析「台账 vs 按花名册」差异），看板两层分别如实展示
