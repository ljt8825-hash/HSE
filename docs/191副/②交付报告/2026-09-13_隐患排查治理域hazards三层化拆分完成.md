## 关键技术决策与本单特殊处理
1. **全 200 响应契约（code 语义 -1/-2/-3）**：逐条核对原文件**无任何 `res.status()` 调用**，恒 HTTP 200，区别仅在 body `code` —— `sendNotFound`→`error(-2)`、通用失败/`sendValidationError`→`error(-1)`、`review` 参数校验→`error(-3)`。service 错误描述符统一不带 httpStatus；controller `respond()` 还原 `res.json(error(code,msg))`，200 输出，code 语义完整保留。
2. **CSV 流式导出下沉 controller**：`/export` 原 `sendHazardCsvExport`（写 res setHeader+send）改由 controller 处理 `__t:'csv'` 描述符（`text/csv` + `Content-Disposition` + `res.send`），service 只产出 `{__t:'csv', csv}`（BOM + 12 列表头）。实测新旧 CSV 长度一致（12321 字节）。
3. **双执行包裹 run/runNext**：原 catch 为 `res.json(error(-1,...))` 的端点用 `run()`；catch 为 `next(err)` 的 6 端点（related-risk、export、attachments×3、versions）用 `runNext()` 委托 `next(err)`，与原运行行为一致。
4. **权限中间件留绑定层**：`requirePermission('hse:hazard:create|update|delete')` 全部留在 main.js 绑定；未登录即返回 401，冒烟用 401 验证绑定正确且不触库。
5. **内存降级 + 幂等 DDL 保留**：`ensureTables`（attachments/versions/联动/人员/字段/索引）与 `initMemoryData` 在 DB 在线时于读端点惰性执行，调用时机与原文一致；`calcExpiryStatus`、`STATUS_MAP`、`getOrgTownNames`/`extractLocationFromDescription`、`formatRow`、`notifyHazardExpiry`、`syncRiskOnHazardResolve` 私有函数 + `config/hseRules` + `commonResponse` + `config/db` + `routes/audit`(auditLog) + `services/hseEventSyncService` + `services/notificationService` 依赖全部迁入 service。
6. **路径修正**：原 `routes/` 相对路径迁入 `services/` 后统一改为 `../`（`./audit`→`config` 原样，`../config/db` 保持 `../`），`controllers/` 用 `../`；经 `node -e require(...)` 与冒烟双重验证无 MODULE_NOT_FOUND。
