# Ollama 开机自启改造（服务方案不可用 → 计划任务方案）

- **日期**：2026-09-25
- **类别**：②交付报告 / ③决策结论
- **归属对话**：当前会话（服务器启动排查）

## 背景
- `start-hse-ai.bat` 一键启动在第 3 步 `Ollama 检查` 失败（127.0.0.1:11434 不可达），因 Ollama 非服务、无开机自启，需每次手动拉起。
- 用户选择「注册为开机自启」。

## 决策结论（冻结）
- **本机便携版 `ollama.exe serve`（0.33.1，G:\ollama\ollama.exe）不能作为 Windows 服务**直接用 `sc create` 注册启动：服务进程 30 秒 SCM 握手超时，触发系统事件 7000/7009（`等待 Ollama 服务的连接超时`）。官方能注册服务的是 GUI 安装器专用包装，便携版无此能力。
- 改用**任务计划程序登录触发自启**（当前用户交互、无需管理员），比服务更贴合便携版。
- Ollama 固定 11434 的端口契约不变。

## 执行记录
1. 清理游离用户环境变量 `OLLAMA_PORT=11438`（历史残留，会令裸 `ollama serve` 监听 11438 破坏 11434 契约；已删除根治）。
2. 尝试注册 `Ollama` Windows 服务（`sc create "Ollama" binPath= "G:\ollama\ollama.exe serve" start= auto`）；启动超时失败 → **已删除该服务**（不残留开机报错/抢端口）。
3. 注册计划任务 **`HSE-Ollama-AutoStart`**（RunAs=honey，`At Logon` 登录触发，隐藏窗口）：
   - 动作：`powershell.exe -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File "G:\hse-dashboard\scripts\start-ollama.ps1"`
   - `start-ollama.ps1` 自身幂等：11434 已可达则 Already running 复用退出，不会重复拉起；模型库存 `D:\ollama`（用户环境变量 OLLAMA_MODELS）。
   - 实测触发 `LastTaskResult=0`，Ollama 11434 5 模型正常。

## 效果
- 开机登录后自动拉起 Ollama，随后用户仍按 `start-hse-ai.bat` 启动后端/前端即可（其第 3 步现在可过）。
- 停止开发栈不变：`scripts\stop-hse-ai.ps1`（不影响 5876 生产 / Ollama / PostgreSQL）。

## 注意事项
- `HSE-Ollama-AutoStart` 为登录触发；若需系统级开机即启（不依赖登录）需管理员方案，当前非管理员环境未采用。
- 计划任务管理仅对当前用户 honey 生效；换账户登录不会触发。
