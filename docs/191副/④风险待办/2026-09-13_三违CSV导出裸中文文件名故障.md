# 三违 CSV 导出裸中文文件名故障（既有，非拆分引入）

> 类别：④风险待办 · 日期：2026-09-13 · 归属对话：当前会话

## 现象
`GET /api/violations/export/csv` 恒返回 `200 + {"code":-1,"success":false,"message":"操作失败，请稍后重试"}`，且 node 打印 `Invalid character in header content ["Content-Disposition"]`。**三违 CSV 文件从未能正常导出。**

## 根因
原始 `routes/violations.js` 与拆分后 `services/violationService.js` 均执行：
```js
res.setHeader('Content-Disposition', 'attachment; filename=三违记录.csv');
```
头值含裸中文文件名 `三违记录`（大于 latin1 0xff 的字节），Node `ServerResponse.setHeader` 抛 `ERR_INVALID_CHAR`，被 try/catch 收编为固定 `error(-1)`；又因 `res.json` 不覆盖已设的 `text/csv` content-type，故响应头仍为 text/csv 而 body 是错误 JSON。

## 性质确认
- **既有故障**：`git show HEAD:server/routes/violations.js` 同样序列，与拆分无关。hazards (`hazards_YYYY-MM-DD.csv`)、risk-control 用 ASCII 文件名，导出正常；三违是唯一裸中文文件名域。
- **未越权修复**：遵循"拆分旧新行为一致"约束，逐字节复现原契约，不作行为变更。

## 建议修复方向（待用户决策，不含本拆分单）
1. **首选 RFC 5987**：`Content-Disposition: attachment; filename="violations.csv"; filename*=UTF-8''<url-encoded>`，主流浏览器正确解码中文名。
2. 或简化 ASCII 兜底文件名（放弃中文名）。
修复属**独立生产操作**，需单次授权 + 留痕 + 回归。
