# 重大事故等级口径不匹配风险

> 日期：2026-09-28
> 类别：④风险待办
> 来源：下钻子指标级过滤交付（P3.1）真实库核验中发现

## 一、问题

领导视角看板汇总层 `accidents.major` / `weightedIndex` 判定使用国标事故等级词：

```javascript
const ACCIDENT_WEIGHT = { '轻微': 1, '一般': 3, '较大': 6, '重大': 10, '特别重大': 15 };
// major 判定：r.level === '重大' || r.level === '特别重大'
```

但 `accidents` 表真实等级枚举为 **一级 / 三级 / 四级 / 一般**（2026 实测：四级 35、三级 13、一级 5、一般 2），**不存在「重大/特别重大」值**。

## 二、影响

- 「重大事故」趋势行**恒 0**，下钻恒空——按现行口径**永远统计不到一级事故**（若一级=最严重）。
- `weightedIndex`（事故加权指数）的加权对象**错配**：一级事故按 `ACCIDENT_WEIGHT['一级'] || 1 = 1` 计，与四级同级。
- 影响面：领导视角看板（本批次 + 既有）+ 任何消费 `accidents.level` 的模块（BI / 考核分析等，待查）。

## 三、当前行为（非本批次缺陷）

- 子指标过滤谓词与汇总层口径**严格一致**，弹窗数字 = 趋势表数字 = 汇总数字，属正确对齐。
- 本批次交付不改变任何既有数字。

## 四、用户确认（2026-09-28）

用户已确认：事故等级枚举实为「一级/二级/三级/四级」（含一般），**无「重大/特别重大」**；汇总层口径与枚举不匹配为**已知问题，后期增加**（对齐）。

- 当前行为不变：趋势表「重大事故」行恒 0、不可点下钻，如实呈现；弹窗/趋势/汇总数字严格一致。
- 后期对齐属独立批次：涉及 `ACCIDENT_WEIGHT`、`major` 判定、`weightedIndex` 加权对象、及任何消费 `accidents.level` 的模块（BI/考核分析等），需另行决策授权。
- 对齐完成后 `DIM_RECORD_SPEC.subs.major` 过滤实现无需改动即可按新枚举生效。
