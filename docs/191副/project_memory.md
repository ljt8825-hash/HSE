## 经验教训
- koa-connect wrapper caused subtle ctx.state data loss; native Koa rewrite is required instead of wrapping Express middleware
- Backend modifications may not take effect if old processes are not completely terminated before restarting
- 身份证打码功能使用纯数字正则 `/({6}){8}({4})/` 导致含X的身份证号无法匹配，造成明码显示；需使用通用正则 `^(.{6}).*(.{4})$` 兼容18位含X与15位老证
- Custom NInput slot (`trainingDate-edit`) + formatter for inline editing in vxe-table caused unreliable value write-back to `row.trainingDate` on blur, resulting in saving old values; native input editor is required instead
- AI-01 报告中声称存在的 `ai_generation_records` 表经实际数据库检查不存在，需以实际数据库状态为准
- Ollama 路由缺陷：aiService.chat/chatStream 原按全局 config.provider 选端点，导致显式 provider='ollama' 调用打到远程 Grok 地址；修复为尊重 options.provider，Provider 实现显式传 provider: this.name
- CPU 大模型超时口径：qwen2.5:7b 冷启动/生成约 60~125s，worker AI_TIMEOUT_MS=60000 偏紧；需进程级覆盖验证，配置默认值待治理
- WPS 同步仅存储 short-lived object links (via wpsDbsheetAdapter.normalizeAttachments) instead of downloading and storing image bytes, causing HTTP 404 errors when links expire; image display failures occur for 337 new records from September 2026 onwards
- H5 违章人档案拆列映射（2026-09-18 冻结）：主台账「H5员工日常不安全行为台账」tbl5QiCv5Qbal044 违章人信息按列落库——姓名→违章人员姓名、性别→性别、年龄→年龄、职位→车辆类型|保洁员（取自花名册 name/sex/age/job）。前端 toPatrolBody 下发 violation_sex/violation_age/violation_job，后端 validatePatrolBody 读取（上限 PATROL_ATTR_MAX=50）+record 三列映射。禁止再把「姓名,职位,班组」拼进 违章人员姓名 或 描述 列；描述 列括号内仅保留「姓名·班组」（班组无独立列）。三目标列原已在 FEISHU_FIELD_WHITELIST。专属文件 docs/191副/②交付报告/2026-09-18_违章人年龄性别职位落库映射修复.md

## WPS/Office COM 嵌入视频教训（2026-10-11 冻结）
- 本机 PowerPoint 为 12.0（Office 2007）**不支持 mp4 插入**（AddMediaObject2 恒 Unexpected HRESULT）；WPS KWPP（12.0）支持 mp4，嵌视频一律走 `New-Object -ComObject KWPP.Application`。
- WPS `Shapes.AddMediaObject2` 必须 **带窗口打开**（`Presentations.Open($path, 0, 0, -1)` WithWindow=-1），无窗口打开（第4参0）必然 HRESULT 失败；且 COM 失败后 Quit 会带隐藏弹窗卡死并留僵尸 wpp 进程——僵尸实例使后续 `New-Object -ComObject` 复用旧实例读到内存未保存副本（RPC_E_CALL_REJECTED / 占位形状丢失假象），须先 `Stop-Process wpp` 再重试。
- 保存前设 `$app.DisplayAlerts = 1`（ppAlertsNone）抑制格式/兼容弹窗，否则隐藏窗口下 Save 弹窗永久卡死（实测首跑 5 个视频嵌入后卡在 Save，文件未更新）。
- 验证链：python-pptx 重开查幻灯片数与 media 形状名 + COM `Export($dir,'PNG',1600,900)` 导出预览逐页目检；预览 PNG 经 Read 工具查看时会缓存串图，**转存 JPEG/拼图再读**才可靠。中间脚本放 .agent-tmp\。

## H5 关页后自动补传（Background Sync，2026-10-16 冻结，CF-WPS-105）

- **需求与方案**：用户问「是否可以增加关页后自动补传」，选定**方案一（SW 内完整重放）含方案二兜底（系统通知）**。仅 Chromium 系（Chrome/Edge 安卓等）生效；Firefox/iOS 无 SyncManager，注册静默跳过，退回 CF-WPS-103 的「打开页面补传」现状。
- **镜像层（check.html，冻结）**：SW 读不到 localStorage ⇒ 镜像到 IndexedDB（库 `hse-bg-sync`/store `kv`）：`queue`（SW 可重放条目数组）+ `session`（token/exp/creds）。条目 = {id, state(pending|synced|failed), body(页面 toPatrolBody **固化**的载荷), photo{dataUrl,cid,needUpload}, assign}；`needUpload` 对齐页面 photoFp 口径（换过图→重传）；`rec._pendingAssign` 在派发流程（建单即指派）赋值供镜像。
- **铁律（冻结）**：①镜像只在 `bgMergeFromMirror` 完成后重建（`bgMerging` 互斥，bgMirrorQueue 用 `bgMirroring`），绝不覆盖 SW 落表结果；②载荷页面侧固化，SW 只做 HTTP 重放不实现业务；③幂等靠 client_request_id（服务端先查后写），页面与 SW 并发重放不建重单；④镜像钩在 `saveDB()` 首行 `bgScheduleMirror()`（1.2s 防抖 + sig 变更比对）；⑤合并只升级不降级：synced 恒采纳，failed 仅覆盖 pending。
- **SW（sw.js，冻结）**：保留 fetch 纯透传不动，新增 sync 监听 tag `hse-patrol-sync` → `bgSyncRetry()`：逐条 ensureAuth（token 过期→镜像 creds 静默重登）→ needUpload 则 /api/mobile/upload（dataURL→File）→ /api/mobile/patrol/submit（+photo_tokens/+assign_to）→ 每条落盘 IDB；429/5xx/401/网络错→pending，其余 4xx→failed 终态；`remain>0` 时 **reject** ⇒ Chrome 按退避自动重试同 tag；fetch 一律 60s AbortController 超时。通知（仅 `Notification.permission==='granted'`）：补传成功 N 条 / 待补传 N 条（点击打开 /check）。

## 手机端 H5「无法登录」=登录页内联脚本被 CSP 白名单静默拦截（2026-10-21 定谳，CF-WPS-110，Pages Deployment 0537098b）

- **现象（冻结指纹）**：登录页正常渲染、输入框与「登 录」按钮都在，点击后按钮仅短暂 loading 即恢复，**不发任何网络请求、无任何错误提示**。
- **根因（冻结）**：2026-10-21 16:2x 那次 Pages 部署（`7b6022f0`）在 `_pages_deploy/_headers` 新增 CSP，`script-src` 用 **10 个 sha256 内联脚本白名单**。上线后 `login.html` 的内联 `<script>`（定义 `doLogin` + 绑定按钮 click）**整段不执行**：浏览器实测 `typeof window.doLogin === 'undefined'`、`typeof window.mobileApi === 'function'`、内联脚本 `len=1988` 且 `{`16/`}`16 完整、`btn.onclick=null`。CSP 拦截属于**静默失效**——页面看起来完全正常，控制台也未必抛出显眼报错。
- **排错顺序（冻结范式）**：①先证后端清白：`POST /api/mobile/auth/login` 错误手机号 → **401「手机号或密码错误」**（Worker+飞书链路健康）②浏览器运行时符号取证：`typeof window.doLogin` / `typeof window.mobileApi` / `document.scripts[i].textContent.length` ③CSP 哈希逐字节重算（原始字节，不做换行归一化）：本次 **10/10 与本机文件一致**，说明不是「哈希写错」而是白名单机制本身在该环境下失效 ④核对线上产物 vs 本地源码体积。
- **同批部署的第二个坑**：`app.js` 被压成 3894B（本地 9161B）、`check.app.js` 182765B（本地 337781B）。**压缩版函数齐全**（`mobileApi` 正常），排查初期误判为「app.js 截断」，已排除。
- **修复（冻结）**：`script-src` 改为 `'self' 'unsafe-inline'` 并**删除全部 sha256**——CSP 规范中只要存在 hash 或 nonce，`'unsafe-inline'` 就会被忽略，**不能只追加**；`_pages_deploy` 与 `frontend` 全量同步 6 文件（app.js 9161 / check.app.js 337781 / check.html 117392 / login.html 5215 / config.js 745 / version.json 26）；重新部署 → **`0537098b`**。

- **冻结口径（必须遵守）**：①**多页、多段内联、HTML 频繁变更的站点，禁用「内联脚本 sha256 白名单」类 CSP**——失效时无提示、整页功能静默死亡；要 CSP 就用 `'unsafe-inline'` 或服务端 nonce ②**CSP 失效指纹**=页面正常 + 脚本文本完整 + 全局符号缺失 + 点击静默，优先怀疑 CSP，不要先怀疑语法/截断 ③线上判定以**运行时符号**为准（`typeof window.doLogin`），不要只看 HTML 体积或文本是否闭合 ④`_pages_deploy` 与 `frontend` 必须全量同步并校验 MD5，禁止只同步部分文件 ⑤排查顺序固定为「后端 API 实证 → 浏览器运行时取证 → 部署产物比对」，避免在错误层反复猜测。

## CF-WPS-112（2026-10-21）手机端桌面图标进入卡死启动页——动态脚本错过 DOMContentLoaded
- **真机指纹**：停在「正在验证登录状态…」，**无 8 秒兜底「页面没能正常启动」、无 15 秒 watchdog「网络较慢，启动超时」**。
- **排除法（冻结）**：无 8 秒兜底 ⇒ `check.app.js` 已执行到底（`window.__hseAppReady=true` 使 `fatal()` 直接 return）⇒ **排除**脚本下载失败 / SyntaxError / CSP；无 watchdog ⇒ `boot()` 从未被调用（`armBootWatchdog()` 在 `boot()` 首行）。该「双无」组合是「主脚本已执行但启动入口未调用」的确定性指纹。
- **根因**：`check.html` 用**动态 `createElement('script')` 注入** `check.app.js`（async，不阻塞 DOMContentLoaded），而 `boot()` 与全部事件绑定只注册在 `DOMContentLoaded` 监听内。慢网下 337KB 脚本执行时事件早已触发 → 监听永久错过 → 永久停在初始文案。桌面/快网脚本常在事件前执行，故「时好时坏、只有手机不行」。
- **修复（冻结范式）**：事件回调首行加 `if (window.__hseBootDone) return; window.__hseBootDone = true;`；文件末尾 `window.__hseAppReady = true` 之后补 `if (document.readyState !== "loading") document.dispatchEvent(new Event("DOMContentLoaded"));`。**禁止异步脚本只依赖 DOMContentLoaded 做启动**。
- **版本 / 发布**：`.122 → 2026-10-21.130`（`hse-build` + check.html 3 处 `?v=` + `version.json`）；部署 **`5941a661`**；线上 `/check` MD5 `0EE3B8CB…`、`/check.app.js` 338670B `92A746E1…` 均与本地一致；浏览器实测 `/check` 正常启动并跳 `/login`。
