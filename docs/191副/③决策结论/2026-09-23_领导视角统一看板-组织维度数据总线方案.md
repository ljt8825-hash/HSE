## 一、用户需求（已确认）

领导需要一个**按组织维度钻取**的统一看板，而非逐模块翻查。钻取路径：

```
环卫作业中心 / 市政园林作业中心（作业中心）
   └─ 各乡镇作业中心（乡镇）
         └─ 该乡镇跨模块汇总：事故 / 考核 / 三违 / 网格长巡查 / 培训 / 应急演练 / 人员保险 / 车辆保险 / 其他保险 / 超龄人员 …
         └─ 人员维度：先看角色汇总（驾驶员 / 乡镇作业中心经理 / 管理员），再点人看个人明细
         └─ 时间筛选：按年度
```

已确认要点：
- 形态 = **新增独立汇总看板**（保留现有各业务模块不动）。
- 数据范围 = 事故、考核、三违、网格长巡查、培训 + 应急演练、人员保险、车辆保险、其他保险、超龄人员等系统内能串到乡镇/人员的一切。
- 人员维度 = **先角色汇总，再点人看明细**。
- 交互 = **统计汇总 + 可下钻到某条具体业务记录**。

## 二、组织与人员数据总线（权威模型）

组织树单一权威：`hse_org_unit`

```
公司(company)
 ├─ 环卫作业中心 (center)
 │    └─ 长官镇作业中心 / 大曹镇作业中心 / 时集镇作业中心 / 相衙镇作业中心 … (town_center)
 └─ 市政园林作业中心 (center)
      └─ …乡镇作业中心 (town_center)
```

人员归属绑定链（禁止姓名/岗位自动推断身份）：

```
users.id → users.employee_id → employee.id
   → employee_assignment.org_unit_id → hse_org_unit（组织）
   → employee_assignment.position_id → position（岗位：作业中心经理/管理员/司机/网格长…）
   → employee_assignment.supervisor_id → employee.id（直接上级）
```

- 旧表 `department` 仅作组织映射 / 树形展示兼容；当前主路径已绑 `org_unit_id`。
- `employee_assignment.dept_name` 是花名册原始所属部门文本，用于兼容/展示，不是 `org_unit_id` 的替换维度。

## 三、各模块挂「乡镇/人员」维度对照表（调研实测）

| 模块 | 乡镇维度 | 人员维度 | 按乡镇聚合现状 | 按人聚合现状 |
|---|---|---|---|---|
| 月度考核 | 有 `township` + `position` | `employee_id` | ✅ 最干净 | ✅ |
| 事故 | `township` 文本 | `handler_id`/`party_*` | 可筛·无聚合接口 | 有字段·无聚合 |
| 网格长巡查 | `grid_areas.township`(大量NULL)+`area_team` | `inspector_employee_id` | 归因·无统计 | 有字段·无汇总 |
| 三违 | `area_team` 文本解析（无 township 列） | `violator_id` | 无现成 | ✅ 按人可 |
| 培训 | 无 township（需经员工反推） | `employee_id` | ❌ | ✅ |
| 人员保险 | 无 township（有 department 字符串） | `employee_id` | ❌ | ✅ |
| 应急演练 | `township` 字符串 | ❌ 无人关联 | 仅全局统计 | ❌ |
| 超龄人员 | 无 township（有 dept 字符串） | `personnel_id` | ❌ | ✅（仅 keyword） |
| 车辆保险 / 其他保险 | ❌ 无组织维度 | ❌ | ❌ 无法归乡镇 | ❌ |

**核心结论**：系统**没有一条贯通的「记录 → 乡镇」总线**。月度考核最干净；三违/网格巡查靠 `area_team` 文本最长匹配归因（sanweiLedgerDerive 已有此逻辑可复用）；培训/人员保险/超龄靠员工反推；**车辆保险、其他保险几乎无法归到乡镇级**（无任何 org/人员字段）——需要与用户专项确认如何归口。

## 六、风险与待办

> 2026-09-23 用户已确认两条维度归口，本段两条「需用户确认」均闭合：

- **车辆保险 / 其他保险组织维度（已定）**：公司集采，与乡镇/个人无关 → **不做乡镇/个人下钻**，仅在全局/作业中心级展示集采概况即可，不参与乡镇钻取路径。
- **应急演练人员关联（已定）**：当前数据未补充，仅做乡镇级汇总可接受；**后期数据补充后应能挂到管理员（班组级）**，故归因层需为应急演练预留「乡镇 → 班组/管理员」的扩展位（当前无人关联，先到乡镇级，数据到位后同一归因层可升级到人）。
