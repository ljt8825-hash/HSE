# 核心域子路由进一步模块化：position 域三层试点

> 类别：③决策结论 ｜ 日期：2026-09-13 ｜ 归属对话：当前会话（HSE 架构审计·中期拆分）

## 背景

- 巨无霸 `hse-employee.js` 已按 6 核心域 + 7 尾部域拆成 13 个子路由，父文件收编为纯聚合入口（提交链 `f65eab3 → 071bb28`）。
- 用户要求"推进核心域子路由的进一步模块化"，对应《HSE架构重构行动计划_20260912》G6：
  **route=纯绑定 / controller=薄 handler / service=业务+SQL**，service 收逻辑、route 只剩绑定，是 ROI 最高的一步。

## 决策

1. 选 `position` 域（7.6KB / 4 端点 / 自包含）作为**三层结构试点**，验证模板后再批量套用其余 5 域（employee / org-tree / assignment / history / import）。
2. 结构落地（对外契约 `/api/hse/employee/positions(...)` 逐字节不变）：
   - `server/routes/hse-employee/position.js` → **纯绑定**：仅 path+method+middleware → controller
   - `server/controllers/hse-position.js` → **薄 handler**：req 解析 + 调 service + res 包装（含 auditLog）
   - `server/services/positionService.js` → **业务+SQL**：全量迁移原内联 handler，无 express 依赖，可独立单测
3. 复用既有目录与写法规格：`controllers/` 已存在（checkLedgerFactory 等）；`services/` 已存在（employeeEventService 等）。
4. service 返回 `{ row, error, message }` 业务码约定，controller 负责映射为 `error(code,msg)` / `success(...)`，保留原 `-2/-3/-4/-5` 业务码语义。

## 验证结果（2026-09-13 通过）

- smoke（`server/_smoke_employee.cjs`）：`GET /positions → 200`、POST→401（门禁预期）等 40 端点全通过。
- service 直连单测（事务包裹+回滚，不污染数据）：分页/数组两种返回形态、建→改→删、二次删除返回 `-2`，全部通过。
- 提交：`9ccfaaa refactor(hse-employee): modularize position domain into route/controller/service layers`

## 待确认（后续批量套用前需用户拍板）

- 其余 5 域是否沿用同一三层模板逐域落地（每域独立提交+回归）？
- 大域（employee 38KB / import 31KB）是否在 service 层按子功能再细分文件？
- 是否将 position 试点沉淀为项目代码规约（写入 project_memory），供 AGENTS/README 引用？

## 风险 / 注意

- 重构为行为保持型：**不得**顺手修 bug / 改字段口径 / 动前端契约，否则 diff 无法审。
- `history.js` 中 `error` 引用为历史遗留（`res.json(error(...))` 但顶部未 require error，依赖 `response` 中间件挂载）；三层化时顺手将 service 改为统一返回形态，controller 显式 require。
- 生产边界：本次仅新增/重写 `server/{services,controllers,routes}` 下文件，未触碰生产端口/生产表/身份链/WPS 边界。
