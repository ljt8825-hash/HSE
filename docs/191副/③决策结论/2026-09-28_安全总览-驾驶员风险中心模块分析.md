# 安全总览 → 驾驶员风险中心 模块分析

> 日期：2026-09-28　类别：③决策结论（模块分析）
> 分析范围：前端 `web-naive` 页面 + 后端 `hse-driver-risk-center.js`，只读分析，未改动任何代码/数据。

## 一、模块定位与权限

| 项 | 值 |
|----|----|
| 一级菜单 | 安全总览 `/overview`（`HseOverview`） |
| 二级子页 | `/overview/driver-risk-center`（`HseDriverRiskCenter`） |
| 页面标题 | 驾驶员专项风险中心 · 公司驾驶员安全风险管理 |
| 权限 | `authority:['admin']`；父级额外放行 `safety_manager`，子页严格要求 `admin`（AI-09 既定策略） |
| 业务定位 | 驾驶员综合安全风险管理总览 + TOP 风险排行，点击排行项跳转个人画像 `/hse-advanced/risk-profile/{employeeId}`（聚合 → 画像 导航模式） |

## 二、页面组成（前端 web-naive）

`index.vue` 在 `onMounted` 内用 `Promise.all` 并行加载 4 个接口，组成 6 个子组件：

| 卡片区 | 子组件 | 数据接口 |
|--------|--------|----------|
| 顶部总览 | RiskOverview | `/overview` |
| 风险等级分布（环形图+明细列表） | LevelDistribution | `/overview.levelDistribution` |
| 驾驶风险构成（进度列表：扣分/事故/三检/培训） | RiskComposition | `/overview` |
| 驾驶证扣分分析（饼图+TOP +4 统计卡） | DemeritAnalysis | `/demerit/statistics` |
| TOP风险排行（列表） | TopRanking | `/drivers?page=1&pageSize=10` |
| 交通事故分析（等级饼图+年度柱 +3 统计卡） | AccidentAnalysis | `/accident/statistics` |

## 三、后端接口（`server/routes/hse-driver-risk-center.js`，全部只读 GET）

- `GET /overview`：驾驶员数、等级分布、highRiskCount、扣分/事故/三检/培训统计
- `GET /drivers`：驾驶员风险分页列表（含过滤 keyword/risk_level/org/operation）
- `GET /demerit/statistics`：近5年扣分总体/分布/TOP/月度趋势
- `GET /accident/statistics`：事故总体/等级分布/年度趋势/责任事故驾驶 TOP

已在 `server/app.js:540-541` 注册，前缀 `/api/hse/driver-risk-center`。

## 四、数据口径（已核对）

1. **驾驶员识别**（宽松模糊匹配）：`position.name ILIKE '%驾驶员%' OR ILIKE '%司机%'`，基于当前有效岗位 `employee_assignment(is_current=true,is_deleted=false)`。文件头定义 `DRIVER_POSITIONS` 常量但 SQL 未使用（ILIKE 已覆盖该常量所列岗位，冗余无害）。
2. **风险等级**：`risk_level_config`（low/medium/high/critical）；`highRiskCount = high+critical` 求和；按指标字典 high=40-59 分、critical=0-39 分。
3. **综合评分语义**（字典 line296）：0-100 分，**分数越低风险越高**。
4. **TOP 排行排序**：`drivers` 按 `snap.total_score` 升序 `COALESCE(…,100)` → 分数最低（风险最高）排前，取前 10；**方向正确**。
5. **扣分**：近 5 年 `license_demerit_records`（`demerit_date >= 5 年前`）。
6. **事故**：`accident_type='交通事故'`，匹配 `involved_person IN(驾驶员姓名)` 或 `personnel_id IN(驾驶员id)`。
7. **风险快照**：取 `hse_employee_risk_snapshot` 最新 `MAX(snapshot_date)`。

## 五、口径一致性核对结论（核心发现）

### 一致项
- 分数方向与 TOP 排序逻辑自洽 ✔
- 扣分整体口径统一「近5年」且接口标注 `period:近5年` ✔
- 等级编码/色值与指标字典一致 ✔

### 不一致 / 风险点（建议关注）
- **A. 期限文案冲突**：`overview.demeritStatistics` 实际为近 5 年，但前端 `RiskComposition.vue` 的「驾驶证扣分」副标题写「**近一年**有扣分记录」，与后端口径不符，易误导。
- **B. 三检未限定驾驶员范围**：`overview.inspectionStatistics` 直接对 `hse_driver_inspection_records` 全表聚合，未 JOIN 当前驾驶员岗位集合；而分母 `driverCount` 是当前驾驶员，分子可能含非当前驾驶员/已调岗记录，比例失真。
- **C. 事故姓名匹配风险**：overview 事故统计用 `involved_person IN(驾驶员姓名)` 按姓名匹配。①同名驾驶员会互相误命中放大计数；②员工岗位变动/离职后历史事故不再匹配当前驾驶员集合（跟随当前岗位过滤）。
- **D. `responsibleDrivers` 口径与 overall 不一致**：`accident/statistics` 的 `responsibleDrivers` 仅按 `a.personnel_id::bigint = employee.id` 关联，未按姓名、未限定当前为驾驶员；且 `personnel_id` 空值/非数值时 `::bigint` 强转有 SQL 报错隐患（同类问题 2026-09-28 已在 `grid_areas.personnel_id::bigint` 修复过）。
- **E. 扣分/事故 TOP 榜未限定当前岗位**：`demerit/statistics.topDrivers`、`monthlyTrend`、`pointsDistribution` 及 `accident/statistics.responsibleDrivers` 均未过滤该员工当前仍为驾驶员岗位。
- **F. 性能**：`drivers` 列表多处内联子查询 `(SELECT MAX(snapshot_date)…)` 逐行执行，可改用 CTE（性能项，非正确性）。
- **G. 功能受限**：TopRanking 仅取 `pageSize=10` 且无「加载更多/分页/全量列表」入口；`index.vue` 注释说明因无后端导入端点而隐藏「导入」按钮（web-antd 迁移降级）。
- **H. 跳转依赖**：点击排行跳 `/hse-advanced/risk-profile/{id}`，跨一级菜单，依赖该页面存在及其权限，否则点击无响应。
- **I. 权限边界**：仅 `admin` 可见，`safety_manager` 不可见——注释已明确为 AI-09 既定策略，非缺陷。

## 六、生产边界合规（多层复审）

- 全部端点只读 GET，无 DELETE/UPDATE/INSERT/ALTER/DROP/TRUNCATE ✔
- 未触碰生产表写库、WPS 单向架构、身份链、JWT ✔
- 未发现越权写库或冒用生产端口 ✔

## 七、总体结论

结构清晰、职责单一，是「驾驶员风险管理总览 → 个人画像」的聚合导航页，权责与只读边界合规。主要改进空间集中在**口径一致性**：三检未限定当前驾驶员、扣分/事故 TOP 榜未限定当前岗位、overview 扣分期限文案与近 5 年不符、责任驾驶 TOP 的 `personnel_id::bigint` 强转与姓名匹配风险。建议后续在参数化设计中统一「驾驶员 = 当前有效岗位且岗位名匹配」的可复用口径，并统一扣分期限为「近 5 年」。

> 风险待办：以上 A–H 为潜在改进项，如需落地需独立排期并经生产边界授权（本分析未做任何代码/数据改动）。
