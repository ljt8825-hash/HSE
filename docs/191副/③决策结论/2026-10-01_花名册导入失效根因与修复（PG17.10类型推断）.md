## 结论 / 决策

1. **10-01 批次（batch 39）正式入库实际整体失败、0 写入**，非"导了没生效"而是"导了没成功"：
   - 审计仅有 `upload`（11:29，3301 行/跳过 2/成功 3299），无 `import` 记录；
   - `employee` 表 10-01 当日无任何 `updated_at` 更新；
   - 批次状态 `partial_completed`、3299 条 pending 全部仍为 `approved`（未被标记 `imported`）。
2. **根因 = PostgreSQL 17.10 升级后的参数类型推断失败**：员工 UPDATE 语句 `COALESCE($8, direct_supervisor)` 与 WHERE 中 `$8 IS NOT NULL` 组合时，$8 无类型上下文 → `ERROR: 无法确定参数 $8 的数据类型` → 每行在保存点回滚 → 整批 0 写入、批次被标记 partial_completed。
3. **审计静默缺失 = 二次缺陷**：`auditLog()` 对 `!userId` 直接 return，而入库路径未透传 userId → 失败批次连 import 审计都没有，误导排查。
4. **修复已落盘并验证**：
   - 员工 UPDATE、花名册三列 UPDATE 增加 `::varchar` 显式类型转换（`employeeImportV2Service.js` 行 998–1017）；
   - 审计 userId 由 controller → `batchImport` → `performBatchImport` → `auditLog` 全链路透传（行 1087–1088、1346–1349）；
   - `diag_replay3.cjs` 在回滚事务中验证修复后 5 行全流程通过。
5. **生产补入库（用户显式授权）已执行成功**：见②交付报告 2026-10-01 花名册 batch 39 补入库生产放行。
