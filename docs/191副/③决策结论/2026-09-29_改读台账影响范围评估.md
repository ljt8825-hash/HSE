# 驾驶员风险中心「改读台账」影响范围评估

> 日期：2026-09-29　类别：③决策结论（影响评估，只读，未改任何代码/数据）
> 议题：将「安全总览→驾驶员风险中心」数据源从风控快照 `hse_employee_risk_snapshot` 改为读「现场管理→驾驶员管理→评估档案」`driver_assessment` 台账。

## 一、结论（先给结论）

**不建议改读台账。** 台账在完整性、身份关联、等级口径、数据量四方面均无法替代风控快照；若强行切换会造成风险中心能力大退 + 全站风险等级口径分裂，且无法解决风险中心当前"等级/TOP 为空"的真实根因。

## 二、关键实证（只读查询）

| 维度 | 台账 `driver_assessment` | 快照 `hse_employee_risk_snapshot` |
|------|--------------------------|-----------------------------------|
| 记录数 | 仅 **89**（驾驶证评估45 + 三违评估44） | **当前 0 行**（综合评分/等级/TOP 现均无数据） |
| 等级分布 | 较低85 / 一般1 / 较大1 / 空2 / **重大0**，几乎单一等级 | 表空 |
| 风险等级体系 | **中文四级** 较低/一般/较大/重大（《附表1》违章记分规则判定） | **英文四级** low/medium/high/critical（0-100 多维综合分） |
| 身份关联 | **无 `personnel_id`/`employee_id`；`id_card`、`phone` 全空**；仅 `name`，89 条中仅 **44** 个姓名命中 employee | 按 `employee_id` 强关联 ✓ |
| 分数 | 无 `total_score` 列 → **无法排序 TOP** | 有 `total_score`（numeric）+ `dimension_scores` |
| 明细 | 不含量化扣分/三检/事故明细（仅评估结论+管控措施） | 多维采分（扣分+事故+三检+培训） |

## 三、影响范围清单

1. **能力缺失（阻塞项）**
   - 扣分分析（近5年/月度/TOP）、三检、事故维度：台账**均不含这些明细**，`demerit/statistics`、`overview` 的扣分/三检/卡车卡无法由台账产出，需另接明细表。
   - TOP 风险排行：台账无分数，无法按综合分排序；只能退化为按 `assessment_level`（且实测几乎全为"较低"）无区分。
2. **身份关联失败**
   - 台账无身份证/工号外键，仅姓名。89 条仅 44 个姓名能命中 employee → 无法与风险中心其它按 `employee_id` 返回的板块（画报/列表/等级）对齐，重名会扩大误差。
3. **等级口径分裂（全站连锁）**
   - 快照表被 **8 个服务依赖**：`warningCenterService`、`hseRiskProfileService`、`hseAssessmentAnalysisService`、`executiveCockpitService`、`assessmentService`、`analysisCenterService`、`hse-risk-profile-detail`，以及本路由。
   - 风险中心若改用「中文四级台账」，而画像页(/hse-advanced/risk-profile)、预警中心、领导驾驶舱、考核分析等仍用「英文四级快照」→ **同一驾驶员等级在两处不一致**，出现"风险中心=重大、画像页=high"等矛盾。
4. **风险中心「等级/TOP 为空」真实根因**
   - 实测快照表当前 **0 行** → 这正是风险中心等级分布全空、TOP 排行为空的可观测根因。**问题不在"数据源选错"，而在快照未生成**（应排查快照计算链路/定时任务），改读台账不能修复，反而引入上述 1–3 的新问题。

## 四、结论与建议

- **不建议**将风险中心整体改读 `driver_assessment` 台账。
- 若用户真实目标是「数据归属到 现场管理→驾驶员管理、事故管理」的**同源一致**，更合理的做法是：**保证台账与风险引擎使用同一明细数据底座**（扣分 `license_demerit_records`、违章、事故 `accidents`、三检 `hse_driver_inspection_records`），而非把风险中心切到台账这一份"评估结论表"。
- **建议单独立项排查快照为 0 的原因**（`hse_employee_risk_snapshot` 空，快照计算任务是否按期执行、数据底座是否就绪），这是风险中心等级/TOP 无数据的真正修复点。
