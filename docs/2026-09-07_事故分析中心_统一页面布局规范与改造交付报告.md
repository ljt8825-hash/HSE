## 二、区块划分与排列顺序（自上而下固定）

页面采用 **单列纵向流式布局**，区块顺序固定不可调换：

```
┌──────────────────────────────────────────────────────────┐
│ Page 页头                                                 │
│   标题：事故分析中心  描述：HSE事故风险分析与责任追踪        │
│   右上角（页头 extra）：[刷新数据]                          │
├──────────────────────────────────────────────────────────┤
│ B1  查询筛选栏        标题「查询筛选」  extra：[重置][查询]  │
├──────────────────────────────────────────────────────────┤
│ B2  统计概览区        标题「核心指标概览」  7 项指标网格      │
├──────────────────────────────────────────────────────────┤
│ B3  图表分析区                                             │
│     B3-1 事故趋势（全宽：总数/责任事故 + 分类趋势对比）      │
│     B3-2 事故分类分析(1/2) + 事故等级分布(1/2)              │
│     B3-3 责任人员岗位分布(1/2) + 责任人员部门分布(1/2)       │
│     B3-4 乡镇/单位分布（全宽，TOP20）                       │
├──────────────────────────────────────────────────────────┤
│ B4  明细数据表格区    标题「明细数据」                       │
│     extra：[搜索框][导出CSV]                               │
│     NTabs：责任人员TOP排行 / 事故关联人员                    │
└──────────────────────────────────────────────────────────┘
```

**排列依据**：筛选（决定数据）→ 概览（结论先行）→ 图表（归因分析）→ 明细（下钻取证），符合"从结论到过程再到证据"的分析型页面阅读动线。

## 三、统一卡片容器规范

所有 4 个区块（B1~B4）及其内部图表卡，统一使用同一套 `NCard` 参数：

| 属性 | 统一取值 | 说明 |
| --- | --- | --- |
| 组件 | `NCard` | Naive UI 原生卡片，不使用任何封装 |
| `size` | `"small"` | 统一尺寸档位 |
| `:bordered` | `false` | 统一无边框，靠页面底色区分 |
| `:content-style` | `{ padding: '16px' }` | **内容区内边距统一 16px** |
| `class` | `section-card` | 统一圆角 8px |

子卡片（B3-2 内的一级分类汇总卡）使用 `NCard size="small"` + `class="sub-card"`（圆角 6px），作为唯一允许的二级卡片层级。

## 六、查询筛选栏 / 操作按钮 / 内容区 的摆放规则

### 6.1 三级操作归属（核心规则）

| 级别 | 位置 | 承载内容 | 本页实例 |
| --- | --- | --- | --- |
| **页面级** | `Page` 的 `#extra` 插槽（页头右上） | 作用于整页数据的操作 | `[刷新数据]` |
| **区块级** | `NCard` 的 `#header-extra` 插槽（卡片标题行右侧） | 作用于该区块的操作/说明 | B1「重置/查询」；B4「导出CSV」；B2、B3、B4 放口径/记录数说明文字 |
| **行级** | 表格列内 `NButton text` | 作用于单条记录 | 「风险画像」跳转 |

> 规则：**不在内容区顶部堆按钮条，不在内容区底部放操作区**；所有操作向上收敛到卡片标题行右侧。

### 6.2 查询筛选栏（B1）

- 容器：独立 `NCard`（`size="small"`），内容区 `NForm`（`label-placement="left"`、`label-width=72`）内嵌 `NGrid` 响应式栅格。
- 字段顺序：**统计周期（NRadioGroup 按钮组）→ 年份（NSelect，仅月度可用）→ 事故分类（NSelect）→ 关键词（NInput）**。
- 操作按钮放 `#header-extra`，顺序：**重置（tertiary）在左、查询（primary）在右**。
- **草稿 → 提交模式**（`draft` 绑定控件，`applied` 为生效条件）：修改控件不立即生效，点「查询」提交后统一应用；「重置」恢复默认并立即提交。避免"筛选栏控件即时生效、查询按钮形同虚设"的语义冲突。
- 触发语义：
  - 统计周期 / 年份：提交后走服务端参数 `/trend?period=&year=`；
  - 事故分类 / 关键词：提交后在前端过滤已加载数据（分类作用于「事故类型明细」图与「分类趋势对比」系列；关键词作用于 B4 两张明细表）。

### 6.3 明细数据表格区（B4）

- 表格切换用 `NTabs type="line"`，两个 `NTabPane`：「责任人员TOP排行」（本地数据）、「事故关联人员」（`NDataTable remote` 服务端分页 10/20/50）；
- `#header-extra` 放**记录数说明 + 「导出CSV」**（关键词搜索统一收敛到 B1 筛选栏，不在表格区重复放置控件）；
- 两张表统一 `size="small"`、`striped`、`max-height: 420px`（超出内部滚动，不撑破区块）。

## 七、自适应规则（断点表）

栅格统一使用 **`NGrid responsive="self"`**（按栅格容器自身宽度响应，规避侧边栏折叠导致的误判）。Naive UI 断点：`xs<640 ≤ s<1024 ≤ m<1440 ≤ l`。

| 元素 | xs（<640） | s（640–1023） | m（1024–1439） | l（≥1440） |
| --- | --- | --- | --- | --- |
| 筛选栏字段 | 1 列 | 2 列 | 2 列 | 4 列 |
| 概览指标 | 2 列 | 3 列 | 4 列 | 4 列 |
| B3-1 趋势卡内双图 | 1 列（上下） | 1 列 | 1 列 | 2 列（左右） |
| B3-2 分类 + 等级 | 1 列 | 1 列 | 2 列 | 2 列 |
| B3-3 岗位 + 部门 | 1 列 | 1 列 | 2 列 | 2 列 |
| B3-4 乡镇分布 | 全宽 | 全宽 | 全宽 | 全宽 |
| B4 表格 | 横向滚动 + 列宽固定 | 同左 | 自适应铺满 | 自适应铺满 |

补充规则：

1. **图表高度固定**（主趋势 280px、分类/岗位/部门 240px、等级 260px、乡镇 300px），宽度 `100%` 由 `EchartsUI` 自适应；不做百分比高度，避免窄屏压扁。
2. **卡片不设固定高度**，由内容撑开；同行的两张图表卡高度由 `NGrid` 自动对齐。
3. **筛选栏在 xs 断点纵向堆叠**，按钮组与选择器占满整行宽度。
4. **表格在窄屏横向滚动**（`NDataTable` 默认行为），关键信息列（姓名/事故数/责任事故）靠左固定，保证首屏可读。
5. 概览指标单元 `.stat-cell` 采用 `height: 100%` + 边框容器，保证同行等高。

## 十、已知限制与后续建议

1. **筛选为混合模式**：后端 4 个接口目前只支持 `period` / `year` / `page` / `pageSize` 参数，**不支持按分类、关键词的服务端过滤**。因此：
   - 统计周期、年份 → 服务端参数，点「查询」提交后生效；
   - 事故分类 → 前端过滤（作用于「事故类型明细」图与「分类趋势对比」系列）；
   - 关键词 → 前端过滤（TOP 排行为全量过滤；关联人员仅过滤当前页，因其为服务端分页）。
   - 若需全量服务端检索，需后端在 `/classification`、`/responsible` 增加 `category` / `keyword` 参数（**需单独授权后再改后端**）。
2. **导出为纯前端 CSV**：当前导出基于已加载数据生成 CSV（带 BOM，Excel 中文不乱码），非全量导出；如需全量导出需后端提供导出接口。
3. **后续新增子页面**：若事故分析中心拆出子路由（如「事故明细」「责任追踪」），直接复用本文第二~七节的区块模板（B1→B2→B3→B4 + 16px 间距 + `section-card` + `.card-title`）即可保证一致。
