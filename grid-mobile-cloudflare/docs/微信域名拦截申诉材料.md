# 微信域名拦截申诉材料（grid1ns.dpdns.org）

> 起草日期：2026-09-23
> 适用场景：微信内置浏览器打开 `https://grid1ns.dpdns.org/check` 时提示「该网页所属平台可能存在被他人恶意利用…已停止访问该网页」。
> 用途：本文件是**申诉填表模板 + 素材清单**，所有【请填写：…】为需你补全的真实信息，请勿直接编造。

---

## 0. 先看清这件事（决定要不要花力气申诉）

**坏消息（先说透）：**
- 拦截提示里写的是「**该网页所属平台**……」，意味着微信标记的是整个 `dpdns.org` 这个**免费二级域名后缀**，不是你这一条 URL 的内容违规。
- `dpdns.org` 是人人可免费注册子域的动态域名平台，被大量滥用发垃圾/违规内容，所以微信对整条后缀一刀切。
- **免费子域名无法单独做 ICP 备案**（备案主体只能是 `dpdns.org` 的注册者，不是你）。而微信申诉材料清单里「ICP 备案截图 + 营业执照」是提信用的核心——你这条提供不了。

**结论与建议：**
- 申诉**可以试**，但**成功率低、可能被秒拒**。把时间成本考虑进去：与其反复申诉，不如直接走「根治=换备案正规域名」（见第 6 节）。
- 本材料照填不误，先用**通道 1（拦截页底部按钮）**和**通道 2（微信开放社区）**两条路同时提交，哪个先过用哪个。
- 应急：微信内点右上角「···」→「在浏览器打开」，或复制链接到系统浏览器（Chrome/三星浏览器）打开，拦截**只存在于微信内置 X5**，跳出即消失。

## 1. 四条官方申诉通道（按推荐顺序）

| 优先级 | 通道 | 入口 | 时效 | 备注 |
|---|---|---|---|---|
| 1 | 拦截页底部直接申诉 | 微信打开被拦截链接 → 拉到页面最底部 →「申请恢复访问」/「申诉」按钮 | 官方承诺 3 个工作日 | 最直接，但后缀级拦截可能直接驳回 |
| 2 | 微信开放社区发帖 | 电脑访问 `https://developers.weixin.qq.com/community`，发帖分类选「外链访问」 | 网友实测 1–3 天有官方回复，常比通道 1 快 | **最推荐先发这条** |
| 3 | 腾讯安全-网址安全中心 | `https://urlsec.qq.com/complain.html`，输入网址走流程 | 邮件回执，结果邮件通知 | 若是手机管家/腾讯安全引擎拦截更对口 |
| 4 | 微信公众号「腾讯安全防诈骗实验室」 | 微信搜该公众号 → 菜单提交申诉 | 有反馈称 24h 内出结果 | 可顺手试 |

> 注：通道 1 的申诉表单字段与下方「2. 表单逐项填写模板」一致；通道 2 走社区发帖，用「3. 社区发帖正文模板」。

## 5. 提交后跟进

- 通道 1 提交后会生成**回执单号**，务必截图保存，用于进度查询。
- 进度查询：微信 → 我 → 设置 → 账号安全 → 微信安全中心 → 查询申诉进度（输入手机号+回执单号）。
- 若被驳回：看驳回原因。**若是「后缀/平台级」类原因，基本判定申诉路线走不通，直接转第 6 节根治方案**，不要再重复提交（反复提交可能越申越难）。
- 加急（超 48h 无结果）：微信账号客服 400-670-0700（工作日 9:00–18:00），话术：「本人于 X 月 X 日提交域名拦截申诉，回执号 XXX，疑似整后缀误伤，请求加急复核。」（客服仅能催办，不决定结果。）

## 6. 根治方案（申诉不成时的唯一确定性解法）

| 方案 | 说明 | 能否同时解决「微信不拦 + 国内能访问」 |
|---|---|---|
| A. 备案正规域名（**.cn / .com** 等） | 注册自己的域名 → 做 ICP 备案 → 绑定 Cloudflare Pages 自定义域 → 把现场二维码/分享链接全部切过去 | ✅ 唯一能同时解决 |
| B. 临时切回 `pages.dev` | `https://grid-mobile-cloudflare.pages.dev/check` 实测静态页+API 均正常，微信大概率不拦；但国内移动网络可能不稳/偶发被墙 | ⚠️ 部分解决，国内访问有风险 |
| C. 继续用 dpdns.org + 微信内「在浏览器打开」 | 不改域名，靠用户手动跳出微信 | ⚠️ 体验差，仅应急 |

**强烈建议走 A**：备案域名在微信/QQ/国内浏览器信任度最高，基本不会被拦，国内访问也稳。dpdns.org 这类免费域名的「申请恢复访问」申诉成功率本就很低，别把主线寄望于此。

## 7. 我能帮你接着做的（说一声就动手）

1. **统一切换入口域名**：把现场二维码、分享链接、配置里的入口 URL 全部对齐到目标域名（A 方案备案通过后，或临时 B 方案 `pages.dev`）。
2. **配置新域名绑定到 Pages**：备案通过后，加自定义域名 + 配 CORS 白名单 + 改前端 `config.js` 的 API base。
3. 若选 B 临时方案，先小范围给几个人实测 `pages.dev` 在微信里到底拦不拦，再决定全量切。
