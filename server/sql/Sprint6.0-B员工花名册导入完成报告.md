# Sprint6.0-B 员工花名册导入完成报告

## 一、项目背景

Sprint6.0-B 是 HSE 基础数据底座建设的第二阶段，核心目标是完成真实员工花名册的正式导入，实现从 Excel 到员工主数据、组织关联、作业单元关联、岗位关联、责任生成的完整链路。

本阶段基于 Sprint6.0-A 已完成的基础数据模型（组织模型、岗位体系、岗位别名、责任配置、导入规则基础模型），实现了完整的员工花名册导入流程。

## 二、导入流程总览

```
Excel上传 → 字段解析 → 组织匹配 → 岗位匹配 → 作业单元匹配
                                                         ↓
正式导入 ← 人工确认 ← 异常检查 ← 班组确认 ← 责任生成
```

**核心约束：**
- ✅ Excel所属部门不直接写入组织，必须经过组织映射规则匹配到 `hse_org_unit`
- ✅ Excel职位不直接作为岗位，必须经过岗位别名规则匹配到标准岗位
- ✅ 生产管理责任不生成网格等级（grid_level）和巡查频次

## 六、技术实现要点

### 6.1 禁止直接映射的保障机制

1. **组织匹配三重机制**：
   - 第一优先：`employee_import_mapping_rule` 映射规则
   - 第二优先：`hse_org_unit.org_name` 精确匹配
   - 第三优先：模糊匹配（仅用于异常提示，不自动确认）

2. **岗位匹配三重机制**：
   - 第一优先：`employee_position_mapping_rule` 映射规则
   - 第二优先：`hse_position_alias` 别名匹配
   - 第三优先：`position.name` 精确匹配

### 6.2 身份证号去重逻辑

- 导入时先按身份证号查询是否已存在员工
- 存在则更新员工信息（不重复创建）
- 不存在则新建员工记录

### 6.3 责任生成规则

- 根据岗位对应的 `hse_responsibility_config` 配置生成
- `responsibility_type = 'none'` 的岗位不生成责任记录
- `responsibility_type = 'production_manager'` 的岗位不生成 grid_level、grid_role、inspection_frequency
- 责任记录标记 source = 'roster_import'，便于追溯
