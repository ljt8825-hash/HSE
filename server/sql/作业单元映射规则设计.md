# 作业单元映射规则设计

## 一、设计目标

将Excel花名册中的"所属部门"和"职位"字段，通过映射规则匹配到系统中的标准作业单元（`hse_operation_unit`），实现员工与作业单元的准确关联。

**核心原则：禁止人工硬编码员工，所有匹配必须通过规则自动完成。**

## 二、映射规则表结构

### 2.1 employee_operation_unit_mapping_rule

```sql
CREATE TABLE employee_operation_unit_mapping_rule (
  id              BIGSERIAL PRIMARY KEY,
  source_dept     VARCHAR(255),      -- Excel所属部门（原始值）
  source_position VARCHAR(255),      -- Excel职位（原始值，可为NULL）
  target_unit_id  BIGINT,            -- 目标作业单元ID
  target_unit_name VARCHAR(255),     -- 目标作业单元名称
  target_unit_type VARCHAR(50),      -- 目标作业单元类型
  match_priority  INT DEFAULT 50,    -- 匹配优先级（数值越大优先级越高）
  status          VARCHAR(20) DEFAULT 'active',
  remark          VARCHAR(500),
  created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  is_deleted      BOOLEAN DEFAULT false
);
```

## 三、匹配优先级设计

### 3.1 四级优先级体系

```
第一优先（priority=100）：部门精确匹配
    ↓ 不匹配
第二优先（priority=90）：部门+岗位组合匹配
    ↓ 不匹配
第三优先：岗位推断作业单元类型
    ↓ 不匹配
第四优先：组织推断
    ↓ 不匹配
进入异常：unknown_operation_unit
```

### 3.2 各优先级详细规则

#### 第一优先：部门精确匹配（source_position IS NULL）

| source_dept | source_position | target_unit_type | priority | 示例 |
|-------------|-----------------|------------------|----------|------|
| XX镇X班 | NULL | cleaning_team | 100 | "宁城街道一班" → 宁城街道一班 |
| 车队 | NULL | center_vehicle_team | 95 | "车队" → 中心车辆作业组 |

**适用场景：** 部门名称本身就是作业单元名称（如保洁班组）。

#### 第二优先：部门+岗位组合匹配

| source_dept | source_position | target_unit_type | priority | 示例 |
|-------------|-----------------|------------------|----------|------|
| XX镇片区 | 司机 | collection_team | 90 | "宁城街道片区"+"司机" → 宁城街道收运车组 |
| XX镇片区 | 垃圾收运辅助工 | collection_team | 88 | "长官镇片区"+"垃圾收运辅助工" → 长官镇收运车组 |
| XX镇片区 | 中转站管理员 | transfer_station | 85 | "杜集镇片区"+"中转站管理员" → 杜集镇转运站 |

**适用场景：** 同一部门下不同岗位归属不同作业单元（如"片区"部门下司机归收运车组，中转站管理员归转运站）。

#### 第三优先：岗位推断

| 岗位关键词 | 推断类型 | 说明 |
|-----------|---------|------|
| 保洁 | cleaning_team | 保洁员归入人工作业单元 |
| 班长 | cleaning_team | 人工班长归入人工作业单元 |
| 司机 + 部门=车队 | center_vehicle_team | 车队司机归入中心车辆 |
| 司机 + 部门含片区 | collection_team | 片区司机归入收运车辆 |
| 中转站/转运站 | transfer_station | 中转站管理员归入转运站 |
| 收运辅助 | collection_team | 收运辅助工归入收运车辆 |

**适用场景：** 部门不在映射规则中，但岗位可以推断作业单元类型。

#### 第四优先：组织推断

按员工所属组织（org_unit_id）查找同类型的作业单元。仅当组织中只有1个该类型作业单元时才匹配。

**适用场景：** 前三级都不匹配时的兜底策略。

## 四、特殊岗位处理

### 4.1 人工片区长

人工片区长管理整个乡镇片区，不归属具体作业单元。

| source_dept | source_position | 处理方式 |
|-------------|-----------------|---------|
| XX镇片区 | 人工片区长 | operation_unit_id = NULL（不关联作业单元） |

**设计原因：** 片区长是管理岗，管理范围跨越多个作业单元，不归属单一作业单元。

### 4.2 司机岗位区分

| 部门 | 职位 | 目标岗位 | 作业单元类型 |
|------|------|---------|-------------|
| 车队 | 司机 | 垃圾转运车驾驶员 | center_vehicle_team |
| XX镇片区 | 司机 | 垃圾收运车驾驶员 | collection_team |

**区分逻辑：** 通过 `employee_position_mapping_rule.condition_dept` 字段实现条件匹配：
- `condition_dept = '车队'` → 垃圾转运车驾驶员
- `condition_dept = '片区'` → 垃圾收运车驾驶员

匹配时检查部门名是否包含 condition_dept 的值。

## 五、映射规则初始化数据

### 5.1 cleaning_team 规则（51条）

每个"XX镇X班"部门对应一条映射规则：
- source_dept = 班组名称（如"宁城街道一班"）
- source_position = NULL
- target_unit_id = 对应作业单元ID
- match_priority = 100

### 5.2 collection_team 规则（24条）

每个乡镇片区2条规则（司机+收运辅助工）：
- source_dept = "XX镇片区"
- source_position = "司机" / "垃圾收运辅助工"
- target_unit_id = "XX镇收运车组"ID
- match_priority = 90 / 88

### 5.3 transfer_station 规则（10条）

每个乡镇片区1条规则：
- source_dept = "XX镇片区"
- source_position = "中转站管理员"
- target_unit_id = "XX镇转运站"ID
- match_priority = 85

### 5.4 center_vehicle_team 规则（1条）

- source_dept = "车队"
- source_position = NULL
- target_unit_id = "中心车辆作业组"ID
- match_priority = 95

## 六、异常类型

### 6.1 新增异常类型

| 异常类型 | 说明 | 处理方式 |
|----------|------|---------|
| unknown_operation_unit | 无法匹配作业单元 | 进入 employee_import_pending |

### 6.2 异常处理流程

```
四级匹配全部失败
    ↓
标记 unknown_operation_unit 异常
    ↓
写入 employee_import_pending
    ↓
人工确认 → 选择正确作业单元 → 保存映射规则
    ↓
下次导入自动匹配
```

## 七、规则扩展机制

### 7.1 新增部门

当花名册中出现新的部门名称时：
1. 第一至第四级匹配全部失败
2. 进入 `unknown_operation_unit` 异常
3. 人工确认后，创建新作业单元并保存映射规则
4. 下次导入自动匹配

### 7.2 新增岗位

当花名册中出现新岗位时：
1. 岗位匹配可能成功（如果有别名规则）
2. 作业单元匹配通过岗位推断可能成功
3. 如果推断失败，进入异常流程

### 7.3 规则版本管理

支持通过 `remark` 字段记录规则版本和变更原因，便于追溯。
