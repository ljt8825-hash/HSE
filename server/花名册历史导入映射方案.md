## 4. 两套体系的“部门/岗位”识别应对策略（不强行统一）

- 老体系 A：部门=`所属乡镇`（如 `宁城街道`），岗位=`乡镇主管/管理员/收运车司机`。
- 新体系 B：部门=`所属部门`（如 `长官镇四班`），岗位=`乡镇保洁员/项目总经理/人事专员`。

同一身份证在 A→B 下岗位名必然不同（系体系改名，非真实离职）。**历史轨迹按各时期原岗位名存档，不做跨体系映射**（否则失真）。判断“是否变化”仅在同一体系内部比较。

## 5. 去重重放规则（即你提出的“稳定者跳过”的正规化）

按**时间升序**逐份处理，以**身份证**（新体系为主）／（身份证缺失时）**员工编码+姓名**为稳定键：

1. **首次出现** → 新增员工 + 写入一条任职（assignment，is_current=1）。
2. **再次出现且部门+岗位均未变** → **跳过不写新任职**，仅回填缺失基础字段（此步即“扫到相同身份证不用管”）。
3. **再次出现且部门或岗位已变** → 结束上一条任职（is_current=0），写新的任职（is_current=1），记录变迁。
4. 全部重放后，**最新一份的任职即为当前在职**。

效果：一人几十份快照只产生“任职变迁”若干条，稳定者不重复入库——正是你要的优化。

## 6. 离职与在职对账 + 时序推断

- 以 **2026.9.1 的 `离职` 表（106 人）** 为权威离职名单，写 `is_current=0` + 离职日期。
- 其余“曾在历史快照出现、但不在最新在职、也不在离职表”的人：标记 `is_current=0`，**离职日期由快照夹逼推断**。

### 快照夹逼推断（利用相邻快照的时间粒度，约为逐月）

| 事件 | 判定 | 记录时间 |
|------|------|----------|
| 岗位/部门变更 | 快照 N 与快照 N+1 中，该身份证的 部门/岗位 不同 | 变更区间 = (快照N日期, 快照N+1日期)；任职记录落在此区间 |
| 离职 | 快照 M 中仍在、快照 M+1 不再出现（且不在 2026.9.1 离职表/在职表） | 近似离职日期 = 快照 M+1 日期（上界） |
| 老→新体系岗位名切换 | 同一身份证在 A/B 两体系岗位名不同，但部门未变 | 视为“体系改名”，不按变更处理，仅记录体系切换点 |

> 误差 ≈ 两次快照间隔（通常约一个月），可接受作为历史任职/离职的近似时间。
