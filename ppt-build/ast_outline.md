# AST Outline — 人感大纲（Audience-State-Transfer）

> 核心理念：**PPT 不是信息容器，是观众状态迁移的载体。**
> 每一页都回答三个问题：观众为什么要在意（why-care）？他离开这页记住什么（记忆点）？怎么滑向下一页（转场）？

## 整体情绪曲线（Emotion Curve）
```
好奇/共鸣 ──▶ 期待/惊讶 ──▶ 代入/紧张 ──▶ 刺痛/共鸣(踩坑) ──▶ 豁然开朗 ──▶ 兴奋/实用 ──▶ 鼓舞/号召
  P1-P2       P3-P4        P5-P9          P10-P13           P14-P15       P16-P18       P19-P20
```
- 前半段用「真实起点很低」拉低预期、建立信任；
- 中段用「踩坑」制造刺痛共鸣（听众自我代入）；
- 后段用「方法论 ＋ 白嫖策略」把刺痛转化为可带走的武器；
- 结尾收束为一句话 ＋ 行动号召。

---

## P1 · 封面
- **why-care**：「一个月、0 设计、0 专职前端，AI 手搓出生产级系统」——反直觉，勾魂。
- **记忆点**：这不是 demo，是一套真在跑的 HSE 系统。
- **结构**：主标题 ＋ 副标题（实战复盘 / 经验可复制）＋ 时间跨度徽章（2026.06.21–07.24）＋ 分享场景标签。
- **钩子**：「如果告诉你，这套系统的前端几乎没我手写一行，你信吗？」
- **转场**：从「不信」滑向「那到底怎么发生的」→ P2。

## P2 · 为什么是 AI 手搓？
- **why-care**：你大概率也面临「要系统、但没人没钱没时间」——这不是个案。
- **记忆点**：资源为 0 时，AI 不是加速器，是唯一的脚手架。
- **结构**：左「业务痛点（HSE 要合规、要闭环、要移动现场）」／ 右「资源现实（无专职前端、无预算、1 个月）」对比。
- **钩子**：「公司要一套 HSE 系统，给的预算是：没有。给的人，是我。」
- **转场**：既然资源为 0，目标就得定得清醒 → P3。

## P3 · 目标：一套给一线 HSE 人员用的系统
- **why-care**：很多人用 AI 做出来的是玩具；这页先锁死「给谁用、解决什么」。
- **记忆点**：不是给领导看的报表，是给一线安全员每天用的工具。
- **结构**：一句话目标 ＋ 用户画像（项目公司 HSE 安全管理人员）＋ 3 条硬约束（合规闭环 / 移动现场 / 可解释）。
- **钩子**：「它得在扫马路的大爷手机上能用，不是在我 4K 屏上好看。」
- **转场**：目标定了，先看最后长什么样，再倒推怎么走 → P4。

## P4 · 成果速览：数字墙
- **why-care**：用硬数字证明「生产级」不是吹的，击碎 PPT 造车怀疑。
- **记忆点**：10 菜单 / ~45 页 / 59 接口 / 35 表 / 移动 6 模块 / 1 个月 / 4 个 AI 工具。
- **结构**：数字大字报（7 个关键数）＋ 一行来源注（数据来自 `当前系统功能地图.md`）。
- **钩子**：「这些数字，是一个月里 4 个 AI 工具轮班干出来的。」
- **转场**：数字很美，但路不是直线 → 进入四阶段时间线 P5。

## P5 · 一个月的四阶段时间线（总览）
- **why-care**：听众需要一张地图，否则后面细节会迷路。
- **记忆点**：四个阶段 = 四次「重新选路」，不是一条道走到黑。
- **结构**：横向时间轴 4 节点（看板期→HTML 期→Vben 初期→Vben 中期）＋ 每节点一个「主导工具 / 关键动作 / 一句话状态」。
- **钩子**：「注意看，每个节点我都推翻了上一点。」
- **转场**：逐个展开 → P6。

## P6 · 阶段一 · WorkBuddy 看板期（纯 HTML 原型）
- **why-care**：起点比你想的低——纯 HTML 看板，也能开始。
- **记忆点**：看板不是终点，是和 AI 对齐语言的第一块试验田。
- **结构**：左「产物」（`kanban-prototype.html`、`任务管理界面.html`、`DataEngine.js`、`navigation_routes.js`）／ 右「当时我怎么想」（先让 AI 把数据看板跑起来，验证需求）。
- **钩子**：「第一版连框架都没有，就是一堆 HTML ＋ 一个 DataEngine.js。」
- **转场**：HTML 越写越胖，撑不住了 → P7。

## P7 · 阶段二 · WorkBuddy HTML 巨型原型期（上框架决策）
- **why-care**：你也会遇到「原型膨胀」的拐点，看我怎么决策。
- **记忆点**：`objectives_module.js` 单文件 156KB —— 巨型原型是信号，不是成就。
- **结构**：证据墙（`objectives_module.js` 156KB、`hazard_module.js`、`traffic_2026_module.js`、`现场管理模块.js`）＋ 决策（`frontend-refactor-report-step1..5.md` 记录的 HTML→Vue 重构）。
- **钩子**：「一个 js 文件 156KB，AI 自己都快找不着北了。」
- **转场**：决定上 Vue，但直接造轮子踩了大坑 → P8。

## P8 · 阶段三 · VbenAdmin 初期：恢复官方基线（关键转折）
- **why-care**：这是全片最大转折点——承认自研走偏，回到成熟框架。
- **记忆点**：2026-07-14 我把整个前端「还原官方 Vben v5.7」，等于推倒重来。
- **结构**：转折事件（恢复官方基线报告）＋ 新分工模型初现（WorkBuddy 改错 / Trae 干活 / Grok 提示词）＋ 伏笔（偏离主线、没纳 Git 的代价）。
- **钩子**：「最贵的那行代码，是删掉的代码。」
- **转场**：框架定了，AI 角色继续进化 → P9。

## P9 · 阶段四 · VbenAdmin 中期（当前）：AI 进化为分析决策
- **why-care**：AI 不只是写代码了，开始替你做安全分析。
- **记忆点**：提示词从 Grok 演进到 ChatGPT，AI 进化为「分析 + 决策」层（`AI报告生成设计.md`、`HSE AI分析模型设计.md`）。
- **结构**：近期证据（2026-07-18~24 优化报告、Sprint5~11）＋ AI 能力升级（风险趋势/归因/钻取/AI 解释/改善建议）＋ 七维度评价 / L1–L5 成熟度。
- **钩子**：「到这阶段，AI 写的不是按钮，是安全结论。」
- **转场**：路讲完了，现在摊开我摔过的跤 → P10。

## P10 · 踩坑①：文件副本地狱
- **why-care**：你一定也干过「改不动就另存为 -v1.2」——看完会后背发凉。
- **记忆点**：`-v1.1 / -v1.2 / -v1.3` 副本成灾，目录堆成 `_backup_packages_*`、`_temp_clean/`、`backups/`、`.归档_*`。
- **结构**：真实副本清单（车辆/交通安全/考核/集团字典等成批 `-v1.x.md`）＋ 备份目录截图式罗列 ＋ 一句话根因（不敢删、怕丢、没有版本控制兜底）。
- **钩子**：「我电脑里有个 `交通安全风险管理设计-v1.3.md`，我自己都忘了哪个是最终版。」
- **转场**：副本还能忍，下一个坑是真会要命 → P11。

## P11 · 踩坑②：没纳入 Git，无法回退
- **why-care**：副本地狱的同源病——没有版本控制，推倒重来靠的是「手抖的勇气」。
- **记忆点**：铁证——`Vben_Admin_Restore_to_Official_Report.md` 第 14 行原文：「未纳入 Git 版本控制，无法通过 git reset 或 git checkout 直接回退」。
- **结构**：引用原文（高亮）＋ 后果（只能目录级覆盖官方版，赌备份没删）＋ 反差（如果有 Git，这一步本该是一条命令）。
- **钩子**：「那次『还原官方』，我不是在重构，是在赌命。」
- **转场**：还有更隐蔽的坑——你以为在进步，其实在绕圈 → P12。

## P12 · 踩坑③：自造轮子 / 偏离主线 ＋ 功能重复
- **why-care**：两个坑会悄悄吃掉你半个月，还不容易察觉。
- **记忆点**：① 自造轮子导致「与官方显著偏离」（同恢复报告）；② `2026-07-07_变更记录文档.md` 满篇 JSX / `bordered={false}` / `NSegmented 不存在` 等基础错误；③ 功能重复（`功能重复与合并分析报告.md`、`左侧栏重复功能分析.md`、2026-07-24 `业务归属待确认清单.md`）。
- **结构**：三宗罪并列 ＋ 各配真实文件证据 ＋ 代价（返工、菜单合并、归属扯皮）。
- **钩子**：「同一个功能，我做了三遍，还都以为自己是第一次做。」
- **转场**：把坑收个总账，提炼根因 → P13。

## P13 · 踩坑总账与根因
- **why-care**：单个坑你会忘，根因记住了才不再踩。
- **记忆点**：三个坑一个妈——**没有「可回退的安全网」（Git）＋ 没有「单一事实源」（文档/目录治理）**。
- **结构**：坑 → 根因映射表 ＋ 一条铁律（先建安全网，再让 AI 狂奔）＋ 给同行的免责提示。
- **钩子**：「AI 跑得越快，你越需要一个能拉住的缰绳。」
- **转场**：坑讲完，给武器——可复制方法论 → P14。

## P14 · 可复制方法论 I：AI 协作分工模型
- **why-care**：听众最想要的答案——到底怎么和多个 AI 配合不打架。
- **记忆点**：三角色模型 —— WorkBuddy 改错 ／ Trae 干活 ／ Grok·ChatGPT 出提示词。
- **结构**：角色卡（谁干啥、为什么这么分）＋ 协作流（提示词→干活→改错→再提示词）＋ 为何跨工具（各有所长、互补短板）。
- **钩子**：「别让一个 AI 又当爹又当妈，分工比选型重要。」
- **转场**：分工定了，提示词是怎么炼成的 → P15。

## P15 · 可复制方法论 II：提示词演进路线
- **why-care**：提示词不是天赋，是版本迭代出来的。
- **记忆点**：Grok 提示词 → ChatGPT 提示词，提示词本身也走「v1→vn」的演进（参见 `AI Prompt版本管理设计.md`）。
- **结构**：早期（Grok，重指令）→ 中期（ChatGPT，重上下文/角色/约束）＋ 三条可复用写法（给上下文、给约束、要可追溯）＋ 失败样本对照。
- **钩子**：「我最早的提示词，现在看像个发脾气的需求文档。」
- **转场**：方法有了，但额度是天花板 → 点题页 P16。

## P16 · 白嫖策略（点题页）
- **why-care**：免费额度是真实瓶颈，不解决后面全白搭。
- **记忆点**：双杠杆 —— **同一 AI 软件内多账号轮换免费额度** ＋ **跨不同 AI 软件（WorkBuddy / Trae / Grok / ChatGPT）切换分流**。
- **结构**：一句话点题 ＋ 双杠杆图示 ＋ 为什么有效（额度按账号/按软件重置，错峰即用）＋ 一句话警示（合规边界内玩，别碰 ToS 红线）。
- **钩子**：「一个月干完，我一分钱没花在模型订阅上——靠的是轮换，不是靠氪金。」
- **转场**：怎么落地，给清单 → P17。

## P17 · 白嫖策略实操清单
- **why-care**：光说策略不够，要能照着做。
- **记忆点**：轮换节奏表 ＋ 跨软件分流规则 ＋ 3 条风险边界。
- **结构**：① 同软件多账号轮换节奏（按额度周期错峰）；② 跨软件任务分流（编码类/提示词类/长上下文类各归位）；③ 风险（账号封禁、数据合规、上下文割裂的应对）。
- **钩子**：「轮换不是耍小聪明，是把『额度』当成可调度资源。」
- **转场**：所有方法收口成一张可带走的清单 → P18。

## P18 · 给同行的复制清单（行动 checklist）
- **why-care**：离场前最后一页实用物，决定他回去动不动手。
- **记忆点**：7 步复制法（从建 Git 安全网 → 选框架 → 定分工 → 养提示词 → 轮换额度 → 治理目录 → 闭环复盘）。
- **结构**：编号 checklist（每步一句怎么做 ＋ 对应本片页码）＋ 「明天就能做的前 3 步」高亮。
- **钩子**：「把这页拍下来，下周一开始第一步。」
- **转场**：收束情绪 → P19。

## P19 · 结语 ＋ CTA
- **why-care**：给听众一个「我也能开始」的信念。
- **记忆点**：一句话——「AI 手搓系统的本质，是把你从『写代码的人』变成『定方向的人』。」
- **结构**：情绪收束（回望四阶段 ＋ 踩坑变成资产）＋ CTA（① 先建 Git ② 选一个最小场景开搓 ③ 来交流你的踩坑）。
- **钩子**：「我踩的坑，就是你省下的一个月。」
- **转场**：资源指路 → P20。

## P20 · 附录 · 证据与致谢
- **why-care**：训练分享要经得起较真，给溯源。
- **记忆点**：所有数字 / 坑都有真实文件可查，不是编的。
- **结构**：关键证据文件索引（CHANGELOG、功能地图、恢复报告、真实截图路径）＋ 致谢（4 个 AI 工具）＋ 二维码位（可选）。
- **钩子**：「怀疑哪个数字，去翻那几个 md，都在硬盘里。」
- **转场**：结束。
