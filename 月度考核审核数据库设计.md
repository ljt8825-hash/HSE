## 二、新增表结构设计

### 2.1 扣分审核表 (`deduction_review`)

**用途**：记录每条扣分项的审核信息和状态流转。

```sql
CREATE TABLE IF NOT EXISTS deduction_review (
    id                  BIGSERIAL     PRIMARY KEY,
    deduction_id        BIGINT        NOT NULL,                    -- 关联扣分明细表ID
    object_id           BIGINT        NOT NULL,                    -- 关联考核对象表ID
    task_id             BIGINT        NOT NULL,                    -- 关联考核任务表ID
    review_status       VARCHAR(20)   NOT NULL DEFAULT 'pending',  -- 审核状态：pending/confirmed/adjusted/rejected/frozen
    suggested_score     NUMERIC(6,2),                               -- 系统建议扣分值
    confirmed_score     NUMERIC(6,2),                               -- 审核确认扣分值
    reviewer_id         BIGINT,                                     -- 审核人ID
    reviewer_name       VARCHAR(50),                                -- 审核人姓名
    review_time         TIMESTAMPTZ,                                -- 审核时间
    review_comment      TEXT,                                       -- 审核意见
    reject_reason       TEXT,                                       -- 驳回原因
    current_version     INT           DEFAULT 1,                   -- 当前版本号
    is_frozen           BOOLEAN       DEFAULT FALSE,               -- 是否已冻结
    frozen_at           TIMESTAMPTZ,                                -- 冻结时间
    created_at          TIMESTAMPTZ   NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ   NOT NULL DEFAULT NOW(),
    is_deleted          BOOLEAN       DEFAULT FALSE
);

-- 索引
CREATE INDEX IF NOT EXISTS idx_deduction_review_deduction 
    ON deduction_review (deduction_id);
CREATE INDEX IF NOT EXISTS idx_deduction_review_object 
    ON deduction_review (object_id);
CREATE INDEX IF NOT EXISTS idx_deduction_review_task 
    ON deduction_review (task_id);
CREATE INDEX IF NOT EXISTS idx_deduction_review_status 
    ON deduction_review (review_status);
```

**字段说明**：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| review_status | VARCHAR(20) | pending：待审核、confirmed：已确认、adjusted：已调整、rejected：已驳回、frozen：已冻结 |
| suggested_score | NUMERIC(6,2) | 系统自动计算的原始扣分建议值 |
| confirmed_score | NUMERIC(6,2) | 审核后的最终扣分值（如未调整则等于suggested_score） |
| current_version | INT | 指向当前生效的版本号，与版本记录表关联 |

### 2.2 扣分调整记录表 (`deduction_version_history`)

**用途**：记录扣分项的每次调整历史，禁止覆盖，支持完整追溯。

```sql
CREATE TABLE IF NOT EXISTS deduction_version_history (
    id                  BIGSERIAL     PRIMARY KEY,
    deduction_id        BIGINT        NOT NULL,                    -- 关联扣分明细表ID
    review_id           BIGINT        NOT NULL,                    -- 关联审核表ID
    version_no          INT           NOT NULL,                    -- 版本号（递增）
    old_score           NUMERIC(6,2),                               -- 原扣分值
    new_score           NUMERIC(6,2)   NOT NULL,                   -- 调整后扣分值
    operation_type      VARCHAR(30)   NOT NULL,                    -- 操作类型：CREATE/ADJUST/REJECT/APPEAL_ADJUST/ROLLBACK
    adjustment_reason   TEXT           NOT NULL,                   -- 调整原因（必填）
    adjusted_by         BIGINT        NOT NULL,                    -- 调整人ID
    adjusted_by_name    VARCHAR(50)   NOT NULL,                    -- 调整人姓名
    adjusted_at         TIMESTAMPTZ   NOT NULL DEFAULT NOW(),      -- 调整时间
    reviewed_by         BIGINT,                                     -- 审核人ID
    reviewed_by_name    VARCHAR(50),                                -- 审核人姓名
    reviewed_at         TIMESTAMPTZ,                                -- 审核时间
    related_event_id    BIGINT,                                     -- 关联事件ID（如申诉单ID）
    related_event_type  VARCHAR(30),                                -- 关联事件类型（APPEAL/RECTIFICATION等）
    is_current          BOOLEAN       DEFAULT FALSE,               -- 是否为当前版本
    created_at          TIMESTAMPTZ   NOT NULL DEFAULT NOW()
);

-- 索引
CREATE INDEX IF NOT EXISTS idx_deduction_version_deduction 
    ON deduction_version_history (deduction_id);
CREATE INDEX IF NOT EXISTS idx_deduction_version_review 
    ON deduction_version_history (review_id);
CREATE INDEX IF NOT EXISTS idx_deduction_version_no 
    ON deduction_version_history (deduction_id, version_no);
CREATE INDEX IF NOT EXISTS idx_deduction_version_current 
    ON deduction_version_history (deduction_id) WHERE is_current = TRUE;

-- 唯一约束：同一扣分项的版本号不可重复
CREATE UNIQUE INDEX IF NOT EXISTS idx_deduction_version_unique 
    ON deduction_version_history (deduction_id, version_no);
```

**字段说明**：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| version_no | INT | 版本号，同一扣分项下递增，从1开始 |
| old_score | NUMERIC(6,2) | 调整前的扣分值（版本1时为NULL） |
| new_score | NUMERIC(6,2) | 调整后的扣分值 |
| operation_type | VARCHAR(30) | CREATE：系统创建、ADJUST：人工调整、REJECT：驳回取消、APPEAL_ADJUST：申诉调整、ROLLBACK：版本回滚 |
| is_current | BOOLEAN | 标识当前生效版本，同一扣分项仅1条为TRUE |

### 2.3 版本记录表 (`assessment_version_snapshot`)

**用途**：记录考核对象整体得分的版本快照，用于考核结果的版本管理。

```sql
CREATE TABLE IF NOT EXISTS assessment_version_snapshot (
    id                  BIGSERIAL     PRIMARY KEY,
    object_id           BIGINT        NOT NULL,                    -- 关联考核对象表ID
    task_id             BIGINT        NOT NULL,                    -- 关联考核任务表ID
    version_no          INT           NOT NULL,                    -- 得分版本号
    score_auto          NUMERIC(6,2),                               -- 自动计算得分
    score_manual        NUMERIC(6,2),                               -- 人工调整得分
    score_bonus         NUMERIC(6,2),                               -- 加分项得分
    score_total         NUMERIC(6,2)   NOT NULL,                   -- 总得分
    grade               VARCHAR(5),                                 -- 等级
    rank_no             INT,                                        -- 排名
    snapshot_reason     VARCHAR(200),                               -- 快照原因（如"审核完成"、"申诉调整"）
    created_by          BIGINT        NOT NULL,                    -- 操作人ID
    created_by_name     VARCHAR(50)   NOT NULL,                    -- 操作人姓名
    created_at          TIMESTAMPTZ   NOT NULL DEFAULT NOW(),
    is_current          BOOLEAN       DEFAULT FALSE
);

-- 索引
CREATE INDEX IF NOT EXISTS idx_version_snapshot_object 
    ON assessment_version_snapshot (object_id);
CREATE INDEX IF NOT EXISTS idx_version_snapshot_task 
    ON assessment_version_snapshot (task_id);
CREATE INDEX IF NOT EXISTS idx_version_snapshot_current 
    ON assessment_version_snapshot (object_id) WHERE is_current = TRUE;
```

### 2.4 操作日志表 (`operation_log`)

**用途**：记录所有权限操作的详细日志，满足审计需求。

```sql
CREATE TABLE IF NOT EXISTS operation_log (
    id                  BIGSERIAL     PRIMARY KEY,
    module              VARCHAR(30)   NOT NULL DEFAULT 'assessment', -- 功能模块
    operation_type      VARCHAR(30)   NOT NULL,                    -- 操作类型：VIEW/MODIFY/REVIEW/FREEZE/EXPORT/IMPORT/CONFIG
    target_type         VARCHAR(30),                                -- 操作对象类型：TASK/OBJECT/DEDUCTION/RESULT
    target_id           BIGINT,                                     -- 操作对象ID
    target_desc         VARCHAR(200),                               -- 操作对象描述
    operator_id         BIGINT        NOT NULL,                    -- 操作人ID
    operator_name       VARCHAR(50)   NOT NULL,                    -- 操作人姓名
    operator_role       VARCHAR(30),                                -- 操作人角色
    operation_detail    JSONB,                                      -- 操作详情（变更前后值等）
    operation_reason    TEXT,                                       -- 操作原因
    ip_address          VARCHAR(50),                                -- 操作IP
    user_agent          VARCHAR(200),                               -- 用户代理
    operation_time      TIMESTAMPTZ   NOT NULL DEFAULT NOW()
);

-- 索引
CREATE INDEX IF NOT EXISTS idx_operation_log_operator 
    ON operation_log (operator_id);
CREATE INDEX IF NOT EXISTS idx_operation_log_type 
    ON operation_log (operation_type);
CREATE INDEX IF NOT EXISTS idx_operation_log_target 
    ON operation_log (target_type, target_id);
CREATE INDEX IF NOT EXISTS idx_operation_log_time 
    ON operation_log (operation_time);
```

**operation_detail JSON结构示例**：

```json
{
  "field": "confirmed_score",
  "old_value": 5.00,
  "new_value": 2.00,
  "deduction_id": 12345,
```

## 五、数据流转与版本管理流程

### 5.1 扣分数据流转

```
1. 系统自动计算
   → assessment_deduction: 插入扣分记录（source_type=auto, review_status=pending）
   → deduction_review: 插入审核记录（review_status=pending, suggested_score=X）
   → deduction_version_history: 插入v1（operation_type=CREATE, new_score=X）

2. 人工审核确认
   → deduction_review: 更新 review_status=confirmed, confirmed_score=X
   → deduction_version_history: 无新版本（确认不改值）

3. 人工审核调整
   → deduction_review: 更新 review_status=adjusted, confirmed_score=Y
   → deduction_version_history: 插入v2（operation_type=ADJUST, old_score=X, new_score=Y）
   → 更新v1的is_current=FALSE, v2的is_current=TRUE

4. 申诉调整
   → deduction_review: 更新 review_status=adjusted, confirmed_score=Z
   → deduction_version_history: 插入v3（operation_type=APPEAL_ADJUST）
   → 更新v2的is_current=FALSE, v3的is_current=TRUE

5. 结果冻结
   → deduction_review: 更新 review_status=frozen, is_frozen=TRUE
   → assessment_object: 更新 review_status=frozen
   → assessment_result: 插入最终结果（frozen_by=操作人）
   → operation_log: 记录冻结操作
```

### 5.2 得分版本快照

每次扣分调整导致得分变化时，生成得分快照：

```
考核对象张三的得分版本历史：
├── v1: 总分72.0（系统初始计算）           → 历史版本
├── v2: 总分75.0（扣分调整后重新计算）       → 历史版本
└── v3: 总分78.0（申诉调整后重新计算）       → 当前版本 ✅
```

## 六、性能优化建议

| 优化项 | 方案 | 预期效果 |
| :--- | :--- | :--- |
| 当前版本查询 | deduction_version_history表对`(deduction_id) WHERE is_current=TRUE`建部分索引 | 快速定位当前版本 |
| 审核列表查询 | deduction_review表对`(task_id, review_status)`建复合索引 | 加速待审核列表查询 |
| 日志查询 | operation_log按时间分区（月度分区） | 历史日志查询性能提升 |
| 版本历史归档 | 超过1年的version_history数据迁移至归档表 | 减少主表数据量 |
| 批量审核 | 支持批量更新deduction_review状态 | 提升审核效率 |

## 七、数据安全

### 7.1 数据保护

| 安全项 | 措施 |
| :--- | :--- |
| **版本不可篡改** | deduction_version_history表仅允许INSERT，禁止UPDATE和DELETE |
| **日志不可删除** | operation_log表仅允许INSERT，禁止UPDATE和DELETE |
| **冻结数据保护** | 冻结后的数据通过应用层和数据库触发器双重保护 |
| **审计追溯** | 所有变更均可通过版本历史和操作日志完整追溯 |

### 7.2 数据库触发器示例

```sql
-- 禁止修改已冻结的扣分审核记录
CREATE OR REPLACE FUNCTION prevent_frozen_update()
RETURNS TRIGGER AS $$
BEGIN
    IF OLD.is_frozen = TRUE AND NEW.is_frozen = TRUE THEN
        RAISE EXCEPTION '已冻结的审核记录不可修改';
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_prevent_frozen_update
    BEFORE UPDATE ON deduction_review
    FOR EACH ROW
    EXECUTE FUNCTION prevent_frozen_update();
```
