扣分调整方案设计 — 规则层 × 明细层

解决"对某个人 / 某件事 / 某时期调整扣分权重"的多变需求。采用规则层（批量/政策性）+ 明细层（单条/个案式）两层模型，并明确"开关 / 0 值 / 缩放因子"各自职责。

适用范围 月度自动考核扣分 衔接 assessmentScoringEngine / hse_assessment_deduction 日期 2026-08-27

1结论速览

规则层 · 政策性批量
  • 新表 hse_assessment_metric_rule
  • 处理 "事件×对象×时期" 权重
  • 用 scale_factor 加重/减轻
  • 用 active 开关结构性停用
  • 评审后可回滚、可审计
明细层 · 个案单条
  • 现有 hse_assessment_deduction
  • 用 confirmed_score 修正单条
  • 置 0 表示"本条豁免"
  • 冻结后禁止改动（已有保护）
  • 需修复"审核覆盖人工"隐患
对照 · 开关 vs 0 值
  • 结构性问题 → active 开关
  • 加分减分力度 → scale_factor
  • 个案一条别扣 → confirmed=0
  • 三者并行，互不替代
  • 0 不丢语义：配合 deduction_source

3规则层：hse_assessment_metric_rule

列名类型说明
idBIGSERIALPK
rule_nameVARCHAR(100)规则名称
metric_codeVARCHAR(50)命中的指标
object_typeVARCHAR(20)all / employee / grid_level / township / department
object_valueVARCHAR(100)绑定的对象值（员工ID/等级/乡镇）
valid_from / toDATE生效时期
scale_factorNUMERIC(4,2)0 豁免 / <1 减轻 / 1 默认 / >1 加重

activeBOOL开关：FALSE 即结构性停用
remark / auditTEXT / JSONB备注、审计信息（建/改人·时间·版本）

关键语义

把"加权重"固化为 scale_factor 而非改写引擎梯度——原指标 rule_config 保持不动，规则叠加上去，可随时启停、永不破坏基线。

-- 例：2026年9月 火灾隐患整改 加3倍重量 INSERT INTO hse_assessment_metric_rule (rule_name, metric_code, object_type, object_value, valid_from, valid_to, scale_factor, priority, active) VALUES ('Q3 火灾高发期 隐患加重', 'HSE-KPI-HZD-002', 'all', NULL, '2026-09-01','2026-09-30', 2.0, 10, TRUE);
-- 例：某员工当月起 WFH/网格豁免（结构性停） VALUES ('张某 产假网格豁免','HSE-KPI-GRD-001', 'employee','E1234','2026-09-01','2026-12-31', 0, 20, TRUE);

4命中优先级（同一对象多条规则时）

  • 1employee 精确绑定（object_type=employee，object_value=该员工ID）最优先
  • 2其次 grid_level 等级（网格长/等级）
  • 3再 township / department 组织维度
  • 4最后 all 全体；同层内再按 priority 大的生效
只取优先级最高的一条生效（不叠加），语义清晰可预期。若需"基准规则+例外"叠加，后续可扩展为 multiply 模式，本期不做。

5明细层：修正现有 deduction 流程

现状
  • 审核通过：confirmed = suggested
  • adjust 改 confirmed（写版本表）
  • 但审核会覆盖人工调整值 ✕
  • rule_config 未消费 ✕
调整后
  • 审核通过：confirmed = COALESCE(confirmed, suggested)
  • 仅当人工未调整时才回填 suggested
  • rule_config 参与 suggested 计算
  • 删除用 is_deleted 软删（防审计断裂）
语义约定
  • suggested：规则/引擎建议值（自动）
  • confirmed=0：本条豁免但仍留痕
  • confirmed>0：核定的扣分
  • rejected：不算入分（现有逻辑）
必须处理的修复：审核通过接口将 confirmed_score = suggested_score 改为
confirmed_score = COALESCE(confirmed_score, suggested_score)， 否则规则层与人工调整都会在审核通过时被静默覆盖，审计分失真。该改动属现有考核链路修复，建议单独立项回归测试。
