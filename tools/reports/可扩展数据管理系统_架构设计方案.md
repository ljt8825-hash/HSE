## 1. 现状诊断

### 1.1 当前数据流

```
Excel 源文件 (9个目录, 62个, ~390MB)
    ↓ Python 提取脚本 (18个, 硬编码绝对路径)
JS 数据文件 (training_data.js 等 8个, ~2.1MB)
    ↓ <script> 标签注入全局变量
前端渲染 (index.html 读取全局常量)
    ↓
localStorage (三层增量模式: {added, updated, deleted})
```

### 1.2 痛点

| 问题 | 影响 |
|------|------|
| 数据散落在 8 个全局 JS 变量中 | 无法跨模块交叉分析 |
| 无统一查询接口 | 每个模块各写一套 filter/map/reduce |
| 无索引机制 | 遍历全量数组，数据量增长时线性变慢 |
| localStorage 三层增量脆弱 | 增量冲突、数据不一致 |
| 无时间序列分析 | 同比环比靠手算 |
| 无备份/恢复机制 | 数据丢失无法回滚 |

### 1.3 目标

建立一个**轻量但规范**的数据访问层，类似前端版的 SQLite — 有 Schema、有索引、有查询、有持久化，同时**不引入外部依赖**（纯 vanilla JS，<15KB），可直接嵌入现有 HTML 单文件系统。

## 2. 整体架构

```
                    ┌───────────────────────────┐
                    │      DataEngine (入口)     │
                    │  defineCollection()        │
                    │  collection('name')        │
                    │  analysis.yoy() / .mom()   │
                    │  exportBackup()            │
                    └─────┬──────────┬──────────┘
                          │          │
        ┌─────────────────┘          └──────────────────┐
        ▼                                                ▼
┌───────────────┐                              ┌─────────────────┐
│   DataStore   │◄────── 读写 ──────►           │  IndexManager   │
│               │                              │                 │
│ Collection[n] │   每 Collection 有 N 个索引    │  B-tree 单字段   │
│ ├ _records[]  │◄───── 自动同步 ─────►         │  Hash  主键      │
│ ├ _pkIndex    │                              │  Composite 复合  │
│ ├ dimensions  │                              │                 │
│ └ metrics     │                              │ CRUD: create /   │
│               │                              │  lookup / range  │
│ 变更监听 →     │                              │  / drop / list   │
│ indexManager  │                              │  / rebuild        │
└──────┬────────┘                              └─────────────────┘
       │
       ▼
┌─────────────────┐      ┌──────────────────┐
│  Persistence    │      │  AnalysisEngine  │
│                 │      │                  │
│ localStorage    │      │ yoy()  同比      │
│ 版本化快照 ×5   │      │ mom()  环比      │
│ 自动保存 30s    │      │ timeseries()     │
│ 导出/导入 JSON  │      │ crossSection()   │
│ 损坏自动恢复    │      │                  │
└─────────────────┘      └──────────────────┘
```

**四个子系统独立但协作：**

- **Collection** 变更时通知 IndexManager 同步索引
- IndexManager 对 Collection 完全透明 — 查询时无缝加速
- Persistence 在 Collection 变更时标记脏数据，定时落盘
- Analysis 只读地访问 Collection + IndexManager

## Part A: 数据结构设计

### A.1 统一记录模型

每一条数据都是带有 `dimensions`（维度/外键）和 `metrics`（度量/数值）的记录：

```js
// Schema 定义 (以 HSE 培训模块为例)
{
  name: 'training',                      // 集合名
  primaryKey: 'id',                      // 主键字段 (自动生成)
  dimensions: ['month', 'group', 'name'], // 维度: 用于分组/过滤/索引
  metrics:    ['score', 'deduction'],     // 度量: 数值型, 用于聚合
  timeField:  'month',                    // 时间维度 (用于时序分析)
  defaults: { score: 100, deduction: 0 }, // 默认值
  autoIndex: true                         // 自动为维度+时间建索引
}
```

### A.2 记录实例

```js
// 培训考核记录
{
  id: "r_m5x3k2a_7f8g1h",     // 自动生成主键
  month: "5月",                // 维度 → 自动建 idx_month 索引
  group: "安环管理部",          // 维度 → idx_group
  name: "刘金涛",              // 维度 → idx_name
  score: 92,                   // 度量 → 可用于 sum/avg
  deduction: 8,                // 度量
  status: "正常",
  createdAt: "2026-05-15T10:00:00.000Z"
}
```

### A.3 集合设计原则

| 原则 | 说明 |
|------|------|
| **维度外显** | 把用于分组/过滤的字段声明为 `dimensions`，系统自动建索引 |
| **度量可聚合** | 把数值型字段声明为 `metrics`，分析引擎可对其做 sum/avg/max/min |
| **时间必标** | 每个集合必须指定 `timeField`，这是同比环比的前提 |
| **默认值兜底** | `defaults` 确保插入不完整记录时不产生 undefined |

### A.4 项目全部集合一览

```
training    — HSE 教育培训 (roster + monthly assessments + deductions)
accident    — 事故管理记录
emergency   — 应急演练记录
violation   — 三违查处记录
personnel   — 人员保险合规数据
```

## Part B: 索引管理引擎

### B.1 索引类型

```js
// 1. Hash 索引 — 精确匹配 (最适合主键 / 唯一字段)
indexManager.create(coll, {
  name: 'pk_idx',
  fields: ['id'],
  type: 'hash',
  unique: true
});

// 2. B-tree 索引 — 排序 + 范围查询 (适合时间/分数等有序维度)
indexManager.create(coll, {
  name: 'idx_month',
  fields: ['month'],
  type: 'btree'
});

// 3. Composite 复合索引 — 多字段组合查询
indexManager.create(coll, {
  name: 'idx_dim_time',
  fields: ['group', 'month'],  // 先 group 后 month
  type: 'composite'
});
```

### B.2 索引 CRUD 操作

| 操作 | API | 说明 |
|------|-----|------|
| **创建** | `indexManager.create(coll, { name, fields, type, unique })` | 扫描全量数据建索引 |
| **查询** | `indexManager.lookup(coll, 'idx_name', '刘金涛')` | 精确匹配 → O(1) |
| **范围** | `indexManager.range(coll, 'idx_dim_time', '安环管理部')` | 前缀匹配 → O(k) |
| **列表** | `indexManager.list('training')` | 返回索引元数据 |
| **删除** | `indexManager.drop(coll, 'idx_name')` | 移除索引 |
| **重建** | `indexManager.rebuild(coll)` | 全量重扫 |

### B.3 索引自动同步

```js
// Collection 内部变更时自动通知 IndexManager:
// insert → onInsert()    将新记录的 key→pk 写入所有索引
// update → onUpdate()    先删除旧key再插入新key
// remove → onRemove()    从所有索引中清除

// 监听绑定在 Collection 构造时就完成，对上层完全透明
collection.onChange((event, payload) => {
  if (event === 'insert')  indexManager.onInsert(collection, payload[0]);
  if (event === 'remove')  indexManager.onRemove(collection, payload);
  if (event === 'update')  indexManager.onUpdate(collection, payload.old, payload.new);
});
```

### B.4 索引选择策略

```
查询场景                          推荐索引
───────────────────────────────────────────────────
按主键查单条 (getById)            Hash, fields=['id']
按时间过滤 (month='5月')          B-tree, fields=['month']
按乡镇+时间 (group='安环管理部'    Composite, fields=['group','month']
  AND month='5月')
按状态过滤 (status='open')        B-tree, fields=['status'] 或 Partial
全表聚合 (sum all)                无需额外索引 (走主存储)
```

### B.5 性能对比

```
操作          无索引        有 Hash 索引      有 B-tree 索引
─────────────────────────────────────────────────────────
精确查找      O(n) → 遍历    O(1) → Map.get    O(log n) → 二分
范围查找      O(n) → 遍历    —                  O(k+log n)
前缀匹配      O(n) → 遍历    —                  O(k)
插入          O(1) → push   O(1) → Map.set     O(log n)
```

## Part C: 数据持久化机制

### C.1 存储策略

```
localStorage key 结构:

hse_training              ← 当前版本 (完整数据)
hse_training_snapshot_1719740000000   ← 快照 1
hse_training_snapshot_1719653600000   ← 快照 2
hse_training_snapshot_1719567200000   ← 快照 3
hse_training_snapshot_1719480800000   ← 快照 4
hse_training_snapshot_1719394400000   ← 快照 5 (最旧，溢出时删除)
```

### C.2 保存格式

```json
{
  "version": 1,
  "savedAt": "2026-06-30T10:30:00.000Z",
  "collectionName": "training",
  "schema": {
    "primaryKey": "id",
    "dimensions": ["month", "group", "name"],
    "metrics": ["score", "deduction"],
    "timeField": "month"
  },
  "indexes": [
    { "name": "idx_month", "fields": ["month"], "type": "btree", "unique": false },
    { "name": "idx_group", "fields": ["group"], "type": "btree", "unique": false }
  ],
  "records": [ /* 全部记录 */ ],
  "recordCount": 520
}
```

**关键设计：** 每次 save 不仅存数据，还存 Schema 和索引定义 → 下次 load 时可完整恢复整个集合状态。

### C.3 持久化生命周期

```
初始化
  │
  ├─① 从 JS 数据文件创建 Collection (initialData)
  ├─② 尝试从 localStorage 恢复 (覆盖初始数据)
  │     └─ 若数据损坏 → 自动从最新快照恢复
  ├─③ 重建索引
  └─④ 开启自动保存 (30s 间隔，仅在脏数据时写入)
       │
       ▼
  运行时变更 (insert/update/remove)
  ├─ collection 变更 → markDirty()
  └─ 30s 定时器 → 检查脏标记 → save()
       │
       ▼
  save() 时:
  ├─ 当前数据 → snapshot (最多保留 5 个)
  └─ 当前数据 → 主存储
```

### C.4 备份与恢复

```js
// 导出完整备份 (下载 JSON 文件)
HSE.engine.exportBackup();

// 从 JSON 文件导入
HSE.engine.importBackup(jsonData);

// 查看快照列表
HSE.engine.listSnapshots('training');
// → [{ key:'hse_training_snapshot_...', timestamp:'2026-06-29T...' }, ...]

// 从指定快照恢复
HSE.engine.persistence.restore('training', 'hse_training_snapshot_1719740000000');
```

### C.5 与现有三层增量模式对比

| 维度 | 现有三层增量 | DataEngine 持久化 |
|------|-------------|-------------------|
| 存储结构 | `{added, updated, deleted}` 三个子对象 | 完整记录数组 + 版本号 |
| 合并逻辑 | 每次加载都要 `_mergeData()` | 直接读取即用 |
| 数据一致性 | 增量冲突风险（editKey 重复） | 主键保证唯一 |
| 可恢复性 | 无法回滚 | 5 个快照 + 导出备份 |
| 存储大小 | 3 份数据冗余 | 1 份数据 (快照独立) |

## Part D: 同比环比分析算法

### D.1 同比 (Year-over-Year) — `yoy()`

**定义：** 比较当前周期与**去年同一周期**的指标变化。

```
yoy = (currentValue - previousValue) / previousValue × 100%
```

**算法流程：**

```
输入: collectionName='accident', metric='count', period='6月'
  │
  ├─① 解析周期: period='6月' → current={year:2026, month:'6月'}
  │                           previous={year:2025, month:'6月'}
  │
  ├─② 过滤当前数据: 遍历 records，匹配 month 包含 '2026' 和 '6月'
  │     → currRecords = [ {month:'2026年6月', count:3}, ... ]
  │
  ├─③ 过滤去年同期: 同上但 year=2025
  │     → prevRecords = [ {month:'2025年6月', count:5}, ... ]
  │
  ├─④ 聚合: aggFn='sum' → currentValue=3, previousValue=5
  │
  └─⑤ 计算: yoy = ((3-5)/5)*100 = -40.0%  (同比下降)
```

**返回格式：**

```json
{
  "period": "2026年6月",
  "compareWith": "2025年6月",
  "current": 3,
  "previous": 5,
  "yoy": "-40.0",
  "isGrowth": false,
  "recordCount": 3,
  "prevRecordCount": 5
}
```

### D.2 环比 (Month-over-Month) — `mom()`

**定义：** 比较当前周期与**上一周期**的指标变化。

```
mom = (currentValue - prevPeriodValue) / prevPeriodValue × 100%
```

**周期计算逻辑：**

| 模式 | 当前 | 上一周期 |
|------|------|---------|
| monthly | 2026年6月 | 2026年5月 |
| monthly | 2026年1月 | 2025年12月 (跨年) |
| quarterly | 2026年Q2 | 2026年Q1 |
| quarterly | 2026年Q1 | 2025年Q4 (跨年) |

### D.3 时间序列 — `timeseries()`

**定义：** 返回完整的月度趋势数据，包含每个月的值和同比/环比。

```
输入: years=[2026], metric='score', aggFn='avg'
  │
  └─ 遍历 1月→12月:
       ├─ 计算本月 avg(score)
       ├─ 计算去年同月 avg(score) → yoy
       └─ 计算上月 avg(score)     → mom

输出:
[
  { month:'2026年1月', value:88.5, yoy: 3.2, mom: null,  count:47 },
  { month:'2026年2月', value:86.2, yoy:-1.5, mom:-2.6,   count:45 },
  ...
]
```

### D.4 交叉分析 — `crossSection()`

**定义：** 按某个维度分组，计算每组在指定周期的同比。

```
crossSection('accident', 'count', 'township', { period:'6月' })

输出:
[
  { dimension:'安环管理部', current:0, previous:1, yoy:-100, isGrowth:false },
  { dimension:'大曹镇',     current:2, previous:1, yoy: 100, isGrowth:true  },
  { dimension:'保店镇',     current:1, previous:1, yoy:   0, isGrowth:false },
  ...
]
```

### D.5 算法特点

| 特性 | 实现方式 |
|------|---------|
| **支持嵌套路径** | `metric='score.total'` 自动解析 `.` 分隔的路径 |
| **弹性周期解析** | `period='6月'` / `{year:2026, month:'6月'}` / 不传=当前月 |
| **索引加速** | 过滤阶段走 `idx_time` + `idx_dim_time` 索引，非全表扫描 |
| **零除保护** | previousValue=0 时返回 `'+∞'` 或 `0.0` |
| **跨年处理** | 1月环比自动找去年12月 |

## 7. 现有系统迁移方案

### 7.1 三步迁移

```
Step 1 — 引入引擎
  在 index.html 原有的 data.js 文件后添加:
  <script src="DataEngine.js"></script>
  <script src="DataEngine_adapter.js"></script>

Step 2 — 初始化 (替代 localStorage 三层增量)
  // 原来: loadFromLocalStorage() + mergeData()
  // 改为:
  const engine = await HSE.initEngine();

Step 3 — 模块逐个迁移
  第1周: 培训模块 → engine.collection('training')
  第2周: 事故模块 → engine.collection('accident')
  第3周: 三违+应急+保险
  并行运行1个月，确认稳定后删除旧 localStorage 键
```

### 7.2 兼容性设计

- **Adapter 自动提取**现有全局变量 `TRAINING_DATA`、`EMERGENCY_STATS` 等转为统一 Record 格式
- **旧代码不受影响** — 原有的 `TRAINING_DATA` 全局变量依然存在，渲染逻辑不变
- **渐进式替换** — 可以一个模块一个模块地切到新 API

### 7.3 适配器数据映射

```
现有数据源                          → DataEngine 集合
────────────────────────────────────────────────────
TRAINING_DATA (training_data.js)    → 'training'
  .roster[]                          → Record[] (recordType:'roster')
  .months[month][group][]            → Record[] (recordType:'assessment')
  .deductionDetails[month][group][]  → Record[] (recordType:'deduction_detail')

ACCIDENT_DATA (内联)                → 'accident'
  .records[]                         → Record[]

EMERGENCY_STATS (emergency_data.js) → 'emergency'
  .records[]                         → Record[]

SANWEI_DATA (sanwei_data.js)        → 'violation'
  .records[]                         → Record[]

PERSONNEL_INSURANCE_DATA            → 'personnel'
  .records[] / .summary{}            → Record[]
```

## 8. 使用示例

### 8.1 基础 CRUD

```js
const engine = await HSE.initEngine();
const training = engine.collection('training');

// 插入
training.insert({ month: '7月', group: '安环管理部', name: '新员工', score: 95 });

// 查询 — 走索引 idx_group
const results = training.find({ group: '安环管理部' });

// 更新 — 走主键索引
training.update('r_m5x3k2a_7f8g1h', { score: 98 });

// 聚合 — 各小组平均分
training.aggregate('group', 'score', 'avg');
// → [{ key:'安环管理部', value:91.5, count:12 }, ...]
```

### 8.2 索引操作

```js
const idx = engine.indexManager;

// 查看所有索引
idx.list('training');
// → [{ name:'idx_month', fields:['month'], type:'btree', size:520 }, ...]

// 精确查找 — O(1)
idx.lookup(training, 'pk_idx', 'r_m5x3k2a_7f8g1h');

// 前缀范围 — 找安环管理部所有记录
idx.range(training, 'idx_dim_time', '安环管理部');

// 新增自定义索引
idx.create(training, { name: 'idx_status', fields: ['status'], type: 'btree' });

// 删除索引
idx.drop(training, 'idx_status');
```

### 8.3 同比环比

```js
// 培训模块 — 6月考核总分与去年6月对比
HSE.yoy('training', 'score', { period: '6月' });
// → { current: 1256, previous: 1180, yoy: '6.4', isGrowth: true }

// 事故模块 — 各乡镇事故数同比排行榜
HSE.crossSection('accident', 'count', 'township', { period: '6月' });

// 三违模块 — 本月与上月环比
HSE.mom('violation', 'count', { period: { year: 2026, month: '6月' } });

// 全年趋势 — 培训分数逐月变化 (带同比+环比)
HSE.timeseries('training', 'score', { years: [2026], aggFn: 'avg' });
// → [{ month:'2026年1月', value:88.5, yoy:3.2, mom:null }, ...]
```

### 8.4 备份恢复

```js
// 每天下班前导出一份
HSE.engine.exportBackup();  // 下载 data_backup_2026-06-30.json

// 数据出问题 → 查看快照
HSE.engine.listSnapshots('training');

// 恢复
HSE.engine.importBackup(jsonData);
```

## 9. 实施建议

### 9.1 优先级排序

| 优先级 | 任务 | 工时 | 收益 |
|--------|------|:---:|------|
| **P0** | 引入 DataEngine.js → 在培训模块试点 | 2h | 验证可行性 |
| **P1** | 培训模块切到新 API (CRUD + 聚合) | 3h | 告别 N+1 遍历 |
| **P1** | 事故/三违模块迁移 | 3h | 跨模块分析 |
| **P2** | 仪表盘增加同比环比 KPI 卡片 | 2h | 数据洞察 |
| **P2** | 制定数据更新 SOP → 自动化脚本 | 4h | 一键更新 |
| **P3** | 全模块迁移完成，清理旧代码 | 4h | 技术债清零 |

### 9.2 风险控制

- **双写过渡期**: 新引擎写入的同时保留旧 localStorage 写入，运行 2 周无问题再切
- **回滚机制**: 5 个快照 + 导出备份，出问题秒级回滚
- **渐进迁移**: 不需要一次性切全部模块，可以一个模块一个模块来

## 附录: 为什么不用 SQLite / IndexedDB?

| 方案 | 优势 | 劣势 |
|------|------|------|
| SQLite (WASM) | 完整 SQL | 10MB+ WASM 文件, 异步 API |
| IndexedDB | 浏览器原生, 大容量 | API 反人类, 无 SQL, 难调试 |
| **DataEngine** | <15KB, 同步 API, 零依赖, 可嵌入单文件 | 内存上限, 无事务 |

对于本项目 (<1万条记录, 每月更新) 的场景，DataEngine 的方案完全够用，胜在简洁、可控、好调试。
