## 二、核心问题诊断

### 🔴 P0 — 严重问题

#### 问题1：数据源极度分散，无统一入口

原始 Excel 文件散落在 **9 个不同目录**中，每个模块自行管理：

| 模块 | Excel 存放位置 | 文件数 |
|------|:---|:---:|
| HSE教育培训 | `HSE教育培训/` (按月分目录) | 15 |
| 保险及人员管理 | `保险及人员管理/人员保险/` `人员优化/` `车辆保险/` | 6 |
| 规章制度 | `规章制度/` `规章制度/网格化管理/` `规章制度/新建文件夹/` | 10 |
| 目标职责 | `目标职责/安全费用预算及使用/` | 1 |
| 事故管理 | `事故管理/` | 5 |
| 三违管理 | `三违管理/` + 根目录 | 5 |
| 现场管理 | `现场管理/` | 3 |
| 风险分级管控 | `风险分级管控/` | 1 |
| 隐患排查治理 | `隐患排查治理/` | 2 |

**后果**：每当需要更新一项数据，必须知道对应模块的源文件在哪里、用什么脚本处理。

#### 问题2：Python 提取脚本硬编码绝对路径

```python
# extract_training_data.py 第10行
BASE = r"C:\Users\36526\Desktop\新安全看板 - 副本\HSE教育培训"
OUTPUT = r"C:\Users\36526\Desktop\新安全看板 - 副本\安全管理系统\training_data.json"
```

**后果**：换电脑或换用户后所有脚本全部失效，必须逐一手动修改路径。

#### 问题3：超大 Excel 文件拖慢项目

| 文件 | 大小 | 问题 |
|------|------|------|
| `隐患排查治理/6月安全生产隐患排查登记表.xlsx` | **145 MB** | 可能含大量嵌入图片/冗余格式 |
| `三违管理/拍照巡检 AI 识别.xlsx` | **72 MB** | 原始AI识别数据未压缩 |
| `HSE教育培训/2月/2月管理员月度考核结果(1).xlsx` | **43 MB** | 可能含图片附件 |
| `HSE教育培训/1月/1月管理员月度考核结果(1).xlsx` | **34 MB** | 同上 |

**后果**：Git 无法管理，文件拷贝耗时，占用磁盘空间接近 300MB。

### 🟡 P1 — 重要问题

#### 问题4：提取流程不可追溯

JS 数据文件只有简单注释，无法溯源：
```javascript
// 人员保险数据（自动生成于 2026-06-20 16:26:14）
// 数据源：花名册 + 工伤险缴纳表 + 雇主险清单 + 公益岗工资表
```

缺少：源 Excel 文件的 MD5 哈希、提取脚本版本、提取参数。当数据出现异常时无法快速定位是源数据问题还是提取逻辑问题。

#### 问题5：缺乏增量更新机制

当前更新流程：修改 Excel → 重新运行全量提取脚本 → 生成完整 JS 文件覆盖。每次都是全量操作，即使只改了 1 条记录。

#### 问题6：JS 数据文件变量命名不统一

```javascript
const TRAINING_DATA = {...};           // 培训
var PERSONNEL_INSURANCE_DATA = {...};  // 保险
const SANWEI_STATS = {...};            // 三违
const EMERGENCY_STATS = {...};         // 应急
const ACCIDENT_DATA = {...};           // 事故
```

部分用 `const`，部分用 `var`；部分命名为 `_DATA`，部分命名为 `_STATS`。增加维护成本。

#### 问题7：CSV 文件冗余副本

`data/` 和 `安全管理系统/data/` 下有完全相同的 10 个 CSV 文件副本，是历史遗留的重复数据。

### 🟢 P2 — 可优化问题

#### 问题8：Python 脚本版本堆积

- `generate_monthly_report.py` 有 v1~v4 四个版本
- `process_data.py` 有 v1~v5 五个版本
- `get_navigation_routes.py` 有 v3~v4
- `modify_overage_batch.py` 有 v2

旧版本未被清理，占位且容易误用。

#### 问题9：backups/ 积累 100+ 快照

备份目录随时间推移持续膨胀，已经比活跃代码体积还大。缺乏定期清理策略。

#### 问题10：仅培训模块有数据更新模板

`HSE教育培训_数据更新模板.xlsx` 是唯一的数据更新模板，其他模块均无标准模板。数据更新依赖直接修改原始 Excel → 重新运行脚本。

#### 2.2 统一提取入口 `数据源/extract_all.py`

```python
#!/usr/bin/env python3
"""统一数据提取入口"""
import json, subprocess, hashlib, os, sys
from datetime import datetime

CONFIG_FILE = os.path.join(os.path.dirname(__file__), 'extract_config.json')
PROJECT_ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))

def run_extract(module_name, forced=False):
    config = json.load(open(CONFIG_FILE, encoding='utf-8'))
    mod = config['modules'][module_name]
    
    source_dir = os.path.join(os.path.dirname(__file__), mod['source'])
    output_path = os.path.join(os.path.dirname(__file__), mod['output'])
    
    # 计算源文件哈希，判断是否需要更新
    if not forced:
        # 检查源文件是否变化...
        pass
    
    # 执行提取脚本
    script_path = os.path.join(os.path.dirname(__file__), mod['script'])
    result = subprocess.run([sys.executable, script_path], capture_output=True)
    
    # 生成带元数据的JS文件
    meta = {
        'module': module_name,
        'extracted_at': datetime.now().isoformat(),
        'source_hash': hashlib.md5(source_dir.encode()).hexdigest()[:8],
        'script_version': mod.get('script', 'unknown'),
        'row_count': 0  # 由具体提取脚本填充
    }
    
    # 更新配置中的 last_run
    mod['last_run'] = datetime.now().strftime('%Y-%m-%d')
    json.dump(config, open(CONFIG_FILE, 'w', encoding='utf-8'), ensure_ascii=False, indent=2)
    
    print(f'✅ {module_name}: 提取完成 → {output_path}')

if __name__ == '__main__':
    import argparse
    parser = argparse.ArgumentParser()
    parser.add_argument('module', nargs='?', help='模块名，不指定则全部更新')
    parser.add_argument('--force', action='store_true', help='强制全量更新')
    args = parser.parse_args()
    
    if args.module:
        run_extract(args.module, args.force)
    else:
        for name in json.load(open(CONFIG_FILE, encoding='utf-8'))['modules']:
            run_extract(name, args.force)
```

**用法**：
```bash
# 更新单个模块
python 数据源/extract_all.py training

# 全量更新所有模块
python 数据源/extract_all.py

# 强制更新（忽略文件变更检测）
python 数据源/extract_all.py --force
```

### 🥉 方案三：建立数据更新模板体系（业务侧优化）

**目标**：每个模块都有标准化的数据更新模板，非技术人员也能更新数据。

#### 3.1 模板体系

| 模块 | 模板文件名 | 使用场景 |
|------|-----------|----------|
| HSE教育培训 | `模板_HSE培训月度更新.xlsx` | 已有，每月填入新数据 |
| 保险及人员管理 | `模板_人员保险月度变更.xlsx` | 需新建：花名册变动、险种调整 |
| 事故管理 | `模板_事故登记.xlsx` | 需新建：新增事故登记 |
| 应急管理 | `模板_应急演练记录.xlsx` | 需新建：演练后登记 |
| 三违管理 | `模板_三违检查记录.xlsx` | 需新建：每次检查录入 |
| 现场管理 | `模板_消防器材变更.xlsx` | 需新建：器材增减、检验更新 |
| 隐患排查 | `模板_隐患排查登记.xlsx` | 需新建：排查后登记 |

#### 3.2 模板设计原则

```
模板 = 固定表头 + 数据行 + 使用说明Sheet

Sheet1: 数据录入（只填数据行，不动表头）
Sheet2: 使用说明（字段含义、下拉选项、格式要求、数据校验规则）
Sheet3: 下拉选项（供 Sheet1 数据验证引用）
```

**示例**：事故登记模板

| 事故日期 | 乡镇 | 事故类型 | 受伤人数 | 损失金额(元) | 责任认定 | 是否结案 |
|----------|------|----------|----------|-------------|----------|----------|
| 2026-06-15 | 大曹镇 | 车辆碰撞 | 1 | 5000 | 主责 | 否 |

每列设置数据验证（日期格式、下拉选项、数值范围），减少人为输入错误。

## 七、长期愿景：从文件驱动到数据中台

如果未来数据量和更新频率持续增长，可考虑演进到轻量数据库方案：

```
当前: Excel → Python脚本 → JS文件 → 前端
中期: Excel → 统一CLI → JS文件(带元数据) → 前端
远期: Excel → 导入脚本 → SQLite/飞书多维表格 → REST API → 前端
```

但就当前项目规模和纯前端架构需求而言，**方案一+方案二+方案四** 的组合已经能解决 90% 的痛点，且不引入新的技术栈复杂度。
