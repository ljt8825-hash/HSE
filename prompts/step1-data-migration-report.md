## 二、脚本审查结果

### 2.1 发现的问题

对 `migrate_all_v2.py`（v2 迁移脚本）的全面审查发现了以下严重问题：

| # | 问题 | 严重程度 | 影响 |
|---|------|---------|------|
| 1 | **ORM 模型与 `unified_schema.sql` 字段名不一致** | 🔴 严重 | v2 使用 ORM 模型映射字段，但 schema 中已有表（如 `accidents`）字段名不同（`victim_name` vs `name`），导致所有 INSERT 失败 |
| 2 | **`unified_schema.sql` 缺少部分 ORM 表定义** | 🔴 严重 | `violations`、`emergency_drills`、`new_employees`、`personnel_insurances`、`overage_personnels`、`regulations` 等表在 schema 中无定义，依赖 `db.create_all()` 动态创建，表结构与 Node.js 后端的 SQL 查询可能不匹配 |
| 3 | **应急演练数据为汇总统计而非明细** | 🟡 中等 | `emergency_data.js` 中仅有 `levelDistribution`（按级别统计数量），无单条演练记录。v2 脚本为每条统计生成了一条汇总记录 |
| 4 | **`migrate_all_v2.py` 中 `emergency_data.js` 路径引用正确** | ✅ 无问题 | 路径 `DATA_DIR/emergency_data.js` 可以正确找到文件 |
| 5 | **表名不一致** | 🟡 中等 | Schema 中 `personnel_insurance`（无 s）vs ORM 中 `personnel_insurances`（有 s），`over_age_personnel` vs `overage_personnels` |

### 2.2 修复措施

因问题严重（ORM 模型与已有表结构不兼容），**放弃了修复 v2 脚本**，改为编写全新的 **`migrate_all_v3.py`**：

- **使用原生 psycopg2 SQL** 直接操作，完全绕过 ORM 模型
- **字段映射基于 `unified_schema.sql`** 的实际列名
- **为 ORM 专用表自动创建**（如 violations、emergency_drills 等）
- **保持幂等性**：每个模块先 DELETE 再 INSERT，可重复执行
