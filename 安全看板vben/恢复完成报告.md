## 六、架构说明

### 6.1 二次开发模式

本项目严格遵循 Vben Admin 官方推荐的二次开发模式：

- **业务代码独立目录**：所有 HSE 业务代码均放置在独立目录中
  - `src/views/hse/` - HSE 业务视图
  - `src/views/insurance/` - 保险业务视图
  - `src/views/hazards/` - 隐患业务视图
  - `src/api/hse/` - HSE 业务 API
  - `src/store/` - 业务状态管理
  
- **不修改官方核心目录**：
  - ✅ 不修改 `src/_core/`
  - ✅ 不修改 `src/layouts/`
  - ✅ 不修改 `@vben/*` 包内代码
  
- **动态注册方式集成**：
  - 路由通过 `import.meta.glob` 自动加载 modules 目录下的所有路由模块
  - i18n 通过 `import.meta.glob` 自动加载 langs 目录下的所有 JSON 文件
  - 组件按需注册，无需全局注册

### 6.2 技术栈

| 技术 | 版本/说明 |
|-----|----------|
| Vue | 3.x (Composition API + `<script setup>`) |
| TypeScript | 严格模式 |
| Vite | 构建工具 |
| Ant Design Vue | 4.x UI组件库 |
| Pinia | 状态管理 |
| Vue Router | 4.x 路由 |
| TanStack Query | 数据请求缓存（Vben 内置） |
| vxe-table | 高性能表格 |

### 6.3 数据流向

```
UI 组件 (Vue)
    ↓
Store 层 (Pinia) - 状态管理 + Mock fallback
    ↓
API 层 (requestClient) - 接口定义 + 类型
    ↓
HTTP 请求拦截器
    ↓
后端 API (端口 5666)
```

## 七、注意事项

1. **缓存清理**：修改 `preferences.ts` 后，需在浏览器中清除 localStorage 缓存才能生效
2. **权限码**：路由中配置的 `meta.authority` 权限码需与后端返回的权限码一致
3. **后端接口**：当前前端使用 Mock 数据作为 fallback，后端 API 就绪后可移除
4. **端口配置**：前端运行在 5173 端口，后端运行在 5666 端口，通过代理转发
5. **路由模式**：当前使用前端静态路由模式（`accessMode: 'frontend'`），如需后端动态菜单，改为 `'backend'`
